# Google Play: Настройки и приватность

## Обзор модуля

Модуль «Настройки и приватность» Google Play объединяет все механизмы пользовательского контроля над поведением магазина приложений, безопасностью устройства, конфиденциальностью данных и финансовыми операциями. Система охватывает общие настройки приложения (тема, язык, кэш), сетевые предпочтения (автообновление, скачивание по Wi-Fi), уведомления, родительский контроль через Family Link, аутентификацию покупок (пароль, биометрия), Google Play Protect (сканирование приложений на вредоносность), управление устройствами, бюджетирование расходов, Data Safety (прозрачность данных приложений), управление разрешениями приложений, приватность рекламы (Advertising ID, персонализация), экспорт данных через Google Takeout, а также управление подписками и способами оплаты. Модуль тесно интегрирован с Google Account, Android Settings и Family Link, формируя многоуровневую систему контроля для индивидуальных пользователей, семей и детских аккаунтов.

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **Google Play Store** | Официальный магазин приложений, игр, фильмов, книг и контента для Android |
| **Google Account** | Единая учётная запись Google, связанная с Play Store и всеми сервисами Google |
| **Google Play Protect** | Встроенная система безопасности, сканирующая приложения на вредоносность в реальном времени |
| **Family Link** | Сервис родительского контроля Google для управления детскими аккаунтами и устройствами |
| **Family Group** | Семейная группа Google (до 6 участников), объединяющая подписки, покупки и контроль |
| **Family Manager** | Организатор семейной группы с правами управления участниками и одобрения покупок |
| **Data Safety** | Раздел в карточке приложения, отображающий какие данные собирает и передаёт приложение |
| **Advertising ID (AAID)** | Уникальный, сбрасываемый пользователем рекламный идентификатор Android-устройства |
| **Google Takeout** | Сервис экспорта пользовательских данных из всех продуктов Google |
| **Parental Controls** | Система ограничения контента по возрастному рейтингу для детских аккаунтов |
| **Purchase Verification** | Механизм аутентификации при совершении покупок в Google Play |
| **Biometric Verification** | Подтверждение покупки через отпечаток пальца или распознавание лица |
| **Auto-update** | Автоматическое обновление установленных приложений |
| **Sideloaded App** | Приложение, установленное не из Google Play (из стороннего источника) |
| **Content Rating** | Возрастной рейтинг контента (ESRB, PEGI, и др.) |
| **Budget** | Установленный пользователем лимит расходов за период |
| **Purchase Request** | Запрос ребёнка на покупку, требующий одобрения родителя |
| **App Permission** | Разрешение, которое приложение запрашивает для доступа к функциям устройства |
| **Permission Auto-Revocation** | Автоматический отзыв разрешений у неиспользуемых приложений |

## Типы пользователей и роли

### Индивидуальный пользователь

```
Google Account Owner
    └── Полный контроль над настройками Play Store на своём устройстве
```

### Семейная группа (Family Group)

```
Family Manager (взрослый, организатор)
    └── Family Member (взрослый)
        └── Child Account (ребёнок до 13 лет, управляется через Family Link)
```

### Уровни управления устройством

```
Владелец устройства (основной профиль)
    └── Дополнительный пользователь (user profile)
        └── Гостевой профиль
            └── Restricted Profile (ограниченный)
```

## Функциональные требования

### FR-GP-SET-001: Настройки сетевых предпочтений (Network Preferences)

**Приоритет**: P0-Critical

**Описание**: Управление предпочтениями сетевого подключения для скачивания и обновления приложений, определяющее баланс между удобством и экономией мобильного трафика.

**Акторы**: Владелец аккаунта, Family Manager (для детских аккаунтов)

**Предусловия**:
- Пользователь авторизован в Google Play
- Устройство имеет активное интернет-соединение

**Основной сценарий настройки автообновления**:
1. Пользователь открывает Google Play Store
2. Нажимает на иконку профиля в правом верхнем углу
3. Переходит в «Настройки» (Settings)
4. Открывает раздел «Сетевые предпочтения» (Network preferences)
5. Выбирает «Автообновление приложений» (Auto-update apps)
6. Система предлагает варианты:
   - **Только по Wi-Fi** (по умолчанию) — обновления скачиваются только при подключении к Wi-Fi
   - **По любой сети** — обновления через Wi-Fi и мобильные данные (предупреждение о расходе трафика)
   - **Не обновлять** — автоматические обновления полностью отключены
7. Пользователь выбирает вариант
8. Настройка применяется немедленно

**Сценарий настройки скачивания приложений**:
1. В разделе «Сетевые предпочтения» пользователь выбирает «Скачивание приложений» (App download preference)
2. Система предлагает варианты:
   - **По любой сети** — скачивание через любое подключение
   - **Только по Wi-Fi** — скачивание только через Wi-Fi
   - **Спрашивать каждый раз** — при каждом скачивании уточнять, использовать ли мобильные данные
3. Пользователь выбирает предпочтение

**Сценарий индивидуального автообновления для конкретного приложения**:
1. Пользователь открывает страницу приложения в Play Store
2. Нажимает меню (три точки)
3. Видит переключатель «Включить автообновление» (Enable auto update)
4. Пользователь может включить/отключить автообновление для данного конкретного приложения независимо от глобальной настройки

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-001 | По умолчанию автообновление установлено на «Только по Wi-Fi» для экономии мобильного трафика |
| BR-002 | Google Play всегда пытается обновить приложения по Wi-Fi в первую очередь, даже если разрешены мобильные данные |
| BR-003 | Настройка индивидуального автообновления приложения имеет приоритет над глобальной настройкой |
| BR-004 | При отключении автообновления пользователь видит уведомления о доступных обновлениях, но они не скачиваются автоматически |
| BR-005 | Скачивание больших приложений (более 150 МБ) через мобильные данные требует дополнительного подтверждения пользователя |
| BR-006 | Настройки сетевых предпочтений распространяются на все профили устройства, если пользователь является владельцем |

**Результат**: Настройки сетевых предпочтений применены, скачивание и обновление приложений происходит в соответствии с выбранными параметрами.

### FR-GP-SET-002: Настройки уведомлений

**Приоритет**: P1-High

**Описание**: Управление уведомлениями от Google Play Store, включая оповещения об обновлениях, акциях, предложениях и статусе скачивания.

**Акторы**: Владелец аккаунта

**Предусловия**:
- Пользователь авторизован в Google Play
- Уведомления Android разрешены для приложения Google Play Store

**Основной сценарий**:
1. Пользователь переходит в Настройки Google Play > «Общие» (General)
2. Находит раздел уведомлений
3. Управляет следующими категориями уведомлений:

**Категории уведомлений**:

| Категория | Описание | По умолчанию |
|-----------|----------|:------------:|
| Обновления доступны | Уведомление о наличии обновлений для установленных приложений | Включено |
| Автообновление завершено | Уведомление после автоматического обновления приложений | Включено |
| Предложения и акции | Персонализированные предложения, скидки, подборки приложений | Включено |
| Скачивание и установка | Уведомления о прогрессе скачивания и результате установки | Включено |
| Предварительная регистрация | Уведомления о выходе приложений, на которые пользователь зарегистрировался | Включено |
| Подписки | Уведомления о продлении, истечении и ценовых изменениях подписок | Включено |
| Покупки | Подтверждения покупок и возвратов | Включено |

**Сценарий управления через системные настройки Android**:
1. Пользователь переходит в «Настройки устройства» > «Приложения» > «Google Play Store»
2. Нажимает «Уведомления»
3. Видит все категории уведомлений Play Store
4. Для каждой категории может:
   - Включить/отключить
   - Выбрать режим: «Оповещение» (со звуком) или «Беззвучно»
   - Включить/отключить всплывающие уведомления (Pop on screen)
   - Настроить показ точки уведомления (notification dot)

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-007 | Уведомления о безопасности (Google Play Protect) не могут быть полностью отключены пользователем |
| BR-008 | Пользователь может отключить все маркетинговые уведомления (предложения и акции) |
| BR-009 | Уведомления о покупках и транзакциях всегда отправляются на email независимо от настроек push-уведомлений |
| BR-010 | При полном отключении уведомлений Play Store через системные настройки Android все категории деактивируются |
| BR-011 | Уведомления о критических обновлениях безопасности приложений обходят настройку «Не беспокоить» (DND) |

**Результат**: Уведомления Google Play Store настроены согласно предпочтениям пользователя.

### FR-GP-SET-003: Родительский контроль (Parental Controls)

**Приоритет**: P0-Critical

**Описание**: Система ограничения доступного контента по возрастному рейтингу для защиты детей от неподходящего контента. Работает совместно с Google Family Link для комплексного управления детскими аккаунтами.

**Акторы**: Family Manager (родитель), Ребёнок (контролируемый пользователь)

**Предусловия**:
- Family Manager имеет активный Google-аккаунт
- Семейная группа создана в Google Families
- Для детей до 13 лет — аккаунт создан и управляется через Family Link

**Основной сценарий настройки через Google Play (для собственного устройства)**:
1. Пользователь открывает Google Play Store
2. Переходит в Настройки > «Семья» (Family)
3. Выбирает «Родительский контроль» (Parental controls)
4. Включает переключатель родительского контроля
5. Система требует создать PIN-код (4 цифры) для защиты настроек
6. Пользователь задаёт PIN
7. Настраивает ограничения по типам контента:

**Фильтры контента по типам**:

| Тип контента | Уровни ограничения |
|--------------|-------------------|
| Приложения и игры | 3+ / 7+ / 12+ / 16+ / 18+ / Разрешить все |
| Фильмы | По возрастному рейтингу региона (G / PG / PG-13 / R / NC-17 или аналоги) |
| ТВ-шоу | По возрастному рейтингу региона |
| Книги | Ограничить контент сексуального характера (Вкл/Выкл) |
| Музыка | Ограничить откровенный контент (Explicit) (Вкл/Выкл) |

**Сценарий настройки через Family Link (для детского аккаунта)**:
1. Родитель открывает приложение Family Link
2. Выбирает ребёнка из списка
3. Нажимает «Ограничения» > «Google Play»
4. Настраивает фильтры контента по типам (аналогично п.7 выше)
5. Фильтры применяются к аккаунту ребёнка на всех его устройствах

**Сценарий одобрения покупок (Purchase Requests)**:
1. Ребёнок находит приложение/игру в Play Store
2. Нажимает «Купить» или «Установить» (для платного контента)
3. Система определяет, что аккаунт ребёнка — формирует запрос на одобрение
4. Family Manager получает уведомление с деталями запроса:
   - Название приложения/контента
   - Цена
   - Возрастной рейтинг
   - Информация о разработчике
5. Family Manager выбирает:
   - **Одобрить** — покупка совершается с выбранного способа оплаты
   - **Отклонить** — ребёнок получает уведомление об отказе

**Уровни одобрения покупок**:

| Уровень | Описание |
|---------|----------|
| Весь контент | Одобрение требуется для любого скачивания/покупки |
| Только платный контент | Одобрение только для покупок (бесплатные приложения можно скачивать свободно) |
| Только внутриигровые покупки | Одобрение только для in-app purchases |
| Без одобрения | Ребёнок может скачивать и покупать самостоятельно (не рекомендуется) |

**Альтернативные сценарии**:

| Сценарий | Условие | Действие |
|----------|---------|----------|
| A1 | Ребёнок пытается установить приложение с рейтингом выше допустимого | Приложение не отображается в результатах поиска; если открыто по ссылке — кнопка установки заблокирована |
| A2 | Родитель забыл PIN родительского контроля | Сброс возможен только через удаление и повторную настройку родительского контроля |
| A3 | Ребёнок использует устройство без Family Link | Родительский контроль работает только на уровне Play Store через PIN |
| A4 | Family Manager удалён из семейной группы | Все настройки родительского контроля для детей сбрасываются |

**Состояния родительского контроля**:

```
[Отключён] --включение + PIN--> [Активен]
     ^                              |
     |                              |
     +-----<--отключение (PIN)------+
```

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-012 | PIN-код родительского контроля — 4 цифры, уникален для устройства, не связан с Google-аккаунтом |
| BR-013 | Родительский контроль, настроенный через Play Store (PIN), действует только на конкретном устройстве |
| BR-014 | Родительский контроль через Family Link действует на все устройства ребёнка |
| BR-015 | Для детей до 13 лет аккаунт ОБЯЗАН быть создан через Family Link — родительский контроль обязателен |
| BR-016 | Фильтрация по возрастному рейтингу использует региональные системы рейтинга (ESRB в США, PEGI в Европе, IARC и т.д.) |
| BR-017 | Родительский контроль не влияет на уже установленные приложения — только на новые скачивания |
| BR-018 | Purchase Requests для детей до 13 лет без семейного платёжного метода требуют одобрения Family Manager для всех покупок |
| BR-019 | При включённом одобрении «Весь контент» — даже бесплатные приложения требуют согласия родителя |
| BR-020 | Настройки Family Link применяются с серверной стороны — обход на стороне устройства невозможен |

**Результат**: Родительский контроль активирован, контент фильтруется по возрастному рейтингу, покупки требуют одобрения родителя.

### FR-GP-SET-004: Аутентификация покупок (Purchase Verification)

**Приоритет**: P0-Critical

**Описание**: Механизм верификации личности пользователя при совершении покупок в Google Play, включающий поддержку пароля Google-аккаунта, биометрической аутентификации (отпечаток пальца, распознавание лица), PIN-кода и графического ключа устройства.

**Акторы**: Владелец аккаунта, Family Manager

**Предусловия**:
- Пользователь авторизован в Google Play
- К аккаунту привязан хотя бы один способ оплаты

**Основной сценарий настройки**:
1. Пользователь открывает Google Play Store
2. Нажимает на иконку профиля
3. Переходит в «Платежи и подписки» (Payments & subscriptions)
4. Выбирает «Верификация покупок» (Purchase verification)
5. Система предлагает настройки:

**Методы верификации**:

| Метод | Описание | Доступность |
|-------|----------|-------------|
| Пароль Google-аккаунта | Ввод пароля от Google Account перед покупкой | Все устройства |
| Биометрия (отпечаток пальца) | Верификация через сканер отпечатков | Устройства с биометрическим датчиком |
| Биометрия (распознавание лица) | Верификация через фронтальную камеру | Устройства с Face Unlock |
| PIN-код устройства | Ввод PIN блокировки экрана | Все устройства с PIN |
| Графический ключ | Ввод графического ключа блокировки | Все устройства с графическим ключом |

**Частота запроса верификации**:

| Режим | Описание |
|-------|----------|
| Для каждой покупки (по умолчанию) | Верификация требуется при каждой покупке |
| Каждые 30 минут (только мобильные) | После успешной верификации повторная не требуется в течение 30 минут |
| Никогда | Верификация не запрашивается (не рекомендуется) |

**Сценарий включения биометрической верификации**:
1. Пользователь в разделе «Верификация покупок» включает «Биометрическая верификация»
2. Система проверяет наличие зарегистрированных биометрических данных на устройстве
3. Если биометрия настроена — пользователь подтверждает включение отпечатком/лицом
4. Если биометрия не настроена — система предлагает перейти в настройки устройства для настройки
5. Система может запросить пароль Google-аккаунта для первоначальной активации
6. Биометрическая верификация активирована

**Сценарий совершения покупки с верификацией**:
1. Пользователь нажимает «Купить» на странице приложения/контента
2. Система показывает диалог подтверждения покупки с ценой и описанием
3. Запрашивается верификация в зависимости от настроек:
   - Если биометрия — показывает диалог биометрического сканера
   - Если пароль — запрашивает пароль Google-аккаунта
   - Если PIN/ключ — запрашивает ввод PIN или графического ключа
4. Пользователь успешно проходит верификацию
5. Покупка совершается

**Альтернативные сценарии**:

| Сценарий | Условие | Действие |
|----------|---------|----------|
| A1 | Биометрия не распознана (3 попытки) | Fallback на пароль Google-аккаунта |
| A2 | Пароль введён неверно | Показать ошибку, позволить повторить |
| A3 | Устройство разделяется несколькими пользователями | Предупредить: любые биометрические данные на устройстве могут быть использованы для покупок |
| A4 | Покупка in-app через приложение | Верификация применяется аналогично прямым покупкам в Play Store |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-021 | По умолчанию верификация покупок установлена на «Для каждой покупки» |
| BR-022 | Для детских аккаунтов (Family Link) верификация покупок всегда включена и не может быть отключена ребёнком |
| BR-023 | Биометрическая верификация использует все биометрические модели, сохранённые на устройстве (все отпечатки, все лица) |

| BR-025 | Режим «Каждые 30 минут» доступен только на мобильных устройствах, на планшетах и Chromebook — только «Для каждой покупки» или «Никогда» |

| BR-028 | Бесплатные приложения не требуют верификации покупки (кроме случаев родительского контроля) |

**Результат**: Верификация покупок настроена, каждая финансовая операция защищена выбранным методом аутентификации.

### FR-GP-SET-005: Google Play Protect

**Приоритет**: P0-Critical

**Описание**: Встроенная система безопасности Google Play, выполняющая сканирование приложений на устройстве для обнаружения вредоносного ПО, потенциально опасных приложений и угроз безопасности. Play Protect работает как для приложений из Play Store, так и для приложений, установленных из сторонних источников (sideloaded).

**Акторы**: Владелец устройства, Family Manager (для управления настройками на устройстве ребёнка)

**Предусловия**:
- Устройство с Google Play Services
- Пользователь авторизован в Google Play

**Основной сценарий настройки**:
1. Пользователь открывает Google Play Store
2. Нажимает на иконку профиля
3. Выбирает «Play Protect»
4. Система показывает текущий статус безопасности:
   - Дата и время последнего сканирования
   - Количество проверенных приложений
   - Обнаруженные проблемы (если есть)
5. Пользователь нажимает значок настроек (шестерёнка) в правом верхнем углу
6. Управляет настройками:

**Настройки Play Protect**:

| Настройка | Описание | По умолчанию |
|-----------|----------|:------------:|
| Сканирование приложений Play Protect | Основной переключатель: регулярное сканирование всех приложений на устройстве | Включено |
| Улучшенное обнаружение вредоносных приложений | Отправка неизвестных приложений в Google для анализа (расширенное сканирование sideloaded приложений) | Выключено |
| Обнаружение угроз в реальном времени | Мониторинг поведения приложений после установки | Включено |

**Сценарий автоматического сканирования**:
1. Play Protect ежедневно выполняет автоматическое сканирование ВСЕХ установленных приложений
2. Сканирование происходит в фоновом режиме
3. При обнаружении потенциально вредоносного приложения система:
   - Отправляет пользователю уведомление
   - Показывает предупреждение на экране Play Protect
4. Уровни реакции на угрозу:

| Уровень угрозы | Действие системы |
|----------------|-----------------|
| Низкий | Уведомление с рекомендацией удалить приложение |
| Средний | Автоматическое отключение приложения до принятия решения пользователем |
| Критический (подтверждённое вредоносное ПО) | Автоматическое удаление приложения с уведомлением |

**Сценарий сканирования при установке**:
1. Пользователь инициирует установку приложения (из Play Store или сторонних источников)
2. Play Protect автоматически проверяет приложение перед установкой
3. При обнаружении проблем — показывает предупреждение:
   - «Приложение может быть вредоносным» — с кнопками «Всё равно установить» и «Не устанавливать»
   - «Установка заблокирована» — для приложений с подтверждённой вредоносностью
4. При отсутствии проблем — установка продолжается

**Сценарий ручного сканирования**:
1. Пользователь открывает раздел Play Protect
2. Нажимает кнопку «Сканировать»
3. Система сканирует все установленные приложения
4. Отображает результат: «Проблемы не обнаружены» или список обнаруженных проблем

**Сценарий офлайн-сканирования**:
1. При отсутствии интернет-соединения Play Protect выполняет локальное сканирование
2. Используются локальные базы сигнатур вредоносных программ
3. При восстановлении соединения — результаты синхронизируются с облаком

**Альтернативные сценарии**:

| Сценарий | Условие | Действие |
|----------|---------|----------|
| A1 | Пользователь отключает Play Protect | Система показывает предупреждение о снижении безопасности; в статус-баре может появиться иконка |
| A2 | Play Protect удалил приложение, которое пользователь хочет использовать | Пользователь может переустановить с подтверждением «Всё равно установить» |
| A3 | Обновление приложения содержит вредоносный код | Play Protect блокирует обновление и уведомляет пользователя |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-029 | Play Protect включён по умолчанию на всех устройствах с Google Play Services |
| BR-030 | Play Protect сканирует ВСЕ приложения, включая установленные из сторонних источников |
| BR-031 | Ежедневное автоматическое сканирование выполняется без участия пользователя |
| BR-032 | При включённом «Улучшенном обнаружении» неизвестные приложения отправляются в Google для облачного анализа |
| BR-033 | Подтверждённо вредоносные приложения удаляются автоматически без возможности отменить |
| BR-034 | Play Protect может работать офлайн с использованием локальных сигнатур |
| BR-035 | На устройствах детей (Family Link) отключение Play Protect недоступно |
| BR-036 | Play Protect является самой распространённой мобильной системой защиты от угроз в мире (миллиарды устройств) |
| BR-037 | Отключение Play Protect не удаляет его с устройства — его можно включить обратно в любой момент |

**Состояния Play Protect**:

```
[Активен] --отключение пользователем--> [Отключён]
     ^                                       |
     |                                       |
     +-----<--включение пользователем--------+
     |
     +-- [Сканирование] --завершено--> [Результат: Безопасно / Обнаружены угрозы]
```

**Результат**: Play Protect настроен, приложения на устройстве сканируются автоматически, угрозы обнаруживаются и нейтрализуются.

### FR-GP-SET-006: Управление устройствами

**Приоритет**: P1-High

**Описание**: Управление списком устройств, связанных с Google-аккаунтом пользователя в контексте Google Play. Включает просмотр, именование и скрытие устройств из Google Play.

**Акторы**: Владелец аккаунта

**Предусловия**:
- Пользователь авторизован в Google Account
- Хотя бы одно устройство привязано к аккаунту

**Основной сценарий просмотра устройств**:
1. Пользователь переходит в Google Play на веб-версии (play.google.com)
2. Открывает Настройки или раздел «Мои устройства»
3. Система отображает список всех устройств, на которых был выполнен вход с данным Google-аккаунтом:
   - Название устройства (производитель + модель)
   - Тип устройства (телефон, планшет, Chromebook, TV, Wear OS)
   - Пользовательское имя (nickname)
   - Дата последнего использования
   - Статус (активно / неактивно)

**Сценарий именования устройства**:
1. Пользователь находит устройство в списке
2. Нажимает «Изменить» (Edit)
3. Задаёт пользовательское имя (nickname), например «Мой телефон», «Планшет на кухне»

5. Nickname отображается при удалённой установке приложений (выбор устройства для установки)

**Сценарий скрытия устройства**:
1. Пользователь находит устройство, которым больше не пользуется
2. Снимает галочку «Показывать в меню» (Show in menus)
3. Устройство перестаёт отображаться в списке выбора при удалённой установке приложений
4. Устройство НЕ удаляется из истории — оно остаётся привязанным к аккаунту

**Сценарий удалённой установки приложения на устройство**:
1. Пользователь находит приложение в веб-версии Google Play
2. Нажимает «Установить»
3. Система показывает список видимых устройств
4. Пользователь выбирает целевое устройство
5. Приложение начинает устанавливаться на выбранном устройстве (при наличии интернет-соединения)

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-038 | Устройство нельзя полностью удалить из истории Google Play — только скрыть |
| BR-039 | Для удаления аккаунта с устройства необходимо выполнить выход из Google-аккаунта на самом устройстве |
| BR-040 | Ограничение количества регистрируемых устройств отсутствует (лимит в 100 устройств для сертификации снят) |
| BR-041 | Nickname устройства используется для удобства идентификации при удалённой установке |
| BR-042 | Скрытое устройство продолжает получать обновления, если на нём выполнен вход в аккаунт |
| BR-043 | При смене владельца устройства необходимо выполнить factory reset для полного удаления привязки аккаунта |

**Результат**: Пользователь видит и управляет списком устройств, привязанных к его Google-аккаунту.

### FR-GP-SET-007: Бюджет и контроль расходов

**Приоритет**: P1-High

**Описание**: Инструмент установки месячного бюджета для мониторинга расходов в Google Play. Бюджет является информационным инструментом — уведомляет при приближении к лимиту, но НЕ блокирует транзакции при его превышении.

**Акторы**: Владелец аккаунта

**Предусловия**:
- Пользователь авторизован в Google Play
- К аккаунту привязан хотя бы один способ оплаты

**Основной сценарий установки бюджета**:
1. Пользователь открывает Google Play Store
2. Нажимает на иконку профиля
3. Переходит в «Платежи и подписки» (Payments & subscriptions)
4. Выбирает «Бюджет и история» (Budget & history)
5. Нажимает «Установить бюджет» (Set budget)
6. Вводит сумму месячного бюджета в валюте аккаунта
7. Подтверждает
8. Система активирует мониторинг расходов

**Сценарий мониторинга расходов**:
1. Система отслеживает все покупки пользователя в Google Play за текущий месяц:
   - Покупки приложений и игр
   - Внутриигровые покупки (in-app purchases)
   - Покупки фильмов, книг, музыки
   - Подписки (автопродления)
2. При каждой покупке система проверяет общую сумму расходов за месяц
3. Текущие расходы отображаются на экране «Бюджет и история» с визуальным индикатором прогресса

**Сценарий уведомления о приближении к бюджету**:
1. Пользователь совершает покупку
2. Общая сумма расходов приближается к установленному бюджету
3. Система показывает уведомление: «Вы близки к лимиту бюджета» (при достижении ~80%)
4. При превышении бюджета — показывает уведомление: «Вы превысили установленный бюджет»

**Сценарий превышения бюджета**:
1. Пользователь совершает покупку, которая превышает бюджет
2. Система показывает предупреждение о превышении бюджета
3. Покупка НЕ блокируется — транзакция проходит
4. Каждая последующая покупка сопровождается напоминанием о превышении бюджета

**Сценарий просмотра истории расходов**:
1. Пользователь переходит в «Бюджет и история»
2. Видит хронологический список всех покупок:
   - Название контента
   - Дата покупки
   - Сумма
   - Тип покупки (приложение, in-app, подписка и т.д.)
3. Общая сумма за текущий месяц
4. Прогресс относительно бюджета

**Сценарий изменения бюджета**:
1. Пользователь переходит в «Бюджет и история»
2. Нажимает «Изменить бюджет» или «Удалить бюджет»
3. Вводит новую сумму или подтверждает удаление
4. Новый бюджет вступает в силу немедленно

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-044 | Бюджет является информационным инструментом — он НЕ блокирует транзакции при превышении |
| BR-045 | Бюджет устанавливается в валюте Google Play аккаунта пользователя |
| BR-046 | Период бюджета — один календарный месяц, сброс 1-го числа каждого месяца |
| BR-047 | В расчёт бюджета входят ВСЕ типы покупок: приложения, in-app, подписки, контент |
| BR-048 | Возвраты вычитаются из суммы расходов за месяц |
| BR-049 | Бюджет устанавливается для каждого Google-аккаунта отдельно |
| BR-050 | Пользователь может изменить или удалить бюджет в любой момент |
| BR-051 | Для семейных аккаунтов бюджет каждого участника отслеживается независимо |

**Результат**: Бюджет установлен, пользователь получает уведомления при приближении к лимиту расходов.

### FR-GP-SET-008: Data Safety (Прозрачность данных приложений)

**Приоритет**: P0-Critical

**Описание**: Раздел «Безопасность данных» (Data Safety) в карточке каждого приложения в Google Play, предоставляющий пользователю стандартизированную информацию о том, какие данные собирает приложение, как их использует, передаёт ли третьим сторонам и какие меры безопасности применяет. Информация предоставляется разработчиком приложения и является обязательной для публикации.

**Акторы**: Пользователь (просмотр), Разработчик (заполнение через Play Console)

**Предусловия**:
- Приложение опубликовано в Google Play
- Разработчик заполнил форму Data Safety в Play Console

**Основной сценарий просмотра**:
1. Пользователь открывает страницу приложения в Google Play
2. Прокручивает до раздела «Безопасность данных» (Data safety)
3. Видит краткую сводку:
   - Передаются ли данные третьим сторонам
   - Какие данные собираются
   - Применяется ли шифрование данных при передаче
   - Может ли пользователь запросить удаление данных
4. Нажимает «Подробнее» для расширенной информации

**Категории данных в Data Safety**:

| Категория | Примеры данных |
|-----------|---------------|
| Местоположение | Точное местоположение, приблизительное местоположение |
| Личная информация | Имя, email, телефон, адрес, дата рождения |
| Финансовая информация | Платёжные данные, история покупок, кредитный рейтинг |
| Здоровье и фитнес | Медицинские данные, данные фитнес-трекера |
| Сообщения | SMS, email, другие сообщения в приложении |
| Фото и видео | Фотографии, видеозаписи |
| Аудио | Голосовые записи, музыкальные файлы |
| Файлы и документы | Документы, файлы пользователя |
| Календарь | Записи в календаре |
| Контакты | Список контактов |
| Активность в приложении | Поиск, просмотренные элементы, действия в приложении |
| Просмотр веб-страниц | История просмотра |
| Идентификаторы устройства | Device ID, Advertising ID |

**Цели использования данных**:

| Цель | Описание |
|------|----------|
| Функциональность приложения | Данные необходимы для работы приложения |
| Аналитика | Анализ использования приложения |
| Связь с разработчиком | Коммуникация с пользователем (уведомления, поддержка) |
| Реклама и маркетинг | Показ рекламы, маркетинговые кампании |
| Предотвращение мошенничества и безопасность | Борьба с фродом, аутентификация |
| Персонализация | Настройка контента под пользователя |
| Управление аккаунтом | Управление учётной записью пользователя |

**Информация о безопасности**:

| Параметр | Варианты |
|----------|---------|
| Шифрование при передаче | Да / Нет |
| Возможность запроса удаления данных | Да / Нет |
| Независимый аудит безопасности | Да / Нет |
| Соответствие Family Policy | Да / Нет |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-052 | Заполнение раздела Data Safety является ОБЯЗАТЕЛЬНЫМ для всех приложений в Google Play |
| BR-053 | Разработчик несёт ответственность за достоверность предоставленной информации |

| BR-055 | Информация в Data Safety должна соответствовать фактическому поведению приложения — несоответствие может привести к удалению из Play Store |

| BR-059 | Раздел «Безопасность данных» обновляется разработчиком при каждом существенном изменении политик данных |

### FR-GP-SET-009: Управление разрешениями приложений

**Приоритет**: P0-Critical

**Описание**: Система управления разрешениями (permissions) для установленных приложений, определяющая доступ приложений к функциям устройства (камера, микрофон, местоположение, контакты и т.д.). Интегрирована с Android Permission System и Google Play.

**Акторы**: Владелец устройства, Family Manager (для детских устройств)

**Предусловия**:
- Приложение установлено на устройстве
- Устройство на Android 6.0 (API 23) или выше (runtime permissions)

**Просмотр разрешений перед установкой из Google Play**:
1. Пользователь открывает страницу приложения в Google Play
2. Прокручивает до раздела «О приложении» (About this app)
3. В самом низу нажимает «Разрешения приложения» (App permissions)
4. Видит полный список запрашиваемых разрешений с описаниями

**Основной сценарий управления разрешениями установленного приложения**:
1. Пользователь переходит в Настройки устройства > Приложения
2. Выбирает приложение
3. Нажимает «Разрешения» (Permissions)
4. Видит список разрешений с текущим статусом:
   - **Разрешено** — приложение имеет доступ
   - **Запрещено** — приложение не имеет доступа
   - **Спрашивать каждый раз** — при каждом обращении спрашивать пользователя
5. Пользователь может изменить статус каждого разрешения

**Категории разрешений**:

| Разрешение | Описание | Уровень конфиденциальности |
|------------|----------|:--------------------------:|
| Камера | Доступ к камере устройства | Высокий |
| Микрофон | Доступ к микрофону | Высокий |
| Местоположение | GPS и сетевое местоположение | Высокий |
| Контакты | Доступ к списку контактов | Высокий |
| Телефон | Совершение звонков | Высокий |
| SMS | Чтение и отправка SMS | Высокий |
| Хранилище | Доступ к файлам, фото, видео | Средний |
| Календарь | Чтение/запись событий | Средний |
| Физическая активность | Датчики движения | Средний |
| Уведомления | Отправка push-уведомлений | Низкий |
| Ближайшие устройства | Bluetooth, Wi-Fi Direct | Средний |

**Варианты доступа к местоположению (Android 10+)**:

| Вариант | Описание |
|---------|----------|
| Всегда | Приложение получает доступ к местоположению в фоне |
| Только при использовании | Доступ только когда приложение открыто |
| Спрашивать каждый раз | Запрос при каждом обращении к геолокации |
| Запрещено | Доступ к местоположению запрещён |

**Сценарий автоматического отзыва разрешений (Permission Auto-Revocation)**:
1. Система отслеживает использование приложений
2. Если приложение не использовалось в течение длительного периода (обычно 3 месяца)
3. Android автоматически отзывает все ранее выданные разрешения
4. Пользователь получает уведомление
5. При следующем открытии приложение запрашивает разрешения заново
6. Пользователь может отключить авто-отзыв для конкретного приложения:
   - Настройки > Приложения > [Приложение] > «Приостановка активности неиспользуемых» (Pause app activity if unused) — выключить

**Сценарий быстрого отключения камеры/микрофона (Android 12+)**:
1. Пользователь открывает Quick Settings (шторка уведомлений)
2. Находит переключатели «Камера» и «Микрофон»
3. При отключении — ВСЕ приложения теряют доступ к камере/микрофону
4. При попытке использования приложением — показывается запрос на включение

**Индикаторы доступа (Android 12+)**:
1. При использовании камеры или микрофона приложением — в статус-баре появляется зелёный индикатор
2. Пользователь может нажать на индикатор для просмотра, какое приложение использует датчик
3. Индикатор местоположения отображается при активном GPS-доступе

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-060 | Пользователь может изменить любое разрешение в любой момент через настройки устройства |
| BR-061 | Приложение обязано корректно работать (или graceful degradation) при отзыве разрешений |
| BR-062 | Автоматический отзыв разрешений происходит для приложений, не используемых ~3 месяца |

| BR-067 | Индикаторы доступа к камере, микрофону и местоположению не могут быть отключены пользователем |

**Результат**: Пользователь имеет полный контроль над разрешениями каждого приложения, активными индикаторами доступа и автоматическим отзывом неиспользуемых разрешений.

### FR-GP-SET-010: Приватность рекламы (Advertising ID и персонализация)

**Приоритет**: P1-High

**Описание**: Управление рекламным идентификатором Android (AAID — Android Advertising ID) и персонализацией рекламы. Пользователь может сбросить, удалить Advertising ID и отказаться от персонализированной рекламы.

**Акторы**: Владелец устройства

**Предусловия**:
- Устройство с Google Play Services
- Android 12 или выше (для удаления Advertising ID)

**Основной сценарий управления Advertising ID**:
1. Пользователь переходит в Настройки устройства > Google > Реклама (Ads)
2. Видит текущий статус:
   - Текущий Advertising ID (отображается строка идентификатора)
   - Статус персонализации рекламы (Вкл/Выкл)
3. Доступные действия:

**Действия с Advertising ID**:

| Действие | Описание | Результат |
|----------|----------|-----------|
| Сбросить Advertising ID | Генерация нового уникального идентификатора | Рекламные профили, связанные со старым ID, теряют привязку |
| Удалить Advertising ID (Android 12+) | Полное удаление рекламного идентификатора | ID заменяется строкой нулей для всех приложений |
| Отказ от персонализации рекламы | Запрет использования ID для таргетированной рекламы | Приложения получают ID, но не могут использовать его для персонализации |

**Сценарий отказа от персонализации рекламы**:
1. Пользователь переходит в Настройки > Google > Реклама
2. Включает «Отказ от персонализации рекламы» (Opt out of Ads Personalization)
3. Система показывает подтверждение:
   - Реклама будет менее релевантной
   - Количество рекламы НЕ уменьшится
   - Реклама может основываться на других факторах (контент страницы, время суток и т.д.)
4. Пользователь подтверждает
5. Для приложений Advertising ID обнуляется (Android 12+) или помечается как opted-out

**Сценарий удаления Advertising ID (Android 12+)**:
1. Пользователь переходит в Настройки > Конфиденциальность > Реклама
2. Нажимает «Удалить рекламный ID» (Delete advertising ID)
3. Система показывает предупреждение:
   - ID будет удалён
   - Приложения получат строку нулей вместо ID
   - Действие применяется ко всем приложениям на устройстве
4. Пользователь подтверждает
5. Advertising ID удаляется

**Взаимодействие с Google Ads Settings (уровень аккаунта)**:
1. Помимо настроек на устройстве, пользователь может управлять рекламой на уровне Google-аккаунта:
   - myaccount.google.com > «Данные и конфиденциальность» > «Персонализация рекламы»
2. Контролирует:
   - Персонализацию рекламы Google (поиск, YouTube, Gmail)
   - Категории рекламных интересов
   - Рекламные партнёры
3. Настройки на уровне аккаунта и на уровне устройства — независимы друг от друга

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-068 | Advertising ID является уникальным для устройства, не для аккаунта |
| BR-069 | Сброс Advertising ID генерирует полностью новый ID — старый невозможно восстановить |
| BR-070 | При отказе от персонализации на Android 12+ Advertising ID обнуляется (строка нулей) для всех приложений |
| BR-071 | Отказ от персонализации НЕ уменьшает количество рекламы — только её релевантность |
| BR-072 | Удаление Advertising ID (Android 12+) необратимо для текущей сессии — можно заново создать только через сброс настроек |
| BR-073 | Приложения, использующие Advertising ID для целей, не связанных с рекламой, нарушают политику Google Play |
| BR-074 | Все биометрические модели на устройстве имеют доступ к Advertising ID (если он не удалён/обнулён) |
| BR-075 | Настройки рекламной приватности на устройстве и на уровне Google Account — независимые сущности |

**Результат**: Пользователь контролирует свой рекламный идентификатор и уровень персонализации рекламы.

### FR-GP-SET-013: Очистка кэша и управление хранилищем

**Приоритет**: P2-Medium

**Описание**: Управление локальным хранилищем приложения Google Play Store, включая очистку кэша и полный сброс данных приложения.

   - Размер приложения
   - Размер данных пользователя
   - Размер кэша

6. Настройки Play Store сохраняются

### FR-GP-SET-014: Управление подписками

**Приоритет**: P0-Critical

**Описание**: Централизованное управление всеми активными подписками, оформленными через Google Play Billing. Включает просмотр, продление, отмену, изменение плана и восстановление подписок.

**Акторы**: Владелец аккаунта

**Предусловия**:
- Пользователь авторизован в Google Play
- У пользователя есть хотя бы одна подписка

**Основной сценарий просмотра подписок**:
1. Пользователь открывает Google Play Store
2. Нажимает на иконку профиля
3. Переходит в «Платежи и подписки» (Payments & subscriptions)
4. Выбирает «Подписки» (Subscriptions)
5. Система отображает список всех подписок:

**Информация о подписке**:

| Параметр | Описание |
|----------|----------|
| Название приложения | Приложение, к которому оформлена подписка |
| План подписки | Текущий тарифный план (Basic, Premium и т.д.) |
| Стоимость | Цена и периодичность (ежемесячно, ежегодно) |
| Следующее продление | Дата автоматического продления |
| Способ оплаты | Привязанная карта/метод |
| Статус | Активная, Приостановлена, Отменена (истекает), Истекла |

**Сценарий отмены подписки**:
1. Пользователь находит подписку в списке
2. Нажимает на подписку
3. Выбирает «Отменить подписку» (Cancel subscription)
4. Система показывает:
   - Дату, до которой подписка будет активна (оплаченный период)
   - Что произойдёт после отмены (потеря функций)
   - Предложения: приостановка вместо отмены, смена плана
5. Пользователь подтверждает отмену
6. Подписка переходит в статус «Отменена, истекает [дата]»
7. Доступ сохраняется до конца оплаченного периода

**Сценарий приостановки подписки**:
1. Пользователь выбирает подписку
2. Нажимает «Приостановить» (Pause) — если разработчик поддерживает эту функцию
3. Выбирает период приостановки (1-4 недели)
4. Подписка приостанавливается — оплата не списывается
5. По истечении периода приостановки подписка автоматически возобновляется

**Сценарий восстановления подменённой подписки**:
1. Пользователь ранее отменил подписку, но оплаченный период ещё не истёк
2. Переходит в список подписок
3. Находит отменённую подписку
4. Нажимает «Возобновить подписку» (Resubscribe / Restore)
5. Подписка восстанавливается без перерыва

**Сценарий изменения плана подписки**:
1. Пользователь выбирает активную подписку
2. Если разработчик предлагает несколько планов — видит опцию «Изменить план»
3. Выбирает новый план (upgrade/downgrade)
4. Система рассчитывает разницу в стоимости:
   - Upgrade — доплата пропорционально оставшемуся периоду
   - Downgrade — новый план вступает со следующего периода
5. Подтверждает изменение

**Состояния подписки**:

```
[Активная] --отмена--> [Отменена (ожидает истечения)] --истечение--> [Истекла]
     |                          |
     |                          +--восстановление--> [Активная]
     |
     +--приостановка--> [Приостановлена] --возобновление--> [Активная]
     |                                   --таймаут--> [Активная (автопродление)]
     |
     +--ошибка оплаты--> [Grace Period] --оплата успешна--> [Активная]
     |                                  --оплата не прошла--> [Account Hold]
     |                                                             |
     |                                                             +--оплата--> [Активная]
     |                                                             +--таймаут--> [Истекла]
```

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-094 | Отмена подписки не приводит к немедленной потере доступа — доступ сохраняется до конца оплаченного периода |
| BR-095 | Возврат средств за подписку возможен в течение 48 часов после списания (или по решению Google) |
| BR-096 | Приостановка подписки доступна, только если разработчик включил эту функцию |
| BR-097 | При ошибке оплаты (Grace Period) — подписка сохраняется активной на ограниченный срок для обновления платёжных данных |
| BR-098 | Если оплата не проходит после Grace Period — подписка переходит в Account Hold (доступ заблокирован, но подписка не отменена) |
| BR-099 | Пользователь может восстановить отменённую подписку до конца оплаченного периода |
| BR-100 | Подписки привязаны к Google-аккаунту и доступны на всех устройствах с этим аккаунтом |

### FR-GP-SET-017: Удаление Google-аккаунта

**Приоритет**: P1-High

**Описание**: Полное удаление Google-аккаунта с удалением всех связанных данных Google Play (покупки, подписки, библиотека, история). Является частью общего процесса удаления Google Account, а не отдельной функцией Google Play.

**Акторы**: Владелец аккаунта

**Предусловия**:
- Пользователь авторизован в Google Account
- Пользователь понимает необратимость действия

3. Находит раздел «Больше возможностей» (More options) > «Удалить аккаунт Google» (Delete your Google Account)
4. Система требует подтверждение личности (пароль, 2FA)
5. Система показывает ПОЛНЫЙ список того, что будет удалено:

**Данные Google Play, подлежащие удалению**:

| Данные | Описание |
|--------|----------|
| Покупки приложений | Доступ ко всем купленным приложениям |
| Подписки | Все активные подписки отменяются |
| Баланс Google Play | Неиспользованный баланс аннулируется |
| Библиотека контента | Фильмы, книги, музыка, купленные через Play |
| История покупок | Все записи о транзакциях |
| Отзывы | Все оставленные отзывы и рейтинги |
| Список желаний | Сохранённые приложения |
| Привязка устройств | Все устройства отвязываются от аккаунта |

6. Пользователь отмечает две обязательные галочки:
   - Подтверждение удаления всех данных
   - Подтверждение невозможности использования сервисов Google
7. Нажимает «Удалить аккаунт»
8. Аккаунт помечается для удаления

**Временная шкала удаления**:

| Период | Состояние |
|--------|-----------|
| День 0-1 | Аккаунт помечен для удаления, сервисы Google недоступны |
| Дни 2-20 | Возможно восстановление через страницу восстановления Google |
| Дни 21-29 | Данные в подвешенном состоянии на серверах |
| День 30 | Начало безвозвратного удаления данных с активных серверов |
| Дни 31-90 | Удаление данных с резервных серверов и логов |

1. Пользователь переходит на страницу восстановления Google Account
2. Вводит email удалённого аккаунта
3. Проходит верификацию (последний пароль, телефон, и т.д.)
4. Если в пределах ~20 дней — аккаунт восстанавливается
5. Все данные, включая Google Play, восстанавливаются

**Альтернатива удалению аккаунта — удаление только данных Play**:
1. Пользователь может удалить данные только конкретного сервиса (не весь аккаунт)
2. Через myaccount.google.com > «Данные и конфиденциальность» > «Скачивание или удаление данных»
3. Выбирает «Удалить сервис» и выбирает конкретные продукты Google

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|

| BR-117 | Период восстановления аккаунта — примерно 20 дней после удаления |

**Состояния аккаунта**:

```

```

**Результат**: Аккаунт удалён, все данные Google Play безвозвратно стёрты после периода ожидания.

## Ограничения и лимиты

### Общие ограничения

| Параметр | Значение |
|----------|----------|
| Максимальное количество устройств | Без ограничений |
| Частота смены региона | 1 раз в год |
| Период Grace Period подписки | Определяется разработчиком (обычно 3-30 дней) |
| Период Account Hold | До 30 дней |
| Частота автоматического сканирования Play Protect | 1 раз в день |
| Период автоотзыва разрешений неиспользуемых приложений | ~3 месяца |
| Период восстановления удалённого Google-аккаунта | ~20 дней |
| Полное удаление данных с серверов Google | До 90 дней |

### Ограничения родительского контроля

| Параметр | Значение |
|----------|----------|
| Максимальный размер семейной группы | 6 участников |
| Минимальный возраст Family Manager | 18 лет |
| Возраст для обязательного контроля через Family Link | До 13 лет |
| Длина PIN родительского контроля | 4 цифры |

### Ограничения платежей

| Параметр | Значение |
|----------|----------|
| Максимальное количество способов оплаты | Без явного ограничения |
| Период возврата подписки | 48 часов после списания |
| Региональная привязка подарочных карт | Карта и аккаунт должны быть одного региона |
| Период приостановки подписки | 1-4 недели (если поддерживается разработчиком) |

### Ограничения Data Safety

| Параметр | Значение |
|----------|----------|
| Обязательность заполнения | Обязательно для всех приложений |
| Ответственность за достоверность | Разработчик приложения |
| Несоответствие данных | Может привести к удалению из Play Store |
