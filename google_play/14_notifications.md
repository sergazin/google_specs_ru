# Функциональная спецификация: Модуль уведомлений (Google Play)

## 1. Обзор модуля

### 1.1 Назначение
Модуль уведомлений Google Play обеспечивает многоканальную систему информирования пользователей (конечных потребителей) и разработчиков приложений о событиях, связанных с установкой, обновлением, покупкой, безопасностью, программами лояльности, подписками и состоянием приложений. Система охватывает push-уведомления на устройстве, email-уведомления, in-app уведомления в Google Play Store, а также серверные уведомления для разработчиков через Play Console и Real-Time Developer Notifications (RTDN).

### 1.2 Основные компоненты
- Push-уведомления об установке и обновлении приложений
- Уведомления о доступных обновлениях (массовые и индивидуальные)
- Рекомендательные уведомления (персонализированные предложения)
- Уведомления о подписках и предстоящих списаниях
- Уведомления о промо-акциях, скидках и предложениях (Offers Tab)
- Уведомления об ответах разработчика на отзывы пользователя
- Уведомления Play Points (начисления, миссии, акции, уровень)
- Уведомления Play Pass (новые приложения, статус подписки)
- Уведомления о pre-registration (доступность приложения, авто-установка)
- Уведомления безопасности (Google Play Protect)
- Email-уведомления о покупках и квитанции
- Центр уведомлений и предложений (Notifications & Offers)
- Настройки уведомлений (гранулярный контроль по категориям)
- Real-Time Developer Notifications (RTDN) для разработчиков
- Уведомления Play Console (политики, обзор приложений, статистика)
- Уведомления-напоминания о неиспользуемых приложениях

### 1.3 Ключевые особенности
- Многоканальная доставка: push, email, in-app, серверные (Pub/Sub)
- Гранулярный контроль через Android Notification Channels (категории)
- Разделение на пользовательские и разработческие уведомления
- Персонализация рекомендаций на основе истории установок и поведения
- Интеграция с Google Play Protect для проактивной безопасности
- Интеграция с программами лояльности (Play Points, Play Pass)
- Real-Time Developer Notifications через Google Cloud Pub/Sub
- Центр уведомлений с историей и группировкой
- Автоматическая установка приложений при pre-registration
- Обязательные уведомления безопасности, которые нельзя отключить

### 1.4 Роли и участники

| Роль | Описание |
|------|----------|
| Пользователь (Consumer) | Конечный пользователь Android-устройства, устанавливающий приложения из Google Play |
| Разработчик (Developer) | Автор/издатель приложений, использующий Play Console |
| Владелец аккаунта разработчика | Создатель аккаунта разработчика с полными правами |
| Администратор Play Console | Участник команды разработки с правами управления |
| Семейный менеджер (Family Manager) | Управляющий семейной группой, одобряет покупки детей |
| Участник семьи (Family Member) | Член семейной группы с ограниченными правами |
| Google Play Protect | Автоматизированная система безопасности |

## 2. Функциональные требования

### FR-GP-NTF-001: Push-уведомления об установке приложений
**Приоритет:** Высокий
**Описание:** Система должна уведомлять пользователя о ходе и завершении установки приложений из Google Play Store.

**Требования:**
- Отображение push-уведомления о начале загрузки приложения
- Прогресс-бар в области уведомлений, показывающий процент загрузки
- Уведомление о завершении загрузки и начале установки
- Финальное уведомление об успешной установке с кнопкой "Открыть"
- Уведомление об ошибке загрузки или установки с причиной и кнопкой "Повторить"
- Возможность отмены загрузки через кнопку в уведомлении
- Поддержка фоновой установки (уведомление появляется даже при закрытом Play Store)

**Состояния уведомления установки:**

| Состояние | Описание | Действия пользователя |
|-----------|----------|----------------------|
| Downloading | Идет загрузка APK/AAB | Отмена, Пауза |
| Installing | Установка на устройство | Ожидание |
| Installed | Установка завершена успешно | Открыть |
| Failed | Ошибка загрузки/установки | Повторить |
| Pending | В очереди на загрузку | Отмена |
| Waiting for Wi-Fi | Ожидает Wi-Fi (по настройке) | Загрузить по мобильной сети |

**Бизнес-правила:**
- Уведомление о завершении установки отображается даже при idle-устройстве (экран выключен)
- При установке нескольких приложений одновременно каждое имеет отдельное уведомление
- Уведомления установки группируются в одну группу "Google Play" в системном шторке
- Если пользователь запретил уведомления от Play Store, загрузка и установка продолжаются, но без видимого уведомления
- При недостаточном месте на устройстве отображается уведомление с рекомендацией освободить место
- Для приложений большого размера (>150 МБ) система запрашивает подтверждение загрузки по мобильной сети

### FR-GP-NTF-002: Уведомления о доступных обновлениях
**Приоритет:** Высокий
**Описание:** Система должна информировать пользователя о наличии обновлений для установленных приложений.

**Требования:**
- Периодическая проверка обновлений для всех установленных приложений
- Push-уведомление при обнаружении доступных обновлений
- Группировка: если доступно несколько обновлений, одно сводное уведомление
- Указание количества приложений с доступными обновлениями
- Кнопка "Обновить все" в уведомлении для массового обновления
- Индивидуальное уведомление для критических обновлений безопасности
- Поддержка автоматического обновления (фоновое обновление без уведомления, если включено)

**Настройки автообновления:**

| Настройка | Поведение уведомлений |
|-----------|----------------------|
| Автообновление по Wi-Fi | Уведомление только после завершения обновления |
| Автообновление по любой сети | Уведомление только после завершения обновления |
| Не обновлять автоматически | Push-уведомление о доступных обновлениях |
| Автообновление конкретного приложения (вкл) | Обновляется тихо, уведомление по завершении |
| Автообновление конкретного приложения (выкл) | Push-уведомление о доступном обновлении |

**Бизнес-правила:**
- Проверка обновлений происходит не реже одного раза в сутки при наличии сети
- При автообновлении пользователь получает уведомление о завершённом обновлении (не о доступном)
- Если автообновление отключено, уведомление о доступных обновлениях отправляется не чаще одного раза в сутки
- Критические обновления безопасности могут инициировать принудительное уведомление независимо от настроек
- Обновления с изменением разрешений (permissions) требуют явного подтверждения пользователя
- Бейдж на иконке Play Store отображает количество доступных обновлений (если включен в настройках)

### FR-GP-NTF-003: Уведомления о завершении обновления
**Приоритет:** Средний
**Описание:** Система должна уведомлять пользователя о завершении обновления приложений, включая массовые обновления.

**Требования:**
- Push-уведомление после завершения обновления каждого приложения (при ручном обновлении)
- Сводное уведомление после завершения массового обновления ("Обновлено N приложений")
- При автообновлении — тихое уведомление (без звука и вибрации) о завершённых обновлениях
- Указание ключевых изменений (What's New) в развёрнутом уведомлении (если разработчик предоставил)
- Уведомление об ошибке обновления с кнопкой "Повторить"

**Бизнес-правила:**
- Сводное уведомление при массовом обновлении формируется после завершения всех обновлений в пакете
- Если часть обновлений не удалась, уведомление содержит информацию об успешных и неудачных обновлениях
- Автообновления формируют уведомление с низким приоритетом (silent notification) — без звука и вибрации
- Уведомление о What's New отображается только если разработчик заполнил раздел Release Notes

### FR-GP-NTF-004: Рекомендательные уведомления (персонализированные)
**Приоритет:** Высокий
**Описание:** Система должна отправлять персонализированные push-уведомления с рекомендациями приложений и игр на основе предпочтений и поведения пользователя.

**Требования:**
- Персонализация на основе: истории установок, категорий приложений, поисковых запросов, демографии, активности
- Рекомендации новых приложений, похожих на установленные
- Рекомендации трендовых приложений в интересующих категориях
- Напоминания о приложениях, загруженных, но не открытых (App Reminder Notifications)
- Изображения и баннеры приложений в уведомлении для повышения кликабельности
- Указание причины рекомендации ("Похоже на [установленное приложение]", "Популярно в вашем регионе")

**Типы рекомендательных уведомлений:**

| Тип | Описание | Частота |
|-----|----------|---------|
| Новое приложение | Рекомендация нового релиза в интересующей категории | Не чаще 2 раз в неделю |
| Трендовое | Популярное приложение, которое может заинтересовать | Не чаще 1 раза в неделю |
| Напоминание об установленном | Приложение загружено, но не открыто | Через 3-7 дней после установки |
| Редакторский выбор | Приложение из подборки Editor's Choice | Не чаще 1 раза в месяц |
| Сезонное | Приложения к событиям/праздникам | По событиям |

**Бизнес-правила:**
- Рекомендательные уведомления являются отключаемыми через настройки "Notifications & Offers"
- Частота рекомендательных уведомлений ограничена для предотвращения спама (rate limiting)
- Напоминания об установленных, но не открытых приложениях включают изображение и чёткую причину открытия
- Рекомендации учитывают возрастные ограничения (Family Link) и региональную доступность
- Персонализация отключается при выключении опции "Personalized recommendations" в настройках Google
- Рекомендательные уведомления не отправляются для платных приложений без явного согласия пользователя

### FR-GP-NTF-005: Уведомления о подписках и предстоящих списаниях
**Приоритет:** Высокий
**Описание:** Система должна уведомлять пользователя о статусе подписок, предстоящих списаниях, изменениях цен и проблемах с оплатой.

**Требования:**
- Уведомление о предстоящем списании за N дней до даты продления подписки
- Уведомление о завершении пробного периода (trial) с информацией о предстоящем списании
- Уведомление о неудачной попытке списания (payment declined)
- Уведомление об изменении цены подписки с запросом согласия
- Уведомление о завершении вводного периода (introductory pricing) и переходе на полную цену
- Уведомление о приближающемся окончании сезонного пропуска (season pass)
- Уведомление об отмене подписки с информацией о дате окончания доступа
- Уведомление о восстановлении подписки после паузы или account hold

**Состояния подписки и соответствующие уведомления:**

| Состояние | Уведомление | Канал |
|-----------|-------------|-------|
| Trial ending | "Пробный период заканчивается через N дней" | Push + Email |
| Renewal upcoming | "Подписка [App] будет продлена [дата] на сумму [X]" | Push + Email |
| Payment declined | "Не удалось списать средства. Обновите способ оплаты" | Push + Email |
| Price increase | "Цена подписки [App] изменится с [X] на [Y]" | Push + Email |
| Subscription canceled | "Подписка [App] отменена. Доступ до [дата]" | Push + Email |
| Subscription paused | "Подписка [App] приостановлена. Возобновится [дата]" | Push + Email |
| Subscription resumed | "Подписка [App] возобновлена" | Push + Email |
| Grace period | "Проблема с оплатой. Обновите способ оплаты в течение [N] дней" | Push + Email |
| Account hold | "Подписка приостановлена из-за проблем с оплатой" | Push + Email |
| Subscription expired | "Подписка [App] истекла" | Push + Email |
| Introductory price ending | "Вводная цена заканчивается. Далее [полная цена]" | Push + Email |

**Бизнес-правила:**
- Уведомление о renewal отправляется не позднее чем за 24 часа до списания
- При неудачном платеже Google Play использует grace period (обычно 7-30 дней), в течение которого пользователь сохраняет доступ к контенту
- После grace period подписка переходит в account hold — доступ прекращается, но подписка не отменяется
- Уведомления о проблемах с оплатой отправляются многократно в течение grace period
- При изменении цены пользователь должен дать явное согласие; без согласия подписка отменяется по окончании текущего периода
- Разработчик не контролирует текст уведомлений о подписках — они генерируются Google Play автоматически
- Уведомления о подписках являются обязательными и не могут быть отключены пользователем

### FR-GP-NTF-006: Уведомления о промо-акциях и скидках
**Приоритет:** Средний
**Описание:** Система должна информировать пользователя о специальных предложениях, скидках на приложения, промо-кодах и сезонных акциях.

**Требования:**
- Push-уведомления о скидках на приложения и игры из интересующих категорий
- Уведомления о сезонных распродажах Google Play (летняя распродажа, Black Friday и т.д.)
- Уведомления о бесплатных предложениях для платных приложений
- Уведомления о доступных промо-кодах (Offers Tab)
- Уведомления об эксклюзивных предложениях (для участников Play Points, Play Pass)
- Группировка предложений в разделе "Offers" в Play Store

**Типы промо-уведомлений:**

| Тип | Описание | Пример |
|-----|----------|--------|
| Скидка на приложение | Снижение цены приложения или игры | "[Game] -60% — $1.99 вместо $4.99" |
| Бесплатное на время | Платное приложение временно бесплатно | "[App] бесплатно в течение 48 часов" |
| In-app промо | Специальное предложение внутри приложения | "Получите бонус в [Game]" |
| Сезонная акция | Общая распродажа Google Play | "Летняя распродажа: скидки до 80%" |
| Промо-код | Код на бесплатный контент | "Используйте код для получения бонуса" |
| Play Points промо | Умноженные баллы за покупки | "3x баллов Play Points на этой неделе" |

**Бизнес-правила:**
- Промо-уведомления являются полностью отключаемыми в настройках "Notifications & Offers"
- Частота промо-уведомлений ограничена (не более 3-5 в неделю для предотвращения усталости от уведомлений)
- Скидочные уведомления отправляются только для категорий, в которых пользователь активен
- Google Play не уведомляет автоматически о снижении цены приложений из wishlist (нативной функции нет)
- Промо-акции разработчиков отображаются в Offers Tab и могут генерировать уведомление
- Региональные акции учитывают геолокацию пользователя

### FR-GP-NTF-007: Уведомления об ответах разработчика на отзывы
**Приоритет:** Средний
**Описание:** Система должна уведомлять пользователя, когда разработчик приложения отвечает на его отзыв (review) в Google Play Store.

**Требования:**
- Push-уведомление при получении ответа разработчика на отзыв пользователя
- Email-уведомление о полученном ответе разработчика
- Содержимое уведомления: название приложения, текст ответа разработчика
- Возможность перейти к полному отзыву и обновить его из уведомления
- Возможность ответить разработчику (обновить отзыв) прямо из email

**Бизнес-правила:**
- Пользователь получает push-уведомление и email только при первом ответе разработчика на созданный или изменённый отзыв
- При повторных ответах разработчика (без изменения отзыва пользователем) повторное уведомление не отправляется
- Если пользователь обновляет отзыв, счётчик уведомлений сбрасывается — следующий ответ разработчика снова вызовет уведомление
- Email-уведомление содержит ссылку для прямого обновления отзыва
- Уведомления об ответах разработчика можно отключить в настройках

---

### FR-GP-NTF-008: Уведомления Play Points
**Приоритет:** Средний
**Описание:** Система должна уведомлять участников программы Google Play Points о начислениях баллов, доступных миссиях, акциях с множителями и изменениях уровня.

**Требования:**
- Уведомление о начислении баллов за покупку
- Уведомление о доступной новой миссии (mission) или событии (event)
- Уведомление о запуске множителя баллов (Boost/Multiplier event)
- Уведомление о повышении уровня (Bronze -> Silver -> Gold -> Platinum -> Diamond)
- Уведомление о скором истечении неиспользованных баллов (за 30 дней до истечения)
- Уведомление о доступном еженедельном призе (Weekly Prize)
- Уведомление о новых вариантах использования баллов (redemption options)

**Уровни Play Points и бонусы:**

| Уровень | Мин. баллов/год | Множитель | Уведомления |
|---------|----------------|-----------|-------------|
| Bronze | 0 | 1x | Базовые |
| Silver | 200 | 1.1x | + Уведомления о бонусах уровня |
| Gold | 600 | 1.2x | + Приоритетные предложения |
| Platinum | 2000 | 1.4x | + Эксклюзивные события |
| Diamond | 5000 | 1.5x | + VIP-уведомления |

**Бизнес-правила:**
- Баллы истекают через 12 месяцев после начисления, если не использованы
- Уведомление об истечении отправляется за 30 дней до даты экспирации
- Множители (Boost events) действуют ограниченное время; уведомление отправляется при старте и за 24 часа до окончания
- Play Points уведомления доступны только для пользователей, активировавших участие в программе
- Уведомления о Play Points можно отключить отдельно от других категорий уведомлений Play Store
- При смене уровня уведомление включает описание новых привилегий уровня

---

### FR-GP-NTF-009: Уведомления Play Pass
**Приоритет:** Средний
**Описание:** Система должна уведомлять подписчиков Google Play Pass о новых приложениях в каталоге, статусе подписки и персонализированных рекомендациях.

**Требования:**
- Уведомление о новых приложениях и играх, добавленных в каталог Play Pass
- Персонализированные рекомендации из каталога Play Pass на основе предпочтений
- Уведомление о статусе подписки Play Pass (продление, проблемы с оплатой, отмена)
- Уведомления о персонализированных подборках по выбранным жанрам (interest picker)
- Уведомление о семейном доступе (Play Pass Family sharing) — добавление/удаление участников

**Бизнес-правила:**
- Уведомления о новом контенте Play Pass отправляются не чаще 1 раза в неделю
- Рекомендации учитывают жанры, выбранные пользователем через interest picker
- Уведомления о статусе подписки Play Pass обрабатываются как стандартные подписочные уведомления (FR-GP-NTF-005)
- Play Pass Family sharing позволяет до 5 участников семейной группы; уведомления об изменении состава отправляются Family Manager
- Play Pass уведомления доступны только для активных подписчиков

### FR-GP-NTF-010: Уведомления о pre-registration
**Приоритет:** Высокий
**Описание:** Система должна уведомлять пользователей, зарегистрировавших предварительный интерес (pre-registration) к приложению, о его доступности для скачивания.

**Требования:**
- Push-уведомление при публикации приложения в production (запуск)
- Автоматическая установка приложения на устройство пользователя (auto-install) при выполнении условий
- Уведомление о завершении автоматической установки
- Уведомление о предстоящем запуске (reminder), если разработчик настроил
- Уведомление о бонусах за pre-registration (если разработчик предоставляет in-app rewards)

**Условия автоматической установки:**

| Условие | Требование |
|---------|-----------|
| Версия Android | Android 6.0 (Marshmallow) и выше |
| Версия Play Store | 19.2+ |
| Хранилище | Достаточно свободного места |
| Сеть | Наличие подключения Wi-Fi (или разрешение на мобильные данные) |
| Разрешения | Приложение не требует новых runtime permissions |

**Бизнес-правила:**
- Пользователи, имеющие тестовую версию приложения, НЕ получают push-уведомление о релизе
- Разработчик может одновременно иметь не более 2 приложений в статусе pre-registration
- Auto-install происходит только на устройствах, удовлетворяющих всем условиям совместимости
- При невозможности auto-install пользователь получает push-уведомление с кнопкой "Установить"
- Pre-registration бонусы (in-app rewards) автоматически применяются при первом запуске приложения
- Уведомление о pre-registration нельзя отключить для конкретного приложения после регистрации (только отмена самой pre-registration)

### FR-GP-NTF-011: Уведомления безопасности (Google Play Protect)
**Приоритет:** Критический
**Описание:** Система Google Play Protect должна уведомлять пользователя об обнаруженных угрозах безопасности, потенциально вредоносных приложениях и нарушениях приватности.

**Требования:**
- Уведомление при обнаружении потенциально вредоносного приложения (PHA — Potentially Harmful Application)
- Уведомление при автоматическом удалении вредоносного приложения
- Уведомление при блокировке установки приложения из неизвестного источника
- Уведомление о приложении, удалённом из Google Play за нарушение политик
- Privacy alerts — уведомления о приложениях с доступом к персональным данным, нарушающих политики
- Периодическое уведомление о результатах сканирования устройства
- Уведомление-напоминание при отключённом Play Protect

**Типы угроз и действия:**

| Тип угрозы | Действие системы | Уведомление |
|------------|-----------------|-------------|
| Confirmed malware | Автоматическое удаление | "Приложение [X] удалено для защиты устройства" |
| Potentially harmful | Деактивация + уведомление | "Приложение [X] отключено. Рекомендуем удалить" |
| Privacy violation | Уведомление | "Приложение [X] может получать доступ к вашим данным" |
| Removed from Play Store | Уведомление | "Приложение [X] удалено из Google Play" |
| Sideloaded suspicious | Предупреждение при установке | "Это приложение неизвестно. Сканирование рекомендуется" |
| Outdated security | Рекомендация обновить | "Приложение [X] устарело и может быть небезопасным" |

**Бизнес-правила:**
- Уведомления Google Play Protect являются обязательными и не могут быть полностью отключены пользователем
- Уведомление "Security and errors" можно отключить в настройках, но критические угрозы (confirmed malware) по-прежнему генерируют уведомление
- Автоматическое удаление malware происходит без подтверждения пользователя; пользователь уведомляется post factum
- Для приложений из неизвестных источников (sideload) Play Protect сканирует APK перед установкой
- При отключённом Play Protect система периодически напоминает пользователю о рисках и рекомендует включить защиту
- Play Protect проверяет приложения при установке и периодически сканирует устройство (обычно раз в сутки)
- Корпоративные устройства (Android Enterprise) управляются через MDM-политики; Play Protect уведомления могут быть настроены администратором

### FR-GP-NTF-012: Настройки уведомлений (гранулярный контроль)
**Приоритет:** Высокий
**Описание:** Пользователь должен иметь возможность управлять категориями уведомлений Google Play Store через системные настройки Android и настройки приложения Play Store.

**Требования:**
- Доступ через: Настройки Android -> Приложения -> Google Play Store -> Уведомления
- Доступ через: Play Store -> Профиль -> Настройки -> Общие -> Уведомления
- Отдельные переключатели для каждой категории (notification channel)
- Управление приоритетом уведомлений (звук, вибрация, badge, heads-up)
- Страница "Notifications & Offers" с историей полученных предложений

**Категории уведомлений (Notification Channels):**

| Категория | Описание | Можно отключить |
|-----------|----------|----------------|
| Updates available | Доступные обновления приложений | Да |
| Auto-update complete | Завершение автообновления | Да |
| Installation status | Статус установки/загрузки | Частично (можно убрать звук) |
| Offers and promotions | Промо-акции и скидки | Да |
| Recommendations | Персонализированные рекомендации | Да |
| Pre-registration | Готовность предзарегистрированного приложения | Да |
| Play Points | Баллы, миссии, уровень | Да |
| Subscriptions | Продление, проблемы с оплатой подписок | Нет (обязательные) |
| Security and errors | Google Play Protect и ошибки | Частично |
| Review replies | Ответы разработчиков на отзывы | Да |
| Play Pass | Новый контент и подписка Play Pass | Да |
| Billing | Квитанции, проблемы с оплатой | Нет (обязательные) |

**Уровни контроля на каждую категорию:**
- Вкл/Выкл (основной переключатель)
- Звук (звуковое оповещение)
- Вибрация
- Показ на экране блокировки
- Badge на иконке приложения
- Приоритет (heads-up / silent / default)

**Бизнес-правила:**
- При глобальном отключении уведомлений для Play Store все категории отключаются, кроме обязательных (Security critical, Billing, Subscriptions)
- Настройки Notification Channels привязаны к устройству и не синхронизируются между устройствами
- Страница "Notifications & Offers" хранит историю полученных предложений и уведомлений для просмотра
- Android 13+ требует явное разрешение на push-уведомления от приложений (POST_NOTIFICATIONS permission); Play Store запрашивает это разрешение при первом запуске
- Android 15 автоматически скрывает неиспользуемые notification channels для снижения визуального шума
- При сбросе данных приложения Play Store все настройки уведомлений сбрасываются к значениям по умолчанию

### FR-GP-NTF-016: Real-Time Developer Notifications (RTDN)
**Приоритет:** Высокий
**Описание:** Система должна обеспечивать серверные уведомления в реальном времени для разработчиков приложений о событиях подписок и покупок через Google Cloud Pub/Sub.

**Требования:**
- Доставка уведомлений через Google Cloud Pub/Sub при каждом изменении состояния подписки
- Поддержка подписочных уведомлений (SubscriptionNotification) со всеми типами событий
- Поддержка уведомлений о разовых покупках (OneTimeProductNotification)
- Конфигурация через Play Console -> Monetization Setup -> Real-time developer notifications
- Два режима: подписки + voided purchases или все уведомления (включая разовые покупки)

**Типы SubscriptionNotification:**

| notificationType | Код | Описание |
|------------------|-----|----------|
| SUBSCRIPTION_RECOVERED | 1 | Подписка восстановлена из account hold или возобновлена после паузы |
| SUBSCRIPTION_RENEWED | 2 | Активная подписка продлена |
| SUBSCRIPTION_CANCELED | 3 | Подписка отменена (добровольно или принудительно) |
| SUBSCRIPTION_PURCHASED | 4 | Новая подписка оформлена |
| SUBSCRIPTION_ON_HOLD | 5 | Подписка перешла в account hold |
| SUBSCRIPTION_IN_GRACE_PERIOD | 6 | Подписка в grace period (проблемы с оплатой) |
| SUBSCRIPTION_RESTARTED | 7 | Пользователь восстановил подписку через Play -> Аккаунт -> Подписки |
| SUBSCRIPTION_PRICE_CHANGE_CONFIRMED | 8 | (DEPRECATED) Пользователь подтвердил изменение цены |
| SUBSCRIPTION_DEFERRED | 9 | Время рекуррента продлено |
| SUBSCRIPTION_PAUSED | 10 | Подписка приостановлена |
| SUBSCRIPTION_PAUSE_SCHEDULE_CHANGED | 11 | Изменён график паузы |
| SUBSCRIPTION_REVOKED | 12 | Подписка отозвана до истечения |
| SUBSCRIPTION_EXPIRED | 13 | Подписка истекла |
| SUBSCRIPTION_ITEMS_CHANGED | 17 | Изменён элемент в подписочном бандле |
| SUBSCRIPTION_CANCELLATION_SCHEDULED | 18 | Запланирована отмена в конце обязательства (installment) |
| SUBSCRIPTION_PRICE_CHANGE_UPDATED | 19 | Обновлены детали изменения цены |
| SUBSCRIPTION_PENDING_PURCHASE_CANCELED | 20 | Отменена ожидающая транзакция подписки |
| SUBSCRIPTION_PRICE_STEP_UP_CONSENT_UPDATED | 22 | Начался или получено согласие на повышение цены (step-up) |

**Типы OneTimeProductNotification:**

| notificationType | Код | Описание |
|------------------|-----|----------|
| ONE_TIME_PRODUCT_PURCHASED | 1 | Разовая покупка совершена |
| ONE_TIME_PRODUCT_CANCELED | 2 | Ожидающая разовая покупка отменена |

**Бизнес-правила:**
- RTDN сообщает только о факте изменения состояния; для получения полной информации разработчик должен вызвать purchases.subscriptionsv2.get API
- Для настройки RTDN необходимо создать Google Cloud Pub/Sub topic и предоставить доступ сервисному аккаунту google-play-developer-notifications@system.gserviceaccount.com с ролью Pub/Sub Publisher
- RTDN является единственным официальным механизмом серверных уведомлений от Google Play к бэкенду разработчика
- Сообщения в Pub/Sub имеют гарантию at-least-once delivery; разработчик должен обрабатывать дупликаты
- Задержка доставки RTDN обычно составляет несколько секунд, но не гарантируется строгий порядок
- Для тестирования RTDN доступна песочница (sandbox) с тестовыми покупками

### FR-GP-NTF-017: Уведомления Play Console для разработчиков
**Приоритет:** Высокий
**Описание:** Система Play Console должна уведомлять разработчиков о ключевых событиях, связанных с их приложениями: политики, обзор, статистика, аномалии.

**Требования:**
- Email-уведомления о нарушениях политик (policy violations)
- Email-уведомления о результатах обзора приложений (app review)
- Email о предупреждениях (Fair Warnings) и угрозе приостановки
- Уведомления об аномалиях в крашах и ANR (Application Not Responding)
- Уведомления о значимых изменениях рейтинга
- Уведомления о новых отзывах (фильтруемые по рейтингу)
- Уведомления о статусе релиза (публикация, отклонение, rollout progress)
- In-app уведомления в Play Console (Inbox)

**Типы уведомлений Play Console:**

| Категория | Типы событий | Канал | Критичность |
|-----------|-------------|-------|-------------|
| Policy compliance | Violation detected, Warning issued, App removed, App suspended | Email | Критическая |
| App review | Review complete, Rejected (with reasons), Changes requested | Email | Высокая |
| Fair warnings | Warning about potential suspension | Email | Критическая |
| Release management | Published, Rollout %, Staged rollout issues | Email + Console | Средняя |
| Crash/ANR alerts | Spike in crashes, New crash cluster | Email + Console | Высокая |
| Ratings & reviews | Rating change, New review (configurable stars) | Email + Console | Средняя |
| Revenue | Revenue anomaly, Subscription metrics change | Console | Средняя |
| SDK/API deprecation | Deadline approaching, Target API level requirement | Email | Высокая |
| Account status | Developer account warning, Termination risk | Email | Критическая |

**Процесс уведомлений при нарушении политик:**

| Этап | Уведомление | Действия разработчика | Срок |
|------|-------------|----------------------|------|
| Обнаружение нарушения | Email "Notification from Google Play" | Изучить нарушение | - |
| Warning (предупреждение) | Email с деталями нарушения | Исправить нарушение | 7-30 дней |
| App rejection | Email с причинами отклонения | Исправить и перезагрузить | До исправления |
| App removal | Email о удалении из Play Store | Апелляция или исправление | 7 дней на апелляцию |
| App suspension | Email о приостановке | Апелляция | 7 дней на апелляцию |
| Account termination | Email о завершении аккаунта | Апелляция | 7 дней |

**Бизнес-правила:**
- Уведомления о нарушениях политик являются обязательными и отправляются на email аккаунта разработчика
- Разработчик может настроить получателей уведомлений: владелец аккаунта + дополнительные адреса
- Fair Warning означает, что приложение близко к приостановке; повторное нарушение приведёт к suspension
- При отклонении обновления предыдущая версия остаётся доступна в Play Store
- Уведомления о новых отзывах можно фильтровать по количеству звёзд (например, только 1-2 звезды)
- Crash/ANR alerts срабатывают при превышении порогового значения (configurable threshold)
- Уведомления о Target API level requirement отправляются заблаговременно (за 3-6 месяцев до дедлайна)

---

### FR-GP-NTF-018: Уведомления-напоминания о приложениях (App Reminders)
**Приоритет:** Средний
**Описание:** Система должна отправлять уведомления-напоминания пользователям о высококачественных приложениях, которые они загрузили, но не использовали.

**Требования:**
- Обнаружение приложений, загруженных, но не открытых в течение определённого периода
- Push-уведомление с изображением приложения и причиной для его использования
- Персонализированное описание ценности приложения
- Глубокая ссылка (deep link) для быстрого открытия приложения
- Ограничение частоты: не более одного напоминания на приложение

**Бизнес-правила:**
- Напоминание отправляется через 3-7 дней после установки, если приложение ни разу не открыто
- Напоминание отправляется только для приложений с высоким рейтингом и хорошими метриками вовлечения
- Каждое приложение получает не более 1 напоминания (без повторных)
- Напоминания являются частью категории "Recommendations" и отключаются вместе с ней
- Уведомление включает изображение (скриншот или иконку) для повышения вовлечённости

---

### FR-GP-NTF-019: Уведомления о платежах и возвратах
**Приоритет:** Высокий
**Описание:** Система должна уведомлять пользователя обо всех финансовых операциях: покупки, возвраты, проблемы с оплатой, изменения способа оплаты.

**Требования:**
- Push-уведомление об успешной покупке приложения или in-app продукта
- Push-уведомление при неудачной попытке оплаты
- Email-квитанция для каждой покупки (FR-GP-NTF-013)
- Push-уведомление о возврате средств (refund)
- Уведомление при добавлении или удалении способа оплаты
- Уведомление при использовании подарочной карты (gift card) или промо-кода
- Уведомление об ожидающем платеже (pending payment) для медленных способов оплаты

**Состояния платежа и уведомления:**

| Состояние | Уведомление | Каналы |
|-----------|-------------|--------|
| Payment successful | "Покупка завершена: [App/Item] — $X.XX" | Push + Email |
| Payment pending | "Покупка обрабатывается: [App/Item]" | Push |
| Payment failed | "Оплата не прошла. Проверьте способ оплаты" | Push + Email |
| Refund initiated | "Возврат средств за [App/Item] обрабатывается" | Push + Email |
| Refund completed | "Возврат $X.XX за [App/Item] завершён" | Push + Email |
| Gift card redeemed | "Подарочная карта активирована. Баланс: $X.XX" | Push |
| Promo code applied | "Промо-код применён: [описание]" | Push |

**Бизнес-правила:**
- Все финансовые уведомления являются обязательными и не могут быть отключены
- Возврат средств для подписок обрабатывается в течение 1-4 рабочих дней
- При покупке через семейный способ оплаты квитанция отправляется Family Manager
- Pending payment может длиться до 48-72 часов для некоторых способов оплаты
- При превышении лимита подарочной карты запрашивается дополнительный способ оплаты
- Подозрительные финансовые операции могут быть заблокированы с уведомлением о необходимости верификации

---

### FR-GP-NTF-020: Уведомления об удалённых и отключённых приложениях
**Приоритет:** Средний
**Описание:** Система должна уведомлять пользователя о приложениях, удалённых из Google Play Store или отключённых по инициативе Google.

**Требования:**
- Уведомление когда установленное приложение удалено из Google Play
- Уведомление о причине удаления (нарушение политик, запрос разработчика)
- Рекомендация альтернативного приложения (если доступно)
- Уведомление при автоматическом отключении приложения из-за угрозы безопасности (Play Protect)
- Уведомление о приложениях, больше не совместимых с устройством после обновления Android

**Бизнес-правила:**
- Приложение, удалённое из Play Store, остаётся установленным на устройстве пользователя
- Уведомление предупреждает, что приложение больше не получит обновлений
- При выявлении угрозы безопасности Play Protect может удалить приложение автоматически (FR-GP-NTF-011)
- Приложения, не обновлённые до минимального Target API Level, помечаются как "устаревшие"
- Уведомление о несовместимости отправляется только после системного обновления Android

---

### FR-GP-NTF-021: Уведомления о разрешениях приложений (Permission Notifications)
**Приоритет:** Средний
**Описание:** Система должна информировать пользователя об изменениях в разрешениях при обновлении приложений и о приложениях с избыточным доступом.

**Требования:**
- Уведомление при обновлении приложения с новыми разрешениями (для ручного подтверждения)
- Периодическое уведомление о приложениях с неиспользуемыми разрешениями (auto-revoke)
- Уведомление при автоматическом отзыве разрешений у неиспользуемых приложений
- Privacy Dashboard summary (Android 12+) — периодическая сводка о доступах приложений

**Бизнес-правила:**
- Если обновление приложения добавляет новые dangerous permissions, автообновление приостанавливается до подтверждения пользователя
- Android автоматически отзывает runtime permissions у приложений, не используемых более 3 месяцев, с уведомлением
- Автоматический отзыв permissions не применяется к приложениям, которые пользователь явно исключил
- Уведомления об auto-revoke являются системными (от Android, не от Play Store), но связаны с экосистемой

---

### FR-GP-NTF-022: Уведомления о предзаказах (Pre-order Notifications)
**Приоритет:** Средний
**Описание:** Система должна уведомлять пользователей о предзаказанных приложениях, играх, книгах и фильмах.

**Требования:**
- Уведомление о принятии предзаказа (подтверждение)
- Уведомление о предстоящей дате релиза (за 1-3 дня)
- Уведомление о доступности для скачивания (в день релиза)
- Уведомление об автоматическом списании средств при релизе
- Уведомление при изменении цены предзаказа (если цена снижена, списывается меньшая сумма)
- Уведомление при отмене предзаказа (возврат средств)

**Бизнес-правила:**
- При предзаказе средства не списываются до дня релиза
- Если цена снижается между предзаказом и релизом, пользователь платит меньшую сумму
- Пользователь может отменить предзаказ в любое время до релиза без штрафа
- При изменении даты релиза пользователь получает уведомление с новой датой
- Автозагрузка при релизе работает аналогично pre-registration auto-install (FR-GP-NTF-010)

---

### FR-GP-NTF-023: Уведомления об ограничении контента (Content Restrictions)
**Приоритет:** Средний
**Описание:** Система должна уведомлять о действиях, связанных с возрастными ограничениями, родительским контролем и региональными ограничениями.

**Требования:**
- Уведомление при попытке установки приложения, превышающего установленные возрастные ограничения
- Уведомление Family Manager при попытке ребёнка установить приложение с высоким рейтингом
- Уведомление при изменении возрастного рейтинга установленного приложения
- Уведомление о недоступности приложения в текущем регионе (при смене страны)

**Бизнес-правила:**
- Возрастные ограничения определяются рейтинговой системой (IARC, PEGI, ESRB и др.)
- Family Link позволяет Family Manager устанавливать максимально допустимый возрастной рейтинг
- При попытке установки приложения выше допустимого рейтинга ребёнком, запрос может быть направлен Family Manager для одобрения
- Региональные ограничения применяются на основе страны Google-аккаунта, а не текущей геолокации

## 4. Бизнес-правила и логика

### 4.1 Иерархия обязательности уведомлений

| Уровень | Описание | Примеры | Отключаемые |
|---------|----------|---------|-------------|
| 1. Критические безопасности | Угрозы устройству | Play Protect malware removal | Нет |
| 2. Финансовые обязательные | Списания, квитанции | Purchase receipt, subscription renewal | Нет |
| 3. Регуляторные обязательные | Политики, разработческие | Policy violation, fair warning | Нет |
| 4. Функциональные | Установка, обновление | Download complete, update available | Частично |
| 5. Информационные | Рекомендации, промо | New app suggestion, sale | Полностью |

### 4.2 Правила частоты и rate limiting

| Категория уведомлений | Максимальная частота | Период |
|----------------------|---------------------|--------|
| Рекомендации приложений | 2 уведомления | В неделю |
| Трендовые приложения | 1 уведомление | В неделю |
| Промо-акции | 3-5 уведомлений | В неделю |
| Play Points события | 3 уведомления | В неделю |
| Play Pass контент | 1 уведомление | В неделю |
| Напоминание о приложении | 1 уведомление | На приложение (всего) |
| Обновления доступны | 1 уведомление | В сутки |
| Подписки (проблемы) | Без ограничения | При каждом событии |
| Безопасность | Без ограничения | При каждой угрозе |

### 4.3 Правила подавления уведомлений

**Режим "Не беспокоить" (DND):**
- В режиме DND все уведомления Google Play подавляются, кроме критических безопасности (Play Protect: confirmed malware)
- Уведомления доставляются в шторку тихо и отображаются при выходе из DND

**Battery Saver:**
- В режиме энергосбережения фоновая проверка обновлений и рекомендаций приостанавливается
- Финансовые и безопасностные уведомления продолжают доставляться

**Отсутствие сети:**
- При отсутствии подключения push-уведомления помещаются в очередь FCM
- При восстановлении подключения уведомления доставляются с учётом актуальности (expired уведомления не доставляются)

**Multiple accounts:**
- Уведомления отображаются для активного Google-аккаунта
- Уведомления от других аккаунтов помещаются в очередь и доставляются при переключении

### 4.4 Правила для разных ролей (Consumer)

| Действие | Обычный пользователь | Family Manager | Ребёнок (Family Link) |
|---------|---------------------|----------------|----------------------|
| Получать уведомления об обновлениях | Да | Да | Да |
| Управлять настройками уведомлений | Полностью | Полностью | Ограничено |
| Получать промо-уведомления | Да (отключаемые) | Да (отключаемые) | Нет |
| Запрос на покупку | Покупка напрямую | Покупка напрямую | Через Family Manager |
| Получать квитанции | Да | Да + квитанции семьи | Нет |
| Play Points уведомления | Да | Да | Нет |
| Play Protect уведомления | Да | Да | Да (управляется FM) |

### 4.5 Правила для ролей (Developer)

| Owner | Все | Все | Все | Конфигурация |

### 4.6 Жизненный цикл подписки и уведомления (Consumer + Developer)

```
[Покупка] → SUBSCRIPTION_PURCHASED (RTDN:4)
    │        Push + Email пользователю
    ▼
[Активна] → SUBSCRIPTION_RENEWED (RTDN:2) при каждом продлении
    │        Push + Email о предстоящем списании
    │
    ├── [Отмена] → SUBSCRIPTION_CANCELED (RTDN:3)
    │       Push: "Доступ до [дата]"
    │       → [Истечение] → SUBSCRIPTION_EXPIRED (RTDN:13)
    │
    ├── [Проблема с оплатой]
    │       → [Grace Period] → SUBSCRIPTION_IN_GRACE_PERIOD (RTDN:6)
    │       │   Push + Email: "Обновите способ оплаты"
    │       │   Доступ сохраняется
    │       │
    │       → [Account Hold] → SUBSCRIPTION_ON_HOLD (RTDN:5)
    │       │   Push + Email: "Подписка приостановлена"
    │       │   Доступ заблокирован
    │       │
    │       → [Восстановление] → SUBSCRIPTION_RECOVERED (RTDN:1)
    │           Push: "Подписка восстановлена"
    │
    ├── [Пауза] → SUBSCRIPTION_PAUSED (RTDN:10)
    │       Push: "Подписка приостановлена до [дата]"
    │       → [Возобновление] → SUBSCRIPTION_RECOVERED (RTDN:1)
    │
    └── [Изменение цены]
            → SUBSCRIPTION_PRICE_CHANGE_UPDATED (RTDN:19)
            Push + Email: "Цена изменится с [X] на [Y]"
            → Согласие/Отказ → SUBSCRIPTION_PRICE_STEP_UP_CONSENT_UPDATED (RTDN:22)
```
