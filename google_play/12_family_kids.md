# Google Play: Модуль "Семейные функции и детская безопасность" (Family & Kids Safety)

## Обзор модуля

Модуль семейных функций и детской безопасности в Google Play представляет собой комплексную экосистему инструментов для организации совместного использования контента семьёй, защиты детей от нежелательного контента и управления цифровыми привычками несовершеннолетних. Модуль объединяет несколько ключевых подсистем:

- **Семейная группа (Family Group)** — объединение до 6 участников с общим доступом к сервисам Google
- **Семейная библиотека (Family Library)** — механизм совместного доступа к купленному контенту
- **Семейный способ оплаты (Family Payment Method)** — централизованное управление покупками
- **Google Family Link** — приложение родительского контроля для управления устройствами и аккаунтами детей
- **Родительский контроль (Parental Controls)** — фильтрация контента по возрастным рейтингам
- **Программа "Designed for Families"** — сертификация приложений для детей
- **Teacher Approved** — программа оценки приложений учителями
- **Детский раздел** — выделенная секция в Google Play с одобренным контентом

### Ключевые принципы

- Семейная группа имеет строгую иерархию ролей: Менеджер > Родитель > Участник > Ребёнок
- Менеджер семейной группы несёт финансовую ответственность за покупки всех участников
- Дети до 13 лет (или применимого возраста в стране) обязательно имеют контролируемый аккаунт
- Все приложения для детей подчиняются ужесточённым требованиям COPPA и GDPR
- Родительский контроль привязан к профилю устройства и защищён PIN-кодом
- Фильтрация контента основана на международной системе возрастных рейтингов IARC

## FR-FK-001: Создание семейной группы (Family Group)

**Priority**: P0-Critical

**Description**: Пользователь Google (18+) может создать семейную группу, объединяющую до 6 аккаунтов Google. Создатель автоматически становится менеджером семейной группы (Family Manager). Семейная группа является основой для всех семейных функций: совместного доступа к контенту, семейного способа оплаты, родительского контроля и управления детскими аккаунтами.

**Acceptance Criteria**:
- [ ] Пользователь может создать семейную группу из настроек Google Play или через families.google.com
- [ ] Создатель автоматически получает роль Family Manager
- [ ] Семейная группа может содержать от 1 до 6 участников (включая менеджера)
- [ ] Только один пользователь может быть менеджером семейной группы
- [ ] Пользователь может состоять только в одной семейной группе одновременно
- [ ] При создании группы автоматически создаётся семейный календарь в Google Calendar
- [ ] При создании группы менеджеру предлагается настроить семейный способ оплаты
- [ ] Создание семейной группы бесплатно и доступно в поддерживаемых странах

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Только пользователь 18+ (или совершеннолетний в своей стране) может создать семейную группу |
| BR-002 | Пользователь не может создать семейную группу, если уже состоит в другой |
| BR-003 | Смена страны семейной группы невозможна; страна фиксируется по стране менеджера |
| BR-004 | Пользователь, покинувший или удалённый из семейной группы, не может вступить в новую группу в течение 12 месяцев |
| BR-005 | Менеджер не может покинуть группу без её удаления или передачи роли менеджера |
| BR-006 | При удалении семейной группы все участники теряют доступ к общим ресурсам (Family Library, семейный способ оплаты) |

## FR-FK-002: Роли и полномочия в семейной группе

**Priority**: P0-Critical

**Description**: В семейной группе Google существует четырёхуровневая иерархия ролей: Family Manager, Parent, Member и Child. Каждая роль определяет объём полномочий участника в контексте управления группой, одобрения покупок, контроля устройств и доступа к контенту.

**Acceptance Criteria**:
- [ ] В группе обязательно присутствует ровно один Family Manager
- [ ] Менеджер может назначить одного или нескольких участников на роль Parent
- [ ] Участники 18+ по умолчанию имеют роль Member
- [ ] Участники до 13 лет (или применимого возраста в стране) всегда имеют роль Child
- [ ] Участники 13–17 лет могут быть в роли Member с контролируемым аккаунтом
- [ ] Роли отображаются в настройках семейной группы

### FR-FK-002.1: Полномочия Family Manager (Менеджер)

**Priority**: P0-Critical

**Description**: Family Manager — создатель или назначенный владелец семейной группы с максимальными правами.

**Acceptance Criteria**:
- [ ] Менеджер может приглашать новых участников в семейную группу
- [ ] Менеджер может удалять участников из группы
- [ ] Менеджер может назначать роль Parent другим участникам
- [ ] Менеджер может создавать детские аккаунты (Google Account для ребёнка до 13 лет)
- [ ] Менеджер может настраивать и управлять семейным способом оплаты
- [ ] Менеджер может включать/отключать одобрение покупок для участников
- [ ] Менеджер может управлять семейной библиотекой (Family Library)
- [ ] Менеджер может удалить семейную группу целиком
- [ ] Менеджер может передать роль менеджера другому участнику 18+
- [ ] Менеджер решает, какие сервисы Google доступны семейной группе (Google One, YouTube Premium Family и т.д.)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Менеджер должен быть старше 18 лет (или совершеннолетним в стране) |
| BR-002 | Менеджер должен иметь действующую кредитную/дебетовую карту для семейного способа оплаты |
| BR-003 | Менеджер несёт финансовую ответственность за все покупки, совершённые через семейный способ оплаты |
| BR-004 | Менеджер получает email-квитанции обо всех покупках участников через семейный способ оплаты |
| BR-005 | При удалении аккаунта менеджера без передачи роли — семейная группа удаляется |

### FR-FK-002.2: Полномочия Parent (Родитель)

**Priority**: P0-Critical

**Description**: Parent — участник группы с делегированными полномочиями для управления детскими аккаунтами и одобрения покупок.

**Acceptance Criteria**:
- [ ] Родитель может создавать детские аккаунты для детей до 13 лет
- [ ] Родитель может обновлять (upgrade) детские аккаунты
- [ ] Родитель может удалять детские аккаунты
- [ ] Родитель может начинать контроль (supervision) над детским аккаунтом
- [ ] Родитель может прекращать контроль (supervision) над детским аккаунтом
- [ ] Родитель может одобрять или отклонять покупки через семейный способ оплаты
- [ ] Родитель может просматривать покупки участников, совершённые через семейный способ оплаты
- [ ] Родитель может изменять настройки одобрения покупок для участников
- [ ] Родитель НЕ может приглашать новых участников (только менеджер)
- [ ] Родитель НЕ может удалять обычных участников из группы

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Родителем может быть назначен только участник, достигший совершеннолетия в своей стране |
| BR-002 | Роль Parent назначается и отзывается менеджером семейной группы |
| BR-003 | В семейной группе может быть несколько участников с ролью Parent |

### FR-FK-002.3: Полномочия Member (Участник)

**Priority**: P1-High

**Description**: Member — обычный взрослый участник семейной группы с базовыми правами.

**Acceptance Criteria**:
- [ ] Участник может использовать семейный способ оплаты для покупок (если настроено)
- [ ] Участник может получать доступ к контенту из Family Library
- [ ] Участник может добавлять свой контент в Family Library
- [ ] Участник может использовать семейный календарь
- [ ] Участник может покинуть семейную группу добровольно
- [ ] Участник НЕ может управлять другими участниками
- [ ] Участник НЕ может менять настройки семейной группы

### FR-FK-002.4: Полномочия Child (Ребёнок)

**Priority**: P0-Critical

**Description**: Child — участник с контролируемым (supervised) аккаунтом, как правило, младше 13 лет.

**Acceptance Criteria**:
- [ ] Ребёнок может использовать семейный способ оплаты только с одобрения родителя
- [ ] Ребёнок может отправлять запросы на покупку (Purchase Requests) родителю
- [ ] Ребёнок может получать доступ к контенту из Family Library в пределах возрастных ограничений
- [ ] Ребёнку недоступны персонализированные рекламные объявления
- [ ] Ребёнку недоступен ряд сервисов Google (YouTube TV, полноценный Google Pay и т.д.)
- [ ] Ребёнок не может самостоятельно покинуть семейную группу
- [ ] Действия ребёнка отображаются в отчётах Family Link для родителя

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Детский аккаунт обязательно привязан к контролирующему родителю через Family Link |
| BR-002 | Ребёнок до 13 лет не может отключить контроль (supervision) самостоятельно |
| BR-003 | Ребёнку до 13 лет недоступны приложения, не соответствующие политике Families |
| BR-004 | Профиль Play Games для ребёнка генерируется автоматически (автоматический гамертег) |
| BR-005 | Ребёнок не может записывать и публиковать геймплей через Play Games |

## FR-FK-003: Приглашение и добавление участников

**Priority**: P0-Critical

**Description**: Менеджер семейной группы может приглашать новых участников через email или напрямую создавать детские аккаунты. Процесс добавления зависит от возраста приглашаемого и наличия у него аккаунта Google.

**Acceptance Criteria**:
- [ ] Менеджер может отправить приглашение на email Google-аккаунта
- [ ] Приглашённый получает уведомление с возможностью принять или отклонить приглашение
- [ ] При принятии приглашения участник добавляется в группу и получает доступ к общим ресурсам
- [ ] Менеджер/родитель может создать новый аккаунт Google для ребёнка до 13 лет непосредственно из Family Link
- [ ] При создании детского аккаунта родитель подтверждает своё согласие (parental consent)
- [ ] Менеджер/родитель может добавить контроль (supervision) к существующему аккаунту ребёнка
- [ ] Приглашение имеет срок действия, после которого становится недействительным
- [ ] Система предупреждает, если группа достигла максимума в 6 участников

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Максимум 6 участников в группе (включая менеджера) |
| BR-002 | Приглашённый должен находиться в той же стране, что и менеджер семейной группы |
| BR-003 | Пользователь, состоящий в другой семейной группе, должен сначала выйти из неё |
| BR-004 | Пользователь, недавно покинувший/удалённый из группы, не может вступить в новую в течение 12 месяцев |
| BR-005 | Для создания детского аккаунта требуется верификация личности родителя (согласие через кредитную карту или документ) |
| BR-006 | Родительское согласие (parental consent) на создание детского аккаунта подтверждается через паролевую верификацию или платёжную карту |

## FR-FK-004: Удаление и выход участников из группы

**Priority**: P1-High

**Description**: Участники могут покидать семейную группу добровольно, а менеджер может удалять участников. Процесс удаления имеет значительные последствия для доступа к контенту и сервисам.

**Acceptance Criteria**:
- [ ] Взрослый участник может покинуть группу добровольно через настройки
- [ ] Менеджер может удалить любого участника из группы
- [ ] Родитель может удалить созданный им детский аккаунт
- [ ] При выходе/удалении участник теряет доступ к Family Library
- [ ] При выходе/удалении участник теряет доступ к семейному способу оплаты
- [ ] При выходе/удалении участник сохраняет свой личный контент (купленный на личную карту)
- [ ] При удалении менеджера (удаление аккаунта Google) семейная группа расформировывается
- [ ] Ребёнок не может покинуть группу самостоятельно

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | После выхода/удаления участник не может вступить в новую группу в течение 12 месяцев |
| BR-002 | Контент, приобретённый через семейный способ оплаты другого участника, остаётся у того, кто его приобрёл |
| BR-003 | Контент из Family Library, добавленный удалённым участником, становится недоступен остальным |
| BR-004 | Менеджер получает уведомление, когда участник покидает группу |
| BR-005 | При удалении детского аккаунта все его данные удаляются безвозвратно |

## FR-FK-005: Семейная библиотека (Family Library)

**Priority**: P0-Critical

**Description**: Family Library позволяет участникам семейной группы делиться купленным контентом из Google Play: приложениями, играми, фильмами, сериалами и книгами. Менеджер активирует Family Library и настраивает правила совместного доступа.

**Acceptance Criteria**:
- [ ] Менеджер активирует Family Library при создании или в настройках семейной группы
- [ ] Участники могут добавлять подходящий купленный контент в Family Library
- [ ] Участники могут настраивать автоматическое добавление новых покупок в Family Library
- [ ] Все участники группы видят контент Family Library в своих библиотеках Google Play
- [ ] Контент фильтруется по возрастному рейтингу для детских аккаунтов
- [ ] Каждый участник может выбрать — делиться всеми будущими покупками или добавлять выборочно
- [ ] При отключении Family Library участники теряют доступ к чужому контенту

### FR-FK-005.1: Типы совместно доступного контента

**Priority**: P0-Critical

**Description**: Различные типы контента имеют разные правила доступности для Family Library.

**Acceptance Criteria**:
- [ ] Платные приложения и игры, купленные после 2 июля 2016 года, могут быть добавлены в Family Library
- [ ] Фильмы, купленные через Google Play, могут быть добавлены в Family Library
- [ ] ТВ-шоу, купленные (не арендованные) через Google Play, могут быть добавлены
- [ ] Электронные книги и аудиокниги могут быть добавлены (в поддерживаемых странах)
- [ ] Бесплатные приложения НЕ могут быть добавлены в Family Library
- [ ] Внутриигровые покупки (in-app purchases) НЕ могут быть переданы через Family Library
- [ ] Арендованные фильмы и ТВ-шоу НЕ могут быть добавлены
- [ ] Фильмы, купленные на YouTube, НЕ могут быть добавлены
- [ ] Подписки на Newsstand НЕ могут быть добавлены
- [ ] Музыка, купленная через Google Play, НЕ может быть добавлена

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Для добавления контента в Family Library у менеджера должна быть действующая семейная кредитная/дебетовая карта |
| BR-002 | Разработчик приложения может отключить возможность добавления своего приложения в Family Library (opt-out) |
| BR-003 | Доступность типов контента для Family Library зависит от страны семейной группы |
| BR-004 | Книги могут быть добавлены в Family Library только в определённых странах |
| BR-005 | Контент доступен одновременно всем участникам (нет лимита на одновременное использование для приложений и игр) |
| BR-006 | Для фильмов/ТВ-шоу одновременный стриминг может быть ограничен |

- [ ] Родитель привязывает аккаунт ребёнка через Family Link
- [ ] Все настройки Family Link доступны также через веб-интерфейс (families.google.com)
- [ ] Родитель может управлять несколькими детскими аккаунтами из одного приложения

### FR-FK-008.1: Управление экранным временем (Screen Time)

**Priority**: P0-Critical

**Description**: Родитель может устанавливать дневные лимиты использования устройства, расписание блокировки и ограничения по времени для отдельных приложений.

**Acceptance Criteria**:
- [ ] Родитель может установить дневной лимит экранного времени (в часах и минутах)
- [ ] Лимиты можно настроить индивидуально для каждого дня недели
- [ ] При достижении дневного лимита устройство блокируется (разрешены только звонки)

- [ ] Bedtime можно настроить с разным временем для будних и выходных дней
- [ ] Родитель может настроить "Учебное время" (School Time) с ограниченным режимом
- [ ] Родитель может установить индивидуальные таймеры для конкретных приложений (App Timers)
- [ ] Родитель может пометить определённые приложения как "Всегда разрешены" (не подчиняются лимитам)
- [ ] Родитель может удалённо заблокировать устройство ребёнка в любой момент
- [ ] Родитель может предоставить "Бонусное время" для продления лимита в конкретный день
- [ ] Ребёнок видит оставшееся время на экране устройства
- [ ] Ребёнок может запросить дополнительное время у родителя

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Минимальный дневной лимит — 15 минут, максимальный — 24 часа |
| BR-002 | Телефонные звонки и экстренные вызовы доступны даже при заблокированном устройстве |
| BR-003 | Будильник срабатывает даже при заблокированном устройстве |
| BR-004 | Экранное время считается только при включённом экране |
| BR-005 | Бонусное время добавляется только к текущему дню и не переносится |
| BR-006 | При нескольких устройствах у ребёнка экранное время считается суммарно или по каждому устройству отдельно (настраивается) |

## FR-FK-009: Родительский контроль в Google Play (Parental Controls)

**Priority**: P0-Critical

**Description**: Родительский контроль в Google Play — это набор настроек, ограничивающих контент, доступный на устройстве, на основе возрастных рейтингов. В отличие от Family Link, родительский контроль привязан к конкретному устройству и защищён PIN-кодом.

- [ ] Настройки применяются к конкретному устройству (не к аккаунту)
- [ ] Для контролируемых аккаунтов (supervised) родительский контроль управляется через Family Link

- [ ] Уже установленные приложения с неподходящим рейтингом остаются на устройстве, но могут быть скрыты
- [ ] Категории возрастных рейтингов зависят от региональной системы (PEGI, ESRB, ClassInd и т.д.)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Приложения без рейтинга блокируются при включённом родительском контроле |

**Priority**: P1-High

**Description**: Ограничение доступа к фильмам и сериалам на основе кинематографических возрастных рейтингов.

- [ ] Контент выше установленного рейтинга не отображается в поиске и каталоге

### FR-FK-009.4: Возрастные категории рейтингов

**Priority**: P0-Critical

**Description**: Система возрастных рейтингов в Google Play основана на международном стандарте IARC и адаптируется к региональным системам классификации.

**Acceptance Criteria**:
- [ ] Google Play поддерживает рейтинги PEGI (Европа): 3+, 7+, 12+, 16+, 18+
- [ ] Google Play поддерживает рейтинги ESRB (Северная Америка): Everyone, Everyone 10+, Teen, Mature 17+, Adults Only 18+
- [ ] Google Play поддерживает рейтинги ClassInd (Бразилия): Livre, 10+, 12+, 14+, 16+, 18+
- [ ] Google Play поддерживает рейтинги USK (Германия): 0+, 6+, 12+, 16+, 18+
- [ ] Google Play поддерживает рейтинги ACB (Австралия): G, PG, M, MA 15+, R 18+
- [ ] Рейтинг определяется автоматически на основе анкеты разработчика (IARC questionnaire)
- [ ] Рейтинг отображается на странице приложения/контента в Google Play
- [ ] Описатели контента (content descriptors) уточняют причины рейтинга: насилие, сексуальный контент, наркотики, ненормативная лексика, азартные игры
- [ ] Интерактивные элементы (Interactive Elements) отображаются отдельно: покупки в приложении, обмен данными, взаимодействие пользователей

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Все приложения в Google Play обязаны иметь возрастной рейтинг IARC |
| BR-002 | Приложения без рейтинга могут быть удалены из Google Play |
| BR-003 | Неточное заполнение анкеты IARC может привести к удалению или перерейтингу приложения |
| BR-004 | Рейтинг может быть пересмотрен Google или органами IARC при поступлении жалоб |
| BR-005 | Рейтинг присваивается бесплатно через систему IARC |
| BR-006 | Рейтинг пересматривается при значительных обновлениях контента приложения |

## FR-FK-010: Детские аккаунты и жизненный цикл (Child Account Lifecycle)

**Description**: Детский аккаунт Google имеет особый жизненный цикл: от создания с обязательным контролем, через ограниченный режим, до перехода при достижении 13 лет (или применимого возраста в стране).

### FR-FK-010.1: Создание детского аккаунта

**Priority**: P0-Critical

**Description**: Родитель создаёт аккаунт Google для ребёнка до 13 лет через Family Link. Аккаунт автоматически становится контролируемым (supervised).

**Acceptance Criteria**:
- [ ] Родитель инициирует создание детского аккаунта из приложения Family Link
- [ ] Родитель указывает имя, дату рождения ребёнка и создаёт email/пароль
- [ ] Система запрашивает подтверждение родительского согласия (parental consent)
- [ ] Согласие подтверждается через кредитную карту, документ или пароль аккаунта родителя
- [ ] После создания аккаунт автоматически добавляется в семейную группу родителя
- [ ] Аккаунт автоматически переводится в контролируемый (supervised) режим
- [ ] Family Link автоматически устанавливается на устройстве ребёнка при настройке

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Только пользователь с ролью Менеджер или Родитель может создать детский аккаунт |
| BR-002 | Дата рождения ребёнка определяет ограничения аккаунта |
| BR-003 | Parental consent обязателен по закону (COPPA, GDPR) |
| BR-004 | Детский аккаунт не может существовать без привязки к контролирующему родителю |

### FR-FK-010.2: Ограничения детского аккаунта (до 13 лет)

**Priority**: P0-Critical

**Description**: Детский аккаунт имеет системные ограничения на уровне Google-сервисов, которые нельзя снять до достижения ребёнком возраста 13 лет.

**Acceptance Criteria**:
- [ ] Ребёнку недоступен YouTube (доступен YouTube Kids, если настроен родителем)
- [ ] Ребёнку недоступен YouTube TV
- [ ] Ребёнку недоступен Google Pay (полнофункциональный)
- [ ] Ребёнку недоступен Google Ads
- [ ] Google не показывает персонализированную рекламу детям до 13 лет
- [ ] Секции "Электронные книги для вас" и "Аудиокниги для вас" недоступны в Play Books
- [ ] Профиль Play Games автоматически генерируется (ребёнок не может создать свой гамертег)
- [ ] Запись и публикация геймплея через Play Games недоступны
- [ ] Ребёнок видит сообщение "Это приложение недоступно для детей" при попытке установить несовместимое приложение
- [ ] Платёжный профиль ребёнка закрыт — покупки только через семейный способ оплаты

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Ограничения определяются датой рождения и не могут быть отменены родителем |
| BR-002 | Список недоступных приложений и сервисов обновляется Google и может изменяться |
| BR-003 | При попытке доступа к запрещённому сервису ребёнок видит информативное сообщение |
| BR-004 | Ряд Google-приложений предоставляет ограниченную функциональность (например, Google Assistant с безопасным режимом) |

### FR-FK-010.3: Переход при достижении 13 лет (Age Transition)

**Priority**: P0-Critical

**Description**: При достижении ребёнком 13 лет (или применимого возраста в стране) происходит процесс перехода аккаунта, в ходе которого ребёнок и родитель принимают решение о дальнейшем режиме контроля.

**Acceptance Criteria**:
- [ ] За определённое время до дня рождения ребёнка родитель и ребёнок получают email-уведомление
- [ ] В день рождения (13 лет) ребёнок получает email "Готовы обновить свой аккаунт Google?"
- [ ] Ребёнку предоставляется выбор: управлять аккаунтом самостоятельно или оставить контроль родителя
- [ ] Если ребёнок выбирает самостоятельное управление — контроль (supervision) снимается
- [ ] Если ребёнок не предпринимает действий — текущий режим контроля сохраняется
- [ ] Ребёнок может выбрать "обновлённый контроль" — supervision с расширенными правами подростка
- [ ] После 13 лет подросток МОЖЕТ отключить контроль самостоятельно в любой момент
- [ ] При отключении контроля подростком — родитель получает уведомление
- [ ] Родитель может прекратить контроль (supervision) над аккаунтом подростка 13+ в любой момент
- [ ] Прекращение контроля подростком до 18 лет требует одобрения родителя

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Возраст перехода определяется законодательством страны аккаунта (13 лет в США, 16 в некоторых странах ЕС) |
| BR-002 | До 13 лет ребёнок НЕ может отключить контроль самостоятельно |
| BR-003 | После 13 лет подросток получает возможность (но не обязательство) отключить контроль |
| BR-004 | Переход не является автоматическим — требуется действие ребёнка или родителя |
| BR-005 | При отключении контроля — настройки экранного времени, фильтрации и одобрения покупок деактивируются |
| BR-006 | При отключении контроля подросток остаётся в семейной группе как обычный участник (Member) |

### FR-FK-010.4: Передача контроля (Supervision Transfer)

**Priority**: P1-High

**Description**: Контроль (supervision) над детским аккаунтом может быть передан от одного родителя к другому внутри или вне семейной группы.

**Acceptance Criteria**:
- [ ] Текущий контролирующий родитель может инициировать передачу контроля
- [ ] Новый родитель должен подтвердить принятие контроля
- [ ] Передача возможна другому участнику семейной группы с ролью Родитель
- [ ] Передача возможна пользователю вне семейной группы (например, при разводе)
- [ ] После передачи предыдущий родитель теряет права на управление аккаунтом ребёнка
- [ ] Все настройки контроля сохраняются при передаче

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Новый контролирующий родитель должен быть совершеннолетним |
| BR-002 | Передача контроля не меняет принадлежность ребёнка к семейной группе |
| BR-003 | При передаче контроля вне группы — ребёнок может быть переведён в новую семейную группу |

## FR-FK-012: Программа "Designed for Families"

**Priority**: P0-Critical

**Description**: "Designed for Families" — программа Google Play, устанавливающая обязательные требования к приложениям, направленным на детскую аудиторию. Приложения, участвующие в программе, должны соответствовать повышенным стандартам безопасности, контента, рекламы и конфиденциальности.

**Acceptance Criteria**:
- [ ] Разработчик может подать заявку на участие в программе через Google Play Console
- [ ] Приложение должно указать целевую возрастную группу в Play Console
- [ ] Приложение должно пройти проверку на соответствие Families Policy
- [ ] Одобренные приложения получают отметку "Designed for Families" на странице в Google Play
- [ ] Одобренные приложения автоматически становятся кандидатами на оценку Teacher Approved
- [ ] При нарушении требований приложение удаляется из программы и может быть удалено из Google Play

### FR-FK-012.1: Требования к контенту

**Priority**: P0-Critical

**Description**: Контент приложений программы Designed for Families должен соответствовать строгим стандартам.

**Acceptance Criteria**:
- [ ] Весь контент приложения должен быть подходящим для заявленной возрастной группы
- [ ] Приложение не должно содержать насилия, сексуального контента или ненормативной лексики
- [ ] Приложение не должно продвигать алкоголь, табак, наркотики или азартные игры
- [ ] Контент, создаваемый пользователями (UGC), должен быть предварительно модерирован
- [ ] Ссылки на внешние ресурсы должны вести на подходящий для детей контент
- [ ] Приложение должно корректно отражать свой контент в описании и скриншотах на странице магазина

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Приложения с целевой аудиторией "только дети" подчиняются самым строгим требованиям |
| BR-002 | Приложения со смешанной аудиторией (дети + взрослые) должны использовать нейтральный экран определения возраста |
| BR-003 | Misrepresentation (намеренное искажение целевой аудитории) является основанием для удаления из Google Play |

### FR-FK-012.2: Требования к рекламе

**Priority**: P0-Critical

**Description**: Реклама в приложениях для детей должна соответствовать Families Ads Policy и использовать только сертифицированные рекламные SDK.

**Acceptance Criteria**:
- [ ] Реклама, показываемая детям, должна поступать только из Self-Certified Ads SDK
- [ ] Реклама не должна содержать контент для взрослых
- [ ] Реклама не должна быть обманчивой или вводящей в заблуждение
- [ ] Реклама не должна использовать приёмы, направленные на случайные клики детей (например, кнопки, мимикрирующие под игровые элементы)
- [ ] Персонализированная реклама не допускается для аккаунтов детей до 13 лет
- [ ] Реклама алкоголя, азартных игр, табака и лекарств запрещена
- [ ] Если приложение со смешанной аудиторией — реклама для детской аудитории должна поступать из сертифицированного SDK

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Self-Certified Ads SDK — SDK, прошедший самосертификацию в программе Google Play |
| BR-002 | Список сертифицированных SDK публикуется и обновляется Google |
| BR-003 | Использование несертифицированного SDK в приложении для детей приведёт к удалению из Google Play |
| BR-004 | Межстраничная реклама (interstitial ads) должна быть легко закрываема ребёнком |
| BR-005 | Реклама не должна запускаться автоматически с воспроизведением видео и звука |

### FR-FK-012.3: Требования к монетизации

**Priority**: P1-High

**Description**: Монетизация приложений для детей подчиняется специальным правилам для защиты от манипулятивных практик.

**Acceptance Criteria**:
- [ ] In-app purchases в приложениях для детей должны быть прозрачными
- [ ] Кнопки покупки не должны мимикрировать под игровые элементы
- [ ] Описание и цена покупки должны быть ясными до совершения транзакции
- [ ] Приложение не должно использовать давление на покупку (dark patterns)
- [ ] Кросс-промоушн (продвижение других приложений внутри детского приложения) должен соответствовать Families policy
- [ ] Подписки должны иметь прозрачные условия и простой механизм отмены

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Для детских аккаунтов все покупки проходят через механизм Purchase Approval |
| BR-002 | Paywall не должен блокировать основную функциональность обучающего приложения без предупреждения |
| BR-003 | Лут-боксы и подобные механики должны раскрывать вероятности |

### FR-FK-012.4: Требования к конфиденциальности и данным

**Priority**: P0-Critical

**Description**: Приложения для детей должны соблюдать повышенные стандарты конфиденциальности, включая COPPA и GDPR, ограничивая сбор и обработку данных.

**Acceptance Criteria**:
- [ ] Приложение должно иметь политику конфиденциальности, явно описывающую обработку данных детей
- [ ] Ссылка на политику конфиденциальности обязательна на странице приложения в Google Play
- [ ] Сбор персональных данных детей до 13 лет запрещён без verifiable parental consent
- [ ] Приложение не должно передавать данные детей третьим лицам для рекламных целей
- [ ] Приложение должно использовать минимально необходимый объём данных
- [ ] API и SDK, используемые в приложении, не должны собирать данные, нарушающие Families Policy

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | COPPA compliance обязательна для приложений, направленных на детей в США |
| BR-002 | GDPR compliance обязательна для приложений, доступных в ЕС |
| BR-003 | Приложение обязано декларировать практики сбора данных в Play Console (Data Safety section) |
| BR-004 | Google может удалить приложение при обнаружении нарушений конфиденциальности детей |
| BR-005 | Разработчик обязан указать целевую аудиторию приложения (Target audience) в Play Console |

## FR-FK-013: Программа "Teacher Approved"

**Priority**: P1-High

**Description**: Teacher Approved — расширение программы Designed for Families, в рамках которого приложения оцениваются панелью учителей и специалистов в области образования. Одобренные приложения получают специальный бейдж и размещаются в детском разделе Google Play.

**Acceptance Criteria**:
- [ ] Приложение, участвующее в Designed for Families, автоматически попадает в очередь на оценку Teacher Approved
- [ ] Оценка проводится панелью квалифицированных учителей и специалистов
- [ ] Учителя оценивают приложения только для тех возрастных групп, которые они преподают
- [ ] Одобренные приложения получают бейдж "Teacher Approved" на странице в Google Play
- [ ] Бейдж отображается в результатах поиска и в карточке приложения
- [ ] Одобренные приложения размещаются во вкладке "Дети" (Kids) раздела приложений и игр
- [ ] Оценка проводится на постоянной основе (rolling review)
- [ ] Google не гарантирует включение в программу Teacher Approved для всех заявок

### FR-FK-013.1: Критерии оценки Teacher Approved

**Priority**: P1-High

**Description**: Учителя оценивают приложения по комплексу критериев, охватывающих качество контента, дизайн и монетизацию.

**Acceptance Criteria**:
- [ ] Дизайн — насколько приложение удобно и интуитивно понятно для ребёнка целевого возраста
- [ ] Привлекательность (Appeal) — насколько приложение вовлекает ребёнка и поддерживает интерес
- [ ] Обогащение (Enrichment) — насколько приложение развивает навыки, знания или творчество
- [ ] Возрастная соответствие — насколько контент и сложность подходят заявленной возрастной группе
- [ ] Реклама — насколько реклама (если присутствует) уместна и не мешает использованию
- [ ] In-app purchases — насколько покупки (если присутствуют) прозрачны и не навязчивы
- [ ] Кросс-промоушн — насколько продвижение другого контента уместно и безопасно для детей
- [ ] Итоговая рекомендация — общий вердикт о пригодности для детской аудитории

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Консультационная рамка (framework) разработана совместно с академическими экспертами |
| BR-002 | Каждое приложение оценивается несколькими учителями независимо |
| BR-003 | Статус Teacher Approved может быть отозван при обновлениях, нарушающих критерии |
| BR-004 | Программа Teacher Approved действует в США и может расширяться на другие страны |
| BR-005 | Отказ от присвоения Teacher Approved не является основанием для удаления из Google Play |

## FR-FK-016: Фильтрация и показ контента по возрастным группам

**Priority**: P0-Critical

**Description**: Google Play использует систему возрастных рейтингов IARC для автоматической фильтрации контента. Фильтрация работает на нескольких уровнях: на уровне устройства (Parental Controls), на уровне аккаунта (Supervised Account) и на уровне Family Link.

**Acceptance Criteria**:
- [ ] Поиск в Google Play фильтрует результаты в соответствии с настройками родительского контроля
- [ ] Рекомендации и подборки фильтруются по установленному возрастному лимиту
- [ ] Страницы приложений с рейтингом выше установленного недоступны
- [ ] Кнопка "Установить" заменяется на информационное сообщение для заблокированного контента
- [ ] Фильтрация работает отдельно для каждой категории: приложения, игры, фильмы, ТВ, книги
- [ ] При изменении настроек родительского контроля фильтрация обновляется немедленно
- [ ] Для контролируемых аккаунтов уровень фильтрации определяется настройками Family Link

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Устройствный контроль (Parental Controls) защищён PIN-кодом; аккаунтный — паролем родителя |
| BR-002 | При конфликте уровней фильтрации (устройство vs. аккаунт) применяется более строгий |
| BR-003 | Обновления приложений не блокируются родительским контролем (даже если рейтинг изменился) |
| BR-004 | Фильтрация не влияет на уже установленные приложения — они остаются на устройстве |
| BR-005 | Разработчик обязан корректно заполнить IARC-анкету; некорректная информация приводит к санкциям |

## FR-FK-017: Возрастные рейтинги контента (Content Rating System)

**Priority**: P0-Critical

**Description**: Система возрастных рейтингов в Google Play основана на IARC и отображает для пользователей локализованные рейтинги соответствующей региональной организации. Рейтинг определяется на основе анкеты, заполняемой разработчиком.

### FR-FK-017.1: Процесс получения рейтинга

**Priority**: P0-Critical

**Description**: Разработчик заполняет анкету IARC в Google Play Console, и рейтинг присваивается автоматически.

**Acceptance Criteria**:
- [ ] Разработчик выбирает категорию приложения (приложение или игра)
- [ ] Разработчик отвечает на вопросы о содержимом: насилие, сексуальный контент, наркотики, азартные игры, ненормативная лексика
- [ ] Разработчик указывает интерактивные элементы: UGC, обмен данными, покупки, социальное взаимодействие
- [ ] Система автоматически вычисляет рейтинги для всех регионов
- [ ] Рейтинги отображаются на странице подтверждения (Summary)
- [ ] Разработчик подтверждает и публикует рейтинг
- [ ] Рейтинг присваивается бесплатно и мгновенно
- [ ] При значительном обновлении контента разработчик обязан пересмотреть анкету

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Все приложения обязаны иметь рейтинг IARC для публикации в Google Play |
| BR-002 | Приложения без рейтинга подлежат удалению |
| BR-003 | Неточные ответы в анкете могут привести к перерейтингу или удалению |
| BR-004 | Рейтинг относится к основному контенту приложения; реклама оценивается отдельно |
| BR-005 | IARC может инициировать пересмотр рейтинга по жалобам пользователей |

### FR-FK-017.2: Отображение рейтинга

**Priority**: P1-High

**Description**: Возрастной рейтинг и описатели контента отображаются на странице приложения.

**Acceptance Criteria**:
- [ ] Возрастной рейтинг отображается иконкой и текстом на странице приложения
- [ ] Рейтинг адаптируется к региональной системе пользователя (PEGI для Европы, ESRB для США и т.д.)
- [ ] Описатели контента (content descriptors) указывают причины рейтинга
- [ ] Интерактивные элементы (Interactive Elements) отображаются отдельным списком
- [ ] При нажатии на рейтинг открывается детальная информация
- [ ] Рейтинг отображается в результатах поиска

## FR-FK-018: Целевая аудитория приложения (Target Audience Declaration)

**Priority**: P0-Critical

**Description**: Разработчик обязан указать целевую аудиторию приложения в Google Play Console. Эта декларация определяет, к каким политикам подчиняется приложение и как оно отображается в каталоге.

**Acceptance Criteria**:
- [ ] Разработчик выбирает целевые возрастные группы: до 5, 6–8, 9–12, 13–15, 16–17, 18+
- [ ] Можно выбрать несколько возрастных групп
- [ ] Если выбрана хотя бы одна группа до 13 лет — приложение подчиняется Families Policy
- [ ] Если целевая аудитория "только дети" — применяются максимальные ограничения
- [ ] Если целевая аудитория "дети и взрослые" — требуется нейтральный экран определения возраста
- [ ] Если целевая аудитория "только взрослые" — приложение не показывается детским аккаунтам
- [ ] Декларация влияет на требования к рекламе, данным и контенту

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Все приложения обязаны указать целевую аудиторию |
| BR-002 | Намеренное занижение возраста аудитории для обхода ограничений является нарушением политики |
| BR-003 | Приложения "только для детей" не могут апеллировать к взрослой аудитории (и наоборот) |
| BR-004 | Google может пересмотреть декларацию, если реальная аудитория не соответствует заявленной |
| BR-005 | При изменении целевой аудитории приложение подвергается повторной проверке |

## FR-FK-019: Primarily Child-Directed Declaration

**Priority**: P1-High

**Description**: Разработчик приложения, ориентированного преимущественно на детей, должен подать декларацию Primarily Child-Directed. Эта декларация накладывает дополнительные обязательства по COPPA и ограничивает сбор данных и рекламу.

**Acceptance Criteria**:
- [ ] Разработчик отмечает в Play Console, что приложение преимущественно направлено на детей
- [ ] Декларация активирует обязательное соблюдение COPPA requirements
- [ ] Google не показывает персонализированную рекламу пользователям таких приложений
- [ ] Сбор данных в приложении ограничен минимально необходимым объёмом
- [ ] Приложение не может использовать Google Sign-In для детских аккаунтов без соблюдения дополнительных требований
- [ ] Намеренное искажение декларации (misrepresentation) является грубым нарушением

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Primarily Child-Directed приложения не могут использовать несертифицированные рекламные SDK |
| BR-002 | Нарушение COPPA может повлечь юридические последствия помимо удаления из Google Play |
| BR-003 | Google проводит проактивные проверки приложений с этой декларацией |
