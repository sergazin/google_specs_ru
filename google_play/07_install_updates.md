# Google Play: Установка, обновления и управление приложениями

## Обзор модуля

Модуль установки, обновлений и управления приложениями является центральным функциональным ядром Google Play. Он обеспечивает полный жизненный цикл приложения на устройстве пользователя: от обнаружения и установки (бесплатной или платной) через систему обновлений (автоматических и ручных) до удаления, архивации и переустановки. Модуль интегрирован с Google Play Protect для обеспечения безопасности, поддерживает оптимизацию размера через Android App Bundles, условную доставку функциональных модулей, Instant Apps для пробного запуска без установки, удалённую установку на другие устройства и управление хранилищем. Все операции привязаны к Google-аккаунту пользователя, что обеспечивает переносимость покупок и данных между устройствами.

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **APK** | Android Package Kit — формат файла установки приложения Android |
| **AAB (Android App Bundle)** | Формат публикации приложений, позволяющий Google Play генерировать оптимизированные APK для каждого устройства |
| **Split APK** | Частичный APK, содержащий только ресурсы, необходимые для конкретной конфигурации устройства |
| **Sideloading** | Установка приложений из источников, отличных от Google Play (через APK-файлы) |
| **Google Play Protect** | Встроенная система безопасности Android, проверяющая приложения при установке и периодически на устройстве |
| **Instant App** | Приложение, которое можно запустить без полной установки на устройство |
| **Dynamic Feature Module** | Функциональный модуль приложения, загружаемый по требованию, а не при начальной установке |
| **Conditional Delivery** | Условная доставка модулей на основе характеристик устройства (архитектура, регион, возможности) |
| **On-Demand Delivery** | Загрузка модулей приложения по запросу пользователя после установки базового приложения |
| **Install-time Delivery** | Доставка модулей вместе с основным пакетом при установке |
| **Auto-archive** | Автоматическая архивация неиспользуемых приложений для освобождения места с сохранением данных |
| **Library (Библиотека)** | Список всех приложений, когда-либо установленных или приобретённых на аккаунт Google |
| **OBB (Opaque Binary Blob)** | Файл расширения для приложений, превышающих базовый размер |
| **Remote Install** | Удалённая установка приложений на устройство через веб-интерфейс или другое устройство |
| **Staged Rollout** | Поэтапный выпуск обновления для процента пользователей |
| **Download Queue** | Очередь загрузок, управляющая последовательностью скачивания и установки приложений |
| **Family Library** | Общая семейная библиотека для совместного использования купленных приложений |
| **Refund Window** | Временное окно, в течение которого можно вернуть средства за покупку приложения |

## Типы пользователей и роли

### Роли в контексте установки и обновлений

| Роль | Описание |
|------|----------|
| **Анонимный пользователь** | Может просматривать каталог Google Play, но не может устанавливать приложения |
| **Владелец аккаунта Google** | Основной пользователь устройства, управляет установкой, обновлениями, покупками |
| **Участник Family Group** | Член семейной группы, имеет доступ к общей библиотеке приложений |
| **Пользователь с ограниченным профилем** | Ограниченный профиль на планшете, может использовать только разрешённые приложения |
| **Ребёнок (Family Link)** | Пользователь младше 13 лет, все установки требуют одобрения родителя |
| **Родитель (Family Link)** | Управляет установками для детского аккаунта, одобряет или отклоняет запросы |
| **Администратор устройства (MDM)** | Корпоративный администратор, управляет приложениями через Managed Google Play |
| **Разработчик (Publisher)** | Публикует приложения, управляет обновлениями через Google Play Console |

### Иерархия контроля установки

```
Google Play Protect (системный уровень)
    └── MDM-администратор (корпоративный уровень)
        └── Родитель / Family Link (семейный уровень)
            └── Владелец аккаунта (пользовательский уровень)
                └── Пользователь с ограниченным профилем (подчинённый уровень)
```

## Функциональные требования

### FR-GP-INST-001: Установка бесплатного приложения

**Приоритет**: P0-Critical

**Описание**: Загрузка и установка бесплатного приложения из каталога Google Play на устройство пользователя.

**Акторы**: Владелец аккаунта Google, Участник Family Group, Ребёнок (с одобрением родителя)

**Предусловия**:
- Пользователь авторизован в Google-аккаунте на устройстве
- Устройство подключено к интернету
- На устройстве достаточно свободного места для установки
- Приложение доступно в стране/регионе пользователя
- Приложение совместимо с устройством (версия Android, архитектура процессора, разрешение экрана)

**Основной сценарий**:
1. Пользователь открывает страницу приложения в Google Play
2. Система отображает кнопку "Установить" и размер загрузки
3. Пользователь нажимает "Установить"
4. Система отображает список запрашиваемых разрешений (для приложений с targetSdkVersion < 23)
5. Google Play Protect выполняет проверку безопасности приложения
6. Система начинает загрузку оптимизированного пакета (Split APK на основе конфигурации устройства)
7. Отображается прогресс-бар загрузки с процентом и оставшимся размером
8. По завершении загрузки система автоматически начинает установку
9. Система отображает уведомление об успешной установке
10. Кнопка на странице приложения меняется на "Открыть"
11. Приложение добавляется на домашний экран (если включена настройка)
12. Приложение добавляется в библиотеку Google Play пользователя

**Альтернативные сценарии**:

| Сценарий | Условие | Действие |
|----------|---------|----------|
| A1 | Недостаточно места на устройстве | Показать предупреждение с указанием необходимого и доступного места; предложить освободить место или управлять хранилищем |
| A2 | Приложение несовместимо с устройством | Кнопка "Установить" недоступна; отображается сообщение "Ваше устройство не совместимо с этой версией" |
| A3 | Приложение недоступно в регионе | Приложение не отображается в поиске; при прямом переходе — сообщение о недоступности |
| A4 | Потеря интернет-соединения во время загрузки | Загрузка приостанавливается; автоматическое возобновление при восстановлении связи |
| A5 | Ребёнок запрашивает установку (Family Link) | Запрос отправляется родителю для одобрения; ребёнок видит статус "Ожидание одобрения" |
| A6 | Google Play Protect обнаружил угрозу | Установка блокируется; отображается предупреждение с описанием угрозы |
| A7 | Приложение уже установлено | Вместо "Установить" отображается "Открыть" (или "Обновить" при наличии обновления) |
| A8 | MDM-политика запрещает установку | Кнопка "Установить" недоступна; сообщение "Установка запрещена вашим администратором" |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-001 | Бесплатные приложения не требуют привязки платёжного метода |
| BR-002 | Установка возможна только при авторизации в Google-аккаунте; анонимная установка невозможна |
| BR-003 | При использовании AAB пользователь загружает только код и ресурсы, релевантные его устройству (экономия до 15-35% размера) |
| BR-004 | Установленное приложение привязывается к Google-аккаунту, а не к конкретному устройству |
| BR-005 | Автоматическое добавление иконки на домашний экран контролируется системной настройкой "Добавлять значки на главный экран" |
| BR-006 | При установке проверяется минимальная версия Android (minSdkVersion), заданная разработчиком |
| BR-007 | Приложение добавляется в историю установок (библиотеку) аккаунта даже после удаления |

**Результат**: Приложение загружено, установлено и готово к использованию. Добавлено в библиотеку аккаунта.

### FR-GP-INST-002: Покупка и установка платного приложения

**Приоритет**: P0-Critical

**Описание**: Приобретение и установка приложения с фиксированной стоимостью через систему оплаты Google Play.

**Акторы**: Владелец аккаунта Google, Участник Family Group (при наличии доступа к Family Library)

**Предусловия**:
- Пользователь авторизован в Google-аккаунте
- К аккаунту привязан хотя бы один способ оплаты (банковская карта, Google Play баланс, PayPal, оператор связи и др.)
- Приложение доступно в регионе пользователя
- Устройство совместимо с приложением

**Основной сценарий**:
1. Пользователь открывает страницу платного приложения
2. Система отображает кнопку с ценой в локальной валюте (например, "149 руб." или "$4.99")
3. Пользователь нажимает кнопку с ценой
4. Система открывает окно подтверждения покупки:
   - Название приложения и издатель
   - Цена (включая налоги, если применимо)
   - Выбранный способ оплаты (с возможностью переключения)
5. Пользователь подтверждает аутентификацию (отпечаток пальца, Face ID, PIN, пароль Google-аккаунта)
6. Система обрабатывает платёж
7. При успешной оплате начинается автоматическая загрузка и установка
8. Пользователь получает email с квитанцией о покупке
9. Приложение добавляется в библиотеку покупок аккаунта

**Альтернативные сценарии**:

| Сценарий | Условие | Действие |
|----------|---------|----------|
| A1 | Способ оплаты отклонён | Предложить выбрать другой способ оплаты или добавить новый |
| A2 | Недостаточно средств на балансе Google Play | Предложить пополнить баланс или выбрать другой способ оплаты |
| A3 | Покупка через Family Library | Списание с аккаунта владельца Family Group; при наличии собственного способа оплаты — с аккаунта покупателя |
| A4 | Требуется одобрение родителя | Ребёнок не может совершить покупку без подтверждения родителя (Family Link) |
| A5 | Приложение уже куплено ранее | Кнопка отображается как "Установить" (бесплатно); повторная оплата не требуется |
| A6 | Промо-код / подарочная карта | Стоимость списывается с баланса Google Play |

**Окно возврата средств**:

| Условие | Срок возврата | Процедура |
|---------|---------------|-----------|
| Автоматический возврат | До 2 часов после покупки | Кнопка "Вернуть" на странице приложения; приложение автоматически удаляется |
| Запрос на возврат | 2 часа — 48 часов | Через форму запроса; решение принимает Google |
| После 48 часов | Свыше 48 часов | Необходимо обращаться к разработчику; Google может отклонить |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-008 | Покупка привязана к Google-аккаунту навсегда; переустановка на любое устройство с тем же аккаунтом бесплатна |
| BR-009 | Автоматический возврат возможен только один раз для каждого приложения; при повторной покупке и возврате — только через запрос |
| BR-010 | Цена отображается в локальной валюте пользователя на основе страны аккаунта |
| BR-011 | Налоги (VAT, GST и т.д.) рассчитываются автоматически на основе региона и отображаются в итоговой стоимости |
| BR-012 | Google взимает комиссию с разработчика (15% для первого $1M, затем 30%), пользователь платит полную цену |
| BR-013 | Разработчик может включить приложение в Family Library, позволяя до 5 участникам семейной группы использовать его |
| BR-014 | Подтверждение аутентификации обязательно для каждой покупки, если не настроено временное окно (до 30 минут) |
| BR-015 | При смене страны аккаунта платежи обрабатываются по правилам новой страны |

**Результат**: Приложение оплачено, загружено, установлено. Покупка зафиксирована в аккаунте навсегда.

### FR-GP-INST-003: Автоматическое обновление приложений

**Приоритет**: P0-Critical

**Описание**: Автоматическая загрузка и установка доступных обновлений приложений без вмешательства пользователя, согласно настроенной политике.

**Акторы**: Система (Google Play Services), Владелец аккаунта (настройка политики)

**Предусловия**:
- На устройстве установлены приложения с доступными обновлениями
- Автоматическое обновление включено (настройка по умолчанию)
- Соблюдены условия сети (Wi-Fi / любая сеть — зависит от настройки)

**Политики автоматического обновления (глобальные)**:

| Политика | Описание | Статус по умолчанию |
|----------|----------|---------------------|
| **По любой сети** | Обновления загружаются через Wi-Fi и мобильные данные | Нет |
| **Только по Wi-Fi** | Обновления загружаются только при подключении к Wi-Fi | Да (по умолчанию) |
| **Не обновлять автоматически** | Автоматические обновления отключены полностью | Нет |

**Политики автоматического обновления (per-app)**:

| Настройка | Описание |
|-----------|----------|
| Включено (по умолчанию) | Следует глобальной политике |
| Отключено | Конкретное приложение не обновляется автоматически, даже если глобальная политика включена |

**Основной сценарий**:
1. Google Play проверяет наличие обновлений приблизительно раз в сутки (точный интервал определяется системой)
2. При обнаружении доступных обновлений формируется очередь обновлений
3. Система проверяет выполнение условий сети (Wi-Fi / любая сеть)
4. Система проверяет наличие достаточного места на устройстве
5. Система проверяет уровень заряда батареи (обновление откладывается при критически низком заряде)
6. Начинается последовательная загрузка и установка обновлений из очереди
7. Обновления устанавливаются в фоновом режиме без прерывания работы пользователя
8. При обновлении работающего приложения — обновление применяется при следующем запуске
9. Отображается уведомление о завершении обновлений (опционально)

**Альтернативные сценарии**:

| Сценарий | Условие | Действие |
|----------|---------|----------|
| A1 | Обновление требует новых разрешений (target SDK < 23) | Автоматическое обновление приостанавливается; пользователь уведомляется о необходимости ручного подтверждения |
| A2 | Недостаточно места для обновления | Обновление откладывается; предложение освободить место |
| A3 | Потеря соединения во время загрузки | Загрузка приостанавливается; автоматически возобновляется при восстановлении соединения |
| A4 | Приложение в процессе использования | Обновление загружается, но применяется при следующем запуске приложения |
| A5 | Staged Rollout — обновление доступно не всем | Обновление доставляется только пользователям в выбранном проценте; остальные ждут расширения rollout |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-016 | Проверка обновлений происходит примерно раз в сутки; может пройти до 24 часов между публикацией обновления и его обнаружением на устройстве |
| BR-017 | По умолчанию автоматические обновления включены и настроены на загрузку только по Wi-Fi |
| BR-018 | Пользователь может отключить автообновление для конкретного приложения, не затрагивая глобальную политику |
| BR-019 | При поэтапном выпуске (Staged Rollout) обновление может быть доступно только 1-100% пользователей, определяемых разработчиком |
| BR-020 | Если разработчик обнаружил критический баг, он может остановить rollout — уже обновлённые пользователи НЕ откатываются автоматически |
| BR-021 | Обновления, требующие новых критических разрешений, не устанавливаются автоматически до подтверждения пользователя |
| BR-022 | При автоматическом обновлении загружается только дельта (разница между текущей и новой версией), а не полный пакет, что уменьшает размер загрузки |

**Результат**: Установленные приложения автоматически обновляются до актуальных версий без вмешательства пользователя.

### FR-GP-INST-004: Ручное обновление отдельного приложения

**Приоритет**: P0-Critical

**Описание**: Инициированное пользователем обновление конкретного приложения до последней доступной версии.

**Акторы**: Владелец аккаунта Google

**Предусловия**:
- Приложение установлено на устройстве
- Доступно обновление (новая версия опубликована разработчиком)
- Устройство подключено к интернету

**Основной сценарий**:
1. Пользователь открывает страницу приложения в Google Play
2. Система отображает кнопку "Обновить" (вместо "Открыть")
3. Рядом с кнопкой отображается информация:
   - Размер обновления
   - Что нового (release notes / changelog)
4. Пользователь нажимает "Обновить"
5. Система начинает загрузку обновления
6. Отображается прогресс загрузки
7. По завершении загрузки — автоматическая установка
8. Кнопка меняется на "Открыть"
9. Если приложение было запущено — новая версия применяется при следующем запуске

**Альтернативный путь — через раздел "Управление приложениями"**:
1. Пользователь нажимает на аватар профиля в Google Play
2. Выбирает "Управление приложениями и устройством"
3. Система показывает вкладку "Обзор" с информацией:
   - "Доступны обновления" — количество приложений с обновлениями
4. Пользователь нажимает "Подробнее"
5. Отображается список приложений с доступными обновлениями
6. Пользователь выбирает конкретное приложение и нажимает "Обновить"

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-023 | Ручное обновление возможно через любой тип сети, независимо от настроек автоматических обновлений |
| BR-024 | При ручном обновлении отображается changelog (что нового), предоставленный разработчиком |

### FR-GP-INST-008: Удаление приложения

**Приоритет**: P0-Critical

**Описание**: Полное удаление установленного приложения с устройства с возможностью сохранения данных.

**Акторы**: Владелец аккаунта Google, Родитель (для устройства ребёнка), MDM-администратор

**Предусловия**:
- Приложение установлено на устройстве
- Приложение не является системным (system app) без root-доступа

**Основной сценарий (из Google Play)**:
1. Пользователь открывает страницу установленного приложения
2. Нажимает "Удалить"

5. Система удаляет приложение, его данные и кэш
6. Освобождается занимаемое место на устройстве

8. Приложение остаётся в библиотеке Google Play (для возможности переустановки)

**Альтернативный сценарий (из настроек устройства)**:
1. Пользователь переходит в Настройки > Приложения
2. Выбирает приложение
3. Нажимает "Удалить"
4. Подтверждает удаление

**Альтернативный сценарий (из Google Play "Управление")**:
1. Пользователь переходит в "Управление приложениями и устройством"
2. Вкладка "Управление"
3. Выбирает одно или несколько приложений (чекбоксами)
4. Нажимает иконку удаления (корзина)
5. Подтверждает массовое удаление

**Особые случаи**:

| Случай | Поведение |
|--------|-----------|
| Системное приложение | Удаление невозможно; доступно только "Удалить обновления" (откат к предустановленной версии) |

| Платное приложение | Удаление не означает возврат средств; переустановка бесплатна в будущем |
| Приложение с активной подпиской | Удаление не отменяет подписку; подписку нужно отменить отдельно |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-040 | Удаление приложения удаляет все локальные данные приложения (если приложение не использует облачную синхронизацию) |
| BR-041 | Удаление платного приложения НЕ аннулирует покупку; приложение можно переустановить бесплатно в любой момент |
| BR-042 | Удаление приложения НЕ отменяет активные подписки; подписка продолжает действовать и списывать средства |
| BR-043 | Удалённое приложение сохраняется в библиотеке аккаунта Google Play для возможности переустановки |
| BR-044 | Системные приложения (предустановленные производителем) можно только "Отключить" или "Удалить обновления", но не удалить полностью |
| BR-045 | При массовом удалении каждое приложение удаляется последовательно; процесс можно отменить до завершения |

**Результат**: Приложение удалено с устройства. Покупка сохранена в аккаунте.

### FR-GP-INST-011: Откат к предыдущей версии приложения

**Приоритет**: P2-Medium

**Описание**: Возврат приложения к предыдущей версии после обновления. Функциональность крайне ограничена в стандартном Google Play.

**Акторы**: Владелец аккаунта Google, Администратор устройства

**Возможности отката в рамках Google Play**:

| Метод | Описание | Доступность |
|-------|----------|-------------|
| Удаление обновлений системного приложения | Откат системного приложения к предустановленной заводской версии | Все пользователи |
| Отключение автообновления | Предотвращение обновления конкретного приложения до нежелательной версии | Все пользователи |
| Полное удаление и установка старой версии | Удаление текущей версии и установка из стороннего источника (APK) | Продвинутые пользователи |

**Сценарий отката системного приложения**:
1. Пользователь переходит в Настройки > Приложения
2. Выбирает системное приложение (например, Google Chrome, YouTube)
3. Нажимает меню "..." > "Удалить обновления"
4. Система запрашивает подтверждение
5. Приложение откатывается к версии, предустановленной на заводе
6. Данные приложения могут быть сброшены

**Сценарий предотвращения нежелательного обновления**:
1. Пользователь открывает страницу приложения в Google Play
2. Нажимает меню "..."
3. Снимает отметку "Автоматическое обновление"
4. Приложение исключается из автообновления
5. Пользователь вручную решает, когда обновлять

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-059 | Google Play НЕ предоставляет интерфейса для скачивания предыдущих версий приложений |
| BR-060 | Откат обновлений доступен только для системных (предустановленных) приложений и только до заводской версии |
| BR-061 | При откате системного приложения данные приложения могут быть потеряны |
| BR-062 | Разработчик может остановить распространение текущей версии через Google Play Console, но это не откатывает приложение у уже обновившихся пользователей |
| BR-063 | Android содержит скрытую функцию rollback (в Android 12+), но она предназначена для тестирования и не доступна обычным пользователям через стандартный интерфейс |
| BR-064 | Для установки более старой версии из стороннего источника необходимо сначала полностью удалить текущую версию (downgrade без удаления запрещён системой) |

**Результат**: Системное приложение откачено к заводской версии; или автообновление конкретного приложения отключено.

### FR-GP-INST-012: Установка из APK (Sideloading)

**Приоритет**: P1-High

**Описание**: Установка приложений из файлов APK, полученных не через Google Play, с учётом системных ограничений безопасности.

**Акторы**: Владелец аккаунта Google

**Предусловия**:
- Пользователь имеет APK-файл на устройстве (загружен из браузера, получен через мессенджер и т.д.)
- Источник установки разрешён в настройках безопасности

**Модель разрешений по версиям Android**:

| Версия Android | Модель разрешений |
|----------------|-------------------|
| Android < 8.0 | Глобальная настройка "Неизвестные источники" (вкл/выкл для всех источников) |
| Android 8.0+ (Oreo) | Per-app разрешение: каждому приложению-источнику (Chrome, Files, Telegram) выдаётся разрешение отдельно |

**Основной сценарий (Android 8.0+)**:
1. Пользователь открывает APK-файл через файловый менеджер или другое приложение
2. Система проверяет, разрешена ли установка из этого приложения-источника
3. Если не разрешена — отображается диалог:
   - "В целях безопасности на телефоне заблокирована установка приложений из неизвестных источников"
   - Кнопка "Настройки" для перехода к разрешениям
4. Пользователь переходит в Настройки > Приложения > Специальный доступ > Установка неизвестных приложений
5. Выбирает приложение-источник (например, Chrome)
6. Включает "Разрешить из этого источника"
7. Возвращается к установке APK
8. Google Play Protect сканирует APK-файл
9. Если угроз не обнаружено — начинается установка
10. Если обнаружена угроза — предупреждение с возможностью отменить или продолжить на свой риск

**Уровни предупреждений Google Play Protect при sideloading**:

| Уровень | Описание | Действие |
|---------|----------|----------|
| Безопасно | Угроз не обнаружено | Установка без предупреждений |
| Предупреждение | Приложение потенциально опасно | Предупреждение с возможностью продолжить |
| Блокировка | Приложение определено как вредоносное | Установка заблокирована; рекомендация удалить APK |
| Неизвестно | Приложение не может быть проверено (новое, нет данных) | Предупреждение "Приложение не проверено"; предложение отправить на проверку в Google |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-065 | На Android 8.0+ разрешение на установку из неизвестных источников выдаётся per-app, а не глобально |
| BR-066 | Google Play Protect сканирует ВСЕ устанавливаемые приложения, включая sideloaded, независимо от источника |
| BR-067 | Приложения, установленные через sideloading, НЕ получают автоматических обновлений через Google Play (если в Google Play есть та же подпись разработчика — обновление возможно) |
| BR-068 | MDM-политики могут полностью запретить sideloading на корпоративных устройствах |
| BR-069 | Google Play Protect может заблокировать установку определённо вредоносного приложения даже при включённом разрешении на неизвестные источники |
| BR-070 | При включении сканирования в реальном времени (Enhanced) Google Play Protect отправляет новые APK на серверы Google для углублённого анализа |
| BR-071 | Sideloading не добавляет приложение в библиотеку Google Play |

**Результат**: Приложение установлено из APK-файла после прохождения проверок безопасности.

### FR-GP-INST-013: Проверка безопасности Google Play Protect при установке

**Приоритет**: P0-Critical

**Описание**: Автоматическая проверка безопасности приложений системой Google Play Protect при установке и периодическое сканирование установленных приложений.

**Акторы**: Система (Google Play Protect), Владелец аккаунта (управление настройками)

**Режимы работы Google Play Protect**:

| Режим | Описание |
|-------|----------|
| Проверка при установке из Google Play | Все приложения в Google Play проходят проверку перед публикацией и при загрузке на устройство |
| Проверка при sideloading | APK-файлы из сторонних источников сканируются при попытке установки |
| Периодическое сканирование | Все установленные приложения периодически проверяются на наличие угроз |
| Сканирование в реальном времени (Enhanced) | Новые, неизвестные приложения отправляются на серверы Google для глубокого анализа |

**Основной сценарий проверки при установке**:
1. Пользователь инициирует установку приложения
2. Google Play Protect автоматически сканирует приложение
3. Проверяется:
   - Наличие в каталоге известных вредоносных приложений
   - On-device machine learning анализ
   - Сравнение с базой сигнатур
   - Анализ поведения (для Enhanced режима)
4. Результат проверки:
   - Безопасно — установка продолжается без задержки
   - Подозрительно — предупреждение пользователю
   - Опасно — блокировка установки

**Сценарий периодического сканирования**:
1. Google Play Protect автоматически сканирует устройство (примерно раз в день)
2. Проверяются все установленные приложения (включая sideloaded)
3. Google сканирует ~200 миллиардов приложений ежедневно по всем устройствам
4. При обнаружении угрозы:
   - Уведомление пользователю
   - Рекомендация удалить приложение
   - В критических случаях — автоматическое отключение или удаление

**Действия при обнаружении угроз**:

| Уровень угрозы | Действие системы |
|----------------|-----------------|
| Низкий риск | Уведомление с рекомендацией |
| Средний риск | Отключение приложения до удаления пользователем |
| Критический риск | Автоматическое удаление приложения с уведомлением |

**Настройки Google Play Protect**:

| Настройка | Описание | По умолчанию |
|-----------|----------|:------------:|
| Сканирование приложений с Play Protect | Включает/отключает сканирование | Включено |
| Улучшение обнаружения вредоносных приложений | Отправка неизвестных приложений в Google для анализа | Включено |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-072 | Google Play Protect включён по умолчанию на всех Android-устройствах с Google Play Services |
| BR-073 | Пользователь может отключить Google Play Protect, но Google настоятельно не рекомендует этого делать |
| BR-074 | Google Play Protect проверяет все приложения, независимо от источника установки (Google Play, sideloading) |
| BR-075 | Периодическое сканирование происходит автоматически, даже если устройство не подключено к сети (используется локальная база сигнатур) |
| BR-076 | При обнаружении критически опасного приложения система может удалить его автоматически без согласия пользователя |
| BR-077 | Результаты сканирования отображаются в разделе Google Play Protect приложения Google Play |
| BR-078 | Certification: Google Play Protect сертифицирован AV-TEST и другими организациями |

**Результат**: Приложения проверены на безопасность; угрозы обнаружены и нейтрализованы.

### FR-GP-INST-014: Оптимизация размера загрузки (App Bundles и Split APKs)

**Приоритет**: P1-High

**Описание**: Оптимизация размера загружаемого приложения через систему Android App Bundles, которая генерирует персонализированные APK для каждого устройства.

**Акторы**: Система (Google Play), Разработчик (публикация AAB)

**Предусловия**:
- Разработчик опубликовал приложение в формате AAB (Android App Bundle)
- С августа 2021 года AAB является обязательным форматом для новых приложений в Google Play

**Механизм оптимизации**:

```
Разработчик загружает AAB
         |
         v
Google Play анализирует AAB
         |
         v
Генерация Split APKs для каждой конфигурации:
    ├── Base APK (основной код)
    ├── Configuration APKs:
    │   ├── ABI split (arm64-v8a / armeabi-v7a / x86 / x86_64)
    │   ├── Screen density split (ldpi / mdpi / hdpi / xhdpi / xxhdpi / xxxhdpi)
    │   └── Language split (ru / en / es / ...)
    └── Dynamic Feature APKs (по запросу)
         |
         v
Пользователь получает ТОЛЬКО релевантные splits
```

**Основной сценарий (для пользователя)**:
1. Пользователь нажимает "Установить" в Google Play
2. Google Play определяет конфигурацию устройства:
   - Архитектура процессора (arm64-v8a)
   - Плотность экрана (xxhdpi)
   - Язык устройства (ru)
3. Система формирует оптимизированный набор Split APKs для данного устройства
4. Загружается только необходимый объём данных (на 15-35% меньше универсального APK)
5. Split APKs устанавливаются как единое приложение

**Информация о размере на странице приложения**:

| Элемент | Описание |
|---------|----------|
| Размер загрузки | Фактический размер, который будет загружен на конкретное устройство (с учётом оптимизации) |
| Размер на устройстве | Примерный размер после установки (больше размера загрузки из-за распаковки) |

**Лимиты размера**:

| Параметр | Значение |
|----------|----------|
| Максимальный размер загрузки (compressed download) | 200 МБ для AAB |
| Предупреждение о размере при загрузке через мобильные данные | Настраиваемый порог (по умолчанию при больших загрузках) |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-079 | С августа 2021 года все новые приложения в Google Play обязаны использовать формат AAB |
| BR-080 | Средняя экономия размера загрузки при использовании AAB составляет ~15%, для некоторых приложений — до 35% |
| BR-081 | Пользователь видит персонализированный размер загрузки, рассчитанный для его устройства, а не универсальный размер |
| BR-082 | При обновлении загружается дельта (разница между версиями), а не полный пакет, что дополнительно уменьшает размер |
| BR-083 | Разработчик не контролирует, какие splits генерируются — это полностью автоматический процесс Google Play |
| BR-084 | Подпись APK генерируется Google Play (App Signing by Google Play), а не разработчиком |

**Результат**: Пользователь загружает оптимизированный пакет приложения, содержащий только необходимые для его устройства ресурсы.

### FR-GP-INST-015: Условная доставка (Conditional Delivery)

**Приоритет**: P2-Medium

**Описание**: Доставка функциональных модулей приложения на основе характеристик устройства, региона или других условий.

**Акторы**: Система (Google Play), Разработчик (конфигурация модулей)

**Типы доставки модулей**:

| Тип доставки | Описание | Момент загрузки |
|-------------|----------|-----------------|
| Install-time | Модуль доставляется вместе с базовым приложением | При установке |
| On-demand | Модуль загружается по запросу внутри приложения | В процессе использования |
| Conditional | Модуль загружается при установке ТОЛЬКО если устройство соответствует условиям | При установке (условно) |

**Условия для Conditional Delivery**:

| Условие | Пример |
|---------|--------|
| Характеристики оборудования | Камера, AR-сенсоры, NFC, Bluetooth LE |
| Версия OpenGL ES | Модуль для OpenGL ES 3.1+ |
| Страна пользователя | Модуль платёжной системы для конкретного региона |
| Минимальная версия API | Модуль для Android 12+ |

**Основной сценарий — Conditional Delivery**:
1. Пользователь устанавливает приложение
2. Google Play проверяет характеристики устройства
3. На основе условий, заданных разработчиком, формируется набор модулей:
   - Устройство с AR-сенсором — получает AR-модуль
   - Устройство без AR — не получает AR-модуль
4. Пользователь загружает только релевантные модули
5. Размер установки уменьшается за счёт отсутствия ненужных модулей

**Основной сценарий — On-Demand Delivery**:
1. Пользователь устанавливает базовое приложение
2. В процессе использования нажимает на функцию, реализованную как On-Demand модуль
3. Приложение запрашивает загрузку модуля через Play Core Library
4. Google Play начинает загрузку модуля в фоне
5. Пользователь видит прогресс загрузки (реализация UX на стороне разработчика)
6. По завершении загрузки функция становится доступной
7. Модуль сохраняется на устройстве до удаления приложения или ручного удаления

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-085 | Conditional Delivery работает только с приложениями, опубликованными в формате AAB |
| BR-086 | Условия доставки задаются разработчиком при публикации и не могут быть изменены пользователем |
| BR-087 | On-Demand модули имеют ограничение по размеру: до 200 МБ для сжатого размера загрузки |
| BR-088 | Пользователь не видит отдельных модулей — для него это единое приложение |
| BR-089 | Если условия Conditional Delivery изменились (например, пользователь сменил страну), модуль не удаляется автоматически |
| BR-090 | On-Demand модули могут быть удалены приложением программно для освобождения места (Deferred Uninstall) |

**Результат**: Пользователь получает только те функциональные модули, которые релевантны его устройству и контексту.

### FR-GP-INST-016: Instant Apps (пробный запуск без установки)

**Приоритет**: P2-Medium

**Описание**: Запуск приложений без полной установки на устройство для пробного использования.

**Акторы**: Любой пользователь с устройством Android 5.0+

**Предусловия**:
- Разработчик реализовал поддержку Instant Apps для своего приложения
- На устройстве включена функция Google Play Instant (Settings > Google > Instant Apps)

**Источники запуска Instant App**:

| Источник | Описание |
|----------|----------|
| Кнопка "Попробовать" в Google Play | На странице приложения кнопка "Попробовать" рядом с "Установить" |
| Ссылка (URL) | Переход по ссылке, связанной с Instant App |
| Баннер на сайте | Smart Banner на мобильном сайте разработчика |
| Google Play Games | Кнопка "Instant Play" для игр |
| Реклама (Google Ads) | Рекламный баннер с кнопкой запуска |
| Сообщение в мессенджере | Ссылка на Instant App, переданная в чате |

**Основной сценарий**:
1. Пользователь нажимает "Попробовать" на странице приложения в Google Play
2. Система загружает минимально необходимый модуль приложения (без полной установки)

4. Пользователь взаимодействует с приложением

   - Отображается предложение "Установить полную версию"

**Ограничения Instant Apps**:

| Ограничение | Значение |
|------------|----------|
| Максимальный размер модуля | 15 МБ (рекомендуется как можно меньше) |
| Доступ к хранилищу | Ограниченный (sandbox) |
| Фоновая работа | Ограничена |
| Push-уведомления | Недоступны |
| Уникальные идентификаторы устройства | Ограничены |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-091 | Instant App не устанавливается на устройство — его данные временные и удаляются после использования |
| BR-092 | Пользователь может в любой момент установить полную версию приложения из Instant App |
| BR-093 | Данные и прогресс из Instant App могут быть перенесены в полную версию (если разработчик реализовал Transfer API) |
| BR-094 | Google Play Instant можно отключить глобально в настройках устройства |
| BR-095 | Instant Apps работают в sandbox-режиме с ограниченными разрешениями (нет доступа к контактам, камере и т.д. без явного запроса) |
| BR-096 | Для игр функция называется "Instant Play" и доступна через Google Play Games |
| BR-097 | Размер Instant App-модуля должен быть не более 15 МБ для обеспечения быстрого запуска |

**Результат**: Пользователь пробует приложение без установки; при необходимости устанавливает полную версию с сохранением данных.

### FR-GP-INST-017: Управление хранилищем

**Приоритет**: P1-High

**Описание**: Инструменты для управления дисковым пространством, занимаемым приложениями, их данными и кэшем.

**Акторы**: Владелец аккаунта Google, Система (автоматическая архивация)

**Компоненты хранилища приложения**:

| Компонент | Описание | Можно очистить |
|-----------|----------|:--------------:|
| Приложение (APK/код) | Исполняемый код приложения | Только удалением приложения |
| Данные пользователя | Настройки, БД, файлы приложения | Да (очистить данные) |
| Кэш | Временные файлы для ускорения работы | Да (очистить кэш) |
| Дополнительные файлы | OBB, медиа, загрузки | Зависит от приложения |

**Сценарий управления хранилищем через Google Play**:
1. Пользователь переходит в "Управление приложениями и устройством"
2. В разделе "Обзор" система отображает:
   - Общий объём хранилища
   - Использованное и свободное место
3. Пользователь нажимает "Освободить место"
4. Система предлагает действия:
   - Удалить неиспользуемые приложения
   - Очистить кэш приложений
   - Удалить загруженные файлы
5. Пользователь выбирает приложения/данные для удаления
6. Подтверждает очистку
7. Место освобождается

**Сценарий очистки данных отдельного приложения**:
1. Пользователь переходит в Настройки > Приложения > [Приложение]
2. Раздел "Хранилище"
3. Отображается:
   - Общий размер приложения
   - Размер данных пользователя
   - Размер кэша
4. Действия:
   - "Очистить кэш" — удаление временных файлов (приложение продолжает работать)
   - "Очистить данные" — полный сброс приложения к начальному состоянию

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|

**Приоритет**: P1-High

**Описание**: Автоматическое частичное удаление неиспользуемых приложений для освобождения места с сохранением пользовательских данных и иконки на домашнем экране.

**Акторы**: Система (Google Play), Владелец аккаунта (включение/настройка)

- Функция включена пользователем в настройках Google Play

   - Приложение продолжает работать как раньше

**Состояния приложения при архивации**:

                                          Пользователь нажимает иконку
                                                    |
                                                    v
                                            [Восстановление (загрузка)]

                                                    v

**Управление исключениями**:
1. Пользователь может исключить конкретное приложение из автоархивации

**Акторы**: Владелец аккаунта Google, Система (Google Backup)

**Предусловия**:
- Пользователь имеет Google-аккаунт с историей установок
- На предыдущем устройстве была включена функция резервного копирования

## Ограничения и лимиты

### Системные ограничения

| Параметр | Значение |
|----------|----------|
| Максимальный размер загрузки AAB (compressed) | 200 МБ |
| Максимальный размер Instant App модуля | 15 МБ |
| Максимальный размер Auto Backup на приложение | 25 МБ |
| Участников в Family Group | До 6 |
| Частота проверки обновлений | ~1 раз в сутки |
| Окно автоматического возврата | 2 часа |
| Окно запроса возврата | 48 часов |
| Откладывание обновления (MDM) | До 90 дней |
| Количество устройств на аккаунте | Неограниченно (но неактивные скрываются) |

### Требования к устройству

| Параметр | Требование |
|----------|-----------|
| Google Play Services | Обязательно для работы Google Play |
| Google-аккаунт | Обязателен для установки |
| Интернет-соединение | Обязательно для загрузки; офлайн — только sideloading |
| Свободное место | Минимум размер приложения + временный буфер |
| Версия Android | Определяется minSdkVersion приложения |

### Ограничения по ролям

| Действие | Анонимный | Владелец аккаунта | Ребёнок (Family Link) | MDM-пользователь |
|----------|:---------:|:------------------:|:---------------------:|:-----------------:|
| Просмотр каталога | + | + | + (фильтрованный) | + (фильтрованный) |
| Установка бесплатного | - | + | Требует одобрения | По политике MDM |
| Покупка платного | - | + | Требует одобрения | По политике MDM |
| Обновление | - | + | + (автоматическое) | По политике MDM |
| Удаление | - | + | + | По политике MDM |
| Sideloading | - | + | Обычно запрещено | По политике MDM |
| Удалённая установка | - | + | - | + (администратор) |
| Настройка автообновления | - | + | - | - (MDM контролирует) |
| Управление Family Library | - | + (владелец) | - | - |
