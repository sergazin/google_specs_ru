# Планирование встреч

## Описание

Модуль планирования встреч в Google Calendar предоставляет комплексный набор инструментов для эффективной организации совместных мероприятий. Включает функции создания страниц бронирования (Appointment Schedule), поиска свободного времени (Find a Time), автоматических предложений слотов, управления переговорными комнатами, буферного времени между встречами и сокращенных встреч (Speedy Meetings). Модуль оптимизирует процесс планирования, минимизируя ручную координацию и переписку между участниками.

## Роли пользователей

- **Пользователь (личный аккаунт)** - владелец персонального Google-аккаунта с базовыми функциями планирования и одной страницей бронирования
- **Пользователь Workspace** - участник организации Google Workspace с расширенными функциями, включая доступ к переговорным комнатам
- **Workspace Individual** - подписчик на индивидуальный план с премиальными функциями бронирования
- **Business Standard/Plus/Enterprise пользователь** - сотрудник организации с платной подпиской и полным набором функций
- **Администратор Workspace** - управляющий ресурсами организации (переговорные комнаты, оборудование) и политиками календаря
- **Гость (внешний пользователь)** - человек без аккаунта Google или из внешней организации, бронирующий время через публичную страницу
- **Со-организатор (Co-host)** - пользователь с правами соведущего в расписании встреч

## Функциональные требования

### FR-SCH-001: Создание расписания встреч (Appointment Schedule)

**Описание:** Создание настраиваемого расписания для бронирования встреч внешними и внутренними пользователями

**Роли:** Пользователь, Пользователь Workspace

**Предусловия:**
- Пользователь авторизован в Google Calendar
- Доступ к веб-версии Calendar (создание недоступно на мобильных)

**Основной сценарий:**
1. Пользователь нажимает "Create" в левом верхнем углу
2. Выбирает "Appointment schedule"
3. Система отображает панель настроек "Bookable appointment schedule"
4. Пользователь вводит название расписания
5. Указывает длительность встречи (минимум 5 минут)
6. Настраивает общую доступность по дням недели
7. Опционально устанавливает даты начала и окончания действия расписания
8. Выбирает календари для проверки конфликтов
9. Настраивает дополнительные параметры (буфер, лимиты)
10. Нажимает "Save"
11. Система создает расписание и генерирует уникальную ссылку на страницу бронирования

**Альтернативные сценарии:**
- **А1 (Длительность < 5 минут):** Система отклоняет, минимум 5 минут
- **А2 (Персональный аккаунт):** Ограничение одной страницей бронирования
- **А3 (Премиум подписка):** Доступ к множественным страницам бронирования

**Бизнес-правила:**
- BR-001: Минимальная длительность встречи - 5 минут
- BR-002: Название расписания видно всем, кто имеет ссылку
- BR-003: Расписание автоматически скрывает занятые слоты на основе выбранных календарей
- BR-004: По умолчанию проверяется только основной календарь пользователя
- BR-005: Пользователь с личным аккаунтом может создать только одну страницу бронирования

**Результат:** Создано расписание встреч с уникальной страницей бронирования

### FR-SCH-002: Предварительно настроенная страница бронирования

**Описание:** Автоматическое создание страницы бронирования для пользователей без существующего расписания

**Роли:** Пользователь Workspace

**Предусловия:**
- Пользователь авторизован
- Пользователь не имеет настроенного расписания встреч

**Основной сценарий:**
1. Система автоматически создает предварительно настроенную страницу бронирования
2. Страница появляется в боковой панели Calendar
3. Настройки основаны на рабочих часах пользователя
4. Система автоматически обновляет доступность на основе существующих событий
5. Пользователь может использовать страницу без дополнительной настройки
6. При желании пользователь может редактировать настройки

**Бизнес-правила:**
- BR-010: Предварительно настроенная страница основана на Working Hours пользователя
- BR-011: Автоматическое обновление для избежания конфликтов
- BR-012: Функция доступна для пользователей Workspace

**Результат:** Готовая к использованию страница бронирования без ручной настройки

### FR-SCH-003: Настройка доступности расписания

**Описание:** Детальная настройка временных слотов для бронирования

**Роли:** Пользователь, Пользователь Workspace

**Предусловия:**
- Расписание встреч создано

**Основной сценарий:**
1. Пользователь открывает настройки расписания
2. Устанавливает общую доступность для каждого дня недели
3. Может добавить несколько периодов в один день
4. Настраивает исключения для конкретных дат (Adjusted availability)
5. Указывает календари для проверки конфликтов
6. Устанавливает окно планирования (Scheduling window):
   - Даты начала и окончания приема бронирований
   - Минимальное время до встречи
   - Максимальное время вперед для бронирования
7. Сохраняет настройки

**Альтернативные сценарии:**
- **А1 (Изменение рабочих часов):** При изменении Working Hours расписание НЕ обновляется автоматически
- **А2 (Праздничные дни):** Можно указать особую доступность для конкретных дат

**Бизнес-правила:**
- BR-020: Изменение Working Hours не влияет на существующее расписание автоматически
- BR-021: Можно указать несколько периодов доступности в один день
- BR-022: Adjusted availability имеет приоритет над общими настройками

**Результат:** Настроена детальная доступность для бронирования

### FR-SCH-004: Буферное время между встречами

**Описание:** Автоматическое добавление перерыва между назначенными встречами

**Роли:** Пользователь, Пользователь Workspace

**Предусловия:**
- Расписание встреч создано

**Основной сценарий:**
1. Пользователь открывает настройки расписания
2. Находит раздел "Buffer time"
3. Включает опцию буферного времени
4. Указывает длительность буфера (например, 10, 15, 30 минут)
5. Сохраняет настройки
6. Система автоматически блокирует слоты, примыкающие к забронированным встречам
7. На странице бронирования эти слоты отображаются как недоступные

**Альтернативные сценарии:**
- **А1 (Буфер перед и после):** Можно настроить буфер отдельно до и после встречи
- **А2 (Существующие события):** Буфер учитывает все события в проверяемых календарях

**Бизнес-правила:**
- BR-030: Буферное время блокируется для новых бронирований
- BR-031: Буфер применяется к каждой забронированной встрече
- BR-032: Буфер учитывает существующие события из выбранных календарей

**Результат:** Настроено автоматическое буферное время между встречами

**Бизнес-правила:**

**Результат:** Установлен дневной лимит бронирований

### FR-SCH-006: Бронирование встречи через страницу

**Описание:** Процесс бронирования времени гостем через публичную страницу

**Роли:** Гость (внешний пользователь), Пользователь

**Предусловия:**
- Существует активное расписание встреч
- Гость имеет ссылку на страницу бронирования

**Основной сценарий:**
1. Гость переходит по ссылке на страницу бронирования
2. Система отображает доступные временные слоты
3. Гость выбирает подходящий слот
4. Гость вводит свои данные:
   - Email (обязательно)
   - Имя
   - Дополнительные поля (если настроены)
5. При необходимости гость может добавить сообщение
6. Гость нажимает "Book"
7. Система создает событие в календаре владельца расписания
8. Гость получает подтверждение на email
9. Владелец расписания получает уведомление о новом бронировании

**Альтернативные сценарии:**
- **А1 (Слот занят):** Если другой пользователь забронировал слот раньше, отображается ошибка
- **А2 (Верификация email - премиум):** Система отправляет код подтверждения перед бронированием
- **А3 (Платная встреча - премиум):** Гость перенаправляется на оплату через Stripe

**Бизнес-правила:**
- BR-050: Слот блокируется после подтверждения бронирования
- BR-051: Все занятые слоты (Busy события) не отображаются на странице
- BR-052: События с RSVP "Yes" или "Maybe" блокируют слоты
- BR-053: Целодневные события со статусом "Busy" делают весь день недоступным

**Результат:** Встреча забронирована, событие создано в календарях

**Бизнес-правила:**

### FR-SCH-008: Оплата бронирования через Stripe (Премиум)

**Описание:** Сбор оплаты за бронирование встречи

**Роли:** Гость, Пользователь Workspace (Business Standard/Plus/Enterprise)

**Предусловия:**
- Владелец расписания подключил аккаунт Stripe
- Настроена стоимость встречи

**Основной сценарий:**
1. Гость выбирает слот и заполняет форму
2. Система отображает стоимость встречи
3. Гость нажимает "Book and pay"
4. Система перенаправляет на страницу оплаты Stripe
5. Гость вводит платежные данные
6. После успешной оплаты система создает бронирование
7. Гость получает чек и подтверждение

**Альтернативные сценарии:**
- **А1 (Отмена оплаты):** Бронирование не создается, слот остается доступным
- **А2 (Ошибка платежа):** Отображается сообщение об ошибке, бронирование не создается

**Бизнес-правила:**
- BR-070: Бронирование создается только после успешной оплаты
- BR-071: Функция требует подключения Stripe аккаунта
- BR-072: Оплата мотивирует посещение и снижает no-show

**Результат:** Оплата принята, бронирование создано

## Состояния и переходы

### Состояния расписания встреч (Appointment Schedule)
```
[Draft] -> [Active] -> [Paused] -> [Active]
                  \-> [Deleted]
            [Paused] -> [Deleted]
```
- **Draft** - создается, не опубликовано
- **Active** - активно, принимает бронирования
- **Paused** - приостановлено, не принимает новые бронирования, существующие остаются
- **Deleted** - удалено, недоступно

### Состояния бронирования (Booking)
```
[Pending] -> [Confirmed] -> [Completed]
                       \-> [Cancelled by guest]
                       \-> [Cancelled by owner]
                       \-> [No-show]
```
- **Pending** - ожидает подтверждения (для платных - ожидает оплаты)
- **Confirmed** - подтверждено, событие создано
- **Completed** - встреча состоялась
- **Cancelled by guest** - отменено гостем
- **Cancelled by owner** - отменено владельцем расписания
- **No-show** - гость не явился

### Состояния RSVP события
```
[Not responded] -> [Yes] -> [Maybe] -> [No]
                       \-> [No]
                   [Maybe] -> [Yes]
                        \-> [No]
```
- **Not responded** - без ответа
- **Yes** - участие подтверждено
- **Maybe** - возможное участие
- **No** - отказ от участия

### Состояния переговорной комнаты
```
[Available] -> [Booked] -> [In use] -> [Available]
                      \-> [Released] -> [Available]
           [Booked] -> [Cancelled] -> [Available]
```
- **Available** - свободна для бронирования
- **Booked** - забронирована на определенное время
- **In use** - используется (во время события)
- **Released** - автоматически освобождена (все отказались)
- **Cancelled** - бронирование отменено

## Особенности бизнес-логики

### Автоматическое скрытие занятых слотов
- Система автоматически скрывает слоты на основе событий в выбранных календарях
- Только события со статусом "Busy" блокируют слоты
- RSVP "Yes" или "Maybe" также блокирует слот
- Целодневные события "Busy" делают весь день недоступным

### Интеллектуальный подбор комнат
- Система учитывает рабочую локацию участников
- Приоритет отдается комнатам в здании участников
- История бронирований влияет на рекомендации
- Вместимость и оборудование учитываются автоматически

### Оптимизация времени
- Speedy Meetings создает естественные перерывы между встречами
- Буферное время предотвращает наложение встреч
- Focus Time защищает время для индивидуальной работы
- Time Insights помогает анализировать распределение времени

### Гибридная работа
- Working Location помогает координировать очные встречи
- Система предлагает комнаты на основе физического присутствия участников
- Out of Office информирует об отсутствии на рабочем месте

### Защита от спама (Премиум)
- Верификация email предотвращает фейковые бронирования
- Оплата через Stripe мотивирует реальное посещение
- Лимиты бронирований защищают от злоупотреблений

### Совместимость с разными типами аккаунтов
- Базовые функции доступны всем пользователям
- Премиум функции требуют платной подписки
- Переговорные комнаты доступны только для Workspace
