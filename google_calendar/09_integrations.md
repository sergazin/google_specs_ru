# Интеграции

## Описание

Модуль "Интеграции" обеспечивает связь Google Calendar с экосистемой Google Workspace (Google Meet, Gmail, Google Drive, Google Tasks, Google Maps) и сторонними сервисами (Slack, Zoom, Microsoft Teams). Модуль позволяет автоматически создавать видеоконференции для встреч, извлекать события из электронных писем (авиабилеты, бронирования отелей, ресторанов), прикреплять файлы к событиям, управлять задачами, рассчитывать время в пути с учетом трафика, синхронизировать календари через CalDAV/iCal и встраивать календарь на внешние веб-сайты.

Цель модуля - создать единый центр планирования, где все инструменты для организации времени бесшовно интегрированы друг с другом, обеспечивая максимальную эффективность управления расписанием и минимизацию ручного ввода данных. Интеграции автоматически обогащают события контекстом (ссылки на звонки, файлы, локации, маршруты) и синхронизируют данные между сервисами в реальном времени.

## Роли пользователей

### Роли в контексте интеграций:

1. **Владелец календаря (Calendar Owner)** - пользователь, владеющий основным или вторичным календарем
   - Может настраивать интеграции для своего календаря
   - Может включать/отключать автоматическое создание событий из Gmail
   - Может устанавливать Zoom/Slack/Teams как приложения по умолчанию для конференций
   - Может настраивать публикацию и встраивание календаря
   - Может управлять подключенными сторонними приложениями
   - Может предоставлять/отзывать доступ к API календаря

2. **Организатор события (Event Organizer)** - пользователь, создающий событие
   - Может добавлять Google Meet или сторонние видеоконференции к событию
   - Может прикреплять файлы Google Drive к событиям
   - Может добавлять локации с интеграцией Google Maps
   - Может управлять доступом гостей к прикрепленным файлам
   - Может создавать задачи, связанные с событием

3. **Гость события (Event Guest)** - приглашенный участник события
   - Может просматривать прикрепленные файлы (при наличии доступа)
   - Может присоединяться к видеоконференциям по ссылке
   - Может открывать маршрут до локации в Google Maps
   - Не может изменять настройки интеграций события

4. **Пользователь Google Workspace** - пользователь с корпоративным аккаунтом
   - Может использовать расширенные функции интеграций (автоматическое планирование с Gemini)
   - Может устанавливать дополнения из Google Workspace Marketplace
   - Может синхронизировать календарь с корпоративными системами

5. **Администратор Google Workspace** - корпоративный администратор
   - Может настраивать Google Meet как обязательное приложение для конференций
   - Может отключать/разрешать сторонние интеграции (Zoom, Slack, Teams)
   - Может управлять политиками доступа к API календаря
   - Может настраивать domain-wide делегирование для интеграций
   - Может блокировать/разрешать автоматическое создание событий из Gmail

6. **Внешний пользователь (без аккаунта Google)** - посетитель встроенного календаря
   - Может просматривать публичный календарь через iframe
   - Может видеть события с публичным доступом
   - Не может редактировать или добавлять события
   - Может подписаться на публичный iCal-фид

7. **Разработчик приложения (Third-party Developer)** - создатель интеграций
   - Может получать доступ к API Calendar через OAuth 2.0
   - Должен запрашивать необходимые OAuth scopes
   - Должен пройти верификацию Google для чувствительных scopes
   - Может создавать дополнения для Workspace Marketplace

### FR-INT-001: Автоматическое добавление Google Meet к событию

**Описание:** Позволяет автоматически создавать уникальную ссылку на видеоконференцию Google Meet при создании события в календаре, обеспечивая мгновенный доступ к виртуальной встрече для всех участников.

**Роли:** Организатор события, Пользователь Google Workspace, Администратор Google Workspace

**Предусловия:**
- Пользователь авторизован в Google Calendar
- Google Meet не заблокирован администратором организации
- Пользователь создает новое событие или редактирует существующее

**Основной сценарий:**
1. Пользователь открывает Google Calendar и нажимает на время для создания нового события
2. В форме создания события появляется опция "Add Google Meet video conferencing"
3. Пользователь нажимает на кнопку добавления видеоконференции
4. Система автоматически генерирует уникальную ссылку Google Meet
5. Ссылка на Meet отображается в описании события с кнопкой "Join with Google Meet"
6. При сохранении события ссылка включается в приглашение, отправляемое гостям
7. Гости получают email с прямой ссылкой для присоединения к звонку

**Альтернативные сценарии:**
- Сценарий A (Автоматическое добавление Meet по умолчанию): Администратор Workspace настраивает политику автоматического добавления Meet к всем событиям с гостями, при создании события с приглашенными Meet ссылка генерируется автоматически без действий пользователя
- Сценарий B (Изменение ссылки Meet): Организатор решает использовать другую ссылку Meet, нажимает "Change conference", выбирает "Create new meeting" или вводит код существующей встречи, старая ссылка заменяется
- Сценарий C (Удаление Meet из события): Организатор нажимает крестик рядом с ссылкой Meet, конференция удаляется из события, гости получают обновленное приглашение без ссылки на звонок
- Сценарий D (Присоединение к Meet из календаря): Пользователь открывает событие за несколько минут до начала, нажимает кнопку "Join with Google Meet", браузер открывает страницу Meet с предпросмотром видео/аудио

**Бизнес-правила:**
- BR-INT-001: Каждое событие может иметь только одну ссылку на видеоконференцию
- BR-INT-002: Ссылка Meet остается активной и после окончания события (может быть использована повторно)
- BR-INT-003: Гости видят ссылку Meet в приглашении независимо от наличия Google аккаунта
- BR-INT-004: Google Meet бесплатен для всех пользователей с Google аккаунтом
- BR-INT-005: Для Google Workspace пользователей доступны расширенные функции Meet (запись, noise cancellation, breakout rooms)
- BR-INT-006: Администратор может установить Google Meet как единственный разрешенный сервис видеоконференций

**Результат:** Событие создано с уникальной ссылкой Google Meet, все гости получили приглашение с возможностью присоединиться к звонку одним кликом

### FR-INT-002: Расширенные функции Google Meet в событии

**Описание:** Позволяет организаторам настраивать дополнительные параметры Google Meet встречи непосредственно из интерфейса Google Calendar, включая комнату ожидания, автоматические заметки, контроль доступа и настройки записи.

**Роли:** Организатор события, Пользователь Google Workspace

**Предусловия:**
- Событие содержит ссылку на Google Meet
- Пользователь является организатором события
- Пользователь имеет подписку Google Workspace (для расширенных функций)

**Основной сценарий:**
1. Организатор открывает событие с Google Meet в Google Calendar
2. Нажимает на раздел видеоконференции для открытия настроек Meet
3. Видит доступные опции: "Waiting room", "Take notes for me", "Record meeting"
4. Включает нужные опции переключателями
5. Сохраняет событие с обновленными настройками Meet
6. При начале встречи выбранные функции активируются автоматически
7. После встречи заметки и запись (если включены) отправляются участникам по email

**Альтернативные сценарии:**
- Сценарий A (Комната ожидания): Организатор включает "Waiting room", при присоединении участников они попадают в виртуальную комнату ожидания, организатор получает уведомление и принимает/отклоняет каждого участника
- Сценарий B (Автоматические заметки): Организатор включает "Take notes for me", во время встречи AI записывает ключевые моменты, после встречи участники получают email с резюме, ключевыми решениями и следующими шагами
- Сценарий C (Запись встречи): Организатор включает "Record meeting", запись начинается при входе первого участника, после окончания запись сохраняется в Google Drive организатора, ссылка отправляется участникам
- Сценарий D (Настройка доступа): Организатор ограничивает доступ к встрече только для приглашенных гостей, пользователи без приглашения видят сообщение "Ask to join" и ждут одобрения организатора

**Бизнес-правила:**
- BR-INT-007: Функция записи доступна только для Google Workspace Business Standard и выше
- BR-INT-008: Автоматические заметки ("Take notes for me") доступны для Workspace с Gemini
- BR-INT-009: Комната ожидания по умолчанию отключена для событий внутри организации
- BR-INT-010: Записи встреч занимают место в Google Drive организатора
- BR-INT-011: Участники получают уведомление о начале записи встречи
- BR-INT-012: Заметки после встречи включают резюме, ключевые решения и suggested next steps

**Результат:** Настройки Google Meet сконфигурированы, при проведении встречи активируются автоматические заметки, запись и контроль доступа согласно настройкам

### FR-INT-003: Автоматическое создание событий из Gmail (бронирования)

**Описание:** Позволяет Google Calendar автоматически распознавать информацию о бронированиях и резервациях из входящих писем Gmail (авиабилеты, отели, рестораны, билеты на мероприятия) и создавать соответствующие события в календаре.

**Роли:** Владелец календаря, Пользователь Google Workspace, Администратор Google Workspace

**Предусловия:**
- Пользователь использует Gmail как почтовый сервис
- Включена опция "Smart features and personalization" в Gmail
- Включена опция "Show events automatically created by Gmail in my calendar" в Google Calendar
- Пользователь получает подтверждение бронирования от поддерживаемых сервисов

**Основной сценарий:**
1. Пользователь бронирует авиабилет на сайте авиакомпании
2. Авиакомпания отправляет email-подтверждение на Gmail пользователя
3. Gmail анализирует содержимое письма и обнаруживает данные о рейсе
4. Google Calendar автоматически создает событие с информацией: дата вылета, время, номер рейса, аэропорты
5. Событие появляется в календаре пользователя с пометкой "Gmail"
6. При открытии события отображается ссылка на исходное письмо-подтверждение
7. Пользователь может редактировать или удалить автоматически созданное событие

**Альтернативные сценарии:**
- Сценарий A (Бронирование отеля): Пользователь получает подтверждение от Booking.com или Airbnb, Calendar создает событие на период проживания с адресом отеля, датами заезда/выезда, номером брони и ссылкой на письмо
- Сценарий B (Бронирование ресторана): Пользователь получает подтверждение от OpenTable, Calendar создает событие на время резервации с названием ресторана, адресом и количеством гостей
- Сценарий C (Билеты на мероприятие): Пользователь получает e-ticket на концерт или спортивное мероприятие, Calendar создает событие с датой, временем, названием мероприятия и адресом площадки
- Сценарий D (Изменение бронирования): Авиакомпания отправляет email об изменении рейса, Calendar автоматически обновляет соответствующее событие с новым временем, пользователь получает уведомление об изменении

**Бизнес-правила:**
- BR-INT-013: События из Gmail видны только владельцу календаря, даже если календарь общий
- BR-INT-014: Автоматическое создание событий работает только для подтверждающих писем (не пересылок, не копий)
- BR-INT-015: Поддерживаются крупные авиакомпании, сети отелей, системы бронирования ресторанов, билетные системы
- BR-INT-016: События обновляются автоматически при получении измененного подтверждения
- BR-INT-017: Пользователь может отключить функцию в настройках Calendar -> "Events from Gmail"
- BR-INT-018: Удаление события из календаря не влияет на исходное бронирование

**Результат:** Событие автоматически создано в календаре на основе письма-подтверждения с полной информацией о бронировании и ссылкой на исходное письмо

### FR-INT-004: Ручное добавление события из Gmail с помощью Gemini

**Описание:** Позволяет пользователям быстро создавать события в Google Calendar из контекста email-переписки с помощью AI-ассистента Gemini, который анализирует содержание письма и предлагает детали события.

**Роли:** Пользователь Google Workspace с Gemini

**Предусловия:**
- Пользователь имеет подписку Google Workspace с Gemini
- Пользователь читает email в Gmail
- Боковая панель Gemini доступна в Gmail

**Основной сценарий:**
1. Пользователь открывает email с обсуждением встречи или события
2. Нажимает на иконку Gemini в боковой панели Gmail
3. Вводит запрос: "Создай событие в календаре на основе этого письма"
4. Gemini анализирует содержимое письма и предлагает детали события: название, дату, время, участников
5. Пользователь просматривает предложенные данные и корректирует при необходимости
6. Нажимает "Add to Calendar" для создания события
7. Событие создается в Google Calendar с заполненными полями

**Альтернативные сценарии:**
- Сценарий A (Help me schedule): Пользователь нажимает "Help me schedule" в Gmail, Gemini анализирует переписку и календарь пользователя, предлагает оптимальное время встречи на основе доступности всех участников
- Сценарий B (Прямое определение события): Gemini обнаруживает в письме детали события (дату, время), показывает кнопку "Add to Calendar" прямо в интерфейсе письма, пользователь нажимает для мгновенного создания
- Сценарий C (Шаблон Appointment Schedule): Пользователь создает страницу бронирования Appointment Schedule, делится ссылкой в email, получатели могут выбрать удобное время без переписки

**Бизнес-правила:**
- BR-INT-019: Gemini анализирует только письма в текущем треде при создании события
- BR-INT-020: Функция "Help me schedule" требует доступа к календарям всех участников
- BR-INT-021: Appointment Schedule ссылки можно вставлять в Gmail через опцию Compose
- BR-INT-022: Gemini не создает события без подтверждения пользователя
- BR-INT-023: Созданные через Gemini события идентичны обычным событиям календаря

**Результат:** Событие создано в Google Calendar на основе анализа email Gemini с автоматически заполненными деталями

### FR-INT-005: Прикрепление файлов Google Drive к событиям

**Описание:** Позволяет пользователям прикреплять файлы из Google Drive к событиям календаря для предоставления участникам доступа к материалам встречи: повесткам, презентациям, документам.

**Роли:** Организатор события, Владелец календаря

**Предусловия:**
- Пользователь создает или редактирует событие
- Пользователь имеет доступ к Google Drive
- Файл для прикрепления находится в Drive

**Основной сценарий:**
1. Пользователь открывает событие для редактирования
2. В описании события нажимает иконку скрепки "Add attachment" или "Add Google Drive attachment"
3. Открывается окно выбора файла из Google Drive с вкладками: "My Drive", "Shared with me", "Recent"
4. Пользователь выбирает файл (документ, презентацию, таблицу, PDF)
5. Нажимает "Select" для прикрепления файла к событию
6. Система показывает диалог: "Share this file with meeting attendees?"
7. Пользователь выбирает уровень доступа: View, Comment, Edit
8. Файл прикрепляется к событию, гости получают обновленное приглашение с ссылкой на файл

**Альтернативные сценарии:**
- Сценарий A (Автоматическое предоставление доступа): Пользователь нажимает "Share with all guests", система автоматически предоставляет права Viewer всем текущим и будущим гостям события
- Сценарий B (Прикрепление нескольких файлов): Пользователь повторяет процесс добавления для каждого файла, все файлы отображаются списком в описании события
- Сценарий C (Загрузка с компьютера): Пользователь в окне выбора файла нажимает "Upload", загружает файл с компьютера, файл сохраняется в Drive и прикрепляется к событию
- Сценарий D (Открытие файла из события): Гость открывает событие в календаре, видит список прикрепленных файлов, нажимает на файл, документ открывается в новой вкладке

**Бизнес-правила:**
- BR-INT-024: Прикрепленные файлы видны всем гостям события (при наличии доступа)
- BR-INT-025: Права на файлы сохраняются и после окончания события
- BR-INT-026: Организатор может отозвать доступ к файлу через Google Drive в любое время
- BR-INT-027: Названия файлов отображаются в приглашении и уведомлениях о событии
- BR-INT-028: Если у гостя нет доступа к файлу, он видит запрос на доступ
- BR-INT-029: Максимальное количество прикрепленных файлов не ограничено

**Результат:** Файлы из Google Drive прикреплены к событию, все гости получили соответствующий уровень доступа и могут открыть материалы из приглашения

### FR-INT-006: Интеграция с Google Tasks - создание задач в календаре

**Описание:** Позволяет пользователям создавать и управлять задачами Google Tasks непосредственно из интерфейса Google Calendar, с возможностью блокировки времени для работы над задачей.

**Роли:** Владелец календаря, Пользователь Google Workspace

**Предусловия:**
- Пользователь авторизован в Google Calendar
- Google Tasks доступен для пользователя
- Пользователь имеет права на создание событий в календаре

**Основной сценарий:**
1. Пользователь открывает Google Calendar
2. Нажимает на время в календарной сетке для создания нового элемента
3. В появившемся окне переключается с "Event" на "Task"
4. Вводит название задачи и описание
5. Устанавливает дату и опционально время для задачи

### FR-INT-013: Синхронизация через CalDAV

**Описание:** Позволяет подключать Google Calendar к сторонним приложениям календаря через протокол CalDAV для двунаправленной синхронизации событий.

**Роли:** Владелец календаря, Разработчик приложения

**Предусловия:**
- Стороннее приложение поддерживает протокол CalDAV
- Приложение использует OAuth 2.0 для аутентификации
- Пользователь предоставил разрешение на доступ к календарю

**Основной сценарий:**
1. Пользователь открывает стороннее приложение календаря (например, Apple Calendar)
2. Выбирает опцию добавления аккаунта CalDAV
3. Вводит URL сервера CalDAV: https://apidata.googleusercontent.com/caldav/v2/calid/user
4. Система перенаправляет на страницу авторизации Google
5. Пользователь входит в Google аккаунт и предоставляет права
6. Приложение получает OAuth токен и подключается к календарю
7. События синхронизируются между Google Calendar и сторонним приложением

**Альтернативные сценарии:**
- Сценарий A (Apple Calendar на Mac): Пользователь в системных настройках добавляет Internet Accounts -> Google, выбирает Calendars, система автоматически настраивает CalDAV
- Сценарий B (Thunderbird): Пользователь устанавливает Lightning add-on, добавляет CalDAV календарь через File -> New -> Calendar, вводит Google CalDAV URL
- Сценарий C (Ошибка аутентификации): Старое приложение использует Basic Authentication, Google отклоняет соединение с 401 Unauthorized, пользователь должен использовать приложение с поддержкой OAuth 2.0

**Бизнес-правила:**
- BR-INT-071: Google Calendar CalDAV требует OAuth 2.0, Basic Authentication не поддерживается
- BR-INT-072: Старый endpoint https://www.google.com/calendar/dav устарел и не поддерживается
- BR-INT-073: CalID в URL - это ID календаря из настроек Google Calendar
- BR-INT-074: Синхронизация двунаправленная: изменения отправляются в обе стороны
- BR-INT-075: Поддерживаются стандартные CalDAV операции: REPORT, PUT, DELETE

### FR-INT-018: API доступ для сторонних приложений

**Описание:** Позволяет сторонним приложениям получать доступ к данным Google Calendar через Google Calendar API с использованием OAuth 2.0 авторизации.

**Роли:** Разработчик приложения, Пользователь, Администратор Google Workspace

**Предусловия:**
- Разработчик зарегистрировал приложение в Google Cloud Console
- Приложение запрашивает соответствующие OAuth scopes
- Приложение прошло верификацию Google (для чувствительных scopes)

**Основной сценарий:**
1. Пользователь открывает стороннее приложение, требующее доступ к календарю
2. Приложение перенаправляет на страницу авторизации Google
3. Пользователь входит в Google аккаунт
4. Google показывает запрашиваемые разрешения: "View and edit your calendar", "See your primary Google Account email address"
5. Пользователь нажимает "Allow" для предоставления доступа
6. Google возвращает access token приложению
7. Приложение использует API для чтения/записи событий календаря

**Альтернативные сценарии:**
- Сценарий A (Минимальные scopes): Приложение запрашивает только calendar.readonly scope, может только читать события, не может создавать или редактировать
- Сценарий B (Отзыв доступа): Пользователь в настройках Google Account -> Security -> Third-party apps видит приложение, нажимает "Remove access", приложение теряет доступ к календарю
- Сценарий C (Domain-wide delegation): Администратор настраивает service account с domain-wide delegation, приложение может действовать от имени любого пользователя организации без индивидуального согласия
- Сценарий D (Верификация приложения): Google требует верификацию для scopes типа calendar или calendar.events, разработчик подает заявку, проходит проверку безопасности

**Бизнес-правила:**
- BR-INT-101: OAuth scopes определяют уровень доступа приложения: readonly, events, settings
- BR-INT-102: Пользователь должен явно предоставить разрешения каждому приложению
- BR-INT-103: Администратор может пометить приложение как Trusted (полный доступ), Limited или Blocked
- BR-INT-104: Domain-wide delegation требует настройки в Admin Console и подтверждения scopes
- BR-INT-105: Access tokens истекают через 1 час, refresh tokens позволяют получить новые
- BR-INT-106: Чувствительные scopes требуют прохождения верификации Google

**Результат:** Стороннее приложение получило авторизованный доступ к Google Calendar API в рамках предоставленных scopes

## Состояния интеграций

### Состояния подключения интеграции:

```
[Not Installed] -> [Installing] -> [Connected] -> [Error] -> [Reconnecting]
                                       |              ^            |
                                       v              |            |
                                 [Disconnected] ------+------------+
```

**Not Installed (Не установлено)**
- Дополнение не установлено
- Пользователь видит опцию установки в Marketplace
- Функциональность недоступна

**Installing (Установка)**
- Пользователь инициировал установку
- Запрошены разрешения OAuth
- Ожидание подтверждения пользователя

**Connected (Подключено)**
- OAuth авторизация успешна
- Access token активен
- Интеграция функционирует нормально

**Error (Ошибка)**
- Token истек или отозван
- API недоступен
- Требуется повторная авторизация

**Reconnecting (Переподключение)**
- Система автоматически обновляет token
- Попытка восстановить соединение
- Временная недоступность

**Disconnected (Отключено)**
- Пользователь отозвал доступ
- Администратор заблокировал приложение
- Требуется повторная установка
