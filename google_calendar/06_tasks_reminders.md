# Задачи и напоминания (Tasks & Reminders)

## Описание

Модуль "Задачи и напоминания" управляет созданием, организацией и выполнением задач в экосистеме Google Calendar и Google Tasks. Начиная с 2023-2025 годов Google объединил функционал напоминаний (Reminders) из Calendar и Google Assistant в единый продукт Google Tasks, создав унифицированную систему управления делами. Задачи интегрированы с Google Calendar, Gmail, Google Docs, Google Drive, Google Chat и голосовым ассистентом Gemini. С ноября 2025 года появилась возможность блокировать время в календаре для работы над задачами, отображая статус "Занят" (Busy).

## Роли пользователей

### Владелец аккаунта (Account Owner)
- Полный доступ ко всем спискам задач и задачам
- Создание, редактирование, удаление задач и списков
- Настройка уведомлений и напоминаний
- Управление интеграциями с другими сервисами Google
- Блокировка времени в календаре для задач
- Назначение задач другим пользователям (в Google Chat/Docs)

### Участник Google Chat Space (Chat Space Member)
- Получение назначенных задач через Space
- Редактирование назначенных задач
- Отметка задач как выполненных
- Просмотр назначенных задач в своем списке Tasks
- Не может создавать повторяющиеся задачи для других

### Участник совместного документа (Document Collaborator)
- Получение назначенных задач через Google Docs
- Редактирование назначенных задач
- Отметка задач как выполненных
- Просмотр связи задачи с исходным документом

### Администратор Google Workspace (Workspace Admin)
- Управление политиками Tasks для организации
- Настройка ограничений на интеграции
- Доступ к аудит-логам действий с задачами
- Управление миграцией напоминаний в Tasks

## Функциональные требования

### FR-TSK-001: Создание задачи
**Описание:** Создание новой задачи в списке Google Tasks
**Роли:** Владелец аккаунта
**Предусловия:**
- Пользователь авторизован в Google аккаунте
- Google Tasks доступен в регионе пользователя

**Основной сценарий:**
1. Пользователь открывает Google Tasks (через Calendar, Gmail, или tasks.google.com)
2. Пользователь нажимает "Add a task" или "+"
3. Система создает пустую задачу в режиме редактирования
4. Пользователь вводит название задачи
5. Пользователь опционально добавляет:
   - Описание (детали задачи)
   - Дату и время выполнения
   - Повторение
   - Список (категория)
6. Пользователь сохраняет задачу (нажатием Enter или кликом вне поля)
7. Система добавляет задачу в выбранный список
8. Если указана дата, задача появляется в Google Calendar

**Альтернативный сценарий A1: Создание задачи через Calendar**
1. Пользователь кликает на пустое место в Google Calendar
2. Система показывает всплывающее окно создания события
3. Пользователь выбирает вкладку "Task"
4. Пользователь заполняет данные задачи
5. Система создает задачу с привязкой к выбранной дате

**Альтернативный сценарий A2: Создание задачи из email**
1. Пользователь открывает Gmail
2. Пользователь выделяет email(ы) в списке
3. Пользователь нажимает иконку "Add to tasks" или Shift+T
4. Система создает задачу с названием = тема письма
5. Система добавляет ссылку на исходное письмо в задачу

**Альтернативный сценарий A3: Создание задачи через drag-and-drop**
1. Пользователь перетаскивает email из Gmail в панель Tasks
2. Система создает задачу с названием = тема письма
3. Можно перетащить несколько писем одновременно

**Бизнес-правила:**
- BR-001: Название задачи обязательно (не может быть пустым)
- BR-002: Максимальная длина названия задачи при миграции из Keep сокращается
- BR-003: Задача по умолчанию создается в списке "My Tasks" или последнем использованном
- BR-004: Дата и время необязательны
- BR-005: Задача без даты не отображается в Calendar, но доступна в Tasks
- BR-006: Максимум 100,000 задач на аккаунт (всего)
- BR-007: Максимум 20,000 незавершенных задач в одном списке

**Результат:** Задача создана и доступна в Google Tasks

### FR-TSK-002: Редактирование задачи
**Описание:** Изменение параметров существующей задачи
**Роли:** Владелец аккаунта, Участник Chat Space (для назначенных), Участник документа (для назначенных)
**Предусловия:**
- Задача существует
- Пользователь имеет права на редактирование

**Основной сценарий:**
1. Пользователь кликает на задачу в списке Tasks
2. Система открывает детали задачи
3. Пользователь редактирует нужные поля:
   - Название
   - Описание
   - Дата/время
   - Повторение
   - Список (перемещение)
4. Изменения сохраняются автоматически
5. Если изменена дата, задача перемещается в Calendar

**Альтернативный сценарий A1: Перемещение задачи в другой список**
1. Пользователь открывает задачу
2. Пользователь нажимает на текущий список
3. Система показывает выпадающий список доступных списков
4. Пользователь выбирает целевой список
5. Задача перемещается в новый список

**Альтернативный сценарий A2: Изменение даты перетаскиванием**
1. Пользователь находится в Google Calendar
2. Пользователь перетаскивает задачу на новую дату/время
3. Система обновляет дату и время задачи

**Бизнес-правила:**
- BR-010: Изменения синхронизируются в реальном времени
- BR-011: Повторяющиеся задачи нельзя перемещать в другой список
- BR-012: Общие (shared) задачи нельзя делать повторяющимися
- BR-013: При изменении даты повторяющейся задачи меняется только текущий экземпляр
- BR-014: Редактирование серии повторений доступно через меню повторения

**Результат:** Задача обновлена

### FR-TSK-003: Удаление задачи
**Описание:** Удаление задачи из системы
**Роли:** Владелец аккаунта, Участник Chat Space (для назначенных), Участник документа (для назначенных)
**Предусловия:**
- Задача существует
- Пользователь имеет права на удаление

**Основной сценарий:**
1. Пользователь открывает контекстное меню задачи
2. Пользователь выбирает "Delete"
3. Система удаляет задачу
4. Задача исчезает из списка и Calendar
5. Для повторяющихся задач удаляется вся серия

**Альтернативный сценарий A1: Удаление одного экземпляра повторяющейся задачи**
1. Пользователь открывает повторяющуюся задачу в Calendar
2. Пользователь удаляет только текущий экземпляр
3. Следующие экземпляры серии сохраняются

**Бизнес-правила:**
- BR-020: Удаление необратимо
- BR-021: При удалении общей задачи она удаляется у всех участников
- BR-022: Удаление задачи из Calendar удаляет её из Tasks и наоборот

**Результат:** Задача удалена из системы

### FR-TSK-004: Отметка задачи как выполненной
**Описание:** Изменение статуса задачи на "Выполнено"
**Роли:** Владелец аккаунта, Участник Chat Space, Участник документа
**Предусловия:**
- Задача существует
- Задача не завершена

**Основной сценарий:**
1. Пользователь нажимает на чекбокс слева от названия задачи
2. Система отмечает задачу как выполненную
3. Задача визуально перечеркивается
4. Задача перемещается в секцию "Completed"
5. Если задача повторяющаяся, создается следующий экземпляр
6. Следующий экземпляр появляется в списке задач
7. Система записывает дату завершения (completed date)

**Альтернативный сценарий A1: Отметка выполнения через Calendar**
1. Пользователь находит задачу в Google Calendar
2. Пользователь кликает на задачу
3. Пользователь нажимает "Mark complete"
4. Задача отмечается как выполненная

**Альтернативный сценарий A2: Отмена выполнения**
1. Пользователь находит выполненную задачу в секции "Completed"
2. Пользователь нажимает на чекбокс
3. Система возвращает задачу в активные
4. Задача снова отображается в основном списке

**Бизнес-правила:**
- BR-030: Выполненные задачи сохраняются в истории 365 дней
- BR-031: Для повторяющейся задачи при завершении автоматически создается следующий экземпляр
- BR-032: Дата завершения записывается для аналитики (начиная с 2025)
- BR-033: Выполненные задачи можно скрыть из отображения
- BR-034: Нельзя отменить выполнение для удаленных серий повторений

**Результат:** Задача отмечена как выполненная

### FR-TSK-005: Создание подзадач (Subtasks)
**Описание:** Добавление подзадач к основной задаче
**Роли:** Владелец аккаунта
**Предусловия:**
- Основная задача существует
- Задача не является общей (shared)

**Основной сценарий:**
1. Пользователь открывает задачу
2. Пользователь выбирает "Add subtask" в контекстном меню
3. Система создает подзадачу под основной задачей
4. Пользователь вводит название подзадачи
5. Подзадача отображается с отступом под родительской задачей

**Альтернативный сценарий A1: Преобразование задачи в подзадачу**
1. Пользователь выделяет задачу
2. Пользователь нажимает Tab или Ctrl+] (Mac: Cmd+])
3. Задача становится подзадачей предыдущей задачи в списке

**Альтернативный сценарий A2: Преобразование подзадачи в задачу**
1. Пользователь выделяет подзадачу
2. Пользователь нажимает Shift+Tab или Ctrl+[ (Mac: Cmd+[)
3. Подзадача становится самостоятельной задачей

**Бизнес-правила:**
- BR-040: Подзадачи не могут быть повторяющимися
- BR-041: Задачи с подзадачами не могут быть повторяющимися
- BR-042: Общие (shared) задачи не могут иметь подзадач
- BR-043: Подзадачи не отображаются отдельно в Calendar
- BR-044: При выполнении родительской задачи подзадачи остаются незавершенными
- BR-045: Глубина вложенности подзадач: 1 уровень (подзадачи не могут иметь подзадач)

**Результат:** Подзадача создана

### FR-TSK-006: Управление списками задач (Task Lists)
**Описание:** Создание и управление категориями задач
**Роли:** Владелец аккаунта
**Предусловия:**
- Пользователь авторизован

**Основной сценарий - Создание списка:**
1. Пользователь открывает боковую панель Tasks
2. Пользователь нажимает на выпадающий список текущего списка
3. Пользователь выбирает "Create new list"
4. Пользователь вводит название списка
5. Система создает пустой список
6. Пользователь может переключаться между списками

**Альтернативный сценарий A1: Переименование списка**
1. Пользователь открывает настройки списка (три точки)
2. Пользователь выбирает "Rename list"
3. Пользователь вводит новое название
4. Система обновляет название

**Альтернативный сценарий A2: Удаление списка**
1. Пользователь открывает настройки списка
2. Пользователь выбирает "Delete list"
3. Система запрашивает подтверждение
4. Пользователь подтверждает
5. Система удаляет список и все задачи в нем

**Альтернативный сценарий A3: Изменение порядка списков**
1. Пользователь открывает выпадающее меню списков
2. Пользователь перетаскивает список в новую позицию
3. Система сохраняет новый порядок

**Бизнес-правила:**
- BR-050: Список "My Tasks" существует по умолчанию и не может быть удален
- BR-051: Название списка не может быть пустым
- BR-052: При удалении списка все задачи удаляются безвозвратно
- BR-053: Можно создавать неограниченное количество списков
- BR-054: Списки не могут быть общими (sharing lists не поддерживается)
- BR-055: Специальные списки создаются автоматически: "Starred", "Old Google Keep Reminders"

**Результат:** Список создан/изменен/удален

### FR-TSK-007: Настройка повторяющихся задач
**Описание:** Создание задач с автоматическим повторением
**Роли:** Владелец аккаунта
**Предусловия:**
- Задача существует
- Задача не является общей
- Задача не имеет подзадач

**Основной сценарий:**
1. Пользователь создает или открывает задачу
2. Пользователь нажимает "Add date/time" -> "Repeat"
3. Система показывает варианты повторения:
   - Daily (ежедневно)
   - Weekly (еженедельно)
   - Monthly (ежемесячно)
   - Yearly (ежегодно)
   - Custom (настраиваемое)
4. Пользователь выбирает частоту
5. Пользователь настраивает окончание:
   - Never (никогда)
   - On date (до определенной даты)
   - After N occurrences (после N повторений)
6. Система сохраняет настройки повторения

**Альтернативный сценарий A1: Custom повторение**
1. Пользователь выбирает "Custom"
2. Система показывает настройки:
   - "Repeats every" (каждые N): день/неделю/месяц/год
   - Для недели: выбор дней недели
   - Для месяца: по числу или по дню недели
3. Пользователь настраивает и сохраняет

**Альтернативный сценарий A2: Остановка повторения**
1. Пользователь открывает повторяющуюся задачу
2. Пользователь нажимает на информацию о повторении
3. Пользователь выбирает "Stop repeating"
4. Система останавливает серию
5. Оставшиеся будущие экземпляры не создаются

**Бизнес-правила:**
- BR-060: Для повторения обязательна дата
- BR-061: Время необязательно (по умолчанию: весь день)
- BR-062: При завершении задачи создается следующий экземпляр серии
- BR-063: Повторяющиеся задачи нельзя перемещать между списками
- BR-064: Если серия остановлена, её нельзя возобновить (нужно создать новую)
- BR-065: Удаление одного экземпляра из Calendar не влияет на всю серию
- BR-066: Общие (shared) и подзадачи не могут повторяться

**Результат:** Настроено повторение задачи

### FR-TSK-008: Блокировка времени для задачи (Time Blocking) - Новая функция 2025
**Описание:** Резервирование времени в календаре для работы над задачей
**Роли:** Владелец аккаунта
**Предусловия:**
- Пользователь использует Google Calendar
- Функция доступна (rollout с ноября 2025)

**Основной сценарий:**
1. Пользователь кликает на пустой временной слот в Calendar
2. Система показывает меню создания
3. Пользователь выбирает "Task"
4. Пользователь вводит название задачи
5. Пользователь устанавливает продолжительность (duration)
6. Пользователь включает опцию "Mark as busy"
7. Система создает задачу с блокировкой времени
8. Время отображается как "Занят" (Busy) для других
9. Задача появляется и в Calendar, и в Tasks

**Альтернативный сценарий A1: Включение "Do Not Disturb"**
1. После шага 6 пользователь включает "Do not disturb"
2. Система активирует режим "Не беспокоить" на время задачи
3. Уведомления блокируются в этот период
4. Доступно только для Work/School аккаунтов

**Альтернативный сценарий A2: Автоматическое отклонение встреч**
1. После шага 6 пользователь включает "Automatically decline meetings"
2. Система автоматически отклоняет приглашения на это время
3. Доступно только для Work/School аккаунтов

**Альтернативный сценарий A3: Добавление времени к существующей задаче**
1. Пользователь открывает существующую задачу
2. Пользователь добавляет дату, время и продолжительность
3. Пользователь включает "Mark as busy"
4. Задача превращается в блок времени в Calendar

**Бизнес-правила:**
- BR-070: Duration (продолжительность) необязательна для обычных задач
- BR-071: Для отображения "Busy" нужно указать время и продолжительность
- BR-072: Задача не исчезает после окончания времени блока
- BR-073: Задача остается в списке до отметки "Выполнено"
- BR-074: "Do not disturb" и "Auto-decline" доступны только для рабочих аккаунтов
- BR-075: Time blocking доступен всем: Workspace, Individual, Personal Gmail
- BR-076: При завершении задачи блок времени НЕ удаляется из календаря

**Результат:** Время заблокировано в календаре для работы над задачей

### FR-TSK-009: Приоритизация задач (Stars)
**Описание:** Выделение важных задач с помощью звездочки
**Роли:** Владелец аккаунта
**Предусловия:**
- Задача существует

**Основной сценарий:**
1. Пользователь наводит курсор на задачу
2. Пользователь нажимает на иконку звездочки
3. Система отмечает задачу как избранную
4. Задача появляется в специальном списке "Starred"
5. Звездочка заполняется цветом

**Альтернативный сценарий A1: Просмотр избранных задач**
1. Пользователь открывает выпадающее меню списков
2. Пользователь выбирает "Starred"
3. Система показывает все избранные задачи из всех списков

**Альтернативный сценарий A2: Снятие звездочки**
1. Пользователь нажимает на заполненную звездочку
2. Система снимает отметку избранного
3. Задача исчезает из списка "Starred"

**Бизнес-правила:**
- BR-080: Starred задачи собираются из всех списков в одно место
- BR-081: Сортировка в Starred: по дате или по времени добавления звезды
- BR-082: Нельзя вручную переупорядочить задачи в Starred
- BR-083: Звездочка сохраняется при перемещении задачи между списками

## Сущности данных

### Задача (Task)
- **Task ID** - уникальный идентификатор задачи (строка)
- **Title** - название задачи (обязательное)
- **Notes** - описание/заметки (опционально)
- **Due Date** - дата дедлайна (опционально)
- **Due Time** - время дедлайна (опционально)
- **Duration** - продолжительность для time blocking (опционально)
- **Status** - статус: needsAction (активна) / completed (выполнена)
- **Completed Date** - дата завершения (для выполненных)
- **List ID** - идентификатор списка
- **Parent Task ID** - идентификатор родительской задачи (для подзадач)
- **Position** - позиция в списке (строка)
- **Starred** - избранная (boolean)
- **Recurrence** - правило повторения (RRULE)
- **Show as Busy** - отображать как "Занят" (boolean)
- **Links** - связанные объекты (emails, docs)
- **Created** - дата создания
- **Updated** - дата последнего изменения

### Список задач (Task List)
- **List ID** - уникальный идентификатор списка
- **Title** - название списка
- **Position** - порядок в списке списков
- **Is Default** - является ли списком по умолчанию
- **Created** - дата создания
- **Updated** - дата последнего изменения

### Повторение (Recurrence)
- **Frequency** - частота: DAILY, WEEKLY, MONTHLY, YEARLY
- **Interval** - интервал (каждые N дней/недель/месяцев/лет)
- **By Day** - дни недели (для WEEKLY)
- **By Month Day** - день месяца (для MONTHLY)
- **Count** - количество повторений (опционально)
- **Until** - дата окончания (опционально)

### Назначенная задача (Assigned Task)
- **Task ID** - идентификатор задачи
- **Assignee** - email исполнителя
- **Assigner** - email назначившего
- **Source** - источник: CHAT_SPACE / DOCUMENT
- **Source ID** - идентификатор Space или Document
- **Link** - ссылка на источник

## Состояния и переходы

### Состояния задачи
- **Active (needsAction)** - задача создана, ожидает выполнения
- **Completed** - задача выполнена
- **Deleted** - задача удалена (финальное состояние)

### Диаграмма состояний
```
[Создание] → [Active]
                ↓
              [Completed] ⇄ [Active] (отмена выполнения)
                ↓
              [Deleted] (необратимо)

[Active] → [Deleted] (удаление)
```

### Состояния повторяющейся задачи
```
[Active (экземпляр 1)] → [Completed] → [Active (экземпляр 2)] → [Completed] → ...
                                            ↓
                                    [Stop Repeating]
                                            ↓
                                    [Серия остановлена]
```

### Состояния time block
- **Scheduled** - время заблокировано, задача активна
- **In Progress** - текущее время в пределах блока
- **Passed** - время блока прошло, задача остается активной
- **Completed** - задача выполнена (блок остается в календаре)

### Визуальные состояния приоритета
- **Normal** - обычная задача
- **Starred** - избранная (звездочка заполнена)
- **Overdue** - просроченная (дата в прошлом)

## Ограничения и лимиты

### Количественные ограничения
- **Всего задач на аккаунт:** До 100,000
- **Незавершенных задач в списке:** До 20,000
- **Количество списков:** Не ограничено
- **Глубина подзадач:** 1 уровень (подзадачи не могут иметь подзадач)
- **Хранение выполненных задач:** 365 дней
- **Pending tasks в Calendar:** За последние 30 дней

### Ограничения повторений
- Повторяющиеся задачи нельзя перемещать между списками
- Задачи с подзадачами не могут повторяться
- Общие (shared) задачи не могут повторяться
- Остановленную серию нельзя возобновить

### Ограничения шаринга
- Списки задач нельзя делить с другими пользователями
- Назначать задачи можно только через Chat Space или Docs
- Назначенные задачи не могут иметь подзадач
- Назначенные задачи не могут повторяться

### Ограничения Time Blocking (2025)
- "Do not disturb" доступен только для Work/School аккаунтов
- "Auto-decline meetings" доступен только для Work/School аккаунтов
- Требуется указать время и продолжительность для Busy статуса

### Ограничения Gemini
- Требуется Google One или платный Workspace
- Gemini Live не поддерживает отмену действий
- Нужно включить Keep Activity для работы с Tasks

### API лимиты
- **Courtesy limit:** 50,000 запросов в день
- Можно запросить увеличение квоты

- Получаю напоминание в 15:00
- Могу остановить серию при необходимости

### US-003: Создание задач из почты
**Как** пользователь Gmail,
**Я хочу** быстро превращать важные письма в задачи,
**Чтобы** не терять follow-up действия.

**Критерии приемки:**
- Могу перетащить письмо в Tasks
- Тема письма становится названием задачи
- Ссылка на письмо сохраняется
- Могу добавить дату выполнения

### US-004: Приоритизация задач
**Как** пользователь с множеством задач,
**Я хочу** отмечать важные задачи звездочкой и видеть их в одном месте,
**Чтобы** фокусироваться на приоритетном.

**Критерии приемки:**
- Могу отметить задачу звездочкой одним кликом
- Все избранные задачи видны в списке "Starred"
- Могу сортировать по дате или времени добавления звезды
- Звездочка сохраняется при перемещении задачи

### US-005: Делегирование через Chat
**Как** руководитель проекта,
**Я хочу** назначать задачи членам команды через Google Chat Space,
**Чтобы** распределять работу без дополнительных инструментов.

**Критерии приемки:**
- Могу создать задачу в Space
- Могу выбрать исполнителя из участников
- Исполнитель получает уведомление
- Задача появляется в его Google Tasks

### US-006: Голосовое управление задачами
**Как** пользователь Gemini,
**Я хочу** создавать и управлять задачами голосом,
**Чтобы** экономить время.

**Критерии приемки:**
- Могу сказать "Remind me tomorrow at 10am to call doctor"
- Gemini создает задачу с датой и временем
- Могу сказать "Mark buy milk as done"
- Могу удалять задачи голосовой командой

### US-007: Проект с подзадачами
**Как** пользователь со сложной задачей,
**Я хочу** разбить её на подзадачи,
**Чтобы** отслеживать прогресс поэтапно.

**Критерии приемки:**
- Могу добавить подзадачи к основной задаче
- Подзадачи отображаются с отступом
- Могу отмечать подзадачи отдельно от основной
- Основная задача не завершается автоматически при завершении подзадач

### US-008: Просмотр просроченных задач
**Как** забывчивый пользователь,
**Я хочу** видеть все просроченные задачи в одном месте,
**Чтобы** не терять важные дела.

**Критерии приемки:**
- Calendar показывает индикатор "Pending tasks"
- Могу видеть просроченные за последние 30 дней
- Могу быстро изменить дату или завершить задачу
- Tasks показывает просроченные за 365 дней

### US-009: Организация задач по категориям
**Как** пользователь с разными областями жизни,
**Я хочу** создать отдельные списки для работы, дома и хобби,
**Чтобы** организовать задачи по контексту.

**Критерии приемки:**
- Могу создать несколько списков
- Могу перемещать задачи между списками
- Могу переключаться между списками
- Starred задачи собираются из всех списков

### US-010: Защита времени для глубокой работы
**Как** разработчик,
**Я хочу** заблокировать 2 часа в календаре для кодинга с автоматическим отклонением встреч,
**Чтобы** защитить время фокусировки.

**Критерии приемки:**
- Создаю задачу "Кодинг" с продолжительностью 2 часа
- Включаю "Mark as busy" и "Auto-decline meetings"
- Система автоматически отклоняет приглашения на это время
- После завершения блока задача остается в списке

## Бизнес-правила и валидация

### Правила создания задач
- **BR-001:** Название задачи обязательно
- **BR-002:** Задача без даты не отображается в Calendar
- **BR-003:** Максимум 100,000 задач на аккаунт
- **BR-004:** Максимум 20,000 незавершенных в одном списке
- **BR-005:** Новые задачи добавляются в конец списка

### Правила повторений
- **BR-060:** Для повторения обязательна дата
- **BR-061:** Повторяющиеся задачи нельзя перемещать между списками
- **BR-062:** Подзадачи и общие задачи не могут повторяться
- **BR-063:** Остановленную серию нельзя возобновить
- **BR-064:** При завершении создается следующий экземпляр

### Правила подзадач
- **BR-040:** Максимум 1 уровень вложенности
- **BR-041:** Задачи с подзадачами не могут повторяться
- **BR-042:** Общие задачи не могут иметь подзадач
- **BR-043:** Подзадачи не отображаются отдельно в Calendar

### Правила Time Blocking
- **BR-070:** Для Busy статуса нужны время и продолжительность
- **BR-071:** Задача не исчезает после окончания времени
- **BR-072:** "Do not disturb" и "Auto-decline" только для Work/School
- **BR-073:** Блок времени сохраняется после завершения задачи

### Правила назначения
- **BR-100:** Назначение только через Chat Space или Docs
- **BR-101:** Списки задач нельзя делить
- **BR-102:** Назначенные задачи не могут повторяться
- **BR-103:** Назначенные задачи не могут иметь подзадач

### Правила миграции Keep
- **BR-140:** Миграция автоматическая и необратимая
- **BR-141:** Location-based напоминания теряются
- **BR-142:** Длинные названия сокращаются
- **BR-143:** Старые напоминания (>1 года) идут в отдельный список

### Правила уведомлений
- **BR-110:** Уведомления только для задач с датой/временем
- **BR-111:** SMS не поддерживается для бесплатных аккаунтов
- **BR-112:** Desktop notifications требуют открытого Calendar
- **BR-113:** Nudges напоминают о просроченных задачах

### Правила Gemini
- **BR-130:** Требуется Google One или платный Workspace
- **BR-131:** Keep Activity должен быть включен
- **BR-132:** Gemini Live не поддерживает отмену

## Сообщения об ошибках

### Ошибки создания
- **E-001:** "Task title cannot be empty" - пустое название
- **E-002:** "You have reached the maximum number of tasks (100,000)" - лимит задач
- **E-003:** "This list has reached the maximum number of open tasks (20,000)" - лимит в списке

### Ошибки повторений
- **E-010:** "Tasks with subtasks cannot repeat" - подзадачи
- **E-011:** "Shared tasks cannot repeat" - общая задача
- **E-012:** "Repeating tasks cannot be moved to a different list" - перемещение
- **E-013:** "Cannot restart a stopped repeating series" - возобновление серии

### Ошибки шаринга
- **E-020:** "Task lists cannot be shared" - попытка поделиться списком
- **E-021:** "Shared tasks cannot have subtasks" - подзадачи для общей
- **E-022:** "User must have access to the document to be assigned" - нет доступа

### Ошибки Gemini
- **E-030:** "Google One or Workspace subscription required" - нет подписки
- **E-031:** "Keep Activity must be enabled" - не включена интеграция
- **E-032:** "Cannot undo action in Gemini Live" - нельзя отменить

### Ошибки Time Blocking
- **E-040:** "Duration required for busy status" - нет продолжительности
- **E-041:** "Do not disturb is only available for work or school accounts" - ограничение аккаунта
