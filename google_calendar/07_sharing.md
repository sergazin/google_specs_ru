# Общий доступ и разрешения (Sharing & Permissions)

## Описание

Модуль управления общим доступом и разрешениями в Google Calendar, предназначенный для организации совместного использования календарей и событий. Обеспечивает гибкую систему предоставления доступа к личным и рабочим календарям, управление уровнями разрешений, делегирование календарных полномочий, а также контроль приватности и публичности календарной информации.

Система состоит из девяти ключевых компонентов:
1. **Общий доступ к календарю** - предоставление доступа конкретным пользователям и группам
2. **Уровни доступа** - управление правами просмотра занятости, деталей и редактирования
3. **Публичные календари** - открытие календаря для всех пользователей интернета
4. **Приватные календари** - защита конфиденциальной информации
5. **Делегирование доступа** - передача полномочий по управлению календарем
6. **Управление приглашениями** - контроль кто может приглашать и отвечать на события
7. **Ссылка для общего доступа** - создание публичных и приватных URL календаря
8. **Отзыв доступа** - удаление разрешений и сброс приватных ссылок
9. **Организационные политики** - административное управление доступом в Google Workspace

## Роли пользователей

### Уровни доступа к календарю:
- **Владелец (Owner)** - создатель календаря, имеет полный контроль: управление событиями, настройка доступа, передача владения, удаление календаря
- **Редактор (Make changes to events)** - может создавать, редактировать и удалять события, управлять гостями событий
- **Полный доступ (Make changes and manage sharing)** - все права редактора плюс возможность управлять настройками доступа календаря
- **Читатель (See all event details)** - может просматривать все детали событий (название, время, место, описание, гостей)
- **Только занятость (See only free/busy)** - видит только блоки занятости без деталей событий

### Дополнительные роли:
- **Делегат (Delegate)** - пользователь с полным доступом, управляющий календарем от имени владельца
- **Администратор Google Workspace** - управление политиками доступа, ограничениями внешнего и внутреннего общего доступа для организации
- **Организатор события** - создатель события, имеет права управления конкретным событием независимо от прав на календарь

## Функциональные требования

### FR-SHR-001: Предоставление доступа к календарю конкретному пользователю (Share Calendar with Specific Person)
**Описание:** Владелец календаря может предоставить доступ к своему календарю конкретному пользователю, указав его email-адрес и уровень разрешений.

**Роли:** Владелец, Пользователь с правами "Make changes and manage sharing"

**Предусловия:**
- Пользователь авторизован в Google Calendar
- Пользователь является владельцем календаря или имеет право управления доступом
- Известен email-адрес получателя доступа

**Основной сценарий:**
1. Пользователь открывает Google Calendar на компьютере
2. В левой панели находит раздел "My calendars"
3. Наводит курсор на нужный календарь и нажимает на три точки (More)
4. Выбирает "Settings and sharing" из выпадающего меню
5. На левой панели настроек выбирает "Share with specific people or groups"
6. Нажимает "Add people and groups"
7. Вводит email-адрес пользователя в поле поиска
8. Система показывает автодополнение из контактов и организации
9. Выбирает пользователя из списка или вводит email полностью
10. В выпадающем списке "Permissions" выбирает уровень доступа
11. Нажимает "Send" для отправки приглашения

**Альтернативные сценарии:**
- Сценарий A (Добавление группы Google Groups): вместо индивидуального email вводит адрес группы - все участники группы получают доступ
- Сценарий B (Без уведомления): снимает галочку уведомления - получатель не получит email, но календарь появится в его списке
- Сценарий C (Изменение уровня доступа): выбирает уже добавленного пользователя и меняет его уровень доступа в выпадающем списке

**Бизнес-правила:**
- BR-SHR-001: При предоставлении доступа получатель получает email-уведомление со ссылкой для добавления календаря
- BR-SHR-002: Получатель должен нажать на ссылку в email для добавления календаря в свой список "Other calendars"
- BR-SHR-003: Новые участники группы получают уведомление о доступных календарях в течение часа после добавления в группу
- BR-SHR-004: Если группа содержит более 100 общих календарей, новые участники не получают email-уведомление
- BR-SHR-005: Общий доступ через мобильное приложение недоступен - требуется использование браузера
- BR-SHR-006: Пользователь может быть добавлен только один раз - повторное добавление обновляет существующие права

**Результат:** Пользователь или группа получили доступ к календарю с назначенным уровнем разрешений

### FR-SHR-002: Управление уровнями доступа (Manage Access Levels)
**Описание:** Владелец календаря определяет объем информации и действий, доступных для каждого пользователя, выбирая один из четырех уровней разрешений.

**Роли:** Владелец, Пользователь с правами "Make changes and manage sharing"

**Предусловия:**
- Пользователь имеет право управления доступом к календарю
- Доступ уже предоставлен одному или нескольким пользователям

**Основной сценарий:**
1. Пользователь открывает настройки календаря (Settings and sharing)
2. Переходит в раздел "Share with specific people or groups"
3. Видит список всех пользователей с текущими уровнями доступа
4. Нажимает на выпадающий список напротив нужного пользователя
5. Выбирает новый уровень доступа из четырех опций:
   - "See only free/busy (hide details)" - только занятость
   - "See all event details" - все детали событий
   - "Make changes to events" - редактирование событий
   - "Make changes and manage sharing" - полный доступ
6. Изменение применяется мгновенно

**Альтернативные сценарии:**
- Сценарий A (Понижение прав): меняет "Make changes to events" на "See all event details" - пользователь немедленно теряет возможность редактирования
- Сценарий B (Повышение до полного доступа): выбирает "Make changes and manage sharing" - пользователь получает возможность управлять доступом других

**Бизнес-правила:**
- BR-SHR-007: Уровень "See only free/busy" скрывает название события, место, описание и список гостей
- BR-SHR-008: Уровень "See all event details" показывает все данные, кроме событий с пометкой "Private"
- BR-SHR-009: Для приватных событий даже при уровне "See all event details" виден только блок занятости
- BR-SHR-010: Уровень "Make changes to events" позволяет создавать, редактировать и удалять события
- BR-SHR-011: Уровень "Make changes and manage sharing" включает все права редактора плюс управление доступом
- BR-SHR-012: Только владелец может удалить календарь - даже пользователи с полным доступом не имеют этого права
- BR-SHR-013: Изменение уровня доступа применяется мгновенно без задержки

**Результат:** Уровень доступа пользователя изменен в соответствии с выбором

### FR-SHR-003: Публикация календаря (Make Calendar Public)
**Описание:** Владелец может сделать календарь публичным, позволяя любому пользователю интернета находить и просматривать его без приглашения.

**Роли:** Владелец, Пользователь с правами "Make changes and manage sharing"

**Предусловия:**
- Пользователь имеет право управления доступом к календарю
- Организационные политики (для Workspace) разрешают публикацию календарей

**Основной сценарий:**
1. Пользователь открывает настройки календаря (Settings and sharing)
2. Переходит в раздел "Access permissions for events"
3. Устанавливает галочку "Make available to public"
4. Система показывает предупреждение о публичности
5. Выбирает уровень публичного доступа из выпадающего списка:
   - "See only free/busy (hide details)"
   - "See all event details"
6. Подтверждает действие
7. Календарь становится доступен всем пользователям интернета

**Альтернативные сценарии:**
- Сценарий A (Получение ссылки): после публикации нажимает "Get shareable link" для получения прямой ссылки на календарь
- Сценарий B (Встраивание на сайт): копирует HTML-код из раздела "Integrate calendar" для вставки календаря на веб-страницу
- Сценарий C (Отмена публикации): снимает галочку "Make available to public" - календарь становится приватным

**Бизнес-правила:**
- BR-SHR-014: Публичный календарь доступен всем, кто знает его URL или идентификатор
- BR-SHR-015: Публичные календари индексируются поисковыми системами при выборе соответствующей опции
- BR-SHR-016: Даже при публичном доступе "See all event details" события с пометкой "Private" скрыты
- BR-SHR-017: Для календарей организации публикация может быть заблокирована администратором
- BR-SHR-018: Публичный календарь можно добавить по URL в любое приложение, поддерживающее iCal
- BR-SHR-019: Владелец публичного календаря несет ответственность за его содержимое

**Результат:** Календарь стал публично доступным с выбранным уровнем видимости

### FR-SHR-004: Публикация календаря для организации (Share with Organization)
**Описание:** В Google Workspace пользователь может сделать свой календарь видимым для всех сотрудников организации без индивидуального добавления каждого.

**Роли:** Владелец, Пользователь с правами "Make changes and manage sharing"

**Предусловия:**
- Пользователь использует аккаунт Google Workspace
- Администратор организации разрешил внутренний общий доступ
- Пользователь имеет право управления доступом к календарю

**Основной сценарий:**
1. Пользователь открывает настройки календаря (Settings and sharing)
2. Переходит в раздел "Access permissions for events"
3. Устанавливает галочку "Make available for [Organization Name]"
4. Выбирает уровень доступа для организации:
   - "See only free/busy (hide details)"
   - "See all event details"
5. Сохраняет настройки

**Альтернативные сценарии:**
- Сценарий A (Разные уровни): устанавливает "See only free/busy" для организации, но добавляет конкретных коллег с "See all event details"
- Сценарий B (Одновременно публичный и организационный): включает оба уровня с разными правами

**Бизнес-правила:**
- BR-SHR-020: Пользователи организации могут найти и подписаться на календарь через директорию
- BR-SHR-021: Внешние пользователи не могут найти организационные календари
- BR-SHR-022: Администратор может установить уровень доступа по умолчанию для всей организации
- BR-SHR-023: Индивидуальные разрешения имеют приоритет над организационными
- BR-SHR-024: Новые сотрудники организации автоматически получают доступ согласно настройкам

**Результат:** Календарь доступен для просмотра всем сотрудникам организации

### FR-SHR-005: Защита приватности событий (Event Privacy Settings)
**Описание:** Пользователь может установить уровень приватности для отдельных событий, контролируя видимость информации даже для тех, кто имеет доступ к календарю.

**Роли:** Владелец события, Редактор календаря

**Предусловия:**
- Пользователь имеет право создавать или редактировать события в календаре
- Событие создано или находится в процессе создания

**Основной сценарий:**
1. Пользователь создает новое событие или открывает существующее для редактирования
2. Находит настройку "Visibility" (Видимость) в параметрах события
3. Выбирает один из уровней видимости:
   - "Default visibility" - согласно настройкам календаря
   - "Public" - все детали видны любому с доступом к календарю
   - "Private" - детали скрыты, виден только блок занятости
4. Сохраняет событие

**Альтернативные сценарии:**
- Сценарий A (Массовое изменение): выбирает несколько событий и устанавливает одинаковый уровень видимости
- Сценарий B (Настройка по умолчанию для Gmail-событий): в настройках календаря устанавливает default visibility для событий из email

**Бизнес-правила:**
- BR-SHR-025: Приватные события показывают "Busy" без названия, места и описания
- BR-SHR-026: Даже при доступе "See all event details" приватные события остаются скрытыми
- BR-SHR-027: Только создатель события и пользователи с правами редактирования могут видеть детали приватных событий
- BR-SHR-028: События из Gmail с настройкой "Only me" не видны даже пользователям с правами редактирования
- BR-SHR-029: Если календарь публичный, события с "Public" visibility видны всем интернет-пользователям
- BR-SHR-030: Изменение visibility применяется мгновенно для всех просматривающих календарь

**Результат:** Событие защищено выбранным уровнем приватности

### FR-SHR-006: Делегирование управления календарем (Calendar Delegation)
**Описание:** Владелец календаря может назначить делегата с полным доступом для управления календарем от своего имени, что особенно полезно для руководителей и их ассистентов.

**Роли:** Владелец

**Предусловия:**
- Пользователь является владельцем календаря
- Известен email-адрес делегата
- Оба пользователя находятся в одной организации Google Workspace (для полной функциональности)

**Основной сценарий:**
1. Владелец открывает настройки календаря (Settings and sharing)
2. Переходит в раздел "Share with specific people or groups"
3. Нажимает "Add people and groups"
4. Вводит email-адрес будущего делегата
5. Выбирает уровень доступа "Make changes and manage sharing"
6. Нажимает "Send"
7. Делегат получает email-уведомление
8. После принятия делегат может управлять календарем

**Альтернативные сценарии:**
- Сценарий A (Создание событий от имени владельца): делегат создает событие - владелец отображается как организатор в приглашениях
- Сценарий B (Ответ на приглашения): делегат может принимать или отклонять приглашения от имени владельца
- Сценарий C (Управление несколькими календарями): делегат добавляется к нескольким календарям владельца

**Бизнес-правила:**
- BR-SHR-031: При создании события делегатом владелец календаря указывается как организатор
- BR-SHR-032: Делегат может отвечать на приглашения (RSVP) от имени владельца
- BR-SHR-033: Делегат не может изменять настройки аккаунта владельца
- BR-SHR-034: Делегат не имеет доступа к задачам (Tasks) владельца
- BR-SHR-035: Делегат не может настраивать уведомления или напоминания для владельца
- BR-SHR-036: Делегат не имеет доступа к контактам Google владельца
- BR-SHR-037: Владелец видит все действия делегата в истории изменений

**Результат:** Делегат получил полномочия управлять календарем от имени владельца

### FR-SHR-007: Управление разрешениями гостей события (Guest Permissions)
**Описание:** Организатор события может настроить права гостей: возможность изменять событие, приглашать других и видеть список участников.

**Роли:** Организатор события, Редактор календаря

**Предусловия:**
- Пользователь создает новое событие или редактирует существующее
- Событие имеет или будет иметь гостей

**Основной сценарий:**
1. Пользователь открывает событие для редактирования
2. Находит раздел "Guest permissions" (обычно в дополнительных опциях)
3. Видит три опции с чекбоксами:
   - "Modify event" - гости могут изменять событие
   - "Invite others" - гости могут приглашать других участников
   - "See guest list" - гости могут видеть список приглашенных
4. Устанавливает или снимает галочки согласно требованиям
5. Сохраняет событие

**Альтернативные сценарии:**
- Сценарий A (Приватная встреча): снимает все три галочки - гости не видят друг друга и не могут менять событие
- Сценарий B (Коллаборативное планирование): включает все три опции - любой гость может редактировать и приглашать

**Бизнес-правила:**
- BR-SHR-038: По умолчанию гости могут видеть список участников и приглашать других
- BR-SHR-039: По умолчанию гости не могут изменять событие
- BR-SHR-040: Отключение "See guest list" скрывает всех участников кроме организатора
- BR-SHR-041: Даже при отключенной опции "Invite others" гости могут переслать приглашение по email
- BR-SHR-042: Если гость переслал приглашение, получатель может добавить себя по ссылке в email
- BR-SHR-043: Организатор всегда видит полный список гостей независимо от настроек

**Результат:** Права гостей события настроены согласно требованиям организатора

### FR-SHR-008: Создание ссылки для общего доступа (Create Shareable Link)
**Описание:** Пользователь может получить ссылку на календарь для предоставления доступа без необходимости отправлять персональное приглашение.

**Роли:** Владелец, Пользователь с правами "Make changes and manage sharing"

**Предусловия:**
- Пользователь имеет право управления доступом к календарю
- Календарь настроен на публичный или организационный доступ

**Основной сценарий:**
1. Пользователь открывает настройки календаря (Settings and sharing)
2. Переходит в раздел "Integrate calendar"
3. Находит поле "Public URL to this calendar" (для публичных календарей)
4. Копирует ссылку нажатием на иконку копирования
5. Передает ссылку получателям любым удобным способом
6. Получатели переходят по ссылке и могут просматривать или добавить календарь

**Альтернативные сценарии:**
- Сценарий A (Приватная ссылка iCal): копирует "Secret address in iCal format" - ссылка для добавления в любое приложение
- Сценарий B (HTML-код для встраивания): копирует "Embed code" для вставки календаря на веб-страницу
- Сценарий C (Ссылка для конкретного формата): выбирает формат XML или iCal

**Бизнес-правила:**
- BR-SHR-044: Публичная ссылка открывает календарь в веб-браузере
- BR-SHR-045: Приватная ссылка (iCal) позволяет добавить календарь в другие приложения (Outlook, Apple Calendar)
- BR-SHR-046: Приватная ссылка дает полный доступ к содержимому без авторизации
- BR-SHR-047: Google не рекомендует делиться приватной ссылкой с ненадежными пользователями
- BR-SHR-048: Embed code создает iframe для отображения календаря на веб-странице
- BR-SHR-049: Встроенный календарь наследует настройки видимости основного календаря

**Результат:** Получена ссылка для предоставления доступа к календарю

### FR-SHR-009: Сброс приватных ссылок (Reset Private URLs)
**Описание:** Владелец может сбросить приватные URL календаря, отозвав доступ у всех, кто использовал эти ссылки.

**Роли:** Владелец

**Предусловия:**
- Пользователь является владельцем календаря
- Календарь имеет приватные ссылки (iCal, XML)

**Основной сценарий:**
1. Пользователь открывает настройки календаря (Settings and sharing)
2. Переходит в раздел "Integrate calendar"
3. Находит секцию "Secret address in iCal format"
4. Нажимает кнопку "Reset" рядом с приватной ссылкой
5. Система показывает предупреждение о последствиях
6. Подтверждает сброс
7. Генерируется новая приватная ссылка
8. Старая ссылка становится недействительной

**Альтернативные сценарии:**
- Сценарий A (Предоставление новой ссылки): после сброса копирует новую ссылку и отправляет доверенным пользователям
- Сценарий B (Полное закрытие доступа): сбрасывает ссылку и не предоставляет новую никому

**Бизнес-правила:**
- BR-SHR-050: После сброса все приложения, использующие старую ссылку, потеряют доступ
- BR-SHR-051: Сброс происходит мгновенно
- BR-SHR-052: Новая ссылка генерируется автоматически после сброса
- BR-SHR-053: Публичные ссылки не затрагиваются сбросом приватных URL
- BR-SHR-054: Персональные разрешения (share with specific people) не затрагиваются сбросом

**Результат:** Приватные ссылки сброшены, старые URL недействительны

### FR-SHR-010: Отзыв доступа у пользователя (Revoke User Access)
**Описание:** Владелец может удалить ранее предоставленный доступ у конкретного пользователя или группы.

**Роли:** Владелец, Пользователь с правами "Make changes and manage sharing"

**Предусловия:**
- Пользователь имеет право управления доступом к календарю
- Доступ предоставлен одному или нескольким пользователям

**Основной сценарий:**
1. Пользователь открывает настройки календаря (Settings and sharing)
2. Переходит в раздел "Share with specific people or groups"
3. Находит пользователя или группу в списке
4. Нажимает "X" или "Remove" напротив имени пользователя
5. Система запрашивает подтверждение
6. Подтверждает удаление
7. Доступ отзывается немедленно

**Альтернативные сценарии:**
- Сценарий A (Удаление группы): удаляет Google Group - все участники группы теряют доступ
- Сценарий B (Отключение публичного доступа): снимает галочку "Make available to public" - все анонимные пользователи теряют доступ
- Сценарий C (Отключение организационного доступа): снимает галочку "Make available for [Organization]"

**Бизнес-правила:**
- BR-SHR-055: После отзыва доступа пользователь немедленно теряет возможность видеть календарь
- BR-SHR-056: Календарь удаляется из списка "Other calendars" у пользователя
- BR-SHR-057: Пользователь теряет доступ ко всем событиям календаря, включая прошлые
- BR-SHR-058: Уведомление об отзыве доступа не отправляется автоматически
- BR-SHR-059: Если пользователь был добавлен через группу, удаление из группы автоматически отзывает доступ
- BR-SHR-060: Владелец не может удалить свой собственный доступ

**Результат:** Доступ пользователя или группы отозван

### FR-SHR-011: Передача владения календарем (Transfer Calendar Ownership)
**Описание:** Владелец может передать права владения календарем другому пользователю, сохранив или потеряв собственный доступ.

**Роли:** Владелец

**Предусловия:**
- Пользователь является владельцем вторичного календаря (не основного)
- Новый владелец имеет аккаунт Google
- Для организации: новый владелец находится в той же организации

**Основной сценарий:**
1. Владелец открывает настройки календаря
2. Переходит в раздел "Share with specific people or groups"
3. Убеждается, что будущий владелец добавлен в список (если нет - добавляет)
4. Нажимает на выпадающий список напротив пользователя
5. Выбирает "Make owner" (Сделать владельцем)
6. Система показывает предупреждение и запрашивает подтверждение
7. Подтверждает передачу
8. Новый владелец получает email-уведомление

**Альтернативные сценарии:**
- Сценарий A (Принятие владения): новый владелец имеет 60 дней на принятие - до этого момента прежний владелец сохраняет права
- Сценарий B (Сохранение доступа): после передачи прежний владелец автоматически становится редактором

**Бизнес-правила:**
- BR-SHR-061: Основной календарь (Primary) не может быть передан
- BR-SHR-062: Новый владелец должен принять владение в течение 60 дней
- BR-SHR-063: До принятия владения прежний владелец остается владельцем
- BR-SHR-064: После принятия прежний владелец получает права "Make changes and manage sharing"
- BR-SHR-065: Может быть только один владелец вторичного календаря
- BR-SHR-066: При удалении аккаунта Google все принадлежащие календари удаляются - рекомендуется передать владение заранее
- BR-SHR-067: Передача владения недоступна в мобильном приложении

**Результат:** Владение календарем передано новому пользователю

### FR-SHR-012: Ответ на приглашение от имени другого пользователя (Respond on Behalf)
**Описание:** Делегат с полным доступом может принимать или отклонять приглашения от имени владельца календаря.

**Роли:** Делегат (пользователь с правами "Make changes and manage sharing")

**Предусловия:**
- Делегат имеет полный доступ к календарю владельца
- Владелец получил приглашение на событие
- Делегат работает с календарем владельца

**Основной сценарий:**
1. Делегат открывает календарь владельца в своем аккаунте
2. Находит событие с ожидающим ответом (pending RSVP)
3. Открывает событие
4. Выбирает ответ: "Yes", "No", или "Maybe"
5. Опционально добавляет примечание
6. Сохраняет ответ
7. Организатор события видит ответ от имени владельца календаря

**Альтернативные сценарии:**
- Сценарий A (Предложение нового времени): делегат нажимает "Propose a new time" - организатор получает альтернативное предложение
- Сценарий B (Изменение ответа): делегат изменяет ранее данный ответ

**Бизнес-правила:**
- BR-SHR-068: Ответ записывается от имени владельца календаря, не делегата
- BR-SHR-069: Делегат получает уведомления о приглашениях так же, как владелец (если настроено)
- BR-SHR-070: Для защиты от несанкционированного ответа можно требовать вход при ответе через email-ссылки
- BR-SHR-071: Пересланные приглашения могут позволить получателю изменить RSVP владельца
- BR-SHR-072: Владелец может просматривать все ответы, данные делегатом

**Результат:** Ответ на приглашение зарегистрирован от имени владельца календаря

### FR-SHR-013: Пересылка приглашения другим участникам (Forward Invitation)
**Описание:** Гость события может переслать приглашение другим пользователям, если это разрешено настройками события.

**Роли:** Гость события

**Предусловия:**
- Пользователь является приглашенным на событие
- Настройка "Guests can invite others" включена (или пользователь пересылает email)
- Пользователь имеет право просматривать список гостей (для некоторых функций)

**Основной сценарий:**
1. Гость получает email-приглашение на событие
2. Нажимает "Forward" в email-клиенте
3. Указывает email-адрес нового получателя
4. Отправляет переадресованное приглашение
5. Новый получатель переходит по ссылке в email
6. Новый участник может ответить на приглашение и добавить событие в свой календарь

**Альтернативные сценарии:**
- Сценарий A (Добавление через ссылку): получатель нажимает ссылку и добавляет себя как гостя
- Сценарий B (Через интерфейс Calendar): гость открывает событие, нажимает "Add guests" и вводит email

**Бизнес-правила:**
- BR-SHR-073: Даже при отключенной опции "Guests can invite others" пересылка email остается возможной
- BR-SHR-074: Пересланные приглашения содержат рабочие ссылки для RSVP
- BR-SHR-075: Получатель пересланного приглашения может изменить RSVP оригинального получателя
- BR-SHR-076: Для предотвращения несанкционированных RSVP можно требовать авторизацию при ответе
- BR-SHR-077: Организатор получает уведомление о новых участниках, добавленных через пересылку

**Результат:** Приглашение переслано новому участнику

### FR-SHR-014: Настройка политик общего доступа администратором (Admin Sharing Policies)
**Описание:** Администратор Google Workspace может настроить политики, ограничивающие возможности пользователей по предоставлению внешнего и внутреннего доступа к календарям.

**Роли:** Администратор Google Workspace

**Предусловия:**
- Пользователь имеет права администратора в Google Admin Console
- Организация использует платный аккаунт Google Workspace

**Основной сценарий:**
1. Администратор открывает Google Admin Console (admin.google.com)
2. Переходит в Apps → Google Workspace → Calendar
3. Выбирает "Sharing settings" (Настройки общего доступа)
4. Выбирает организационное подразделение (OU) для применения политики
5. Настраивает параметры внешнего доступа:
   - "External sharing options for primary calendars"
   - "External sharing options for secondary calendars"
6. Настраивает параметры внутреннего доступа:
   - "Internal sharing options for primary calendars"
7. Сохраняет изменения

**Альтернативные сценарии:**
- Сценарий A (Полная блокировка внешнего доступа): выбирает "Only free/busy information" для внешних пользователей
- Сценарий B (Разные политики для OU): применяет разные настройки для разных подразделений организации
- Сценарий C (Доверенные домены): настраивает белый список внешних доменов для расширенного доступа

**Бизнес-правила:**
- BR-SHR-078: Организационные политики имеют приоритет над индивидуальными настройками пользователей
- BR-SHR-079: Пользователи не могут превысить ограничения, установленные администратором
- BR-SHR-080: По умолчанию основные календари не доступны вне домена
- BR-SHR-081: Суперадмины могут видеть все детали всех календарей независимо от настроек доступа
- BR-SHR-082: Изменения политик могут применяться в течение 24 часов
- BR-SHR-083: Политики могут быть настроены отдельно для основных и вторичных календарей
- BR-SHR-084: Можно настроить доверенный список доменов (до 200 доменов)

**Результат:** Политики общего доступа установлены для организации или подразделения

## User Stories

### US-SHR-001: Предоставление доступа ассистенту
**Как** руководитель,
**Я хочу** предоставить своему ассистенту полный доступ к моему календарю,
**Чтобы** он мог управлять моим расписанием, создавать встречи и отвечать на приглашения от моего имени.

**Критерии приемки:**
- Ассистент может видеть все детали моих событий
- Ассистент может создавать события, и я буду указан как организатор
- Ассистент может принимать/отклонять приглашения от моего имени
- Я вижу все изменения, сделанные ассистентом

---

### US-SHR-002: Показ занятости команде
**Как** член команды,
**Я хочу** показать свою занятость коллегам без раскрытия деталей личных встреч,
**Чтобы** они могли видеть мои свободные слоты при планировании командных встреч.

**Критерии приемки:**
- Коллеги видят только блоки "Занят/Свободен"
- Названия, места и описания событий скрыты
- Личные события не раскрывают никакой информации

---

### US-SHR-003: Публикация расписания мероприятий
**Как** организатор публичных мероприятий,
**Я хочу** опубликовать календарь событий для всех желающих,
**Чтобы** посетители могли видеть предстоящие мероприятия и добавлять их в свои календари.

**Критерии приемки:**
- Календарь доступен всем в интернете без авторизации
- Посетители могут копировать события в свои календари
- Календарь можно встроить на сайт мероприятия

---

### US-SHR-004: Организация приватной встречи
**Как** HR-менеджер,
**Я хочу** создать конфиденциальную встречу, скрытую от коллег,
**Чтобы** проводить собеседования с кандидатами без публикации деталей.

**Критерии приемки:**
- Коллеги видят только "Занят" без названия встречи
- Участники встречи не видят друг друга в списке гостей
- Комната бронируется без публикации темы встречи

---

### US-SHR-005: Отзыв доступа бывшего сотрудника
**Как** администратор,
**Я хочу** немедленно отозвать доступ к корпоративным календарям у увольняющегося сотрудника,
**Чтобы** он не видел конфиденциальную информацию о встречах после увольнения.

**Критерии приемки:**
- Доступ отзывается мгновенно
- Сотрудник теряет доступ ко всем shared календарям
- Сброшены все приватные ссылки, которыми он мог поделиться

---

### US-SHR-006: Передача календаря при смене роли
**Как** руководитель проекта, переходящий на другую должность,
**Я хочу** передать владение календарем проекта моему преемнику,
**Чтобы** он мог продолжить управление календарем команды.

**Критерии приемки:**
- Преемник становится полноправным владельцем
- Все существующие события и настройки сохраняются
- Все пользователи сохраняют свои уровни доступа

---

### US-SHR-007: Ограничение внешнего доступа
**Как** администратор безопасности,
**Я хочу** запретить сотрудникам делиться календарями с внешними пользователями,
**Чтобы** предотвратить утечку информации о внутренних встречах и проектах.

**Критерии приемки:**
- Опция "Share with external users" недоступна для сотрудников
- Существующие внешние доступы продолжают работать или отзываются
- Администратор получает отчеты о попытках внешнего доступа

## Бизнес-правила и ограничения

### Иерархия доступа:
| Уровень | Видит занятость | Видит детали | Видит приватные | Редактирует | Управляет доступом |
|---------|-----------------|--------------|-----------------|-------------|-------------------|
| See only free/busy | Да | Нет | Нет | Нет | Нет |
| See all event details | Да | Да | Нет | Нет | Нет |
| Make changes to events | Да | Да | Нет* | Да | Нет |
| Make changes and manage sharing | Да | Да | Нет* | Да | Да |
| Owner | Да | Да | Да | Да | Да |

*Примечание: Редакторы видят детали событий, которые они создали или где они являются гостями, но не видят приватные события других.

### Ограничения платформы:
- Общий доступ через мобильное приложение невозможен - только через веб-браузер
- Передача владения недоступна с мобильных устройств
- Некоторые расширенные настройки доступны только через Calendar API

### Ограничения групп:
- Новые участники группы получают уведомление о доступных календарях в течение 1 часа
- Если группе доступно более 100 календарей, новые участники не получают email-уведомление
- Для использования группового приглашения требуется право просмотра email-адресов участников

### Временные ограничения:
- Новый владелец должен принять передачу владения в течение 60 дней
- Изменения политик администратора применяются в течение 24 часов

## Нефункциональные требования

### Производительность
- **NFR-SHR-001**: Изменение уровня доступа применяется мгновенно (менее 1 секунды)
- **NFR-SHR-002**: Email-уведомления о предоставлении доступа отправляются в течение 5 минут
- **NFR-SHR-003**: Обновление доступа для участников группы происходит в течение 1 часа
- **NFR-SHR-004**: Сброс приватных URL применяется мгновенно

### Безопасность
- **NFR-SHR-005**: Приватные URL криптографически стойкие и непредсказуемые
- **NFR-SHR-006**: Все операции по управлению доступом логируются для аудита
- **NFR-SHR-007**: Поддержка требования авторизации для RSVP через email-ссылки
- **NFR-SHR-008**: Организационные политики применяются принудительно

### Масштабируемость
- **NFR-SHR-009**: Поддержка предоставления доступа группам любого размера
- **NFR-SHR-010**: Поддержка до 200 доверенных доменов в белом списке
- **NFR-SHR-011**: Поддержка вложенных групп для автоматического наследования доступа

### Совместимость
- **NFR-SHR-012**: Приватные iCal-ссылки совместимы с Outlook, Apple Calendar и другими приложениями
- **NFR-SHR-013**: Embed-код работает в современных браузерах (Chrome, Firefox, Safari, Edge)
- **NFR-SHR-014**: API для управления доступом доступен для интеграции

## Интеграции

### Внутренние интеграции Google:
- **Google Groups** - предоставление доступа группам, автоматическое управление при изменении состава
- **Google Workspace Admin Console** - централизованное управление политиками организации
- **Gmail** - отправка уведомлений о доступе и приглашений
- **Google Meet** - автоматическое добавление ссылок на встречи для участников
- **Google Drive** - предоставление доступа к прикрепленным файлам

### Внешние интеграции:
- **iCal-совместимые приложения** - синхронизация через приватные URL
- **Веб-сайты** - встраивание публичных календарей через iframe
- **Third-party scheduling tools** - интеграция через Calendar API
- **SSO/SAML** - корпоративная авторизация для доступа к календарям

## Технические ограничения

- **TL-SHR-001**: Общий доступ невозможен через мобильное приложение
- **TL-SHR-002**: Передача владения невозможна через мобильное приложение
- **TL-SHR-003**: Максимум 200 доверенных доменов в белом списке организации
- **TL-SHR-004**: Изменения политик администратора применяются в течение 24 часов
- **TL-SHR-005**: Новый владелец должен принять передачу в течение 60 дней
- **TL-SHR-006**: Группы с более чем 100 календарями не отправляют уведомления новым участникам
- **TL-SHR-007**: Расширенные ACL для ресурсных календарей требуют использования API

## Метрики успеха

- **Количество общих календарей** - индикатор коллаборации в организации
- **Процент календарей с внешним доступом** - мониторинг распространения данных
- **Время ответа на запросы делегирования** - эффективность административных процессов
- **Количество сбросов приватных URL** - индикатор потенциальных проблем безопасности
- **Процент использования групп vs индивидуальных разрешений** - эффективность управления доступом
- **Количество переданных календарей** - активность управления жизненным циклом
