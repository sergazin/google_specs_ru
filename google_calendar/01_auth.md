# Функциональная спецификация: Аутентификация и управление аккаунтом

**Сервис:** Google Calendar
**Модуль:** Аутентификация и управление аккаунтом
**Версия:** 1.0
**Дата:** 2026-01-09

---

## 1. Общее описание

Модуль аутентификации и управления аккаунтом обеспечивает безопасный доступ пользователей к Google Calendar через единую систему аутентификации Google Account. Модуль поддерживает как личные аккаунты Google, так и корпоративные аккаунты Google Workspace с расширенными политиками безопасности.

---

## 2. Роли и права доступа

### 2.1 Личный пользователь (Personal User)

| Характеристика | Описание |
|----------------|----------|
| Тип аккаунта | Бесплатный Google Account (@gmail.com или привязанный email) |
| Управление 2FA | Самостоятельная настройка |
| Длительность сессии | 14 дней (по умолчанию) |
| Управление устройствами | Полный доступ к своим устройствам |
| Делегирование | Может делегировать доступ к своему календарю |

### 2.2 Workspace пользователь (Workspace User)

| Характеристика | Описание |
|----------------|----------|
| Тип аккаунта | Корпоративный Google Workspace аккаунт |
| Управление 2FA | Определяется политикой организации |
| Длительность сессии | Определяется администратором (от 1 часа до "никогда") |
| SSO | Поддержка SAML/OIDC через корпоративный IdP |
| Ограничения | Политики безопасности организации |

### 2.3 Администратор Workspace (Workspace Admin)

| Роль | Привилегии |
|------|-----------|
| Super Admin | Полный контроль над всеми настройками Calendar, управление 2FA, сессиями, доступом ко всем календарям |
| Calendar Admin | Доступ ко всем календарям пользователей, управление ресурсами |
| Calendar Resources Admin | Управление переговорными, оборудованием и другими ресурсами |
| Services Admin | Управление настройками сервиса Calendar для организации |

## 3. Функциональные требования

### 3.1 Вход через Google Account

#### FR-AUTH-001: Первичная аутентификация
**Описание:** Система должна позволять пользователю войти в Google Calendar используя учетные данные Google Account.

**Бизнес-правила:**
- При входе в любой сервис Google (Gmail, Drive, YouTube) пользователь автоматически получает доступ ко всем сервисам Google, включая Calendar
- Первый аккаунт, в который вошел пользователь в рамках сессии браузера, становится аккаунтом по умолчанию
- При открытии Calendar в новой вкладке используется аккаунт по умолчанию

**User Story:**
> Как пользователь, я хочу войти в Google Calendar с помощью своего Google аккаунта, чтобы получить доступ к своим событиям и расписанию.

**Состояния:**
```
[Не аутентифицирован] → (ввод email) → [Ожидание пароля] → (ввод пароля) → [Проверка 2FA] → (подтверждение) → [Аутентифицирован]
```

#### FR-AUTH-002: Запоминание устройства
**Описание:** Система должна предоставлять возможность запомнить устройство для упрощения последующих входов.

**Бизнес-правила:**
- Запомненное устройство сохраняет сессию на срок, определяемый политикой (14 дней для личных, настраиваемый для Workspace)
- При изменении пароля все сессии на устройствах аннулируются
- Пользователь может принудительно завершить сессию на любом устройстве

**User Story:**
> Как пользователь, я хочу чтобы система запомнила мое устройство, чтобы не вводить пароль каждый раз при входе.

#### FR-AUTH-003: Автоматический вход при активной сессии
**Описание:** При наличии активной сессии Google Account пользователь автоматически получает доступ к Calendar.

**Бизнес-правила:**
- Если пользователь аутентифицирован в любом сервисе Google, вход в Calendar происходит без повторной аутентификации
- Автоматический вход не работает, если истек срок сессии
- Автоматический вход не работает в режиме инкогнито без явной аутентификации

### 3.2 Single Sign-On для Workspace

#### FR-AUTH-010: Аутентификация через корпоративный IdP
**Описание:** Workspace пользователи могут входить через корпоративный провайдер идентификации (IdP) с использованием SSO.

**Бизнес-правила:**
- Поддерживаются протоколы SAML 2.0 и OIDC
- После успешной аутентификации в IdP доступ к Google Calendar предоставляется без дополнительной проверки
- Политика сессии IdP должна истекать раньше политики Google Workspace для корректной работы
- Администратор определяет, требуется ли SSO для всех пользователей или только для определенных групп

**User Story:**
> Как сотрудник компании, я хочу входить в Google Calendar через корпоративную систему единого входа (Okta, Azure AD), чтобы использовать единые учетные данные.

**Состояния:**
```
[Не аутентифицирован] → (ввод корп. email) → [Перенаправление на IdP] → (вход в IdP) → [Возврат с токеном] → [Аутентифицирован]
```

#### FR-AUTH-011: Управление SSO сессией администратором
**Описание:** Администратор может управлять параметрами SSO сессии.

**Бизнес-правила:**
- При сбросе sign-in cookies пользователя через Admin Console, SSO сессия IdP может сохраняться
- Для полного завершения доступа необходимо завершить сессию как в Google, так и в IdP
- Администратор должен координировать политики сессий между Google Workspace и IdP

---

### 3.3 Двухфакторная аутентификация (2FA/2SV)

#### FR-AUTH-020: Поддерживаемые методы 2FA
**Описание:** Система поддерживает множество методов второго фактора аутентификации.

**Доступные методы:**
| Метод | Описание | Уровень безопасности |
|-------|----------|---------------------|
| Security Key | Аппаратный ключ (YubiKey и др.) | Высокий (защита от фишинга) |
| Passkey | Биометрическая аутентификация + криптоключи | Высокий (защита от фишинга) |
| Google Prompt | Push-уведомление на доверенное устройство | Средний |
| Google Authenticator | TOTP-коды (работает офлайн) | Средний |
| SMS | Код подтверждения через SMS | Низкий (не рекомендуется) |
| Голосовой вызов | Код через телефонный звонок | Низкий |
| Резервные коды | Одноразовые коды (10 штук) | Для восстановления |

**User Story:**
> Как пользователь, заботящийся о безопасности, я хочу настроить двухфакторную аутентификацию, чтобы защитить свой календарь от несанкционированного доступа.

#### FR-AUTH-021: Обязательная 2FA для Workspace
**Описание:** Администратор Workspace может установить обязательное требование 2FA для пользователей.

**Бизнес-правила:**
- Администратор настраивает политику 2FA в Admin Console (Menu → Security → Authentication → 2-step verification)
- Google принудительно требует 2FA для учетных записей администраторов
- При потере устройства 2FA администратор может сгенерировать резервные коды для пользователя
- Super Admin должен хранить резервные коды для других администраторов
- Рекомендуется регистрировать несколько ключей безопасности для администраторских аккаунтов

**User Story:**
> Как администратор, я хочу принудительно включить 2FA для всех сотрудников, чтобы повысить безопасность корпоративных данных.

#### FR-AUTH-022: Резервные коды
**Описание:** Система предоставляет резервные коды для восстановления доступа при потере основного метода 2FA.

**Бизнес-правила:**
- Выдается набор из 10 одноразовых 8-значных кодов
- После использования код становится неактивным
- При генерации нового набора кодов предыдущий набор аннулируется
- Резервные коды недоступны для пользователей Advanced Protection Program
- Коды следует хранить в безопасном месте, Google никогда не запрашивает коды вне процесса входа

**User Story:**
> Как пользователь, я хочу сохранить резервные коды, чтобы восстановить доступ к аккаунту при потере телефона.

#### FR-AUTH-023: Passkeys
**Описание:** Система поддерживает беспарольную аутентификацию через passkeys.

**Бизнес-правила:**
- Passkey требует включенной блокировки экрана на устройстве
- При отключении блокировки экрана passkey не может использоваться до повторной активации
- Пользователь может удалить passkey с потерянного устройства через настройки аккаунта
- Passkeys обеспечивают тот же уровень защиты от фишинга, что и security keys
- Возможен обход passkey через опцию "Попробовать другой способ"

**User Story:**
> Как пользователь, я хочу использовать отпечаток пальца или Face ID для входа, чтобы не запоминать пароли.

### 3.4 Управление сессиями

#### FR-AUTH-030: Длительность веб-сессии
**Описание:** Система управляет временем жизни сессий пользователей.

**Бизнес-правила:**
| Тип пользователя | Длительность по умолчанию | Настраиваемость |
|------------------|---------------------------|-----------------|
| Личный аккаунт | 14 дней | Нет |
| Workspace пользователь | 14 дней | Да (админ) |
| Workspace Admin | 1 час | Да (от 1 до 24 часов) |

**Ограничения:**
- Длительность сессии не применяется к нативным мобильным приложениям (Android, iOS)
- Длительность сессии не применяется к OAuth-аутентифицированным приложениям
- Длительность сессии не применяется к ChromeOS
- Сессии мобильных приложений не истекают автоматически (только при сбросе пароля)

**User Story:**
> Как администратор, я хочу настроить время сессии в 4 часа для пользователей с повышенными привилегиями, чтобы требовать частую повторную аутентификацию.

#### FR-AUTH-031: Принудительная реаутентификация
**Описание:** Администратор может настроить политику принудительной повторной аутентификации.

**Бизнес-правила:**
- Минимальный интервал реаутентификации: 1 час
- Максимальный интервал реаутентификации: 24 часа
- Интервал отсчитывается с момента последней аутентификации, не с момента неактивности
- Применимо к Google Cloud Console и Cloud SDK

#### FR-AUTH-032: Просмотр активных устройств
**Описание:** Пользователь может просматривать список устройств с активными сессиями.

**Бизнес-правила:**
- Список доступен в разделе Security → Your Devices → Manage All Devices
- Отображается информация об устройстве и времени последнего доступа
- Время доступа может отличаться от ожидаемого из-за фоновой синхронизации приложений
- На одном устройстве может быть несколько активных сессий

**User Story:**
> Как пользователь, я хочу видеть список устройств, на которых выполнен вход в мой аккаунт, чтобы контролировать безопасность.

#### FR-AUTH-033: Сброс сессий пользователя (Admin)
**Описание:** Администратор Workspace может принудительно завершить сессии пользователя.

**Бизнес-правила:**
- Сброс sign-in cookies завершает все активные веб-сессии
- При использовании SSO необходимо дополнительно завершить сессию в IdP
- После сброса пользователь должен пройти повторную аутентификацию
- Функция доступна в Admin Console → Users → User Security Settings

**User Story:**
> Как администратор, я хочу немедленно завершить все сессии уволенного сотрудника, чтобы предотвратить несанкционированный доступ.

### 3.5 Переключение между аккаунтами

#### FR-AUTH-040: Добавление дополнительного аккаунта
**Описание:** Пользователь может добавить несколько Google аккаунтов на одном устройстве.

**Бизнес-правила:**
- При добавлении нового аккаунта он становится активным
- Каждый аккаунт требует отдельной полной аутентификации
- Профильное фото показывает текущий активный аккаунт
- Добавление аккаунта доступно через профильное фото → "Manage accounts on this device"

**User Story:**
> Как пользователь с личным и рабочим аккаунтами, я хочу добавить оба аккаунта в приложение, чтобы видеть события из обоих календарей.

#### FR-AUTH-041: Переключение между аккаунтами
**Описание:** Пользователь может переключаться между добавленными аккаунтами.

**Бизнес-правила:**
- Переключение доступно через нажатие на профильное фото
- Перед переключением необходимо сохранить несохраненные изменения
- На мобильных устройствах переключение работает только в портретной ориентации
- Переключение через меню профиля не меняет аккаунт по умолчанию

**User Story:**
> Как пользователь, я хочу быстро переключаться между личным и рабочим календарями без повторного ввода пароля.

**Состояния:**
```
[Активен аккаунт A] → (нажатие на профиль) → [Выбор аккаунта] → (выбор B) → [Активен аккаунт B]
```

#### FR-AUTH-042: Изменение аккаунта по умолчанию
**Описание:** Пользователь может изменить аккаунт по умолчанию для браузера.

**Бизнес-правила:**
- Аккаунт по умолчанию определяется порядком входа (первый = по умолчанию)
- Для изменения необходимо выйти из всех аккаунтов и войти заново в нужном порядке
- Аккаунт по умолчанию используется при открытии сервисов Google в новой вкладке

**User Story:**
> Как пользователь, я хочу установить рабочий аккаунт по умолчанию, чтобы Calendar открывался с рабочим расписанием.

#### FR-AUTH-043: Отображение событий из нескольких аккаунтов
**Описание:** Приложение Calendar может отображать события из всех добавленных аккаунтов.

**Бизнес-правила:**
- Пользователь может выбрать, какие календари отображать через меню
- Каждый календарь можно включить/отключить независимо
- Доступ к каждому аккаунту требует соответствующих разрешений

### 3.6 Выход из системы

#### FR-AUTH-050: Выход из одного устройства
**Описание:** Пользователь может выйти из аккаунта на текущем устройстве.

**Бизнес-правила:**
- Выход из Google Calendar означает выход из всех сервисов Google на устройстве
- Данные (события, файлы, фото) остаются в облаке
- При повторном входе все данные синхронизируются заново

**User Story:**
> Как пользователь, я хочу выйти из аккаунта на общем компьютере, чтобы защитить свои данные.

#### FR-AUTH-051: Удаленный выход с устройства
**Описание:** Пользователь может удаленно завершить сессию на другом устройстве.

**Бизнес-правила:**
- Доступно через Security → Your Devices → Manage All Devices
- Необходимо выйти из каждой сессии на устройстве отдельно (если их несколько)
- После удаленного выхода требуется повторная аутентификация на устройстве

**User Story:**
> Как пользователь, я хочу выйти из аккаунта на потерянном телефоне, чтобы защитить свои данные.

#### FR-AUTH-052: Выход со всех устройств
**Описание:** Пользователь может одновременно завершить все активные сессии.

**Бизнес-правила:**
- Быстрый способ: нажать "Don't recognize this device?" → "Secure your account"
- Следование инструкциям включает смену пароля
- После смены пароля все сессии автоматически завершаются (кроме текущей)
- Рекомендуется также включить 2FA для дополнительной защиты

**User Story:**
> Как пользователь, обнаруживший подозрительную активность, я хочу немедленно выйти со всех устройств, чтобы защитить аккаунт.

**Состояния:**
```
[Аутентифицирован на N устройствах] → (смена пароля) → [Все сессии завершены] → [Аутентифицирован только на текущем]
```

#### FR-AUTH-053: Удаление аккаунта с устройства
**Описание:** Пользователь может полностью удалить аккаунт с мобильного устройства.

**Бизнес-правила:**
- Удаление аккаунта прекращает синхронизацию Calendar на устройстве
- Локально кешированные данные удаляются
- Данные в облаке остаются без изменений
- Доступно через Manage accounts → Remove account

## 4. Делегирование доступа к календарю

### FR-AUTH-060: Уровни делегированного доступа
**Описание:** Пользователь может предоставить другим пользователям различные уровни доступа к своему календарю.

**Уровни доступа:**
| Уровень | Права |
|---------|-------|
| See only free/busy | Только информация о занятости, без деталей событий |
| See all event details | Просмотр всех деталей (кроме приватных событий) |
| Make changes to events | Редактирование событий + просмотр списка общего доступа |
| Make changes and manage sharing | Полный контроль: создание, редактирование, управление доступом |

**User Story:**
> Как руководитель, я хочу дать ассистенту полный доступ к моему календарю, чтобы он мог планировать встречи от моего имени.

#### FR-AUTH-061: Ограничения делегирования
**Описание:** Определенные функции недоступны для делегатов.

**Бизнес-правила:**
- Делегат не может настраивать уведомления и напоминания от имени владельца
- Приглашения от основного календаря отправляются от имени владельца
- Приглашения от дополнительных календарей отправляются от имени делегата
- Календарь с полными правами появляется в "My calendars", с ограниченными — в "Other calendars"

## 5. Административные функции (Workspace)

### FR-AUTH-070: Управление политиками аутентификации
**Описание:** Администратор может настраивать политики аутентификации для организации.

**Доступные настройки:**
- Обязательность 2FA
- Допустимые методы 2FA
- Длительность веб-сессий
- Требования к паролям
- Настройки SSO

**User Story:**
> Как администратор, я хочу настроить политики безопасности для всей организации, чтобы обеспечить соответствие корпоративным стандартам.

#### FR-AUTH-071: Контроль доступа приложений
**Описание:** Администратор может управлять доступом приложений к данным Google Workspace.

**Уровни доступа для приложений:**
| Уровень | Описание |
|---------|----------|
| Trusted | Полный доступ к данным Workspace |
| Limited | Ограниченный доступ |
| Specific Google data | Доступ только к определенным данным |
| Blocked | Доступ запрещен |

**Бизнес-правила:**
- Приложения могут быть добавлены в белый список по OAuth Client ID
- Белый список сохраняет доступ даже при применении Context-Aware Access политик

#### FR-AUTH-072: Управление доступом к календарям пользователей
**Описание:** Администратор с соответствующими привилегиями может управлять календарями всех пользователей.

**Бизнес-правила:**
- Super Admin и Calendar Admin видят все детали событий во всех календарях
- Привилегии Calendar не позволяют управлять календарями через Calendar App или API
- Для управления ресурсами требуется отдельная привилегия Calendar Resources

---

## 6. Восстановление доступа

### FR-AUTH-080: Восстановление при потере 2FA
**Описание:** Система предоставляет механизмы восстановления доступа при потере устройства 2FA.

**Методы восстановления:**
1. Использование резервных кодов
2. Использование альтернативного зарегистрированного метода 2FA
3. Обращение к администратору (для Workspace)
4. Процедура восстановления аккаунта Google

**Бизнес-правила (Workspace):**
- Администратор может сгенерировать временные резервные коды
- Super Admin должен иметь резервные ключи безопасности в безопасном месте
- Рекомендуется заранее зарегистрировать несколько методов 2FA

**User Story:**
> Как пользователь, потерявший телефон, я хочу использовать резервный код, чтобы восстановить доступ к календарю.

### FR-AUTH-081: Восстановление аккаунта
**Описание:** При невозможности использования стандартных методов доступна процедура восстановления аккаунта.

**Бизнес-правила:**
- Восстановление требует подтверждения личности
- Для Workspace аккаунтов восстановление выполняется администратором
- Для личных аккаунтов используется процедура восстановления Google Account

## 8. Интеграционные сценарии

### 8.1 Сценарий: Первый вход нового сотрудника Workspace

1. Сотрудник получает корпоративный email
2. При первом входе запрашивается установка пароля
3. Если в организации включена обязательная 2FA — требуется регистрация метода 2FA
4. Если настроен SSO — перенаправление на корпоративный IdP
5. После успешной аутентификации — доступ к Calendar

### 8.2 Сценарий: Подозрительная активность в аккаунте

1. Пользователь обнаруживает неизвестное устройство в списке активных
2. Пользователь нажимает "Don't recognize this device?"
3. Система предлагает "Secure your account"
4. Пользователь меняет пароль
5. Все сессии завершаются
6. Пользователь включает 2FA (если не включена)
7. Пользователь входит заново на доверенных устройствах

### 8.3 Сценарий: Увольнение сотрудника

1. Администратор получает уведомление об увольнении
2. Администратор сбрасывает sign-in cookies пользователя
3. Если используется SSO — администратор завершает сессию в IdP
4. Администратор блокирует учетную запись
5. Календарь сотрудника может быть передан другому пользователю

## 9. Ограничения и исключения

### 9.1 Технические ограничения

| Ограничение | Описание |
|-------------|----------|
| Мобильные приложения | Длительность сессии не применяется к нативным приложениям |
| ChromeOS | Длительность сессии не применяется |
| OAuth приложения | Длительность сессии не применяется к OAuth-авторизованным приложениям |
| Google Authenticator | Синхронизация кодов в облако доступна только с апреля 2023 |
| Advanced Protection | Резервные коды недоступны |

### 9.2 Бизнес-ограничения

| Ограничение | Описание |
|-------------|----------|
| Аккаунт по умолчанию | Изменяется только через полный выход и повторный вход |
| Делегат и уведомления | Делегат не может управлять уведомлениями владельца |
| Calendar API | Admin привилегии Calendar не дают доступ через API |
| Множественные сессии | Каждую сессию на устройстве нужно завершать отдельно |

## 10. Глоссарий

| Термин | Определение |
|--------|-------------|
| 2FA/2SV | Двухфакторная аутентификация / Двухшаговая проверка |
