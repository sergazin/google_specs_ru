# Общественный транспорт — Google Maps

> **Module ID**: GMAPS-008
> **Version**: 1.0.0
> **Last Updated**: 2026-03-19
> **Dependencies**: Маршрутизация, Поиск, Уведомления, Платежи (Google Wallet)

## Executive Summary

Модуль «Общественный транспорт» обеспечивает полный цикл планирования и совершения поездок на общественном транспорте в Google Maps. Включает построение мультимодальных маршрутов (автобус, метро, трамвай, электричка, паром, монорельс, фуникулёр), отображение расписаний и прибытия в реальном времени, прогнозирование загруженности вагонов и станций, информацию о стоимости проезда, интеграцию с транспортными операторами через GTFS/GTFS-RT, виджет «Транспорт рядом», навигацию по пересадкам, офлайн-карты транспорта, доступные маршруты для людей с ограниченной мобильностью и сервисные алерты о нарушениях в работе транспорта. Покрытие — более 1 000 000 остановок в 10 000+ транспортных агентств в 100+ странах.

## Функциональные требования

### FR-TRNS-001: Построение маршрута на общественном транспорте
**Приоритет**: P0

> Как пользователь, я хочу построить маршрут из точки А в точку Б с использованием общественного транспорта, чтобы спланировать поездку оптимальным образом.

**Предусловия**:
- Пользователь указал начальную и конечную точки маршрута
- Для выбранного региона доступны данные GTFS от транспортных операторов
- Выбран режим маршрутизации «Общественный транспорт»

**Основной поток**:
1. Пользователь вводит начальную и конечную точки маршрута
2. Пользователь выбирает вкладку «Общественный транспорт» (иконка поезда/автобуса)
3. Система строит несколько вариантов маршрута с учётом:
   - Текущего времени и расписания транспорта
   - Времени пешего перехода до остановки и от остановки
   - Количества и длительности пересадок
   - Общего времени в пути
   - Доступных видов транспорта
4. Каждый вариант маршрута отображает:
   - Общее время в пути (от двери до двери)
   - Время отправления и прибытия
   - Виды транспорта на каждом сегменте (иконки)
   - Номера маршрутов / линий
   - Количество пересадок
   - Время пешего перехода (первая/последняя миля + между пересадками)
   - Стоимость проезда (если доступна)
   - Загруженность (если доступна)
5. Варианты маршрутов ранжируются по релевантности (оптимальное сочетание времени, пересадок и удобства)
6. Пользователь выбирает один из вариантов для детального просмотра

**Альтернативный поток — Маршрут недоступен**:
1. В регионе отсутствуют данные GTFS
2. Система информирует пользователя, что данные о транспорте недоступны
3. Система предлагает альтернативные режимы (автомобиль, велосипед, пешком)

**Альтернативный поток — Транспорт не работает в запрошенное время**:
1. Пользователь запрашивает маршрут на ночное время (транспорт не ходит)
2. Система информирует, что общественный транспорт недоступен в это время
3. Система предлагает ближайшее доступное время отправления
4. Система предлагает альтернативные режимы (такси, ходьба)

**Критерии приёмки**:
- [ ] AC-001: Система строит минимум 2–5 вариантов маршрута при наличии данных
- [ ] AC-002: Каждый вариант содержит полную информацию (время, пересадки, виды транспорта)
- [ ] AC-003: Варианты ранжируются по оптимальности
- [ ] AC-004: При отсутствии данных отображается информативное сообщение
- [ ] AC-005: Время пешего перехода включено в общее время маршрута

**Бизнес-правила**:

| ID правила | Правило |
|------------|---------|
| BR-001 | Маршрут строится от двери до двери, включая пешие сегменты до/от остановки |
| BR-002 | Система учитывает текущее время суток и актуальное расписание (будни / выходные / праздники) |
| BR-003 | Если маршрут с пересадкой требует значительно больше времени, чем прямой, прямой маршрут отображается выше в списке |
| BR-004 | Пешие сегменты не должны превышать разумную дистанцию (обычно до 1.5 км до остановки) |
| BR-005 | Маршруты отображаются только при наличии актуальных данных GTFS от оператора |

### FR-TRNS-002: Фильтрация и предпочтения маршрутов
**Приоритет**: P0

> Как пользователь, я хочу настроить предпочтения для построения маршрута, чтобы система предлагала наиболее подходящие мне варианты.

**Предусловия**:
- Пользователь находится на экране построения маршрута общественного транспорта
- Данные о транспорте доступны для региона

**Основной поток**:
1. Пользователь нажимает «Параметры» (Options) на экране маршрута
2. Система отображает доступные фильтры:
   - **Тип транспорта**: автобус, метро, трамвай, поезд/электричка, паром (множественный выбор)
   - **Предпочтение маршрута**: меньше пересадок / меньше ходьбы / быстрее всего
   - **Доступность**: маршруты с учётом инвалидной коляски (wheelchair accessible)
   - **Время отправления**: уехать сейчас / уехать к определённому времени / прибыть к определённому времени
3. Пользователь настраивает фильтры
4. Система перестраивает маршруты с учётом выбранных параметров
5. Результаты обновляются в реальном времени

**Критерии приёмки**:
- [ ] AC-001: Все типы фильтров доступны и функционируют
- [ ] AC-002: Фильтр по типу транспорта корректно исключает невыбранные виды
- [ ] AC-003: Предпочтение «меньше пересадок» приоритизирует прямые маршруты
- [ ] AC-004: Предпочтение «меньше ходьбы» минимизирует пешие сегменты
- [ ] AC-005: Wheelchair-accessible фильтр показывает только маршруты без лестниц, с лифтами и пандусами

**Бизнес-правила**:

| ID правила | Правило |
|------------|---------|
| BR-006 | Фильтр типа транспорта позволяет множественный выбор; при отключении всех типов фильтр сбрасывается |
| BR-007 | Предпочтение маршрута — взаимоисключающие опции (выбирается одно из трёх) |
| BR-008 | Wheelchair-accessible маршруты доступны только в поддерживаемых городах (Лондон, Нью-Йорк, Токио, Мехико, Бостон, Сидней и др.) |
| BR-009 | Время «прибыть к» рассчитывает маршрут обратно от нужного времени прибытия |
| BR-010 | Настройки фильтров не сохраняются между сессиями (сбрасываются при новом поиске) |

### FR-TRNS-003: Детальный просмотр маршрута
**Приоритет**: P0

> Как пользователь, я хочу просмотреть подробности выбранного маршрута, чтобы знать каждый шаг поездки.

**Предусловия**:
- Пользователь выбрал один из предложенных вариантов маршрута

**Основной поток**:
1. Пользователь нажимает на выбранный маршрут
2. Система отображает пошаговую детализацию маршрута:
   - **Пеший сегмент до остановки**: направление, расстояние, время
   - **Посадка**: название остановки, номер маршрута/линии, направление движения, платформа (если применимо)
   - **В транспорте**: количество остановок, названия промежуточных остановок (раскрываемый список), время в пути сегмента
   - **Пересадка**: название станции/остановки, направление перехода, время на пересадку
   - **Высадка**: название остановки
   - **Пеший сегмент до назначения**: направление, расстояние, время
3. На карте отображается:
   - Полный маршрут с цветовой кодировкой по видам транспорта
   - Маркеры остановок посадки и высадки
   - Пешие сегменты (пунктирная линия)
   - Точки пересадок
4. Для каждого транспортного сегмента отображается:
   - Название линии / номер маршрута
   - Цвет линии (соответствует официальной схеме оператора)
   - Конечная станция (направление)
   - Время отправления (по расписанию или реальное)
   - Оператор

**Критерии приёмки**:
- [ ] AC-001: Все сегменты маршрута отображаются последовательно
- [ ] AC-002: Промежуточные остановки доступны в раскрываемом списке
- [ ] AC-003: Карта отображает маршрут с цветовой кодировкой
- [ ] AC-004: Время каждого сегмента указано корректно
- [ ] AC-005: Информация о направлении (конечная станция) присутствует

**Бизнес-правила**:

| ID правила | Правило |
|------------|---------|
| BR-011 | Цветовая кодировка линий соответствует официальным цветам транспортного оператора |
| BR-012 | Время пересадки включает расчётное время перехода между платформами |
| BR-013 | Промежуточные остановки скрыты по умолчанию; раскрываются по нажатию |
| BR-014 | Если для сегмента доступно реальное время — отображается реальное; иначе — по расписанию |

### FR-TRNS-004: Расписания и время отправления
**Приоритет**: P0

> Как пользователь, я хочу видеть расписание отправлений с конкретной остановки или станции, чтобы спланировать время выхода из дома.

**Предусловия**:
- Пользователь находится на странице остановки/станции или использует виджет «Транспорт рядом»

**Основной поток**:
1. Пользователь выбирает остановку или станцию на карте, либо через поиск
2. Система отображает страницу остановки/станции с информацией:
   - Название остановки/станции
   - Все маршруты/линии, обслуживающие эту остановку
   - Ближайшие отправления по каждому маршруту/линии
   - Направление движения (конечная станция)
3. Для каждого отправления указывается:
   - Время отправления (по расписанию)
   - Реальное время прибытия транспорта (если доступен GTFS-RT)
   - Задержка (если есть отклонение от расписания)
   - Загруженность вагона/автобуса (если доступна)
4. Пользователь может просмотреть полное расписание маршрута на весь день
5. Пользователь может переключать дни (будни/выходные/конкретная дата)

**Альтернативный поток — Реальное время недоступно**:
1. Транспортный оператор не предоставляет GTFS-RT данные
2. Система отображает только расписание (статические данные GTFS)
3. Время отправления помечается как «по расписанию» (без индикатора реального времени)

**Критерии приёмки**:
- [ ] AC-001: Все маршруты, проходящие через остановку, отображаются
- [ ] AC-002: Ближайшие отправления отсортированы по времени
- [ ] AC-003: Реальное время отличается визуально от расписания
- [ ] AC-004: Задержки отображаются с указанием величины
- [ ] AC-005: Полное расписание на день доступно для просмотра

**Бизнес-правила**:

| ID правила | Правило |
|------------|---------|
| BR-015 | Реальное время прибытия приоритетнее расписания; при доступности GTFS-RT отображается именно оно |
| BR-016 | Задержка отображается, если отклонение от расписания превышает 1 минуту |
| BR-017 | Расписание учитывает тип дня: будни, суббота, воскресенье, праздничные дни |
| BR-018 | Прошедшие отправления не отображаются; список начинается с ближайшего предстоящего |
| BR-019 | Если все рейсы на сегодня завершены — отображается первый рейс следующего дня |

### FR-TRNS-005: Прибытие транспорта в реальном времени
**Приоритет**: P0

> Как пользователь, я хочу видеть реальное время прибытия автобуса или поезда, чтобы не ждать на остановке дольше необходимого.

**Предусловия**:
- Транспортный оператор предоставляет данные GTFS Realtime (Trip Updates и/или Vehicle Positions)
- Пользователь просматривает остановку или активный маршрут

**Основной поток**:
1. Система получает данные GTFS Realtime от оператора:
   - **Trip Updates**: обновлённые времена прибытия/отправления
   - **Vehicle Positions**: текущие координаты транспортных средств
2. На странице остановки/станции отображается:
   - Реальное время до прибытия (например, «3 мин», «прибывает», «задержка 5 мин»)
   - Индикатор реального времени (иконка «live» или пульсирующая точка)
   - Позиция транспортного средства на карте (если доступны Vehicle Positions)
3. Данные обновляются автоматически каждые 15–60 секунд
4. При активном маршруте система отслеживает:
   - Текущую позицию транспорта на маршруте
   - Обновлённый ETA для каждого сегмента
   - Уведомление о задержках

**Альтернативный поток — Потеря данных реального времени**:
1. Связь с источником GTFS-RT потеряна
2. Система переключается на данные расписания
3. Индикатор «live» убирается
4. При восстановлении связи — автоматический возврат к реальному времени

**Критерии приёмки**:
- [ ] AC-001: Реальное время прибытия обновляется автоматически
- [ ] AC-002: Индикатор «live» отличает реальное время от расписания
- [ ] AC-003: Позиция транспорта на карте обновляется
- [ ] AC-004: При потере данных — корректный фолбэк на расписание
- [ ] AC-005: Задержки отображаются с точностью до минуты

**Бизнес-правила**:

| ID правила | Правило |
|------------|---------|
| BR-020 | Данные реального времени предоставляются транспортными операторами; Google не генерирует их самостоятельно |
| BR-021 | При расхождении данных реального времени и расписания — реальное время приоритетнее |
| BR-022 | Позиция транспорта на карте отображается только при наличии данных Vehicle Positions |
| BR-023 | Частота обновления данных реального времени зависит от оператора (типично 15–60 секунд) |
| BR-024 | Если реальное время прибытия ≤ 1 минуты — отображается «прибывает» вместо числа |

### FR-TRNS-006: Прогноз загруженности транспорта (Crowdedness)
**Приоритет**: P1

> Как пользователь, я хочу знать, насколько загружен автобус или вагон метро, чтобы решить, стоит ли ждать следующий рейс или выбрать альтернативный маршрут.

**Предусловия**:
- Для данного маршрута/станции доступны данные о загруженности (исторические или от оператора)

**Основной поток**:
1. Система определяет прогноз загруженности на основе:
   - Исторических данных о местоположении (агрегированные и анонимизированные)
   - Пользовательских отчётов о загруженности (crowdsourcing)
   - Данных от транспортного оператора (если предоставлены)
   - AI-моделей прогнозирования
2. Загруженность отображается для:
   - Конкретного рейса (вагона/автобуса) — в карточке отправления
   - Станции/остановки — под названием станции
   - Сегмента маршрута — при построении маршрута
3. Уровни загруженности:
   - **Много свободных мест** (Many seats available)
   - **Несколько свободных мест** (Some seats available)
   - **Стоячие места** (Standing room only)
   - **Ограниченно стоячих мест** (Limited standing room)
   - **Переполнен** (Crush load / At capacity)
4. Пользователь может оставить собственный отчёт о загруженности после поездки

**Альтернативный поток — Пользовательский отчёт о загруженности**:
1. Во время или после поездки система предлагает оценить загруженность
2. Пользователь выбирает один из уровней загруженности
3. Отчёт агрегируется с другими для улучшения прогнозов
4. Система благодарит пользователя за вклад

**Критерии приёмки**:
- [ ] AC-001: Загруженность отображается при доступности данных
- [ ] AC-002: Уровни загруженности визуально различимы (иконки и текст)
- [ ] AC-003: Пользователь может оставить отчёт о загруженности
- [ ] AC-004: Прогноз учитывает время суток и день недели
- [ ] AC-005: При отсутствии данных — секция загруженности не отображается

**Бизнес-правила**:

| ID правила | Правило |

**Альтернативный поток — AI-рекомендация альтернативы**:
1. Система анализирует, что пешком или на велосипеде будет быстрее, чем на транспорте
2. Система отображает рекомендацию: «Пешком за XX мин — быстрее, чем на транспорте»
3. Пользователь видит сравнение времени всех доступных режимов

**Критерии приёмки**:
- [ ] AC-001: Мультимодальные маршруты строятся корректно
- [ ] AC-002: Время на пересадку реалистично (учитывает физическое расстояние)
- [ ] AC-003: Буферное время для пересадок соблюдается

### FR-TRNS-012: Сервисные алерты и уведомления о нарушениях
**Приоритет**: P1

> Как пользователь, я хочу получать информацию о сбоях, задержках и изменениях в работе транспорта, чтобы скорректировать свои планы.

   - **Изменение маршрута** (Detour): транспорт следует по изменённому маршруту
   - **Сокращённое обслуживание** (Reduced Service): меньше рейсов, чем обычно
   - **Закрытие станции** (Station Closed): станция временно закрыта

   - На странице затронутой станции/маршрута (баннер вверху)

3. Каждый алерт содержит:
   - Тип нарушения
   - Затронутые линии/маршруты/станции
   - Период действия (начало — конец)
   - Описание (текст от оператора)
   - Рекомендуемые альтернативы (если предоставлены)
4. При построении маршрута через затронутый сегмент:
   - Система предупреждает пользователя
   - Система перестраивает маршрут в обход (если алерт типа NO_SERVICE)
   - Система показывает увеличенное время (если алерт типа Delay)

**Альтернативный поток — Плановые изменения**:
1. Оператор публикует информацию о плановых работах (ремонт путей, закрытие на выходные)
2. Система отображает плановые алерты заблаговременно
3. При построении маршрута на дату плановых работ — система учитывает ограничения

**Критерии приёмки**:
- [ ] AC-001: Сервисные алерты отображаются на затронутых станциях и маршрутах
- [ ] AC-002: При построении маршрута алерты учитываются в расчёте
- [ ] AC-003: Алерты типа NO_SERVICE приводят к перестройке маршрута
- [ ] AC-004: Плановые алерты отображаются заблаговременно
- [ ] AC-005: Алерты ранжируются по степени влияния (DETOUR > DELAY > MODIFIED_SERVICE)

**Бизнес-правила**:

| ID правила | Правило |
|------------|---------|
| BR-055 | Алерты с эффектом NO_SERVICE автоматически исключают затронутые сегменты из маршрутизации |
| BR-056 | Алерты с эффектом DETOUR имеют наивысший приоритет предупреждения |
| BR-057 | Множественные алерты на одном маршруте упорядочиваются по степени влияния (impact score) |
| BR-058 | Impact score рассчитывается на основе полей effect, cause и informed_entity |

- [ ] AC-003: Если полностью доступный маршрут невозможен — указываются барьеры

### FR-TRNS-016: Интеграция с транспортными операторами (GTFS)
**Приоритет**: P0

> Как транспортный оператор, я хочу предоставить данные о маршрутах, расписаниях и реальном времени в Google Maps, чтобы пассажиры могли планировать поездки через крупнейшую картографическую платформу.

**Предусловия**:
- Транспортный оператор зарегистрирован в Google Transit Partners
- Данные подготовлены в формате GTFS / GTFS Realtime

**Основной поток**:
1. Оператор создаёт данные в формате GTFS:
   - **Обязательные данные**: агентство, маршруты, поездки, расписания, остановки, стоп-таймы
   - **Опциональные данные**: тарифы, формы маршрутов, частоты, трансферы, уровни
2. Оператор загружает GTFS-фид через Transit Partners Portal
3. Google валидирует данные:
   - Проверка формата и полноты
   - Проверка корректности координат
   - Проверка непротиворечивости расписания
4. После валидации данные публикуются в Google Maps
5. Оператор может дополнительно подключить GTFS Realtime:
   - **Trip Updates**: обновлённые времена прибытия/отправления
   - **Vehicle Positions**: текущие координаты транспорта
   - **Service Alerts**: сервисные уведомления
6. Данные обновляются по расписанию, согласованному с оператором

**Критерии приёмки**:
- [ ] AC-001: GTFS-фид успешно загружается и валидируется
- [ ] AC-002: Маршруты, расписания и остановки корректно отображаются в Google Maps
- [ ] AC-003: GTFS Realtime данные обновляются с заданной частотой
- [ ] AC-004: Сервисные алерты публикуются и отображаются
- [ ] AC-005: Ошибки валидации подробно описаны для оператора

**Бизнес-правила**:

| ID правила | Правило |
|------------|---------|
| BR-076 | Данные GTFS предоставляются транспортными операторами бесплатно; Google не взимает плату за публикацию |
| BR-077 | Оператор несёт ответственность за актуальность и корректность данных |
| BR-078 | Google валидирует данные, но не модифицирует их без согласия оператора |
| BR-079 | GTFS Realtime — опциональное дополнение к статическому GTFS |
| BR-080 | Обновление статических данных GTFS рекомендуется не реже 1 раза в квартал |
