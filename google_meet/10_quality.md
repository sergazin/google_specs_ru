# Модуль: Качество связи и диагностика

## Описание модуля

Модуль "Качество связи и диагностика" отвечает за мониторинг, адаптацию и оптимизацию качества видео- и аудиосвязи в Google Meet. Система обеспечивает автоматическую адаптацию параметров передачи в зависимости от условий сети, предоставляет пользователям и администраторам инструменты диагностики, собирает метрики качества и генерирует отчеты о проблемах.

Ключевые принципы модуля:
- **Адаптивность**: автоматическая подстройка качества под текущие условия сети
- **Прозрачность**: информирование пользователя о состоянии соединения
- **Проактивность**: предупреждение о проблемах до их критического влияния
- **Аналитика**: детальный сбор метрик для постфактум анализа

---

## Роли пользователей

### Участник встречи (Participant)
- Просмотр индикатора качества своего соединения
- Получение автоматических рекомендаций по улучшению качества
- Ручное изменение настроек разрешения видео
- Переключение в режим "Только аудио"
- Отправка отчетов о проблемах
- Оценка качества звонка после завершения

### Организатор встречи (Host)
- Все возможности участника
- Просмотр сводной информации о качестве соединения участников
- Получение предупреждений о проблемах с качеством у участников
- Возможность отключить видео у участника с плохим соединением

### Администратор Workspace (Admin)
- Доступ к Meet Quality Tool (MQT)
- Просмотр детальной статистики по встречам, участникам и устройствам
- Настройка политик качества для организации
- Анализ журналов активности Meet
- Диагностика проблем устройств Google Meet Hardware
- Делегирование доступа к MQT другим пользователям

### Супер-администратор (Super Admin)
- Все возможности администратора
- Управление настройками загрузки клиентских логов
- Создание кастомных ролей с доступом к MQT
- Настройка глобальных ограничений качества видео

## Функциональные требования

### FR-QUAL-001: Адаптивное управление качеством видео

**Описание**: Система автоматически регулирует качество исходящего и входящего видео в зависимости от доступной пропускной способности сети, задержки и загрузки CPU.

**Алгоритм адаптации**:
1. Система непрерывно мониторит:
   - Доступную пропускную способность (входящую и исходящую)
   - Задержку сети (RTT)
   - Потери пакетов (Packet Loss)
   - Джиттер (Jitter)
   - Загрузку CPU устройства

2. На основе метрик принимается решение о целевом разрешении:

| Условия сети | Целевое разрешение | Битрейт |
|--------------|-------------------|---------|
| Отличные (latency <50ms, bandwidth >3.2 Mbps) | 1080p (Full HD) | До 3.2 Mbps |
| Хорошие (latency <50ms, bandwidth 2.6-3.2 Mbps) | 720p (HD) | 2.6-3.2 Mbps |
| Удовлетворительные (latency <100ms, bandwidth 1-2 Mbps) | 360p (SD) | 1-2 Mbps |
| Плохие (latency >100ms или bandwidth <1 Mbps) | Автоснижение до 240p | <1 Mbps |
| Критические (bandwidth <300 Kbps) | Только аудио | ~100 Kbps |

3. Переключение происходит плавно, без резких скачков качества
4. При улучшении условий качество восстанавливается с задержкой 10-15 секунд

**Особые условия для 1080p**:
- Доступно только на компьютерах с камерой 1080p
- Требуется достаточная вычислительная мощность
- Работает только в звонках с двумя участниками
- По умолчанию выключено - пользователь должен активировать вручную

**Бизнес-правила**:
- BR-QUAL-001: При конфликте между качеством видео и стабильностью аудио, приоритет отдается аудио
- BR-QUAL-002: Если bandwidth падает ниже минимального порога более 30 секунд, система принудительно переключает в режим пониженного качества
- BR-QUAL-003: Используются кодеки VP9 и AV1 для оптимальной компрессии

---

### FR-QUAL-002: Индикаторы качества соединения

**Описание**: Система отображает визуальные индикаторы качества соединения для информирования пользователя о текущем состоянии.

**Типы индикаторов**:

1. **Основной индикатор качества сети**
   - Зеленый: Отличное качество соединения
   - Желтый: Удовлетворительное качество, возможны незначительные проблемы
   - Красный: Плохое качество, высокая вероятность проблем с видео/аудио

2. **Индикатор на кнопке "Еще" (More options)**
   - Красная точка появляется при обнаружении проблем с сетью или устройством
   - Отображается в течение 5 минут или до нажатия на кнопку
   - Появляется не чаще одного раза в день для одной и той же проблемы

3. **Индикаторы для других участников** (видны организатору)
   - Иконка качества соединения рядом с плиткой участника
   - Предупреждение о нестабильном соединении участника

**Логика определения качества**:

| Параметр | Зеленый | Желтый | Красный |
|----------|---------|--------|---------|
| RTT (задержка) | <50 ms | 50-150 ms | >150 ms |
| Packet Loss | <1% | 1-5% | >5% |
| Jitter | <30 ms | 30-100 ms | >100 ms |
| Bandwidth | >2.6 Mbps | 1-2.6 Mbps | <1 Mbps |

**Бизнес-правила**:
- BR-QUAL-004: Индикатор качества обновляется каждые 5 секунд
- BR-QUAL-005: При резком ухудшении качества (переход из зеленого в красный) генерируется всплывающее уведомление
- BR-QUAL-006: Индикаторы других участников видны только организатору и со-организаторам

### FR-QUAL-003: Диагностика и рекомендации в реальном времени

**Описание**: Система предоставляет автоматические рекомендации по устранению проблем с качеством во время встречи.

**Механизм работы**:

1. **Обнаружение проблемы**:
   - Мониторинг метрик в реальном времени
   - Анализ паттернов (повторяющиеся проблемы)
   - Определение источника проблемы (сеть, устройство, браузер)

2. **Категории проблем и рекомендации**:

| Проблема | Диагностика | Рекомендация |
|----------|-------------|--------------|
| Низкая пропускная способность | Bandwidth <1 Mbps | Перейти на проводное соединение, закрыть другие приложения |
| Высокий Packet Loss | Loss >5% | Проверить Wi-Fi, приблизиться к роутеру |
| Высокая загрузка CPU | CPU >90% | Закрыть вкладки браузера, снизить разрешение видео |
| Проблемы с VPN | Высокий RTT через VPN | Временно отключить VPN |
| Плохое Wi-Fi | Частые переподключения | Использовать 5 GHz вместо 2.4 GHz |
| Недостаточно света | Низкое качество видео с камеры | Включить дополнительное освещение |

3. **Отображение рекомендаций**:
   - Доступ через меню "Еще" -> "Устранение неполадок и справка"
   - Персонализированные советы на основе выявленной проблемы
   - Пошаговые инструкции для устранения

**Бизнес-правила**:
- BR-QUAL-007: Рекомендации показываются только для проблем, которые пользователь может исправить
- BR-QUAL-008: Одна и та же рекомендация не показывается повторно в течение встречи
- BR-QUAL-009: Критические рекомендации (переключение на аудио) имеют приоритет

### FR-QUAL-004: Ручное управление разрешением видео

**Описание**: Пользователь может вручную установить разрешение отправляемого и принимаемого видео.

**Доступные настройки Send Resolution (исходящее видео)**:
- Full HD (1080p) - при наличии совместимой камеры и достаточной мощности CPU
- High Definition (720p) - требуется четырехъядерный процессор
- Standard Definition (360p) - базовое качество

**Доступные настройки Receive Resolution (входящее видео)**:
- High Definition (720p)
- Standard Definition (360p)
- Audio Only - отключение видео других участников

**Логика применения**:
1. Настройки применяются немедленно после выбора
2. Настройки сохраняются на уровне браузера
3. Система может автоматически снизить качество ниже выбранного при проблемах с сетью
4. Администратор может ограничить максимально доступное разрешение

**Бизнес-правила**:
- BR-QUAL-010: Пользователь не может выбрать разрешение выше, чем позволяет его оборудование
- BR-QUAL-011: Опция 1080p отображается только при соответствии всем требованиям
- BR-QUAL-012: При выборе "Audio Only" контент презентаций продолжает отображаться

### FR-QUAL-005: Режим экономии трафика (Saver Mode)

**Описание**: Специальный режим для мобильных устройств, минимизирующий потребление данных и заряда батареи.

**Функциональность**:

1. **Активация**:
   - Через настройки приложения Meet
   - Опция "Ограничить использование данных" (Limit data usage)
   - Может быть включена постоянно или для конкретного звонка

2. **Эффект при включении**:
   - Снижение разрешения входящего видео до минимума
   - Снижение частоты кадров
   - Оптимизация аудио кодека
   - Уменьшение частоты обновления метаданных
   - Снижение энергопотребления

3. **Ограничения режима**:
   - Качество видео других участников значительно снижено
   - Может быть заметна задержка видео
   - Некоторые визуальные эффекты отключены

**Бизнес-правила**:
- BR-QUAL-013: Режим экономии доступен только на мобильных устройствах (Android, iOS)
- BR-QUAL-014: При активации режима система отправляет уведомление пользователю о снижении качества
- BR-QUAL-015: Настройка режима сохраняется между сессиями

### FR-QUAL-006: Автоматическое переключение на аудио

**Описание**: При критическом ухудшении сетевых условий система автоматически предлагает или переключает пользователя в режим "Только аудио".

**Сценарии переключения**:

1. **Рекомендательный режим**:
   - Условие: Bandwidth стабильно ниже 500 Kbps более 15 секунд
   - Действие: Показывается рекомендация отключить камеру
   - Пользователь принимает решение самостоятельно

2. **Принудительный режим** (при административной настройке):
   - Условие: Bandwidth ниже 300 Kbps более 30 секунд
   - Действие: Камера автоматически отключается
   - Уведомление пользователю о причине

3. **Частичное отключение**:
   - Условие: Умеренные проблемы с bandwidth
   - Действие: Отключается только входящее видео (Receive = Audio Only)
   - Исходящее видео продолжает работать

**Восстановление**:
- При улучшении условий пользователю предлагается включить камеру
- Автоматическое включение не происходит
- Кнопка включения камеры остается активной

**Бизнес-правила**:
- BR-QUAL-016: Аудио имеет абсолютный приоритет над видео
- BR-QUAL-017: Контент экрана (Screen Share) сохраняется даже при отключении видео участников
- BR-QUAL-018: Принудительное отключение логируется для администратора

### FR-QUAL-007: Статистика соединения

**Описание**: Система собирает детальную статистику о качестве соединения каждого участника для анализа и диагностики.

**Собираемые метрики**:

1. **Сетевые метрики**:
   - Round-Trip Time (RTT) - задержка в миллисекундах
   - Packet Loss (%) - процент потерянных пакетов
   - Jitter (ms) - вариация задержки
   - Available Bandwidth (Mbps) - доступная пропускная способность
   - Used Bandwidth (Mbps) - фактически используемая пропускная способность
   - Network Congestion - уровень перегрузки сети

2. **Аудио метрики**:
   - Microphone Level - уровень входного сигнала микрофона
   - Received Audio Level - уровень получаемого аудио
   - Audio Packet Loss - потери аудио пакетов
   - Audio Jitter Buffer - размер буфера

3. **Видео метрики**:
   - Send Resolution - разрешение исходящего видео
   - Receive Resolution - разрешение входящего видео
   - Framerate (FPS) - частота кадров
   - Video Bitrate - битрейт видео
   - Video Packet Loss - потери видео пакетов

4. **Системные метрики**:
   - CPU Usage (%) - загрузка процессора
   - Memory Usage - использование памяти
   - Device Type - тип устройства
   - Browser/App Version - версия клиента
   - OS Version - версия операционной системы

**Частота сбора**: Метрики собираются каждые 1-5 секунд в зависимости от типа.

**Хранение**: Данные хранятся 30 дней в Meet Quality Tool.

### FR-QUAL-008: Meet Quality Tool (MQT) для администраторов

**Описание**: Административный инструмент для анализа качества встреч, диагностики проблем и мониторинга устройств.

**Доступ к MQT**:
- Через Admin Console: Menu > Apps > Google Workspace > Google Meet > Meet quality tool
- Прямая ссылка для делегированных пользователей
- Требуемая роль: Service Settings administrator privilege

**Представления данных (Views)**:

1. **По встречам (Meetings)**:
   - Список всех встреч организации
   - Поиск по коду встречи, организатору, участнику
   - Сводная статистика: количество встреч, средняя длительность
   - Агрегированные метрики качества

2. **По участникам (Participants)**:
   - История участия пользователя во встречах
   - Паттерны проблем (повторяющиеся у конкретного пользователя)
   - Анализ оборудования и сети пользователя

3. **По устройствам (Devices)**:
   - Статус Google Meet Hardware устройств
   - История диагностических тестов
   - Метрики качества видео, разрешения, захвата аудио

**Функции MQT**:

1. **Детализация по endpoint'у**:
   - Графики метрик во времени
   - Video Packet Loss over time
   - Bandwidth (used vs available)
   - CPU load during meeting

2. **Диагностические тесты** (для Meet Hardware):
   - Тест качества соединения
   - Тест пропускной способности видео
   - Тест разрешения
   - Тест захвата аудио
   - Хранится последние 10 результатов тестов

3. **Сводная панель**:
   - Количество встреч за период
   - Средняя длительность
   - Уровень перегрузки сети
   - Средний Packet Loss
   - Средний Jitter
   - Рейтинги обратной связи пользователей

**Ограничения**:
- Данные не отображаются в реальном времени (есть задержка)
- Срок хранения данных: 30 дней
- Содержимое встреч не записывается и не анализируется

### FR-QUAL-009: Журналы активности Meet (Activity Logs)

**Описание**: Система записывает события активности для каждого участника встречи, создавая аудит-лог для анализа.

**События, записываемые в журнал**:

1. **Call Event** (при выходе участника из звонка):
   - Device Type - тип устройства
   - Location - местоположение (страна, регион)
   - IP Address - IP-адрес участника
   - Identifier - идентификатор участника
   - Call Rating - оценка звонка (если оставлена)

2. **Usage Metrics**:
   - Time with video on - время с включенным видео
   - Time with audio on - время с включенным аудио
   - Time screen sharing - время демонстрации экрана
   - Total duration - общая длительность участия

3. **Network Statistics**:
   - Jitter - вариация задержки
   - Packet Loss - потери пакетов
   - RTT - round-trip time
   - Bandwidth statistics - статистика пропускной способности

**Доступ к логам**:
- Admin Console: Menu > Reporting > Audit and investigation > Meet log events
- Требуется привилегия: Audit & Investigation administrator

**Фильтрация логов**:
- По дате/периоду
- По организатору
- По участнику
- По коду встречи
- По типу события

### FR-QUAL-010: Отчеты о проблемах от пользователей

**Описание**: Пользователи могут отправлять отчеты о проблемах с качеством непосредственно во время или после встречи.

**Механизмы отправки**:

1. **Во время встречи (Desktop)**:
   - Меню "Еще" > "Сообщить о проблеме"
   - Описание проблемы в свободной форме
   - Автоматический скриншот (с возможностью удаления)
   - Отправка логов браузера (если разрешено администратором)

2. **Во время встречи (Android)**:
   - Коснуться экрана > "Еще" > "Настройки"
   - "Сообщить о проблеме" > "Начать"
   - Ввод описания проблемы
   - Скриншот (с возможностью удаления)

3. **Во время встречи (iOS)**:
   - Коснуться экрана > "Еще" > "Настройки"
   - "Отправить отзыв" > "Начать"
   - Ввод описания проблемы

4. **После встречи**:
   - Кнопка "Отправить отзыв" на экране завершения
   - Стандартная форма обратной связи

**Содержимое отчета**:
- Описание проблемы (пользовательский ввод)
- Скриншот (опционально)
- Логи браузера (автоматически)
- Метрики соединения на момент отправки
- Информация об устройстве и браузере

**Обработка отчетов**:
- Отправляются в Google для анализа
- Не включают содержимое звонка (аудио/видео)
- Администратор может отключить загрузку клиентских логов

### FR-QUAL-011: Оценка качества звонка

**Описание**: После завершения звонка система может запрашивать у пользователя оценку качества.

**Механизм оценки**:

1. **Триггеры показа запроса оценки**:
   - Звонок длился более 2 минут
   - Были зафиксированы проблемы с качеством
   - Случайная выборка для сбора статистики

2. **Форма оценки**:
   - Бинарная оценка: "Хорошо" / "Плохо"
   - При оценке "Плохо" - запрос уточнения проблемы:
     - Проблемы со звуком
     - Проблемы с видео
     - Проблемы с соединением
     - Другое

3. **Автоматические данные**:
   - При негативной оценке автоматически отправляются технические метрики
   - Контент звонка не передается

**Использование оценок**:
- Агрегированные данные доступны в MQT
- Используются для улучшения сервиса
- Помогают выявлять систематические проблемы

### FR-QUAL-012: Административные политики качества

**Описание**: Администраторы Workspace могут устанавливать политики качества для всей организации.

**Доступные политики**:

1. **Политика качества исходящего видео**:
   - `Adjust automatically` (по умолчанию) - автоматическая адаптация
   - `Limited video bandwidth` - ограничение до 1 Mbps
   - `Audio only` - видео выключено по умолчанию, пользователь может включить (до 1 Mbps)

2. **Политика качества записи**:
   - Разрешение записи: 720p или 1080p
   - Качество записи экрана: настраиваемое

3. **Политика загрузки логов**:
   - Разрешить/запретить отправку клиентских логов в отчетах о проблемах

4. **Политики для подразделений**:
   - Разные настройки для разных организационных единиц
   - Наследование от родительского подразделения

**Применение политик**:
- Политики применяются при входе пользователя в систему
- Изменения вступают в силу для новых встреч
- Пользователь не может превысить ограничения политики

### FR-QUAL-013: Делегирование доступа к MQT

**Описание**: Супер-администратор может предоставить доступ к Meet Quality Tool пользователям без полных административных прав.

**Процесс делегирования**:

1. **Создание кастомной роли**:
   - Создание роли с правом "Admin quality dashboard access"
   - Без других административных привилегий

2. **Назначение роли**:
   - Назначение роли конкретным пользователям
   - Пользователи получают доступ только к MQT

3. **Ограничения делегированного доступа**:
   - Доступ только по прямой ссылке
   - Нет доступа к Admin Console
   - Только просмотр данных MQT
   - Нет возможности изменять настройки

### FR-QUAL-014: Оптимизация для слабых устройств

**Описание**: Система адаптирует нагрузку для устройств с ограниченными ресурсами.

**Критерии определения слабого устройства**:
- CPU с менее чем 4 ядрами
- RAM менее 4 GB
- Устаревшая версия браузера
- Высокая загрузка CPU (>80%) при базовых операциях

**Адаптации для слабых устройств**:

1. **Автоматические**:
   - Ограничение максимального разрешения до 360p
   - Снижение частоты кадров
   - Отключение визуальных эффектов (blur, backgrounds)
   - Упрощенный рендеринг галереи участников

2. **Рекомендуемые пользователю**:
   - Использование Spotlight view вместо галереи
   - Закрытие лишних вкладок браузера
   - Отключение расширений браузера
   - Снижение разрешения видео вручную

3. **Кодек-оптимизация**:
   - Использование H.264 вместо VP9 на старых устройствах
   - Меньшая нагрузка на CPU за счет аппаратного ускорения

**Мониторинг ресурсов**:
- Постоянный мониторинг CPU usage
- Предупреждение при перегреве (для ноутбуков)
- Рекомендации по снижению нагрузки

### FR-QUAL-015: Интеграция с сетевой инфраструктурой

**Описание**: Система использует сетевые оптимизации для улучшения качества на уровне инфраструктуры.

**Технологии оптимизации**:

1. **Enterprise Content Delivery Network (eCDN)**:
   - Снижение нагрузки на внешний канал
   - Кэширование контента внутри сети организации
   - Особенно эффективно для live-стриминга

2. **Умная маршрутизация**:
   - Выбор оптимального пути до серверов Google
   - Обход перегруженных участков сети
   - Автоматическое переключение при деградации

3. **QoS рекомендации**:
   - Приоритизация UDP трафика (порты 3478, 19302-19309)
   - Резервирование bandwidth для Meet
   - Настройка сетевого оборудования

**Требования к сети**:
- UDP порты 3478, 19302-19309 для аудио/видео
- TCP/UDP 443 для веб-трафика и аутентификации
- При блокировке UDP используется TCP (снижение качества)

## Состояния и статусы

### Состояния качества соединения (ConnectionQuality)

```
[Initializing] --> [Connecting] --> [Good] <--> [Degraded] <--> [Poor] --> [Disconnected]
                                      ^            |              |
                                      |            v              v
                                      +-------- [Recovering] <----+
```

| Состояние | Описание | Триггер перехода |
|-----------|----------|------------------|
| Initializing | Инициализация соединения | Пользователь присоединяется к встрече |
| Connecting | Установка соединения | Начало WebRTC handshake |
| Good | Отличное качество | RTT <50ms, Loss <1%, Bandwidth >2.6 Mbps |
| Degraded | Удовлетворительное качество | RTT 50-150ms, Loss 1-5%, Bandwidth 1-2.6 Mbps |
| Poor | Плохое качество | RTT >150ms, Loss >5%, Bandwidth <1 Mbps |
| Recovering | Восстановление качества | Улучшение метрик в течение 10 секунд |
| Disconnected | Соединение потеряно | Полная потеря связи |

### Состояния видео режима (VideoMode)

```
[HD_1080p] --> [HD_720p] --> [SD_360p] --> [Low_240p] --> [Audio_Only]
    ^             ^             ^              ^               |
    |             |             |              |               |
    +-------------+-------------+--------------+---------------+
                    (при улучшении условий)
```

| Состояние | Условия активации |
|-----------|-------------------|
| HD_1080p | Bandwidth >3.2 Mbps, 1080p камера, мощный CPU, 2 участника |
| HD_720p | Bandwidth 2.6-3.2 Mbps, 4+ ядра CPU |
| SD_360p | Bandwidth 1-2.6 Mbps |
| Low_240p | Bandwidth 0.5-1 Mbps |
| Audio_Only | Bandwidth <0.5 Mbps или ручное переключение |

### Статусы индикатора качества (QualityIndicator)

| Статус | Цвет | Значение | Действие системы |
|--------|------|----------|------------------|
| Excellent | Зеленый | Все метрики в норме | - |
| Warning | Желтый | Одна или более метрик в зоне предупреждения | Показ рекомендаций |
| Critical | Красный | Критические проблемы с качеством | Показ красной точки, рекомендации |

## Ограничения и лимиты

### Сетевые требования

| Параметр | Минимум | Рекомендуемое | Оптимальное |
|----------|---------|---------------|-------------|
| Bandwidth (входящий) | 1 Mbps | 2.6 Mbps | 3.2+ Mbps |
| Bandwidth (исходящий) | 1 Mbps | 2.6 Mbps | 3.2+ Mbps |
| Latency (RTT) | <100 ms | <50 ms | <30 ms |
| Packet Loss | <5% | <1% | <0.1% |
| Jitter | <100 ms | <30 ms | <10 ms |

### Системные требования

| Параметр | Минимум | Рекомендуемое |
|----------|---------|---------------|
| RAM | 4 GB | 8 GB |
| CPU | 2 ядра | 4+ ядра (для HD) |
| CPU для 1080p | 4+ ядра + достаточная мощность | - |

### Лимиты хранения данных

| Данные | Срок хранения |
|--------|---------------|
| Метрики в MQT | 30 дней |
| Журналы активности | 6 месяцев (по умолчанию) |
| Результаты диагностических тестов | 10 последних тестов |

### Лимиты частоты

| Событие | Ограничение |
|---------|-------------|
| Показ красной точки индикатора | 1 раз в день для одной проблемы |
| Длительность показа красной точки | 5 минут |
| Запрос оценки после звонка | Не для каждого звонка (алгоритмическая выборка) |
| Обновление индикатора качества | Каждые 5 секунд |

### Ограничения разрешений

| Разрешение | Условия доступности |
|------------|---------------------|
| 1080p (отправка) | Камера 1080p + мощный CPU + 2 участника |
| 1080p (прием) | Достаточный bandwidth |
| 720p | Четырехъядерный CPU или выше |
| При административном ограничении | Не выше 1 Mbps |

## Интеграции с другими модулями

### Модуль видеоконференций (Core Meeting)
- **Получает**: Информацию о текущих участниках и их устройствах
- **Предоставляет**: Данные о качестве для отображения индикаторов
- **Взаимодействие**: При критическом ухудшении качества может отключить видео участника

### Модуль записи (Recording)
- **Получает**: Настройки политики качества записи
- **Предоставляет**: Метрики качества записанного контента
- **Взаимодействие**: Качество записи зависит от административных политик

### Модуль аутентификации (Auth)
- **Получает**: Идентификацию пользователя для логирования
- **Предоставляет**: -
- **Взаимодействие**: Метрики привязываются к идентификатору пользователя

### Модуль административного управления (Admin)
- **Получает**: Политики качества для организации
- **Предоставляет**: Данные для MQT, журналы активности
- **Взаимодействие**: Администратор настраивает политики, просматривает статистику

### Модуль уведомлений (Notifications)
- **Получает**: -
- **Предоставляет**: Триггеры для показа уведомлений о качестве
- **Взаимодействие**: Показ рекомендаций и предупреждений пользователю

### Модуль устройств Meet Hardware
- **Получает**: Команды на запуск диагностических тестов
- **Предоставляет**: Результаты тестов, метрики устройства
- **Взаимодействие**: Администратор может удаленно диагностировать устройства

### Модуль трансляций (Live Streaming)
- **Получает**: Параметры качества трансляции
- **Предоставляет**: Метрики качества для зрителей
- **Взаимодействие**: Ultra-low latency streaming с поддержкой до 100,000 зрителей

### Модуль eCDN
- **Получает**: Запросы на оптимизацию доставки контента
- **Предоставляет**: Информацию о локальном кэшировании
- **Взаимодействие**: Снижение нагрузки на внешний канал организации
