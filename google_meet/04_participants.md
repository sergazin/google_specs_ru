# Модуль "Управление участниками" (Participants Management)

## 1. Описание модуля

Модуль "Управление участниками" отвечает за полный жизненный цикл участия пользователей во встречах Google Meet. Модуль охватывает процессы присоединения к встрече, контроль доступа через зал ожидания, управление ролями и правами участников, модерацию, интерактивные функции коммуникации (поднятие руки, реакции) и распределение участников по комнатам обсуждения.

### 1.1. Основные функции модуля

- Управление процессом присоединения к встрече
- Контроль доступа через зал ожидания (Waiting Room)
- Система ролей и разграничение прав участников
- Модерация участников (отключение микрофона/камеры, удаление)
- Интерактивные функции (поднятие руки, реакции)
- Закрепление участников на экране
- Управление комнатами обсуждения (Breakout Rooms)
- Контроль лимитов участников

---

## 2. Роли пользователей

### 2.1. Организатор встречи (Meeting Organizer)

Пользователь, создавший встречу через Google Calendar или напрямую в Google Meet.

**Полномочия:**
- Все права хоста встречи по умолчанию
- Настройка параметров доступа до начала встречи
- Предварительное назначение участников в комнаты обсуждения
- Изменение настроек встречи в Google Calendar

### 2.2. Хост встречи (Meeting Host)

Основной модератор активной встречи. По умолчанию им становится организатор.

**Полномочия:**
- Включение/отключение Host Management
- Допуск участников из зала ожидания
- Назначение и снятие со-хостов (до 25 человек)
- Отключение микрофона любого участника
- Включение Audio Lock / Video Lock для всех участников
- Удаление участников из встречи
- Блокировка участников от повторного входа
- Создание и управление комнатами обсуждения
- Закрепление участников на экране для всех
- Управление настройками чата и презентации
- Отключение реакций для всех участников
- Опускание поднятых рук участников
- Завершение встречи для всех участников

### 2.3. Со-хост (Co-Host)

Участник, которому хост делегировал часть полномочий модерации.

**Полномочия:**
- Допуск участников из зала ожидания
- Отключение микрофона участников
- Управление Audio Lock / Video Lock
- Удаление участников из встречи
- Закрепление участников на экране для всех (до 3 закреплений)
- Участие в управлении комнатами обсуждения
- Опускание поднятых рук участников

**Ограничения:**
- Не может назначать других со-хостов
- Не может изменять настройки Host Management
- Некоторые настройки комнат обсуждения доступны только основному хосту

### 2.4. Участник (Participant)

Обычный пользователь, присоединившийся к встрече.

**Полномочия:**
- Управление собственным микрофоном и камерой (если не заблокировано)
- Поднятие/опускание руки
- Отправка реакций (если разрешено)
- Закрепление участников на своем экране (до 6 закреплений)
- Участие в чате (если разрешено)
- Демонстрация экрана (если разрешено)

**Ограничения:**
- Не может отключать микрофон/камеру других участников
- Не может удалять других участников
- Не может управлять допуском в зал ожидания

## 3. Функциональные требования

### 3.1. Присоединение к встрече

#### FR-PART-001: Инициация подключения к встрече

**Описание:** Система должна поддерживать несколько способов присоединения к встрече.

**Способы присоединения:**
1. **По ссылке** - переход по URL вида `meet.google.com/xxx-xxxx-xxx`
2. **Из Google Calendar** - нажатие кнопки "Присоединиться" в событии календаря
3. **По коду встречи** - ввод кода в интерфейсе Google Meet
4. **По телефону** - набор номера и ввод PIN-кода
5. **Из Gmail** - через виджет встречи в интерфейсе почты
6. **Через приглашение** - по ссылке из email-приглашения

**Бизнес-правила:**
- Пользователь должен быть аутентифицирован в Google Account (для большинства функций)
- Анонимные пользователи могут подключаться с ограниченными правами (если разрешено настройками)
- До подключения пользователь видит экран предпросмотра с настройками камеры/микрофона

---

#### FR-PART-002: Уровни доступа к встрече

**Описание:** Система должна поддерживать три уровня контроля доступа к встрече.

**Уровни доступа:**

| Уровень | Описание | Поведение |
|---------|----------|-----------|
| **Open** | Открытый доступ | Любой пользователь со ссылкой входит без подтверждения |
| **Trusted** | Доверенный доступ | Пользователи из домена организатора и приглашенные через Calendar входят свободно. Остальные должны "постучать" |
| **Restricted** | Ограниченный доступ | Только приглашенные через Calendar или добавленные хостом во время встречи входят свободно. Все остальные должны "постучать" |

**Бизнес-правила:**
- Уровень по умолчанию: Trusted
- Уровень Restricted недоступен для личных аккаунтов (только Workspace)
- Изменение уровня доступа возможно организатором в Calendar или хостом во время встречи
- При миграции со старых настроек Quick Access: On = Trusted, Off = Restricted

---

#### FR-PART-003: Механизм "Стука в дверь" (Knock to Join)

**Описание:** Система должна обеспечивать процесс запроса на вход для участников, не имеющих автоматического доступа.

**Процесс:**
1. Участник нажимает "Попросить присоединиться" (Ask to Join)
2. Запрос отображается у хоста и со-хостов
3. Хост/со-хост принимает решение: допустить или отклонить
4. Участник получает уведомление о результате

**Бизнес-правила:**
- Запрос содержит имя и email (если доступен) запрашивающего
- Хост видит все ожидающие запросы в списке
- Запросы обрабатываются индивидуально или массово ("Допустить всех")
- При отклонении участник может повторить запрос
- Телефонные участники также должны "стучать" при соответствующих настройках

---

#### FR-PART-004: Контроль времени начала встречи

**Описание:** Система должна контролировать, могут ли участники присоединиться до хоста.

**Режимы:**
- **Guests can join before you** (включено): Участники могут входить до хоста
- **Guests cannot join before you** (выключено): Участники ожидают присоединения хоста

**Бизнес-правила:**
- Настройка устанавливается организатором в Google Calendar
- Если участники не могут войти до хоста, они видят экран ожидания
- После присоединения хоста все ожидающие уведомляются о возможности входа

---

### 3.2. Зал ожидания (Waiting Room)

#### FR-PART-005: Активация зала ожидания

**Описание:** Система должна позволять хосту создавать виртуальную комнату ожидания для участников.

**Активация:**
- При создании события в Google Calendar
- Во время активной встречи через Host Controls

**Бизнес-правила:**
- Зал ожидания доступен только для аккаунтов Google Workspace
- При активации все новые участники попадают в зал ожидания
- Участники, уже находящиеся в основной встрече, не затрагиваются

---

#### FR-PART-006: Управление участниками в зале ожидания

**Описание:** Система должна предоставлять хосту инструменты управления участниками в зале ожидания.

**Действия хоста:**
- Просмотр списка ожидающих участников
- Допуск отдельного участника
- Допуск всех участников одновременно
- Отклонение запроса на вход
- Отправка односторонних сообщений в зал ожидания

**Бизнес-правила:**
- Участники в зале ожидания не слышат и не видят основную встречу
- Хост может отправлять текстовые сообщения участникам в зале ожидания
- Участники не могут отвечать на сообщения хоста из зала ожидания
- При допуске участник мгновенно переходит в основную комнату

---

#### FR-PART-007: Перемещение участников в зал ожидания

**Описание:** Система должна позволять хосту перемещать уже присутствующих участников обратно в зал ожидания.

**Бизнес-правила:**
- Хост может переместить любого участника (кроме других хостов/со-хостов) в зал ожидания
- Перемещенный участник сохраняет свои настройки (имя, аватар)
- Для возврата в основную комнату требуется повторный допуск хоста
- Участник уведомляется о перемещении в зал ожидания

---

#### FR-PART-008: Автоматический допуск из зала ожидания

**Описание:** Система должна поддерживать опцию автоматического допуска участников при входе хоста.

**Настройка:** "Bring in automatically"

**Бизнес-правила:**
- При включении: все участники из зала ожидания автоматически допускаются при входе хоста
- При выключении: хост вручную допускает каждого участника
- Настройка устанавливается при создании встречи

---

### 3.3. Модерация участников

#### FR-PART-009: Отключение микрофона участника

**Описание:** Система должна позволять хосту/со-хосту отключать микрофон отдельного участника.

**Механизм:**
1. Хост выбирает участника в списке или на видео-плитке
2. Нажимает "Mute"
3. Микрофон участника отключается
4. Участник получает уведомление

**Бизнес-правила:**
- По соображениям приватности хост НЕ МОЖЕТ включить микрофон участника
- После отключения участник сам решает, включать ли микрофон обратно
- При включенном Audio Lock участник не сможет включить микрофон
- Уведомление содержит информацию о том, кто отключил микрофон

---

#### FR-PART-010: Массовое отключение микрофонов

**Описание:** Система должна позволять хосту отключить микрофоны всех участников одновременно.

**Функция:** "Mute All"

**Бизнес-правила:**
- Требуется включенный Host Management
- Доступно только на десктопе и iOS
- Не влияет на микрофон самого хоста и со-хостов
- Все участники получают уведомление об отключении

---

#### FR-PART-011: Блокировка аудио (Audio Lock)

**Описание:** Система должна позволять хосту заблокировать возможность использования микрофона для всех участников.

**Механизм:**
1. Хост включает Audio Lock в Host Controls
2. Все микрофоны участников отключаются
3. Участники не могут включить свои микрофоны до снятия блокировки

**Бизнес-правила:**
- Audio Lock не применяется к хосту и со-хостам
- Настройка доступна только с десктопа или iOS
- Блокировка применяется ко всем устройствам участников
- При включении блокировки мобильные участники со старыми версиями приложения могут быть отключены от встречи
- Блокировка распространяется на комнаты обсуждения, созданные после её включения

---

#### FR-PART-012: Блокировка видео (Video Lock)

**Описание:** Система должна позволять хосту заблокировать возможность использования камеры для всех участников.

**Механизм:**
1. Хост включает Video Lock в Host Controls
2. Все камеры участников отключаются
3. Участники не могут включить свои камеры до снятия блокировки

**Бизнес-правила:**
- Аналогичны правилам Audio Lock (FR-PART-011)
- Audio Lock и Video Lock могут использоваться независимо друг от друга

---

#### FR-PART-013: Удаление участника из встречи

**Описание:** Система должна позволять хосту/со-хосту удалить участника из активной встречи.

**Опции при удалении:**
- **Remove** - простое удаление из встречи
- **Remove + Abuse Report** - удаление с отправкой отчета о нарушении
- **Remove + Block** - удаление с блокировкой повторного входа

**Бизнес-правила:**
- Удаленный участник мгновенно отключается от встречи
- При простом удалении участник может повторно присоединиться
- При блокировке участник не может войти в данную встречу
- Блокировка действует только для текущей встречи (и параллельных с тем же кодом)
- Для разблокировки требуется ручное приглашение хостом
- При включенном Host Management только хост и со-хосты могут удалять
- При выключенном Host Management любой участник из домена организатора может удалять

---

#### FR-PART-014: Завершение встречи для всех

**Описание:** Система должна позволять хосту завершить встречу для всех участников одновременно.

**Функция:** "End meeting for all"

**Бизнес-правила:**
- Требуется включенный Host Management
- Все участники автоматически отключаются
- После завершения ссылка на встречу остается доступной
- Участники не могут присоединиться до перезапуска встречи хостом
- Встреча автоматически перезапускается при повторном входе хоста
- Рекомендуется создавать новую встречу для новой группы участников

---

### 3.4. Управление ролями

#### FR-PART-015: Назначение со-хоста

**Описание:** Система должна позволять хосту делегировать права модерации другим участникам.

**Механизм:**
1. Хост открывает панель участников
2. Выбирает участника для назначения со-хостом
3. Подтверждает назначение
4. Участник получает уведомление о новых правах

**Бизнес-правила:**
- Максимум 25 со-хостов на встречу
- Только основной хост может назначать со-хостов
- Со-хост не может назначать других со-хостов
- Со-хост может быть снят хостом в любой момент
- Права со-хоста действуют только для текущей сессии встречи

---

#### FR-PART-016: Передача роли хоста

**Описание:** Система должна поддерживать механизм передачи основных прав хоста.

**Бизнес-правила:**
- Хост может передать свои права другому участнику
- После передачи исходный хост становится обычным участником
- Новый хост получает все полномочия модерации
- При выходе хоста из встречи права могут быть переданы автоматически (в зависимости от настроек)

---

#### FR-PART-017: Определение прав модерации по типу аккаунта

**Описание:** Права на модерацию определяются типом аккаунта организатора встречи.

**Матрица прав:**

| Тип аккаунта | Кто может мутить | Кто может удалять |
|--------------|------------------|-------------------|
| Личный аккаунт | Только модератор | Только модератор |
| Google Workspace | Участники из домена организатора | Хост/со-хосты (при Host Management) |
| Education | Создатель встречи, владелец события Calendar | Создатель встречи |

---

### 3.5. Поднятие руки (Raise Hand)

#### FR-PART-018: Поднятие руки участником

**Описание:** Система должна позволять участникам сигнализировать о желании высказаться.

**Механизм:**
1. Участник нажимает кнопку "Raise Hand"
2. Иконка руки появляется на видео-плитке участника
3. Все участники и хосты получают уведомление
4. Участник перемещается в верхнюю часть сетки

**Бизнес-правила:**
- Функция доступна на всех платформах (десктоп, Android, iOS)
- Минимальные требования: Android 6.0+, iOS 12.0+
- Поднятые руки отображаются в порядке времени поднятия
- Участники с поднятыми руками группируются в начале списка

---

#### FR-PART-019: Распознавание жеста поднятия руки

**Описание:** Система должна поддерживать автоматическое распознавание физического жеста поднятия руки.

**Механизм:**
1. Участник включает опцию "Hand Raise Gesture" в настройках реакций
2. Камера отслеживает жест поднятия руки
3. При удержании руки несколько секунд система фиксирует поднятие

**Бизнес-правила:**
- Функция отключена по умолчанию
- Для распознавания рука должна быть видима и отведена от лица/тела
- Система автоматически отключает распознавание для активного спикера
- Это предотвращает ложные срабатывания при жестикуляции во время речи

---

#### FR-PART-020: Опускание рук модератором

**Описание:** Система должна позволять хосту/со-хосту опускать руки участников.

**Функции:**
- Опускание руки отдельного участника
- Массовое опускание рук ("Lower All")

**Бизнес-правила:**
- Участник уведомляется об опускании руки
- После опускания участник может снова поднять руку
- Хост видит полную очередь поднятых рук с временными метками

---

### 3.6. Реакции (Reactions)

#### FR-PART-021: Отправка реакций

**Описание:** Система должна позволять участникам выражать эмоции через эмодзи-реакции.

**Механизм:**
1. Участник открывает панель реакций
2. Выбирает эмодзи из доступного набора
3. Реакция отображается на экране у всех участников

**Отображение реакций:**
- Временный значок в левом верхнем углу плитки отправителя
- Анимированный эмодзи, всплывающий снизу слева экрана
- При одновременных одинаковых реакциях они объединяются в увеличивающийся "шар"

**Бизнес-правила:**
- Доступен полный набор эмодзи (около 4000 символов)
- Реакции являются "недеструктивным" способом коммуникации
- Участник может настроить оттенок кожи для эмодзи

---

#### FR-PART-022: Настройки отображения реакций

**Описание:** Система должна позволять участникам настраивать отображение реакций.

**Настройки:**
- Показывать/скрывать реакции других участников
- Включить/выключить анимацию реакций
- Включить/выключить звуковое сопровождение реакций

**Бизнес-правила:**
- Настройки индивидуальны для каждого участника
- Настройки не влияют на возможность отправки собственных реакций

---

#### FR-PART-023: Отключение реакций хостом

**Описание:** Система должна позволять хосту запретить отправку реакций участниками.

**Механизм:**
1. Хост включает Host Management
2. В настройках отключает опцию "Send reactions"
3. Кнопка реакций становится недоступной для участников

**Бизнес-правила:**
- Настройка не влияет на способность хоста/со-хостов отправлять реакции
- При выключении все участники теряют возможность отправки реакций

---

#### FR-PART-024: Жестовые реакции Apple

**Описание:** На устройствах Apple с iOS 17+ и macOS Sonoma система поддерживает распознавание жестов для отправки реакций.

**Бизнес-правила:**
- Функция включена по умолчанию на поддерживаемых устройствах
- Распознаются стандартные жесты Apple (большой палец вверх, сердце руками и др.)
- Участник может отключить функцию в настройках устройства

---

### 3.7. Закрепление участников (Pinning)

#### FR-PART-025: Персональное закрепление

**Описание:** Система должна позволять участникам закреплять видео-плитки других участников на своем экране.

**Механизм:**
1. Участник наводит курсор на плитку нужного пользователя
2. Нажимает "Pin" и выбирает "For myself only"
3. Закрепленная плитка фиксируется на экране участника

**Бизнес-правила:**
- Максимум 6 персональных закреплений на участника
- Закрепление видит только сам участник
- Закрепленный участник НЕ получает уведомлений
- Можно закреплять как видео участников, так и презентации
- Недоступно в режиме Companion Mode

---

#### FR-PART-026: Модерируемое закрепление

**Описание:** Система должна позволять хосту/со-хосту закреплять плитки для всех участников.

**Функция:** "Pin for everyone" (Moderated Pin)

**Механизм:**
1. Хост выбирает плитку участника
2. Нажимает "Pin" и выбирает "For everyone"
3. Плитка закрепляется на экранах всех участников

**Бизнес-правила:**
- Максимум 3 модерируемых закрепления
- Только хост и со-хосты могут создавать модерируемые закрепления
- Модерируемые закрепления доступны только с десктопа/ноутбука
- На мобильных устройствах (Android, iOS) модерируемые закрепления НЕ отображаются
- При выходе и повторном входе закрепленного участника требуется повторное закрепление

---

#### FR-PART-027: Spotlight (Прожектор)

**Описание:** Система должна поддерживать режим выделения участника для всех.

**Отличие от Pin:**
- Spotlight виден всем участникам без исключения
- Spotlight применяется к одному участнику
- Отображается как полноэкранный режим для выбранного участника

**Бизнес-правила:**
- Используется для выделения активного спикера или презентатора
- Хост может включать/выключать Spotlight

---

### 3.8. Комнаты обсуждения (Breakout Rooms)

#### FR-PART-028: Создание комнат обсуждения

**Описание:** Система должна позволять хосту создавать отдельные комнаты для групповых обсуждений.

**Способы создания:**
- Заранее через Google Calendar при создании события
- Во время активной встречи через панель Activities

**Бизнес-правила:**
- Максимум 100 комнат обсуждения на встречу
- Доступно только для аккаунтов Google Workspace
- Создание и запуск возможны только с десктопа/ноутбука
- Только хост может создавать комнаты обсуждения

---

#### FR-PART-029: Распределение участников по комнатам

**Описание:** Система должна поддерживать несколько способов распределения участников.

**Способы:**
- **Автоматическое** - система случайным образом распределяет участников
- **Ручное** - хост вручную назначает каждого участника
- **Drag-and-drop** - хост перетаскивает участников между комнатами
- **Shuffle** - случайное перемешивание между комнатами

**Бизнес-правила:**
- Хост может перемещать участников между комнатами в любой момент
- Изменения применяются после сохранения
- Предварительное распределение сохраняется в событии Calendar

---

#### FR-PART-030: Управление комнатами обсуждения во время сессии

**Описание:** Система должна предоставлять инструменты управления активными комнатами.

**Возможности хоста:**
- Переход между любыми комнатами
- Перемещение участников между комнатами
- Отправка сообщений во все комнаты
- Закрытие отдельных комнат
- Установка таймера для комнат

**Бизнес-правила:**
- За 30 секунд до окончания таймера участники видят обратный отсчет
- Блокировки Audio/Video Lock, установленные в основной комнате, применяются к новым комнатам обсуждения
- Изменения блокировок в отдельной комнате не влияют на другие комнаты
- Со-хосты могут управлять комнатами с ограничениями

---

#### FR-PART-031: Возврат участников в основную комнату

**Описание:** Система должна обеспечивать механизм завершения сессии обсуждения.

**Механизмы:**
- Хост вручную закрывает все комнаты
- Истекает установленный таймер
- Хост завершает встречу для всех

**Бизнес-правила:**
- При закрытии комнаты все участники возвращаются в основную
- Участники получают предупреждение перед возвратом
- Содержимое чата комнаты обсуждения не переносится в основную комнату

## 5. Состояния и статусы

### 5.1. Состояния участника в контексте встречи

```
[НЕ В ВСТРЕЧЕ]
    │
    ├─> [ЗАПРАШИВАЕТ ВХОД] ──> [ОТКЛОНЕН] ──> [НЕ В ВСТРЕЧЕ]
    │         │
    │         v
    ├─> [В ЗАЛЕ ОЖИДАНИЯ] ──> [НЕ В ВСТРЕЧЕ] (вышел)
    │         │
    │         v
    └─> [ВО ВСТРЕЧЕ] ─────────> [НЕ В ВСТРЕЧЕ] (вышел/удален)
          │     ^
          v     │
    [В КОМНАТЕ ОБСУЖДЕНИЯ] ───┘
```

**Описание состояний:**

| Состояние | Описание |
|-----------|----------|
| НЕ В ВСТРЕЧЕ | Пользователь не подключен к встрече |
| ЗАПРАШИВАЕТ ВХОД | Пользователь "постучал" и ожидает решения хоста |
| В ЗАЛЕ ОЖИДАНИЯ | Пользователь допущен, но находится в зале ожидания |
| ВО ВСТРЕЧЕ | Пользователь активный участник основной комнаты |
| В КОМНАТЕ ОБСУЖДЕНИЯ | Пользователь находится в одной из комнат обсуждения |
| ОТКЛОНЕН | Запрос на вход отклонен хостом |

### 5.2. Состояния роли участника

```
[PARTICIPANT] ──> [CO_HOST] ──> [PARTICIPANT]
                      │
[HOST] ───────────────┘
   │
   v
[PARTICIPANT] (при передаче роли хоста)
```

### 5.3. Состояния аудио/видео

```
[ВКЛЮЧЕНО] <──> [ВЫКЛЮЧЕНО_УЧАСТНИКОМ]
    │                    │
    v                    v
[ЗАБЛОКИРОВАНО_ХОСТОМ] ──> [РАЗБЛОКИРОВАНО] ──> [ВЫКЛЮЧЕНО_УЧАСТНИКОМ]
```

### 5.4. Состояния поднятой руки

```
[ОПУЩЕНА] <──> [ПОДНЯТА]
    ^              │
    │              v
    └── [ОПУЩЕНА_МОДЕРАТОРОМ]
```
