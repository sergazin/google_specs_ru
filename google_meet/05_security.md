# Модуль "Безопасность и модерация" - Google Meet

## 1. Описание модуля

Модуль "Безопасность и модерация" обеспечивает комплексную защиту видеоконференций в Google Meet. Модуль отвечает за шифрование данных, контроль доступа к встречам, управление участниками, предотвращение нежелательного поведения, соответствие нормативным требованиям и аудит всех действий в системе.

### 1.1 Ключевые функции модуля

- Многоуровневое шифрование данных (в транзите, в покое, end-to-end)
- Контроль доступа к встречам с гибкими политиками
- Управление залом ожидания (waiting room/lobby)
- Блокировка встреч и участников
- Модерация и управление хостами
- Отчеты о нарушениях и злоупотреблениях
- Корпоративные политики безопасности
- Аудит и логирование всех событий
- Соответствие регуляторным требованиям (HIPAA, GDPR, SOC)

## 3. Функциональные требования

### 3.1 Шифрование данных

#### FR-SEC-001: Шифрование в транзите

**Описание:** Система должна обеспечивать шифрование всех данных при передаче между клиентом и серверами Google.

**Требования:**
- Все медиаданные (видео, аудио) шифруются по протоколу DTLS (Datagram Transport Layer Security)
- Потоки реального времени защищены протоколом SRTP (Secure Real-time Transport Protocol)
- Соответствие стандартам безопасности IETF
- Шифрование применяется автоматически без возможности отключения пользователем
- Минимальная длина ключа шифрования: 128 бит

**Бизнес-правила:**
- BR-SEC-001-01: Шифрование в транзите обязательно для всех типов подписки
- BR-SEC-001-02: При невозможности установить зашифрованное соединение — подключение отклоняется

---

#### FR-SEC-002: Шифрование в покое

**Описание:** Система должна шифровать все сохраненные данные встреч.

**Требования:**
- Записи встреч в Google Drive шифруются по стандарту AES-256
- Транскрипции и чаты шифруются при хранении
- Метаданные встреч шифруются
- Ключи шифрования управляются инфраструктурой Google Cloud

**Бизнес-правила:**
- BR-SEC-002-01: Шифрование в покое применяется автоматически
- BR-SEC-002-02: Срок хранения записей по умолчанию: 3 месяца (настраивается администратором)

---

#### FR-SEC-003: Клиентское end-to-end шифрование (CSE)

**Описание:** Система должна поддерживать дополнительный уровень шифрования, при котором даже Google не имеет доступа к содержимому.

**Требования:**
- Медиаконтент шифруется на стороне браузера клиента
- Ключи шифрования контролируются организацией клиента
- Только авторизованные участники могут расшифровать контент
- Серверы Google не имеют доступа к расшифрованным данным

**Доступность по тарифам:**
| Тариф | Поддержка CSE |
|-------|---------------|
| Бесплатный | Нет |
| Business Starter | Нет |
| Business Standard | Нет |
| Business Plus | Нет |
| Enterprise Standard | Да |
| Enterprise Plus | Да |
| Education Standard | Да |
| Education Plus | Да |

**Бизнес-правила:**
- BR-SEC-003-01: CSE должен быть активирован администратором
- BR-SEC-003-02: При использовании CSE некоторые функции недоступны (автоматическая транскрипция)
- BR-SEC-003-03: CSE доступен для Google Meet Hardware с июля 2025

---

### 3.2 Контроль доступа к встречам

#### FR-SEC-004: Уровни доступа к встрече

**Описание:** Система должна поддерживать три уровня доступа к встрече.

**Уровни доступа:**

| Уровень | Код | Описание |
|---------|-----|----------|
| Открытый | `OPEN` | Любой с ссылкой может присоединиться без подтверждения |
| Доверенный | `TRUSTED` | Участники домена и приглашенные через Calendar — без подтверждения, остальные должны "постучать" |
| Ограниченный | `RESTRICTED` | Только приглашенные через Calendar или изнутри встречи, все остальные должны "постучать" |

**Бизнес-правила:**
- BR-SEC-004-01: Уровень по умолчанию: `TRUSTED`
- BR-SEC-004-02: Уровень `RESTRICTED` недоступен для бесплатных пользователей
- BR-SEC-004-03: Администратор может принудительно установить минимальный уровень для организации

---

#### FR-SEC-005: Зал ожидания (Waiting Room / Lobby)

**Описание:** Система должна обеспечивать механизм предварительного одобрения участников перед входом во встречу.

**Требования:**
- Участники, которым требуется одобрение, помещаются в зал ожидания
- Хост и со-хосты получают уведомление о новых запросах
- Возможность одобрить/отклонить отдельного участника
- Возможность одобрить/отклонить всех ожидающих одновременно
- Хост может отправлять односторонние сообщения в зал ожидания

**Статусы участника в зале ожидания:**

```
[REQUESTING] --> [ADMITTED] --> [IN_MEETING]
      |
      +--> [DENIED] --> [BLOCKED] (после 2 отказов)
```

**Бизнес-правила:**
- BR-SEC-005-01: После двух отклонений запроса участник автоматически блокируется от повторных попыток
- BR-SEC-005-02: Анонимные пользователи и сторонние боты автоматически отклоняются без действий хоста
- BR-SEC-005-03: Опция "Впустить автоматически" позволяет автоматически принимать всех при входе хоста

---

#### FR-SEC-006: Требование присутствия хоста

**Описание:** Система должна поддерживать режим, при котором встреча не начинается без присутствия хоста.

**Требования:**
- Опция "Хост должен присоединиться первым" в настройках встречи
- Участники не могут войти до прихода хоста
- При выходе хоста встреча может продолжаться (если есть со-хост)

**Бизнес-правила:**
- BR-SEC-006-01: По умолчанию опция отключена
- BR-SEC-006-02: Администратор может сделать опцию обязательной для организации

---

#### FR-SEC-007: Временные ограничения доступа

**Описание:** Система должна применять временные ограничения для входа во встречу.

**Требования:**
- Внешние участники могут войти не ранее чем за 15 минут до начала
- Телефонные участники могут подключиться не ранее чем за 15 минут до начала
- PIN-код для телефонного подключения действителен только во время запланированной встречи

**Бизнес-правила:**
- BR-SEC-007-01: Участники из календарного приглашения могут входить раньше
- BR-SEC-007-02: Хост и со-хосты не имеют временных ограничений

---

#### FR-SEC-008: Безопасность кода встречи

**Описание:** Система должна генерировать криптографически стойкие коды встреч.

**Требования:**
- Код встречи: 10 символов
- Алфавит: 25 символов (исключая легко путаемые символы)
- Случайная генерация для защиты от перебора
- Код можно полностью сменить для существующей встречи

**Бизнес-правила:**
- BR-SEC-008-01: При смене кода также меняется телефонный PIN
- BR-SEC-008-02: Рекомендуется ротация кодов для регулярных встреч

---

### 3.3 Блокировка встречи и участников

#### FR-SEC-009: Блокировка встречи

**Описание:** Система должна позволять заблокировать встречу для предотвращения входа новых участников.

**Требования:**
- Хост может включить режим "Lock Meeting" в любой момент
- В заблокированном режиме никто не может присоединиться
- Режим можно отключить в любой момент
- Текущие участники остаются во встрече

**Бизнес-правила:**
- BR-SEC-009-01: Блокировка не влияет на участников, уже находящихся во встрече
- BR-SEC-009-02: При блокировке "стук" (knock) отключается полностью

---

#### FR-SEC-010: Удаление участника из встречи

**Описание:** Система должна позволять хосту удалять участников из встречи.

**Требования:**
- Хост/со-хост может удалить любого участника
- Удаленный участник получает уведомление
- Возможность поиска участника по имени для быстрого удаления
- История удалений сохраняется в логах

**Бизнес-правила:**
- BR-SEC-010-01: Удаленный участник не может повторно присоединиться без повторного приглашения хостом
- BR-SEC-010-02: Удаление автоматически прекращает все активности участника (демонстрация экрана, чат)

---

#### FR-SEC-011: Блокировка участника

**Описание:** Система должна позволять блокировать конкретных участников.

**Требования:**
- Опция "Block" при удалении участника
- Заблокированный участник не может "постучать" повторно
- Блокировка действует до конца текущей встречи

**Бизнес-правила:**
- BR-SEC-011-01: Блокировка не распространяется на другие встречи хоста
- BR-SEC-011-02: Заблокированный пользователь не получает уведомления о блокировке

---

### 3.4 Модерация встречи

#### FR-SEC-012: Управление хостом (Host Management)

**Описание:** Система должна предоставлять централизованное управление функциями безопасности встречи.

**Требования:**
- Панель "Host controls" для управления всеми настройками
- Возможность включить/отключить Host Management
- При включенном Host Management доступны расширенные контроли

**Бизнес-правила:**
- BR-SEC-012-01: Host Management отключен по умолчанию
- BR-SEC-012-02: Host Management доступен для всех тарифов Google Workspace

---

#### FR-SEC-013: Управление демонстрацией экрана

**Описание:** Система должна позволять ограничивать демонстрацию экрана.

**Требования:**
- Хост может запретить участникам демонстрацию экрана
- Настройка применяется ко всем участникам кроме хостов
- Можно изменить в любой момент встречи

**Статусы настройки:**
| Значение | Описание |
|----------|----------|
| `EVERYONE` | Все участники могут демонстрировать экран |
| `HOSTS_ONLY` | Только хосты и со-хосты могут демонстрировать |

**Бизнес-правила:**
- BR-SEC-013-01: По умолчанию: `EVERYONE`
- BR-SEC-013-02: При отключении демонстрации активная демонстрация участника прерывается

---

#### FR-SEC-014: Управление чатом

**Описание:** Система должна позволять ограничивать отправку сообщений в чат.

**Требования:**
- Хост может запретить участникам отправку сообщений
- Чат может быть полностью отключен для всех кроме хостов

**Бизнес-правила:**
- BR-SEC-014-01: По умолчанию чат включен для всех
- BR-SEC-014-02: История чата сохраняется даже при отключении чата

---

#### FR-SEC-015: Управление микрофоном участников

**Описание:** Система должна позволять хосту управлять микрофонами участников.

**Требования:**
- Хост может заглушить (mute) любого участника
- Хост может заглушить всех участников одновременно
- Участник может снять заглушку самостоятельно (если не заблокировано)
- Опция "Lock audio" предотвращает включение микрофона участниками

**Бизнес-правила:**
- BR-SEC-015-01: При блокировке аудио только хост может разрешить участнику говорить
- BR-SEC-015-02: Заглушение не влияет на системные уведомления

---

#### FR-SEC-016: Управление видео участников

**Описание:** Система должна позволять хосту управлять видеопотоками участников.

**Требования:**
- Хост может отключить видео участника
- Опция "Lock video" предотвращает включение камеры участниками
- Участник получает уведомление об отключении видео

**Бизнес-правила:**
- BR-SEC-016-01: При блокировке видео только хост может разрешить участнику включить камеру
- BR-SEC-016-02: Отключение видео не влияет на демонстрацию экрана

---

#### FR-SEC-017: Назначение со-хостов

**Описание:** Система должна позволять делегировать полномочия хоста другим участникам.

**Требования:**
- Хост может назначить до 25 со-хостов на встречу
- Со-хосты получают доступ к контролям модерации
- Со-хост может быть назначен только из основной комнаты (не из breakout room)
- Хост может отозвать полномочия со-хоста

**Бизнес-правила:**
- BR-SEC-017-01: Только основной хост может назначать/удалять со-хостов
- BR-SEC-017-02: Со-хост не может назначать других со-хостов
- BR-SEC-017-03: При выходе хоста со-хосты сохраняют полномочия

---

### 3.5 Безопасность записей

#### FR-SEC-018: Контроль доступа к записи

**Описание:** Система должна обеспечивать безопасный доступ к записям встреч.

**Требования:**
- Запись сохраняется в папке "Meet Recordings" организатора
- Организатор и инициатор записи получают email со ссылкой
- Участники из той же организации автоматически получают доступ
- Группы не получают автоматический доступ

**Бизнес-правила:**
- BR-SEC-018-01: Внешние участники не могут начинать запись
- BR-SEC-018-02: В немодерируемых встречах только участники домена могут записывать
- BR-SEC-018-03: Требуется достаточно места в Google Drive для записи

---

#### FR-SEC-019: Уведомления о записи

**Описание:** Система должна уведомлять участников о начале/окончании записи.

**Требования:**
- Визуальное уведомление при начале записи
- Визуальное уведомление при остановке записи
- Индикатор записи виден всем участникам на протяжении всей записи

**Бизнес-правила:**
- BR-SEC-019-01: Уведомление обязательно и не может быть отключено
- BR-SEC-019-02: Участник может покинуть встречу, если не согласен с записью

---

#### FR-SEC-020: Compliance Recording (запись для соответствия требованиям)

**Описание:** Система должна поддерживать автоматическую запись для регуляторных требований.

**Требования:**
- Автоматическая запись для определенных пользователей/групп
- Хранение в WORM-совместимом Google Cloud Storage
- Захват транскрипций вместе с записью
- Соответствие требованиям FINRA и других регуляторов

**Доступность:** Enterprise Plus, Education Plus

**Бизнес-правила:**
- BR-SEC-020-01: Compliance recording имеет приоритет над пользовательскими настройками
- BR-SEC-020-02: Пользователь получает уведомление о compliance recording
- BR-SEC-020-03: Политики хранения настраиваются администратором

---

### 3.6 Защита от сторонних приложений

#### FR-SEC-021: Блокировка сторонних приложений записи

**Описание:** Система должна предоставлять инструменты для блокировки несанкционированных приложений записи.

**Требования:**
- Администратор может блокировать домены сторонних сервисов записи
- Блокировка расширений Chrome для записи
- Уведомление администратора при обнаружении сторонних рекордеров

**Бизнес-правила:**
- BR-SEC-021-01: Блокировка настраивается на уровне организации
- BR-SEC-021-02: Пользователь не может обойти блокировку на управляемых устройствах

---

### 3.7 Отчеты о нарушениях

#### FR-SEC-022: Подача жалобы на участника

**Описание:** Система должна позволять участникам сообщать о нарушениях.

**Требования:**
- Кнопка "Report abuse" в меню встречи
- Обязательные поля: тип нарушения, имена нарушителей, описание
- Опциональное прикрепление видеоклипа (с согласия отправителя)
- Жалоба отправляется в Google для расследования

**Типы нарушений:**
| Код | Описание |
|-----|----------|
| `HARASSMENT` | Преследование, травля, угрозы |
| `HATE_SPEECH` | Ненависть по признаку расы, религии, пола и т.д. |
| `SPAM` | Спам, нежелательный контент |
| `EXPLICIT_CONTENT` | Откровенный/непристойный контент |
| `ILLEGAL_ACTIVITY` | Незаконная деятельность |
| `OTHER` | Другое нарушение |

**Бизнес-правила:**
- BR-SEC-022-01: Все поля формы обязательны для заполнения
- BR-SEC-022-02: Google расследует жалобу и принимает меры
- BR-SEC-022-03: При серьезных нарушениях аккаунт может быть заблокирован

---

#### FR-SEC-023: Блокировка пользователя для звонков

**Описание:** Система должна позволять блокировать пользователей для личных звонков.

**Требования:**
- Опция "Block" в настройках звонков

**Бизнес-правила:**

- BR-SEC-023-02: Блокировка двусторонняя (взаимная)

## 5. Состояния и статусы

### 5.1 Состояния безопасности встречи

```
[CREATED] --> [OPEN] <--> [LOCKED]
                 |
                 v
            [ENDED]
```

| Состояние | Описание |
|-----------|----------|
| `CREATED` | Встреча создана, еще не начата |
| `OPEN` | Встреча активна, вход разрешен (согласно настройкам) |
| `LOCKED` | Встреча заблокирована, новый вход запрещен |
| `ENDED` | Встреча завершена |

### 5.2 Статусы запроса на вход

```
[KNOCKED] --> [WAITING] --> [ADMITTED] --> [IN_MEETING]
                  |
                  +--> [DENIED] --> [BLOCKED] (после 2 отказов)
```

| Статус | Описание |
|--------|----------|
| `KNOCKED` | Участник "постучал" |
| `WAITING` | Ожидает в зале ожидания |
| `ADMITTED` | Допущен |
| `IN_MEETING` | Находится во встрече |
| `DENIED` | Отказано в доступе |
| `BLOCKED` | Заблокирован |

### 5.3 Статусы отчета о нарушении

```
[SUBMITTED] --> [PENDING] --> [INVESTIGATING] --> [RESOLVED]
                                    |
                                    +--> [ACTION_TAKEN]
                                    |
                                    +--> [NO_VIOLATION]
```
