# Поиск и фильтрация

## Описание

Модуль "Поиск и фильтрация" предоставляет пользователям Google Keep комплексный набор инструментов для быстрого поиска и организации заметок. Модуль включает полнотекстовый поиск по содержимому заметок, OCR-поиск по тексту в изображениях, систему фильтров по различным критериям (тип, цвет, метки, люди, категории), а также автоматическую категоризацию заметок на основе их содержимого.

Ключевые возможности модуля:
- **Полнотекстовый поиск** — мгновенный поиск по заголовкам и содержимому заметок с подсветкой найденных совпадений
- **OCR-поиск** — распознавание и поиск текста в изображениях и рукописных записях
- **Фильтрация по типам** — фильтры по напоминаниям, аудиозаписям, URL-ссылкам, спискам, изображениям, рисункам
- **Фильтрация по атрибутам** — фильтрация по цвету, меткам, соавторам
- **Автоматическая категоризация (Things)** — интеллектуальная группировка заметок по темам (книги, музыка, путешествия, еда, цитаты и др.)
- **Поиск в архиве** — полная поддержка поиска по архивированным заметкам

## Роли пользователей

| Роль | Описание | Права в модуле поиска |
|------|----------|----------------------|
| **Владелец заметки** | Пользователь, создавший заметку | Полный поиск по всем своим заметкам, включая архив. Видит все метки, цвета, закрепления |
| **Соавтор (Collaborator)** | Пользователь с доступом к общей заметке | Может находить общие заметки через поиск. Не видит метки, цвета и закрепления владельца |
| **Гость (без аккаунта)** | Неавторизованный пользователь | Не имеет доступа к функциям поиска |

**Важно:** Метки, цвета и закрепления являются приватными для каждого пользователя. При поиске соавторы видят только содержимое заметок, но не организационную структуру владельца.

## Функциональные требования

### FR-SEARCH-001: Полнотекстовый поиск по заметкам

**Описание:**
Система предоставляет возможность поиска заметок по ключевым словам и фразам, содержащимся в заголовках и теле заметок. Поиск осуществляется в реальном времени с подсветкой найденных совпадений.

**Роли:**
Владелец заметки, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- У пользователя есть хотя бы одна заметка или доступ к общей заметке

**Основной сценарий:**
1. Пользователь нажимает на строку поиска в верхней части интерфейса
2. Пользователь вводит поисковый запрос (минимум 1 символ)
3. Система выполняет поиск в реальном времени по всем доступным заметкам
4. Результаты отображаются мгновенно, заменяя стандартный вид заметок
5. Найденные ключевые слова подсвечиваются в заголовках заметок
6. Пользователь нажимает на заметку для её открытия

**Альтернативные сценарии:**
- **A1:** Если совпадений не найдено — отображается сообщение "Ничего не найдено"
- **A2:** Пользователь очищает поисковую строку — возвращается стандартный вид заметок
- **A3:** Поиск по рукописным заметкам — система ищет по распознанному тексту рукописи

**Бизнес-правила:**
- BR-001: Поиск нечувствителен к регистру
- BR-002: Поиск выполняется по заголовку и содержимому заметки
- BR-003: Поиск охватывает активные заметки и архив
- BR-004: Поиск НЕ охватывает заметки в корзине
- BR-005: Транскрипции голосовых заметок включаются в поиск
- BR-006: Подсветка совпадений работает только в превью, при открытии заметки подсветка не сохраняется

**Результат:**
Пользователь получает список заметок, соответствующих поисковому запросу, с визуальной подсветкой найденных совпадений.

### FR-SEARCH-002: Поиск текста в изображениях (OCR)

**Описание:**
Система автоматически распознает текст на изображениях, прикрепленных к заметкам, используя технологию оптического распознавания символов (OCR). Распознанный текст индексируется и становится доступным для поиска.

**Роли:**
Владелец заметки, Соавтор

**Предусловия:**
- Заметка содержит изображение с текстом
- Изображение успешно загружено и обработано системой OCR

**Основной сценарий:**
1. Пользователь добавляет изображение к заметке (фото, скан документа, скриншот)
2. Система автоматически анализирует изображение на наличие текста
3. Распознанный текст индексируется для поиска (без явного отображения пользователю)
4. При поисковом запросе система ищет совпадения в распознанном тексте
5. Заметки с изображениями, содержащими искомый текст, отображаются в результатах

**Альтернативные сценарии:**
- **A1:** Изображение низкого качества — OCR может не распознать текст или распознать частично
- **A2:** Рукописный текст — OCR пытается распознать, точность зависит от разборчивости почерка
- **A3:** Текст на нестандартном фоне — точность распознавания снижается

**Бизнес-правила:**
- BR-007: Поддерживаемые форматы изображений: GIF, JPEG, JPG, PNG, WEBP
- BR-008: Максимальный размер файла: 10 МБ
- BR-009: Максимальное разрешение: 25 мегапикселей
- BR-010: PDF-файлы не поддерживаются напрямую (требуется конвертация в изображение)
- BR-011: OCR работает на всех платформах (Web, Android, iOS)
- BR-012: Точность распознавания печатного текста: 95%+
- BR-013: Точность распознавания рукописного текста: 70-85% (при разборчивом почерке)

**Результат:**
Пользователь может находить заметки, вводя текст, который содержится на изображениях внутри этих заметок.

### FR-SEARCH-003: Извлечение текста из изображения (Grab Image Text)

**Описание:**
Пользователь может явно извлечь распознанный текст из изображения и добавить его в тело заметки в виде редактируемого текста.

**Роли:**
Владелец заметки

**Предусловия:**
- Заметка содержит изображение
- Изображение содержит распознаваемый текст

**Основной сценарий:**
1. Пользователь открывает заметку с изображением
2. Пользователь нажимает на изображение
3. Пользователь выбирает меню (три точки)
4. Пользователь выбирает опцию "Распознать текст" (Grab image text)
5. Система обрабатывает изображение (около 30 секунд)
6. Распознанный текст добавляется в тело заметки под изображением
7. Текст становится редактируемым и полностью доступным для поиска

**Альтернативные сценарии:**
- **A1:** Текст не распознан — появляется сообщение об ошибке или пустой результат
- **A2:** Частичное распознавание — добавляется распознанная часть текста с возможными ошибками
- **A3:** Экспорт в Google Docs — пользователь может скопировать текст в Google Документы

**Бизнес-правила:**
- BR-014: Оригинальное изображение сохраняется в заметке
- BR-015: Извлеченный текст можно редактировать
- BR-016: Прямой экспорт в другие форматы (TXT, DOC) не поддерживается
- BR-017: Функция "Копировать в Документы" доступна для быстрого переноса

**Результат:**
Распознанный текст добавляется в заметку как редактируемый контент.

### FR-SEARCH-004: Быстрые фильтры по типу контента

**Описание:**
Система предоставляет набор быстрых фильтров для отображения заметок определенного типа: с напоминаниями, со списками, с изображениями, с рисунками, с URL-ссылками, с аудиозаписями.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь авторизован
- Пользователь находится на главном экране или в режиме поиска

**Основной сценарий:**
1. Пользователь нажимает на строку поиска
2. Система отображает панель быстрых фильтров с иконками типов
3. Пользователь нажимает на иконку нужного типа:
   - Напоминания (колокольчик)
   - Списки (чекбокс)
   - Изображения (картинка)
   - Рисунки (кисть)
   - URL-ссылки (ссылка)
   - Аудиозаписи (микрофон)
4. Система фильтрует заметки, оставляя только соответствующие выбранному типу
5. Результаты отображаются в стандартном формате сетки/списка

**Альтернативные сценарии:**
- **A1:** Заметок выбранного типа нет — отображается пустой результат
- **A2:** Комбинирование с текстовым поиском — пользователь может ввести текст после выбора фильтра

**Бизнес-правила:**
- BR-018: Можно выбрать только один фильтр типа за раз
- BR-019: Фильтр типа можно комбинировать с текстовым поиском
- BR-020: Фильтры применяются к активным заметкам и архиву
- BR-021: Фильтр "Напоминания" показывает как активные, так и прошедшие напоминания

**Результат:**
Пользователь видит только заметки выбранного типа.

### FR-SEARCH-005: Фильтрация по меткам (Labels)

**Описание:**
Пользователь может фильтровать заметки по присвоенным меткам. Метки отображаются в боковом меню и в панели поиска.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь создал хотя бы одну метку
- Хотя бы одна заметка имеет присвоенную метку

**Основной сценарий:**
1. **Вариант A — через боковое меню:**
   - Пользователь открывает боковое меню (гамбургер-иконка)
   - Пользователь видит список всех созданных меток
   - Пользователь нажимает на нужную метку
   - Отображаются только заметки с этой меткой

2. **Вариант B — через поиск:**
   - Пользователь нажимает на строку поиска
   - В панели фильтров пользователь видит секцию "Метки"
   - Пользователь выбирает нужную метку
   - Результаты фильтруются по выбранной метке

**Альтернативные сценарии:**
- **A1:** Поиск по нескольким меткам — официально не поддерживается, но возможен обходной путь через поисковый запрос
- **A2:** Метка без заметок — отображается пустой результат
- **A3:** Комбинация с текстовым поиском — можно искать текст внутри заметок с определенной меткой

**Бизнес-правила:**
- BR-022: Максимум 50 меток на аккаунт
- BR-023: Одна заметка может иметь несколько меток
- BR-024: Метки видны только владельцу (соавторы не видят метки)
- BR-025: Фильтрация по меткам применяется к активным заметкам и архиву
- BR-026: Порядок заметок при фильтрации по метке сохраняется (по дате создания/изменения)

**Результат:**
Пользователь видит все заметки с выбранной меткой.

### FR-SEARCH-006: Фильтрация по цвету

**Описание:**
Пользователь может фильтровать заметки по их цвету фона. Доступные цвета отображаются в панели поиска.

**Роли:**
Владелец заметки

**Предусловия:**
- Хотя бы одной заметке присвоен цвет

**Основной сценарий:**
1. Пользователь нажимает на строку поиска
2. В панели фильтров пользователь видит секцию "Цвета" с доступными цветами
3. Пользователь нажимает на нужный цвет
4. Система отображает только заметки с выбранным цветом фона

**Альтернативные сценарии:**
- **A1:** Нет заметок выбранного цвета — отображается пустой результат
- **A2:** Комбинация с другими фильтрами — можно комбинировать цвет с текстовым поиском или типом

**Бизнес-правила:**
- BR-027: Доступные цвета: белый (по умолчанию), красный, оранжевый, желтый, зеленый, бирюзовый, синий, темно-синий, фиолетовый, розовый, коричневый, серый
- BR-028: Можно выбрать только один цвет за раз
- BR-029: Цвета приватны для владельца (соавторы не видят цвета)
- BR-030: При использовании Chrome-расширения "Category Tabs" доступна фильтрация через цветные вкладки

**Результат:**
Пользователь видит все заметки выбранного цвета.

### FR-SEARCH-007: Фильтрация по соавторам (People)

**Описание:**
Пользователь может фильтровать заметки по людям, с которыми они были предоставлены в совместный доступ.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь поделился хотя бы одной заметкой с другим пользователем

**Основной сценарий:**
1. Пользователь нажимает на строку поиска
2. В панели фильтров пользователь видит секцию "Люди"
3. Система отображает аватары/имена людей, с которыми есть общие заметки
4. Пользователь выбирает нужного человека
5. Отображаются все заметки, к которым есть совместный доступ с этим человеком

**Альтернативные сценарии:**
- **A1:** Нет общих заметок — секция "Люди" не отображается
- **A2:** Соавтор удален — заметки не отображаются в фильтре по этому человеку

**Бизнес-правила:**
- BR-031: Отображаются только пользователи с активным совместным доступом
- BR-032: Можно выбрать только одного человека за раз
- BR-033: Фильтр показывает как заметки, где пользователь — владелец, так и заметки, где он — соавтор

**Результат:**
Пользователь видит все заметки, к которым есть совместный доступ с выбранным человеком.

### FR-SEARCH-008: Автоматическая категоризация (Things)

**Описание:**
Система автоматически анализирует содержимое заметок и группирует их по тематическим категориям: книги, музыка, путешествия, еда, цитаты, идеи и другие.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь имеет заметки с содержимым, поддающимся категоризации

**Основной сценарий:**
1. Пользователь нажимает на строку поиска
2. В панели фильтров пользователь видит секцию "Вещи" (Things)
3. Система отображает обнаруженные категории на основе контента заметок
4. Пользователь выбирает категорию (например, "Путешествия")
5. Отображаются все заметки, относящиеся к этой категории

**Альтернативные сценарии:**
- **A1:** Категория не определена — заметка не появляется ни в одной тематической группе
- **A2:** Заметка относится к нескольким категориям — отображается в каждой соответствующей

**Бизнес-правила:**
- BR-034: Категоризация происходит автоматически на основе анализа контента
- BR-035: Пользователь не может вручную назначить категорию
- BR-036: Доступные категории:
  - Книги (Books)
  - Музыка (Music)
  - Путешествия (Travel)
  - Еда (Food)
  - Цитаты (Quotes)
  - Места (Places)
  - Фильмы и ТВ (Movies & TV)
- BR-037: Категоризация работает на основе ключевых фраз ("список покупок", "рецепт", "прочитать книгу" и т.д.)
- BR-038: Геолокационные заметки могут группироваться по местоположению

**Результат:**
Пользователь видит заметки, автоматически сгруппированные по выбранной тематической категории.

### FR-SEARCH-009: Поиск в архивированных заметках

**Описание:**
Архивированные заметки полностью индексируются и доступны для поиска наравне с активными заметками.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь имеет архивированные заметки

**Основной сценарий:**
1. Пользователь выполняет поисковый запрос
2. Система ищет совпадения как в активных заметках, так и в архиве
3. Результаты из архива отображаются вместе с активными заметками
4. Архивированные заметки визуально отличаются или имеют соответствующую пометку

**Альтернативные сценарии:**
- **A1:** Поиск только в архиве — пользователь сначала переходит в раздел "Архив", затем выполняет поиск
- **A2:** Восстановление из архива — найденную заметку можно разархивировать

**Бизнес-правила:**
- BR-039: Архивированные заметки полностью индексируются
- BR-040: Все фильтры применимы к архивированным заметкам
- BR-041: Архивированные заметки не имеют срока хранения
- BR-042: Метки, цвета и содержимое сохраняются при архивации

**Результат:**
Пользователь может находить заметки в архиве с помощью стандартного поиска.

### FR-SEARCH-010: Исключение корзины из поиска

**Описание:**
Заметки, находящиеся в корзине (удаленные заметки), не индексируются и не отображаются в результатах поиска.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь удалил заметки (они находятся в корзине)

**Основной сценарий:**
1. Пользователь выполняет поисковый запрос
2. Система ищет только в активных заметках и архиве
3. Заметки из корзины не отображаются в результатах

**Альтернативные сценарии:**
- **A1:** Просмотр корзины — пользователь переходит в раздел "Корзина" для просмотра удаленных заметок
- **A2:** Восстановление и поиск — после восстановления заметка снова индексируется

**Бизнес-правила:**
- BR-043: Заметки в корзине автоматически удаляются через 7 дней
- BR-044: В течение 7 дней можно восстановить заметку из корзины
- BR-045: Восстановленная заметка возвращается в архив, если была архивирована до удаления
- BR-046: Поиск внутри корзины не поддерживается

**Результат:**
Удаленные заметки не засоряют результаты поиска.

### FR-SEARCH-011: Поиск по голосовым заметкам

**Описание:**
Голосовые заметки автоматически транскрибируются, и их текстовое содержимое индексируется для поиска.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь создал голосовую заметку через мобильное приложение
- Заметка содержит аудиозапись с транскрипцией

**Основной сценарий:**
1. Пользователь создает голосовую заметку, нажав на микрофон в мобильном приложении
2. Система записывает аудио и автоматически транскрибирует речь в текст
3. Транскрипция сохраняется в заметке вместе с аудиофайлом
4. При поиске система ищет совпадения в транскрипции
5. Голосовые заметки с найденными совпадениями отображаются в результатах

**Альтернативные сценарии:**
- **A1:** Транскрипция не распознана — поиск по содержимому невозможен, но можно найти через фильтр "Аудиозаписи"
- **A2:** Частичное распознавание — поиск работает по распознанной части

**Бизнес-правила:**
- BR-047: Транскрипция выполняется автоматически в момент записи
- BR-048: Аудиофайл и транскрипция сохраняются вместе
- BR-049: Транскрипция доступна для редактирования
- BR-050: Функция доступна только в мобильных приложениях (Android, iOS)

**Результат:**
Пользователь может находить голосовые заметки по их текстовому содержимому.

### FR-SEARCH-012: Поиск по закрепленным заметкам

**Описание:**
Закрепленные заметки (Pinned) отображаются в верхней части результатов поиска, сохраняя приоритет.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь имеет закрепленные заметки

**Основной сценарий:**

2. Система находит совпадения среди всех заметок
3. Закрепленные заметки, соответствующие запросу, отображаются в отдельной секции "Закрепленные"

**Альтернативные сценарии:**
- **A1:** Нет закрепленных заметок среди результатов — отображается только секция "Другие"

**Бизнес-правила:**
- BR-051: Закрепление приватно для владельца
- BR-052: Соавторы не видят статус закрепления
- BR-053: Порядок внутри секции закрепленных сохраняется

**Результат:**
Важные (закрепленные) заметки остаются приоритетными в результатах поиска.

### FR-SEARCH-015: Комбинирование фильтров

**Описание:**
Пользователь может комбинировать текстовый поиск с одним или несколькими фильтрами для более точного поиска.

**Роли:**
Владелец заметки

**Предусловия:**
- Пользователь находится в режиме поиска

**Основной сценарий:**
1. Пользователь вводит текстовый запрос
2. Дополнительно выбирает фильтр по типу (например, "Списки")
3. Дополнительно выбирает фильтр по цвету (например, "Красный")
4. Система применяет все фильтры одновременно
5. Отображаются только заметки, соответствующие всем критериям

**Альтернативные сценарии:**
- **A1:** Нет результатов — ни одна заметка не соответствует всем критериям
- **A2:** Снятие фильтра — результаты пересчитываются

**Бизнес-правила:**
- BR-060: Фильтры применяются по принципу "И" (AND), а не "ИЛИ" (OR)
- BR-061: Можно комбинировать: текст + тип + цвет + метку
- BR-062: Фильтр по людям работает как отдельный критерий
- BR-063: Автоматические категории (Things) можно комбинировать с текстовым поиском

**Результат:**
Пользователь получает максимально точные результаты поиска.

## Состояния и статусы

### Состояния поискового запроса

```
[Пустой запрос] --> [Ввод текста] --> [Поиск выполняется] --> [Результаты получены]
                                   |                            |
                                   v                            v
                            [Применение фильтров]    [Нет результатов]
                                   |
                                   v
                         [Результаты обновлены]
```

| Состояние | Описание | Переходы |
|-----------|----------|----------|
| `IDLE` | Строка поиска пуста | -> TYPING (ввод текста), -> FILTERED (выбор фильтра) |
| `TYPING` | Пользователь вводит текст | -> SEARCHING (debounce 300ms), -> IDLE (очистка) |
| `SEARCHING` | Выполняется поиск | -> RESULTS, -> NO_RESULTS |
| `RESULTS` | Найдены результаты | -> TYPING (изменение запроса), -> FILTERED, -> IDLE |
| `NO_RESULTS` | Результатов не найдено | -> TYPING, -> FILTERED, -> IDLE |
| `FILTERED` | Применен фильтр | -> RESULTS, -> NO_RESULTS |

### Состояния OCR-обработки

| Состояние | Описание |
|-----------|----------|
| `PENDING` | Изображение загружено, ожидает обработки |
| `PROCESSING` | Выполняется распознавание |
| `COMPLETED` | Текст распознан и проиндексирован |
| `FAILED` | Ошибка распознавания |
| `NO_TEXT` | Текст на изображении не обнаружен |

## Ограничения и лимиты

### Поисковые ограничения

| Параметр | Лимит | Описание |
|----------|-------|----------|
| Максимальная длина запроса | 500 символов | Ограничение на текстовый запрос |
| Debounce поиска | 300 мс | Задержка перед выполнением поиска |
| Максимум результатов на экране | Без ограничений | Виртуальная прокрутка |
| Глубина поиска | Все заметки | Без ограничения по количеству |

### OCR-ограничения

| Параметр | Лимит | Описание |
|----------|-------|----------|
| Максимальный размер изображения | 10 МБ | Ограничение на загрузку |
| Максимальное разрешение | 25 мегапикселей | Ограничение для OCR |
| Поддерживаемые форматы | GIF, JPEG, JPG, PNG, WEBP | PDF не поддерживается |
| Время обработки OCR | ~30 секунд | Для функции "Grab image text" |
| Точность печатного текста | 95%+ | При хорошем качестве изображения |
| Точность рукописного текста | 70-85% | При разборчивом почерке |

### Ограничения меток и фильтров

| Параметр | Лимит | Описание |
|----------|-------|----------|
| Максимум меток | 50 | На один аккаунт |
| Метки на заметку | Без ограничений | Одна заметка может иметь несколько меток |
| Цветов доступно | 12 | Стандартная палитра |
| Фильтров одновременно | Несколько | Комбинирование разрешено |

### Временные ограничения

| Параметр | Лимит | Описание |
|----------|-------|----------|
| Хранение в корзине | 7 дней | Автоматическое удаление после |
| Хранение в архиве | Бессрочно | Без автоудаления |
| Синхронизация индекса | Реальное время | Изменения индексируются мгновенно |
