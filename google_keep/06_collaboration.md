# Совместная работа

## Описание

Модуль "Совместная работа" обеспечивает функциональность совместного редактирования заметок в Google Keep. Модуль позволяет пользователям приглашать других пользователей к заметкам, предоставляя им возможность редактирования контента в режиме реального времени. Все изменения мгновенно синхронизируются между всеми участниками на всех их устройствах.

### Ключевые возможности модуля:
- Приглашение соавторов по email, имени или через Google Group
- Совместное редактирование текста, списков, изображений, рисунков и аудиозаписей
- Синхронизация изменений в реальном времени
- Семейный доступ через Family Group
- Визуальная индикация новых изменений от соавторов

### Ограничения модуля:
- Отсутствует режим "только для чтения" - все соавторы получают права на редактирование
- Невозможно отследить авторство конкретных изменений
- Отсутствует детальная история изменений с возможностью отката

## Роли пользователей

### Владелец заметки (Owner)
Пользователь, создавший заметку. Обладает полными правами на заметку.

**Возможности:**
- Полное редактирование заметки (текст, списки, изображения, рисунки, аудио)
- Добавление и удаление соавторов
- Удаление заметки (с потерей доступа для всех соавторов)
- Архивирование заметки (персональное)
- Добавление ярлыков и напоминаний (персональное)
- Изменение цвета заметки (персональное)

**Ограничения:**
- Не может передать права владения другому пользователю
- Не может быть удален из списка соавторов

### Соавтор (Collaborator / Writer)
Пользователь, приглашенный к заметке владельцем или другим соавтором.

**Возможности:**
- Полное редактирование заметки (текст, списки, изображения, рисунки, аудио)
- Добавление новых соавторов к заметке
- Удаление других соавторов из заметки
- Архивирование заметки (видно только этому пользователю)
- Добавление ярлыков (видно только этому пользователю)
- Добавление напоминаний (видно только этому пользователю)
- Изменение цвета заметки (видно только этому пользователю)

**Ограничения:**
- Не может удалить заметку (только отказаться от доступа)
- Не может удалить владельца заметки из списка соавторов

### Гость (не зарегистрированный пользователь)
Пользователи без аккаунта Google не могут участвовать в совместной работе с заметками. Для получения доступа необходима регистрация Google-аккаунта.

## Функциональные требования

### FR-COLLAB-001: Добавление соавтора к заметке

**Описание:** Владелец или соавтор заметки может пригласить нового пользователя к совместной работе над заметкой путем указания его email-адреса, имени из контактов или группы Google.

**Роли:** Владелец, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Заметка существует и доступна пользователю
- У приглашаемого пользователя есть Google-аккаунт

**Основной сценарий:**
1. Пользователь открывает заметку
2. Пользователь нажимает на иконку "Соавторы" (силуэт человека со знаком +)
3. Система отображает модальное окно со списком текущих соавторов
4. Пользователь вводит email-адрес, имя контакта или название Google Group
5. Система выполняет автодополнение из контактов пользователя
6. Пользователь выбирает нужного пользователя из списка или подтверждает ввод
7. Пользователь опционально активирует чекбокс "Отправить уведомление"
8. Пользователь нажимает "Готово" / "Сохранить"
9. Система добавляет нового соавтора с ролью WRITER
10. Если выбрано уведомление - система отправляет email приглашенному пользователю
11. Заметка появляется в списке заметок приглашенного пользователя

**Альтернативные сценарии:**

*A1. Пользователь не найден:*
1. Система отображает сообщение о том, что пользователь не найден
2. Пользователь может ввести email вручную
3. Если email валиден - продолжается основной сценарий с шага 7

*A2. Пользователь уже является соавтором:*
1. Система не добавляет дубликат
2. Пользователь остается в текущем модальном окне

*A3. Приглашение Google Group:*
1. Пользователь вводит название группы Google
2. Система добавляет всех участников группы как соавторов
3. Все участники группы получают доступ к заметке

**Бизнес-правила:**
- BR-001: Соавтор может быть добавлен только с ролью WRITER (редактирование)
- BR-002: Email уведомление отправляется только при активации соответствующей опции
- BR-003: Приглашенный пользователь должен иметь Google-аккаунт для доступа
- BR-004: Добавление соавтора не требует его подтверждения - доступ предоставляется немедленно

**Результат:** Новый соавтор добавлен к заметке, заметка появляется в его списке заметок

### FR-COLLAB-002: Добавление семейной группы к заметке

**Описание:** Пользователь может одним действием предоставить доступ к заметке всем членам своей семейной группы Google (Google Family Group).

**Роли:** Владелец, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Пользователь является членом семейной группы Google
- Заметка существует и доступна пользователю

**Основной сценарий:**
1. Пользователь открывает заметку
2. Пользователь нажимает на иконку "Соавторы"
3. Система отображает модальное окно управления соавторами
4. Пользователь нажимает "Семейная группа"
5. Система добавляет всех членов семейной группы как соавторов
6. Пользователь нажимает "Сохранить"
7. Заметка появляется у всех членов семьи

**Альтернативные сценарии:**

*A1. Пользователь не состоит в семейной группе:*
1. Опция "Семейная группа" не отображается или неактивна
2. Пользователь может добавлять соавторов индивидуально

*A2. Добавление дополнительных соавторов к семейной заметке:*
1. После добавления семейной группы пользователь может добавить дополнительных соавторов
2. Эти соавторы не обязаны быть членами семьи

**Бизнес-правила:**
- BR-005: Семейная группа добавляется целиком, нельзя исключить отдельных членов при добавлении
- BR-006: Члены семьи могут быть удалены индивидуально после добавления группы
- BR-007: Изменения в составе семейной группы Google не влияют автоматически на уже расшаренные заметки

**Результат:** Все члены семейной группы получают доступ к заметке как соавторы

### FR-COLLAB-003: Удаление соавтора из заметки

**Описание:** Владелец или соавтор заметки может отозвать доступ у другого соавтора, удалив его из списка участников.

**Роли:** Владелец, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Заметка существует и доступна пользователю
- В заметке есть хотя бы один соавтор (помимо владельца)

**Основной сценарий:**
1. Пользователь открывает заметку
2. Пользователь нажимает на иконку "Соавторы"
3. Система отображает список текущих соавторов
4. Пользователь нажимает иконку удаления (X) рядом с именем соавтора
5. Соавтор удаляется из списка
6. Пользователь нажимает "Готово" / "Сохранить"
7. Система отзывает доступ соавтора к заметке
8. Заметка исчезает из списка заметок удаленного соавтора

**Альтернативные сценарии:**

*A1. Попытка удалить владельца заметки:*
1. Система не позволяет выполнить действие
2. Иконка удаления рядом с владельцем отсутствует или неактивна
3. При попытке через API возвращается ошибка

*A2. Удаление последнего соавтора:*
1. Заметка остается только у владельца
2. Заметка перестает быть совместной

**Бизнес-правила:**
- BR-008: Владелец заметки не может быть удален из списка соавторов
- BR-009: Удаление соавтора происходит мгновенно без подтверждения со стороны удаляемого
- BR-010: Удаленный соавтор теряет доступ ко всему контенту заметки
- BR-011: Удаленный соавтор не получает уведомление об удалении

**Результат:** Соавтор удален, его доступ к заметке отозван

### FR-COLLAB-004: Выход соавтора из заметки

**Описание:** Соавтор может самостоятельно покинуть заметку, отказавшись от дальнейшего участия в совместной работе.

**Роли:** Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Пользователь является соавтором (не владельцем) заметки

**Основной сценарий:**
1. Соавтор открывает заметку
2. Соавтор нажимает на иконку "Соавторы"
3. Система отображает список соавторов
4. Соавтор нажимает иконку удаления рядом со своим именем
5. Соавтор нажимает "Сохранить"
6. Система удаляет пользователя из списка соавторов
7. Заметка исчезает из списка заметок пользователя

**Альтернативные сценарии:**

*A1. Владелец пытается покинуть заметку:*
1. Владелец не может покинуть собственную заметку
2. Для отказа от заметки владелец должен удалить её

**Бизнес-правила:**
- BR-012: Соавтор может покинуть заметку в любой момент без одобрения владельца
- BR-013: После выхода соавтор теряет доступ ко всем данным заметки
- BR-014: Соавтор может быть повторно приглашен после выхода

**Результат:** Пользователь удален из списка соавторов, доступ к заметке потерян

### FR-COLLAB-005: Совместное редактирование текстовой заметки

**Описание:** Несколько соавторов могут одновременно редактировать текстовое содержимое заметки. Изменения синхронизируются в реальном времени.

**Роли:** Владелец, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Заметка существует и является совместной
- Устройство подключено к интернету (для синхронизации)

**Основной сценарий:**
1. Соавтор открывает заметку
2. Соавтор вносит изменения в текст заметки
3. Клиент немедленно применяет изменения локально (оптимистичный рендеринг)
4. Клиент отправляет операцию изменения на сервер
5. Сервер получает операцию и применяет алгоритм Operational Transformation (OT)
6. Сервер рассылает трансформированные операции всем подключенным клиентам
7. Клиенты других соавторов получают и применяют изменения
8. Изменения отображаются у всех соавторов в реальном времени

**Альтернативные сценарии:**

*A1. Редактирование в офлайн-режиме:*
1. Пользователь редактирует заметку без интернет-соединения
2. Система сохраняет изменения локально с временными метками
3. При восстановлении соединения клиент отправляет накопленные операции на сервер
4. Сервер применяет Operational Transformation для разрешения конфликтов
5. Изменения синхронизируются со всеми клиентами

*A2. Конфликт версий (офлайн-редактирование несколькими пользователями):*
1. Несколько пользователей редактируют заметку офлайн
2. При синхронизации возникает конфликт, который не может быть разрешен автоматически
3. Система отображает уведомление о конфликте версий
4. Пользователь видит разные версии заметки
5. Пользователь выбирает "Сохранить выбранную версию" или "Сохранить обе версии"

*A3. Одновременное редактирование одного участка текста:*
1. Два пользователя редактируют один и тот же участок текста
2. Сервер применяет Operational Transformation
3. Изменения трансформируются для совместимости
4. Оба изменения сохраняются (например, вставки объединяются)

**Бизнес-правила:**
- BR-015: Изменения применяются локально мгновенно (оптимистичная модель)
- BR-016: Конфликты разрешаются автоматически через Operational Transformation
- BR-017: При невозможности автоматического разрешения пользователю предлагается выбор
- BR-018: Офлайн-изменения сохраняются и синхронизируются при восстановлении соединения

**Результат:** Изменения сохранены и видны всем соавторам

### FR-COLLAB-006: Совместное редактирование списка с чекбоксами

**Описание:** Соавторы могут совместно работать со списками задач, отмечая выполненные пункты. Изменения статуса чекбоксов синхронизируются между всеми участниками.

**Роли:** Владелец, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Заметка содержит список с чекбоксами
- Заметка является совместной

**Основной сценарий:**
1. Соавтор открывает заметку со списком
2. Соавтор отмечает пункт как выполненный (ставит галочку)
3. Текст пункта становится перечеркнутым
4. Пункт перемещается в раздел "Выполненные" (внизу списка)
5. Изменение синхронизируется с сервером
6. Все соавторы видят обновленный статус пункта

**Альтернативные сценарии:**

*A1. Снятие отметки выполнения:*
1. Соавтор нажимает на отмеченный пункт
2. Галочка снимается, текст перестает быть перечеркнутым
3. Пункт возвращается в основной список
4. Изменение синхронизируется со всеми соавторами

*A2. Добавление нового пункта в список:*
1. Соавтор добавляет новый пункт
2. Пункт добавляется в конец списка невыполненных
3. Изменение синхронизируется со всеми соавторами

*A3. Изменение текста пункта:*
1. Соавтор редактирует текст существующего пункта
2. Текст обновляется в реальном времени у всех соавторов

**Бизнес-правила:**
- BR-019: Статус чекбокса виден всем соавторам
- BR-020: Порядок пунктов определяется: невыполненные сверху, выполненные снизу
- BR-021: Выполненные пункты можно скрыть или удалить массово

**Результат:** Изменения в списке синхронизированы между всеми соавторами

### FR-COLLAB-007: Совместное редактирование изображений и рисунков

**Описание:** Соавторы могут добавлять, просматривать и редактировать изображения и рисунки в совместных заметках.

**Роли:** Владелец, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Заметка является совместной

**Основной сценарий (добавление изображения):**
1. Соавтор открывает заметку
2. Соавтор нажимает на иконку добавления изображения
3. Соавтор выбирает изображение из галереи или делает фото
4. Система загружает изображение на сервер
5. Изображение появляется в заметке
6. Изменение синхронизируется со всеми соавторами

**Основной сценарий (редактирование рисунка):**
1. Соавтор открывает заметку с рисунком или создает новый
2. Соавтор переходит в режим редактирования рисунка
3. Соавтор вносит изменения (добавляет линии, стирает)
4. Соавтор сохраняет изменения
5. Рисунок обновляется в заметке
6. Изменение синхронизируется со всеми соавторами

**Альтернативные сценарии:**

*A1. Удаление изображения:*
1. Соавтор удаляет изображение из заметки
2. Изображение удаляется у всех соавторов
3. Действие необратимо

**Бизнес-правила:**
- BR-022: Изображения синхронизируются между всеми соавторами
- BR-023: Рисунки можно редактировать, но одновременное редактирование рисунка не поддерживается в реальном времени
- BR-024: Любой соавтор может добавлять и удалять изображения

**Результат:** Графический контент синхронизирован между всеми соавторами

### FR-COLLAB-008: Индикация новых изменений от соавторов

**Описание:** Система визуально уведомляет пользователя о том, что соавтор внес изменения в заметку, которые пользователь еще не видел.

**Роли:** Владелец, Соавтор

**Предусловия:**
- Заметка является совместной
- Другой соавтор внес изменения

**Основной сценарий:**
1. Соавтор A вносит изменения в заметку
2. Изменения синхронизируются на сервере
3. Соавтор B открывает приложение Google Keep
4. Заметка отображается с визуальной индикацией (затенение/подсветка)
5. Под заметкой отображается имя или email соавтора и дата/время изменения
6. Соавтор B открывает заметку
7. Индикация снимается после просмотра

**Альтернативные сценарии:**

*A1. Просмотр изменений в реальном времени:*
1. Оба соавтора одновременно просматривают заметку
2. Изменения отображаются в реальном времени
3. Специальная индикация не требуется - пользователь видит изменения мгновенно

**Бизнес-правила:**
- BR-025: Затенение заметки применяется при первом появлении у нового соавтора
- BR-026: Затенение применяется при изменении заметки соавтором
- BR-027: Отображается имя/email последнего редактора и время изменения
- BR-028: Нет детальной истории - только информация о последнем изменении

**Результат:** Пользователь информирован о новых изменениях в совместных заметках

### FR-COLLAB-009: Персональные атрибуты заметки

**Описание:** Некоторые атрибуты заметки являются персональными и не синхронизируются между соавторами. Каждый соавтор может настраивать их индивидуально.

**Роли:** Владелец, Соавтор

**Предусловия:**
- Пользователь авторизован в системе
- Заметка является совместной

**Персональные атрибуты:**

| Атрибут | Описание | Видимость |
|---------|----------|-----------|
| Ярлыки (Labels) | Категоризация заметок | Только для текущего пользователя |
| Цвет заметки | Цветовая маркировка | Только для текущего пользователя |
| Напоминание | Время уведомления | Только для текущего пользователя |
| Статус архивации | Перемещение в архив | Только для текущего пользователя |
| Закрепление | Закрепление вверху списка | Только для текущего пользователя |

**Основной сценарий (установка ярлыка):**
1. Соавтор A открывает совместную заметку
2. Соавтор A добавляет ярлык "Работа"
3. Ярлык отображается только у Соавтора A
4. Соавтор B не видит этот ярлык

**Бизнес-правила:**
- BR-029: Персональные атрибуты хранятся отдельно для каждого пользователя
- BR-030: Изменение персональных атрибутов не создает уведомление для других соавторов
- BR-031: Архивирование заметки одним соавтором не архивирует её у других

**Результат:** Персональные настройки применены только для текущего пользователя

### FR-COLLAB-010: Удаление совместной заметки

**Описание:** Владелец может удалить совместную заметку, что приводит к потере доступа для всех соавторов.

**Роли:** Владелец

**Предусловия:**
- Пользователь является владельцем заметки
- Заметка является совместной

**Основной сценарий:**
1. Владелец открывает совместную заметку
2. Владелец нажимает на меню действий (три точки)
3. Владелец выбирает "Удалить"
4. Система перемещает заметку в корзину владельца
5. Заметка немедленно исчезает из списка заметок всех соавторов
6. Соавторы теряют доступ к заметке

**Альтернативные сценарии:**

*A1. Восстановление заметки из корзины:*
1. Владелец открывает корзину
2. Владелец восстанавливает заметку
3. Заметка восстанавливается со всеми соавторами
4. Соавторы снова получают доступ

*A2. Соавтор пытается удалить заметку:*
1. Соавтор не видит опцию удаления заметки
2. Через API возвращается ошибка - нет прав OWNER

**Бизнес-правила:**
- BR-032: Только владелец может удалить заметку
- BR-033: Удаление немедленно лишает всех соавторов доступа
- BR-034: Восстановление из корзины восстанавливает доступ для всех соавторов
- BR-035: Заметка в корзине автоматически удаляется через 7 дней

**Результат:** Заметка удалена, все соавторы потеряли доступ

### FR-COLLAB-011: Отправка уведомления о приглашении

**Описание:** При добавлении соавтора система может отправить email-уведомление приглашенному пользователю.

**Роли:** Владелец, Соавтор (инициатор приглашения)

**Предусловия:**
- Пользователь добавляет нового соавтора
- Опция уведомления активирована

**Основной сценарий:**
1. Пользователь добавляет соавтора
2. Пользователь активирует чекбокс "Отправить уведомление"
3. Пользователь сохраняет изменения
4. Система отправляет email на адрес приглашенного
5. Email содержит информацию о заметке и ссылку для доступа
6. Приглашенный пользователь переходит по ссылке
7. Открывается Google Keep с этой заметкой

**Альтернативные сценарии:**

*A1. Уведомление не отправляется:*
1. Чекбокс уведомления не активирован
2. Соавтор добавляется без email-уведомления
3. Заметка появляется в списке приглашенного при следующей синхронизации

**Бизнес-правила:**
- BR-036: Уведомление опционально
- BR-037: Доступ предоставляется независимо от статуса уведомления
- BR-038: Уведомление не требует подтверждения от получателя

**Результат:** Приглашенный пользователь получает email-уведомление о новой совместной заметке

### FR-COLLAB-012: Отключение возможности получения приглашений

**Описание:** Пользователь может отключить возможность получения приглашений к совместным заметкам от других пользователей.

**Роли:** Любой авторизованный пользователь

**Предусловия:**
- Пользователь авторизован в системе

**Основной сценарий:**
1. Пользователь открывает настройки Google Keep
2. Пользователь находит опцию "Разрешить добавление в заметки"
3. Пользователь отключает опцию
4. Система сохраняет настройку
5. Другие пользователи не могут добавить этого пользователя как соавтора

**Альтернативные сценарии:**

*A1. Попытка добавить пользователя с отключенным доступом:*
1. Инициатор пытается добавить пользователя
2. Система отображает ошибку или игнорирует добавление

**Бизнес-правила:**
- BR-039: Пользователь может сам делиться заметками даже с отключенной опцией
- BR-040: Существующие совместные заметки остаются доступными

**Результат:** Пользователь защищен от нежелательных приглашений

## Сущности данных

### Note (Заметка)
```
Note {
  id: string (UUID)              // Уникальный идентификатор заметки
  owner_id: string               // ID владельца заметки
  title: string                  // Заголовок заметки
  content: string                // Текстовое содержимое
  type: enum                     // Тип: NOTE, LIST, DRAWING
  created_at: timestamp          // Дата создания
  updated_at: timestamp          // Дата последнего изменения
  updated_by: string             // ID последнего редактора
  is_shared: boolean             // Флаг совместной заметки
  is_trashed: boolean            // Флаг удаления
  trashed_at: timestamp          // Дата удаления
}
```

### Permission (Разрешение)
```
Permission {
  id: string (UUID)              // Уникальный идентификатор разрешения
  note_id: string                // ID заметки
  member_type: enum              // Тип: USER, GROUP, FAMILY
  member_email: string           // Email пользователя/группы
  role: enum                     // Роль: OWNER, WRITER
  created_at: timestamp          // Дата добавления
  created_by: string             // ID пригласившего
}
```

### UserNoteSettings (Персональные настройки заметки)
```
UserNoteSettings {
  user_id: string                // ID пользователя
  note_id: string                // ID заметки
  color: string                  // Цвет заметки
  labels: array<string>          // Ярлыки
  is_pinned: boolean             // Закреплена
  is_archived: boolean           // В архиве
  reminder: Reminder             // Напоминание
  last_viewed_at: timestamp      // Последний просмотр
  has_unseen_changes: boolean    // Есть непросмотренные изменения
}
```

### Collaborator (Соавтор - представление для UI)
```
Collaborator {
  email: string                  // Email соавтора
  display_name: string           // Отображаемое имя
  photo_url: string              // URL фото профиля
  role: enum                     // Роль: OWNER, WRITER
  is_family: boolean             // Член семейной группы
}
```

### SyncOperation (Операция синхронизации)
```
SyncOperation {
  id: string (UUID)              // ID операции
  note_id: string                // ID заметки
  user_id: string                // ID автора операции
  operation_type: enum           // Тип: INSERT, DELETE, UPDATE
  position: integer              // Позиция в тексте
  content: string                // Содержимое операции
  timestamp: timestamp           // Время операции
  server_timestamp: timestamp    // Время применения на сервере
  is_applied: boolean            // Применена на сервере
}
```

### VersionConflict (Конфликт версий)
```
VersionConflict {
  id: string (UUID)              // ID конфликта
  note_id: string                // ID заметки
  user_id: string                // ID пользователя с конфликтом
  local_version: NoteVersion     // Локальная версия
  server_version: NoteVersion    // Серверная версия
  created_at: timestamp          // Время обнаружения конфликта
  resolved: boolean              // Разрешен
  resolution: enum               // Способ разрешения: KEEP_LOCAL, KEEP_SERVER, KEEP_BOTH
}
```

## Состояния и статусы

### Статусы разрешений (Permission)

```
[OWNER] - Владелец заметки (не может быть изменен или удален)
    |
    v
[WRITER] - Соавтор с правами редактирования
    |
    v
[REMOVED] - Доступ отозван (разрешение удалено)
```

### Состояния синхронизации заметки

```
[SYNCED] <---> [LOCAL_CHANGES] ---> [SYNCING] ---> [SYNCED]
    |              |                    |
    |              |                    v
    |              +------------> [CONFLICT] ---> [RESOLVED] ---> [SYNCED]
    |                                   |
    v                                   v
[OFFLINE] ---> [PENDING_SYNC] -------> [SYNCING]
```

| Состояние | Описание |
|-----------|----------|
| SYNCED | Заметка полностью синхронизирована |
| LOCAL_CHANGES | Есть локальные изменения, ожидающие отправки |
| SYNCING | Выполняется синхронизация |
| CONFLICT | Обнаружен конфликт версий |
| RESOLVED | Конфликт разрешен пользователем |
| OFFLINE | Устройство офлайн |
| PENDING_SYNC | Есть изменения, накопленные офлайн |

### Состояния индикации изменений

```
[NO_CHANGES] - Нет непросмотренных изменений
     |
     v (соавтор внес изменения)
[HAS_CHANGES] - Есть непросмотренные изменения (заметка затенена)
     |
     v (пользователь открыл заметку)
[NO_CHANGES]
```

### Статусы операций синхронизации

```
[PENDING] ---> [SENT] ---> [ACKNOWLEDGED] ---> [APPLIED]
                  |
                  v
              [TRANSFORMED] ---> [APPLIED]
                  |
                  v (невозможно трансформировать)
              [CONFLICTED]
```

## Ограничения и лимиты

### Ограничения соавторства

| Параметр | Значение | Примечание |
|----------|----------|------------|
| Максимум соавторов на заметку | Не задокументировано (высокий лимит) | Нет официального ограничения |
| Роли соавторов | Только WRITER | Нет режима "только чтение" |
| Передача владения | Невозможна | Владелец не может быть изменен |
| Требования к соавтору | Google-аккаунт | Гости без аккаунта не поддерживаются |

### Ограничения контента

| Параметр | Значение | Примечание |
|----------|----------|------------|
| Максимум символов в заметке | 20 000 | Применяется к совместным заметкам |
| Максимум вложений | Не задокументировано | Ограничено общим размером хранилища |
| Размер хранилища | 15 ГБ | Общий лимит Google One, делится между сервисами |

### Ограничения синхронизации

| Параметр | Значение | Примечание |
|----------|----------|------------|
| Задержка синхронизации (онлайн) | < 1 секунда | В нормальных условиях сети |
| Хранение офлайн-изменений | До восстановления соединения | Все изменения сохраняются локально |
| Хранение конфликтных версий | 30 дней | Автоматическое удаление после |

### Ограничения уведомлений

| Параметр | Значение | Примечание |
|----------|----------|------------|
| Email-уведомления о приглашении | Опционально | Можно включить/выключить |
| Push-уведомления об изменениях | Не поддерживаются | Только визуальная индикация |
| Уведомления об удалении | Не отправляются | Доступ просто пропадает |

## Интеграции с другими модулями

### Модуль заметок (Notes Module)
- **Зависимость:** Совместная работа расширяет базовую функциональность заметок
- **Интеграция:**
  - Создание заметки определяет владельца
  - Все типы контента (текст, списки, изображения, аудио) поддерживают совместное редактирование
  - Удаление заметки владельцем влияет на всех соавторов

### Модуль списков (Lists/Checklists Module)
- **Зависимость:** Списки наследуют функциональность совместной работы
- **Интеграция:**
  - Статусы чекбоксов синхронизируются между соавторами
  - Порядок элементов определяется сервером
  - Операции "Снять все галочки" и "Удалить выполненные" применяются ко всем соавторам

### Модуль напоминаний (Reminders Module)
- **Зависимость:** Напоминания являются персональными для каждого соавтора
- **Интеграция:**
  - Каждый соавтор может установить свое напоминание
  - Напоминания не синхронизируются между соавторами
  - Изменение напоминания одним пользователем не влияет на других

### Модуль ярлыков (Labels Module)
- **Зависимость:** Ярлыки являются персональными
- **Интеграция:**
  - Каждый соавтор видит свои ярлыки
  - Ярлыки не синхронизируются между соавторами
  - Фильтрация по ярлыкам показывает только заметки с ярлыками текущего пользователя

### Модуль архива (Archive Module)
- **Зависимость:** Архивация персональная
- **Интеграция:**
  - Архивация заметки одним соавтором не архивирует её у других
  - Разархивация также персональная
  - Заметка может быть в архиве у одного и в основном списке у другого

### Модуль поиска (Search Module)
- **Зависимость:** Поиск работает по совместным заметкам
- **Интеграция:**
  - Совместные заметки включены в результаты поиска
  - Поиск учитывает персональные ярлыки
  - Фильтр "Совместные" показывает только заметки с соавторами

### Модуль корзины (Trash Module)
- **Зависимость:** Только владелец может удалять в корзину
- **Интеграция:**
  - Удаленные заметки владельца исчезают у всех соавторов
  - Соавторы не могут удалить заметку в корзину
  - Восстановление из корзины восстанавливает доступ для всех

### Модуль аутентификации (Authentication Module)
- **Зависимость:** Требуется для определения прав доступа
- **Интеграция:**
  - Проверка прав при каждой операции
  - Идентификация пользователя для персональных настроек
  - Привязка email к Google-аккаунту соавторов

### Модуль Google Family
- **Зависимость:** Опциональная интеграция для семейного доступа
- **Интеграция:**
  - Получение списка членов семьи
  - Массовое добавление семейной группы
  - Синхронизация с изменениями состава семьи (не автоматическая)

### Модуль аудита (для Google Workspace)
- **Зависимость:** Административный модуль для организаций
- **Интеграция:**
  - Логирование всех операций с заметками
  - Отслеживание добавления/удаления соавторов
  - API для получения логов аудита
  - Интеграция с Google Cloud Logging

### Модуль синхронизации (Sync Engine)
- **Зависимость:** Ключевая инфраструктура для совместной работы
- **Интеграция:**
  - Operational Transformation для разрешения конфликтов
  - Очередь операций для офлайн-режима
  - Real-time push для мгновенных обновлений
  - Версионирование для обнаружения конфликтов
