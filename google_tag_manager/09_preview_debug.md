# Предварительный просмотр и отладка (Preview & Debug)

## Описание

Модуль предварительного просмотра и отладки позволяет тестировать конфигурацию контейнера Google Tag Manager до её публикации на боевой среде. Пользователь запускает режим предпросмотра (Preview Mode), после чего его сайт загружается с черновой версией контейнера, а параллельно открывается интерфейс отладчика Tag Assistant, отображающий в реальном времени: какие теги сработали, какие нет и почему, значения переменных, события dataLayer, состояние согласия (Consent), а также порядок срабатывания тегов. Модуль поддерживает отладку как веб-контейнеров (client-side), так и серверных контейнеров (server-side). Сессию отладки можно передать другому пользователю через общую ссылку (Shared Preview Link).

Ключевой принцип: режим предпросмотра виден только пользователю, запустившему сессию (или получившему ссылку), и никак не влияет на работу сайта для обычных посетителей.

---

## Роли пользователей

| Роль | Уровень доступа в GTM | Возможности в модуле Preview & Debug |
|---|---|---|
| **Читатель (Read)** | Только чтение | Может запустить предпросмотр опубликованных версий контейнера через страницу Versions. Не может просматривать черновики рабочих областей (Workspace) |
| **Редактор (Edit)** | Чтение + редактирование | Может запустить предпросмотр черновика текущей рабочей области (Workspace). Может создавать и отправлять Shared Preview Link |
| **Утверждающий (Approve)** | Чтение + редактирование + создание версий | Все возможности редактора. Может просматривать любую версию контейнера в режиме предпросмотра |
| **Публикатор (Publish)** | Полный доступ | Все возможности утверждающего. Может публиковать контейнер после проверки в режиме предпросмотра |
| **Получатель ссылки** | Без аккаунта GTM | Может открыть предпросмотр по Shared Preview Link. Видит отладочный интерфейс, но не имеет доступа к конфигурации контейнера в GTM |

## Функциональные требования

### FR-DBG-001: Запуск режима предпросмотра веб-контейнера

**Описание:** Пользователь с правами Edit и выше может запустить режим предпросмотра текущей рабочей области для веб-контейнера.

**Предусловия:**
- Пользователь авторизован в GTM и находится в рабочей области (Workspace)
- Пользователь имеет права Edit, Approve или Publish на уровне контейнера
- Контейнер имеет тип "Web"

**Основной сценарий:**
1. Пользователь нажимает кнопку "Preview" в рабочей области
2. Система открывает Tag Assistant в новой вкладке браузера
3. Пользователь вводит URL целевого сайта
4. Пользователь нажимает "Connect"
5. Система открывает целевой сайт в отдельной вкладке с черновой версией контейнера
6. Tag Assistant устанавливает связь с целевым сайтом и начинает получать данные отладки
7. Отладочный интерфейс отображает события и статусы тегов в реальном времени

**Бизнес-правила:**
- BR-001: Черновая версия контейнера загружается только для текущего пользователя; обычные посетители видят опубликованную версию
- BR-002: Сессия предпросмотра привязана к браузеру, в котором была инициирована
- BR-003: При наличии расширения Tag Assistant сайт открывается в новой вкладке; без расширения -- в отдельном окне
- BR-004: Данные отладки сохраняются при навигации между страницами сайта (не сбрасываются при переходе)

**Результат:** Сессия предпросмотра активна, отладочный интерфейс отображает данные в реальном времени.

---

### FR-DBG-002: Просмотр опубликованных версий контейнера

**Описание:** Пользователь с правами Read и выше может запустить предпросмотр ранее опубликованной версии контейнера.

**Предусловия:**
- Пользователь имеет минимум права Read на уровне контейнера
- Существует хотя бы одна опубликованная версия контейнера

**Основной сценарий:**
1. Пользователь переходит на страницу Versions
2. Пользователь выбирает нужную версию контейнера
3. Пользователь выбирает действие "Preview" из меню версии
4. Система запускает предпросмотр выбранной версии аналогично FR-DBG-001

**Бизнес-правила:**
- BR-005: Пользователь с правами Read не может просматривать черновики рабочих областей, только опубликованные версии
- BR-006: Предпросмотр версии загружает конфигурацию именно этой версии, а не текущий черновик

**Результат:** Сессия предпросмотра запущена с конфигурацией выбранной версии.

### FR-DBG-003: Отображение временной шкалы событий (Event Timeline)

**Описание:** Отладочный интерфейс отображает хронологическую последовательность всех событий dataLayer, происходящих на странице.

**Предусловия:**
- Сессия предпросмотра активна (FR-DBG-001 или FR-DBG-002)

**Основной сценарий:**
1. При загрузке страницы система автоматически регистрирует стандартные события в определённом порядке:
   - **Consent Initialization** -- установка и обновление настроек согласия
   - **Initialization** -- теги, которые должны сработать раньше всех остальных триггеров
   - **Container Loaded** (Page View) -- событие загрузки страницы (начало загрузки)
   - **DOM Ready** -- HTML-структура страницы загружена
   - **Window Loaded** -- страница полностью загружена (включая изображения, скрипты)
2. При действиях пользователя на сайте (клики, отправка форм, прокрутка) регистрируются пользовательские события
3. Каждое событие dataLayer.push() отображается отдельной записью на временной шкале
4. Пользователь может выбрать любое событие для просмотра деталей

**Бизнес-правила:**
- BR-007: Минимум 5 стандартных событий появляются при каждой загрузке страницы вне зависимости от конфигурации GTM
- BR-008: События сохраняются при навигации между страницами -- полная история доступна на протяжении всей сессии
- BR-009: Порядок событий на шкале соответствует хронологическому порядку их возникновения

**Результат:** Пользователь видит полную хронологию событий и может выбрать любое для детального анализа.

---

### FR-DBG-004: Анализ статуса срабатывания тегов

**Описание:** Для каждого события на временной шкале система отображает, какие теги сработали (Tags Fired) и какие не сработали (Tags Not Fired), с указанием причин.

**Предусловия:**
- Сессия предпросмотра активна
- Пользователь выбрал событие на временной шкале (FR-DBG-003)

**Основной сценарий:**
1. Пользователь выбирает событие на временной шкале
2. Система отображает две группы тегов:
   - **Tags Fired** -- теги, которые успешно сработали при данном событии
   - **Tags Not Fired** -- теги, которые не сработали при данном событии
3. Для каждого сработавшего тега отображается:
   - Название тега
   - Тип тега
   - Статус выполнения (успех / ошибка)
   - Количество срабатываний
4. Для каждого несработавшего тега отображается:
   - Название тега
   - Причина несрабатывания (триггер не выполнен, блокирующий триггер активен, согласие не получено и т.д.)

**Бизнес-правила:**
- BR-010: Для анализа причин несрабатывания необходимо сначала выбрать событие на шкале, затем нажать на конкретный тег
- BR-011: Тег может отображаться как "не сработавший" по нескольким причинам одновременно (например, триггер не выполнен И согласие не дано)
- BR-012: Теги с ошибкой выполнения (тег сработал, но вернул ошибку) отображаются в группе "Tags Fired" с соответствующей пометкой

**Результат:** Пользователь понимает, какие теги сработали при каждом событии и почему остальные не сработали.

---

### FR-DBG-005: Просмотр значений переменных

**Описание:** Для каждого события на временной шкале система отображает текущие значения всех переменных контейнера на момент этого события.

**Предусловия:**
- Сессия предпросмотра активна
- Пользователь выбрал событие на временной шкале

**Основной сценарий:**
1. Пользователь переходит на вкладку "Variables" для выбранного события
2. Система отображает список всех переменных контейнера с их значениями:
   - Название переменной
   - Тип переменной
   - Разрешённое (вычисленное) значение на момент выбранного события

**Бизнес-правила:**
- BR-013: Значения переменных привязаны к конкретному событию -- при переключении между событиями значения обновляются
- BR-014: Если переменная не имеет значения на момент события, она отображается как undefined
- BR-015: Имена переменных dataLayer регистрозависимы (case-sensitive)

**Результат:** Пользователь видит точные значения всех переменных в момент каждого события.

---

### FR-DBG-006: Просмотр состояния dataLayer

**Описание:** Система отображает содержимое объекта dataLayer для каждого события -- как отправленное сообщение, так и кумулятивное состояние dataLayer после обработки сообщения.

**Предусловия:**
- Сессия предпросмотра активна
- Пользователь выбрал событие на временной шкале

**Основной сценарий:**
1. Пользователь переходит на вкладку "Data Layer" для выбранного события
2. Система отображает:
   - **Message** -- точный объект, переданный через dataLayer.push() для данного события
   - **Data Layer (State)** -- полное состояние dataLayer после обработки этого сообщения (кумулятивный результат всех предыдущих push)

**Бизнес-правила:**
- BR-016: Объект Message отображается в точности, как был передан (без модификаций)
- BR-017: Data Layer State показывает слияние (merge) всех предшествующих сообщений
- BR-018: Если переменная отсутствует во вкладке Variables, но присутствует в Data Layer, это указывает на отсутствие соответствующей переменной GTM (необходимо создать Data Layer Variable)

**Результат:** Пользователь видит как отдельное сообщение каждого push, так и полное состояние dataLayer.

---

### FR-DBG-007: Просмотр состояния согласия (Consent)

**Описание:** Система отображает текущее состояние Google Consent Mode для каждого события, включая все типы согласия.

**Предусловия:**
- Сессия предпросмотра активна
- На сайте настроен Google Consent Mode (через CMP или вручную)

**Основной сценарий:**
1. Пользователь переходит на вкладку "Consent" для выбранного события
2. Система отображает текущее состояние для каждого типа согласия:
   - ad_storage
   - analytics_storage
   - ad_user_data
   - ad_personalization
   - functionality_storage
   - personalization_storage
   - security_storage
3. Для каждого типа указан статус: granted / denied

**Бизнес-правила:**
- BR-019: Consent Default должен появляться как можно раньше, в идеале -- до события Initialization
- BR-020: Если тег прочитал состояние согласия до того, как был установлен Consent Default, система фиксирует предупреждение "A tag read consent state before a default was set"
- BR-021: Тег может не сработать, если требуемый тип согласия имеет статус "denied" -- это отображается как причина несрабатывания (FR-DBG-004)
- BR-022: Состояние согласия может меняться в ходе сессии (например, пользователь принял cookies) -- каждое изменение отражается на шкале как отдельное событие

**Результат:** Пользователь видит состояние всех типов согласия на момент каждого события и может диагностировать проблемы, связанные с Consent Mode.

### FR-DBG-008: Отладка нескольких контейнеров

**Описание:** Если на сайте установлено несколько контейнеров GTM или тегов gtag.js, пользователь может переключаться между ними в одной сессии отладки.

**Предусловия:**
- Сессия предпросмотра активна
- На целевом сайте установлено два или более контейнера GTM / gtag.js

**Основной сценарий:**
1. Система обнаруживает все контейнеры GTM и реализации gtag.js на странице
2. В верхней части интерфейса Tag Assistant отображается выпадающий список контейнеров
3. Пользователь выбирает нужный контейнер из списка
4. Интерфейс отладки обновляется, отображая события, теги и переменные выбранного контейнера

**Бизнес-правила:**
- BR-023: Переключение между контейнерами не требует перезапуска сессии предпросмотра
- BR-024: Global site tags (gtag.js) всегда доступны для отладки; контейнеры GTM доступны, если для них включён режим предпросмотра
- BR-025: Каждый контейнер имеет собственный набор событий, тегов, переменных и триггеров

**Результат:** Пользователь может отлаживать все контейнеры на странице без перезапуска сессии.

---

### FR-DBG-009: Общая ссылка предпросмотра (Shared Preview Link)

**Описание:** Пользователь может сгенерировать ссылку для передачи сессии предпросмотра другому человеку без предоставления доступа к аккаунту GTM.

**Предусловия:**
- Сессия предпросмотра активна
- Пользователь имеет права Edit и выше

**Основной сценарий:**
1. Пользователь в интерфейсе Tag Assistant нажимает "More Actions" > "Share"
2. Система отображает диалог "Share debug session":
   - Поле для ввода домена целевого сайта
   - Выбор тегов для отладки:
     - Только Global site tags (gtag.js)
     - Global site tags (gtag.js) + GTM-XXXXXX (контейнер)
3. Пользователь выбирает параметры и копирует сгенерированную ссылку
4. Пользователь отправляет ссылку получателю (email, мессенджер и т.д.)
5. Получатель открывает ссылку в браузере
6. Система подключает получателя к сессии предпросмотра и открывает отладочный интерфейс

**Бизнес-правила:**
- BR-026: Для отладки тегов, триггеров и переменных GTM необходимо выбрать вариант с контейнером (GTM-XXXXXX), а не только gtag.js
- BR-027: Получатель ссылки видит отладочный интерфейс, но не имеет доступа к конфигурации контейнера в GTM
- BR-028: Ссылка действительна на протяжении текущей сессии предпросмотра; при завершении сессии владельцем ссылка перестаёт работать
- BR-029: Ссылка не требует аутентификации в Google-аккаунте

**Результат:** Другой пользователь может просматривать отладочную информацию по ссылке без доступа к аккаунту GTM.

### FR-DBG-010: Отладка серверного контейнера (Server-Side Preview)

**Описание:** Пользователь может запустить режим предпросмотра для серверного контейнера GTM, чтобы отладить обработку входящих запросов, клиентов, событий и тегов на стороне сервера.

**Предусловия:**
- Пользователь имеет права Edit и выше на серверный контейнер
- Серверный контейнер настроен и привязан к tagging server
- URL tagging server указан в настройках контейнера (Admin > Container Settings)

**Основной сценарий:**
1. Пользователь выбирает серверный контейнер в GTM
2. Пользователь нажимает "Preview"
3. Система открывает интерфейс отладки серверного контейнера
4. Левая панель отображает входящие HTTP-запросы (например, collect?v=2&...)
5. Каждый запрос может содержать подэлементы -- отдельные события (page_view, scroll, add_to_cart и т.д.)
6. Правая панель отображает детали выбранного запроса/события через вкладки

**Вкладки правой панели:**
- **Request** -- клиент, принявший запрос (claiming client); входящие и исходящие HTTP-запросы
- **Tags** -- сработавшие и несработавшие теги; статус (успех/ошибка); количество срабатываний
- **Variables** -- значения переменных серверного контейнера
- **Event Data** -- полные данные события, используемые для вычисления значений переменных
- **Console** -- ошибки, возникшие при срабатывании тегов (сообщение ошибки + источник)

**Бизнес-правила:**
- BR-030: Только один клиент (Client) может "принять" (claim) входящий запрос; клиент распознаёт формат запроса и забирает его себе
- BR-031: GA4 группирует несколько событий в один HTTP-запрос; каждое событие отображается как подэлемент запроса
- BR-032: Для полной отладки сквозного потока (web -> server) необходимо активировать предпросмотр обоих контейнеров: сначала серверного, затем веб-контейнера
- BR-033: Если код ответа исходящего запроса отличается от 2XX, система отображает тело ответа с описанием ошибки

**Результат:** Пользователь видит полную картину обработки запросов серверным контейнером.

---

### FR-DBG-011: Просмотр исходящих HTTP-запросов серверного контейнера

**Описание:** Для серверного контейнера система отображает детали исходящих HTTP-запросов, отправляемых тегами к внешним сервисам (Google Analytics, Facebook и т.д.).

**Предусловия:**
- Сессия предпросмотра серверного контейнера активна (FR-DBG-010)
- Сработал хотя бы один тег, отправляющий данные во внешний сервис

**Основной сценарий:**
1. Пользователь выбирает сработавший тег
2. Система отображает секцию "Outgoing HTTP Requests"
3. Для каждого исходящего запроса отображается:
   - URL-адрес назначения (endpoint вендора)
   - Параметры запроса
   - Код ответа (status code)
   - Заголовки ответа
   - Тело ответа (если есть)

**Бизнес-правила:**
- BR-034: Исходящий запрос должен совпадать с тем, что видно в Network-вкладке браузера (1:1 соответствие)
- BR-035: Код ответа, отличный от 2XX, указывает на ошибку обработки запроса вендором; тело ответа содержит описание ошибки

**Результат:** Пользователь может верифицировать, что серверный контейнер отправляет корректные данные во внешние сервисы.

---

### FR-DBG-012: Ручная отправка запросов в серверный контейнер

**Описание:** Пользователь может получить специальный HTTP-заголовок для ручной отправки запросов в серверный контейнер в режиме предпросмотра.

**Предусловия:**
- Сессия предпросмотра серверного контейнера активна (FR-DBG-010)

**Основной сценарий:**
1. Пользователь нажимает меню (три точки) в интерфейсе предпросмотра серверного контейнера
2. Пользователь выбирает "Send requests manually"
3. Система отображает значение HTTP-заголовка X-Gtm-Server-Preview
4. Пользователь добавляет этот заголовок к HTTP-запросу и отправляет его на tagging server
5. Запрос отображается в интерфейсе предпросмотра

**Бизнес-правила:**
- BR-036: Запросы попадают в интерфейс предпросмотра по одному из двух условий:
  - Cookie-заголовок входящего запроса содержит отладочные cookies
  - HTTP-запрос содержит заголовок X-Gtm-Server-Preview с корректным значением
- BR-037: Ручная отправка запросов полезна для отладки без привязки к браузеру (например, из Postman или серверного приложения)

**Результат:** Пользователь может тестировать серверный контейнер, отправляя произвольные HTTP-запросы.

### FR-DBG-013: Отладка с использованием расширения Tag Assistant

**Описание:** Расширение Tag Assistant для Chrome расширяет возможности режима предпросмотра, обеспечивая более стабильное соединение и дополнительные функции.

**Предусловия:**
- Браузер Google Chrome
- Расширение Tag Assistant установлено

**Основной сценарий:**
1. Пользователь запускает предпросмотр (FR-DBG-001)
2. Расширение автоматически устанавливает связь между Tag Assistant и целевым сайтом
3. Расширение обеспечивает дополнительные функции:
   - Сайт открывается в новой вкладке (а не в отдельном окне)
   - Поддержка отладки нескольких вкладок одновременно в одной сессии
   - Обнаружение Google-тегов внутри iframe
   - Индикация активного режима предпросмотра в панели расширения

**Бизнес-правила:**
- BR-038: Расширение не является обязательным -- предпросмотр работает и без него, но с ограничениями
- BR-039: Без расширения: сайт открывается в отдельном окне, нет поддержки отладки iframe, нет одновременной отладки нескольких вкладок
- BR-040: Расширения Tag Assistant Legacy и Tag Assistant Companion объединены в единое расширение Tag Assistant
- BR-041: При обновлении Tag Assistant Legacy до Tag Assistant расширение Companion удаляется автоматически

**Результат:** Расширенные возможности отладки при наличии расширения Tag Assistant.

### FR-DBG-014: Анализ деталей триггеров

**Описание:** Для каждого тега система отображает условия триггеров и показывает, какие условия выполнены, а какие нет.

**Предусловия:**
- Сессия предпросмотра активна
- Пользователь выбрал событие на временной шкале и нажал на конкретный тег

**Основной сценарий:**
1. Пользователь нажимает на тег (сработавший или несработавший)
2. Система отображает:
   - Список триггеров, привязанных к тегу (firing triggers)
   - Список блокирующих триггеров (blocking triggers), если настроены
   - Для каждого триггера -- какие условия (filters) выполнены, а какие нет
   - Текущие значения переменных, участвующих в условиях
3. Для тегов с настроенной последовательностью (Tag Sequencing) отображаются:
   - Тег, срабатывающий перед основным (Setup Tag)
   - Тег, срабатывающий после основного (Cleanup Tag)

**Бизнес-правила:**
- BR-042: Тег может не сработать по нескольким причинам одновременно: невыполненные условия триггера + блокирующий триггер + отсутствие согласия
- BR-043: Tag Sequencing срабатывает вне зависимости от условий основного триггера тега -- если цепочка настроена, связанные теги срабатывают по своей логике
- BR-044: Для корректного анализа необходимо сначала выбрать событие, затем нажать на тег -- без выбора события детали могут быть неполными

**Результат:** Пользователь понимает, почему тег сработал или не сработал, с точностью до каждого условия.

### FR-DBG-015: Завершение сессии предпросмотра

**Описание:** Пользователь может завершить сессию предпросмотра, после чего сайт переключается обратно на опубликованную версию контейнера.

**Предусловия:**
- Сессия предпросмотра активна

**Основной сценарий:**
1. Пользователь закрывает вкладку Tag Assistant или нажимает кнопку завершения в GTM
2. Система прекращает загрузку черновой версии контейнера
3. При следующей загрузке страницы сайт использует опубликованную версию контейнера
4. Все Shared Preview Links, связанные с данной сессией, становятся недействительными

**Бизнес-правила:**
- BR-045: Завершение сессии не влияет на конфигурацию контейнера -- все изменения в рабочей области сохраняются
- BR-046: После завершения сессии данные отладки не сохраняются (история событий теряется)

**Результат:** Режим предпросмотра деактивирован, сайт работает с опубликованной версией.

## Сущности данных

### Debug Session (Сессия отладки)
| Поле | Описание |
|---|---|
| Session ID | Уникальный идентификатор сессии отладки |
| Container ID | Идентификатор контейнера GTM (GTM-XXXXXX) |
| Container Type | Тип контейнера: Web / Server |
| Workspace ID | Идентификатор рабочей области (для черновиков) или Version ID (для опубликованных версий) |
| Target URL | URL целевого сайта |
| Initiated By | Пользователь, запустивший сессию |
| Status | Текущий статус сессии (Active / Ended) |
| Created At | Время создания сессии |

### Event Record (Запись события)
| Поле | Описание |
|---|---|
| Event ID | Порядковый номер события в сессии |
| Event Name | Название события (Consent Initialization, Container Loaded, click, form_submit и т.д.) |
| Event Type | Тип: стандартное (system) / пользовательское (custom) |
| Page URL | URL страницы, на которой произошло событие |
| Timestamp | Время возникновения события |
| Data Layer Message | Объект, переданный через dataLayer.push() |
| Data Layer State | Кумулятивное состояние dataLayer после обработки |

### Tag Execution Record (Запись выполнения тега)
| Поле | Описание |
|---|---|
| Tag ID | Идентификатор тега |
| Tag Name | Название тега |
| Tag Type | Тип тега (GA4 Event, Custom HTML и т.д.) |
| Event ID | Событие, при котором тег анализировался |
| Fired | Сработал ли тег: true / false |
| Execution Status | Статус: Success / Error / Not Fired |
| Firing Count | Количество срабатываний |
| Not Fired Reasons | Массив причин несрабатывания |

### Variable Snapshot (Снимок переменных)
| Поле | Описание |
|---|---|
| Event ID | Событие, к которому привязан снимок |
| Variable Name | Название переменной |
| Variable Type | Тип переменной |
| Resolved Value | Вычисленное значение на момент события |

### Consent State (Состояние согласия)
| Поле | Описание |
|---|---|
| Event ID | Событие, к которому привязано состояние |
| Consent Type | Тип согласия (ad_storage, analytics_storage и т.д.) |
| Status | granted / denied |

### Server Request Record (Запись серверного запроса)
| Поле | Описание |
|---|---|
| Request ID | Идентификатор запроса |
| Claiming Client | Клиент, принявший запрос |
| Incoming URL | URL входящего HTTP-запроса |
| Incoming Headers | Заголовки входящего запроса |
| Events | Массив событий, извлечённых из запроса |
| Outgoing Requests | Массив исходящих HTTP-запросов (URL, параметры, статус ответа, тело ответа) |

## Состояния и статусы

### Состояния сессии предпросмотра

```
[Не активна] --(Нажатие "Preview")--> [Инициализация]
[Инициализация] --(Ввод URL, Connect)--> [Подключение]
[Подключение] --(Успешное соединение)--> [Активна]
[Подключение] --(Таймаут / Ошибка)--> [Ошибка подключения]
[Ошибка подключения] --(Повторная попытка)--> [Подключение]
[Активна] --(Навигация по сайту)--> [Активна] (данные накапливаются)
[Активна] --(Закрытие Tag Assistant)--> [Завершена]
[Активна] --(Потеря связи)--> [Отключена]
[Отключена] --(Восстановление связи)--> [Активна]
[Отключена] --(Таймаут)--> [Завершена]
```

### Статусы выполнения тега

```
[Ожидает] --(Событие произошло, условия триггера выполнены, согласие дано)--> [Сработал: Успех]
[Ожидает] --(Событие произошло, условия триггера выполнены, согласие дано, ошибка выполнения)--> [Сработал: Ошибка]
[Ожидает] --(Условия триггера не выполнены)--> [Не сработал: Триггер]
[Ожидает] --(Блокирующий триггер активен)--> [Не сработал: Заблокирован]
[Ожидает] --(Согласие не дано)--> [Не сработал: Согласие]
[Ожидает] --(Несколько причин)--> [Не сработал: Множественные причины]
```

### Статусы серверного запроса

```
[Получен] --(Клиент распознал формат)--> [Принят клиентом]
[Получен] --(Ни один клиент не распознал)--> [Не принят (No Client Claimed)]
[Принят клиентом] --(Событие извлечено)--> [Обработан]
[Обработан] --(Теги отправили запросы)--> [Отправлен]
[Отправлен] --(Ответ 2XX)--> [Успех]
[Отправлен] --(Ответ не 2XX)--> [Ошибка вендора]
```

## Ограничения и лимиты

| Ограничение | Описание |
|---|---|
| Привязка к браузеру | Сессия предпросмотра работает только в браузере, в котором была инициирована (кроме Shared Preview Link) |
| Одна активная сессия | Для одного контейнера в одном браузере может быть активна только одна сессия предпросмотра |
| Не сохраняется между сессиями | История событий и данные отладки не сохраняются после завершения сессии |
| Требует доступа к сайту | Целевой сайт должен быть доступен для браузера пользователя; предпросмотр не работает на сайтах с ограниченным доступом без аутентификации |
| Блокировщики рекламы | Блокировщики рекламы и расширения конфиденциальности могут блокировать работу тегов и искажать результаты отладки |
| CSP / iframe ограничения | Content Security Policy сайта может блокировать подключение Tag Assistant; отладка iframe требует расширения Tag Assistant |
| Серверный контейнер: Preview Server | Для серверного предпросмотра необходим отдельный preview server (может быть тот же tagging server или выделенный) |
| Серверный контейнер: двойной предпросмотр | Для сквозной отладки (web -> server) необходимо активировать предпросмотр обоих контейнеров в правильном порядке: сначала серверный, затем веб |
| Регистрозависимость dataLayer | Имена переменных и событий в dataLayer чувствительны к регистру; несовпадение регистра приводит к тому, что push не работает |
