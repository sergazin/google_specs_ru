# Триггеры

## Описание

Триггеры (Triggers) — модуль Google Tag Manager, определяющий **когда** должны срабатывать теги. Триггер прослушивает веб-страницу или мобильное приложение на предмет определённых событий (загрузка страницы, клики, отправка форм, прокрутка и др.) и при выполнении заданных условий инициирует срабатывание привязанных тегов. Каждый тег должен иметь хотя бы один триггер срабатывания; без триггера тег никогда не выполнится. Триггеры также могут выступать в роли исключений (exceptions), блокируя срабатывание тега при определённых условиях.

---

## Роли пользователей

| Роль | Права в контексте триггеров |
|---|---|
| **Владелец аккаунта (Account Owner)** | Полный доступ ко всем контейнерам и триггерам. Управление правами других пользователей |
| **Администратор контейнера (Container Admin)** | Создание, редактирование, удаление любых триггеров в контейнере. Публикация версий |
| **Редактор (Editor / Publish)** | Создание, редактирование, удаление триггеров. Публикация версий контейнера |
| **Утверждающий (Approve)** | Создание и редактирование триггеров в рабочей области. Утверждение версий, но не публикация |
| **Автор (Edit)** | Создание и редактирование триггеров в рабочей области. Не может публиковать или утверждать |
| **Читатель (Read)** | Просмотр триггеров без возможности изменения |

## Функциональные требования

### FR-TRG-001: Создание триггера

**Описание:** Пользователь с правами редактирования может создать новый триггер в рабочей области контейнера.

**Предусловия:**
- Пользователь авторизован и имеет права Edit или выше
- Выбрана рабочая область (Workspace)

**Основной сценарий:**
1. Пользователь инициирует создание нового триггера
2. Система предлагает выбрать тип триггера из доступных категорий
3. Пользователь задаёт имя триггера
4. Пользователь настраивает параметры, специфичные для выбранного типа
5. Пользователь добавляет условия фильтрации (опционально)
6. Система сохраняет триггер в рабочей области

**Бизнес-правила:**
- BR-001: Имя триггера должно быть непустым
- BR-002: Имя триггера не обязано быть уникальным, но рекомендуется для удобства управления
- BR-003: Триггер создаётся в текущей рабочей области и не влияет на опубликованную версию до публикации
- BR-004: Тип триггера нельзя изменить после создания — необходимо создать новый

### FR-TRG-002: Типы триггеров — Page View (Просмотр страницы)

**Описание:** Группа триггеров, срабатывающих на различных этапах загрузки страницы.

**Подтипы:**

| Подтип | Момент срабатывания | Событие dataLayer |
|---|---|---|
| **Page View** | Сразу при начале загрузки страницы (до полной отрисовки) | gtm.js |
| **DOM Ready** | Когда браузер завершил построение полной модели DOM-дерева | gtm.dom |
| **Window Loaded** | Когда страница полностью загружена, включая все ресурсы (изображения, скрипты) | gtm.load |

**Бизнес-правила:**
- BR-005: Page View срабатывает первым, DOM Ready — вторым, Window Loaded — последним
- BR-006: Все три подтипа могут использоваться одновременно в одном контейнере
- BR-007: Каждый подтип допускает добавление условий фильтрации (по URL, referrer и пр.)

**User stories:**
- Как маркетолог, я хочу запускать пиксель аналитики на всех страницах при начале загрузки, чтобы получать данные о трафике
- Как аналитик, я хочу запускать скрипт после полной загрузки DOM, чтобы корректно отслеживать элементы страницы

### FR-TRG-003: Типы триггеров — Click (Клик)

**Описание:** Триггеры, срабатывающие при кликах пользователя на элементы страницы.

**Подтипы:**

| Подтип | Описание |
|---|---|
| **All Elements (Все элементы)** | Срабатывает при клике на любой HTML-элемент: кнопки, изображения, div-блоки, ссылки и т.д. |
| **Just Links (Только ссылки)** | Срабатывает только при клике на HTML-элементы `<a>` с атрибутом href |

**Параметры подтипа Just Links:**

| Параметр | Описание |
|---|---|
| **Wait for Tags (Ожидание тегов)** | Задерживает переход по ссылке до завершения выполнения всех тегов или истечения таймаута (по умолчанию 2000 мс). Гарантирует, что теги отправят данные до ухода пользователя со страницы |
| **Check Validation (Проверка валидности)** | Триггер срабатывает только при валидном действии клика. Если отключено, тег срабатывает при любом клике по ссылке |

**Встроенные переменные клика:**
- Click Element — HTML-элемент, по которому кликнули
- Click Classes — CSS-классы элемента
- Click ID — атрибут id элемента
- Click Target — атрибут target ссылки
- Click URL — URL ссылки
- Click Text — текстовое содержимое элемента

**Бизнес-правила:**
- BR-008: All Elements отслеживает клики по всем элементам DOM, включая дочерние элементы
- BR-009: Just Links отслеживает только элементы `<a>` с href
- BR-010: Wait for Tags актуален только для Just Links, так как All Elements не вызывает перехода
- BR-011: Переменные клика автоматически заполняются при каждом событии клика

**User stories:**
- Как маркетолог, я хочу отслеживать клики по кнопке "Купить", чтобы измерить конверсию
- Как аналитик, я хочу отслеживать клики по исходящим ссылкам с ожиданием тегов, чтобы данные гарантированно отправлялись до перехода

---

### FR-TRG-004: Типы триггеров — Form Submission (Отправка формы)

**Описание:** Триггер срабатывает при отправке HTML-формы на странице.

**Параметры:**

| Параметр | Описание |
|---|---|
| **Wait for Tags** | Задерживает отправку формы до завершения всех тегов или истечения таймаута |
| **Check Validation** | Триггер срабатывает только если форма прошла валидацию (встроенную HTML5 или пользовательскую) |

**Встроенные переменные:**
- Form Element — HTML-элемент формы
- Form Classes — CSS-классы формы
- Form ID — атрибут id формы
- Form Target — атрибут target формы
- Form URL — URL атрибута action формы
- Form Text — текстовое содержимое формы

**Бизнес-правила:**
- BR-012: Без Check Validation триггер срабатывает при любом submit, даже если форма невалидна
- BR-013: С Check Validation триггер срабатывает только при успешной валидации
- BR-014: Wait for Tags гарантирует, что теги отработают до фактической отправки данных формы

**User stories:**
- Как маркетолог, я хочу отслеживать отправку формы заявки, чтобы фиксировать лиды
- Как аналитик, я хочу отслеживать только успешные отправки форм (с проверкой валидации), чтобы не считать ошибочные попытки

---

### FR-TRG-005: Типы триггеров — Element Visibility (Видимость элемента)

**Описание:** Триггер срабатывает, когда указанный HTML-элемент становится видимым в области просмотра (viewport) браузера.

**Параметры:**

| Параметр | Описание |
|---|---|
| **Selection Method (Метод выбора)** | **ID** — выбор элемента по атрибуту id; **CSS Selector** — выбор одного или нескольких элементов по CSS-селектору |
| **Element ID / Element Selector** | Значение ID или CSS-селектор для поиска целевого элемента |
| **Minimum Percent Visible (Минимальный процент видимости)** | Какая доля элемента должна быть видима для срабатывания (по умолчанию 50%) |
| **Minimum On-Screen Duration (Минимальное время на экране)** | Сколько миллисекунд элемент должен быть видим непрерывно перед срабатыванием |
| **Observe DOM Changes (Отслеживать изменения DOM)** | Если включено, триггер отслеживает элементы, появляющиеся динамически (попапы, лениво загружаемый контент) |

**Частота срабатывания:**

| Опция | Описание |
|---|---|
| **Once per page (Раз на страницу)** | Триггер сработает только один раз за загрузку страницы |
| **Once per element (Раз на элемент)** | Если CSS-селектор находит несколько элементов, триггер сработает по одному разу для каждого |
| **Every time an element appears on screen (При каждом появлении)** | Триггер срабатывает каждый раз, когда элемент становится видимым |

**Встроенные переменные:**
- Percent Visible — процент видимой площади элемента (0-100)
- On-Screen Duration — время нахождения элемента на экране (мс)

**Бизнес-правила:**
- BR-015: Элемент считается видимым при загрузке страницы, прокрутке, переключении вкладки на передний план или программном показе
- BR-016: Observe DOM Changes необходимо включать для динамически добавляемых элементов (AJAX, SPA)
- BR-017: Минимальный процент видимости от 1 до 100

**User stories:**
- Как маркетолог, я хочу знать, видел ли пользователь баннер с акцией, чтобы оценить охват
- Как аналитик, я хочу отслеживать, что пользователь увидел блок с ценами (не менее 75% элемента, не менее 3 секунд), чтобы оценить вовлечённость

### FR-TRG-006: Типы триггеров — Scroll Depth (Глубина прокрутки)

**Описание:** Триггер срабатывает при достижении определённой глубины прокрутки страницы.

**Параметры:**

| Параметр | Описание |
|---|---|
| **Vertical Scroll Depths (Вертикальная прокрутка)** | Отслеживание прокрутки сверху вниз |
| **Horizontal Scroll Depths (Горизонтальная прокрутка)** | Отслеживание прокрутки слева направо |
| **Percentages (Проценты)** | Пороговые значения в процентах от высоты/ширины страницы (напр., 25, 50, 75, 90) |
| **Pixels (Пиксели)** | Пороговые значения в абсолютных пикселях |

**Встроенные переменные:**
- Scroll Depth Threshold — значение порога (число)
- Scroll Depth Units — единицы измерения (percent/pixels)
- Scroll Direction — направление прокрутки (vertical/horizontal)

**Бизнес-правила:**
- BR-018: Вертикальная и горизонтальная прокрутка могут использоваться одновременно в одном триггере
- BR-019: Проценты и пиксели могут задаваться списком через запятую (напр., 25, 50, 75, 100)
- BR-020: Каждое пороговое значение срабатывает не более одного раза за загрузку страницы
- BR-021: Триггер фиксирует факт прохождения порога при прокрутке вниз, повторная прокрутка вверх и вниз не вызывает повторного срабатывания

**User stories:**
- Как контент-менеджер, я хочу знать, какой процент пользователей доскролливает до конца статьи, чтобы оценить качество контента
- Как маркетолог, я хочу показывать ретаргетинговый пиксель только тем, кто просмотрел хотя бы 50% страницы

### FR-TRG-007: Типы триггеров — YouTube Video (Видео YouTube)

**Описание:** Триггер срабатывает при взаимодействии пользователя с встроенным видеоплеером YouTube на странице.

**Параметры захвата событий:**

| Событие | Описание |
|---|---|
| **Start (Начало)** | Видео начало воспроизведение |
| **Complete (Завершение)** | Видео воспроизведено до конца |
| **Pause (Пауза)** | Пользователь поставил видео на паузу |
| **Seeking (Перемотка)** | Пользователь переместил ползунок воспроизведения |
| **Buffering (Буферизация)** | Видео перешло в состояние буферизации |
| **Progress (Прогресс)** | Видео достигло указанных точек прогресса |

**Настройка Progress:**
- По процентам — через запятую (напр., 10, 25, 50, 75)
- По времени — в секундах через запятую (напр., 5, 15, 30, 60)

**Дополнительная опция:**
- **Add JavaScript API support to all YouTube videos** — автоматически добавляет параметр enablejsapi=1 к iframe YouTube для активации API отслеживания

**Встроенные переменные:**
- Video Provider — всегда "youtube"
- Video Status — статус события (start, complete, pause, seeking, buffering, progress)
- Video URL — URL видео
- Video Title — заголовок видео
- Video Duration — общая длительность видео (секунды)
- Video Current Time — текущая позиция воспроизведения (секунды)
- Video Percent — процент просмотра
- Video Visible — находится ли плеер в области видимости

**Бизнес-правила:**
- BR-022: Для работы триггера видеоплеер должен быть встроен через iframe YouTube
- BR-023: Опция JavaScript API автоматически модифицирует iframe для добавления поддержки API
- BR-024: Прогресс-события срабатывают однократно для каждого порога за сеанс воспроизведения
- BR-025: Триггер не работает с видеоплеерами других провайдеров (Vimeo, собственные плееры)

**User stories:**
- Как маркетолог, я хочу знать, сколько пользователей досмотрели обучающее видео до конца, чтобы оценить вовлечённость
- Как аналитик, я хочу отслеживать процент просмотра промо-ролика (25%, 50%, 75%, 100%), чтобы оптимизировать контент

### FR-TRG-008: Типы триггеров — Custom Event (Пользовательское событие)

**Описание:** Триггер срабатывает при появлении указанного пользовательского события в dataLayer.

**Параметры:**

| Параметр | Описание |
|---|---|
| **Event Name (Имя события)** | Строка, которая должна совпасть с именем события, переданным через dataLayer.push({event: 'eventName'}) |
| **Use regex matching** | Если включено, имя события интерпретируется как регулярное выражение |

**Бизнес-правила:**
- BR-026: Имя события сопоставляется строго (exact match) по умолчанию
- BR-027: При включении regex имя события может содержать регулярное выражение для гибкого сопоставления
- BR-028: Custom Event — основной способ интеграции с внешними скриптами и сервисами (CRM-формы, чат-боты, платёжные системы)
- BR-029: Разработчик сайта должен реализовать push события в dataLayer для срабатывания триггера

**User stories:**
- Как маркетолог, я хочу отслеживать событие "purchase_complete" из нашей платёжной системы, чтобы фиксировать конверсии
- Как аналитик, я хочу одним триггером ловить все события, начинающиеся с "form_" (через regex), чтобы централизованно обрабатывать формы

### FR-TRG-009: Типы триггеров — History Change (Изменение истории)

**Описание:** Триггер срабатывает при изменении фрагмента URL (hash) или при использовании HTML5 History API (pushState / popState). Критически важен для одностраничных приложений (SPA).

**Встроенные переменные:**
- History Source — источник события (pushState, replaceState, popstate, hashchange)
- New History Fragment — новый фрагмент URL (после #)
- Old History Fragment — предыдущий фрагмент URL
- New History State — новый объект состояния history
- Old History State — предыдущий объект состояния history

**Бизнес-правила:**
- BR-030: Триггер отслеживает как изменения hash (#), так и pushState/replaceState
- BR-031: Необходим для корректного отслеживания навигации в SPA (React, Angular, Vue)
- BR-032: Срабатывает при каждом изменении истории, если не ограничен условиями фильтрации

**User stories:**
- Как аналитик, я хочу отслеживать виртуальные просмотры страниц в нашем SPA-приложении, чтобы корректно считать трафик
- Как маркетолог, я хочу запускать пиксель конверсии при переходе на определённый hash-маршрут

---

### FR-TRG-010: Типы триггеров — Timer (Таймер)

**Описание:** Триггер срабатывает по истечении заданного интервала времени. Может срабатывать повторно через равные промежутки.

**Параметры:**

| Параметр | Описание |
|---|---|
| **Event Name** | Имя события в dataLayer (по умолчанию gtm.timer) |
| **Interval (Интервал)** | Время в миллисекундах между срабатываниями (напр., 10000 = 10 секунд) |
| **Limit (Лимит)** | Максимальное количество срабатываний. Пустое значение = без ограничений |

**Бизнес-правила:**
- BR-033: Таймер запускается при загрузке страницы (или при выполнении условий фильтрации)
- BR-034: Первое срабатывание происходит через один интервал после старта
- BR-035: При Limit = 1 триггер сработает ровно один раз
- BR-036: Без лимита таймер срабатывает бесконечно, пока страница открыта
- BR-037: Таймер останавливается при уходе со страницы

**User stories:**
- Как маркетолог, я хочу показать попап-опрос через 30 секунд пребывания на странице
- Как аналитик, я хочу каждые 60 секунд отправлять событие "heartbeat" для измерения вовлечённости

---

### FR-TRG-011: Типы триггеров — Trigger Group (Группа триггеров)

**Описание:** Составной триггер, который срабатывает только когда все включённые в группу триггеры сработали хотя бы по одному разу.

**Параметры:**
- Набор из двух или более существующих триггеров контейнера
- Возможность добавить один и тот же триггер несколько раз (для требования многократного срабатывания)

**Бизнес-правила:**
- BR-038: Группа срабатывает только когда ВСЕ входящие триггеры сработали (логическое И)
- BR-039: Порядок срабатывания входящих триггеров не имеет значения
- BR-040: Один триггер может быть добавлен в группу несколько раз — тогда он должен сработать соответствующее число раз
- BR-041: Trigger Group работает в пределах одной загрузки страницы
- BR-042: Минимальное количество триггеров в группе — 2

**User stories:**
- Как маркетолог, я хочу показать тег конверсии только когда пользователь И прокрутил страницу до 75%, И кликнул по CTA-кнопке
- Как аналитик, я хочу зафиксировать событие "engaged user", когда пользователь просмотрел видео на 50% И провёл на странице более 30 секунд

### FR-TRG-012: Условия фильтрации триггеров (Trigger Conditions / Filters)

**Описание:** Каждый триггер может содержать одно или несколько условий фильтрации, определяющих, при каких обстоятельствах триггер сработает (или не сработает). Условия действуют как дополнительные ограничения поверх базового события.

**Структура условия:**
Каждое условие состоит из трёх компонентов:
1. **Переменная (Variable)** — встроенная или пользовательская переменная GTM
2. **Оператор (Operator)** — логический оператор сравнения
3. **Значение (Value)** — строка или число для сравнения

**Доступные операторы:**

| Оператор | Описание |
|---|---|
| **equals (равно)** | Точное совпадение строки |
| **contains (содержит)** | Подстрока присутствует в значении |
| **starts with (начинается с)** | Значение начинается с указанной строки |
| **ends with (заканчивается на)** | Значение заканчивается указанной строкой |
| **matches RegEx (соответствует регулярному выражению)** | Совпадение по regex (регистрозависимо) |
| **matches RegEx (ignore case)** | Совпадение по regex (регистронезависимо) |
| **matches CSS selector** | Элемент соответствует CSS-селектору |
| **does not equal** | Не равно |
| **does not contain** | Не содержит |
| **does not start with** | Не начинается с |
| **does not end with** | Не заканчивается на |
| **does not match RegEx** | Не соответствует regex |
| **does not match RegEx (ignore case)** | Не соответствует regex (без учёта регистра) |
| **less than (меньше)** | Числовое сравнение: меньше |
| **less than or equals (меньше или равно)** | Числовое сравнение: меньше или равно |
| **greater than (больше)** | Числовое сравнение: больше |
| **greater than or equals (больше или равно)** | Числовое сравнение: больше или равно |

**Бизнес-правила:**
- BR-043: Несколько условий в одном триггере объединяются логическим **И** (AND) — все должны выполняться одновременно
- BR-044: Для реализации логического **ИЛИ** (OR) необходимо создать отдельные триггеры и привязать их к одному тегу
- BR-045: Regex по умолчанию работает в режиме частичного совпадения (contains); для точного совпадения нужны якоря ^ и $
- BR-046: CSS-селектор применим только к триггерам, связанным с элементами (Click, Form, Visibility)
- BR-047: Переменная в условии может быть любой встроенной или пользовательской переменной контейнера

**User stories:**
- Как маркетолог, я хочу запускать тег только на страницах каталога (URL содержит "/catalog/"), чтобы не перегружать другие страницы
- Как аналитик, я хочу создать триггер клика только по кнопкам с классом "btn-purchase", чтобы отслеживать целевые действия

### FR-TRG-013: Исключающие триггеры (Trigger Exceptions / Blocking Triggers)

**Описание:** Исключающий триггер (exception) привязывается к тегу и блокирует его срабатывание при выполнении условий исключения, даже если основной триггер сработал.

**Бизнес-правила:**
- BR-048: Исключающий триггер и обычный триггер создаются одинаково — различие только в способе привязки к тегу
- BR-049: Один и тот же триггер может одновременно быть основным триггером для одного тега и исключающим для другого
- BR-050: Тип события исключающего триггера **должен совпадать** с типом события основного триггера. Нельзя заблокировать Click-триггер с помощью Page View-исключения
- BR-051: Если условия исключающего триггера выполнены, тег не срабатывает, даже если условия основного триггера выполнены
- BR-052: К одному тегу может быть привязано несколько исключающих триггеров
- BR-053: Исключающие триггеры оцениваются одновременно с основными, не последовательно

**Типичные сценарии исключений:**
- Блокировка тега на определённых страницах (напр., страница "спасибо")
- Блокировка тега для определённых устройств (мобильные / десктоп)
- Блокировка тега в тестовых/staging окружениях
- Блокировка тега при отсутствии согласия на cookie (consent management)

**User stories:**
- Как маркетолог, я хочу запускать тег аналитики на всех страницах, кроме страницы политики конфиденциальности
- Как аналитик, я хочу блокировать рекламные теги для пользователей, не давших согласие на cookie

### FR-TRG-014: Опции срабатывания тегов (Tag Firing Options)

**Описание:** Для каждого тега можно указать частоту срабатывания при многократной активации триггера.

**Опции:**

| Опция | Описание |
|---|---|
| **Once per event (Раз на событие)** | Тег срабатывает при каждом уникальном событии триггера (по умолчанию). Если пользователь кликнул 3 раза — тег сработает 3 раза |
| **Once per page (Раз на страницу)** | Тег сработает только один раз за загрузку страницы, даже если триггер активировался многократно |
| **Unlimited (Без ограничений)** | Специальная опция для последовательности тегов (Tag Sequencing). Тег срабатывает при каждой активации без ограничений |

**Бизнес-правила:**
- BR-054: Once per event — наиболее распространённая настройка
- BR-055: Once per page актуальна для обычных сайтов, но не рекомендуется для SPA без дополнительной логики
- BR-056: Unlimited используется преимущественно в контексте Tag Sequencing

---

### FR-TRG-015: Редактирование триггера

**Описание:** Пользователь может изменить параметры существующего триггера.

**Бизнес-правила:**
- BR-057: Тип триггера (Page View, Click и т.д.) нельзя изменить — необходимо создать новый
- BR-058: Изменения триггера применяются ко всем тегам, использующим этот триггер
- BR-059: Изменения сохраняются в текущей рабочей области и не влияют на опубликованную версию
- BR-060: При изменении триггера, используемого несколькими тегами, все связанные теги будут затронуты

---

### FR-TRG-016: Удаление триггера

**Описание:** Пользователь может удалить триггер из рабочей области.

**Бизнес-правила:**
- BR-061: Триггер нельзя удалить, если он используется хотя бы одним тегом
- BR-062: Для удаления необходимо сначала отвязать триггер от всех тегов
- BR-063: Удаление происходит в рабочей области и применяется после публикации

---

### FR-TRG-017: Копирование триггера

**Описание:** Пользователь может создать копию существующего триггера с сохранением всех параметров.

**Бизнес-правила:**
- BR-064: Копия создаётся с суффиксом "Copy of" к имени
- BR-065: Копия не привязана к тегам оригинала — это независимый триггер
- BR-066: Все условия фильтрации и параметры копируются полностью

## Сущности данных

### Trigger (Триггер)

| Поле | Описание | Обязательное |
|---|---|---|
| triggerId | Уникальный идентификатор триггера в контейнере | Да (генерируется) |
| name | Имя триггера | Да |
| type | Тип триггера (pageview, domReady, windowLoaded, click, linkClick, formSubmission, elementVisibility, scrollDepth, youtubeVideo, customEvent, historyChange, timer, triggerGroup) | Да |
| filters | Массив условий фильтрации [{variable, operator, value}] | Нет |
| customEventFilter | Условие на имя пользовательского события (для Custom Event) | Для Custom Event |
| parameters | Параметры, специфичные для типа триггера | Зависит от типа |
| workspaceId | Рабочая область, в которой создан триггер | Да (контекст) |
| containerId | Контейнер, к которому относится триггер | Да (контекст) |
| fingerprint | Отпечаток для контроля версий | Да (генерируется) |

### TriggerCondition (Условие фильтрации)

| Поле | Описание |
|---|---|
| variable | Переменная GTM для сравнения |
| operator | Оператор сравнения |
| value | Значение для сопоставления |

### TriggerGroup (Группа триггеров)

| Поле | Описание |
|---|---|
| triggerId | Идентификатор группового триггера |
| memberTriggers | Массив ссылок на входящие триггеры (с возможностью дублирования) |

## Состояния и статусы

### Жизненный цикл триггера

```
[Создан в Workspace] → [Настроен] → [Привязан к тегу] → [Опубликован]
       ↑                                                        ↓
       ← ← ← ← ← [Изменён в новом Workspace] ← ← ← ← ← ← ← ←
```

| Состояние | Описание |
|---|---|
| **Draft (Черновик)** | Триггер создан или изменён в рабочей области, но не опубликован |
| **Published (Опубликован)** | Триггер включён в опубликованную версию контейнера и активен на сайте |
| **Modified (Изменён)** | Триггер изменён в рабочей области относительно опубликованной версии |
| **Deleted (Удалён)** | Триггер удалён в рабочей области (удаление применяется после публикации) |

### Состояния привязки к тегам

| Состояние | Описание |
|---|---|
| **Unlinked (Не привязан)** | Триггер существует, но не привязан ни к одному тегу. Не оказывает влияния на работу контейнера |
| **Firing Trigger (Активирующий)** | Триггер привязан к тегу как основной — инициирует срабатывание тега |
| **Exception (Исключающий)** | Триггер привязан к тегу как исключение — блокирует срабатывание тега |
| **Both (Обе роли)** | Триггер одновременно является активирующим для одного тега и исключающим для другого |

## Ограничения и лимиты

| Ограничение | Значение |
|---|---|
| Максимальное количество триггеров в контейнере (бесплатная версия) | ~2000 |
| Максимальное количество триггеров в контейнере (GTM 360) | Без ограничений |

| Минимальный интервал таймера | Нет формального ограничения (рекомендуется >= 1000 мс) |

## Интеграции с другими модулями

### Теги (Tags)
- Триггер привязывается к тегу как активирующий (firing) или исключающий (exception)
- Один триггер может быть привязан к нескольким тегам
- Один тег может иметь несколько активирующих триггеров (логика ИЛИ между ними)
- Один тег может иметь несколько исключающих триггеров

### Переменные (Variables)
- Условия фильтрации триггеров используют переменные GTM (встроенные и пользовательские) для сопоставления
- Каждый тип триггера автоматически заполняет набор встроенных переменных (Click URL, Form ID, Scroll Depth Threshold и т.д.)
- Пользовательские переменные (Data Layer Variable, JavaScript Variable, Lookup Table и пр.) расширяют возможности условий

### Рабочие области (Workspaces)
- Триггеры создаются и редактируются в контексте рабочей области
- Изменения в одной рабочей области не видны в других до публикации
- При конфликтах между рабочими областями (изменение одного триггера в двух Workspace) требуется ручное разрешение при публикации

### Версии и публикация (Versions)
- Триггеры включаются в версию контейнера при публикации
- Возврат к предыдущей версии восстанавливает триггеры в состояние той версии
- История версий позволяет отслеживать, кто и когда изменил триггер

### DataLayer
- Custom Event триггеры прослушивают события, отправленные через dataLayer.push()
- Данные из dataLayer доступны через переменные типа Data Layer Variable и могут использоваться в условиях триггеров
- History Change и Timer генерируют собственные события в dataLayer (gtm.historyChange, gtm.timer)

### Режим предварительного просмотра (Preview / Debug Mode)
- Все триггеры тестируются через режим Preview
- В режиме Preview отображается, какие триггеры сработали, какие не сработали и почему (какие условия не выполнены)
- Debug-панель показывает список событий и связанных триггеров в хронологическом порядке

### Consent Mode (Управление согласием)
- Исключающие триггеры часто используются для блокировки тегов при отсутствии согласия пользователя на обработку cookie
- Интеграция с системами управления согласием (CMP) через Custom Event или переменные согласия
