# Переменные

## Описание

Модуль "Переменные" (Variables) в Google Tag Manager отвечает за хранение, извлечение и передачу данных между тегами, триггерами и другими переменными. Переменные являются именованными заполнителями для значений, которые динамически подставляются во время выполнения: при загрузке страницы, при клике, при отправке формы и других событиях. Модуль делится на две категории: встроенные переменные (Built-in Variables), предоставляемые платформой без настройки, и пользовательские переменные (User-Defined Variables), создаваемые вручную для специфических бизнес-задач.

Переменные используются в двух контекстах:
1. **В триггерах** --- для определения условий срабатывания (например, "Page Path содержит /checkout")
2. **В тегах** --- для подстановки динамических значений (например, передача идентификатора транзакции в Google Analytics)

Синтаксис обращения к переменной в тегах и триггерах: `{{Variable Name}}`.

---

## Роли пользователей

| Роль | Уровень | Действия с переменными |
|------|---------|----------------------|
| **Просмотр (Read)** | Контейнер | Просмотр списка переменных и их конфигурации. Не может создавать, изменять или удалять переменные |
| **Редактирование (Edit)** | Контейнер | Создание, изменение, удаление переменных в рабочей области (Workspace). Не может создавать версии и публиковать |
| **Утверждение (Approve)** | Контейнер | Все права Edit + создание версий контейнера с изменениями переменных. Не может публиковать |
| **Публикация (Publish)** | Контейнер | Полные права: создание, редактирование, удаление переменных, создание версий и публикация на рабочий сайт |
| **Администратор (Admin)** | Аккаунт | Управление доступом пользователей к контейнерам, включая контроль над модулем переменных |

**Бизнес-правила ролей:**
- BR-ROLE-001: Права наследуются сверху вниз --- если у пользователя есть право Publish, он автоматически имеет Edit и Read
- BR-ROLE-002: Прямые разрешения (Direct) сохраняются даже при потере унаследованных (Inherited) разрешений
- BR-ROLE-003: Изменения переменных вступают в силу только после публикации версии контейнера пользователем с правом Publish

## Функциональные требования

### Категория A: Встроенные переменные (Built-in Variables)

---

### FR-VAR-001: Управление встроенными переменными

**Описание:** Система предоставляет предопределённый набор переменных, сгруппированных по категориям, которые пользователь может включать и отключать без необходимости создания или настройки.

**Поведение:**
- При создании нового контейнера активированы только базовые встроенные переменные (Page URL, Page Hostname, Page Path, Referrer, Event)
- Остальные встроенные переменные доступны для активации через панель "Настроить" (Configure)
- Включение/отключение не требует создания версии --- переменная сразу становится доступной в рабочей области
- Встроенные переменные нельзя переименовать, удалить или изменить их логику

**Бизнес-правила:**
- BR-VAR-001: Встроенные переменные не учитываются в лимите размера контейнера (200 КБ)
- BR-VAR-002: Отключение встроенной переменной не удаляет её --- она может быть повторно активирована в любой момент
- BR-VAR-003: Если встроенная переменная используется в теге или триггере и затем отключена, ссылки на неё перестают разрешаться

**User Story:**
> Как маркетолог, я хочу быстро активировать нужные встроенные переменные, чтобы использовать стандартные данные о странице и событиях без написания кода.

---

### FR-VAR-002: Встроенные переменные категории "Страницы" (Pages)

**Описание:** Переменные, извлекающие информацию о текущей загруженной странице.

**Состав:**

| Переменная | Ключ dataLayer | Возвращаемое значение |
|-----------|---------------|----------------------|
| Page URL | --- | Полный URL текущей страницы (включая протокол, домен, путь, параметры) |
| Page Hostname | --- | Имя хоста текущей страницы (например, `www.example.com`) |
| Page Path | --- | Относительный путь страницы (например, `/products/shoes`) |
| Referrer | --- | URL предыдущей страницы, с которой пользователь перешёл |

**Бизнес-правила:**
- BR-VAR-004: Page URL включает query-параметры и хэш-фрагменты
- BR-VAR-005: Referrer возвращает пустую строку, если переход был прямым (direct) или referrer заблокирован политикой безопасности
- BR-VAR-006: Все переменные страницы доступны с момента первого события контейнера (gtm.js)

**User Story:**
> Как аналитик, я хочу использовать Page Path в триггере, чтобы активировать тег конверсии только на странице /checkout/success.

---

### FR-VAR-003: Встроенные переменные категории "Клики" (Clicks)

**Описание:** Переменные, фиксирующие данные о DOM-элементе, по которому произошёл клик.

**Состав:**

| Переменная | Ключ dataLayer | Возвращаемое значение |
|-----------|---------------|----------------------|
| Click Element | gtm.element | Ссылка на DOM-элемент, по которому кликнул пользователь |
| Click Classes | gtm.elementClasses | Строковое значение атрибута `class` элемента |
| Click ID | gtm.elementId | Значение атрибута `id` элемента |
| Click URL | gtm.elementUrl | URL из атрибута `href` (для ссылок) или `action` (для форм) |
| Click Target | gtm.elementTarget | Значение атрибута `target` элемента (например, `_blank`) |
| Click Text | gtm.elementText | Текстовое содержимое элемента |

**Бизнес-правила:**
- BR-VAR-007: Переменные кликов заполняются только при срабатывании событий All Clicks, Just Links или пользовательских click-событий
- BR-VAR-008: Click Element возвращает ссылку на DOM-объект, а не строку --- его нельзя передать как текст в тег аналитики
- BR-VAR-009: Если у элемента нет соответствующего атрибута (например, нет id), переменная возвращает пустую строку
- BR-VAR-010: Click URL для обычных элементов (не ссылок и не форм) возвращает пустую строку

**User Story:**
> Как маркетолог, я хочу отслеживать клики по кнопке "Купить" с определённым CSS-классом, чтобы считать микроконверсии в воронке продаж.

### FR-VAR-004: Встроенные переменные категории "Формы" (Forms)

**Описание:** Переменные, фиксирующие данные о формах при их отправке.

**Состав:**

| Переменная | Ключ dataLayer | Возвращаемое значение |
|-----------|---------------|----------------------|
| Form Element | gtm.element | Ссылка на DOM-элемент формы |
| Form Classes | gtm.elementClasses | CSS-классы формы |
| Form ID | gtm.elementId | Атрибут `id` формы |
| Form URL | gtm.elementUrl | Значение атрибута `action` формы |
| Form Target | gtm.elementTarget | Значение атрибута `target` формы |
| Form Text | gtm.elementText | Текстовое содержимое формы |

**Бизнес-правила:**
- BR-VAR-011: Переменные форм заполняются только при событии Form Submission
- BR-VAR-012: Form Element возвращает ссылку на DOM-объект `<form>`, а не на кнопку submit
- BR-VAR-013: Если форма отправляется через AJAX без стандартного submit, переменные могут не заполниться

**User Story:**
> Как маркетолог, я хочу различать отправки разных форм на одной странице (заявка, подписка, обратный звонок) по их Form ID, чтобы считать конверсии отдельно.

### FR-VAR-005: Встроенные переменные категории "Прокрутка" (Scrolling)

**Описание:** Переменные, фиксирующие данные о глубине прокрутки страницы.

**Состав:**

| Переменная | Ключ dataLayer | Возвращаемое значение |
|-----------|---------------|----------------------|
| Scroll Depth Threshold | gtm.scrollThreshold | Пороговое значение прокрутки (число: процент или пиксели) |
| Scroll Depth Units | gtm.scrollUnits | Единица измерения: `percent` или `pixels` |
| Scroll Direction | gtm.scrollDirection | Направление прокрутки: `vertical` или `horizontal` |

**Бизнес-правила:**
- BR-VAR-014: Переменные прокрутки заполняются только при срабатывании триггера типа Scroll Depth
- BR-VAR-015: Пороговые значения задаются в конфигурации триггера, а не в переменных
- BR-VAR-016: При одной загрузке страницы каждый порог срабатывает максимум один раз

**User Story:**
> Как контент-менеджер, я хочу знать, какой процент пользователей дочитывает статью до конца (прокрутка 90%), чтобы оценить качество контента.

### FR-VAR-006: Встроенные переменные категории "Видимость" (Visibility)

**Описание:** Переменные, связанные с появлением элементов в видимой области экрана.

**Состав:**

| Переменная | Ключ dataLayer | Возвращаемое значение |
|-----------|---------------|----------------------|
| Percent Visible | gtm.visibleRatio | Процент видимости элемента (0-100) |
| On-Screen Duration | gtm.visibleTime | Время нахождения элемента в видимой области (мс) |

**Бизнес-правила:**
- BR-VAR-017: Переменные видимости заполняются только при срабатывании триггера Element Visibility
- BR-VAR-018: Процент видимости вычисляется на основе пересечения области элемента с видимой областью окна браузера

**User Story:**
> Как рекламодатель, я хочу фиксировать, когда баннер становится видимым на 50% и более на 2 секунды, чтобы считать реальные показы рекламы.

### FR-VAR-007: Встроенные переменные категории "История" (History)

**Описание:** Переменные, фиксирующие изменения в истории браузера (для SPA-приложений).

**Состав:**

| Переменная | Ключ dataLayer | Возвращаемое значение |
|-----------|---------------|----------------------|
| New History Fragment | gtm.newUrlFragment | Новый хэш-фрагмент URL после изменения |
| Old History Fragment | gtm.oldUrlFragment | Предыдущий хэш-фрагмент URL |
| New History State | gtm.newHistoryState | Новый объект состояния History API |
| Old History State | gtm.oldHistoryState | Предыдущий объект состояния History API |
| History Source | gtm.historyChangeSource | Источник изменения: `pushState`, `replaceState`, `popstate`, `hashchange` |

**Бизнес-правила:**
- BR-VAR-019: Переменные истории заполняются только при срабатывании триггера History Change
- BR-VAR-020: Критически важны для SPA (Single Page Applications), где навигация не вызывает полную перезагрузку
- BR-VAR-021: History State возвращает объект, а не строку --- может содержать вложенные данные

**User Story:**
> Как аналитик SPA-приложения, я хочу фиксировать каждый переход между "страницами" через History Change, чтобы отправлять виртуальные просмотры страниц в Google Analytics.

### FR-VAR-008: Встроенные переменные категории "Ошибки" (Errors)

**Описание:** Переменные, фиксирующие JavaScript-ошибки на странице.

**Состав:**

| Переменная | Ключ dataLayer | Возвращаемое значение |
|-----------|---------------|----------------------|
| Error Message | gtm.errorMessage | Текст сообщения об ошибке |
| Error URL | gtm.errorUrl | URL скрипта, в котором произошла ошибка |
| Error Line | gtm.errorLineNumber | Номер строки, на которой произошла ошибка |
| Debug Mode | --- | `true`, если контейнер запущен в режиме отладки |

**Бизнес-правила:**
- BR-VAR-022: Переменные ошибок заполняются только при срабатывании триггера JavaScript Error
- BR-VAR-023: Не все ошибки перехватываются --- ошибки в try/catch не генерируют событие window.onerror
- BR-VAR-024: Debug Mode возвращает `true` только при использовании режима предварительного просмотра GTM

**User Story:**
> Как разработчик, я хочу логировать JavaScript-ошибки на сайте через GTM, чтобы мониторить стабильность фронтенда без внедрения отдельного инструмента.

### FR-VAR-009: Встроенные переменные категории "Утилиты" (Utilities)

**Описание:** Служебные переменные общего назначения.

**Состав:**

| Переменная | Возвращаемое значение |
|-----------|----------------------|
| Event | Имя текущего события dataLayer (например, `gtm.js`, `gtm.dom`, `gtm.load`, пользовательское) |
| Environment Name | Имя текущего окружения (`Live`, `Latest`, `Now Editing` или пользовательское) |
| Container ID | Идентификатор контейнера GTM (например, `GTM-XXXXXX`) |
| Container Version | Номер опубликованной версии контейнера |
| Random Number | Случайное число (целое) |
| HTML ID | Идентификатор, позволяющий пользовательским HTML-тегам сигнализировать об успехе/неудаче |
| Client ID | Идентификатор клиента из cookie Google Analytics |
| Session ID | Идентификатор текущей сессии Google Analytics |
| Session Number | Порядковый номер сессии пользователя |

**Бизнес-правила:**
- BR-VAR-025: Event доступен всегда и содержит имя события, вызвавшего текущую обработку
- BR-VAR-026: Environment Name возвращает пустую строку, если контейнер запущен вне именованного окружения
- BR-VAR-027: Random Number генерирует новое значение при каждом обращении
- BR-VAR-028: Container Version возвращает номер опубликованной версии, а не версии рабочей области
- BR-VAR-029: Client ID, Session ID и Session Number предоставляют официально поддерживаемый способ получения идентификаторов GA непосредственно в GTM

**User Story:**
> Как аналитик, я хочу использовать Container Version в отладочных тегах, чтобы понимать, какая версия контейнера активна на сайте в данный момент.

### FR-VAR-010: Создание пользовательской переменной

**Описание:** Пользователь с правом Edit создаёт новую переменную, выбирая тип и задавая конфигурацию.

**Поведение:**
- Пользователь указывает имя переменной и выбирает тип из списка доступных типов
- Для каждого типа отображается специфичная форма настройки
- После сохранения переменная доступна в рабочей области для использования в тегах и триггерах
- Изменения вступают в силу на рабочем сайте только после публикации версии контейнера

**Бизнес-правила:**
- BR-VAR-030: Имя переменной должно быть уникальным в пределах контейнера (без учёта регистра)
- BR-VAR-031: Имя переменной не может совпадать с именем встроенной переменной
- BR-VAR-032: Рекомендуемый формат именования: `Тип - Описание` (например, `DLV - Transaction ID`, `CJS - Format Phone`)
- BR-VAR-033: Пользовательские переменные учитываются в общем лимите размера контейнера (200 КБ)
- BR-VAR-034: Удаление переменной, используемой в тегах или триггерах, приводит к неразрешённым ссылкам

**User Story:**
> Как маркетолог, я хочу создать пользовательскую переменную для извлечения идентификатора заказа из Data Layer, чтобы передавать его в тег конверсии.

### FR-VAR-011: Форматирование значения переменной (Format Value)

**Описание:** Для любой пользовательской переменной доступна опция форматирования возвращаемого значения.

**Поведение:**
- Преобразование регистра: приведение строки к нижнему регистру (lowercase) или верхнему (UPPERCASE)
- Замена значения `undefined`: подстановка указанной строки или значения другой переменной
- Замена значения `null`: подстановка указанной строки или значения другой переменной
- Замена значения `true`/`false`: подстановка пользовательских строк вместо булевых значений

**Бизнес-правила:**
- BR-VAR-035: Форматирование применяется после вычисления основного значения переменной
- BR-VAR-036: Преобразование регистра применяется только к строковым значениям
- BR-VAR-037: Если значение `undefined` и задана замена --- подставляется замена; если замена не задана --- переменная возвращает `undefined`
- BR-VAR-038: Google Analytics теги отбрасывают параметры со значением `undefined` из отправляемого хита

**User Story:**
> Как аналитик, я хочу настроить замену `undefined` на пустую строку для переменной категории товара, чтобы избежать слова "undefined" в отчётах Google Analytics.

### FR-VAR-012: Переменная типа "Data Layer Variable"

**Описание:** Извлекает значение по ключу из объекта dataLayer --- основного механизма передачи данных от сайта в GTM.

**Конфигурация:**
- **Data Layer Variable Name** --- имя ключа (поддерживает точечную нотацию для вложенных объектов, например `ecommerce.purchase.actionField.id`)
- **Data Layer Version** --- версия модели данных (Version 1 или Version 2)
- **Default Value** --- значение по умолчанию, если ключ не найден

**Бизнес-правила:**
- BR-VAR-039: Version 2 (рекомендуемая) поддерживает точечную нотацию для доступа к вложенным объектам и массивам
- BR-VAR-040: Version 1 выполняет слияние всех push-ов dataLayer в один объект; Version 2 использует модель состояний
- BR-VAR-041: Если ключ не найден и Default Value не задано, переменная возвращает `undefined`
- BR-VAR-042: Значение извлекается на момент текущего события --- если ключ был добавлен после события, переменная его не видит
- BR-VAR-043: Точечная нотация работает только в Version 2 (например, `user.name` извлечёт `name` из объекта `user`)

**User Story:**
> Как аналитик e-commerce, я хочу извлечь идентификатор транзакции из `dataLayer.push({ecommerce: {transaction_id: 'T12345'}})`, чтобы передать его в тег Google Ads Conversion.

---

### FR-VAR-013: Переменная типа "JavaScript Variable"

**Описание:** Извлекает значение глобальной JavaScript-переменной по её имени.

**Конфигурация:**
- **Global Variable Name** --- имя глобальной переменной (например, `document.title`, `window.screen.width`)

**Бизнес-правила:**
- BR-VAR-044: Переменная должна быть доступна в глобальной области видимости (`window`)
- BR-VAR-045: Поддерживает точечную нотацию для доступа к свойствам объектов
- BR-VAR-046: Если переменная не существует, возвращается `undefined`
- BR-VAR-047: Переменная извлекается синхронно --- асинхронные значения (промисы) не поддерживаются

**User Story:**
> Как разработчик, я хочу получить значение `document.title`, чтобы использовать его как название страницы в тегах аналитики, когда dataLayer не настроен.

---

### FR-VAR-014: Переменная типа "Custom JavaScript"

**Описание:** Выполняет произвольную JavaScript-функцию и возвращает её результат.

**Конфигурация:**
- **Custom JavaScript** --- функция JavaScript, которая должна возвращать значение через `return`

**Формат:** Функция оборачивается в `function() { ... }` и должна содержать оператор `return`.

**Бизнес-правила:**
- BR-VAR-048: Код должен быть оформлен как анонимная функция: `function() { return ...; }`
- BR-VAR-049: Функция выполняется синхронно --- нельзя использовать `async/await`, `setTimeout`, `fetch`
- BR-VAR-050: Внутри функции можно обращаться к другим переменным GTM через `{{Variable Name}}`
- BR-VAR-051: Если функция не содержит `return`, переменная возвращает `undefined`

## Состояния и статусы

### Жизненный цикл переменной

```
[Создана в Workspace] → [Сохранена] → [Включена в версию] → [Опубликована] → [Активна на сайте]
         ↓                    ↓                                       ↓
    [Удалена]           [Изменена]                            [Заменена новой версией]
                             ↓
                      [Включена в новую версию] → [Опубликована]
```

| Состояние | Описание |
|-----------|----------|
| **Черновик (Draft)** | Переменная создана или изменена в рабочей области, не включена в версию |
| **В версии (In Version)** | Переменная зафиксирована в версии контейнера, но версия не опубликована |
| **Опубликована (Published)** | Переменная активна в опубликованной версии контейнера на рабочем сайте |
| **Изменена (Modified)** | Переменная изменена в рабочей области по сравнению с опубликованной версией |
| **Удалена (Deleted)** | Переменная удалена в рабочей области; удаление вступит в силу после публикации |

### Состояния встроенной переменной

| Состояние | Описание |
|-----------|----------|
| **Активирована (Enabled)** | Переменная доступна для использования в тегах и триггерах |
| **Деактивирована (Disabled)** | Переменная скрыта из списков выбора, но может быть повторно активирована |

### Разрешение значения переменной (Runtime)

```
[Обращение к переменной] → [Вычисление значения] → [Применение Format Value] → [Возврат значения]
                                    ↓
                            [Ошибка / не найдено]
                                    ↓
                          [Возврат Default Value или undefined]
```

## Ограничения и лимиты

| Ограничение | Значение |
|-------------|----------|
| Максимальный размер контейнера | 200 КБ (все теги + триггеры + переменные) |
| Уникальность имени переменной | В пределах контейнера |
| Максимальное количество рабочих областей | Зависит от плана (бесплатный: 3, Tag Manager 360: неограниченно) |
| Конфликт рабочих областей | Если две рабочих области редактируют одну переменную, при публикации возникает конфликт, требующий разрешения |
| Вложенность dataLayer-ключей | Поддерживается через точечную нотацию (только Version 2) |
| Выполнение Custom JavaScript | Синхронное; асинхронные операции не поддерживаются |
| Количество строк в Lookup/RegEx Table | Не ограничено формально, но влияет на размер контейнера |
| Циклические ссылки переменных | Переменная A ссылается на B, B на A --- приводит к ошибке выполнения |
| Максимальная длина имени переменной | Не документировано явно; рекомендуется до 64 символов для читаемости |

## Интеграции с другими модулями

### Теги (Tags)

- Переменные подставляются в конфигурацию тегов через синтаксис `{{Variable Name}}`
- Используются для передачи динамических значений: идентификаторов транзакций, имён страниц, пользовательских измерений
- Google Analytics Settings Variable хранит конфигурацию целиком для UA-тегов
- Google Tag Settings Variables хранят конфигурацию для GA4-тегов

### Триггеры (Triggers)

- Переменные используются в условиях срабатывания триггеров (например, `{{Page Path}} содержит /checkout`)
- Встроенные переменные кликов, форм, прокрутки, видимости, истории заполняются соответствующими триггерами
- Без активации нужной встроенной переменной её нельзя использовать в условии триггера

### Рабочие области (Workspaces)

- Каждая рабочая область имеет свою копию конфигурации переменных
- Изменения в одной рабочей области не видны в других до публикации
- Конфликты при одновременном редактировании одной переменной в разных рабочих областях разрешаются при создании версии

### Версии (Versions)

- Состояние всех переменных фиксируется при создании версии контейнера
- Откат к предыдущей версии восстанавливает все переменные в состоянии той версии
- История изменений каждой переменной доступна через журнал версий

### Окружения (Environments)

- Переменная `Environment Name` возвращает имя текущего окружения
- Можно использовать переменные для условной логики в зависимости от окружения (dev/staging/production)

### Папки (Folders)

- Переменные могут быть организованы в папки для удобства навигации
- Папки не влияют на логику работы переменных
- Одна переменная может находиться только в одной папке

### Предварительный просмотр и отладка (Preview & Debug)

- В режиме Preview видны все обращения к переменным и их разрешённые значения
- Для каждого события отображается список переменных с текущими значениями
- Позволяет диагностировать `undefined` и некорректные значения до публикации

### Consent Mode (Управление согласием)

- Переменные, зависящие от cookies (1st Party Cookie, Analytics Storage), могут возвращать `undefined`, если пользователь не дал согласие
- Consent Mode влияет на доступность данных, но не на саму конфигурацию переменных
