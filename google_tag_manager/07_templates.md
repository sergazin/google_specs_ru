# Шаблоны и галерея (Community Template Gallery)

## Описание

Модуль «Шаблоны и галерея» предоставляет экосистему создания, управления и распространения пользовательских шаблонов тегов и переменных в Google Tag Manager. Модуль состоит из двух взаимосвязанных частей:

1. **Template Editor** — встроенный редактор для создания собственных шаблонов тегов и переменных с использованием sandboxed JavaScript и визуального конструктора полей.
2. **Community Template Gallery** — публичный маркетплейс шаблонов, созданных сторонними разработчиками и опубликованных через GitHub-репозитории. Контент галереи предоставляется третьими сторонами, а не Google.

Шаблоны позволяют пользователям внедрять теги без написания пользовательского HTML/JavaScript, используя интуитивный интерфейс с полями ввода. Каждый шаблон имеет модель разрешений (permissions), обеспечивающую прозрачность и контроль над тем, какие действия тег выполняет на сайте.

---

## Роли пользователей

### Роли внутри GTM-контейнера (потребители шаблонов)

| Роль | Описание в контексте шаблонов |
|------|-------------------------------|
| **Read** | Может просматривать список шаблонов в контейнере и их конфигурацию, но не может добавлять, редактировать или удалять шаблоны |
| **Edit** | Может добавлять шаблоны из галереи в workspace, создавать и редактировать собственные шаблоны в Template Editor, импортировать/экспортировать шаблоны. Не может публиковать изменения |
| **Approve** | Все возможности Edit + может создавать версии контейнера с новыми/изменёнными шаблонами, но не может публиковать |
| **Publish** | Все возможности Approve + может публиковать версию контейнера с шаблонами в продакшн |

### Роли в экосистеме галереи (создатели шаблонов)

| Роль | Описание |
|------|----------|
| **Template Developer** | Разработчик, создающий шаблон в Template Editor и экспортирующий его. Владеет GitHub-репозиторием шаблона |
| **Gallery Submitter** | Лицо, отправляющее шаблон на публикацию в Community Template Gallery. Обычно совпадает с Template Developer |
| **Google Reviewer** | Сотрудник Google, проверяющий шаблон на соответствие политикам перед публикацией в галерее |
| **Gallery Consumer** | Пользователь GTM, который находит и добавляет шаблоны из галереи в свой контейнер |

## Функциональные требования

### FR-TPL-001: Создание пользовательского шаблона

**Описание:** Пользователь с правами Edit и выше может создать новый шаблон тега или переменной через Template Editor.

**Предусловия:**
- Пользователь имеет доступ к контейнеру с правами Edit или выше
- Пользователь находится в активном workspace

**Основной сценарий:**
1. Пользователь переходит в раздел Templates контейнера
2. Пользователь выбирает создание нового шаблона тега (Tag Template) или переменной (Variable Template)
3. Система открывает Template Editor с четырьмя вкладками: Info, Fields, Code, Permissions
4. Пользователь заполняет информацию о шаблоне (название, описание, иконка)
5. Пользователь определяет поля ввода через визуальный конструктор на вкладке Fields
6. Пользователь пишет логику шаблона на sandboxed JavaScript на вкладке Code
7. Система автоматически определяет необходимые разрешения на основе используемых API
8. Пользователь просматривает и при необходимости уточняет разрешения на вкладке Permissions
9. Пользователь сохраняет шаблон

**Альтернативные сценарии:**
- 6а. Код содержит синтаксические ошибки — система отображает ошибки, шаблон не сохраняется до их исправления
- 7а. Код использует API, требующие явного указания ресурсов (например, конкретных доменов для sendPixel) — пользователь должен уточнить конфигурацию разрешений вручную

**Бизнес-правила:**
- Шаблон тега отличается от шаблона переменной: шаблон переменной обязан возвращать значение
- Шаблон существует в рамках конкретного контейнера и workspace
- Название шаблона должно быть уникальным в пределах контейнера

### FR-TPL-002: Определение полей шаблона

**Описание:** Template Developer определяет набор полей ввода, которые конечный пользователь (маркетолог) будет заполнять при создании тега/переменной на основе шаблона.

**Поддерживаемые типы полей:**

| Тип поля | Назначение |
|----------|------------|
| Text Input | Ввод текстового значения (ID аккаунта, URL и т.д.) |
| Drop-down Menu | Выбор одного значения из предопределённого списка |
| Checkbox | Булевый переключатель (вкл/выкл) |
| Radio Button | Выбор одного варианта из нескольких |
| Simple Table | Табличный ввод данных (пары ключ-значение и т.п.) |
| Group | Логическая группировка нескольких полей |

**Бизнес-правила:**
- Имена параметров полей должны быть в формате lowerCamelCase (userName, customerID, shoppingCartValue)
- Метки полей — в формате sentence case
- Каждое поле может иметь help text — информационную подсказку с примером ввода и описанием эффекта значения
- Значения полей доступны в коде шаблона через объект `data`

### FR-TPL-003: Модель разрешений шаблона (Permissions)

**Описание:** Каждый шаблон имеет явно объявленный набор разрешений, определяющий, какие действия код шаблона может выполнять на веб-странице. Это обеспечивает прозрачность и контроль.

**Перечень разрешений (Web-контейнер):**

| Разрешение | Описание | Конфигурация |
|------------|----------|--------------|
| **access_globals** | Доступ к глобальным переменным window | Список ключей; чекбоксы read/write/execute |
| **access_local_storage** | Доступ к localStorage | Список ключей; чекбоксы read/write |
| **access_template_storage** | Доступ к хранилищу шаблона | Чекбоксы read/write |
| **get_cookies** | Чтение cookies | Список имён cookies, разрешённых для чтения |
| **set_cookies** | Установка cookies | Список имён cookies + параметры (domain, path, expiry и т.д.) |
| **inject_script** | Загрузка внешних скриптов | Список разрешённых URL/доменов |
| **inject_hidden_iframe** | Внедрение скрытого iframe | Список разрешённых URL |
| **send_pixel** | Отправка pixel-запросов | Список разрешённых доменов |
| **read_data_layer** | Чтение Data Layer | Список разрешённых ключей |
| **write_data_layer** | Запись в Data Layer | Список разрешённых ключей |
| **read_title** | Чтение заголовка страницы | Без конфигурации |
| **read_character_set** | Чтение кодировки страницы | Без конфигурации |
| **read_url** | Чтение URL страницы | Компоненты: protocol, host, port, path, query, fragment, extension |
| **read_referrer** | Чтение URL реферера | Компоненты: protocol, host, port, path, query, fragment |
| **read_container_data** | Чтение данных контейнера | Без конфигурации |
| **read_event_data** | Чтение данных события | Список разрешённых ключей |
| **logging** | Логирование в консоль разработчика и GTM Preview | Опция: включение в продакшн (по умолчанию — только в debug/preview) |
| **access_consent** | Доступ к Consent API | Чтение/запись состояния согласия |

**Бизнес-правила:**
- Разрешения автоматически определяются по используемым API в коде шаблона
- Автоматическое определение происходит в реальном времени при редактировании кода
- Разработчик может сузить (но не расширить) автоматически определённые разрешения
- При добавлении шаблона из галереи пользователь видит полный список запрашиваемых разрешений
- Перед обновлением импортированного шаблона пользователь видит diff изменений в разрешениях
- Разрешения можно проверить программно через queryPermission API в sandboxed JavaScript

### FR-TPL-004: Тестирование шаблона

**Описание:** Template Editor предоставляет встроенный механизм юнит-тестирования для валидации логики шаблона без развёртывания.

**Основной сценарий:**
1. Разработчик переходит на вкладку Tests в Template Editor
2. Разработчик создаёт тестовые случаи
3. Каждый тест использует `runCode` для симуляции выполнения шаблона с тестовыми данными
4. Для проверки результатов используется `assertThat`
5. Разработчик запускает тесты
6. Система отображает результаты: пройденные и провалившиеся тесты

**Бизнес-правила:**
- Тесты выполняются в изолированной среде без реального воздействия на страницу
- Тесты не являются обязательными для сохранения шаблона
- Тесты рекомендуются перед публикацией в галерею

### FR-TPL-005: Предварительный просмотр шаблона

**Описание:** Template Editor включает секцию Template Preview, позволяющую увидеть результат выполнения кода шаблона.

**Основной сценарий:**
1. Разработчик пишет код на вкладке Code
2. Система отображает результат выполнения в секции Template Preview ниже редактора кода
3. Разработчик может проверить корректность работы шаблона до сохранения

**Бизнес-правила:**
- Preview отображает выходные данные для шаблонного кода в реальном времени

---

### FR-TPL-006: Обзор и поиск шаблонов в галерее

**Описание:** Пользователь может искать и просматривать шаблоны в Community Template Gallery.

**Точки входа:**
- Прямой доступ через tagmanager.google.com/gallery
- Из интерфейса GTM: раздел Templates > кнопка "Search Gallery" (отдельно для Tag Templates и Variable Templates)

**Основной сценарий:**
1. Пользователь открывает галерею
2. Система отображает список доступных шаблонов (теги и/или переменные в зависимости от точки входа)
3. Пользователь может фильтровать по текстовому запросу (например, "remarketing")
4. Пользователь нажимает на шаблон для просмотра детальной страницы
5. На детальной странице отображается:
   - Описание шаблона
   - Информация об авторе
   - Список запрашиваемых разрешений (permissions)
   - Ссылка на GitHub-репозиторий шаблона
   - Ссылки автора на документацию и поддержку (опционально)

**Бизнес-правила:**
- Галерея содержит только шаблоны, прошедшие проверку Google
- Контент предоставляется третьими сторонами; Google не гарантирует качество или производительность шаблонов

### FR-TPL-007: Добавление шаблона из галереи в контейнер

**Описание:** Пользователь импортирует шаблон из Community Template Gallery в свой контейнер GTM.

**Предусловия:**
- Пользователь имеет доступ к контейнеру с правами Edit или выше
- Пользователь находится в активном workspace

**Основной сценарий:**
1. Пользователь находит нужный шаблон в галерее (FR-TPL-006)
2. Пользователь нажимает "Add to workspace"
3. Система отображает запрашиваемые разрешения шаблона
4. Пользователь подтверждает добавление
5. Шаблон добавляется в контейнер и становится доступным как вариант при создании нового тега/переменной

**Бизнес-правила:**
- Добавленный шаблон появляется в списке доступных типов тегов/переменных
- Пользователь может использовать импортированный шаблон так же, как встроенные типы тегов
- После импорта шаблон можно отредактировать в Template Editor (создаётся локальная копия)

### FR-TPL-008: Обновление импортированного шаблона

**Описание:** Когда автор шаблона публикует новую версию, пользователи, импортировавшие шаблон, получают уведомление о доступном обновлении.

**Основной сценарий:**
1. Автор шаблона публикует новую версию (обновляет metadata.yaml в GitHub-репозитории)
2. При следующем входе пользователя в контейнер система отображает notification bar о доступных обновлениях
3. Пользователь нажимает "View"
4. Система отображает список шаблонов с доступными обновлениями
5. Пользователь выбирает шаблон для обновления
6. Система отображает diff: сравнение текущей и новой версии
7. Пользователь нажимает "Accept update"
8. Шаблон обновляется до новой версии

**Альтернативные сценарии:**
- 7а. Пользователь решает не обновлять — шаблон остаётся на текущей версии, уведомление сохраняется
- 6а. Изменились разрешения — система явно выделяет изменения в permissions

**Бизнес-правила:**
- Обновление не является принудительным; пользователь сам решает, обновлять ли шаблон
- Перед обновлением пользователь всегда видит diff изменений (код и разрешения)
- Обновление применяется в текущем workspace и требует публикации контейнера для вступления в силу

### FR-TPL-009: Публикация шаблона в Community Template Gallery

**Описание:** Разработчик шаблона может подать заявку на публикацию своего шаблона в галерею.

**Предусловия:**
- Шаблон создан и протестирован в Template Editor
- Разработчик принял Community Template Gallery Terms of Service (чекбокс на вкладке Info)
- Создан публичный GitHub-репозиторий с лицензией Apache 2.0

**Основной сценарий (полный процесс):**

1. **Подготовка шаблона:**
   - Разработчик отмечает чекбокс "Agree to the Community Template Gallery Terms of Service" на вкладке Info
   - Разработчик экспортирует шаблон на локальную машину
   - Файл переименовывается в `template.tpl`

2. **Подготовка GitHub-репозитория:**
   - Разработчик создаёт публичный GitHub-репозиторий
   - Добавляет лицензию Apache 2.0
   - Загружает обязательные файлы:
     - `template.tpl` — экспортированный файл шаблона
     - `metadata.yaml` — метаданные с информацией о версиях
     - `LICENSE` — файл лицензии Apache 2.0
   - Опционально добавляет `README.md`

3. **Настройка metadata.yaml:**
   - Указывается SHA (хеш) Git-коммита для каждой версии
   - Добавляются changeNotes с описанием изменений

4. **Настройка категорий:**
   - В файле template.tpl в секции INFO указываются от 1 до 3 категорий, упорядоченных от наиболее к наименее релевантной

5. **Отправка в галерею:**
   - Разработчик переходит на tagmanager.google.com/gallery
   - Нажимает "Submit Template"
   - Вводит URL GitHub-репозитория
   - Нажимает "Submit"

6. **Проверка Google:**
   - Google проверяет шаблон на соответствие политикам
   - При одобрении — шаблон появляется в галерее
   - При отклонении — разработчик получает уведомление с причиной

**Бизнес-правила:**
- GitHub-репозиторий должен быть публичным
- Лицензия обязательно Apache 2.0
- Каждый репозиторий содержит один шаблон
- Если в галерее уже есть шаблон с аналогичной функциональностью, новый может быть отклонён

---

### FR-TPL-010: Обновление опубликованного шаблона в галерее

**Описание:** Автор обновляет ранее опубликованный шаблон в Community Template Gallery.

**Основной сценарий:**
1. Разработчик вносит изменения в template.tpl и коммитит в GitHub
2. Разработчик копирует SHA нового коммита
3. Разработчик добавляет новую запись в секцию versions файла metadata.yaml:
   - Новый sha (в начало списка)
   - changeNotes с описанием изменений данной версии
4. Разработчик коммитит обновлённый metadata.yaml
5. Галерея автоматически подхватывает новую версию
6. Все пользователи, импортировавшие шаблон, получают уведомление об обновлении (FR-TPL-008)

**Бизнес-правила:**
- Новая версия добавляется в начало (top) списка versions в metadata.yaml
- changeNotes должны кратко описывать суть изменений
- SHA должен соответствовать конкретному коммиту с изменениями в template.tpl

### FR-TPL-011: Экспорт и импорт шаблонов

**Описание:** Шаблоны могут быть экспортированы из одного контейнера и импортированы в другой для распространения преконфигурированных компонентов.

**Основной сценарий экспорта:**
1. Пользователь открывает шаблон в Template Editor
2. Пользователь выбирает экспорт
3. Система генерирует файл шаблона (.tpl) и сохраняет на локальную машину

**Основной сценарий импорта:**
1. Пользователь переходит в раздел Templates
2. Пользователь выбирает импорт шаблона
3. Пользователь загружает файл .tpl
4. Система импортирует шаблон в текущий контейнер/workspace

**Бизнес-правила:**
- Экспорт/импорт может использоваться для распространения шаблонов без публикации в галерею
- Импортированный шаблон не получает автоматических обновлений (в отличие от шаблонов из галереи)
- При импорте используется стандартный механизм экспорта/импорта контейнера GTM (теги, триггеры, переменные, шаблоны)

---

### FR-TPL-012: Редактирование импортированного шаблона

**Описание:** После импорта шаблона из галереи пользователь может отредактировать его локально в Template Editor.

**Основной сценарий:**
1. Пользователь открывает импортированный шаблон из раздела Templates
2. Система открывает Template Editor с текущей конфигурацией шаблона
3. Пользователь вносит изменения в любую вкладку (Info, Fields, Code, Permissions)
4. Пользователь сохраняет изменения

**Бизнес-правила:**
- Локальное редактирование разрывает связь с галерейной версией в части изменённых компонентов
- Если после локального редактирования выходит обновление из галереи, пользователь должен вручную разрешить конфликт

---

### FR-TPL-013: Использование шаблона для создания тега/переменной

**Описание:** Конечный пользователь (маркетолог) создаёт тег или переменную на основе шаблона, заполняя только поля конфигурации.

**Основной сценарий:**
1. Пользователь создаёт новый тег или переменную
2. В списке типов отображаются как встроенные типы, так и импортированные шаблоны
3. Пользователь выбирает шаблон
4. Система отображает форму с полями, определёнными в шаблоне (FR-TPL-002)
5. Пользователь заполняет поля (ID аккаунта, параметры и т.д.)
6. Пользователь настраивает триггеры (для тегов)
7. Пользователь сохраняет тег/переменную

**Бизнес-правила:**
- Пользователь не пишет HTML или JavaScript — только заполняет поля шаблона
- Разрешения шаблона прозрачны и видны пользователю до применения
- Один шаблон может использоваться для создания множества экземпляров тегов/переменных с разной конфигурацией

## Сущности данных

### Template (Шаблон)

| Атрибут | Описание |
|---------|----------|
| ID | Уникальный идентификатор шаблона в контейнере |
| Type | Тип шаблона: Tag или Variable |
| Name | Название шаблона (уникальное в контейнере) |
| Description | Описание назначения шаблона |
| Icon | Иконка шаблона |
| Categories | От 1 до 3 категорий (для галерейных шаблонов) |
| Fields | Набор определённых полей ввода |
| Code | Sandboxed JavaScript код логики шаблона |
| Permissions | Набор объявленных разрешений с конфигурацией |
| Tests | Набор юнит-тестов |
| Source | Источник: local (создан в контейнере), gallery (импортирован из галереи), imported (импортирован из файла) |
| Gallery Repository URL | URL GitHub-репозитория (для галерейных шаблонов) |
| Gallery Version SHA | SHA текущей установленной версии (для галерейных шаблонов) |
| TOS Accepted | Принятие условий Community Template Gallery ToS |

### Gallery Entry (Запись в галерее)

| Атрибут | Описание |
|---------|----------|
| Repository URL | URL публичного GitHub-репозитория |
| Author | Информация об авторе/организации |
| Template File | Файл template.tpl |
| Metadata | Содержимое metadata.yaml |
| Versions | Список версий (SHA + changeNotes) |
| Categories | Категории шаблона |
| Status | Статус в галерее (активный, отклонённый, удалённый) |
| Submission Date | Дата подачи заявки |
| Approval Date | Дата одобрения |
| Links | Ссылки на документацию и поддержку |

### Template Field (Поле шаблона)

| Атрибут | Описание |
|---------|----------|
| Parameter Name | Имя параметра (lowerCamelCase) |
| Field Type | Тип поля (text, dropdown, checkbox, radio, simple_table, group) |
| Label | Метка поля (sentence case) |
| Help Text | Подсказка с примером ввода |
| Default Value | Значение по умолчанию |
| Options | Варианты для dropdown/radio |
| Required | Обязательность заполнения |

### Template Permission (Разрешение шаблона)

| Атрибут | Описание |
|---------|----------|
| Permission Type | Тип разрешения (access_globals, get_cookies и т.д.) |
| Configuration | Специфичная конфигурация (список ключей, доменов, имён cookies и т.д.) |
| Access Level | Уровень доступа (read/write/execute — где применимо) |
| Auto-detected | Определено ли автоматически из кода |

### Metadata (metadata.yaml)

| Атрибут | Описание |
|---------|----------|
| homepage | URL домашней страницы автора |
| documentation | URL документации шаблона |
| versions | Список версий (массив объектов {sha, changeNotes}) |

## Состояния и статусы

### Жизненный цикл шаблона в контейнере

```
[Создание] --> (Draft)
    |
    +--> [Сохранение] --> (Saved in Workspace)
    |                         |
    |                         +--> [Создание версии контейнера] --> (In Container Version)
    |                         |                                       |
    |                         |                                       +--> [Публикация контейнера] --> (Live)
    |                         |
    |                         +--> [Редактирование] --> (Saved in Workspace) // цикл
    |
    +--> [Удаление] --> (Deleted)
```

| Состояние | Описание | Доступные действия |
|-----------|----------|--------------------|
| **Draft** | Шаблон создаётся в Template Editor, ещё не сохранён | Редактирование, сохранение, отмена |
| **Saved in Workspace** | Шаблон сохранён в workspace | Редактирование, удаление, экспорт, создание версии, использование для создания тегов/переменных |
| **In Container Version** | Шаблон включён в версию контейнера | Публикация версии |
| **Live** | Шаблон работает в продакшн (в составе опубликованной версии контейнера) | Создание новой версии |
| **Deleted** | Шаблон удалён из workspace | Нет (необратимо в рамках workspace; предыдущие версии контейнера сохраняют шаблон) |

### Жизненный цикл шаблона в галерее

```
[Подготовка GitHub] --> (Repository Ready)
    |
    +--> [Submit Template] --> (Under Review)
    |                            |
    |                            +--> [Одобрение] --> (Published)
    |                            |                       |
    |                            |                       +--> [Обновление metadata.yaml] --> (Update Available)
    |                            |                       |                                       |
    |                            |                       |                                       +--> (Published) // новая версия
    |                            |                       |
    |                            |                       +--> [Нарушение политик] --> (Removed)
    |                            |
    |                            +--> [Отклонение] --> (Rejected)
    |                                                    |
    |                                                    +--> [Исправление + повторная подача] --> (Under Review)
```

| Состояние | Описание |
|-----------|----------|
| **Repository Ready** | GitHub-репозиторий подготовлен с template.tpl, metadata.yaml и LICENSE |
| **Under Review** | Шаблон подан и ожидает проверки Google |
| **Published** | Шаблон одобрен и доступен в галерее |
| **Update Available** | Автор обновил metadata.yaml; новая версия доступна пользователям |
| **Rejected** | Шаблон отклонён Google (нарушение политик, дубликат и т.д.) |
| **Removed** | Шаблон удалён из галереи (нарушение политик пост-фактум) |

### Состояния импортированного шаблона (в контейнере)

| Состояние | Описание |
|-----------|----------|
| **Up to date** | Установлена последняя версия шаблона из галереи |
| **Update available** | В галерее доступна новая версия; отображается notification bar |
| **Locally modified** | Шаблон отредактирован локально после импорта |

## Ограничения и лимиты

### Технические ограничения шаблонов
- Код шаблона выполняется в sandboxed-среде — доступ к браузерным API только через специальные sandbox API
- Запрещён прямой доступ к `window`, `document` и другим глобальным объектам — только через разрешённые API с явными permissions
- Шаблон переменной обязан возвращать значение; шаблон тега — нет

### Ограничения галереи
- GitHub-репозиторий обязательно должен быть публичным
- Лицензия обязательно Apache 2.0
- Один репозиторий = один шаблон
- Если шаблон с аналогичной функциональностью уже существует в галерее, новый может быть отклонён
- Google оставляет за собой право удалить любой шаблон в любое время

### Политики контента (основания для отклонения/удаления)
- Нарушение прав интеллектуальной собственности
- Нарушение применимых законов
- Порнографический или непристойный контент
- Содержание вредоносного ПО или вирусов
- Нарушение условий обслуживания третьих сторон
- Мошеннический или вводящий в заблуждение контент
- Спамный пользовательский опыт
- Содержание персональной или конфиденциальной информации
- Создание неоправданного риска для инфраструктуры GTM

### Ограничения ролей
- Для создания/редактирования шаблонов требуется минимум уровень Edit на контейнере
- Для публикации контейнера с шаблонами — уровень Publish
- Подача шаблона в галерею доступна любому с GitHub-аккаунтом и принятием ToS

## Интеграции с другими модулями

### Теги (Tags)
- Шаблоны тегов определяют новые типы тегов, доступные в модуле управления тегами
- Каждый экземпляр тега ссылается на свой базовый шаблон
- При обновлении шаблона все теги, созданные на его основе, наследуют новое поведение

### Переменные (Variables)
- Шаблоны переменных определяют новые типы переменных
- Переменные, созданные из шаблона, используются в тегах и триггерах наравне со встроенными

### Триггеры (Triggers)
- Теги, созданные из шаблонов, привязываются к триггерам стандартным образом
- Шаблоны не создают новые типы триггеров (только теги и переменные)

### Workspace и версионирование
- Шаблоны живут в workspace и подчиняются общим правилам версионирования контейнера
- Изменения в шаблонах фиксируются при создании версии контейнера
- Конфликты между workspace'ами, затрагивающие шаблоны, разрешаются стандартным механизмом обновления workspace

### Preview и Debug
- Шаблоны можно тестировать через GTM Preview Mode
- Logging из шаблонов отображается в режиме Preview/Debug
- В продакшн логирование по умолчанию отключено (контролируется permission logging)

### Consent Mode
- Шаблоны могут взаимодействовать с Consent API через permission access_consent
- Шаблоны consent mode — специальный подтип шаблонов для управления согласием пользователя
- Поведение шаблона может зависеть от состояния согласия

### Контейнерный экспорт/импорт
- Шаблоны включаются в экспорт контейнера наряду с тегами, триггерами и переменными
- При импорте контейнера шаблоны импортируются автоматически

### Server-side контейнеры
- Server-side контейнеры поддерживают дополнительный тип шаблонов: Client Templates
- Модель разрешений для server-side шаблонов расширена специфичными для серверной среды permissions
