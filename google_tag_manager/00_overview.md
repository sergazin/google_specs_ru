# Google Tag Manager — Обзор спецификации

## Описание сервиса

Google Tag Manager (GTM) — система управления тегами от Google, входящая в Google Marketing Platform. Позволяет маркетологам и аналитикам добавлять, изменять и удалять маркетинговые и аналитические теги на сайте или в мобильном приложении без участия разработчиков. Поддерживает как клиентскую (browser), так и серверную (server-side) модель сбора данных.

## Целевая аудитория

| Роль | Описание |
|------|----------|
| **Digital-маркетолог** | Управление рекламными и аналитическими тегами без кода |
| **Веб-аналитик** | Настройка сбора данных, событий, конверсий для GA4, Google Ads и др. |
| **Разработчик** | Интеграция GTM на сайт/приложение, создание кастомных шаблонов, Data Layer |
| **Агентство** | Управление тегами для множества клиентов через аккаунты и контейнеры |
| **Enterprise (GTM 360)** | Крупные компании с Approval Workflow, зонами, расширенными лимитами |

## Ключевые метрики

| Метрика | Описание |
|---------|----------|
| Количество контейнеров | Сколько сайтов/приложений управляется |
| Количество тегов | Общее число активных тегов |
| Частота публикаций | Как часто обновляются контейнеры |
| Время до публикации | От создания тега до деплоя в продакшн |
| Ошибки тегов | Теги, не срабатывающие в Preview Mode |
| Покрытие Consent Mode | % тегов, корректно работающих с согласием |

## Версии продукта

| Версия | Описание |
|--------|----------|
| **GTM Free** | Бесплатная версия. До 3 рабочих областей, 2000 тегов, без Approval Workflow |
| **GTM 360** | Enterprise-версия (часть GMP 360). Неограниченные воркспейсы, зоны, Approval Workflow, SLA, расширенные лимиты |
| **Server-Side GTM** | Серверный контейнер на Google Cloud (Cloud Run / App Engine). Оплата по трафику |

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **Container** | Контейнер — основная единица GTM, содержащая теги, триггеры и переменные для одного сайта/приложения |
| **Tag** | Фрагмент кода (JS/пиксель), выполняющийся на странице при срабатывании триггера |
| **Trigger** | Условие, при котором срабатывает тег (загрузка страницы, клик, отправка формы и т.д.) |
| **Variable** | Именованный контейнер для данных, используемый в тегах и триггерах |
| **Data Layer** | JavaScript-объект (`dataLayer`) для передачи данных со страницы в GTM |
| **Workspace** | Рабочая область для параллельной работы нескольких пользователей |
| **Version** | Снимок состояния контейнера на момент публикации |
| **Environment** | Среда для тестирования (staging, dev, production) |
| **Zone** | Зона (GTM 360) — изолированная область контейнера с ограниченными правами |
| **Consent Mode** | Механизм адаптации тегов к согласию пользователя (GDPR, ePrivacy) |
| **Tag Assistant** | Встроенный отладчик для предварительного просмотра тегов |
| **Client** | Компонент серверного контейнера, принимающий входящие запросы |
| **Community Template Gallery** | Маркетплейс готовых шаблонов тегов и переменных |
| **GTM 360** | Enterprise-версия GTM с расширенными функциями (зоны, approval, SLA) |

### Потоки данных

1. **Создание тега**: Auth → Container → Workspace → Tag + Trigger + Variables → Preview → Publish → Version
2. **Server-Side**: Web Container → HTTP Request → Server Container → Client → Server Tag → Destination (GA4, Ads, etc.)
3. **Consent Flow**: User Consent → Consent Mode → Tag Firing Decision → Adjusted Data Collection
4. **Template Flow**: Template Editor → Test → Gallery Submission → Review → Published → Import to Container
