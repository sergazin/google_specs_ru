# Функциональная спецификация: Модуль "Теги" (Google Tag Manager)

## Описание

Модуль "Теги" является центральным компонентом Google Tag Manager. Тег — это фрагмент кода, который отправляет данные в стороннюю систему (Google Analytics, Google Ads, Facebook и др.). Вместо ручной вставки кода на сайт, маркетологи и аналитики создают, настраивают и управляют тегами через интерфейс GTM. Каждый тег привязывается к одному или нескольким триггерам (условиям срабатывания) и может использовать переменные для динамической подстановки значений.

### Основные компоненты
- Встроенные шаблоны тегов (Google Analytics, Google Ads, Floodlight и др.)
- Шаблоны из Community Template Gallery (Facebook Pixel, LinkedIn Insight, Mixpanel и др.)
- Пользовательские теги (Custom HTML, Custom Image)
- Система привязки тегов к триггерам
- Настройки последовательности выполнения (Tag Sequencing)
- Приоритет срабатывания (Tag Firing Priority)
- Параметры частоты срабатывания (Tag Firing Options)
- Постановка на паузу (Tag Pausing)
- Управление согласиями (Consent Settings)
- Расписание активности тега (Tag Firing Schedule)

## Роли пользователей

### Уровень аккаунта

| Роль | Описание |
|------|----------|
| **Admin (Администратор)** | Управляет правами пользователей. Автоматически имеет минимум Read-доступ ко всем контейнерам аккаунта |
| **User (Пользователь)** | Видит настройки аккаунта и список пользователей, но не может редактировать. Не имеет автоматического доступа к контейнерам |

### Уровень контейнера

| **No Access** | Нет | Нет | Нет | Нет |
| **Read** | Да | Нет | Нет | Нет |

| **Approve** | Да | Да | Да | Нет |
| **Publish** | Да | Да | Да | Да |

## Функциональные требования

### FR-TAG-001: Создание тега из встроенного шаблона

**Приоритет:** Критический

**Описание:** Пользователь с правами Edit и выше должен иметь возможность создать новый тег, выбрав один из встроенных шаблонов Google Tag Manager.

**Встроенные типы тегов:**
- Google Tag (gtag.js) — единый тег для отправки данных в продукты Google
- Google Analytics: GA4 Event — отправка событий в Google Analytics 4
- Google Analytics: GA4 Configuration — настройка потока данных GA4
- Google Ads Conversion Tracking — отслеживание конверсий Google Ads
- Google Ads Remarketing — тег ремаркетинга Google Ads
- Conversion Linker — связывание кликов с конверсиями (обязателен для Google Ads)
- Floodlight Counter — счётчик Floodlight (Campaign Manager 360)
- Floodlight Sales — отслеживание продаж Floodlight
- Custom HTML — произвольный HTML/JavaScript-код
- Custom Image — пиксель-трекер (1x1 изображение)

**Входные данные:**
- Тип тега (из списка шаблонов)
- Название тега (задаётся пользователем)
- Параметры конфигурации (зависят от типа тега)
- Минимум один триггер срабатывания

**Выходные данные:**
- Созданный тег в текущем рабочем пространстве (Workspace)
- Тег в статусе "Draft" (черновик), не опубликован

**Бизнес-правила:**
- Тег не может существовать без хотя бы одного триггера срабатывания
- Название тега должно быть уникальным в пределах контейнера
- Тег создаётся в текущем рабочем пространстве пользователя
- Изменения не влияют на опубликованную версию контейнера до публикации
- Максимальное количество тегов в контейнере — 5 000
- Общий размер контейнера не должен превышать 200 КБ

---

### FR-TAG-002: Создание тега из Community Template Gallery

**Приоритет:** Высокий

**Описание:** Пользователь должен иметь возможность добавить шаблон тега из галереи сообщества и создать тег на его основе.

**Доступные категории шаблонов (примеры):**
- Facebook Pixel (Meta Pixel)
- LinkedIn Insight Tag
- Twitter (X) Universal Website Tag
- Mixpanel
- Hotjar Tracking Code
- Pinterest Tag
- TikTok Pixel
- Matomo Analytics
- Criteo OneTag
- Bing UET Tag
- И сотни других шаблонов от сторонних разработчиков

**Входные данные:**
- Выбор шаблона из галереи
- Подтверждение разрешений шаблона (permissions)
- Параметры конфигурации шаблона
- Триггер(ы) срабатывания

**Выходные данные:**
- Шаблон добавлен в контейнер
- Тег создан на основе шаблона

**Бизнес-правила:**
- Перед добавлением шаблона пользователь обязан просмотреть и подтвердить разрешения, которые запрашивает шаблон (какие данные он собирает, куда отправляет)
- Шаблоны галереи создаются и поддерживаются сторонними разработчиками, не Google
- Google не гарантирует качество и безопасность сторонних шаблонов
- Добавленный шаблон становится доступен как тип тега при создании новых тегов
- Обновления шаблона из галереи требуют повторного подтверждения разрешений

---

### FR-TAG-003: Создание пользовательского HTML-тега (Custom HTML)

**Приоритет:** Высокий

**Описание:** Пользователь должен иметь возможность создать тег с произвольным HTML/JavaScript-кодом для случаев, когда нет подходящего шаблона.

**Входные данные:**
- Название тега
- HTML/JavaScript-код
- Триггер(ы) срабатывания
- Опция: поддержка document.write

**Выходные данные:**
- Тег Custom HTML создан в рабочем пространстве

**Бизнес-правила:**
- Максимальная длина кода в Custom HTML — 102 400 символов
- Код выполняется в контексте страницы (имеет доступ к DOM)
- Опция document.write должна быть явно включена, если требуется (по умолчанию отключена)
- Custom HTML теги несут повышенные риски безопасности — рекомендуется использовать шаблоны, когда возможно
- Код может содержать обращения к переменным GTM через синтаксис {{Имя переменной}}

---

### FR-TAG-004: Создание пользовательского тега-изображения (Custom Image)

**Приоритет:** Средний

**Описание:** Пользователь должен иметь возможность создать тег-пиксель, который загружает изображение (обычно 1x1 пиксель) по указанному URL для трекинга.

**Входные данные:**
- Название тега
- URL изображения (может содержать переменные GTM)
- Опция: включить кэширование
- Триггер(ы) срабатывания

**Выходные данные:**
- Тег Custom Image создан

**Бизнес-правила:**
- URL может содержать динамические параметры через переменные GTM
- Если кэширование отключено, к URL добавляется cache-busting параметр
- Тег не выполняет JavaScript, только загружает изображение
- Используется для простых трекинг-пикселей сторонних систем

---

### FR-TAG-005: Привязка тега к триггерам

**Приоритет:** Критический

**Описание:** Пользователь должен иметь возможность привязать к тегу один или несколько триггеров срабатывания и триггеров исключения.

**Входные данные:**
- Один или несколько триггеров срабатывания (Firing Triggers)
- Ноль или несколько триггеров исключения (Exception Triggers), опционально

**Выходные данные:**
- Тег привязан к указанным триггерам

**Бизнес-правила:**
- Тег обязан иметь минимум один триггер срабатывания
- Триггеры исключения имеют приоритет над триггерами срабатывания: если оба условия выполняются одновременно, тег НЕ срабатывает
- Если привязано несколько триггеров срабатывания, тег срабатывает при выполнении ЛЮБОГО из них (логическое ИЛИ)
- Триггеры исключения проверяются для КАЖДОГО срабатывания
- Один триггер может быть привязан к нескольким тегам

---

### FR-TAG-006: Настройка приоритета срабатывания (Tag Firing Priority)

**Приоритет:** Средний

**Описание:** Пользователь должен иметь возможность задать числовой приоритет срабатывания тега для управления порядком выполнения тегов, привязанных к одному триггеру.

**Входные данные:**
- Числовое значение приоритета (целое число, положительное или отрицательное)

**Выходные данные:**
- Приоритет установлен для тега

**Бизнес-правила:**
- Значение по умолчанию — 0
- Тег с более высоким значением приоритета начинает выполнение раньше
- Приоритет влияет ТОЛЬКО на порядок начала выполнения, НЕ на порядок завершения
- Теги выполняются асинхронно: тег с приоритетом 3 начнёт выполняться раньше тега с приоритетом 1, но может завершиться позже
- Приоритет действует только среди тегов, привязанных к одному и тому же триггеру
- Для гарантированного последовательного выполнения следует использовать Tag Sequencing (FR-TAG-007), а не приоритет

---

### FR-TAG-007: Настройка последовательности выполнения (Tag Sequencing)

**Приоритет:** Высокий

**Описание:** Пользователь должен иметь возможность задать теги, которые должны выполниться ДО (Setup Tag) и ПОСЛЕ (Cleanup Tag) основного тега, с гарантией последовательности.

**Входные данные:**
- Setup Tag (тег подготовки) — опционально, выполняется перед основным тегом
- Cleanup Tag (тег очистки) — опционально, выполняется после основного тега
- Флаг: "Не запускать основной тег, если Setup Tag не выполнился" (опционально)
- Флаг: "Не запускать Cleanup Tag, если основной тег не выполнился" (опционально)

**Выходные данные:**
- Последовательность выполнения настроена

**Бизнес-правила:**
- В последовательности участвуют максимум 3 тега: Setup → Main → Cleanup
- Setup Tag гарантированно завершается ПЕРЕД запуском основного тега (синхронное ожидание)
- Cleanup Tag гарантированно запускается ПОСЛЕ завершения основного тега
- Если включён флаг "Не запускать основной тег при ошибке Setup", и Setup Tag завершился с ошибкой — основной тег НЕ выполняется
- Если включён флаг "Не запускать Cleanup при ошибке Main", и основной тег завершился с ошибкой — Cleanup Tag НЕ выполняется
- Setup и Cleanup теги сами по себе не требуют собственных триггеров — они наследуют триггер основного тега
- Тег не может быть одновременно Setup/Cleanup тегом и иметь собственную последовательность
- Tag Sequencing — это единственный способ гарантировать строгий порядок выполнения (в отличие от Tag Firing Priority)

### FR-TAG-008: Настройка параметров частоты срабатывания (Tag Firing Options)

**Приоритет:** Высокий

**Описание:** Пользователь должен иметь возможность ограничить частоту срабатывания тега.

**Варианты:**

| Опция | Описание |
|-------|----------|
| **Once per event** | Тег срабатывает один раз на каждое событие (значение по умолчанию) |
| **Once per page** | Тег срабатывает максимум один раз за загрузку страницы, даже если триггер активируется многократно |
| **Unlimited** | Тег срабатывает каждый раз, когда срабатывает триггер, без ограничений. Применяется только в контексте Tag Sequencing |

**Бизнес-правила:**
- "Once per event" — значение по умолчанию для новых тегов
- "Once per page" полезен для тегов, которые должны загрузиться ровно один раз (например, базовая конфигурация аналитики)
- "Unlimited" используется преимущественно при Tag Sequencing, когда Setup/Cleanup тег должен срабатывать при каждом вызове основного тега
- Если два триггера одного типа (например, оба — Click) срабатывают от одного и того же клика, тег с опцией "Once per event" сработает только один раз
- На SPA (Single-Page Applications) "Once per page" может работать некорректно из-за отсутствия реальных перезагрузок страницы

### FR-TAG-009: Постановка тега на паузу и снятие с паузы

**Приоритет:** Высокий

**Описание:** Пользователь должен иметь возможность временно приостановить срабатывание тега без его удаления и без изменения триггеров.

**Входные данные:**
- Действие: Пауза (Pause) или Снятие с паузы (Unpause)

**Выходные данные:**
- Тег переведён в статус "Paused" или возвращён в активный статус
- Визуальная индикация паузы в списке тегов (иконка паузы)

**Бизнес-правила:**
- Приостановленный тег НЕ срабатывает, даже если его триггеры активируются
- Приостановленный тег НЕ загружает никакой JavaScript-код на страницу
- Изменение статуса паузы требует сохранения и публикации для вступления в силу
- Пауза сохраняет все настройки тега (триггеры, переменные, конфигурацию)
- Пауза полезна для временного отключения тегов рекламных кампаний, отладки проблем, A/B тестирования тегов

### FR-TAG-010: Настройка расписания срабатывания тега (Tag Firing Schedule)

**Приоритет:** Средний

**Описание:** Пользователь должен иметь возможность задать временной диапазон, в течение которого тег будет активен.

**Входные данные:**
- Дата и время начала активности (Start Date)
- Дата и время окончания активности (End Date)
- Часовой пояс

**Выходные данные:**
- Тег срабатывает только в заданном временном окне

**Бизнес-правила:**
- Вне заданного временного диапазона тег НЕ срабатывает, даже если триггеры активируются
- Расписание проверяется на стороне клиента (по времени браузера пользователя или по серверному времени в зависимости от настройки)
- Расписание не влияет на статус тега — тег остаётся "активным", но просто не срабатывает вне окна
- Полезно для ограниченных по времени кампаний и промоакций

### FR-TAG-011: Настройка согласий (Consent Settings)

**Приоритет:** Критический

**Описание:** Пользователь должен иметь возможность настроить, какие типы согласий пользователя (consent) необходимы для срабатывания тега.

**Типы согласий:**
- `ad_storage` — хранение данных для рекламы (cookies рекламных платформ)
- `analytics_storage` — хранение данных аналитики (cookies аналитики)
- `ad_user_data` — отправка пользовательских данных в рекламные платформы
- `ad_personalization` — использование данных для персонализации рекламы
- `functionality_storage` — хранение данных для функциональности сайта
- `personalization_storage` — хранение данных для персонализации
- `security_storage` — хранение данных безопасности

**Два типа проверок согласий:**

| Тип | Описание |
|-----|----------|
| **Built-in Consent Checks** | Встроены в тег (например, тег Google Analytics автоматически проверяет `analytics_storage`). Логика изменяет поведение тега на основе статуса согласия |
| **Additional Consent Checks** | Дополнительные проверки, заданные пользователем вручную. Если любой из указанных типов согласия имеет статус "denied" — тег НЕ срабатывает |

**Режимы реализации Consent Mode:**

| Режим | Поведение |
|-------|-----------|
| **Basic** | Теги Google не загружаются до взаимодействия пользователя с баннером согласия. Данные не передаются до получения согласия |
| **Advanced** | Теги загружаются сразу, но отправляют только анонимизированные пинги (без cookies) до получения согласия. После получения согласия — полноценное отслеживание |

**Бизнес-правила:**
- Consent Mode обязателен для соблюдения GDPR, ePrivacy Directive и аналогичных регуляций
- Consent Mode v2 (текущая версия) требует все четыре типа: `ad_storage`, `analytics_storage`, `ad_user_data`, `ad_personalization`
- Встроенные проверки нельзя отключить — они являются частью тега
- Additional Consent Checks добавляются через Advanced Settings тега
- Consent Initialization — специальный триггер, который срабатывает до всех остальных триггеров для установки начального состояния согласий
- Теги с Additional Consent Checks не срабатывают, если хотя бы один указанный тип согласия имеет статус "denied"
- Функция Consent Overview (включается в Admin > Container Settings) позволяет видеть состояние согласий всех тегов контейнера на одной странице

### FR-TAG-012: Редактирование тега

**Приоритет:** Критический

**Описание:** Пользователь с правами Edit и выше должен иметь возможность изменить любые параметры существующего тега.

**Доступные для редактирования параметры:**
- Название тега
- Тип тега (только путём пересоздания)
- Параметры конфигурации (зависят от типа)
- Привязанные триггеры (срабатывания и исключения)
- Приоритет срабатывания
- Последовательность выполнения (Tag Sequencing)
- Параметры частоты срабатывания
- Настройки согласий
- Расписание

**Бизнес-правила:**
- Редактирование происходит в рабочем пространстве пользователя
- Тип тега не может быть изменён — необходимо создать новый тег нужного типа
- Изменения не влияют на опубликованную версию до публикации
- Несколько пользователей могут работать с одним тегом в разных рабочих пространствах, но при публикации возможны конфликты
- При редактировании сохраняется история изменений тега

---

### FR-TAG-013: Удаление тега

**Приоритет:** Высокий

**Описание:** Пользователь с правами Edit и выше должен иметь возможность удалить тег из контейнера.

**Бизнес-правила:**
- Удаление происходит в рабочем пространстве и требует публикации для вступления в силу
- При удалении тега привязанные к нему триггеры НЕ удаляются (триггеры могут использоваться другими тегами)
- Если удаляемый тег используется как Setup или Cleanup в последовательности другого тега — пользователь получает предупреждение
- Удалённый тег можно восстановить до публикации через отмену изменений в рабочем пространстве
- После публикации восстановление возможно через откат версии контейнера

---

### FR-TAG-014: Копирование (дублирование) тега

**Приоритет:** Средний

**Описание:** Пользователь должен иметь возможность создать копию существующего тега со всеми его настройками.

**Бизнес-правила:**
- Копия создаётся с суффиксом "— Copy" в названии
- Все настройки копируются: конфигурация, триггеры, приоритет, последовательность, consent settings
- Копия создаётся в том же рабочем пространстве
- Копия находится в статусе "Draft"

## Состояния и статусы

### Жизненный цикл тега

```
[Создан (Draft)] → [Сохранён в Workspace] → [Включён в Версию] → [Опубликован (Live)]
                                                                          ↓
                                                                    [Изменён (Modified)]
                                                                          ↓
                                                                    [Опубликован (Live)]
```

### Статусы тега

| Статус | Описание | Переходы |
|--------|----------|----------|
| **Draft** | Тег создан, но не сохранён в версии контейнера | → Saved in Version, → Deleted |
| **Active (Published)** | Тег опубликован и срабатывает при выполнении условий триггеров | → Modified, → Paused, → Deleted |
| **Paused** | Тег приостановлен, не срабатывает | → Active (через Unpause + Publish) |
| **Modified (Unpublished changes)** | Тег изменён в рабочем пространстве, но изменения не опубликованы | → Active (через Publish), → Reverted |
| **Scheduled** | Тег активен только в заданном временном окне | → Active (при наступлении времени), → Inactive (по истечении окна) |
| **Deleted (in workspace)** | Тег удалён в рабочем пространстве, но удаление не опубликовано | → Active (через Revert), → Permanently Deleted (через Publish) |

### Состояния срабатывания тега (runtime)

| Состояние | Описание |
|-----------|----------|
| **Fired** | Тег успешно выполнился |
| **Not Fired** | Тег не сработал (триггер не активировался) |
| **Blocked by Exception Trigger** | Тег заблокирован триггером исключения |
| **Blocked by Consent** | Тег заблокирован из-за отсутствия согласия пользователя |
| **Paused** | Тег не сработал, так как находится на паузе |
| **Failed** | Тег сработал, но выполнение завершилось ошибкой |
| **Outside Schedule** | Тег не сработал, так как текущее время вне расписания |

## Интеграции с другими модулями

### Триггеры (Triggers)
- Каждый тег обязан быть привязан минимум к одному триггеру срабатывания
- Триггеры исключения блокируют срабатывание тега при определённых условиях
- Consent Initialization Trigger — специальный триггер для установки начальных состояний согласий до загрузки всех остальных тегов

### Переменные (Variables)
- Теги используют переменные для динамической подстановки значений в конфигурации
- Встроенные переменные (Page URL, Click Element, Event и др.)
- Пользовательские переменные (Data Layer Variable, Custom JavaScript, Lookup Table и др.)
- Переменные разрешаются в момент срабатывания тега

### Рабочие пространства (Workspaces)
- Все изменения тегов происходят в рамках рабочего пространства
- Несколько пользователей могут работать над разными тегами в разных рабочих пространствах параллельно
- При публикации рабочего пространства могут возникнуть конфликты, если другие пространства изменяли те же теги

### Версии (Versions)
- Каждая публикация создаёт новую версию контейнера
- Версии включают снимок всех тегов, триггеров и переменных
- Возможен откат к любой предыдущей версии

### Папки (Folders)
- Теги могут быть организованы в папки для удобства навигации
- Папки носят организационный характер и не влияют на логику выполнения

### Среды (Environments)
- Теги публикуются в среду (Production, Staging, Development)
- Среды позволяют тестировать теги на staging-сервере перед развёртыванием в production

### Consent Overview
- Центральная панель для просмотра настроек согласий всех тегов контейнера
- Позволяет выявить теги без настроенных consent checks

### Tag Assistant / Preview Mode
- Инструмент отладки, показывающий работу тегов в реальном времени
- Интеграция с Chrome DevTools для расширенной отладки

### Community Template Gallery
- Источник шаблонов тегов от сторонних разработчиков
- Система разрешений для контроля доступа шаблонов к данным
