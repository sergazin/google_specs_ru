# Интеграции и дополнения (Add-ons)

## Описание

Модуль "Интеграции и дополнения" обеспечивает расширение функциональности Google Forms через встроенные интеграции с сервисами Google Workspace (Drive, Sheets, Calendar, Gmail) и систему установки дополнительных расширений (add-ons) из Google Workspace Marketplace. Модуль позволяет автоматизировать рабочие процессы, расширять возможности форм, интегрироваться со сторонними сервисами через Zapier и API, а также управлять установленными дополнениями с контролем разрешений.

Система дополнений предоставляет доступ к сотням расширений от сторонних разработчиков, включая таймеры для тестирования, системы прокторинга, расширенную аналитику, автоматическую отправку уведомлений, генерацию документов, выдачу сертификатов и интеграцию с внешними платформами. В 2025 году интеграция дополнена возможностями Google Workspace Studio для автоматизации через Gemini AI и поддержкой Forms API для программного управления формами.

Цель модуля - превратить Google Forms из простого инструмента сбора данных в мощную платформу для автоматизации бизнес-процессов, онлайн-тестирования с прокторингом, управления рабочими процессами и интеграции с корпоративными системами через открытые API и богатую экосистему дополнений.

## Роли пользователей

### Роли в контексте интеграций и дополнений:

1. **Владелец формы (Form Owner)** - пользователь, создавший форму
   - Может устанавливать и удалять дополнения для своих форм
   - Настраивает интеграции с Google Sheets, Calendar, Gmail
   - Управляет разрешениями установленных дополнений
   - Может использовать Apps Script для кастомной автоматизации
   - Настраивает связь с таблицей Sheets для сбора ответов
   - Настраивает интеграции с Zapier и webhook для автоматизации
   - Может использовать Forms API для программного управления

2. **Редактор формы (Form Editor)** - пользователь с правами редактирования
   - Может использовать установленные дополнения владельцем
   - Может просматривать ответы в связанной таблице Sheets
   - Не может устанавливать или удалять дополнения
   - Может экспортировать ответы в различные форматы
   - Может использовать функции установленных add-ons

3. **Респондент (Respondent)** - пользователь, заполняющий форму
   - Взаимодействует с функциями дополнений (таймер, прокторинг)
   - Может получать автоматические уведомления и сертификаты
   - Видит интегрированные календарные события при регистрации
   - Предоставляет разрешения на камеру/экран (при прокторинге)
   - Получает подтверждения по email через настроенные add-ons

4. **Пользователь Google Workspace** - пользователь с Google аккаунтом
   - Имеет доступ ко всем встроенным интеграциям Google
   - Может устанавливать дополнения из Workspace Marketplace
   - Может использовать Gemini AI для автоматизации через Workspace Studio
   - Может создавать кастомные интеграции через Apps Script
   - Может использовать Forms API для программной работы

5. **Администратор Google Workspace** - корпоративный администратор
   - Управляет доступом к Google Workspace Marketplace на уровне организации
   - Может блокировать или разрешать установку конкретных дополнений
   - Настраивает политики безопасности для add-ons
   - Может устанавливать дополнения для всех пользователей домена
   - Управляет разрешениями API на уровне организации
   - Настраивает доступ к Gemini AI для пользователей

6. **Разработчик (Developer)** - технический пользователь
   - Создает кастомные add-ons через Apps Script
   - Использует Forms API для интеграции с внешними системами
   - Публикует дополнения в Workspace Marketplace
   - Настраивает OAuth авторизацию для приложений
   - Разрабатывает интеграции через Zapier, Make, API webhooks
   - Использует Google Apps Script Forms Service для автоматизации

### FR-INT-001: Автоматическая связь формы с Google Sheets

**Описание:** Позволяет автоматически создавать таблицу Google Sheets для сбора ответов на форму с синхронизацией в реальном времени при каждой отправке формы.

**Роли:** Владелец формы, Редактор формы

**Предусловия:**
- Пользователь создал форму в Google Forms
- Пользователь авторизован в Google Drive
- У пользователя есть место в хранилище Drive (хотя Sheets не занимает место)

**Основной сценарий:**
1. Пользователь открывает созданную форму в режиме редактирования
2. Переходит на вкладку "Ответы" (Responses) в верхней части редактора
3. Нажимает зеленую иконку с крестиком "Создать таблицу" (Create Spreadsheet)
4. В диалоговом окне выбирает один из вариантов: "Создать новую таблицу" или "Выбрать существующую таблицу"
5. При выборе "Создать новую" вводит название таблицы или оставляет по умолчанию (название формы + " (Responses)")
6. Нажимает кнопку "Создать" (Create)
7. Система создает таблицу Google Sheets в той же папке Drive, где находится форма
8. Таблица автоматически открывается в новой вкладке

**Альтернативные сценарии:**
- Сценарий A (Выбор существующей таблицы): Пользователь выбирает "Выбрать существующую таблицу", открывается окно выбора из Drive, выбирает таблицу, новый лист добавляется в выбранную таблицу с названием "Form Responses 1"
- Сценарий B (Автоматическое создание столбцов): Система автоматически создает столбцы в таблице: "Timestamp" (дата/время отправки), затем по одному столбцу для каждого вопроса формы с заголовками из текста вопросов
- Сценарий C (Реальное время обновления): Респондент отправляет заполненную форму, в течение 1-2 секунд новая строка с ответами автоматически добавляется в таблицу Sheets, все пользователи с доступом к таблице видят обновление
- Сценарий D (Отключение связи): Владелец в настройках таблицы может отключить автоматический сбор ответов, нажав "Отключить связь с формой", существующие данные сохраняются, новые ответы не добавляются

**Бизнес-правила:**
- BR-INT-001: Таблица Sheets создается в той же папке Drive, где находится форма
- BR-INT-002: Таблица наследует права доступа формы, но владелец может изменить их независимо
- BR-INT-003: Синхронизация происходит в режиме реального времени (задержка < 5 секунд)
- BR-INT-004: Первый столбец всегда "Timestamp" с датой и временем отправки
- BR-INT-005: При изменении вопросов в форме новые столбцы добавляются в таблицу автоматически
- BR-INT-006: Удаление ответа в форме не удаляет строку в таблице (требуется ручное удаление)
- BR-INT-007: Одна форма может быть связана только с одной таблицей одновременно

**Результат:** Таблица Google Sheets создана и связана с формой, автоматически собирает все ответы в реальном времени с временной меткой и организацией по столбцам для каждого вопроса

### FR-INT-002: Экспорт ответов формы в различные форматы

**Описание:** Позволяет экспортировать все ответы формы в различные форматы файлов (CSV, Excel, PDF) для анализа в сторонних приложениях или архивирования.

**Роли:** Владелец формы, Редактор формы

**Предусловия:**
- Форма получила хотя бы один ответ
- Пользователь имеет доступ к просмотру ответов
- Форма связана с таблицей Google Sheets

**Основной сценарий:**
1. Пользователь открывает форму и переходит на вкладку "Ответы"
2. Нажимает на иконку с тремя точками (меню дополнительных действий)
3. Выбирает опцию "Скачать ответы (.csv)"
4. Браузер начинает скачивание CSV файла с названием формы
5. Файл сохраняется в папку загрузок с расширением .csv
6. Файл содержит все ответы с временными метками в табличном формате

**Альтернативные сценарии:**
- Сценарий A (Экспорт через Sheets в Excel): Пользователь открывает связанную таблицу Sheets, нажимает "Файл" -> "Скачать" -> "Microsoft Excel (.xlsx)", получает файл в формате Excel с сохранением всех формул и форматирования
- Сценарий B (Экспорт в PDF через Sheets): Пользователь открывает таблицу Sheets, выбирает "Файл" -> "Скачать" -> "PDF-документ (.pdf)", настраивает параметры страницы (альбомная/книжная, масштаб), получает PDF для печати или архивирования
- Сценарий C (Экспорт отдельных ответов): Пользователь в индивидуальном режиме просмотра ответов нажимает "Печать", затем "Сохранить как PDF", сохраняет один ответ в формате PDF для документирования
- Сценарий D (Автоматический экспорт через Apps Script): Разработчик создает скрипт для автоматического экспорта ответов раз в день/неделю в Google Drive в формате CSV с последующей отправкой по email

**Бизнес-правила:**
- BR-INT-008: CSV экспорт доступен напрямую из интерфейса Forms
- BR-INT-009: Excel и PDF экспорт требует перехода в связанную таблицу Sheets
- BR-INT-010: CSV файл использует кодировку UTF-8 для поддержки международных символов
- BR-INT-011: Экспортируются только отправленные ответы (черновики не включаются)
- BR-INT-012: Экспорт сохраняет временные метки в формате ISO 8601
- BR-INT-013: Загруженные респондентами файлы не включаются в CSV (только ссылки на них)

**Результат:** Ответы формы экспортированы в выбранный формат файла, готовы для анализа в Excel, архивирования в PDF или импорта в другие системы через CSV

### FR-INT-003: Интеграция с Gmail для автоматических уведомлений

**Описание:** Позволяет настроить автоматическую отправку email-уведомлений владельцу формы при каждом новом ответе через встроенную интеграцию с Gmail.

**Роли:** Владелец формы

**Предусловия:**
- Пользователь является владельцем формы
- У пользователя есть активный Gmail аккаунт
- Форма опубликована и принимает ответы

**Основной сценарий:**
1. Пользователь открывает форму в режиме редактирования
2. Переходит на вкладку "Ответы" (Responses)
3. Нажимает на иконку с тремя точками (дополнительные настройки)
4. Выбирает опцию "Получать уведомления о новых ответах" (Get email notifications for new responses)
5. Включает переключатель уведомлений
6. Система сохраняет настройку
7. При каждом новом ответе владелец получает email на адрес Gmail, связанный с Google аккаунтом

**Альтернативные сценарии:**
- Сценарий A (Уведомления через Apps Script): Разработчик создает кастомный скрипт для отправки уведомлений нескольким адресатам, настраивает триггер "On form submit", скрипт отправляет письмо с деталями ответа через MailApp.sendEmail()
- Сценарий B (Условные уведомления): Через Apps Script пользователь настраивает отправку уведомлений только при определенных условиях (например, если ответ содержит конкретное значение или оценка ниже порога)
- Сценарий C (Уведомления с кастомным шаблоном): Разработчик использует HTML-шаблоны для форматирования email с логотипом компании, цветовой схемой и структурированным отображением ответов
- Сценарий D (Уведомления в Google Chat): Через Workspace Studio пользователь настраивает автоматизацию: при новом ответе формы отправляется сообщение в групповой чат команды с кратким обзором ответа

**Бизнес-правила:**
- BR-INT-014: Уведомления отправляются на email владельца формы (изменить получателя нельзя без Apps Script)
- BR-INT-015: Email содержит краткое резюме ответа и ссылку на полный ответ в форме
- BR-INT-016: Уведомления отправляются мгновенно (в течение минуты после отправки формы)
- BR-INT-017: Для отправки уведомлениям нескольким людям требуется использование Apps Script
- BR-INT-018: Уведомления можно отключить в любой момент в настройках формы
- BR-INT-019: С 2025 года через Workspace Studio можно настроить уведомления в Google Chat и контактные группы

**Результат:** Автоматические email-уведомления настроены, владелец формы получает мгновенное оповещение на Gmail при каждом новом ответе с кратким резюме и ссылкой для просмотра деталей

### FR-INT-004: Интеграция с Google Calendar для создания событий

**Описание:** Позволяет автоматически создавать события в Google Calendar на основе ответов формы, например, для регистрации на встречи, бронирования времени или записи на консультации.

**Роли:** Владелец формы, Респондент

**Предусловия:**
- Форма содержит вопросы с типом "Дата" и/или "Время"
- Пользователь имеет доступ к Google Calendar
- Форма опубликована и принимает ответы

**Основной сценарий:**
1. Владелец формы добавляет вопрос типа "Дата" для выбора даты события
2. Добавляет вопрос типа "Время" для выбора времени события
3. Устанавливает расширение "Form Director" или аналогичное из Marketplace
4. Настраивает add-on: выбирает календарь для создания событий
5. Настраивает маппинг полей формы (дата, время, название, описание)
6. Респондент заполняет форму, выбирает дату и время
7. При отправке формы автоматически создается событие в указанном Calendar
8. Респондент опционально получает приглашение на событие по email

**Альтернативные сценарии:**
- Сценарий A (Использование Apps Script): Разработчик создает скрипт, использующий CalendarApp.getDefaultCalendar().createEvent(), настраивает триггер на отправку формы, события создаются автоматически с данными из ответов
- Сценарий B (Добавление участников): При заполнении формы респондент вводит email, скрипт добавляет его как участника события, респондент получает приглашение в Calendar с возможностью принять/отклонить
- Сценарий C (Проверка доступности): Скрипт проверяет доступность временного слота через Calendar API перед созданием события, если время занято, отправляет респонденту email с просьбой выбрать другое время
- Сценарий D (Интеграция с Meet): При создании события автоматически добавляется ссылка на Google Meet видеоконференцию, респонденту отправляется приглашение с возможностью присоединиться к звонку

**Бизнес-правила:**
- BR-INT-020: Прямая интеграция с Calendar требует использования дополнений или Apps Script
- BR-INT-021: События могут создаваться в личном календаре или общем календаре с правами редактирования
- BR-INT-022: При создании события можно устанавливать напоминания (за 10 минут, час, день)
- BR-INT-023: События могут включать описание, локацию, участников из ответов формы
- BR-INT-024: Если респондент редактирует ответ формы, событие не обновляется автоматически (требуется кастомная логика)
- BR-INT-025: Максимум 5000 событий можно создать через Apps Script в день (квота Google)

**Результат:** При отправке формы автоматически создается событие в Google Calendar с выбранной датой, временем и деталями, респондент получает приглашение и может добавить встречу в свой календарь

### FR-INT-005: Установка дополнений (Add-ons) из Google Workspace Marketplace

**Описание:** Позволяет пользователям устанавливать дополнительные расширения функциональности для Google Forms из официального магазина Google Workspace Marketplace.

**Роли:** Владелец формы, Пользователь Google Workspace

**Предусловия:**
- Пользователь авторизован в Google Forms
- У пользователя есть активный Google аккаунт
- Администратор организации не заблокировал установку add-ons (для Workspace)

**Основной сценарий:**
1. Пользователь открывает форму в режиме редактирования
2. Нажимает на иконку с тремя точками (дополнительное меню) в правом верхнем углу
3. Выбирает опцию "Дополнения" (Add-ons)
4. В открывшемся окне нажимает "Установить дополнения" (Get add-ons)
5. Открывается Google Workspace Marketplace с фильтром "Works with Forms"
6. Пользователь просматривает доступные дополнения, читает описания и отзывы
7. Нажимает "Установить" (Install) на выбранном дополнении
8. Система запрашивает разрешения доступа (просмотр/редактирование форм, доступ к Drive, отправка email)
9. Пользователь просматривает разрешения и нажимает "Разрешить" (Allow)
10. Дополнение устанавливается и становится доступно в меню Add-ons формы

**Альтернативные сценарии:**
- Сценарий A (Установка конкретного дополнения): Пользователь ищет дополнение по названию (например, "Quilgo" для прокторинга), находит в результатах, устанавливает, настраивает параметры в интерфейсе дополнения
- Сценарий B (Просмотр популярных дополнений): В Marketplace пользователь фильтрует по категориям (Education, Productivity, Notifications), сортирует по популярности или рейтингу, выбирает наиболее подходящее
- Сценарий C (Установка для всех форм): После установки дополнение доступно для всех форм пользователя, не требует повторной установки для каждой формы
- Сценарий D (Отклонение разрешений): Пользователь отклоняет запрос разрешений, установка прерывается, дополнение не устанавливается, пользователь может повторить попытку позже

**Бизнес-правила:**
- BR-INT-026: Дополнения устанавливаются для всего аккаунта пользователя, не для отдельной формы
- BR-INT-027: Каждое дополнение запрашивает только необходимые разрешения согласно политике Google
- BR-INT-028: Администраторы Workspace могут блокировать установку дополнений на уровне организации
- BR-INT-029: Бесплатные дополнения не требуют оплаты, платные предлагают пробный период
- BR-INT-030: Установленные дополнения автоматически обновляются разработчиками
- BR-INT-031: Пользователь может установить неограниченное количество дополнений

**Результат:** Дополнение установлено из Workspace Marketplace, доступно в меню Add-ons формы, готово к использованию с предоставленными разрешениями для расширения функциональности

### FR-INT-006: Использование таймера для тестирования (Timer Add-ons)

### FR-INT-007: Прокторинг тестов (Camera and Screen Monitoring)

**Описание:** Позволяет включить функции прокторинга для контроля честности прохождения онлайн-тестов через мониторинг камеры, записи экрана, отслеживания переключения вкладок и блокировки полноэкранного режима.

**Роли:** Владелец формы, Респондент

**Предусловия:**
- Владелец установил add-on с функцией прокторинга (Quilgo, Extended Forms, BoloForms, AutoProctor)
- Форма настроена как тест с включенным режимом тестирования
- Респондент имеет веб-камеру и микрофон (для аудио-прокторинга)

**Основной сценарий:**
1. Владелец формы открывает установленное дополнение для прокторинга (например, Quilgo)
2. В настройках включает функции прокторинга: "Camera monitoring", "Screen recording", "Tab switch detection"
3. Настраивает параметры: частоту снимков с камеры (каждые 30 секунд), блокировку полноэкранного режима
4. Устанавливает настройки Trust Score (автоматический расчет уровня доверия)
5. Сохраняет настройки и публикует форму
6. Респондент открывает форму, система запрашивает разрешения на доступ к камере и экрану
7. Респондент предоставляет разрешения и начинает тест
8. В течение теста система делает снимки с камеры, записывает экран, отслеживает переключения вкладок
9. После отправки формы владелец получает отчет с Trust Score, снимками, логами аномалий

**Альтернативные сценарии:**
- Сценарий A (Отказ от разрешений): Респондент отказывается предоставить доступ к камере, система блокирует доступ к тесту, отображает сообщение "Прокторинг обязателен для этого теста"
- Сценарий B (Обнаружение переключения вкладок): Респондент переключается на другую вкладку браузера, система фиксирует событие, добавляет метку в отчет, снижает Trust Score, опционально блокирует дальнейшее прохождение
- Sценарий C (AI-распознавание аномалий): Quilgo использует AI для анализа снимков с камеры, обнаруживает присутствие нескольких людей, использование телефона, отсутствие респондента перед камерой, отмечает в отчете
- Сценарий D (Полноэкранный режим): Система принудительно переводит браузер в полноэкранный режим, блокирует выход, при попытке выхода фиксируется нарушение и снижается Trust Score

**Бизнес-правила:**
- BR-INT-038: Прокторинг требует явного согласия респондента на доступ к камере и экрану
- BR-INT-039: Все записи и снимки хранятся в Google Drive владельца формы в зашифрованном виде
- BR-INT-040: Trust Score рассчитывается на основе количества аномалий: переключение вкладок, отсутствие лица, несколько людей
- BR-INT-041: Снимки с камеры делаются через случайные интервалы (каждые 15-60 секунд)
- BR-INT-042: Прокторинг работает только в современных браузерах (Chrome, Edge, Firefox)
- BR-INT-043: Респондент видит индикатор активной камеры/записи экрана в браузере
- BR-INT-044: Владелец может просматривать индивидуальные отчеты прокторинга для каждого респондента

**Результат:** Прокторинг включен для теста, система мониторит поведение респондентов через камеру и запись экрана, генерирует Trust Score и детальный отчет с снимками и логами аномалий для выявления нечестного поведения

- Сценарий A (Gemini анализ ответов формы): Пользователь настраивает поток: новый ответ → Gemini анализирует текстовые ответы → определяет приоритет запроса (низкий/средний/высокий) → создает задачу в Google Tasks с соответствующим приоритетом
- Сценарий B (Автоматическое резюмирование): При получении 10+ ответов Workspace Studio через Gemini создает сводку ключевых инсайтов, отправляет email с резюме руководителю
- Sценарий C (Триггеры на основе содержания): Gemini анализирует ответы формы, при обнаружении негативного отзыва (sentiment analysis) автоматически создает приоритетный тикет в системе поддержки
- Сценарий D (Интеграция с Calendar и Gmail): Новый ответ формы регистрации → Gemini извлекает дату/время → создает событие Calendar → отправляет приглашение через Gmail с персонализированным текстом

**Бизнес-правила:**
- BR-INT-106: Workspace Studio доступен для Google Workspace Business и Enterprise планов
- BR-INT-107: Gemini AI может анализировать и обрабатывать данные форм на естественном языке
- BR-INT-108: Автоматизации могут связывать Forms с Gmail, Drive, Sheets, Calendar, Meet, Chat, Tasks
- BR-INT-109: Не требуется программирование, автоматизации создаются через естественный язык
- BR-INT-110: Потоки выполняются на инфраструктуре Google, не требуют собственных серверов
- BR-INT-111: Gemini может выполнять sentiment analysis, классификацию, извлечение данных из ответов

**Результат:** AI-автоматизация создана через Google Workspace Studio, использует Gemini для интеллектуальной обработки ответов формы, автоматически выполняет действия в других приложениях Workspace на основе анализа данных

### FR-INT-019: Экспорт и импорт форм для миграции и резервного копирования

**Описание:** Позволяет экспортировать структуру формы в различные форматы для резервного копирования, миграции между аккаунтами или создания шаблонов.

**Роли:** Владелец формы, Администратор Google Workspace

**Предусловия:**
- Пользователь имеет права владельца на форму
- Доступ к Google Drive для сохранения экспорта

**Основной сценарий:**
1. Пользователь открывает форму в режиме редактирования
2. Нажимает на иконку с тремя точками (меню) в правом верхнем углу
3. Выбирает опцию "Создать копию" (Make a copy)
4. Система создает полную копию формы с тем же названием + " (Copy)"
5. Копия сохраняется в ту же папку Drive
6. Пользователь может переместить копию в другую папку или предоставить доступ другому аккаунту
7. Для переноса в другой аккаунт предоставляет доступ "Редактор", получатель создает свою копию

**Альтернативные сценарии:**
- Сценарий A (Экспорт через Apps Script): Разработчик использует FormApp API для получения структуры формы в JSON, сохраняет в файл, импортирует в другой аккаунт через скрипт создания формы
- Сценарий B (Использование шаблонов): Пользователь создает форму как шаблон, сохраняет в Template Gallery организации, другие пользователи создают копии из галереи шаблонов
- Sценарий C (Массовая миграция форм): Администратор использует Google Drive API для копирования всех форм из одной папки в другую, сохраняет структуру папок, обновляет права доступа
- Сценарий D (Резервное копирование с ответами): Пользователь копирует форму и связанную таблицу Sheets с ответами, создает полный backup включая данные респондентов

**Бизнес-правила:**
- BR-INT-112: Копия формы создается без ответов (пустая форма)
- BR-INT-113: Все вопросы, настройки, темы оформления копируются полностью
- BR-INT-114: Связь с оригинальной таблицей Sheets не копируется (нужно создать новую)
- BR-INT-115: При копировании сохраняются настройки квизов с правильными ответами и баллами
- BR-INT-116: Add-ons не копируются автоматически, требуется переустановка
- BR-INT-117: Для экспорта структуры в JSON требуется использование Apps Script или API

**Результат:** Форма экспортирована/скопирована для резервного копирования, миграции в другой аккаунт или использования как шаблон, структура сохранена полностью без потери настроек

### FR-INT-020: Административное управление интеграциями на уровне организации

**Описание:** Позволяет администраторам Google Workspace централизованно управлять доступом к дополнениям, API интеграциям и внешним сервисам для всех пользователей организации.

**Роли:** Администратор Google Workspace

**Предусловия:**
- Пользователь имеет права администратора Google Workspace
- Организация использует Google Workspace (Business, Enterprise, Education)
- Доступ к Admin Console

**Основной сценарий:**
1. Администратор открывает Google Admin Console (admin.google.com)
2. Переходит в раздел "Apps" -> "Google Workspace" -> "Google Forms"
3. Просматривает настройки доступности Forms для организации
4. Переходит в "Marketplace apps" для управления дополнениями
5. Видит список установленных дополнений пользователями организации
6. Может заблокировать конкретные дополнения через "Block app"
7. Устанавливает политику: "Allow users to install only approved apps"
8. Добавляет утвержденные дополнения в whitelist
9. Настройки применяются ко всем пользователям домена

**Альтернативные сценарии:**
- Сценарий A (Централизованная установка дополнений): Администратор устанавливает дополнение для всех пользователей организации, настраивает параметры по умолчанию, пользователи автоматически получают доступ к add-on
- Сценарий B (Блокировка API доступа): Администратор в разделе "Security" -> "API controls" ограничивает доступ к Forms API, разрешает только доверенным приложениям через OAuth whitelist
- Sценарий C (Аудит использования интеграций): Администратор в разделе "Reports" -> "Audit" просматривает логи использования дополнений, API вызовов, выявляет неавторизованные интеграции
- Сценарий D (Политики для внешних интеграций): Администратор блокирует интеграцию с Zapier и webhook для отделов с конфиденциальными данными, разрешает только для маркетинга

**Бизнес-правила:**
- BR-INT-118: Администратор может блокировать установку конкретных add-ons для всей организации
- BR-INT-119: Политики безопасности применяются немедленно ко всем пользователям домена
- BR-INT-120: Заблокированные дополнения автоматически удаляются у пользователей
- BR-INT-121: Администратор может устанавливать дополнения централизованно для всех или OU
- BR-INT-122: API controls позволяют ограничить доступ сторонних приложений к данным Forms
- BR-INT-123: Логи аудита сохраняются минимум 6 месяцев для Enterprise планов

**Результат:** Администратор централизованно управляет доступом к интеграциям и дополнениям на уровне организации, обеспечивает безопасность данных через политики и whitelist, отслеживает использование через аудит-логи
