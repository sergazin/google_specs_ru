# Аналитика и отчеты

## Описание

Модуль аналитики и отчетов Google Forms - это комплексная система визуализации и анализа собранных ответов, которая включает автоматическую генерацию графиков и диаграмм в реальном времени, сводную статистику по форме, детальный анализ по каждому вопросу, временные метрики заполнения, встроенные инструменты фильтрации и сегментации данных, экспорт ответов в различных форматах, интеграцию с Google Sheets для расширенной аналитики с pivot-таблицами и формулами, а также возможность создания кастомных дашбордов. Система автоматически выбирает оптимальный тип визуализации в зависимости от типа вопроса, поддерживает интерактивное изучение данных, позволяет копировать графики для использования в презентациях и отчетах, и обеспечивает мгновенное обновление аналитики при получении новых ответов.

## Роли пользователей

- **Создатель формы (Owner)** - имеет полный доступ ко всем ответам, аналитике, может экспортировать данные, управлять настройками отчетов
- **Соавтор с правами редактирования (Editor)** - может просматривать все ответы и аналитику, экспортировать данные, но не может удалять ответы или изменять настройки формы
- **Соавтор только для просмотра (Viewer)** - может только просматривать аналитику и ответы, не может экспортировать или изменять данные
- **Пользователь Google Workspace** - имеет доступ к расширенным функциям аналитики и интеграции с другими сервисами Workspace
- **Администратор домена Workspace** - может просматривать аналитику всех форм в организации через Admin Console
- **Респондент (Respondent)** - обычно не имеет доступа к аналитике, если только создатель не включил опцию "See summary charts after submit"

## Функциональные требования

### FR-ANALYTICS-001: Вкладка "Responses" - центр управления ответами

**Описание:** Центральная вкладка для доступа ко всем ответам, аналитике и настройкам обработки данных формы.

**Роли:** Создатель формы, Соавтор с правами редактирования, Соавтор только для просмотра

**Предусловия:**
- Форма создана и опубликована
- Пользователь имеет доступ к форме
- Пользователь авторизован в Google Forms

**Основной сценарий:**
1. Пользователь открывает свою форму в режиме редактирования
2. Нажимает на вкладку "Responses" в верхней части интерфейса (рядом с "Questions")
3. Система отображает вкладку с тремя основными подразделами:
   - **Summary** (Сводка) - визуальная аналитика с графиками и диаграммами
   - **Question** (По вопросам) - детальный анализ каждого вопроса
   - **Individual** (Индивидуальные) - просмотр отдельных ответов респондентов
4. В верхней части вкладки отображается панель управления:
   - Переключатель "Accepting responses" (Принимать ответы) - включить/отключить прием новых ответов
   - Общее количество ответов - крупным шрифтом (например, "42 responses")
   - Иконка Google Sheets - создать или открыть связанную таблицу
   - Иконка Download (три точки) - меню экспорта в CSV
   - Иконка Print - печать сводки ответов
   - Иконка настроек (три точки) - дополнительные опции
5. При клике на переключатель "Accepting responses":
   - Зеленый (ON) - форма принимает ответы
   - Серый (OFF) - форма закрыта, появляется возможность ввести кастомное сообщение для респондентов
6. Счетчик ответов обновляется в реальном времени при получении новых ответов
7. Система показывает дату и время последнего полученного ответа
8. Если ответов еще нет, отображается сообщение:
   - "Waiting for responses" с иконкой пустой формы
   - Ссылка на форму для распространения
   - Кнопка "Send form" для быстрого доступа к отправке

**Альтернативные сценарии:**
- Сценарий А (Нет ответов): Показывается пустое состояние с подсказкой как получить первые ответы
- Сценарий Б (Форма закрыта): Переключатель в положении OFF, отображается сообщение о закрытии
- Сценарий В (Ограниченный доступ): Соавтор только для просмотра не видит переключатель приема ответов
- Сценарий Г (Большое количество ответов): При >1000 ответов появляется уведомление о возможной задержке загрузки

**Бизнес-правила:**
- BR-001: Вкладка Responses доступна только пользователям с правами редактирования или просмотра формы
- BR-002: Счетчик ответов обновляется в реальном времени без перезагрузки страницы
- BR-003: Переключатель "Accepting responses" доступен только создателю и соавторам с правами редактирования
- BR-004: По умолчанию открывается подраздел Summary
- BR-005: Все подразделы используют единый источник данных - полученные ответы
- BR-006: Максимальное отображаемое количество в счетчике - 999,999 (после показывается "999,999+")

**Результат:** Пользователь имеет доступ к центральному интерфейсу управления всеми ответами и аналитикой формы

### FR-ANALYTICS-002: Summary - сводная аналитика с автоматическими визуализациями

**Описание:** Автоматическая генерация визуальных диаграмм и графиков для всех вопросов формы с выбором оптимального типа визуализации в зависимости от типа вопроса.

**Роли:** Создатель формы, Соавтор с правами редактирования, Соавтор только для просмотра

**Предусловия:**
- Форма имеет хотя бы один ответ
- Пользователь находится на вкладке Responses
- Выбран подраздел Summary

**Основной сценарий:**
1. Пользователь открывает подраздел Summary во вкладке Responses
2. Система автоматически анализирует типы вопросов и генерирует визуализации
3. Для каждого вопроса отображается:
   - Заголовок вопроса жирным шрифтом
   - Количество ответов на этот вопрос
   - Визуализация данных в оптимальном формате
   - Опциональное описание вопроса (если было добавлено)
4. Типы автоматических визуализаций в зависимости от типа вопроса:

   **Для Multiple choice (Один вариант ответа):**
   - Круговая диаграмма (Pie chart) по умолчанию
   - Каждый вариант окрашен в свой цвет
   - Показывается процент выбора каждого варианта
   - Легенда с названиями вариантов справа от диаграммы
   - Отображается количество ответов для каждого варианта

   **Для Checkboxes (Множественный выбор):**
   - Горизонтальная столбчатая диаграмма (Horizontal bar chart)
   - Каждый вариант - отдельный столбец
   - Показывается количество и процент выборов
   - Респонденты могли выбрать несколько вариантов, сумма >100%
   - Столбцы отсортированы по популярности (от большего к меньшему)

   **Для Linear scale (Линейная шкала):**
   - Вертикальная столбчатая диаграмма (Column chart)
   - Ось X - значения шкалы (например, 1-5)
   - Ось Y - количество ответов
   - Каждый столбец показывает распределение выборов
   - Отображается средний балл (average) под диаграммой

   **Для Multiple choice grid / Checkbox grid:**
   - Таблица с результатами по каждой строке
   - Для каждой строки показывается мини-диаграмма или проценты
   - Сводная таблица с распределением ответов
   - Цветовое кодирование для лучшей читаемости

   **Для Dropdown (Выпадающий список):**
   - Круговая диаграмма аналогично Multiple choice
   - Или вертикальная столбчатая диаграмма при большом количестве вариантов (>7)

   **Для Short answer / Paragraph (Текстовые ответы):**
   - Список всех ответов в хронологическом порядке
   - Каждый ответ в отдельной карточке
   - Возможность прокрутки списка
   - Не создается график, так как ответы уникальны
   - Отображается количество полученных ответов

   **Для Date / Time:**
   - Список ответов или таблица с датами/временем
   - Временная диаграмма распределения (если много ответов)
   - Группировка по дням/неделям/месяцам

5. Все диаграммы отображаются последовательно, в том же порядке, что и вопросы в форме
6. Каждая визуализация занимает полную ширину контейнера
7. Между визуализациями есть разделители для лучшей читаемости
8. Для диаграмм с большим количеством вариантов (>15) применяется прокрутка или группировка

**Альтернативные сценарии:**
- Сценарий А (Нет ответов на вопрос): Показывается сообщение "No responses yet" вместо диаграммы
- Сценарий Б (Опция "Other"): Если в вопросе включена опция "Other", все текстовые ответы группируются под "Other"
- Сценарий В (Пропущенный вопрос): Если вопрос необязательный и его пропустили, это учитывается в статистике
- Сценарий Г (Очень длинные текстовые ответы): Текст обрезается с многоточием, полный текст виден при клике
- Сценарий Д (Одинаковые проценты): При равном распределении сегменты pie chart имеют равные размеры

**Бизнес-правила:**
- BR-007: Система автоматически выбирает оптимальный тип визуализации, пользователь не может изменить тип
- BR-008: Pie chart используется для вопросов с одним вариантом ответа и количеством опций ≤7
- BR-009: Bar chart используется для множественного выбора и шкал
- BR-010: Цвета диаграмм генерируются автоматически из палитры Material Design
- BR-011: Проценты округляются до целых чисел, если сумма не равна 100%, добавляется корректировка
- BR-012: Текстовые ответы не агрегируются, каждый уникальный ответ отображается отдельно
- BR-013: Для Linear scale автоматически вычисляется среднее значение (average)
- BR-014: Диаграммы обновляются в реальном времени при получении новых ответов
- BR-015: Максимум 50 уникальных вариантов в одной диаграмме, остальные группируются в "Other"

**Результат:** Пользователь видит визуальную сводку всех ответов с автоматически сгенерированными диаграммами

### FR-ANALYTICS-003: Интерактивность диаграмм - копирование и увеличение

**Описание:** Возможность копировать графики в буфер обмена для использования в других документах и увеличивать диаграммы для детального просмотра.

**Роли:** Создатель формы, Соавтор с правами редактирования, Соавтор только для просмотра

**Предусловия:**
- Пользователь находится в подразделе Summary
- Есть хотя бы одна сгенерированная диаграмма
- Диаграмма отображается на экране

**Основной сценарий:**
1. Пользователь наводит курсор мыши на любую диаграмму в Summary
2. В правом верхнем углу диаграммы появляется иконка "..." (три точки)
3. При клике на иконку открывается контекстное меню с опциями:
   - **Copy** (Копировать) - копирует диаграмму как изображение
   - **Download** (Скачать) - сохраняет диаграмму как PNG файл
4. При выборе "Copy":
   - Диаграмма конвертируется в изображение PNG
   - Изображение копируется в буфер обмена
   - Появляется всплывающее уведомление "Chart copied to clipboard"
   - Разрешение изображения: 1200x800 пикселей
   - Включается заголовок вопроса и легенда
5. Пользователь может вставить скопированную диаграмму:
   - В Google Docs через Ctrl+V (Cmd+V на Mac)
   - В Google Slides
   - В презентацию PowerPoint
   - В другие приложения, поддерживающие вставку изображений
6. При выборе "Download":
   - Диаграмма сохраняется как PNG файл
   - Название файла: "Form_title - Question_title.png"
   - Файл загружается в папку Downloads браузера
7. При клике на саму диаграмму (не на меню):
   - Диаграмма увеличивается в модальном окне
   - Фон затемняется (overlay)
   - Диаграмма отображается в большем размере для детального просмотра
   - Кнопка "X" в углу для закрытия модального окна
   - Клик вне диаграммы также закрывает модальное окно
8. В увеличенном виде доступны дополнительные детали:
   - Точные числовые значения для каждого сегмента
   - Полные названия вариантов ответов (без обрезки)
   - Улучшенная читаемость для сложных диаграмм

**Альтернативные сценарии:**
- Сценарий А (Браузер не поддерживает Clipboard API): Показывается сообщение с инструкцией использовать "Download"
- Сценарий Б (Блокировка всплывающих окон): Файл не скачивается, показывается уведомление о разрешении downloads
- Сценарий В (Мобильное устройство): На мобильных функция Copy может быть недоступна, только Download
- Сценарий Г (Очень большая диаграмма): При >50 элементов качество изображения увеличивается до 1600x1200

**Бизнес-правила:**
- BR-016: Копирование доступно для всех типов диаграмм кроме списков текстовых ответов
- BR-017: Формат экспорта - только PNG с прозрачным фоном
- BR-018: Разрешение изображения: стандарт 1200x800px, увеличенное 1600x1200px для сложных диаграмм
- BR-019: Скопированное изображение включает заголовок вопроса, легенду и данные
- BR-020: Цвета в экспортированной диаграмме соответствуют цветам в интерфейсе
- BR-021: Увеличение диаграммы не меняет данные, только размер отображения
- BR-022: Модальное окно закрывается по ESC или клику вне диаграммы

**Результат:** Пользователь может легко копировать диаграммы для использования в презентациях и документах

### FR-ANALYTICS-004: Question - детальный анализ по вопросам

**Описание:** Подраздел для изучения детальной статистики по каждому отдельному вопросу с расширенными метриками.

**Роли:** Создатель формы, Соавтор с правами редактирования, Соавтор только для просмотра

**Предусловия:**
- Форма имеет ответы
- Пользователь находится на вкладке Responses
- Выбран подраздел Question

**Основной сценарий:**
1. Пользователь кликает на подраздел "Question" на вкладке Responses
2. Система отображает выпадающий список (dropdown) всех вопросов формы в верхней части
3. Список содержит:
   - Номер вопроса (например, "Question 1")
   - Полный текст вопроса (обрезается если слишком длинный)
   - Тип вопроса в скобках (например, "Multiple choice")
4. Пользователь выбирает вопрос из списка для анализа
5. Система отображает детальную аналитику для выбранного вопроса:

   **Для вопросов с вариантами ответа (Multiple choice, Checkboxes, Dropdown):**
   - Крупная диаграмма (аналогично Summary, но больше размером)
   - Таблица с детальной статистикой:
     - Вариант ответа
     - Количество выборов (абсолютное число)
     - Процент от всех ответов
     - Визуальная шкала (progress bar) для каждого варианта
   - Общее количество ответов на вопрос
   - Количество пропущенных ответов (если вопрос необязательный)
   - Для Checkboxes: среднее количество выбранных вариантов на респондента

   **Для Linear scale:**
   - Столбчатая диаграмма распределения
   - Ключевые метрики:
     - Среднее значение (Average) с точностью до 2 знаков
     - Медиана (Median)
     - Мода (Mode) - наиболее частый ответ
     - Стандартное отклонение (если включено в настройках)
   - Таблица распределения по каждому значению шкалы
   - Процентное распределение
   - Общее количество ответов

   **Для Grid вопросов (Multiple choice grid, Checkbox grid):**
   - Таблица со всеми строками и столбцами
   - Для каждой ячейки: количество и процент выборов
   - Цветовое кодирование ячеек (heat map) для визуализации паттернов
   - Сводная строка с итогами по каждому столбцу
   - Сводный столбец с итогами по каждой строке
   - Наиболее популярная комбинация ответов

   **Для текстовых вопросов (Short answer, Paragraph):**
   - Полный список всех ответов
   - Сортировка по времени (новые сверху) или алфавиту
   - Функция поиска по ответам (search box)
   - Количество уникальных ответов
   - Количество повторяющихся ответов (если есть)
   - Средняя длина ответа (в символах/словах)
   - Возможность фильтрации ответов

   **Для Date/Time:**
   - Календарная визуализация (heat map по датам)
   - Список всех выбранных дат/времени
   - Диапазон дат (самая ранняя и поздняя)
   - Наиболее популярная дата/время
   - Временная диаграмма распределения

6. Навигация между вопросами:
   - Стрелки "Previous" / "Next" для перехода к предыдущему/следующему вопросу
   - Или выбор через dropdown список
7. Все данные обновляются в реальном времени при получении новых ответов

**Альтернативные сценарии:**
- Сценарий А (Вопрос без ответов): Показывается "0 responses" и пустая диаграмма
- Сценарий Б (Необязательный вопрос): Отображается количество пропущенных ответов отдельно
- Сценарий В (Опция "Other"): Все уникальные текстовые ответы "Other" показываются в отдельном разделе
- Сценарий Г (Длинные текстовые ответы): Применяется прокрутка или пагинация при >100 ответах
- Сценарий Д (Вопрос был изменен): Показывается предупреждение, что вопрос изменился после получения ответов

**Бизнес-правила:**
- BR-023: Dropdown список показывает все вопросы формы в порядке их расположения
- BR-024: Для вопросов с вариантами варианты сортируются по количеству выборов (популярности)
- BR-025: Проценты рассчитываются от общего количества ответивших на этот вопрос
- BR-026: Для необязательных вопросов пропущенные ответы не включаются в расчет процентов
- BR-027: Среднее значение для Linear scale округляется до 2 знаков после запятой
- BR-028: Текстовые ответы показываются в хронологическом порядке (новые сверху) по умолчанию
- BR-029: Цветовое кодирование в Grid использует градиент от светлого к темному
- BR-030: Максимум 1000 текстовых ответов на странице, остальные доступны через пагинацию

**Результат:** Пользователь получает детальную аналитику по каждому вопросу с расширенными метриками

### FR-ANALYTICS-006: Сводная статистика формы

**Описание:** Отображение общих метрик по форме включая количество ответов, процент завершения, среднее время заполнения.

**Роли:** Создатель формы, Соавтор с правами редактирования, Соавтор только для просмотра

**Предусловия:**
- Форма опубликована и получает/получала ответы
- Пользователь находится на вкладке Responses

**Основной сценарий:**
1. Пользователь открывает вкладку Responses формы
2. В верхней части над всеми подразделами отображается панель сводной статистики
3. Основные метрики показываются крупными карточками (cards):

   **Общее количество ответов:**
   - Крупное число с иконкой формы
   - Текст "responses" под числом
   - Обновляется в реальном времени

   **Средний процент завершения (Completion rate):**
   - Процент пользователей, которые завершили форму
   - Формула: (Завершенные ответы / Начатые) × 100%
   - Отображается с иконкой галочки
   - Цветовое кодирование: >80% зеленый, 50-80% желтый, <50% красный

   **Среднее время заполнения (Average completion time):**
   - Среднее время от открытия формы до отправки ответа
   - Формат отображения: "X min Y sec" или "X sec" если меньше минуты
   - Иконка часов/таймера
   - Вычисляется только для ответов, завершенных за одну сессию

4. Дополнительные метрики (отображаются под основными):

   **Временная диаграмма ответов:**
   - График получения ответов по времени
   - Ось X - дата/время
   - Ось Y - количество ответов
   - Показывает тренд: когда форма была наиболее активна
   - Можно переключать масштаб: по часам, дням, неделям, месяцам

   **Статус формы:**
   - "Accepting responses" - активна, зеленая метка
   - "Not accepting responses" - закрыта, красная метка
   - Количество просмотров формы (если доступно через Google Workspace)

   **Неполные ответы (если есть):**
   - Количество начатых, но незавершенных ответов
   - Процент пользователей, которые бросили форму
   - Вопрос, на котором чаще всего прерывались (drop-off point)

5. Временной график автоматически группирует данные:
   - По часам - если форма активна менее 2 дней
   - По дням - если форма активна 2-30 дней
   - По неделям - если форма активна 1-6 месяцев
   - По месяцам - если форма активна более 6 месяцев

6. При наведении на график отображается tooltip:
   - Точная дата/время
   - Количество ответов в этот период
   - Процент от общего количества

7. Все метрики можно скрыть/показать через кнопку "Show summary statistics"

**Альтернативные сценарии:**
- Сценарий А (Мало данных): Если ответов <5, средние метрики не показываются или помечаются как "Insufficient data"
- Сценарий Б (Форма без ограничения по времени): Среднее время может быть искажено, показывается только медианное время
- Сценарий В (Анонимные ответы): Completion rate может быть неточным без отслеживания пользователей
- Сценарий Г (Очень старая форма): График по умолчанию показывает последние 30 дней, доступна опция "Show all time"
- Сценарий Д (Всплеск ответов): График автоматически масштабируется для отображения пиков активности

**Бизнес-правила:**
- BR-039: Счетчик ответов обновляется каждые 10 секунд в реальном времени
- BR-040: Completion rate вычисляется только если включено отслеживание прогресса (Workspace feature)
- BR-041: Среднее время рассчитывается только для ответов, завершенных за <2 часа (игнорирует брошенные формы)
- BR-042: Медианное время используется вместо среднего если разброс >300% (устраняет выбросы)
- BR-043: Временной график показывает данные в часовом поясе создателя формы
- BR-044: Минимальное количество ответов для показа статистики времени - 3
- BR-045: Drop-off analysis доступен только в Google Workspace
- BR-046: Просмотры формы (views) отслеживаются только если форма встроена через iframe или через Workspace

**Результат:** Пользователь видит общую статистику эффективности формы и паттерны заполнения

### FR-ANALYTICS-007: Экспорт в Google Sheets - создание и синхронизация

**Описание:** Создание связанной Google Таблицы для расширенной аналитики с автоматической синхронизацией новых ответов.

**Роли:** Создатель формы, Соавтор с правами редактирования

**Предусловия:**
- Форма создана и опубликована
- Пользователь имеет права на создание файлов в Google Drive
- Пользователь находится на вкладке Responses

**Основной сценарий:**
1. Пользователь нажимает на иконку Google Sheets (зеленая таблица) в верхней панели вкладки Responses
2. Появляется диалоговое окно с двумя опциями:
   - **Create a new spreadsheet** - создать новую таблицу
   - **Select existing spreadsheet** - выбрать существующую таблицу
3. При выборе "Create a new spreadsheet":
   - Пользователь может ввести имя таблицы или использовать имя по умолчанию: "Form name (Responses)"
   - Нажимает кнопку "Create"
4. Система создает новую Google Таблицу в том же расположении в Drive, что и форма
5. Таблица автоматически настраивается:
   - Создается лист с именем "Form Responses 1"
   - Первая строка (header row) содержит названия столбцов:
     - **Timestamp** - дата и время отправки ответа
     - Название каждого вопроса как заголовок столбца
     - Если включен сбор email: столбец **Email Address**
     - Если включена оценка: столбец **Score**
   - Каждый ответ добавляется как новая строка
   - Столбцы автоматически форматируются по типу данных
6. После создания:
   - Таблица автоматически открывается в новой вкладке браузера
   - Иконка Google Sheets в форме меняет цвет на зеленый (индикатор подключения)
   - При наведении на иконку показывается tooltip: "View responses in Sheets"
7. Синхронизация ответов:
   - Каждый новый ответ автоматически добавляется как новая строка в таблицу
   - Синхронизация происходит в течение 1-5 секунд после получения ответа
   - Не требуется обновление страницы Sheets
   - Данные добавляются в конец таблицы (append)
8. В таблице доступны все ответы с момента создания связи:
   - Ответы, полученные ДО создания таблицы, автоматически экспортируются
   - Удаление строки в Sheets НЕ удаляет ответ в форме
   - Изменение данных в Sheets НЕ влияет на данные в форме (односторонняя синхронизация)
9. При клике на иконку Google Sheets после создания связи:
   - Таблица открывается в новой вкладке
   - Можно отключить связь (Unlink form)

**Альтернативные сценарии:**
- Сценарий А (Выбор существующей таблицы): Можно выбрать уже созданную таблицу, ответы добавятся на новый лист
- Сценарий Б (Таблица удалена): Если связанная таблица удалена, иконка становится неактивной, можно создать новую связь
- Сценарий В (Нет прав на создание): Если нет прав, показывается ошибка с инструкцией обратиться к владельцу Drive
- Сценарий Г (Лимит строк): При достижении 10,000+ ответов создается новый лист "Form Responses 2"
- Сценарий Д (Изменение вопросов): Если вопросы формы изменены, новые столбцы добавляются, старые остаются
- Сценарий Е (Множественные таблицы): Можно отключить старую связь и создать новую таблицу

**Бизнес-правила:**
- BR-047: Только создатель формы и соавторы с правами редактирования могут создавать связь с Sheets
- BR-048: Синхронизация односторонняя: Forms → Sheets, изменения в Sheets не влияют на форму
- BR-049: Максимум 1 активная связь с таблицей на форму в конкретный момент
- BR-050: Удаление ответа в форме НЕ удаляет строку в Sheets автоматически
- BR-051: Timestamp в Sheets использует часовой пояс создателя формы
- BR-052: Заголовки столбцов берутся из текста вопросов, ограничены 256 символами
- BR-053: При изменении текста вопроса заголовок столбца НЕ обновляется (сохраняется оригинальный)
- BR-054: Лимит строк на лист - 10,000, после автоматически создается новый лист
- BR-055: Форматирование столбцов: Timestamp - DateTime, числа - Number, остальное - Plain text
- BR-056: Связь с таблицей сохраняется в метаданных формы

**Результат:** Все ответы формы автоматически экспортируются и синхронизируются с Google Sheets для расширенной аналитики

### FR-ANALYTICS-008: Расширенная аналитика в Google Sheets - Pivot Tables и Charts

**Описание:** Использование инструментов Google Sheets для создания продвинутых аналитических отчетов, сводных таблиц и кастомных графиков.

**Роли:** Создатель формы, Соавтор с правами редактирования

**Предусловия:**
- Форма связана с Google Sheets
- Таблица содержит ответы
- Пользователь имеет доступ к таблице
- Пользователь находится в Google Sheets

**Основной сценарий:**
1. Пользователь открывает связанную Google Таблицу с ответами формы
2. Видит структурированные данные со всеми ответами
3. Для создания Pivot Table (сводной таблицы):
   - Выделяет весь диапазон данных (Ctrl+A или клик на угол таблицы)
   - Переходит в меню **Insert > Pivot table**
   - Выбирает "New sheet" для создания сводной таблицы на отдельном листе
   - Нажимает "Create"
4. В редакторе Pivot Table настраивает:

   **Rows (Строки):**
   - Добавляет вопрос, по которому нужна группировка (например, "Age group")
   - Можно добавить несколько уровней группировки

   **Columns (Столбцы):**
   - Добавляет вопрос для перекрестного анализа (например, "Preferred option")
   - Создает матрицу данных

   **Values (Значения):**
   - Выбирает метрику для подсчета: COUNTA, SUM, AVERAGE и т.д.
   - Например, COUNTA of Email Address - подсчет количества ответов
   - Или AVERAGE of Rating - среднее значение рейтинга

   **Filters (Фильтры):**
   - Добавляет фильтры для сегментации данных
   - Например, фильтр по дате для анализа определенного периода

5. Примеры аналитики с Pivot Table:

   **Анализ по демографии:**
   - Rows: Age group
   - Columns: Gender
   - Values: COUNTA of Timestamp
   - Результат: сколько человек каждого возраста и пола заполнили форму

   **Анализ удовлетворенности:**
   - Rows: Question about satisfaction (Linear scale 1-5)
   - Values: COUNTA, показывает распределение оценок
   - Filters: Date range (только последний месяц)

   **Кросс-табуляция:**
   - Rows: Product preference
   - Columns: Purchase intention
   - Values: Count of responses
   - Показывает связь между предпочтениями и намерением купить

6. Создание кастомных графиков:
   - Выделяет данные в Pivot Table или исходные данные
   - Переходит в **Insert > Chart**
   - Выбирает тип графика:
     - **Column chart** - для сравнения категорий
     - **Line chart** - для временных трендов
     - **Pie chart** - для показа долей
     - **Scatter chart** - для корреляций
     - **Bar chart** - для рейтингов
     - **Combo chart** - для комбинированных метрик
   - Настраивает Chart editor:
     - Data range (диапазон данных)
     - X-axis (ось X)
     - Series (серии данных)
     - Стилизация и цвета

7. Примеры продвинутых визуализаций:

   **Временной тренд ответов:**
   - Chart type: Line chart
   - X-axis: Timestamp (группировка по дням)
   - Y-axis: Count of responses
   - Показывает динамику получения ответов

   **Сравнение средних оценок:**
   - Chart type: Column chart
   - X-axis: Вопросы с Linear scale
   - Y-axis: Average score
   - Показывает средний балл по каждому вопросу

   **Heat map для Grid вопросов:**
   - Использует Conditional formatting
   - Применяет цветовую шкалу к таблице Grid ответов
   - Визуализирует паттерны без графиков

8. Использование формул для дополнительной аналитики:
   - **COUNTIF** - подсчет ответов по условию
   - **SUMIF** - сумма значений по условию
   - **AVERAGEIF** - среднее по условию
   - **FILTER** - фильтрация данных по критериям
   - **QUERY** - SQL-подобные запросы к данным
   - **UNIQUE** - извлечение уникальных значений
   - **SORT** - сортировка данных

9. Пример использования QUERY функции:
   ```
   =QUERY(A:Z, "SELECT B, COUNT(A) WHERE C='Yes' GROUP BY B ORDER BY COUNT(A) DESC")
   ```
   - Извлекает данные по определенному критерию и группирует их

10. Создание Dashboard (дашборда):
    - Создает отдельный лист "Dashboard"
    - Копирует важные графики из других листов
    - Размещает графики и метрики компактно
    - Использует Slicers для интерактивной фильтрации
    - Добавляет текстовые блоки с выводами

**Альтернативные сценарии:**
- Сценарий А (Автоматические Pivot Table suggestions): Google Sheets может предложить готовые Pivot Tables через "Explore" функцию
- Сценарий Б (Большой объем данных): Для >5000 строк Pivot Tables могут работать медленнее, используются фильтры
- Сценарий В (Экспорт графиков): Графики можно копировать в Google Slides, Docs или экспортировать как изображения
- Сценарий Г (Shared Sheets): Несколько пользователей могут работать с аналитикой одновременно
- Сценарий Д (Apps Script): Для автоматизации можно использовать Google Apps Script для создания кастомных отчетов

**Бизнес-правила:**
- BR-057: Pivot Tables обновляются вручную (кнопка Refresh), не автоматически при новых ответах
- BR-058: Максимум 256 столбцов в Pivot Table (ограничение Google Sheets)
- BR-059: Charts автоматически обновляются если базовые данные изменились
- BR-060: Рекомендуется создавать Pivot Tables на отдельных листах для лучшей организации
- BR-061: Conditional formatting можно применять к любым данным для визуализации паттернов

### FR-ANALYTICS-009: Экспорт ответов в CSV

**Описание:** Скачивание всех ответов формы в формате CSV для использования в других приложениях и инструментах аналитики.

**Роли:** Создатель формы, Соавтор с правами редактирования

**Предусловия:**
- Форма имеет хотя бы один ответ
- Пользователь находится на вкладке Responses
- Пользователь имеет права на экспорт данных

**Основной сценарий:**
1. Пользователь открывает вкладку Responses
2. Нажимает на иконку "..." (три точки) в правом верхнем углу панели ответов
3. В выпадающем меню выбирает опцию **"Download responses (.csv)"**
4. Система генерирует CSV файл:
   - Первая строка содержит заголовки (названия вопросов и служебные поля)
   - Каждая последующая строка - это один ответ респондента
   - Столбцы разделены запятыми
   - Текстовые значения заключены в кавычки
5. Структура CSV файла:

   **Служебные столбцы:**
   - **Timestamp** - дата и время отправки в формате "MM/DD/YYYY HH:MM:SS"
   - **Email Address** - если включен сбор email
   - **Score** - если включена система баллов/оценок

   **Столбцы вопросов:**
   - Каждый вопрос - отдельный столбец
   - Заголовок столбца = полный текст вопроса
   - Для длинных вопросов текст не обрезается

6. Форматирование ответов в CSV:

   **Для Multiple choice:**
   - Просто текст выбранного варианта

   **Для Checkboxes (множественный выбор):**
   - Все выбранные варианты через точку с запятой: "Option 1; Option 2; Option 3"

   **Для Linear scale:**
   - Числовое значение (например, "4")

   **Для Grid вопросов:**
   - Каждая строка Grid становится отдельным столбцом
   - Название столбца: "Question [Row name]"
   - Значение: выбранный вариант в этой строке

   **Для текстовых ответов:**
   - Полный текст в кавычках
   - Переносы строк заменяются на "\n"

   **Для Date/Time:**
   - Дата в формате "MM/DD/YYYY"
   - Время в формате "HH:MM:SS"

   **Для пропущенных вопросов:**
   - Пустая ячейка (только запятые)

7. Система автоматически загружает файл в браузер:
   - Название файла: "Form_title (Responses).csv"
   - Кодировка: UTF-8 (поддержка всех языков)
   - Размещается в папке Downloads
8. Появляется уведомление: "Responses downloaded"
9. CSV файл можно открыть в различных приложениях:
   - Microsoft Excel
   - Google Sheets (через Import)
   - Numbers (Mac)
   - LibreOffice Calc
   - Специализированные инструменты аналитики (SPSS, R, Python pandas)
   - Базы данных

**Альтернативные сценарии:**
- Сценарий А (Большой файл): При >10,000 ответов загрузка может занять несколько секунд
- Сценарий Б (Специальные символы): Запятые и кавычки в ответах экранируются правильно
- Сценарий В (Множественные экспорты): Можно экспортировать несколько раз, каждый раз генерируется актуальный файл
- Сценарий Г (Открытие в Excel): Excel может некорректно отображать UTF-8, нужно использовать Import wizard
- Сценарий Д (Нет ответов): При отсутствии ответов экспортируется только строка заголовков
- Сценарий Е (Файловые вложения): Загруженные файлы представлены как URL ссылки в CSV

**Бизнес-правила:**
- BR-065: CSV экспорт доступен только создателю и соавторам с правами редактирования
- BR-066: Экспортируются все ответы, фильтрация перед экспортом недоступна
- BR-067: Кодировка файла всегда UTF-8 для поддержки всех языков
- BR-068: Разделитель столбцов - запятая (,), альтернативный разделитель недоступен
- BR-069: Timestamp использует часовой пояс создателя формы
- BR-070: Максимальная длина значения в ячейке - 50,000 символов (ограничение CSV)
- BR-071: Экспорт не влияет на хранимые данные, это копия для чтения
- BR-072: Удаленные ответы (после экспорта) не попадают в последующие экспорты
- BR-073: CSV файл не содержит форматирования, только raw data

**Результат:** Пользователь получает CSV файл со всеми ответами для использования в других инструментах аналитики

### FR-ANALYTICS-011: Фильтрация и поиск в ответах

**Описание:** Инструменты для фильтрации и поиска по текстовым ответам в разделах Question и Individual.

**Роли:** Создатель формы, Соавтор с правами редактирования, Соавтор только для просмотра

**Предусловия:**
- Форма имеет ответы
- Пользователь находится на вкладке Responses
- Есть вопросы с текстовыми ответами

**Основной сценарий:**
1. Пользователь открывает подраздел Question и выбирает вопрос с текстовыми ответами (Short answer или Paragraph)
2. Над списком ответов отображается поле поиска (search box) с иконкой лупы
3. Пользователь вводит ключевое слово в поле поиска
4. Система выполняет поиск в реальном времени (live search):
   - Задержка 300мс после прекращения ввода
   - Поиск без учета регистра (case-insensitive)
   - Поиск по частичному совпадению (substring match)
5. Результаты поиска:
   - Показываются только ответы, содержащие поисковый запрос
   - Совпадающие слова выделяются желтым фоном (highlight)
   - Счетчик результатов: "Showing X of Y responses"
   - Остальные ответы скрываются
6. Функция фильтрации по длине ответа (доступна через "..." меню):
   - **All responses** - все ответы
   - **Short responses** - ответы <50 символов
   - **Medium responses** - ответы 50-200 символов
   - **Long responses** - ответы >200 символов
   - **Empty responses** - пропущенные вопросы
7. Сортировка текстовых ответов:
   - **Newest first** - по времени получения (новые сверху) - по умолчанию
   - **Oldest first** - старые сверху
   - **A to Z** - алфавитная сортировка
   - **Z to A** - обратная алфавитная
   - **Longest first** - по длине (длинные сверху)
   - **Shortest first** - короткие сверху
8. В подразделе Individual доступен глобальный поиск:
   - Поле поиска в верхней части
   - Поиск по всем текстовым полям всех ответов
   - Результат: показываются только ответы респондентов, содержащие поисковый запрос
   - Переход между найденными ответами через Previous/Next
9. Сброс фильтров:
   - Кнопка "Clear filter" очищает поле поиска
   - Кнопка "Reset" сбрасывает все фильтры и сортировку
10. Счетчик отфильтрованных результатов обновляется в реальном времени

**Альтернативные сценарии:**
- Сценарий А (Нет совпадений): Показывается "No responses match your search", предлагается изменить запрос
- Сценарий Б (Поиск по Email): Можно искать ответы конкретного респондента по email (если сбор включен)
- Сценарий В (Regex поиск): Продвинутые пользователи могут использовать регулярные выражения (через Sheets)
- Сценарий Г (Экспорт отфильтрованных): Экспорт всегда включает все ответы, не только отфильтрованные
- Сценарий Д (Сохранение фильтров): Фильтры сбрасываются при перезагрузке страницы

**Бизнес-правила:**
- BR-082: Поиск работает только для текстовых ответов (Short answer, Paragraph)
- BR-083: Поиск без учета регистра (case-insensitive)
- BR-084: Минимальная длина поискового запроса - 1 символ
- BR-085: Максимальная длина поискового запроса - 100 символов
- BR-086: Live search с задержкой 300мс для оптимизации производительности
- BR-087: Поиск по частичному совпадению (substring), не по целым словам
- BR-088: Фильтры и сортировка не сохраняются между сессиями
- BR-089: Поиск работает только в загруженных ответах (первые 1000), для большего объема использовать Sheets
- BR-090: Highlight (выделение) совпадений ограничено 10 вхождениями на ответ

**Результат:** Пользователь может быстро находить нужные ответы среди большого количества текстовых данных

### FR-ANALYTICS-012: Удаление и модерация ответов

**Описание:** Возможность удалять отдельные ответы или все ответы формы, модерация неуместного контента.

**Роли:** Создатель формы, Соавтор с правами редактирования

**Предусловия:**
- Форма имеет ответы
- Пользователь имеет права на редактирование формы
- Пользователь находится на вкладке Responses

**Основной сценарий:**
1. **Удаление отдельного ответа (из Individual):**
   - Пользователь открывает подраздел Individual
   - Просматривает конкретный ответ
   - Нажимает на иконку "..." (три точки) в правом верхнем углу карточки ответа
   - Выбирает **"Delete this response"**
   - Появляется модальное окно подтверждения:
     - "Delete this response?"
     - "This action cannot be undone"
     - Кнопка "Cancel" (отмена)
     - Кнопка "Delete" (красная, подтверждение)
   - При нажатии "Delete":
     - Ответ удаляется из формы
     - Автоматический переход к следующему ответу
     - Появляется уведомление: "Response deleted"
     - Счетчик общих ответов уменьшается на 1

2. **Удаление всех ответов (массовое):**
   - Пользователь нажимает на иконку "..." (три точки) в верхней панели вкладки Responses
   - Выбирает **"Delete all responses"**
   - Появляется модальное окно с серьезным предупреждением:
     - "Delete all X responses?"
     - "This will permanently delete all responses from Google Forms"
     - "If you have a linked spreadsheet, responses there will NOT be deleted"
     - Чекбокс: "I understand this action cannot be undone"
     - Кнопка "Cancel"
     - Кнопка "Delete all" (красная, активна только после включения чекбокса)
   - При подтверждении:
     - Все ответы удаляются из Google Forms
     - Вкладка Responses показывает "Waiting for responses"
     - Счетчик ответов сбрасывается на 0
     - Появляется уведомление: "All responses deleted"
     - Ответы в связанной Google Sheets НЕ удаляются (остаются)

3. **Модерация неуместного контента (Flag as inappropriate):**
   - Доступно в подразделе Individual для каждого ответа
   - Пользователь нажимает "..." > **"Flag as inappropriate"**
   - Появляется диалоговое окно:
     - "Why is this inappropriate?"
     - Опции: Spam, Offensive content, Irrelevant, Other
     - Текстовое поле для комментария (опционально)
     - Кнопка "Submit"
   - После отправки:
     - Ответ помечается специальной меткой (красный флаг)
     - Уведомление отправляется создателю формы (если это не он)
     - Ответ остается видимым, но помечен для review
   - Создатель может просмотреть помеченные ответы:
     - Фильтр "Flagged responses" (доступен через меню)
     - Решить: удалить или снять метку

4. **Восстановление удаленных ответов:**
   - НЕТ встроенной функции восстановления в Google Forms
   - Удаленные ответы восстановить невозможно
   - Если была связь с Google Sheets, данные остаются там
   - Рекомендация: всегда создавать резервную копию в Sheets перед массовым удалением

5. **Журнал удалений (для Workspace):**
   - В Google Workspace администраторы могут просмотреть Audit log
   - Логируется: кто, когда и какие ответы удалил
   - Доступно через Admin Console

**Альтернативные сценарии:**
- Сценарий А (Случайное удаление): Нет функции отмены, данные потеряны безвозвратно (если нет Sheets)
- Сценарий Б (Удаление с мобильного): Функция доступна в мобильном приложении Google Forms
- Сценарий В (Ограниченные права): Соавтор только для просмотра не видит опции удаления
- Сценарий Г (Спам-атака): При получении множества спам-ответов можно быстро удалить все и перезапустить форму
- Сценарий Д (Частичное удаление): Нет функции выбора нескольких ответов для удаления, только по одному или все

**Бизнес-правила:**
- BR-091: Удаление ответов доступно только создателю и соавторам с правами редактирования
- BR-092: Удаленные ответы невозможно восстановить
- BR-093: Удаление в Forms не влияет на данные в связанной Google Sheets
- BR-094: Удаление всех ответов требует явное подтверждение через чекбокс
- BR-095: Счетчик ответов обновляется мгновенно после удаления
- BR-096: Flagged responses не удаляются автоматически, требуется ручная модерация
- BR-097: В Google Workspace все удаления логируются в Audit log
- BR-098: Нет функции массового выбора и удаления конкретных ответов
- BR-099: Удаление ответа также удаляет связанные файловые вложения (если были)
- BR-100: После удаления всех ответов форма продолжает принимать новые ответы (если не отключено)

**Результат:** Пользователь может управлять ответами, удалять спам и модерировать неуместный контент

### FR-ANALYTICS-013: Настройка отображения сводки для респондентов

**Описание:** Возможность показывать респондентам сводную статистику ответов после отправки формы.

    - Обновляется в реальном времени при получении новых ответов

- Сценарий Г (Текстовые ответы с персональными данными): Рекомендуется включить "Show charts only" чтобы скрыть текст

### FR-ANALYTICS-014: Временная аналитика ответов

**Описание:** Анализ паттернов получения ответов по времени и датам для выявления трендов и пиков активности.

**Роли:** Создатель формы, Соавтор с правами редактирования, Соавтор только для просмотра

**Предусловия:**
- Форма получила ответы
- Ответы распределены по времени (не все в один момент)
- Пользователь имеет доступ к Google Sheets или Workspace аналитике

**Основной сценарий:**
1. **Базовая временная визуализация (встроенная):**
   - Пользователь открывает вкладку Responses
   - Под счетчиком ответов отображается текст: "Last response: X minutes/hours/days ago"
   - Этот индикатор показывает свежесть данных

2. **Расширенная временная аналитика через Google Sheets:**
   - Пользователь экспортирует ответы в Google Sheets (см. FR-ANALYTICS-007)
   - В таблице есть столбец "Timestamp" с датой и временем каждого ответа
   - Создает новый лист для временной аналитики

3. **Создание временного графика - Timeline Chart:**
   - Выделяет столбец "Timestamp"
   - Добавляет вспомогательный столбец с формулой подсчета:
     ```
     =COUNTIFS($A$2:$A, ">="&DATE(2025,1,1), $A$2:$A, "<"&DATE(2025,1,2))
     ```
   - Или использует Pivot Table:
     - Rows: Timestamp (группировка по дням/часам/неделям)
     - Values: COUNTA of Timestamp
   - Insert > Chart > Line chart
   - Настраивает:
     - X-axis: Дата/Время
     - Y-axis: Количество ответов
     - Chart title: "Response Timeline"

4. **Группировка ответов по периодам:**
   - По часам (для анализа активности в течение дня)
   - По дням (для отслеживания ежедневных трендов)
   - По дням недели (для выявления паттернов: будни vs выходные)
   - По неделям (для долгосрочного анализа)
   - По месяцам (для форм, открытых несколько месяцев)

5. **Формулы для временного анализа:**

   **Извлечение часа дня:**
   ```
   =HOUR(A2)
   ```
   Позволяет построить диаграмму: в какие часы суток больше всего ответов

   **Извлечение дня недели:**
   ```
   =TEXT(A2, "dddd")
   ```
   Показывает, в какой день недели больше активность

   **Группировка по дате (без времени):**
   ```
   =DATEVALUE(TEXT(A2, "MM/DD/YYYY"))
   ```
   Группирует все ответы одного дня вместе

   **Количество ответов в определенный период:**
   ```
   =COUNTIFS(A:A, ">=1/1/2025", A:A, "<2/1/2025")
   ```

6. **Визуализации временных паттернов:**

   **Heat map по часам и дням недели:**
   - Строки: Дни недели (Monday - Sunday)
   - Столбцы: Часы дня (0-23)
   - Значения: Количество ответов
   - Conditional formatting: цветовая шкала от белого (мало) до темно-синего (много)
   - Показывает: когда респонденты наиболее активны

   **Кумулятивный график (Cumulative chart):**
   - Показывает нарастающий итог ответов
   - X-axis: Дата
   - Y-axis: Общее количество ответов к этой дате
   - Полезно для отслеживания прогресса сбора данных

   **Сравнение периодов:**
   - Две линии на графике: эта неделя vs прошлая неделя
   - Показывает изменение активности респондентов

7. **Метрики временной аналитики:**
   - **Peak time** - час/день с максимальным количеством ответов
   - **Average daily responses** - среднее количество ответов в день
   - **Response velocity** - скорость получения ответов (ответов/час)
   - **Time to first response** - время от публикации формы до первого ответа
   - **Time to target** - время достижения целевого количества ответов
   - **Inactive periods** - периоды без ответов (пробелы)

8. **Анализ эффективности распространения:**
   - Сравнить временные метки с действиями по распространению
   - Если разослали email в 10:00, ожидается пик ответов в течение 1-2 часов
   - Если опубликовали в соцсетях, можно увидеть волны активности

**Альтернативные сценарии:**
- Сценарий А (Все ответы в одно время): Если форма использовалась на мероприятии, все ответы могут быть в течение 1-2 часов
- Сценарий Б (Длительный сбор): Для форм, открытых месяцами, актуальна месячная группировка
- Сценарий В (Разные часовые пояса): Timestamp в часовом поясе создателя, может искажать данные для глобальной аудитории
- Сценарий Г (Использование Google Data Studio): Можно подключить Sheets к Data Studio для интерактивных дашбордов
- Сценарий Д (Apps Script автоматизация): Можно создать автоматический еженедельный отчет с временными метриками

**Бизнес-правила:**
- BR-111: Timestamp каждого ответа записывается автоматически при отправке формы
- BR-112: Timestamp использует часовой пояс создателя формы
- BR-113: Точность Timestamp - до секунды
- BR-114: Временная аналитика требует экспорта в Google Sheets, не доступна встроенно в Forms
- BR-115: Для корректного анализа нужно минимум 10-20 ответов распределенных по времени
- BR-116: Heat map наиболее эффективен при >100 ответах
- BR-117: Формулы COUNTIFS и Pivot Tables обновляются автоматически при синхронизации новых ответов
- BR-118: Для глобальных форм рекомендуется добавить вопрос о часовом поясе респондента

**Результат:** Пользователь понимает временные паттерны получения ответов и может оптимизировать время распространения формы

### FR-ANALYTICS-015: Интеграция с Google Data Studio / Looker Studio

**Описание:** Подключение Google Forms через Sheets к Google Looker Studio (ранее Data Studio) для создания интерактивных дашбордов и продвинутых визуализаций.

**Роли:** Создатель формы (с доступом к Looker Studio), Соавтор с правами редактирования

**Предусловия:**
- Форма связана с Google Sheets
- Таблица содержит ответы
- Пользователь имеет доступ к Google Looker Studio
- Пользователь авторизован в Google аккаунте

**Основной сценарий:**
1. **Подготовка данных:**
   - Пользователь экспортирует ответы формы в Google Sheets
   - Таблица содержит структурированные данные с заголовками
   - Убеждается, что данные актуальны и синхронизируются

2. **Создание подключения в Looker Studio:**
   - Открывает Looker Studio (lookerstudio.google.com)
   - Нажимает кнопку "Create" > "Report"
   - Выбирает источник данных: "Google Sheets"
   - В диалоговом окне выбирает нужную таблицу с ответами формы
   - Выбирает конкретный лист (обычно "Form Responses 1")
   - Нажимает "Add to report"

3. **Автоматическая настройка полей:**
   - Looker Studio автоматически определяет типы данных:
     - Timestamp → Date & Time
     - Email → Text
     - Числовые ответы → Number
     - Linear scale → Number
     - Текстовые ответы → Text
   - При необходимости можно изменить типы полей вручную

4. **Создание интерактивного дашборда:**

   **Добавление Time Series Chart (временной график):**
   - Добавляет компонент "Time series chart"
   - Dimension: Timestamp (по дням)
   - Metric: Record Count (количество ответов)
   - Показывает динамику получения ответов

   **Добавление Pie Chart (круговая диаграмма):**
   - Для вопросов Multiple choice
   - Dimension: Название вопроса (например, "What is your age group?")
   - Metric: Record Count
   - Показывает распределение ответов

   **Добавление Bar Chart (столбчатая диаграмма):**
   - Для сравнения категорий
   - Dimension: Вариант ответа
   - Metric: Count или Average (для Linear scale)
   - Сортировка по популярности

   **Добавление Scorecard (метрика):**
   - Для отображения ключевых чисел
   - Метрики: общее количество ответов, средний рейтинг, процент положительных ответов
   - Крупный шрифт для быстрого восприятия

   **Добавление Table (таблица):**
   - Для детального просмотра данных
   - Можно включить: Email, Timestamp, конкретные ответы
   - Сортировка и фильтрация

   **Добавление Geo Map (географическая карта):**
   - Если в форме есть вопрос о локации/стране
   - Dimension: Country/Region
   - Metric: Record Count
   - Показывает географическое распределение респондентов

5. **Интерактивные фильтры:**
   - Добавляет Date Range Control:
     - Позволяет выбрать временной период
     - Все графики на дашборде обновляются согласно выбранному периоду
   - Добавляет Filter Control:
     - По конкретному вопросу (например, "Age group")
     - Позволяет фильтровать данные по сегментам
   - Добавляет Drop-down list:
     - Для выбора конкретной категории
     - Например, выбор конкретного филиала/региона

6. **Вычисляемые поля (Calculated Fields):**
   - Создает кастомные метрики:

   **Completion rate:**
   ```
   COUNT(Timestamp) / COUNT(Email Address) * 100
   ```

   **Average score:**
   ```
   AVG(Linear_scale_question)
   ```

   **Response velocity (ответов в день):**
   ```
   COUNT(Timestamp) / DATE_DIFF(MAX(Timestamp), MIN(Timestamp))
   ```

   **Positive sentiment rate (для форм с рейтингами):**
   ```
   CASE WHEN Rating >= 4 THEN 1 ELSE 0 END
   ```
   Затем: SUM(Positive) / COUNT(Total) * 100

7. **Стилизация дашборда:**
   - Применяет тему (Theme) для единообразия цветов
   - Добавляет заголовки и текстовые блоки с пояснениями
   - Размещает элементы в логичном порядке
   - Добавляет логотип организации
   - Настраивает цвета графиков

8. **Настройка автообновления:**
   - В настройках источника данных включает "Data freshness"
   - Устанавливает частоту обновления: каждые 15 минут, 1 час, 4 часа, 12 часов
   - Данные из Sheets синхронизируются автоматически
   - Дашборд всегда показывает актуальные данные

9. **Публикация и совместный доступ:**
   - Нажимает кнопку "Share"
   - Настраивает права доступа:
     - **Edit access** - могут изменять дашборд
     - **View access** - только просмотр
   - Генерирует публичную ссылку (если нужно)
   - Встраивает дашборд на сайт через iframe
   - Или отправляет по email конкретным людям

10. **Scheduled reports (запланированные отчеты):**
    - Настраивает автоматическую отправку отчета по email
    - Выбирает частоту: ежедневно, еженедельно, ежемесячно
    - Получатели получают PDF или ссылку на дашборд

**Альтернативные сценарии:**
- Сценарий А (Большой объем данных): При >10,000 строк рекомендуется использовать Data Blending или агрегацию в Sheets
- Сценарий Б (Множественные формы): Можно объединить данные из нескольких форм в один дашборд через UNION в Data Source
- Сценарий В (Real-time мониторинг): Looker Studio обновляется каждые 15 минут, не мгновенно
- Сценарий Г (Кастомные визуализации): Можно использовать Community Visualizations для уникальных графиков
- Сценарий Д (Экспорт дашборда): Можно экспортировать как PDF для презентаций

**Бизнес-правила:**
- BR-119: Looker Studio бесплатен для всех Google аккаунтов
- BR-120: Подключение к Google Sheets не требует дополнительных разрешений (если есть доступ к таблице)

- BR-123: Дашборды интерактивны - фильтры работают в реальном времени без перезагрузки

**Результат:** Пользователь создает интерактивный дашборд с продвинутой аналитикой и визуализациями, автоматически обновляющийся при получении новых ответов

## Сущности данных

### Ответ формы (Form Response)
- **response_id** - уникальный идентификатор ответа
- **form_id** - ID формы, к которой относится ответ
- **timestamp** - дата и время отправки ответа (DateTime)
- **respondent_email** - email респондента (если сбор включен)
- **score** - общий балл/оценка (если включена система баллов)
- **completion_status** - статус завершения (completed, partial, abandoned)
- **completion_time_seconds** - время заполнения в секундах
- **submission_ip** - IP адрес отправки (для Workspace, если включено)
- **edit_after_submit_url** - URL для редактирования ответа (если включено)
- **answers** - массив ответов на вопросы (JSON)

### Ответ на вопрос (Question Answer)
- **question_id** - ID вопроса
- **question_text** - текст вопроса
- **question_type** - тип вопроса (multiple_choice, short_answer, linear_scale и т.д.)
- **answer_value** - значение ответа (текст, число, массив)
- **is_answered** - отвечен ли вопрос (boolean)
- **answer_timestamp** - время ответа на вопрос (для отслеживания прогресса)
- **validation_passed** - прошел ли валидацию (boolean)

### Сводная статистика формы (Form Summary Statistics)
- **form_id** - ID формы
- **total_responses** - общее количество ответов
- **completed_responses** - количество завершенных ответов
- **partial_responses** - количество частичных ответов
- **average_completion_time_seconds** - среднее время заполнения
- **median_completion_time_seconds** - медианное время заполнения
- **completion_rate_percent** - процент завершения
- **first_response_timestamp** - время первого ответа
- **last_response_timestamp** - время последнего ответа
- **peak_response_time** - час/день с максимальной активностью
- **average_daily_responses** - среднее количество ответов в день
- **last_updated** - время последнего обновления статистики

### Статистика по вопросу (Question Statistics)
- **question_id** - ID вопроса
- **question_type** - тип вопроса
- **total_answers** - общее количество ответов на вопрос
- **skipped_count** - количество пропусков (для необязательных)
- **unique_answers_count** - количество уникальных ответов (для текстовых)
- **answer_distribution** - распределение ответов (JSON)
  - Для Multiple choice: {option: count, ...}
  - Для Linear scale: {value: count, ...}
  - Для Checkboxes: {option: count, ...} (сумма >100%)
- **average_value** - среднее значение (для Linear scale)
- **median_value** - медиана (для Linear scale)
- **mode_value** - мода/наиболее частый ответ
- **standard_deviation** - стандартное отклонение (для числовых)
- **most_popular_option** - самый популярный вариант
- **least_popular_option** - наименее популярный вариант

### Визуализация (Chart/Visualization)
- **chart_id** - ID визуализации
- **question_id** - связанный вопрос
- **chart_type** - тип графика (pie, bar, column, line, table)
- **chart_data** - данные для графика (JSON)
- **chart_image_url** - URL изображения графика (для экспорта)
- **created_timestamp** - время создания визуализации
- **last_updated** - время последнего обновления

### Экспорт данных (Data Export)
- **export_id** - уникальный ID экспорта
- **form_id** - ID формы
- **export_format** - формат экспорта (csv, xlsx, sheets_link)
- **exported_by_user_id** - кто экспортировал
- **export_timestamp** - время экспорта
- **responses_count** - количество ответов в экспорте
- **file_url** - URL файла экспорта (если применимо)
- **file_size_bytes** - размер файла

### Связь с Google Sheets (Sheets Integration)
- **integration_id** - ID интеграции
- **form_id** - ID формы
- **spreadsheet_id** - ID таблицы Google Sheets
- **sheet_name** - название листа
- **sync_status** - статус синхронизации (active, paused, error)
- **created_timestamp** - время создания связи
- **last_sync_timestamp** - время последней синхронизации
- **total_synced_responses** - количество синхронизированных ответов
- **sync_direction** - направление синхронизации (form_to_sheets)

### Временная метрика (Time Metric)
- **metric_id** - ID метрики
- **form_id** - ID формы
- **date** - дата (Date)
- **hour** - час дня (0-23, для почасового анализа)
- **day_of_week** - день недели (Monday-Sunday)
- **responses_count** - количество ответов в этот период
- **cumulative_count** - кумулятивное количество ответов на эту дату

### Модерация контента (Content Moderation)
- **flag_id** - ID флага
- **response_id** - ID помеченного ответа
- **flagged_by_user_id** - кто пометил
- **flag_reason** - причина (spam, offensive, irrelevant, other)
- **flag_comment** - комментарий модератора
- **flag_timestamp** - время пометки
- **moderation_status** - статус модерации (pending, reviewed, deleted, cleared)
- **resolved_by_user_id** - кто разрешил
- **resolved_timestamp** - время разрешения

## Состояния и статусы

### Статусы завершения ответа
- **completed** - ответ полностью заполнен и отправлен
- **partial** - ответ начат, но не завершен (сохранен как черновик)
- **abandoned** - респондент начал, но не завершил форму (отслеживается в Workspace)

### Типы визуализаций
- **pie_chart** - круговая диаграмма (для Multiple choice, Dropdown)
- **bar_chart** - горизонтальная столбчатая (для Checkboxes)
- **column_chart** - вертикальная столбчатая (для Linear scale)
- **line_chart** - линейный график (для временных трендов)
- **table** - таблица (для Grid вопросов, текстовых ответов)
- **text_list** - список текста (для Short answer, Paragraph)
- **heat_map** - тепловая карта (для Grid с цветовым кодированием)

### Статусы синхронизации с Sheets
- **active** - синхронизация активна и работает
- **paused** - синхронизация приостановлена пользователем
- **error** - ошибка синхронизации (таблица удалена, нет доступа)
- **not_configured** - связь не настроена

### Статусы модерации
- **pending** - ожидает модерации
- **reviewed** - проверено модератором
- **deleted** - ответ удален после модерации
- **cleared** - флаг снят, контент признан приемлемым

### Форматы экспорта
- **csv** - Comma-Separated Values file
- **xlsx** - Microsoft Excel file (через сторонние надстройки)
- **sheets_link** - ссылка на Google Sheets
- **pdf** - PDF отчет (через печать)
- **json** - JSON format (через API)

## Ограничения и лимиты

### Лимиты ответов
- **Максимум ответов в одной форме**: 5,000,000 (теоретический лимит, практически неограниченно)
- **Рекомендуемое количество для оптимальной производительности UI**: до 10,000 ответов
- **Максимум ответов на странице Individual**: просмотр по одному
- **Максимум текстовых ответов в печатной версии**: 50 на вопрос

### Лимиты визуализации
- **Максимум уникальных вариантов в диаграмме**: 50 (остальные группируются в "Other")
- **Оптимальное количество сегментов для Pie chart**: 7 или менее
- **Разрешение экспортированной диаграммы**: 1200x800px (стандарт), 1600x1200px (увеличенное)
- **Формат экспорта диаграмм**: только PNG

### Лимиты Google Sheets интеграции
- **Максимум строк на лист**: 10,000 (после создается новый лист)
- **Максимум столбцов в Sheets**: 18,278 (теоретический лимит Google Sheets)
- **Практический лимит столбцов для формы**: ~200 вопросов
- **Задержка синхронизации**: 1-5 секунд после отправки ответа
- **Максимум связей с таблицами**: 1 активная связь на форму

### Лимиты экспорта CSV
- **Максимальный размер CSV файла**: ограничен только доступной памятью браузера
- **Практический лимит для стабильного экспорта**: до 50,000 ответов
- **Кодировка**: UTF-8 only
- **Максимальная длина значения в ячейке**: 50,000 символов

### Лимиты поиска и фильтрации
- **Загруженных ответов для поиска в UI**: первые 1,000
- **Минимальная длина поискового запроса**: 1 символ
- **Максимальная длина поискового запроса**: 100 символов
- **Задержка live search**: 300мс

### Лимиты Looker Studio
- **Строк данных для эффективной работы**: до 50,000
- **Частота автообновления**: минимум каждые 15 минут
- **Максимум источников данных в бесплатном отчете**: 10
- **Максимум графиков в одном дашборде**: без жесткого лимита, но рекомендуется до 20 для производительности

### Лимиты производительности
- **Время загрузки Summary с 100 ответами**: <2 секунды
- **Время загрузки Summary с 1,000 ответами**: 2-5 секунд
- **Время загрузки Summary с 10,000 ответами**: 5-15 секунд
- **Время генерации CSV для 1,000 ответов**: 1-3 секунды
- **Время генерации CSV для 10,000 ответов**: 10-30 секунд

## Интеграции с другими модулями

### Модуль "Создание и редактирование формы"
- Изменение вопросов влияет на структуру данных в Sheets (добавляются новые столбцы)
- Удаление вопроса не удаляет столбец в Sheets (сохраняются исторические данные)
- Изменение типа вопроса может повлиять на визуализацию

### Модуль "Настройки формы"
- Включение сбора email добавляет столбец Email в аналитику
- Включение системы баллов добавляет столбец Score
- Настройка "See summary charts" влияет на доступность аналитики для респондентов

### Модуль "Распространение и доступ"
- Закрытие приема ответов не влияет на просмотр аналитики
- Ограничение формы организацией влияет на доступ к публичной summary для респондентов

### Модуль "Response validation"
- Валидация влияет на качество данных в аналитике
- Не прошедшие валидацию ответы не сохраняются

### Модуль "Условная логика (Logic)"
- Ответы учитывают только показанные вопросы
- Пропущенные по логике вопросы отображаются как "Not answered"

### Модуль "Файловые вложения"
- Загруженные файлы представлены как URL в CSV и Sheets
- Файлы хранятся в Google Drive создателя формы
- Удаление ответа удаляет связанные файлы

### Модуль "Уведомления"
- Можно настроить уведомления при достижении определенного количества ответов
- Email уведомления могут включать краткую сводку

### Google Drive
- Связанная Google Sheets хранится в том же расположении, что и форма
- Права доступа к таблице управляются независимо от формы

### Google Workspace Admin Console
- Администраторы могут просматривать Audit logs всех форм и ответов
- Доступны политики retention для хранения данных форм

## Метрики и производительность

### Ключевые метрики
- **Скорость загрузки Summary**: <2 секунды для форм с до 1,000 ответов
- **Синхронизация с Sheets**: 1-5 секунд задержки после отправки ответа
- **Обновление в реальном времени**: счетчик ответов обновляется каждые 10 секунд
- **Время генерации диаграмм**: мгновенно (рендеринг на клиенте)
- **Экспорт CSV (1,000 ответов)**: 1-3 секунды
- **Экспорт CSV (10,000 ответов)**: 10-30 секунд

### Бенчмарки производительности
- **Поиск в 500 текстовых ответах**: <1 секунда
- **Фильтрация ответов**: мгновенно (клиентская обработка)
- **Looker Studio dashboard load**: 3-10 секунд в зависимости от сложности
- **Печать Summary (10 вопросов)**: 5-15 секунд генерация PDF
