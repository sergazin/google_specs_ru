# Условная логика и настройки форм

## Описание

Модуль условной логики и настроек форм Google Forms - это комплексная система управления поведением формы и маршрутизацией респондентов, которая включает условные переходы между разделами на основе ответов (branching logic), перемешивание вопросов и вариантов ответов для предотвращения списывания, ограничение количества ответов и настройку одного ответа на пользователя, возможность редактирования ответов после отправки, отображение прогресс-бара для многостраничных форм, настройку сообщений подтверждения и ссылки для повторной отправки, валидацию ответов с проверкой данных по различным правилам, а также множество презентационных настроек для улучшения пользовательского опыта. Система позволяет создавать сложные адаптивные формы, которые показывают разные вопросы разным пользователям в зависимости от их предыдущих ответов, обеспечивая персонализированный опыт заполнения.

## Роли пользователей

- **Создатель формы (Owner)** - может настраивать всю условную логику, разделы, переходы, валидацию и все параметры формы
- **Редактор формы (Editor)** - имеет те же права что и создатель для настройки логики и параметров
- **Респондент (без входа)** - заполняет форму согласно настроенной логике, видит только релевантные вопросы
- **Респондент (с Google аккаунтом)** - может иметь ограничение "1 ответ", видеть прогресс-бар, редактировать свои ответы
- **Просмотрщик результатов (Viewer)** - может видеть настройки формы, но не может их изменять
- **Администратор Workspace** - может управлять доступом к функциям форм для организации

## Функциональные требования

### FR-LOGIC-001: Создание разделов формы

**Описание:** Разбиение формы на логические разделы (секции) для структурирования вопросов и реализации условных переходов.

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Пользователь открыл форму в режиме редактирования
- Форма содержит хотя бы один вопрос

**Основной сценарий:**
1. Создатель формы открывает форму в редакторе Google Forms
2. В правой панели инструментов видит кнопку "Add section" (значок с двумя горизонтальными линиями)
3. Нажимает на кнопку "Add section"
4. Система вставляет разрыв раздела, создавая новую секцию:
   - Появляется визуальный разделитель между секциями
   - Новая секция получает автоматическое название "Untitled Section"
   - Поле для заголовка секции (Section title)
   - Необязательное поле для описания секции (Section description)
5. Создатель заполняет:
   - **Заголовок раздела** - основное название (например, "Personal Information")
   - **Описание раздела** - дополнительные инструкции или пояснения
6. Каждый раздел может содержать:
   - Неограниченное количество вопросов
   - Текст, изображения, видео между вопросами
   - Собственные настройки навигации
7. В нижней части каждого раздела (кроме последнего) появляется меню навигации:
   - "Continue to next section" (по умолчанию)
   - "Submit form" (завершить и отправить)
   - "Go to section..." (перейти к конкретному разделу)
8. Создатель может:
   - Перетаскивать вопросы между разделами
   - Менять порядок разделов целиком
   - Дублировать разделы с кнопкой копирования
   - Удалять разделы (вопросы переместятся в предыдущий раздел)
9. При предпросмотре формы разделы отображаются как отдельные страницы
10. Респондент видит только один раздел за раз с кнопками навигации

**Альтернативные сценарии:**
- Сценарий А (Первый раздел): Первый раздел не имеет настроек навигации "назад", только "вперед"
- Сценарий Б (Последний раздел): Последний раздел показывает кнопку "Submit" вместо "Next"
- Сценарий В (Единственный вопрос в разделе): Раздел может содержать всего один вопрос для условной логики
- Сценарий Г (Удаление единственного раздела): Нельзя удалить все разделы, хотя бы один должен остаться

**Бизнес-правила:**
- BR-001: Форма может содержать неограниченное количество разделов
- BR-002: Каждый раздел отображается как отдельная страница для респондента
- BR-003: Заголовок раздела обязателен, описание опционально
- BR-004: Пустые разделы (без вопросов) разрешены
- BR-005: Порядок разделов определяет порядок по умолчанию (без условной логики)
- BR-006: Разделы нумеруются автоматически в редакторе (Section 1, Section 2...)
- BR-007: Заголовок и описание раздела поддерживают форматирование текста

**Результат:** Форма структурирована на логические разделы-страницы

### FR-LOGIC-002: Условные переходы на основе ответов

**Описание:** Настройка динамической навигации между разделами формы в зависимости от выбранного ответа на вопрос (branching logic).

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Форма разделена на несколько разделов (минимум 2)
- В форме есть вопросы типа "Multiple choice" или "Dropdown"
- Пользователь находится в режиме редактирования формы

**Основной сценарий:**
1. Создатель формы выбирает вопрос типа Multiple choice или Dropdown
2. Нажимает на значок с тремя точками (⋮) в правом нижнем углу вопроса
3. В выпадающем меню выбирает "Go to section based on answer"
4. Система активирует режим условных переходов:
   - Справа от каждого варианта ответа появляется выпадающий список
   - Список содержит доступные направления навигации
5. Для каждого варианта ответа создатель выбирает направление:
   - **Continue to next section** - перейти к следующему по порядку разделу
   - **Go to section 2** - перейти к конкретному разделу (2, 3, 4...)
   - **Go to section 3** - другой конкретный раздел
   - **Submit form** - завершить форму и отправить ответы
6. Пример настройки для вопроса "Are you a student or teacher?":
   - Ответ "Student" → Go to section 2 "Student Questions"
   - Ответ "Teacher" → Go to section 3 "Teacher Questions"
   - Ответ "Other" → Go to section 4 "General Questions"
7. Система сохраняет настройки автоматически
8. В режиме предпросмотра/заполнения:
   - Респондент выбирает ответ
   - Нажимает "Next"
   - Система автоматически направляет к указанному разделу
   - Пропущенные разделы не показываются
9. Вопрос с условными переходами отображает индикатор:
   - Значок ветвления рядом с вопросом
   - Подсказка "Go to section based on answer"
10. Можно настроить несколько вопросов с ветвлением в одной форме

**Альтернативные сценарии:**
- Сценарий А (Несколько вопросов в разделе): Если раздел содержит несколько вопросов с условной логикой, срабатывает ПОСЛЕДНИЙ вопрос перед переходом
- Сценарий Б (Рекомендация): Лучше создавать разделы с одним ключевым вопросом для четкой логики
- Сценарий В (Пропуск разделов): Респондент может пропустить несколько разделов в зависимости от ответа
- Сценарий Г (Завершение формы): Опция "Submit form" позволяет досрочно завершить форму для определенных ответов
- Сценарий Д (Циклические переходы): Можно создать переход обратно к предыдущему разделу (не рекомендуется)

**Бизнес-правила:**
- BR-008: Условные переходы работают только с вопросами типа "Multiple choice" и "Dropdown"
- BR-009: Каждый вариант ответа может иметь свой уникальный переход
- BR-010: Если в разделе несколько вопросов с ветвлением, работает только последний
- BR-011: Невозможно создать переход к разделу, который идет раньше текущего (только вперед или submit)
- BR-012: Можно переходить к любому последующему разделу, пропуская промежуточные
- BR-013: Опция "Submit form" немедленно завершает форму
- BR-014: Условная логика применяется при нажатии кнопки "Next", не автоматически при выборе
- BR-015: Респондент не видит пропущенные разделы и не может к ним вернуться

**Результат:** Форма адаптируется к ответам респондента, показывая только релевантные вопросы

### FR-LOGIC-003: Перемешивание порядка вопросов

**Описание:** Рандомизация последовательности вопросов в форме для предотвращения списывания и снижения систематической ошибки.

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Форма создана и содержит вопросы
- Пользователь имеет права на редактирование формы
- Пользователь находится в настройках формы

**Основной сценарий:**
1. Создатель формы нажимает на значок "Settings" (шестеренка) в верхней панели
2. Открывается модальное окно настроек формы
3. Переключается на вкладку "Presentation"
4. В разделе настроек видит опцию "Shuffle question order"
5. Включает переключатель (toggle) "Shuffle question order"
6. Система автоматически сохраняет изменение
7. Закрывает окно настроек
8. Поведение при заполнении формы:
   - Каждый респондент видит вопросы в случайном порядке
   - Порядок генерируется индивидуально при открытии формы
   - Разные респонденты получают разные последовательности
9. Вопросы перемешиваются, но сохраняют:
   - Свой исходный номер в результатах
   - Связь с разделами (перемешивание внутри раздела)
   - Настройки валидации и обязательности
10. В результатах ответы отображаются в оригинальном порядке, как созданы в редакторе

**Альтернативные сценарии:**
- Сценарий А (Разделы формы): Если форма разделена на секции, вопросы перемешиваются ТОЛЬКО внутри каждой секции отдельно
- Сценарий Б (Порядок разделов): Порядок самих разделов НЕ перемешивается, только вопросы внутри них
- Сценарий В (Отключение перемешивания): Можно отключить функцию в любой момент - новые респонденты увидят исходный порядок
- Сценарий Г (Тестирование): В режиме предпросмотра каждое открытие показывает новый случайный порядок
- Сценарий Д (Избежание перемешивания): Чтобы определенные вопросы не перемешивались, нужно поместить их в отдельные разделы

**Бизнес-правила:**
- BR-016: Перемешивание применяется ко всем вопросам формы
- BR-017: Невозможно выборочно перемешать только часть вопросов (все или ничего)
- BR-018: Перемешивание происходит при каждом новом открытии формы
- BR-019: Порядок уникален для каждого респондента
- BR-020: В формах с разделами перемешивание ограничено рамками каждого раздела
- BR-021: Результаты всегда показывают вопросы в оригинальном порядке
- BR-022: Перемешивание не влияет на оценку в режиме Quiz
- BR-023: Условная логика (go to section) не конфликтует с перемешиванием
- BR-024: Первый вопрос раздела может стать последним после перемешивания

**Результат:** Вопросы появляются в случайном порядке для каждого респондента

### FR-LOGIC-004: Перемешивание вариантов ответов

**Описание:** Рандомизация порядка вариантов ответов в вопросах с выбором для предотвращения систематической ошибки выбора.

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Форма содержит вопросы типа Multiple choice, Checkboxes или Dropdown
- Вопрос имеет несколько вариантов ответа
- Пользователь редактирует форму

**Основной сценарий:**
1. Создатель формы открывает вопрос типа Multiple choice, Checkboxes или Dropdown
2. Нажимает на значок с тремя точками (⋮) в правом нижнем углу вопроса
3. В выпадающем меню выбирает "Shuffle option order"
4. Система активирует перемешивание для этого вопроса:
   - Появляется индикатор "Options will be shuffled"
   - Варианты ответа сохраняют исходный порядок в редакторе
5. Настройка применяется к конкретному вопросу (не ко всей форме)
6. Создатель может настроить перемешивание для других вопросов индивидуально
7. При заполнении формы респондентом:
   - Открывается форма
   - Для вопросов с включенным перемешиванием варианты появляются в случайном порядке
   - Каждый респондент видит свою уникальную последовательность
   - Разные вопросы перемешиваются независимо
8. Пример вопроса "What is your favorite color?":
   - Исходный порядок: Red, Blue, Green, Yellow, Other
   - Респондент А видит: Green, Yellow, Red, Other, Blue
   - Респондент Б видит: Blue, Red, Other, Green, Yellow
9. В результатах ответы группируются по оригинальным вариантам, независимо от порядка
10. Можно отключить перемешивание для вопроса в любой момент

**Альтернативные сценарии:**
- Сценарий А (Опция "Other"): Если есть вариант "Other", он обычно остается в конце (не перемешивается)
- Сценарий Б (Quiz режим): Перемешивание работает и в режиме теста, не влияя на правильность ответа
- Сценарий В (Условные переходы): При использовании "Go to section based on answer" перемешивание не влияет на логику - переход связан с содержанием ответа, а не позицией
- Сценарий Г (Все вопросы): Нужно включать перемешивание для каждого вопроса отдельно
- Сценарий Д (Dropdown): В выпадающих списках перемешивание работает так же, как в множественном выборе

**Бизнес-правила:**
- BR-025: Перемешивание настраивается индивидуально для каждого вопроса
- BR-026: Доступно только для типов: Multiple choice, Checkboxes, Dropdown
- BR-027: Недоступно для типов: Short answer, Paragraph, Linear scale, Date, Time
- BR-028: Каждый респондент получает уникальный порядок вариантов
- BR-029: Порядок генерируется заново при каждом открытии формы
- BR-030: В результатах варианты группируются по оригинальному порядку
- BR-031: Опция "Other" (если есть) может оставаться внизу или перемешиваться
- BR-032: Перемешивание не влияет на корректность ответов в Quiz режиме
- BR-033: Условная логика работает независимо от перемешивания

**Результат:** Варианты ответов отображаются в случайном порядке для каждого респондента

### FR-LOGIC-005: Ограничение количества ответов

**Описание:** Настройка автоматического закрытия формы после достижения определенного числа ответов (через сторонние дополнения).

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Форма создана и опубликована
- Создатель имеет Google аккаунт
- Создатель установил дополнение (add-on) для ограничения ответов

**Основной сценарий:**
1. Создатель формы открывает Google Forms
2. В редакторе формы нажимает на значок "More" (три точки) → "Add-ons" → "Get add-ons"
3. В Google Workspace Marketplace ищет "Form Limiter" или "formLimiter"
4. Устанавливает дополнение "formLimiter":
   - Нажимает "Install"
   - Предоставляет необходимые разрешения
   - Дополнение интегрируется с формой
5. После установки в меню появляется "Add-ons" → "formLimiter"
6. Создатель открывает "formLimiter" → "Set limit"
7. В панели настроек выбирает тип ограничения:

   **Опция А: Ограничение по количеству ответов**
   - Выбирает "Limit by number of responses"
   - Вводит максимальное число (например, 100)
   - Форма автоматически закроется после 100 ответов

   **Опция Б: Ограничение по дате/времени**
   - Выбирает "Limit by date and time"
   - Устанавливает дату окончания (например, 31 декабря 2025, 23:59)
   - Форма закроется автоматически в указанное время

   **Опция В: Ограничение по расписанию**
   - Настраивает определенные часы приема ответов
   - Например: принимать ответы только с 9:00 до 17:00

8. Настраивает кастомное сообщение для закрытой формы:
   - "Thank you for your interest. This form is now closed."
   - "Registration limit reached. Please contact us for more information."
9. Активирует ограничение кнопкой "Enable limit"
10. Дополнение мониторит форму в реальном времени:
    - Отслеживает количество ответов
    - При достижении лимита автоматически закрывает прием ответов
    - Переключает настройку "Accepting responses" в OFF
11. После закрытия респонденты видят кастомное сообщение вместо формы

**Альтернативные сценарии:**
- Сценарий А (Ручное закрытие): Создатель может вручную закрыть форму раньше лимита через Settings → Accepting responses → OFF
- Сценарий Б (Изменение лимита): Можно изменить лимит в любой момент через formLimiter настройки
- Сценарий В (Реактивация): После закрытия можно снова открыть форму, увеличив лимит или отключив ограничение
- Сценарий Г (Ограничение на вопрос): Некоторые add-ons позволяют ограничить выбор конкретного варианта ответа (например, "Select time slot" - каждый слот ограничен 10 людьми)
- Сценарий Д (Уведомления): formLimiter может отправить email создателю при достижении лимита

**Бизнес-правила:**
- BR-034: Google Forms не имеет встроенной функции ограничения по количеству (требуется add-on)
- BR-035: Популярные дополнения: formLimiter, Form Limit, Choice Eliminator
- BR-036: formLimiter бесплатен для базового использования
- BR-037: Мониторинг работает в реальном времени (задержка 1-2 минуты)
- BR-038: После закрытия форма переключается в режим "Not accepting responses"
- BR-039: Можно комбинировать ограничения (и по количеству, и по времени)
- BR-040: Кастомное сообщение поддерживает текст и ссылки
- BR-041: Создатель получает email уведомление при достижении лимита
- BR-042: Можно настроить предупреждение за N ответов до лимита

**Результат:** Форма автоматически закрывается при достижении лимита ответов или времени

### FR-LOGIC-006: Ограничение "Один ответ на пользователя"

**Описание:** Настройка формы для приема только одного ответа от каждого пользователя Google, предотвращая множественные отправки.

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Форма создана в Google Forms
- Пользователь имеет права на редактирование формы
- Респонденты имеют Google аккаунты

**Основной сценарий:**

### FR-LOGIC-011: Валидация ответов - Число

**Описание:** Настройка правил проверки числовых значений для ограничения диапазона и формата ответов.

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Форма содержит вопрос типа "Short answer" или "Paragraph"
- Пользователь редактирует форму
- Вопрос должен принимать числовой ввод

**Основной сценарий:**
1. Создатель формы создает или открывает вопрос типа "Short answer"
2. Нажимает на иконку с тремя точками (⋮) в правом нижнем углу вопроса
3. Выбирает "Response validation"
4. Система показывает панель настройки валидации:
   - Первый выпадающий список: выбор типа данных
   - Второй выпадающий список: условие проверки
   - Поле ввода: значение для сравнения
   - Поле "Custom error text": сообщение об ошибке
5. В первом выпадающем списке выбирает "Number"
6. Во втором выпадающем списке доступны опции:

   **Опции валидации для чисел:**
   - **Greater than** - больше чем (>) указанное значение
   - **Greater than or equal to** - больше или равно (≥)
   - **Less than** - меньше чем (<)
   - **Less than or equal to** - меньше или равно (≤)
   - **Equal to** - равно (=)
   - **Not equal to** - не равно (≠)
   - **Between** - в диапазоне от X до Y
   - **Not between** - вне диапазона
   - **Is number** - является числом
   - **Whole number** - целое число (без дробной части)

7. Пример настройки: Вопрос "Enter your age"
   - Number → Greater than or equal to → 18
   - Custom error text: "You must be at least 18 years old"
8. Пример: Вопрос "Rate from 1 to 10"
   - Number → Between → 1 and 10
   - Custom error text: "Please enter a number between 1 and 10"
9. Сохраняет настройки (автоматически)
10. При заполнении формы респондентом:
    - Вводит значение в поле
    - Нажимает "Next" или "Submit"
    - Система проверяет значение:
      - Если соответствует правилу → переход дальше
      - Если НЕ соответствует → показывается красное сообщение об ошибке под полем
    - Респондент не может продолжить без исправления

**Альтернативные сценарии:**
- Сценарий А (Нецелое число): Если выбрано "Whole number", значения типа 5.5 будут отклонены
- Сценарий Б (Отрицательные числа): Валидация работает с отрицательными числами (например, > -10)
- Сценарий В (Диапазон): Опция "Between" требует два значения (минимум и максимум)
- Сценарий Г (Текст вместо числа): Если пользователь введет текст, валидация "Is number" отклонит ответ
- Сценарий Д (Пустое поле): Если вопрос НЕ обязательный, пустой ответ проходит валидацию

**Бизнес-правила:**
- BR-085: Валидация Number доступна для типов "Short answer" и "Paragraph"
- BR-086: Можно применить только одно правило валидации на вопрос
- BR-087: Кастомное сообщение об ошибке обязательно (по умолчанию: "Invalid response")
- BR-088: Валидация срабатывает при попытке перейти к следующему вопросу
- BR-089: Поддерживаются целые и дробные числа (зависит от правила)

### FR-LOGIC-014: Валидация ответов - Regular Expression

**Описание:** Настройка сложных правил валидации текста с использованием регулярных выражений для точного контроля формата.

**Роли:** Создатель формы, Редактор формы (с знанием regex)

**Предусловия:**
- Форма содержит вопрос типа "Short answer" или "Paragraph"
- Создатель знаком с синтаксисом регулярных выражений
- Требуется сложная валидация формата

**Основной сценарий:**
1. Создатель формы открывает вопрос типа "Short answer"
2. Нажимает на иконку с тремя точками (⋮) → "Response validation"
3. В первом выпадающем списке выбирает "Regular expression"
4. Во втором выпадающем списке доступны опции:

   **Опции для регулярных выражений:**
   - **Contains** - содержит паттерн
   - **Doesn't contain** - НЕ содержит паттерн
   - **Matches** - полностью соответствует паттерну
   - **Doesn't match** - НЕ соответствует паттерну

5. В поле ввода вводит регулярное выражение (без слешей, только паттерн)
6. Вводит кастомное сообщение об ошибке
7. Примеры использования регулярных выражений:

   **Пример А: Телефонный номер (US формат)**
   - Вопрос: "Enter your phone number (xxx-xxx-xxxx)"
   - Regex → Matches → `^\d{3}-\d{3}-\d{4}$`
   - Error: "Please enter phone in format: 123-456-7890"

   **Пример Б: Почтовый индекс (5 цифр)**
   - Вопрос: "ZIP Code"
   - Regex → Matches → `^\d{5}$`
   - Error: "ZIP code must be exactly 5 digits"

   **Пример В: Номер карты (4 группы по 4 цифры)**
   - Вопрос: "Credit Card (xxxx-xxxx-xxxx-xxxx)"
   - Regex → Matches → `^\d{4}-\d{4}-\d{4}-\d{4}$`
   - Error: "Card number must be in format: 1234-5678-9012-3456"

   **Пример Г: Только буквы (имя)**
   - Вопрос: "First Name (letters only)"
   - Regex → Matches → `^[A-Za-z]+$`
   - Error: "Name must contain only letters"

   **Пример Д: Username (буквы, цифры, подчеркивание, 3-16 символов)**
   - Вопрос: "Choose username"
   - Regex → Matches → `^[A-Za-z0-9_]{3,16}$`
   - Error: "Username: 3-16 characters, letters, numbers, underscore only"

   **Пример Е: Сильный пароль**
   - Вопрос: "Create password (min 8 chars, 1 uppercase, 1 number)"
   - Regex → Matches → `^(?=.*[A-Z])(?=.*\d).{8,}$`
   - Error: "Password must be 8+ characters with at least 1 uppercase and 1 number"

   **Пример Ж: Email (кастомный домен)**
   - Вопрос: "Company email (@company.com only)"
   - Regex → Matches → `^[a-zA-Z0-9._%+-]+@company\.com$`
   - Error: "Please use your @company.com email address"

   **Пример З: URL конкретного сайта**
   - Вопрос: "GitHub profile URL"
   - Regex → Contains → `github\.com`
   - Error: "Please provide a valid GitHub profile URL"

8. При заполнении формы система применяет regex валидацию
9. Если ответ не соответствует паттерну, показывается ошибка

**Альтернативные сценарии:**
- Сценарий А (Неправильный regex): Если синтаксис regex некорректен, валидация может не работать
- Сценарий Б (Тестирование): Рекомендуется протестировать regex через Preview mode
- Сценарий В (Сложные паттерны): Можно создавать очень сложные правила (IPv4, даты, коды и т.д.)
- Сценарий Г (Производительность): Очень сложные regex могут замедлить валидацию
- Сценарий Д (Инструменты): Использовать regex101.com или regexr.com для тестирования паттернов

**Бизнес-правила:**
- BR-107: Regex валидация доступна для "Short answer" и "Paragraph"
- BR-108: Паттерн вводится без слешей (не /pattern/, а просто pattern)
- BR-109: Поддерживается стандартный синтаксис JavaScript RegExp
- BR-110: "Matches" требует полного совпадения (как ^pattern$)
- BR-111: "Contains" ищет паттерн внутри текста
- BR-112: Регистрозависимость по умолчанию (используйте [A-Za-z] для обоих регистров)
- BR-113: Специальные символы нужно экранировать (. становится \.)
- BR-114: Lookahead (?=...) и другие advanced паттерны поддерживаются
- BR-115: Максимальная длина паттерна не ограничена, но рекомендуется <500 символов

**Результат:** Респондент вводит данные в точно заданном формате через regex

- Сценарий Б (Workspace ограничение): В Google Workspace можно ограничить сбор только пользователями организации (@company.com)
- Сценарий В (Несколько email): Нельзя собрать несколько email в одной форме (только один)
- Сценарий Г (Email отправителя): "Verified" гарантирует подлинность email, "Responder input" - нет
- Сценарий Д (Уведомления): Email используется для отправки копии ответа и ссылки на редактирование

**Бизнес-правила:**
- BR-116: Три режима: Do not collect, Verified, Responder input
- BR-117: "Verified" требует вход в Google аккаунт
- BR-118: "Verified" автоматически извлекает email из профиля Google
- BR-119: "Responder input" добавляет обязательное поле Email в начало формы
- BR-120: "Responder input" не верифицирует подлинность email
- BR-121: В Workspace можно ограничить только пользователями домена
- BR-122: Email всегда в отдельной колонке "Email Address" в результатах
- BR-123: "Limit to 1 response" автоматически включает "Verified" режим

   - Section 2 → Continue to next section (Section 3)
   - Section 3 → Submit form

   **Пример Б: Опциональные секции**
   - Section 1 "Basic Info" → Continue to next section
   - Section 2 "Optional Details" → Continue to next section OR Submit form
   - Респондент может выбрать закончить раньше

   **Пример В: Пропуск секций**
   - Section 1 "Intro" → Go to section 3 (пропустить Section 2)
   - Используется для скрытия неактуальных вопросов

6. Для настройки кнопки "Back":
   - По умолчанию в каждом разделе (кроме первого) есть кнопка "Back"
   - Позволяет вернуться к предыдущему разделу
   - Нельзя отключить кнопку "Back" (всегда доступна)
7. Последний раздел формы:
   - Всегда имеет только кнопку "Submit"
   - Нет выбора навигации (форма завершается)

**Альтернативные сценарии:**
- Сценарий А (Конфликт с условной логикой): Если на вопросе настроен "Go to section based on answer", он переопределяет настройки навигации раздела
- Сценарий Б (Первый раздел): Первый раздел не имеет кнопки "Back"
- Сценарий В (Циклы): Можно создать цикл (Go to section 1 из section 3), но это не рекомендуется
- Сценарий Г (Респондент застрял): При циклической навигации респондент может застрять в бесконечном цикле
- Сценарий Д (Submit в середине): "Submit form" удобен для досрочного завершения опроса

**Бизнес-правила:**
- BR-133: Навигация настраивается для каждого раздела индивидуально
- BR-134: По умолчанию все разделы ведут к следующему (Continue to next section)
- BR-135: Можно перейти к любому последующему разделу
- BR-136: Можно создать переход назад (не рекомендуется)
- BR-137: "Submit form" немедленно завершает форму, пропуская остальные разделы
- BR-138: Условная логика вопроса переопределяет навигацию раздела
- BR-139: Кнопка "Back" всегда доступна (кроме первого раздела)
- BR-140: Последний раздел всегда завершается отправкой (Submit)
- BR-141: Навигация не зависит от обязательности вопросов (проверка при попытке перехода)

**Результат:** Контроль потока заполнения формы через настройки навигации разделов

### FR-LOGIC-018: Добавление описаний и изображений в разделы

**Роли:** Создатель формы, Редактор формы

**Предусловия:**

- Есть контент для добавления (текст, изображения, видео)

**Основной сценарий:**
1. Создатель формы открывает раздел (section) в редакторе

    - Изображения и видео в форме
    - Описания разделов
    - Дополнительные текстовые блоки между вопросами

**Альтернативные сценарии:**
- Сценарий А (Множественные изображения): Можно добавить несколько изображений в один раздел
- Сценарий Б (Видео только YouTube): Google Forms поддерживает только YouTube видео (не Vimeo, не прямые .mp4)

- Сценарий Г (Изображения в вопросах): Можно добавить изображения и к самим вопросам и вариантам ответов

**Бизнес-правила:**

- BR-145: Можно добавлять неограниченное количество изображений и видео

- BR-150: Standalone текстовые блоки добавляются через "Add title and description"

**Результат:** Форма обогащена визуальным контентом и инструкциями

### FR-LOGIC-019: Отключение отправки формы

**Описание:** Временное или постоянное закрытие формы для прекращения приема новых ответов.

**Роли:** Создатель формы, Редактор формы

**Предусловия:**
- Форма создана и опубликована
- Пользователь имеет права на редактирование
- Есть причина закрыть форму (достигнут лимит, истек срок и т.д.)

**Основной сценарий:**
1. Создатель формы открывает форму в редакторе
2. Нажимает на вкладку "Responses" (между Questions и Settings)
3. В правом верхнем углу видит переключатель "Accepting responses"
4. По умолчанию переключатель в положении ON (зеленый) - форма принимает ответы
5. Переключает в положение OFF (серый)
6. Форма немедленно перестает принимать ответы
7. Когда респондент пытается открыть форму:
   - Вместо формы видит сообщение
   - Стандартное: "[Form name] is no longer accepting responses."
   - Или: "Try contacting the owner of the form if you think this is a mistake."
8. Для настройки кастомного сообщения:
   - При выключенном "Accepting responses"
   - Под переключателем появляется поле "Message for responders"
   - Можно ввести кастомное сообщение:
     - "Thank you for your interest! Registration is now closed."
     - "The deadline has passed. Please contact us at email@example.com"
     - "Форма временно недоступна. Вернитесь 15 января 2025."
9. Сохранение происходит автоматически
10. Для повторного открытия формы:
    - Переключает "Accepting responses" обратно в ON
    - Форма снова доступна для заполнения
    - Предыдущие ответы сохранены

**Альтернативные сценарии:**
- Сценарий А (Автоматическое закрытие): Для автоматического закрытия по лимиту нужен add-on (formLimiter)
- Сценарий Б (Временное закрытие): Можно временно закрыть на обслуживание или правки, потом открыть
- Сценарий В (Предыдущие ответы): Закрытие формы не влияет на уже собранные ответы
- Сценарий Г (Редактирование закрытой формы): Можно редактировать вопросы даже когда форма закрыта
- Сценарий Д (Ссылка все еще работает): URL формы остается тот же, просто показывается сообщение о закрытии

**Бизнес-правила:**
- BR-151: Переключатель "Accepting responses" управляет приемом ответов
- BR-152: Изменение вступает в силу немедленно
- BR-153: По умолчанию показывается стандартное сообщение о закрытии
- BR-154: Можно настроить кастомное сообщение для респондентов
- BR-155: Кастомное сообщение поддерживает plain text и ссылки
- BR-156: Максимальная длина кастомного сообщения ~500 символов
- BR-157: Закрытие не удаляет и не влияет на существующие ответы
- BR-158: URL формы остается прежним
- BR-159: Форму можно открыть и закрыть множество раз

**Результат:** Форма закрыта для новых ответов с кастомным сообщением

### FR-LOGIC-020: Ограничение доступа к форме (только для организации)

**Описание:** Настройка формы для доступа только пользователям определенного домена Google Workspace.

**Роли:** Создатель формы (в Google Workspace), Редактор формы

**Предусловия:**
- Создатель использует Google Workspace (корпоративный аккаунт)
- Форма создана в Workspace окружении
- Администратор разрешил создание форм с ограничениями

**Основной сценарий:**
1. Создатель формы (пользователь @company.com) открывает Settings
2. На вкладке "General" видит секцию "Respondents"
3. Находит опцию "Restrict to [ваш домен] users"
4. Включает чекбокс "Restrict to company.com users"
5. Нажимает Save
6. Система активирует ограничение доступа
7. Когда пользователь пытается открыть форму:

   **Пользователь из той же организации (@company.com):**
   - Видит экран "Sign in to continue"
   - Входит через корпоративный Google аккаунт
   - Получает доступ к форме

8. Email автоматически собирается (verified режим)
9. В результатах видны только ответы сотрудников организации
10. Полезно для:
    - Внутренних HR опросов

    - IT заявок
    - Тренингов и тестирований

**Альтернативные сценарии:**
- Сценарий А (Только в Workspace): Опция доступна только для Google Workspace аккаунтов, не для бесплатного Gmail
- Сценарий Б (Множественные домены): Если организация имеет несколько доменов, они все включены в ограничение
- Сценарий В (Гостевые аккаунты): Можно настроить исключения для гостевых пользователей (через администратора)
- Сценарий Г (Внешние партнеры): Для доступа внешних партнеров нужно либо отключить ограничение, либо добавить их как гостей
- Сценарий Д (Настройки администратора): Администратор Workspace может принудительно включить это ограничение для всех форм

**Бизнес-правила:**
- BR-160: Опция доступна только в Google Workspace (не в бесплатных аккаунтах)
- BR-161: Требует вход в Google аккаунт организации
- BR-162: Автоматически включает "Collect email addresses" в режиме "Verified"
- BR-163: Блокирует доступ для пользователей вне домена организации
- BR-164: Включает все домены организации (если их несколько)
- BR-165: Можно комбинировать с "Limit to 1 response"
- BR-166: Администратор может принудительно применить это ограничение
- BR-167: Полезно для compliance и внутренней безопасности данных

**Результат:** Форма доступна только пользователям корпоративного домена

## Сущности данных

### Раздел формы (Form Section)
- **section_id** - уникальный идентификатор раздела
- **form_id** - ID формы, к которой принадлежит раздел
- **section_number** - порядковый номер раздела (1, 2, 3...)
- **section_title** - заголовок раздела (обязательно)
- **section_description** - описание раздела (опционально)
- **navigation_type** - тип навигации (continue_to_next, submit_form, go_to_section_X)
- **target_section_id** - ID целевого раздела (для go_to_section)
- **questions** - массив вопросов в разделе
- **media_elements** - изображения и видео в разделе (JSON)
- **created_at** - дата создания раздела
- **updated_at** - дата последнего обновления

### Правило условного перехода (Branching Rule)
- **rule_id** - уникальный ID правила
- **question_id** - ID вопроса с условием
- **question_type** - тип вопроса (multiple_choice, dropdown)
- **answer_option** - вариант ответа, который триггерит переход
- **destination_type** - тип направления (next_section, specific_section, submit)
- **destination_section_id** - ID целевого раздела
- **is_active** - активно ли правило
- **created_by** - создатель правила

### Правило валидации (Validation Rule)
- **validation_id** - уникальный ID правила валидации
- **question_id** - ID вопроса с валидацией
- **validation_type** - тип валидации (number, text, length, regex)
- **condition** - условие (greater_than, contains, matches и т.д.)
- **value** - значение для проверки
- **value_min** - минимальное значение (для between)
- **value_max** - максимальное значение (для between)
- **regex_pattern** - регулярное выражение (для regex типа)
- **error_message** - кастомное сообщение об ошибке
- **is_active** - активна ли валидация

### Настройки формы (Form Settings)
- **form_id** - ID формы
- **accepting_responses** - принимает ли форма ответы (boolean)
- **closed_message** - сообщение при закрытой форме
- **limit_one_response** - ограничение 1 ответ на пользователя (boolean)
- **collect_email** - режим сбора email (none, verified, responder_input)
- **send_response_copy** - отправка копии ответа (always, when_requested, never)
- **allow_response_editing** - разрешить редактирование (boolean)
- **shuffle_questions** - перемешивание вопросов (boolean)
- **show_progress_bar** - показывать прогресс-бар (boolean)
- **show_link_to_submit_another** - показывать ссылку для повторной отправки (boolean)
- **confirmation_message** - сообщение подтверждения
- **restrict_to_domain** - ограничение по домену (для Workspace)
- **domain_name** - название домена (@company.com)
- **response_limit** - лимит ответов (через add-on)
- **response_limit_message** - сообщение при достижении лимита
- **updated_at** - последнее обновление настроек

### Конфигурация перемешивания (Shuffle Configuration)
- **config_id** - ID конфигурации
- **form_id** - ID формы
- **shuffle_questions_enabled** - перемешивание вопросов (boolean)
- **shuffle_scope** - область перемешивания (whole_form, per_section)
- **questions_with_shuffle_options** - массив вопросов с перемешиванием вариантов
  - question_id
  - shuffle_enabled (boolean)
  - keep_other_at_end (boolean)

### Медиа элемент (Media Element)
- **media_id** - уникальный ID элемента
- **section_id** - ID раздела
- **media_type** - тип (image, video, text_block)
- **source_type** - источник (upload, url, drive, photos, youtube)
- **url** - URL медиа ресурса
- **position** - позиция в разделе
- **alignment** - выравнивание (left, center, right)
- **size** - размер (small, medium, large, original)
- **alt_text** - альтернативный текст для изображений
- **caption** - подпись

### Сессия заполнения (Response Session)
- **session_id** - уникальный ID сессии
- **form_id** - ID формы
- **respondent_email** - email респондента (если собирается)
- **respondent_account_id** - Google account ID (для limit to 1)
- **current_section** - текущий раздел
- **sections_visited** - массив посещенных разделов
- **sections_skipped** - массив пропущенных разделов (через branching)
- **shuffle_seed** - seed для перемешивания (уникален для каждой сессии)
- **started_at** - время начала заполнения
- **last_activity_at** - последняя активность
- **is_completed** - завершена ли форма (boolean)
- **edit_token** - токен для редактирования ответа

## Состояния и статусы

### Статусы формы
- **open** - форма открыта и принимает ответы
- **closed** - форма закрыта для новых ответов
- **limited** - форма ограничена (по количеству или времени)
- **domain_restricted** - доступна только для домена организации

### Типы валидации
- **number** - числовая валидация
- **text** - текстовая валидация
- **length** - валидация длины
- **regex** - валидация регулярным выражением

### Условия валидации
- **greater_than** - больше чем
- **greater_than_or_equal** - больше или равно
- **less_than** - меньше чем
- **less_than_or_equal** - меньше или равно
- **equal_to** - равно
- **not_equal_to** - не равно
- **between** - в диапазоне
- **not_between** - вне диапазона
- **is_number** - является числом
- **whole_number** - целое число
- **contains** - содержит (текст или regex)
- **doesnt_contain** - не содержит
- **matches** - полностью соответствует
- **doesnt_match** - не соответствует
- **email** - корректный email
- **url** - корректный URL

### Режимы сбора email
- **none** - не собирать
- **verified** - верифицированный (через Google аккаунт)
- **responder_input** - ввод респондентом вручную

### Режимы отправки копии
- **always** - всегда автоматически
- **when_requested** - по запросу респондента
- **never** - не отправлять

### Типы навигации раздела
- **continue_to_next** - к следующему по порядку
- **submit_form** - отправить форму
- **go_to_section** - к конкретному разделу (+ ID раздела)

## Ограничения и лимиты

### Лимиты разделов
- **Максимальное количество разделов**: нет жесткого лимита (практически до 100+)
- **Минимальное количество разделов для прогресс-бара**: 2
- **Вопросов в разделе**: нет ограничений
- **Изображений в разделе**: нет ограничений
- **Размер заголовка раздела**: до 1000 символов
- **Размер описания раздела**: до 5000 символов

### Лимиты условной логики
- **Правил ветвления на форму**: не ограничено
- **Типы вопросов с ветвлением**: только Multiple choice и Dropdown
- **Вариантов ответа с условиями**: все варианты вопроса
- **Глубина вложенности**: практически неограничена (можно создавать сложные деревья)

### Лимиты валидации
- **Правил валидации на вопрос**: 1 (одно правило)
- **Типы вопросов с валидацией**: Short answer, Paragraph
- **Длина regex паттерна**: до 500 символов (рекомендуется)
- **Длина error message**: до 500 символов

### Лимиты настроек
- **Длина confirmation message**: ~500 символов
- **Длина closed form message**: ~500 символов
- **Response limit**: настраивается через add-on (до миллионов)
- **Email сообщение**: стандартный шаблон Google (не кастомизируется)

### Лимиты перемешивания
- **Вопросов для перемешивания**: все вопросы формы или раздела
- **Вариантов для перемешивания**: все варианты вопроса
- **Новый порядок при каждом открытии**: да (уникальный seed)

### Лимиты медиа
- **Размер загружаемого изображения**: рекомендуется до 2MB
- **Форматы изображений**: JPG, PNG, GIF, BMP
- **Видео**: только YouTube (embedded iframe)
- **Количество медиа элементов**: не ограничено

## Интеграции с другими модулями

### Модуль "Создание и редактирование форм"
- Условная логика настраивается в редакторе форм
- Разделы создаются через инструменты редактора
- Валидация добавляется к вопросам
- Медиа элементы встраиваются между вопросами

### Модуль "Типы вопросов"
- Условные переходы работают только с Multiple choice и Dropdown
- Валидация доступна для Short answer и Paragraph
- Перемешивание вариантов для Multiple choice, Checkboxes, Dropdown
- Linear scale не поддерживает ветвление

### Модуль "Сбор ответов и результаты"
- Email собирается в отдельную колонку результатов
- Пропущенные разделы не создают пустых колонок
- Timestamp обновляется при редактировании ответа
- Edit token привязан к Google аккаунту

### Модуль "Quiz режим"
- Перемешивание вопросов не влияет на оценку
- Перемешивание вариантов не влияет на правильность ответа
- Условная логика работает параллельно с Quiz
- Валидация совместима с автоматической оценкой

### Модуль "Дизайн и темы"
- Прогресс-бар наследует цвет темы формы
- Кнопки навигации (Next, Back, Submit) стилизуются темой
- Медиа элементы адаптируются под тему
- Сообщения об ошибках валидации в красном цвете (не кастомизируется)

### Google Sheets (результаты)
- Колонка Email Address при включенном сборе email
- Timestamp обновляется при редактировании
- Каждая новая отправка (Submit another response) - новая строка
- Пропущенные вопросы (через branching) остаются пустыми

### Google Workspace Admin
- Администратор может принудительно включить "Restrict to domain"
- Ограничение на создание форм для внешних пользователей
- Политики сбора данных и privacy
- Audit logs для всех настроек форм

### Google Apps Script
- Автоматизация закрытия формы по условиям
- Кастомные лимиты ответов через скрипты
- Автоматическая отправка уведомлений при достижении лимита
- Интеграция с другими Google сервисами

### Сторонние Add-ons
- **formLimiter** - ограничение по количеству ответов, дате/времени
- **Form Limit** - альтернатива для лимитов
- **Choice Eliminator** - ограничение выбора конкретных вариантов
- **Email Notifications** - кастомные email уведомления
- **Form Approvals** - workflow с одобрением ответов

## Метрики и производительность

### Ключевые метрики
- **Время валидации ответа**: <100мс
- **Переход между разделами**: мгновенный (<200мс)
- **Генерация порядка перемешивания**: при открытии формы (<500мс)
- **Отправка email копии**: 1-5 минут после Submit
- **Обновление "Accepting responses"**: мгновенно

### Влияние на UX
- **Условная логика**: сокращает количество вопросов на 30-50% для респондентов
- **Валидация**: снижает количество некорректных ответов на 80%+
- **Прогресс-бар**: увеличивает процент завершения форм на 15-20%
- **Перемешивание**: предотвращает списывание в тестах и опросах
- **Редактирование после отправки**: увеличивает точность данных на 10-15%

### Производительность
- **Форма с 100 разделами**: работает без задержек
- **50 правил ветвления**: не влияет на скорость
- **Перемешивание 200 вопросов**: <1 секунда на генерацию порядка
- **Regex валидация сложных паттернов**: <50мс
