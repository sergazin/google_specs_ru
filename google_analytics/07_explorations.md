# Исследования (Explorations)

## Описание

Модуль "Исследования" (Explorations / Explore) в Google Analytics 4 предоставляет набор продвинутых аналитических техник, выходящих за рамки стандартных отчётов. Исследования позволяют визуализировать данные, применять фильтры, сравнивать сегменты, отслеживать пользовательские пути и выявлять закономерности и тренды для принятия решений на основе данных.

Каждое исследование строится на основе трёх панелей: **Переменные** (Variables), **Настройки вкладки** (Tab Settings) и **Визуализация** (Canvas). Пользователь импортирует нужные измерения, метрики и сегменты в панель переменных, затем перетаскивает их в настройки вкладки для построения конкретной визуализации.

GA4 предоставляет 6 техник (типов) исследований:

1. **Свободная форма** (Free Form) — кросс-таблицы с различными типами визуализации
2. **Исследование воронки** (Funnel Exploration) — визуализация шагов конверсии
3. **Исследование пути** (Path Exploration) — древовидный граф пользовательских путей
4. **Пересечение сегментов** (Segment Overlap) — диаграмма Венна для сравнения сегментов
5. **Когортное исследование** (Cohort Exploration) — анализ поведения когорт во времени
6. **Время жизни пользователя** (User Lifetime) — анализ поведения пользователей за весь период взаимодействия

## Роли пользователей

| Роль | Доступ к Explore | Создание исследований | Редактирование своих | Редактирование чужих | Шеринг | Запрос без сэмплирования (360) |
|------|------------------|-----------------------|----------------------|----------------------|--------|-------------------------------|
| Администратор (Administrator) | Полный | Да | Да | Нет (только копия) | Да | Да |
| Редактор (Editor) | Полный | Да | Да | Нет (только копия) | Да | Да |
| Маркетолог (Marketer) | Полный | Да | Да | Нет (только копия) | Да | Да |
| Аналитик (Analyst) | Полный | Да | Да | Нет (только копия) | Да | Да |
| Зритель (Viewer) | Только чтение | Нет | Нет | Нет | Нет | Нет |

**Бизнес-правила ролей:**

- Зритель (Viewer) может просматривать только расшаренные (shared) исследования, но не может их редактировать
- Зритель должен создать копию (duplicate) расшаренного исследования, чтобы модифицировать его
- Расшаренные исследования НЕ являются совместными в реальном времени — изменения одного пользователя не видны другим немедленно
- Пользователь с ролью Analyst или выше может запрашивать результаты без сэмплирования (только GA4 360)
- Ограничения данных (cost metrics, revenue metrics) применяются на уровне роли и могут скрывать определённые метрики в исследованиях

## Функциональные требования

### FR-EXP-001: Создание нового исследования
**Priority**: P0-Critical

**Description**: Пользователь может создать новое исследование, выбрав пустой шаблон (Blank) или один из предустановленных шаблонов из галереи.

**Acceptance Criteria**:
- [ ] При переходе в раздел "Explore" отображается галерея шаблонов
- [ ] Доступен вариант "Blank" для создания исследования с нуля
- [ ] Доступны шаблоны по техникам: Free Form, Funnel Exploration, Path Exploration, Segment Overlap, Cohort Exploration, User Lifetime
- [ ] Доступны шаблоны по вариантам использования (Use Cases)
- [ ] Доступны шаблоны по отраслям (Industries)
- [ ] При выборе шаблона создаётся новое исследование с предзаполненными переменными и настройками
- [ ] Исследование сохраняется автоматически

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Максимум 200 исследований на пользователя на ресурс (property) |
| BR-002 | Максимум 500 расшаренных исследований на ресурс (стандартная лицензия) |
| BR-003 | Максимум 1000 расшаренных исследований на ресурс (GA4 360 лицензия) |
| BR-004 | Новое исследование создаётся как приватное (видимое только создателю) |

### FR-EXP-002: Панель переменных (Variables)
**Priority**: P0-Critical

**Description**: Панель переменных содержит пул измерений (dimensions), метрик (metrics) и сегментов (segments), доступных для использования в исследовании. Пользователь импортирует необходимые элементы, чтобы предзагрузить данные и ускорить визуализацию.

**Acceptance Criteria**:
- [ ] Панель переменных содержит разделы: Dimensions, Metrics, Segments
- [ ] Пользователь может добавлять измерения из списка доступных (кнопка "+")
- [ ] Пользователь может добавлять метрики из списка доступных (кнопка "+")
- [ ] Пользователь может добавлять существующие сегменты или создавать новые
- [ ] Пользователь может изменять временной диапазон (date range) исследования
- [ ] Пользователь может задать название исследования
- [ ] Импортированные переменные доступны для перетаскивания в настройки вкладки

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-005 | Максимум 20 измерений на исследование |
| BR-006 | Максимум 20 метрик на исследование |
| BR-007 | Максимум 10 сегментов на исследование |

---

### FR-EXP-003: Настройки вкладки (Tab Settings)
**Priority**: P0-Critical

**Description**: Панель настроек вкладки определяет конфигурацию текущей визуализации. Пользователь выбирает технику, размещает элементы из переменных в целевые области и настраивает специфические параметры техники.

**Acceptance Criteria**:
- [ ] Пользователь может выбрать технику исследования (Technique)
- [ ] Пользователь может перетащить или выбрать сегменты в область "Segment Comparisons"
- [ ] Пользователь может перетащить измерения в область "Rows" и/или "Columns"
- [ ] Пользователь может перетащить метрики в область "Values"
- [ ] Пользователь может настроить фильтры (Filters) для включения/исключения данных
- [ ] Настройки специфичны для каждой техники (например, тип воронки, тип узла пути)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-008 | Максимум 10 фильтров на вкладку |
| BR-009 | Максимум 5 измерений в строках (Rows) или разбивке (Breakdown), исключая технику воронки и когорт |
| BR-010 | Максимум 2 измерения в столбцах (Columns) для табличных визуализаций |
| BR-011 | Фильтры могут быть на основе измерений и метрик с условиями включения/исключения |

### FR-EXP-004: Управление вкладками (Tabs)
**Priority**: P1-High

**Description**: Исследование может содержать несколько вкладок, каждая из которых представляет отдельную визуализацию с собственной техникой и настройками.

**Acceptance Criteria**:
- [ ] Пользователь может добавлять новые вкладки
- [ ] Пользователь может переименовывать вкладки
- [ ] Пользователь может удалять вкладки
- [ ] Пользователь может переключаться между вкладками
- [ ] Каждая вкладка может использовать разную технику исследования
- [ ] Переменные (измерения, метрики, сегменты) общие для всех вкладок в рамках одного исследования

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-012 | Максимум 10 вкладок (визуализаций) на одно исследование |

### FR-EXP-005: Свободная форма (Free Form Exploration)
**Priority**: P0-Critical

**Description**: Техника свободной формы позволяет создавать кросс-таблицы и визуализировать данные с использованием различных типов диаграмм. Это основная и наиболее гибкая техника исследований.

**Acceptance Criteria**:
- [ ] Поддерживается 6 типов визуализации: таблица (Table), кольцевая диаграмма (Donut Chart), линейная диаграмма (Line Chart), точечная диаграмма (Scatterplot), столбчатая диаграмма (Bar Chart), географическая карта (Geo Map)
- [ ] В таблице поддерживаются вложенные строки (nested rows) для иерархической группировки данных
- [ ] В таблице доступны 3 типа ячеек (Cell Type): гистограмма (Bar Chart), простой текст (Plain Text), тепловая карта (Heatmap)
- [ ] Тепловая карта окрашивает ячейки в зависимости от величины значений (тёмные оттенки = высокие значения, светлые = низкие)
- [ ] Линейная диаграмма поддерживает выбор гранулярности: час, день, неделя, месяц
- [ ] Линейная диаграмма поддерживает обнаружение аномалий (Anomaly Detection), включённое по умолчанию
- [ ] Точечная диаграмма отображает корреляцию двух переменных
- [ ] Географическая карта визуализирует данные на карте мира
- [ ] Правый клик на данных позволяет создать сегмент из выделения ("Create segment from selection")
- [ ] Правый клик на данных позволяет применить фильтр ("Include only selection" / "Exclude selection")

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-013 | Обнаружение аномалий использует байесовскую модель пространства состояний для временных рядов |
| BR-014 | Аномалия определяется статистическим тестом значимости на основе прогнозного значения |
| BR-015 | Кольцевая диаграмма оптимальна при 6 или менее значениях измерения |
| BR-016 | Столбчатая диаграмма рекомендуется при более чем 6 значениях измерения |
| BR-017 | При вложенных строках первое измерение является основной группой, последующие — подгруппами |

### FR-EXP-006: Исследование воронки (Funnel Exploration)
**Priority**: P0-Critical

**Description**: Техника воронки позволяет визуализировать шаги, которые пользователи выполняют для завершения задачи, и определить, насколько успешно они проходят каждый шаг. Поддерживаются открытые и закрытые воронки, стандартная и трендовая визуализация.

**Acceptance Criteria**:
- [ ] Пользователь может определить от 2 до 10 шагов воронки
- [ ] Каждый шаг может иметь одно или несколько условий (events, dimensions)
- [ ] Условия внутри шага объединяются через AND или OR
- [ ] Пользователь может переключить воронку между "открытой" (Open) и "закрытой" (Closed)
- [ ] Пользователь может выбрать тип визуализации: стандартная (Standard / Stepped) или трендовая (Trended / Line Chart)
- [ ] Для каждого шага отображается количество пользователей и процент от предыдущего шага
- [ ] Отображается среднее затраченное время (Elapsed Time) между шагами
- [ ] Пользователь может добавить временное ограничение ("Within") между последовательными шагами
- [ ] Пользователь может добавить разбивку (Breakdown) по измерению под визуализацией воронки
- [ ] В трендовой воронке отображаются все шаги одновременно или конкретный шаг по клику

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-018 | В закрытой воронке пользователи должны войти через первый шаг; если шаг пропущен — пользователь исключается из последующих шагов |
| BR-019 | В открытой воронке пользователи могут войти на любом шаге |
| BR-020 | Затраченное время рассчитывается как сумма времени (в микросекундах) между предыдущим и текущим шагом, делённая на количество пользователей, достигших текущего шага |
| BR-021 | Временное ограничение между шагами задаётся в секундах, минутах, часах или днях |
| BR-022 | Максимум 10 шагов воронки |

---

### FR-EXP-007: Исследование пути (Path Exploration)
**Priority**: P0-Critical

**Description**: Техника исследования пути визуализирует поток событий пользователей в виде древовидного графа. Позволяет анализировать поведение пользователей вперёд от начальной точки или назад от конечной точки.

**Acceptance Criteria**:
- [ ] Визуализация в виде древовидного графа (Tree Graph)
- [ ] Поддерживаются 4 типа узлов: имя события (Event Name), заголовок страницы и имя экрана (Page Title and Screen Name), заголовок страницы и класс экрана (Page Title and Screen Class), путь страницы и класс экрана (Page Path and Screen Class)
- [ ] Пользователь может выбрать начальную точку (Starting Point) — страницу или событие
- [ ] Пользователь может выбрать конечную точку (Ending Point) — страницу или событие
- [ ] Прямой путь (Forward Path): анализ действий от начальной точки вперёд
- [ ] Обратный путь (Reverse Path): анализ действий, приведших к конечной точке
- [ ] Числа в каждом узле показывают общее количество пользователей или событий
- [ ] Пользователь может разворачивать и сворачивать ветви графа
- [ ] Система выявляет зацикливания (looping behavior), когда пользователи повторяют одни и те же действия

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-023 | Исследование пути может иметь ЛИБО начальную точку, ЛИБО конечную точку, но не обе одновременно |
| BR-024 | Зацикливания указывают на потенциальные проблемы навигации, где пользователи "застревают" |
| BR-025 | Тип узла определяет уровень детализации: Event Name для последовательности событий, Page Path для конкретных URL-адресов |

---

### FR-EXP-008: Пересечение сегментов (Segment Overlap)
**Priority**: P1-High

**Description**: Техника пересечения сегментов визуализирует до 3 сегментов в виде диаграммы Венна, позволяя увидеть пересечения и уникальные аудитории между сегментами.

**Acceptance Criteria**:
- [ ] Визуализация в виде диаграммы Венна
- [ ] Поддерживается сравнение от 1 до 3 сегментов одновременно
- [ ] При наведении на внутреннюю область сегмента или пересечения отображаются эксклюзивные числа
- [ ] При наведении на границу сегмента отображаются инклюзивные числа
- [ ] Под диаграммой Венна отображается таблица с разбивкой по измерениям (Breakdown)
- [ ] Пользователь может добавить метрики как значения в таблице
- [ ] Правый клик на пересечении позволяет создать новый сегмент ("Create segment from selection")

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-026 | Максимум 3 сегмента для визуализации в диаграмме Венна |
| BR-027 | Максимум 10 метрик в значениях таблицы пересечений |
| BR-028 | Пересечения позволяют выделять сложные аудитории по составным условиям |

---

### FR-EXP-009: Когортное исследование (Cohort Exploration)
**Priority**: P1-High

**Description**: Техника когортного исследования группирует пользователей по общему признаку (критерий включения) и анализирует, как эти группы ведут себя с течением времени (критерий возврата). Позволяет отслеживать удержание, повторные покупки и другие паттерны.

**Acceptance Criteria**:
- [ ] Пользователь определяет критерий включения в когорту (Cohort Inclusion Criteria)
- [ ] Доступные критерии включения: первое касание / дата привлечения (First Touch), любое событие (Any Event), любая транзакция (Any Transaction), любая конверсия (Any Conversion), конкретное событие
- [ ] Пользователь определяет критерий возврата (Return Criteria): любое событие, любая транзакция, любая конверсия, конкретное событие
- [ ] Пользователь выбирает гранулярность: ежедневно (Daily), еженедельно (Weekly), ежемесячно (Monthly)
- [ ] Пользователь выбирает тип расчёта: стандартный (Standard), скользящий (Rolling), кумулятивный (Cumulative)
- [ ] Данные отображаются в табличном формате, где строки — когорты, столбцы — временные периоды
- [ ] Каждая ячейка содержит значение метрики для данной когорты в данном периоде

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-029 | Гранулярность возврата совпадает с гранулярностью когорт |
| BR-030 | Ежедневно: от полуночи до полуночи в часовом поясе ресурса |
| BR-031 | Еженедельно: с воскресенья по субботу включительно (не скользящие 7 дней) |
| BR-032 | Ежемесячно: с начала календарного месяца |
| BR-033 | Стандартный расчёт: в каждой ячейке — пользователи когорты, выполнившие критерий возврата в конкретном периоде |
| BR-034 | Скользящий расчёт (Rolling): в каждой ячейке — пользователи, выполнявшие критерий возврата в КАЖДОМ периоде до текущего включительно |
| BR-035 | Кумулятивный расчёт (Cumulative): в каждой ячейке — пользователи, выполнившие критерий возврата В ЛЮБОМ периоде до текущего включительно |

### FR-EXP-010: Время жизни пользователя (User Lifetime)
**Priority**: P1-High

**Description**: Техника "Время жизни пользователя" показывает поведение пользователей за весь период их взаимодействия с сайтом или приложением. Использует предиктивные метрики на основе машинного обучения для прогнозирования будущих покупок, оттока и доходов.

**Acceptance Criteria**:
- [ ] Отображаются метрики за весь период жизни пользователя: LTV (Lifetime Value), продолжительность взаимодействия (Lifetime Engagement Duration), транзакции за время жизни (Lifetime Transactions), доход за время жизни (Lifetime Revenue)
- [ ] Поддерживаются предиктивные метрики: вероятность покупки (Purchase Probability), вероятность оттока (Churn Probability), прогнозируемый доход (Predicted Revenue)
- [ ] Метрики могут отображаться как: среднее значение (Average), сумма (Total), перцентили (10-й, 50-й, 80-й, 90-й)
- [ ] Данные можно разбить по измерениям привлечения: первый источник (First User Source), первый канал (First User Medium), первая кампания (First User Campaign)
- [ ] Данные агрегируются за весь период жизни пользователя от момента первого визита

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-036 | LTV рассчитывается как сумма стоимости всех событий, генерирующих доход (purchase, in_app_purchase, app_store_subscription_convert) для данного пользователя с момента привлечения |
| BR-037 | Вероятность покупки: вероятность того, что пользователь, активный за последние 28 дней, совершит покупку в следующие 7 дней |
| BR-038 | Вероятность оттока: вероятность того, что пользователь, активный за последние 28 дней, НЕ будет активен в следующие 7 дней |
| BR-039 | Прогнозируемый доход: ожидаемый доход за следующие 28 дней от пользователя, активного за предыдущие 28 дней |
| BR-040 | Для работы предиктивных метрик требуется минимум 1000 пользователей с покупками за 7-дневный период в последние 28 дней |
| BR-041 | Перцентили (10-й, 50-й, 80-й, 90-й) позволяют оценить распределение метрик и выявить выбросы |

---

### FR-EXP-011: Сегменты в исследованиях
**Priority**: P0-Critical

**Description**: Сегменты — это подмножества пользователей, сессий или событий, определяемые набором условий. Сегменты доступны только в модуле исследований и позволяют фильтровать и сравнивать данные.

**Acceptance Criteria**:
- [ ] Поддерживаются 3 типа сегментов: пользовательские (User Segments), сессионные (Session Segments), событийные (Event Segments)
- [ ] Пользовательский сегмент включает все данные пользователя (события и сессии), удовлетворяющего условиям
- [ ] Сессионный сегмент включает данные только из сессий, удовлетворяющих условиям
- [ ] Событийный сегмент включает только события, удовлетворяющие условиям
- [ ] Условия могут быть "включающими" (Include) и "исключающими" (Exclude)
- [ ] Исключение может быть временным ("Temporarily exclude users when") или постоянным ("Permanently exclude users when")
- [ ] Для пользовательских сегментов доступны последовательности (Sequences) — условия, которые происходят в определённом порядке
- [ ] Последовательности поддерживают временные ограничения (в днях, часах, минутах, секундах)
- [ ] При создании сегмента доступен флажок "Build an audience" для одновременного создания аудитории

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-042 | Область видимости (Scope) для пользовательского сегмента: "Across all sessions", "Within the same session", "Within the same event" |
| BR-043 | Область видимости для сессионного сегмента: "Within the same session", "Within the same event" |
| BR-044 | Область видимости для событийного сегмента: "Within the same event" |
| BR-045 | Последовательности (Sequences) доступны ТОЛЬКО в пользовательских сегментах |
| BR-046 | Сегменты являются ретроспективными — они применяются к уже собранным историческим данным |
| BR-047 | Аудитории, в отличие от сегментов, НЕ ретроспективны — они начинают накапливать данные только с момента создания |
| BR-048 | Максимум 10 сегментов на исследование |
| BR-049 | Условия внутри одной группы объединяются через AND; группы условий объединяются через OR |

### FR-EXP-012: Шеринг исследований
**Priority**: P1-High

**Description**: Пользователь может поделиться исследованием с другими пользователями ресурса. Расшаренное исследование доступно в режиме только для чтения.

**Acceptance Criteria**:
- [ ] Пользователь с ролью Analyst или выше может расшарить своё исследование
- [ ] При расшаривании исследование становится доступно всем пользователям ресурса (property)
- [ ] Расшаренное исследование доступно только для чтения (read-only)
- [ ] Другие пользователи могут создать копию (duplicate) расшаренного исследования для редактирования
- [ ] Зритель (Viewer) может просматривать расшаренные исследования, но не редактировать
- [ ] Пользователь может отменить шеринг исследования

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-050 | Если пользователь запрашивает результаты без сэмплирования для приватного исследования, оно автоматически становится расшаренным (shared) |
| BR-051 | Расшаренные исследования НЕ обновляются в реальном времени для других пользователей — изменения видны после обновления страницы |
| BR-052 | Максимум 500 расшаренных исследований на ресурс (стандартная лицензия) |
| BR-053 | Максимум 1000 расшаренных исследований на ресурс (GA4 360) |

## Состояния и статусы

### Состояния исследования

```
[Создание] → DRAFT (автосохранение)
     ↓
  PRIVATE ←→ SHARED
     ↓           ↓
  DELETED     DELETED
```

| Состояние | Описание |
|-----------|----------|
| PRIVATE | Исследование видимо только создателю; можно редактировать |
| SHARED | Исследование видимо всем пользователям ресурса; только создатель может редактировать; остальные — только чтение |
| DELETED | Исследование удалено; восстановление невозможно |

### Состояния загрузки данных

| Состояние | Описание |
|-----------|----------|
| LOADING | Данные загружаются для текущей визуализации |
| COMPLETE | Данные загружены полностью (без сэмплирования) |
| SAMPLED | Данные загружены с применением сэмплирования |
| UNSAMPLED_REQUESTED | Запрошены результаты без сэмплирования (GA4 360) |
| UNSAMPLED_READY | Результаты без сэмплирования готовы (GA4 360) |
| ERROR | Ошибка загрузки данных (слишком сложный запрос, превышение лимитов и т.д.) |

### Состояния сегмента

| Состояние | Описание |
|-----------|----------|
| DRAFT | Сегмент создаётся в конструкторе |
| ACTIVE | Сегмент сохранён и применён к исследованию |
| CONVERTED_TO_AUDIENCE | Сегмент преобразован в аудиторию GA4 |

## Интеграции с другими модулями

### Интеграция со стандартными отчётами (Reports)

| Аспект | Описание |
|--------|----------|
| Данные | Исследования используют те же данные о событиях, что и стандартные отчёты, но могут подвергаться сэмплированию |
| Хранение | Стандартные отчёты не ограничены настройкой data retention; исследования ограничены (2-14 месяцев или до 50 месяцев для 360) |
| Сегменты vs. Comparisons | Сегменты доступны ТОЛЬКО в исследованиях; в стандартных отчётах используются "Comparisons" |

### Интеграция с аудиториями (Audiences)

| Аспект | Описание |
|--------|----------|
| Создание | Сегменты, созданные в исследованиях, могут быть преобразованы в аудитории через флажок "Build an audience" |
| Ретроспективность | Сегменты ретроспективны (показывают исторические данные); аудитории — нет (накапливают с момента создания) |
| Использование | Аудитории могут использоваться в Google Ads для таргетинга и в стандартных отчётах как условия сравнения |
| Предиктивные аудитории | На основе предиктивных метрик (вероятность покупки, оттока, прогнозируемый доход) создаются автоматические шаблоны аудиторий |

### Интеграция с Google Ads

| Аспект | Описание |
|--------|----------|
| Аудитории | Аудитории, созданные из сегментов исследований, экспортируются в Google Ads для ремаркетинга |
| Данные рекламы | Данные о рекламных кампаниях Google Ads доступны как измерения и метрики в исследованиях |

### Интеграция с BigQuery

| Аспект | Описание |
|--------|----------|
| Экспорт данных | Данные событий GA4 могут экспортироваться в BigQuery для более глубокого анализа без ограничений сэмплирования |
| Дополнение | BigQuery позволяет обойти ограничения хранения данных и сэмплирования исследований |

### Интеграция с Looker Studio

| Аспект | Описание |
|--------|----------|
| Визуализация | Данные GA4, в том числе используемые в исследованиях, могут быть визуализированы в Looker Studio |
| Квоты API | Запросы из Looker Studio к GA4 Data API подвержены тем же квотам токенов, что и запросы исследований |

### Интеграция с предиктивными метриками (ML)

| Аспект | Описание |
|--------|----------|
| User Lifetime | Техника User Lifetime использует предиктивные метрики ML: Purchase Probability, Churn Probability, Predicted Revenue |
| Требования ML | Для работы предиктивных метрик требуется минимум 1000 покупателей за 7-дневный период в последние 28 дней и 1000 не-покупателей за тот же период |
| Обнаружение аномалий | Техника Free Form (линейная диаграмма) использует байесовскую модель временных рядов для выявления аномалий |

### Интеграция с настройками ресурса (Property Settings)

| Аспект | Описание |
|--------|----------|
| Data Retention | Настройка хранения данных (Admin > Data Settings > Data Retention) напрямую определяет максимальный временной диапазон исследований |
| Пользовательские измерения и метрики | Пользовательские измерения (custom dimensions) и метрики (custom metrics), созданные в настройках ресурса, доступны в исследованиях |
| Конверсии | События, помеченные как конверсии, доступны как критерии в когортах, воронках и сегментах |
| Ограничения данных | Ограничения на просмотр cost и revenue метрик, настроенные для ролей, применяются и в исследованиях |
