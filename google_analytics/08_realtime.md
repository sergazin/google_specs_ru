## Глоссарий

| Термин | Определение |
|--------|-------------|
| Realtime Report (Отчёт реального времени) | Отчёт GA4, отображающий активность пользователей на сайте или в приложении за последние 30 минут |
| Active User (Активный пользователь) | Пользователь, который совершил действие (просмотр страницы, событие) в рамках отслеживаемого окна времени (5 или 30 минут) |
| Card (Карточка) | Визуальный блок в отчёте реального времени, отображающий определённый срез данных (источники, страницы, события и т.д.) |
| Comparison (Сравнение) | Механизм сопоставления подмножеств данных бок о бок на основе условий по измерениям |
| User Snapshot (Снимок пользователя) | Режим просмотра активности случайно выбранного отдельного пользователя в реальном времени |
| DebugView (Режим отладки) | Специализированный инструмент для просмотра событий и свойств пользователя в реальном времени от устройств с включённым режимом отладки |
| Key Event (Ключевое событие) | Событие, отмеченное как особо важное для бизнеса (ранее называлось «конверсия» / Conversion) |
| Event Parameter (Параметр события) | Дополнительные данные, передаваемые вместе с событием (например, значение, валюта, название элемента) |
| User Property (Свойство пользователя) | Атрибут, описывающий сегмент пользователей (например, язык, страна, членство) |
| Debug Mode (Режим отладки) | Специальный режим отправки данных, при котором события направляются в DebugView для мониторинга |
| First User Source (Источник первого пользователя) | Источник трафика, через который пользователь впервые попал на сайт или в приложение |
| Audience (Аудитория) | Предопределённая или пользовательская группа пользователей, объединённых по характеристикам или поведению |
| Data Threshold (Порог данных) | Системное ограничение, скрывающее данные для предотвращения идентификации отдельных пользователей по демографическим или иным сигналам |
| Seconds Stream (Поток секунд) | Центральная колонка DebugView, отображающая события за последние 60 секунд |
| Minutes Stream (Поток минут) | Левая колонка DebugView, отображающая архивы событий за каждую из 30 минут |

## Обзор модуля

Модуль «Реальное время» (Realtime) предоставляет мгновенный обзор текущей активности на сайте или в мобильном приложении. Данные обновляются с задержкой в несколько секунд и отображают взаимодействия за последние 30 минут.

Модуль состоит из двух основных компонентов:

1. **Отчёт Realtime** — интерактивная панель с карточками, отображающими агрегированные данные о текущих пользователях, источниках трафика, просмотренных страницах, событиях, ключевых событиях и географии.

2. **DebugView** — специализированный инструмент для отладки, показывающий поток отдельных событий от конкретного устройства с включённым режимом отладки, с возможностью детального просмотра параметров каждого события.

### Ключевые сценарии использования

- **Мониторинг запусков**: проверка работоспособности трекинга при запуске новой кампании, посадочной страницы или функции
- **Валидация тегов**: подтверждение корректности отправки событий, параметров и UTM-меток
- **Реакция на аномалии**: обнаружение неожиданных всплесков или падений трафика
- **Верификация конверсий**: проверка срабатывания ключевых событий при тестировании воронки
- **Отладка реализации**: поэтапная проверка передачи данных с устройства в аналитику через DebugView
- **Оперативная оптимизация**: корректировка рекламных ставок, сообщений или контента на основе данных в реальном времени

## Функциональные требования

### FR-RTM-001: Обзорная карточка активных пользователей

**Priority**: P0-Critical

**Description**: Система отображает количество активных пользователей на сайте или в приложении в двух временных окнах: за последние 5 минут и за последние 30 минут. Дополнительно отображается столбчатая гистограмма с количеством активных пользователей в каждую минуту за последние 30 минут.

**Acceptance Criteria**:
- [ ] Отображается общее число активных пользователей за последние 5 минут
- [ ] Отображается общее число активных пользователей за последние 30 минут
- [ ] Столбчатая гистограмма содержит 30 столбцов — по одному на каждую минуту
- [ ] Данные обновляются автоматически с задержкой в несколько секунд
- [ ] Счётчики пользователей обновляются без перезагрузки страницы
- [ ] При отсутствии активных пользователей отображается «0»

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-001 | Метрика «Active users» учитывает только обработанных (processed) пользователей. Новые пользователи и вернувшиеся пользователи, ещё не прошедшие пакетную обработку, могут не отображаться в счётчике |
| BR-RTM-002 | Подсчёт пользователей основан на уникальных идентификаторах (cookie / device ID / User-ID) и дедуплицируется в рамках окна наблюдения |
| BR-RTM-003 | Пользователь считается «активным», если от его устройства в указанный интервал поступило хотя бы одно событие |

---

### FR-RTM-002: Карточка источников трафика

**Priority**: P0-Critical

**Description**: Система отображает распределение активных пользователей по источникам трафика. По умолчанию отображается измерение «First user source» (Источник первого пользователя). Пользователь может переключить измерение на альтернативное.

**Acceptance Criteria**:
- [ ] Отображается таблица с источниками трафика и количеством активных пользователей для каждого источника
- [ ] По умолчанию используется измерение «First user source»
- [ ] Доступно переключение на измерения: First user medium, First user source / medium, First user source platform, First user campaign
- [ ] Переключение измерения происходит по нажатию на стрелку раскрытия в заголовке карточки
- [ ] Данные обновляются в реальном времени
- [ ] Источники ранжируются по убыванию количества активных пользователей

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-004 | Карточка источников отображает данные только для обработанных (processed) пользователей. Новые пользователи, не прошедшие пакетную обработку, не имеют данных по «First user source» и не отображаются в этой карточке |
| BR-RTM-005 | При наличии более 700 строк данных строки с наименьшим количеством пользователей объединяются в категорию «(other)» |
| BR-RTM-006 | UTM-параметры (utm_source, utm_medium, utm_campaign) являются основой для определения источника трафика |

---

### FR-RTM-003: Карточка аудиторий

**Priority**: P1-High

**Description**: Система отображает распределение активных пользователей (или новых пользователей) по аудиториям, которые были настроены в ресурсе GA4. Позволяет увидеть, к каким сегментам относятся текущие посетители.

**Acceptance Criteria**:
- [ ] Отображается таблица с аудиториями и количеством пользователей (активных или новых)
- [ ] По умолчанию отображаются «Active users by Audience»
- [ ] Доступно переключение на «New users by Audience»
- [ ] Отображаются только аудитории, настроенные в ресурсе GA4
- [ ] Если ни один текущий пользователь не входит ни в одну аудиторию, карточка пуста
- [ ] Аудитории ранжируются по убыванию количества пользователей

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-007 | Пользователь принадлежит аудитории, если он соответствует условиям аудитории на момент текущего сеанса |
| BR-RTM-008 | Один пользователь может одновременно входить в несколько аудиторий, поэтому суммарное количество в карточке может превышать общее число активных пользователей |
| BR-RTM-009 | Системные аудитории (All users, Purchasers и др.) отображаются наряду с пользовательскими |

---

### FR-RTM-004: Карточка страниц и экранов

**Priority**: P0-Critical

**Description**: Система отображает наиболее просматриваемые страницы (для веб-сайта) или экраны (для мобильного приложения) за последние 30 минут. Метрика — количество просмотров (views), а не уникальных пользователей.

**Acceptance Criteria**:
- [ ] Отображается таблица «Views by Page title and screen name» с заголовками страниц / экранов и количеством просмотров
- [ ] Просмотры считаются с повторами (один пользователь может генерировать несколько просмотров одной страницы)
- [ ] Страницы ранжируются по убыванию количества просмотров
- [ ] Отображается заголовок страницы (page_title), а не URL
- [ ] Для мобильных приложений отображается screen_name

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-010 | Метрика «Views» включает повторные просмотры одной страницы одним пользователем |
| BR-RTM-011 | Если страница не имеет заголовка (page_title пуст), отображается URL или «(not set)» |
| BR-RTM-012 | При наличии более 700 строк данных менее популярные страницы объединяются в категорию «(other)» |

---

### FR-RTM-005: Карточка событий

**Priority**: P0-Critical

**Description**: Система отображает количество срабатываний (event count) каждого типа события за последние 30 минут. Показывает, какие события чаще всего триггерятся текущими пользователями.

**Acceptance Criteria**:
- [ ] Отображается таблица «Event count by Event name» с названиями событий и их количеством
- [ ] Включены все типы событий: автоматические (page_view, session_start, first_visit), улучшенное измерение (scroll, click, file_download, video_start, video_progress, video_complete), рекомендованные и пользовательские
- [ ] События ранжируются по убыванию количества срабатываний
- [ ] Счётчик отражает общее количество срабатываний, а не количество уникальных пользователей

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-013 | Событие page_view генерируется автоматически при каждой загрузке страницы |
| BR-RTM-014 | Событие session_start генерируется при начале нового сеанса (30 минут бездействия или смена кампании) |
| BR-RTM-015 | При наличии более 700 строк данных менее частые события объединяются в категорию «(other)» |

---

### FR-RTM-006: Карточка ключевых событий (конверсий)

**Priority**: P0-Critical

**Description**: Система отображает количество срабатываний ключевых событий (Key events, ранее — Conversions) за последние 30 минут. Ключевыми считаются события, отмеченные администратором или редактором ресурса как особо важные для бизнеса.

**Acceptance Criteria**:
- [ ] Отображается таблица «Key events by Event name» с названиями ключевых событий и их количеством
- [ ] Отображаются только события, отмеченные как ключевые в настройках ресурса
- [ ] Если ключевые события не настроены, карточка пуста
- [ ] Если ключевые события настроены, но ни одно не сработало за последние 30 минут, отображается пустая таблица
- [ ] Счётчик отражает общее количество срабатываний ключевого события

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-016 | Событие становится ключевым только после включения соответствующей настройки в разделе Admin > Events > Mark as key event |
| BR-RTM-017 | Изменение статуса ключевого события вступает в силу для данных реального времени с момента сохранения настройки |
| BR-RTM-018 | Все автоматически собираемые, рекомендованные и пользовательские события могут быть отмечены как ключевые |

---

### FR-RTM-007: Географическая карта

**Priority**: P1-High

**Description**: Система отображает интерактивную карту мира с визуализацией распределения активных пользователей по географическому местоположению. Местоположение определяется на основе IP-адреса устройства пользователя.

**Acceptance Criteria**:
- [ ] Отображается карта мира с пузырьками (bubbles), размер которых пропорционален количеству пользователей в данном регионе
- [ ] При нажатии на пузырёк создаётся сравнение (Comparison) по соответствующему городу для всех карточек отчёта
- [ ] Местоположение определяется с точностью до города (при наличии данных IP-геолокации)
- [ ] Карта отображает данные за последние 30 минут
- [ ] Если пользователей нет, карта отображается без пузырьков

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-019 | Геолокация определяется по IP-адресу устройства; это местоположение использования, а не место проживания пользователя |
| BR-RTM-020 | Точность определения города зависит от качества маппинга IP-адресов в данном регионе |
| BR-RTM-021 | При использовании VPN или прокси отображается местоположение сервера, а не фактическое местоположение пользователя |
| BR-RTM-022 | Если ресурс не собирает гранулярные данные о местоположении (настройка отключена), карта может отображать только страну без детализации до города |

---

### FR-RTM-008: Снимок пользователя (User Snapshot)

**Priority**: P1-High

**Description**: Система предоставляет возможность просмотра детальной активности случайно выбранного отдельного пользователя, находящегося на сайте или в приложении прямо сейчас. Функция активируется кнопкой «View user snapshot» в верхней части отчёта Realtime.

**Acceptance Criteria**:
- [ ] Кнопка «View user snapshot» доступна в верхней правой части отчёта
- [ ] При нажатии отображается таймлайн действий случайно выбранного активного пользователя
- [ ] Таймлайн показывает последовательность событий с временными метками
- [ ] Отображается информация о пользователе: источник трафика, местоположение, устройство
- [ ] Справа отображаются карточки: топ-события пользователя и свойства пользователя (User Properties)
- [ ] Доступны стрелки навигации для переключения между случайными пользователями
- [ ] При нажатии на событие в таймлайне отображаются его параметры
- [ ] Таймлайн можно приостановить нажатием для детального изучения

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-023 | Пользователь для снимка выбирается случайно из числа текущих активных пользователей. Система не позволяет искать или выбирать конкретного пользователя |
| BR-RTM-024 | Случайный выбор обусловлен требованиями конфиденциальности: идентификация конкретного пользователя нарушает политику приватности |
| BR-RTM-025 | Навигация стрелками переключает на другого случайного пользователя, а не последовательно перебирает всех |
| BR-RTM-026 | Снимок пользователя показывает данные за текущий сеанс, а не за полные 30 минут |

### FR-RTM-009: Сравнения (Comparisons)

**Priority**: P1-High

**Description**: Система позволяет применять сравнения (Comparisons) к отчёту реального времени для сопоставления подмножеств данных бок о бок. Сравнения создаются на основе условий по измерениям и их значениям.

**Acceptance Criteria**:
- [ ] Кнопка «Add comparison» доступна в верхней части отчёта
- [ ] По умолчанию отображается сравнение «All Users»
- [ ] Пользователь может создать до 4 дополнительных сравнений (всего до 5, включая «All Users»)
- [ ] Каждое сравнение строится на основе условий включения (Include) или исключения (Exclude)
- [ ] Внутри одного сравнения можно задать до 5 условий
- [ ] Несколько условий внутри одного сравнения объединяются логикой AND
- [ ] При выборе одного измерения для условия можно указать несколько значений, объединяемых логикой OR
- [ ] Все карточки отчёта обновляются в соответствии с применёнными сравнениями
- [ ] Данные сравнений отображаются с цветовым кодированием
- [ ] Линейные графики отображают несколько линий (по одной на каждое сравнение)
- [ ] Таблицы и диаграммы показывают данные бок о бок

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-027 | Если карточка не поддерживает измерение, используемое в условии сравнения, для этого сравнения отображается пустая карточка |
| BR-RTM-028 | Пример условия: (Platform = Android OR iOS) AND (Country = Argentina OR Japan) |
| BR-RTM-029 | Сравнения в Realtime работают по тому же принципу, что и в стандартных отчётах, но ограничены набором измерений, доступных в реальном времени |
| BR-RTM-030 | Сравнения являются временными и не сохраняются между сессиями работы с отчётом (если не использована функция сохранения сравнений) |
| BR-RTM-031 | Нажатие на пузырёк географической карты автоматически создаёт сравнение по выбранному городу |

### FR-RTM-010: DebugView (Отладка событий)

**Priority**: P0-Critical

**Description**: DebugView — специализированный инструмент, расположенный в разделе Admin > Data display > DebugView. Отображает события и свойства пользователя, собираемые GA4 с устройства, на котором включён режим отладки. Данные отображаются в реальном времени с детализацией до отдельных событий с параметрами.

**Acceptance Criteria**:
- [ ] DebugView доступен через Admin > Data display > DebugView
- [ ] Интерфейс состоит из трёх колонок: поток минут (слева), поток секунд (по центру), панель событий и свойств (справа)
- [ ] Отображаются только данные от устройств с включённым режимом отладки (debug_mode)
- [ ] Данные DebugView НЕ включаются в стандартные отчёты GA4
- [ ] Данные отображаются за последние 30 минут
- [ ] Цветовое кодирование: синие значки = события, зелёные значки = ключевые события (конверсии), оранжевые значки = свойства пользователя

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-032 | Данные DebugView полностью изолированы от стандартной отчётности GA4 |
| BR-RTM-033 | Передача данных может иметь задержку в несколько минут, особенно для мобильных приложений, где данные батчируются |
| BR-RTM-034 | Фильтры внутреннего трафика (Internal Traffic) могут блокировать отображение данных в DebugView; при необходимости следует использовать VPN или исключения |

- [ ] При нажатии на событие отображаются его параметры (ключ-значение)

- [ ] Поток можно приостановить нажатием на белую область фона

- [ ] Возобновление потока происходит при повторном нажатии

**Business Rules**:

### FR-RTM-012: Поток минут DebugView

- [ ] Внутри каждого круга отображается число событий за эту минуту
- [ ] При нажатии на круг поток секунд (центральная колонка) фильтруется и показывает события именно за эту выбранную минуту
- [ ] Самая последняя минута выделена визуально
- [ ] Круги без событий отображаются пустыми или с нулём

**Business Rules**:
| Rule | Description |

### FR-RTM-013: Панель событий и свойств DebugView

**Priority**: P1-High

**Description**: Правая колонка DebugView содержит две секции: «Top Events» (наиболее частые события за 30 минут) и «User Properties» (текущее состояние свойств пользователя для выбранного устройства).

**Acceptance Criteria**:
- [ ] Секция «Top Events» отображает список наиболее часто логируемых событий за 30 минут
- [ ] При выборе события в секции «Top Events» отображаются его параметры и изменение значений во времени
- [ ] Секция «User Properties» отображает текущее состояние свойств пользователя уровня пользователя
- [ ] У свойств пользователя есть значок часов, при нажатии на который отображается история изменений свойства за 30-минутное окно
- [ ] Конверсионные (ключевые) события выделены зелёным цветом в списке Top Events

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-039 | User Properties отображают последнее известное значение свойства на момент текущего просмотра |
| BR-RTM-040 | История изменений User Properties доступна только за последние 30 минут отладочной сессии |

### FR-RTM-014: Выбор устройства DebugView

**Priority**: P1-High

**Description**: Если режим отладки включён на нескольких устройствах одновременно, DebugView предоставляет селектор устройств для выбора, от какого устройства просматривать данные.

**Acceptance Criteria**:
- [ ] Селектор устройства расположен в верхней левой части DebugView, обозначен как «DEBUG DEVICE»
- [ ] Отображается список всех устройств, которые сейчас отправляют данные с debug_mode
- [ ] При выборе устройства все три колонки обновляются данными этого устройства
- [ ] Каждое устройство идентифицируется уникальным идентификатором
- [ ] Если активно только одно устройство, селектор отображает его без выбора

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-041 | Несколько разработчиков могут одновременно использовать DebugView, каждый выбрав своё устройство, без взаимного влияния |
| BR-RTM-042 | Устройство появляется в селекторе только после поступления хотя бы одного события с debug_mode от этого устройства |
| BR-RTM-043 | После отключения debug_mode на устройстве оно остаётся в селекторе с ранее собранными данными до истечения 30-минутного окна |

### FR-RTM-015: Активация режима отладки

**Priority**: P1-High

**Description**: Для отправки данных в DebugView необходимо активировать режим отладки на устройстве. Существует три метода активации, каждый из которых применим к разным сценариям.

**Acceptance Criteria**:
- [ ] Метод 1: Использование расширения Google Analytics Debugger для Chrome — автоматически добавляет параметр `_dbg` ко всем запросам GA4
- [ ] Метод 2: Использование режима предварительного просмотра Google Tag Manager (GTM Preview Mode) — автоматически включает отладку без дополнительной конфигурации
- [ ] Метод 3: Ручное добавление параметра `debug_mode: true` в конфигурацию Google Tag или конкретного тега событий
- [ ] После активации режима отладки данные начинают поступать в DebugView в течение нескольких секунд (для веб) или минут (для мобильных приложений)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RTM-044 | Любое значение параметра debug_mode (включая строку "false") активирует режим отладки. Для отключения необходимо полностью удалить параметр или оставить его значение неопределённым (undefined) |
| BR-RTM-045 | GTM Preview Mode является наиболее удобным методом для тестирования тегов, поскольку не требует дополнительных настроек |
| BR-RTM-046 | Расширение Chrome GA Debugger влияет на все GA4-запросы в браузере, поэтому его следует отключать после завершения отладки |
| BR-RTM-047 | Для мобильных приложений (iOS/Android) режим отладки активируется через консольные команды (adb для Android, Xcode для iOS) или через флаг в Firebase SDK |

## Состояния и статусы

### Состояния отчёта Realtime

```
[Загрузка] → [Активен (данные поступают)] → [Пустой (нет активных пользователей)]
                     ↓                              ↓
              [Со сравнениями]              [Со сравнениями (пусто)]
                     ↓
              [User Snapshot]
```

| Состояние | Описание |
|-----------|----------|
| Загрузка | Начальная загрузка данных при открытии отчёта |
| Активен | Данные поступают; карточки отображают текущую активность |
| Пустой | Нет активных пользователей за последние 30 минут; все счётчики = 0 |
| Со сравнениями | Применено одно или несколько сравнений; карточки отображают данные с цветовым кодированием |
| User Snapshot | Активирован режим снимка пользователя; отображается таймлайн случайного пользователя |

### Состояния DebugView

```
[Ожидание устройства] → [Приём данных] → [Пауза (пользователь приостановил)]
                                ↓
                   [Просмотр архива (выбрана минута)]
```

| Состояние | Описание |
|-----------|----------|
| Ожидание устройства | DebugView открыт, но нет устройств с включённым debug_mode |
| Приём данных | События поступают от выбранного устройства в реальном времени |
| Пауза | Пользователь приостановил поток секунд для детального изучения событий |
| Просмотр архива | Пользователь выбрал конкретную минуту в потоке минут для просмотра архивных событий |

### Жизненный цикл события в DebugView

```
[Событие на устройстве] → [Отправка с debug_mode] → [Появление в потоке секунд]
                                                            ↓
                                              [Архивация в поток минут (через 60 сек)]
                                                            ↓
                                              [Удаление (через 30 минут)]
```

## Бизнес-правила

### Общие правила модуля Realtime

| Правило | Описание |
|---------|----------|
| BR-RTM-048 | Окно наблюдения фиксировано на 30 минут и не может быть расширено или сужено пользователем |
| BR-RTM-049 | Данные обновляются автоматически; ручного обновления не требуется |
| BR-RTM-050 | Отчёт Realtime не может быть загружен в форматах PDF, CSV или Google Sheets; доступен только шеринг по ссылке |
| BR-RTM-051 | Пользователь не может редактировать карточки (добавлять, удалять, менять порядок); набор карточек фиксирован |
| BR-RTM-052 | Переключение измерений возможно только в карточках, где эта функция предусмотрена (источники, аудитории) |
| BR-RTM-053 | Данные реального времени могут незначительно отличаться от данных стандартных отчётов из-за различий в обработке (batch processing, сэмплирование, атрибуция) |
| BR-RTM-054 | Для мобильных приложений данные могут поступать с задержкой, так как Firebase SDK батчирует события перед отправкой |

### Правила обработки данных

| Правило | Описание |
|---------|----------|
| BR-RTM-055 | Порог данных (Data Threshold) может применяться к данным реального времени, если включены демографические или аудиторные измерения, которые позволяют идентифицировать отдельного пользователя |
| BR-RTM-056 | При применении порога данных соответствующие строки скрываются; пользователь видит предупреждение о применении порога |
| BR-RTM-057 | Пороги данных устанавливаются системой и не подлежат настройке пользователем |
| BR-RTM-058 | Новые пользователи, ещё не прошедшие пакетную обработку, могут отображаться в общем счётчике пользователей, но отсутствовать в карточках, требующих обработанных атрибутов (First user source) |

### Правила DebugView

| Правило | Описание |
|---------|----------|
| BR-RTM-059 | Данные DebugView полностью отделены от стандартной отчётности и не влияют на основные метрики |
| BR-RTM-060 | Одновременно можно отлаживать данные только от одного устройства в рамках одного окна DebugView |
| BR-RTM-061 | Несколько пользователей GA4 могут одновременно использовать DebugView, выбирая разные устройства |
| BR-RTM-062 | Значение "false" в параметре debug_mode активирует DebugView (поскольку любое определённое значение включает режим отладки) |

## Ограничения и лимиты

### Ограничения отчёта Realtime

| Параметр | Ограничение |
|----------|-------------|
| Окно данных | Фиксировано: 30 минут. Невозможно расширить или сузить |
| Окно «Users in last 5 minutes» | Фиксировано: 5 минут |
| Максимум строк в карточке | 700 строк; остальные агрегируются в «(other)» |
| Количество одновременных сравнений | До 5 (включая «All Users») |
| Условий в одном сравнении | До 5 условий |
| Кастомизация карточек | Невозможна: нельзя добавлять, удалять, перемещать карточки |
| Экспорт данных | Не поддерживается (нет PDF, CSV, Sheets) |
| Сохранение фильтров/сравнений | Сравнения могут быть временными (сбрасываются при перезагрузке) |

### Ограничения DebugView

| Параметр | Ограничение |
|----------|-------------|
| Окно данных | 30 минут |
| Поток секунд | Последние 60 секунд в реальном времени |
| Одновременный просмотр | Одно устройство за раз в одном окне |
| Влияние на отчёты | Данные DebugView НЕ попадают в стандартные отчёты |
| Задержка данных (веб) | Несколько секунд |
| Задержка данных (мобильные) | До нескольких минут (из-за батчинга) |
| Фильтры внутреннего трафика | Могут блокировать данные в DebugView |

### Ограничения данных

| Параметр | Ограничение |
|----------|-------------|
| Порог данных | Применяется системой автоматически; не настраивается |
| Точность подсчёта пользователей | Новые/необработанные пользователи могут не учитываться в некоторых карточках |
| Точность геолокации | Зависит от качества маппинга IP-адресов; VPN искажает данные |
| Кросс-платформенные пользователи | Пользователь на разных устройствах может учитываться как несколько активных пользователей, если не настроен User-ID |

## Интеграции с другими модулями

### Входящие зависимости (от других модулей к Realtime)

| Модуль | Описание интеграции |
|--------|---------------------|
| Сбор данных (Data Collection) | Отчёт Realtime получает потоковые данные о событиях, собираемых через Google Tag, GTM, gtag.js, Firebase SDK. Без корректно настроенного сбора данных отчёт будет пустым |
| Потоки данных (Data Streams) | Realtime отображает данные со всех активных потоков (веб-сайты, iOS-приложения, Android-приложения), настроенных в ресурсе GA4 |
| События (Events) | Все события (автоматические, enhanced measurement, рекомендованные, пользовательские) отображаются в карточке событий Realtime |
| Ключевые события (Key Events / Conversions) | Карточка конверсий Realtime отображает только события, отмеченные как ключевые в настройках модуля событий |
| Аудитории (Audiences) | Карточка аудиторий Realtime отображает аудитории, созданные и настроенные в модуле управления аудиториями |
| Пользовательские измерения (Custom Dimensions) | Пользовательские измерения, зарегистрированные в ресурсе, могут использоваться в условиях сравнений Realtime |
| Управление доступом (Access Management) | Роли и разрешения определяют, какие пользователи могут просматривать отчёт и настраивать конфигурацию |

### Исходящие зависимости (от Realtime к другим модулям)

| Модуль | Описание интеграции |
|--------|---------------------|
| Стандартные отчёты (Reports) | Данные, отображаемые в Realtime, после обработки попадают в стандартные отчёты GA4 (с задержкой от нескольких часов до 48 часов) |
| Исследования (Explorations) | Данные реального времени недоступны в модуле Explorations; Explorations работают только с обработанными данными |
| BigQuery Export | Данные реального времени экспортируются в BigQuery в виде потокового экспорта (streaming export), если настроена интеграция |
| Google Ads | Данные о конверсиях, зафиксированных в реальном времени, после обработки передаются в Google Ads для оптимизации ставок |

### Связь Realtime и DebugView

| Аспект | Realtime Report | DebugView |
|--------|-----------------|-----------|
| Назначение | Мониторинг агрегированной активности всех пользователей | Отладка данных от конкретного устройства |
| Гранулярность | Агрегат по карточкам | Индивидуальные события с параметрами |
| Источник данных | Все пользователи (без debug_mode) | Только устройства с debug_mode |
| Влияние на стандартные отчёты | Данные попадают в стандартные отчёты | Данные НЕ попадают в стандартные отчёты |
| Расположение | Reports > Realtime | Admin > Data display > DebugView |
| Экспорт | Только ссылка | Не поддерживается |
