# Отчёты и дашборды — Google Analytics (GA4)

## 1. Описание модуля

Модуль "Отчёты и дашборды" является центральным элементом Google Analytics 4, обеспечивающим полный цикл анализа данных о пользователях, их поведении и монетизации. Модуль объединяет стандартные (предустановленные) отчёты, пользовательские отчёты, отчёты в реальном времени, расширенные исследования (Explorations) и рекламные отчёты (Advertising). Все отчёты строятся на событийной модели данных (event-based), где каждое взаимодействие пользователя с сайтом или приложением фиксируется как событие с набором параметров.

Модуль предоставляет инструменты кастомизации навигации, редактирования отчётов, фильтрации, сравнений, экспорта данных и планирования автоматической рассылки отчётов. Интегрируется с Looker Studio, BigQuery, Google Ads и другими продуктами Google для расширенной аналитики.

## 2. Роли пользователей

### 2.1 Администратор (Administrator)

| Возможность | Описание |
|-------------|----------|
| Полный доступ к отчётам | Просмотр всех стандартных, кастомных и рекламных отчётов |
| Редактирование отчётов | Создание, изменение, удаление кастомных отчётов |
| Управление библиотекой | Создание и редактирование коллекций, топиков, навигации |
| Планирование рассылок | Создание и управление расписанием отправки отчётов по email |
| Управление исследованиями | Полный доступ к Explorations |
| Экспорт данных | Все форматы экспорта без ограничений |

### 2.2 Редактор (Editor)

| Возможность | Описание |
|-------------|----------|
| Полный доступ к отчётам | Просмотр всех стандартных, кастомных и рекламных отчётов |
| Редактирование отчётов | Создание, изменение, удаление кастомных отчётов |
| Управление библиотекой | Создание и редактирование коллекций, топиков, навигации |
| Управление исследованиями | Полный доступ к Explorations |
| Экспорт данных | Все форматы экспорта без ограничений |
| Ограничение | Не может управлять расписанием email-рассылок (только Administrator) |

### 2.3 Аналитик (Analyst)

| Возможность | Описание |
|-------------|----------|
| Просмотр отчётов | Чтение всех опубликованных стандартных и кастомных отчётов |
| Исследования | Создание и редактирование собственных Explorations |
| Экспорт данных | Экспорт доступных отчётов |
| Ограничение | Не может редактировать стандартные отчёты и навигацию |

### 2.4 Просмотрщик (Viewer)

| Возможность | Описание |
|-------------|----------|
| Просмотр отчётов | Чтение опубликованных отчётов в левой навигации |
| Ограниченные исследования | Просмотр только расшаренных Explorations |
| Экспорт данных | Ограниченный экспорт (скачивание доступных отчётов) |
| Ограничение | Не может создавать, редактировать отчёты и исследования |

## 3. Функциональные требования

### 3.1 Стандартные отчёты (Standard Reports)

---

#### FR-RPT-001: Снимок отчётов (Reports Snapshot)

**Priority**: P0-Critical

**Description**: Главный обзорный экран модуля "Отчёты", представляющий сводную информацию о ключевых метриках ресурса в виде карточек (summary cards). Отображается первым при переходе в раздел "Reports" в левой навигации.

**Acceptance Criteria**:
- [ ] Отображается набор карточек с ключевыми метриками: пользователи, новые пользователи, среднее время вовлечения, общий доход
- [ ] Каждая карточка содержит одно или несколько измерений (dimensions), одну или несколько метрик и визуализацию (линейный график, столбчатая диаграмма, таблица)
- [ ] Каждая карточка содержит ссылку на детальный отчёт в правом нижнем углу
- [ ] Администратор или редактор может кастомизировать состав карточек (добавлять, удалять, переупорядочивать)
- [ ] Снимок отчётов поддерживает от 1 до 16 карточек
- [ ] Доступен выбор диапазона дат в правом верхнем углу
- [ ] Поддерживаются сравнения (Comparisons) — до 5 одновременно
- [ ] Карточки можно создавать на основе шаблонов (Reports Snapshot Templates)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-001 | Снимок отчётов является обзорным отчётом (Overview report) и не может содержать таблицу с детальными данными |
| BR-002 | Кастомизация снимка доступна только ролям Administrator и Editor |
| BR-003 | Максимум 16 карточек на один снимок отчётов |
| BR-004 | Шаблоны снимка зависят от типа ресурса (веб-сайт, приложение, веб + приложение) |

---

#### FR-RPT-002: Отчёт в реальном времени (Realtime Report)

**Priority**: P0-Critical

**Description**: Отчёт, показывающий активность пользователей на сайте или в приложении в текущий момент времени (последние 30 минут). Позволяет отслеживать мгновенную реакцию на запуск кампаний, публикацию контента, технические проблемы.

**Acceptance Criteria**:
- [ ] Отображает количество активных пользователей за последние 30 минут
- [ ] Карточка "Users in last 30 minutes" с графиком посекундной/поминутной активности
- [ ] Карточка "Users by First user source" — распределение активных пользователей по источникам первого привлечения
- [ ] Карточка "Users by Audience" — распределение по аудиториям
- [ ] Карточка "Views by Page title and screen name" — самые просматриваемые страницы/экраны
- [ ] Карточка "Event count by Event name" — количество событий по названиям
- [ ] Карточка "Conversions by Event name" — ключевые события (конверсии) за период
- [ ] Карточка "Users by Country/City" — географическое распределение на карте
- [ ] Карточка "Users by Device category" — распределение по устройствам (desktop, mobile, tablet)
- [ ] Данные обновляются автоматически без перезагрузки страницы
- [ ] Поддержка сравнений (Comparisons)
- [ ] Функция "View user snapshot" — просмотр последовательности событий конкретного анонимного пользователя в реальном времени

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-005 | Данные в Realtime отчёте обновляются каждые несколько секунд |
| BR-006 | Realtime отчёт показывает данные за последние 30 минут |
| BR-007 | Карточки Realtime отчёта не подлежат редактированию (состав карточек фиксирован) |
| BR-008 | Максимум 700 строк отображается в таблицах Realtime отчёта; высококардинальные значения агрегируются в "(other)" |
| BR-009 | Realtime отчёт использует user-scoped измерения и метрики |

#### FR-RPT-003: Отчёты по привлечению (Acquisition Reports)

**Priority**: P0-Critical

**Description**: Группа отчётов, показывающих откуда приходят пользователи и как они попадают на сайт или в приложение. Включает обзорный отчёт и два детальных отчёта.

**Acceptance Criteria**:
- [ ] **Acquisition Overview** — обзорный отчёт с карточками: новые пользователи по каналам, сессии по источникам/каналам, Google Ads-кампании, новые пользователи по каналам за период
- [ ] **User Acquisition** — детальный отчёт о привлечении новых пользователей (First user source, First user medium, First user campaign, First user default channel group, First user source / medium, First user source platform, First user Google Ads campaign)
- [ ] **Traffic Acquisition** — детальный отчёт о привлечении трафика (сессий) по источникам (Session source, Session medium, Session campaign, Session default channel group, Session source / medium, Session source platform, Session Google Ads campaign)
- [ ] Каждый детальный отчёт содержит таблицу с метриками: Users, Sessions, Engaged sessions, Average engagement time per session, Engaged sessions per user, Events per session, Engagement rate, Event count, Conversions, Total revenue
- [ ] Переключение измерений через выпадающий список (dimension picker) в левом верхнем углу таблицы
- [ ] Поддержка вторичного измерения (secondary dimension) — одно дополнительное измерение
- [ ] Графики: линейный график и столбчатая диаграмма над таблицей

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-010 | User Acquisition атрибутирует весь трафик пользователя к первому источнику (first touch) |
| BR-011 | Traffic Acquisition атрибутирует трафик к последнему непрямому источнику (last non-direct click) |
| BR-012 | Для атрибуции ключевых событий (конверсий) применяется модель атрибуции, выбранная в настройках ресурса (по умолчанию — data-driven) |
| BR-013 | Канал "(Direct)" включает трафик без определённого источника (прямые переходы, закладки, неразмеченные ссылки) |
| BR-014 | Группировка каналов по умолчанию: Organic Search, Paid Search, Direct, Referral, Organic Social, Paid Social, Email, Display, Affiliates, Audio, SMS, Mobile Push Notifications, Video, Cross-network |

---

#### FR-RPT-004: Отчёты по вовлечению (Engagement Reports)

**Priority**: P0-Critical

**Description**: Группа отчётов, показывающих как пользователи взаимодействуют с контентом сайта или приложения. Включает обзорный отчёт и несколько детальных отчётов.

**Acceptance Criteria**:
- [ ] **Engagement Overview** — обзорный отчёт с карточками: среднее время вовлечения, вовлечённые сессии, среднее время вовлечения на сессию, события, конверсии/ключевые события, просмотры по страницам/экранам
- [ ] **Events** — детальный отчёт по событиям. Таблица со всеми событиями (event_name), метриками: Event count, Total users, Event count per user, Total revenue
- [ ] **Conversions / Key events** — детальный отчёт по ключевым событиям (конверсиям). Отображает только события, помеченные как ключевые (key events)
- [ ] **Pages and screens** — детальный отчёт по страницам (для веб) и экранам (для приложений). Таблица с метриками: Views, Users, Views per user, Average engagement time, Event count, Conversions, Total revenue
- [ ] **Landing pages** — детальный отчёт по страницам входа. Показывает первую страницу, на которую попал пользователь в рамках сессии
- [ ] Каждый детальный отчёт поддерживает переключение измерений, вторичное измерение, фильтры и сравнения

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-015 | Событие считается "вовлечённой сессией" (engaged session), если сессия длится более 10 секунд, содержит ключевое событие или содержит 2+ просмотра страниц/экранов |
| BR-016 | Порог вовлечённой сессии (10 секунд) настраивается администратором в настройках потока данных |
| BR-017 | Engagement rate = Engaged sessions / Total sessions |
| BR-018 | "Pages and screens" объединяет веб-страницы (page_title, page_location) и экраны приложений (screen_name, screen_class) |
| BR-019 | Landing page определяется автоматически как первое событие page_view в рамках сессии |

#### FR-RPT-005: Отчёты по монетизации (Monetization Reports)

**Priority**: P1-High

**Description**: Группа отчётов, показывающих доход от электронной коммерции, покупок в приложениях, рекламы и подписок.

**Acceptance Criteria**:
- [ ] **Monetization Overview** — обзорный отчёт с карточками: общий доход, доход от электронной коммерции, доход от рекламы, доход от покупок в приложении, покупатели, среднее количество покупок на пользователя
- [ ] **E-commerce purchases** — детальный отчёт по покупкам. Таблица: Item name, Item views, Add-to-carts, Cart-to-view rate, E-commerce purchases, Purchase-to-view rate, Item purchase quantity, Item revenue
- [ ] **In-app purchases** — детальный отчёт по покупкам внутри приложения. Таблица: Product ID, количество, доход
- [ ] **Publisher ads** — детальный отчёт по доходу от рекламы (для приложений с AdMob). Таблица: Ad unit, Ad source, доход от рекламы, показы рекламы, клики по рекламе
- [ ] Переключение измерений: Item name, Item brand, Item category (до 5 уровней), Item ID, Item affiliation
- [ ] Поддержка фильтрации по конкретным товарам, брендам, категориям

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-020 | Данные по e-commerce доступны только при корректной настройке отправки событий e-commerce (purchase, add_to_cart, view_item и т.д.) |
| BR-021 | Доход от рекламы (Publisher ads) доступен при интеграции с AdMob или Ad Manager |
| BR-022 | Total revenue = E-commerce revenue + In-app purchase revenue + Ad revenue + Subscription revenue |
| BR-023 | Возвраты (refunds) вычитаются из дохода автоматически при получении соответствующего события refund |

#### FR-RPT-006: Отчёт по удержанию (Retention Report)

**Priority**: P1-High

**Description**: Отчёт, показывающий способность сайта или приложения удерживать пользователей после первого визита. Отображает когорты пользователей и их возвращаемость.

**Acceptance Criteria**:
- [ ] **Retention Overview** — обзорный отчёт с карточками:
  - Новые и вернувшиеся пользователи (New vs Returning users) — линейный график
  - Удержание пользователей по когортам (User retention by cohort) — процент пользователей, вернувшихся в день N после первого визита (до 42 дней)
  - Вовлечение пользователей по когортам (User engagement by cohort) — среднее время вовлечения по когортам
  - Lifetime Value (LTV) — совокупный доход от когорты пользователей с момента привлечения
- [ ] Визуализация: кривая удержания (retention curve) с днями 0-42
- [ ] Сравнение периодов для оценки динамики удержания

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-024 | Удержание рассчитывается на основе когорт — группировки пользователей по дате первого визита |
| BR-025 | Период анализа удержания — до 42 дней с момента первого визита |
| BR-026 | "Вернувшийся пользователь" — пользователь, который совершил хотя бы одну вовлечённую сессию после дня 0 |
| BR-027 | LTV доступен при наличии данных о доходе (e-commerce, in-app purchases, subscriptions) |

---

#### FR-RPT-007: Отчёты по демографии и технологиям (User Reports)

**Priority**: P1-High

**Description**: Группа отчётов, показывающих характеристики аудитории: демографические данные и используемые технологии.

**Acceptance Criteria**:
- [ ] **Demographics Overview** — обзорный отчёт: пользователи по странам (карта), городам, полу, возрастным группам, интересам, языкам
- [ ] **Demographics details** — детальный отчёт с таблицей: Country, City, Gender, Age, Interests, Language. Метрики: Users, New users, Engaged sessions, Engagement rate, Engaged sessions per user, Average engagement time, Event count, Conversions, Total revenue
- [ ] **Tech Overview** — обзорный отчёт: пользователи по платформе (Web, iOS, Android), операционным системам, браузерам, категориям устройств, разрешениям экрана
- [ ] **Tech details** — детальный отчёт с таблицей: Browser, Device category, Device model, Screen resolution, Operating system, OS version, Platform, App version. Метрики: Users, New users, Engaged sessions, Engagement rate, Engaged sessions per user, Average engagement time, Event count, Conversions, Total revenue

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-028 | Демографические данные (пол, возраст, интересы) доступны только при включении сигналов Google (Google Signals) |
| BR-029 | При малом объёме данных демографические данные могут быть скрыты (data thresholding) для защиты конфиденциальности пользователей |
| BR-030 | Пороги конфиденциальности (thresholding) применяются автоматически — GA4 не показывает данные, если размер сегмента позволяет идентифицировать конкретного пользователя |
| BR-031 | Возрастные группы: 18-24, 25-34, 35-44, 45-54, 55-64, 65+ |

### 3.2 Рекламные отчёты (Advertising Reports)

---

#### FR-RPT-008: Обзор рекламы (Advertising Snapshot)

**Priority**: P1-High

**Description**: Обзорный отчёт рекламного раздела, отображающий сводку по рекламным каналам и атрибуции конверсий.

**Acceptance Criteria**:
- [ ] Карточки: каналы, приносящие конверсии; модель атрибуции; данные Google Ads (при наличии связки)
- [ ] Информация о модели атрибуции, используемой для ключевых событий
- [ ] AI-инсайты — автоматически сгенерированные наблюдения о рекламной эффективности

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-032 | Рекламные отчёты требуют наличия хотя бы одного ключевого события (key event / conversion) |
| BR-033 | Полноценные данные Google Ads доступны при связывании аккаунтов GA4 и Google Ads |

---

#### FR-RPT-009: Пути атрибуции (Attribution Paths)

**Priority**: P1-High

**Description**: Отчёт, показывающий последовательность точек касания (touchpoints), которые привели к конверсии. Визуализирует путь пользователя от первого контакта до совершения ключевого события.

**Acceptance Criteria**:
- [ ] Визуализация цепочки точек касания (каналы, источники) в хронологическом порядке
- [ ] Фильтрация по конкретному ключевому событию
- [ ] Отображение ранних точек касания (early touchpoints), средних (mid touchpoints) и поздних (late touchpoints)
- [ ] Группировка по каналам, источникам, средам, кампаниям
- [ ] Количество дней между первым и последним касанием

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-034 | Путь атрибуции строится для каждого ключевого события отдельно |
| BR-035 | "(Direct)" включается в путь атрибуции, но может быть исключён при выборе модели "cross-channel non-direct last click" |
| BR-036 | При интеграции с Google Ads путь может включать показы, engaged views и другие типы взаимодействий |

---

#### FR-RPT-010: Сравнение моделей атрибуции (Model Comparison)

**Priority**: P2-Medium

**Description**: Отчёт, позволяющий сравнить распределение ценности конверсий между каналами по разным моделям атрибуции.

**Acceptance Criteria**:
- [ ] Доступные модели: Cross-channel data-driven, Cross-channel last click (non-direct), Ads-preferred last click
- [ ] Таблица сравнения: для каждого канала — количество конверсий и ценность конверсий по каждой модели
- [ ] Визуализация разницы между моделями
- [ ] Фильтрация по конкретным ключевым событиям

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-037 | Data-driven модель использует алгоритм машинного обучения Google для распределения ценности между точками касания |
| BR-038 | Cross-channel last click (non-direct) присваивает 100% ценности последнему непрямому каналу перед конверсией |
| BR-039 | Ads-preferred last click приоритизирует каналы Google Ads |
| BR-040 | Модель атрибуции для отчётов устанавливается в настройках ресурса (Admin > Attribution settings) |

### 3.3 Исследования (Explorations)

---

#### FR-RPT-011: Свободная форма (Free-form Exploration)

**Priority**: P0-Critical

**Description**: Наиболее гибкий тип исследования, позволяющий создавать произвольные отчёты с перетаскиванием измерений и метрик. Поддерживает шесть типов визуализации.

**Acceptance Criteria**:
- [ ] Типы визуализации: Таблица (Table), Кольцевая диаграмма (Donut chart), Линейный график (Line chart), Диаграмма рассеивания (Scatterplot), Столбчатая диаграмма (Bar chart), Гео-карта (Geo map)
- [ ] Панель "Variables" слева: добавление измерений (до 20), метрик (до 20), сегментов (до 10)
- [ ] Панель "Tab Settings": настройка текущей вкладки — перетаскивание измерений в строки/столбцы, метрик в значения
- [ ] Поддержка фильтров (до 10 на исследование)
- [ ] Поддержка сегментов (до 10 на исследование)
- [ ] Множественные вкладки (tabs) в одном исследовании

- [ ] Сортировка по любому столбцу
- [ ] Ограничение количества строк: 10, 25, 50, 100, 250, 500
- [ ] Cell type: обычное значение, тепловая карта (heat map), столбчатая диаграмма в ячейке (bar chart)

**Business Rules**:

| BR-043 | Максимум 10 фильтров на исследование |

#### FR-RPT-012: Воронка (Funnel Exploration)

**Priority**: P1-High

**Description**: Исследование, визуализирующее последовательные шаги пользователей через определённую воронку конверсии. Позволяет выявить этапы с наибольшим оттоком.

**Acceptance Criteria**:
- [ ] Настройка шагов воронки: до 10 шагов
- [ ] Каждый шаг определяется одним или несколькими событиями/условиями (с операторами AND/OR)
- [ ] Тип воронки: открытая (Open funnel) — пользователь может войти на любом шаге; закрытая (Closed funnel) — только с первого шага
- [ ] Визуализация: горизонтальная столбчатая диаграмма с процентами конверсии между шагами и общим процентом прохождения
- [ ] Показатель отсева (abandonment rate) на каждом шаге
- [ ] Сегментация воронки по измерениям (например, по устройствам, странам)
- [ ] Возможность задать временное ограничение между шагами (elapsed time)
- [ ] Breakdown — разбивка каждого шага по дополнительному измерению

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-046 | Максимум 10 шагов в воронке |
| BR-047 | Открытая воронка учитывает всех пользователей, совершивших шаг N, вне зависимости от прохождения предыдущих шагов |
| BR-048 | Закрытая воронка учитывает только пользователей, прошедших все предыдущие шаги в заданном порядке |
| BR-049 | Временные ограничения между шагами задаются в минутах, часах или днях |

**Business Rules**:

|------|-------------|

#### FR-RPT-021: Фильтры отчётов (Report Filters)

**Priority**: P0-Critical

**Description**: Механизм фильтрации данных в детальных отчётах, позволяющий ограничить выборку по условиям на основе измерений.

**Acceptance Criteria**:
- [ ] Фильтр в строке поиска над таблицей: быстрый текстовый поиск по строкам таблицы
- [ ] Расширенные фильтры (Add filter):
  - Выбор типа: Include (включить) или Exclude (исключить)
  - Выбор измерения из выпадающего списка
  - Выбор оператора совпадения: exact match (точное совпадение), contains (содержит), starts with (начинается с), ends with (заканчивается на), matches regex (регулярное выражение)
  - Выбор значений измерения
- [ ] До 5 условий в одном фильтре, объединённых оператором AND
- [ ] Фильтр можно сохранить как "Default filter" для отчёта (видим всем пользователям)
- [ ] Фильтры работают только в детальных отчётах (не в обзорных)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-073 | Все условия фильтра соединяются оператором AND (все условия должны быть выполнены одновременно) |
| BR-074 | Максимум 5 условий на один фильтр |
| BR-075 | Фильтры не применяются к обзорным отчётам |
| BR-076 | Сохранённый (default) фильтр применяется автоматически при открытии отчёта для всех пользователей |
| BR-077 | Пользователь может временно изменить или снять default filter без сохранения |

#### FR-RPT-022: Сравнения (Comparisons)

**Priority**: P0-Critical

**Description**: Механизм одновременного отображения нескольких сегментов данных на графиках и в таблицах отчётов. Аналог сегментов для стандартных отчётов.

**Acceptance Criteria**:
- [ ] Добавление сравнения через кнопку "Add comparison" или значок редактирования в верхней части отчёта
- [ ] Каждое сравнение определяется одним или несколькими условиями:
  - Включить/исключить (Include/Exclude)
  - Выбор измерения (Country, Device category, Platform, Gender, Age и т.д.)
  - Выбор значения измерения
- [ ] До 5 сравнений одновременно
- [ ] При применении сравнений: графики показывают отдельные линии/столбцы для каждого сравнения; таблица — строки дублируются для каждого сравнения с % изменений
- [ ] Сравнения работают в стандартных отчётах и Realtime отчёте
- [ ] Сравнения не заменяют сегменты в Explorations

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-078 | Максимум 5 сравнений одновременно |
| BR-079 | Сравнения основаны на измерениях (dimensions), а не на произвольных условиях |
| BR-080 | Сравнения отображаются для всего отчёта целиком (все карточки, графики, таблицы) |
| BR-081 | Сравнения доступны в стандартных и Realtime отчётах, но не в Explorations (там используются сегменты) |

#### FR-RPT-023: Диапазон дат (Date Range)

- [ ] Диапазон дат сохраняется при навигации между отчётами в рамках одной сессии

**Business Rules**:

| BR-085 | При сравнении периодов "Previous period" рассчитывается автоматически как период той же длительности непосредственно перед выбранным |

#### FR-RPT-032: Создание и применение сегментов

**Priority**: P1-High

**Description**: Сегменты — это группы пользователей, сессий или событий, определяемые пользователем для углублённого анализа в Explorations. Сегменты не доступны в стандартных отчётах (там используются Comparisons).

**Acceptance Criteria**:
- [ ] Три типа сегментов:
  - **User segment** — группа пользователей (например, пользователи из США, совершившие покупку)
  - **Session segment** — группа сессий (например, сессии из мобильных устройств)
  - **Event segment** — группа событий (например, все события purchase)
- [ ] Создание сегмента: определение условий через UI-конструктор
  - Условия на основе измерений, метрик, событий
  - Логические операторы: AND, OR
  - Операторы сравнения: equals, not equals, contains, starts with, ends with, matches regex, >, <, >=, <=, between
  - Условие включения/исключения
  - Временные условия: "within the same session", "within any X-day period"
- [ ] Применение сегмента к вкладке исследования: перетаскивание сегмента из панели Variables
- [ ] Шаблоны сегментов: предустановленные сегменты (Purchasers, Non-purchasers, Mobile users, Tablet users, и т.д.)
- [ ] Сегменты привязаны к конкретному исследованию

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-113 | Сегменты доступны только в Explorations, не в стандартных отчётах |
| BR-114 | Максимум 10 сегментов на одно исследование |
| BR-115 | Сегменты применяются в рамках текущей вкладки (tab) исследования |
| BR-116 | Шаблоны сегментов можно модифицировать после создания |
| BR-117 | Предиктивные сегменты (predictive audiences) могут использоваться в качестве условий сегментации |

### 3.10 Семплирование данных

#### FR-RPT-036: Семплирование и качество данных

**Priority**: P0-Critical

**Description**: Механизм семплирования данных в GA4 для обеспечения быстрого ответа при больших объёмах. Семплирование применяется в Explorations при превышении определённого порога событий.

**Acceptance Criteria**:
- [ ] Индикатор семплирования: зелёный щит (без семплирования), жёлтый щит (с семплированием) — отображается в правом верхнем углу отчёта/исследования
- [ ] Информация о проценте семплирования (какой процент данных использован)
- [ ] Возможность переключиться на "More detailed results" (медленнее, меньше семплирования) или "Faster results" (быстрее, больше семплирования)
- [ ] Стандартные отчёты не подвержены семплированию (используют агрегированные данные)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-126 | Семплирование применяется в Explorations при превышении 10 млн событий за выбранный период (стандартная GA4) |
| BR-127 | Стандартные отчёты не подвержены семплированию — они используют предварительно агрегированные данные |
| BR-128 | GA4 360 (платная версия): порог семплирования значительно выше (1 млрд событий), доступны несемплированные исследования (Unsampled explorations) |
| BR-129 | При семплировании GA4 экстраполирует данные на основе выборки — результаты являются приближёнными |
| BR-130 | BigQuery Export предоставляет доступ к сырым данным без семплирования и ограничений строк |

#### FR-RPT-037: Пороги данных (Data Thresholds)

**Priority**: P1-High

**Description**: Механизм защиты конфиденциальности, скрывающий данные при малых размерах выборки, которые могут позволить идентифицировать отдельных пользователей.

- [ ] Порог применяется к демографическим данным (возраст, пол, интересы) при включённых Google Signals
- [ ] Способы уменьшить влияние порогов: увеличить диапазон дат, уменьшить гранулярность, отключить Google Signals (если не нужны демографические данные)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-131 | Пороги срабатывают автоматически — пользователь не может их отключить |
| BR-132 | Пороги чаще всего затрагивают данные с включёнными Google Signals |
| BR-133 | Для снижения влияния порогов рекомендуется переключить идентификацию пользователей на "Device-based" вместо "Blended" |

## 5. Состояния и статусы

### 5.1 Статус коллекции

```
[Created] → [Unpublished] → [Published] → [Unpublished]
                                  ↓
                              [Deleted]
```

| Статус | Описание |
|--------|----------|
| Unpublished | Коллекция создана, но не отображается в навигации. Видна только в Library для Admin/Editor |
| Published | Коллекция отображается в левой навигации для всех пользователей ресурса |
| Deleted | Коллекция удалена. Отчёты, входившие в коллекцию, остаются в библиотеке |

### 5.2 Статус расписания рассылки

```
[Created] → [Active] → [Expired]
                ↓
            [Paused] → [Active]
                ↓
            [Deleted]
```

| Статус | Описание |
|--------|----------|
| Active | Расписание активно, отчёты отправляются по графику |
| Paused | Расписание приостановлено, отправка не происходит |
| Expired | Период активности истёк (прошло N месяцев) |
| Deleted | Расписание удалено |

### 5.3 Статус исследования (Exploration)

| Статус | Описание |
|--------|----------|
| Private | Исследование видно только создателю |
| Shared (Read-only) | Исследование видно всем пользователям ресурса в режиме чтения |
| Shared (Edit) | Исследование доступно для редактирования другим пользователям |
| Deleted | Исследование удалено |

### 5.4 Индикаторы качества данных

| Индикатор | Описание |
|-----------|----------|
| Зелёный щит | Данные без семплирования, полная выборка |
| Жёлтый щит | Данные подвержены семплированию, результаты приближённые |
| Значок порога | Часть данных скрыта из-за порогов конфиденциальности (thresholding) |
| Значок кардинальности | Присутствует строка "(other)" из-за высокой кардинальности измерения |

| Аспект | Описание |
|--------|----------|
| Рекламные данные | При связывании аккаунтов: данные кампаний, групп объявлений, ключевых слов доступны в отчётах Acquisition и Advertising |
