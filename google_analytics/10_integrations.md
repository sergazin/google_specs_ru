# Интеграции

## Описание

Модуль «Интеграции» Google Analytics 4 (GA4) обеспечивает двустороннюю связь ресурса GA4 с продуктами экосистемы Google и внешними источниками данных. Интеграции позволяют передавать данные об аудиториях, конверсиях, стоимости рекламы, событиях и пользователях между GA4 и связанными сервисами — Google Ads, Search Console, BigQuery, Firebase, Looker Studio, Google Tag Manager, Merchant Center, Display & Video 360, Search Ads 360, Google Ad Manager. Кроме того, модуль включает Measurement Protocol для серверной отправки событий и Data Import для загрузки данных из внешних источников (CSV / SFTP).

Основная цель модуля — создание единого аналитического пространства, объединяющего данные о поведении пользователей, рекламных затратах, доходах и бизнес-метриках для принятия решений на основе данных.

---

## Роли пользователей

| Роль | Возможности в контексте интеграций |
|------|-----------------------------------|
| **Администратор (Administrator)** | Создание, редактирование и удаление связей (product links) со всеми сервисами. Управление настройками BigQuery Export. Настройка Data Import. Управление Measurement Protocol API secrets. Полный доступ ко всем отчётам интеграций |
| **Редактор (Editor)** | Создание и редактирование связей с продуктами (кроме удаления). Настройка Data Import. Создание аудиторий для экспорта. Управление BigQuery Export. Доступ ко всем отчётам интеграций |
| **Аналитик (Analyst)** | Просмотр отчётов интеграций (Search Console, Google Ads, Ad Manager). Создание отчётов в Looker Studio. Нет доступа к созданию или изменению связей |
| **Просмотрщик (Viewer)** | Просмотр опубликованных отчётов интеграций. Нет доступа к настройке связей |

## Функциональные требования

### FR-INT-001: Связка с Google Ads (Product Linking)
**Priority**: P0-Critical

**Description**: Система должна обеспечивать связывание ресурса GA4 с одним или несколькими аккаунтами Google Ads для обмена данными о конверсиях, аудиториях и кампаниях.

**Acceptance Criteria**:
- [ ] Администратор или редактор может создать связь GA4 — Google Ads из раздела Admin > Product Links > Google Ads Links
- [ ] Для связки необходим доступ администратора к аккаунту Google Ads и роль редактора/администратора в GA4
- [ ] При связке доступны настройки: Enable Personalized Advertising (включение персонализированной рекламы), Enable Auto-Tagging (автоматическая разметка URL)
- [ ] Один ресурс GA4 может быть связан с несколькими аккаунтами Google Ads
- [ ] Один аккаунт Google Ads может быть связан с несколькими ресурсами GA4
- [ ] После связки в GA4 появляются данные о кампаниях Google Ads (клики, показы, расходы)
- [ ] Метрики Google Ads доступны в стандартных и пользовательских отчётах GA4
- [ ] Связь может быть удалена администратором из GA4 или из Google Ads

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-001 | Auto-tagging должен быть включён для корректной атрибуции трафика Google Ads в GA4 |
| BR-INT-002 | Для экспорта аудиторий в Google Ads необходимо включить Google Signals или сбор данных, предоставленных пользователями (User-provided data) |
| BR-INT-003 | Если Google Signals не активен, аудитории не будут экспортироваться в связанные рекламные продукты |

---

### FR-INT-002: Импорт конверсий (ключевых событий) в Google Ads
**Priority**: P0-Critical

**Description**: Система должна позволять импортировать ключевые события (key events) из GA4 в Google Ads в качестве конверсий для использования в стратегиях назначения ставок (Smart Bidding).

**Acceptance Criteria**:
- [ ] После связки аккаунтов ключевые события GA4 становятся доступными для импорта в Google Ads
- [ ] Импорт конверсий выполняется из интерфейса Google Ads (Tools > Conversions > Import > Google Analytics 4)
- [ ] Импортированные конверсии из GA4 по умолчанию создаются как «вторичные» (secondary) конверсии, чтобы избежать двойного учёта
- [ ] Пользователь может вручную изменить статус конверсии на «основную» (primary) в Google Ads для использования в Smart Bidding
- [ ] Данные о конверсиях передаются с задержкой до 24 часов
- [ ] Конверсии из GA4 учитывают модель атрибуции, настроенную в GA4

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-004 | Конверсии из GA4, импортированные в Google Ads, по умолчанию являются вторичными, чтобы не дублировать учёт с конверсиями Google Ads |
| BR-INT-005 | Для корректной работы Smart Bidding рекомендуется использовать только одну конверсию на одно целевое действие (GA4 или нативную Google Ads) |
| BR-INT-006 | Связка Google Ads и GA4 обеспечивает в среднем +23% конверсий и -10% стоимости конверсии за счёт передачи дополнительных сигналов для оптимизации |

---

### FR-INT-003: Экспорт аудиторий в Google Ads
**Priority**: P0-Critical

**Description**: Система должна автоматически экспортировать аудитории, созданные в GA4, в связанные аккаунты Google Ads для ремаркетинга и таргетинга.

**Acceptance Criteria**:
- [ ] Аудитории, созданные в GA4, автоматически экспортируются во все связанные рекламные продукты (Google Ads, DV360, SA360)
- [ ] При создании аудитории GA4 выполняет backfill — заполняет аудиторию недавними пользователями (до 30 дней)
- [ ] Аудитории в Google Ads обновляются по мере того, как пользователи совершают события, соответствующие условиям аудитории
- [ ] Минимальный размер аудитории для использования в ремаркетинге Google Ads Search: 1000 пользователей
- [ ] Минимальный размер аудитории для Google Display Network: 100 пользователей
- [ ] Аудитории поддерживают предиктивные метрики GA4 (вероятность покупки, вероятность оттока)
- [ ] Аудитории с динамической оценкой и временными окнами экспортируются корректно

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-007 | Если событие или пользовательское свойство исключено из персонализации рекламы, аудитории на его основе не экспортируются |
| BR-INT-008 | Если персонализация рекламы отключена для определённого региона, пользователи из этого региона не добавляются в списки ремаркетинга |
| BR-INT-009 | Backfill при создании аудитории происходит только в Google Ads; отчёты GA4 и экспорты аудиторий не содержат backfill-данных |
| BR-INT-010 | Размер аудитории в GA4 и Google Ads может различаться из-за разных методов подсчёта и backfill |

### FR-INT-004: Связка с Google Search Console
**Priority**: P1-High

**Description**: Система должна обеспечивать связывание ресурса GA4 с ресурсом Google Search Console для отображения данных органического поиска в отчётах GA4.

**Acceptance Criteria**:
- [ ] Администратор или редактор может создать связь из раздела Admin > Product Links > Search Console Links
- [ ] Связь создаётся между конкретным веб-потоком данных (web data stream) GA4 и ресурсом Search Console
- [ ] Один ресурс Search Console может быть связан только с одним веб-потоком данных GA4
- [ ] После связки доступны два стандартных отчёта: «Поисковые запросы Google (органика)» и «Органический поисковый трафик Google»
- [ ] Отчёт «Поисковые запросы» отображает: запросы, показы, клики, CTR, средняя позиция
- [ ] Отчёт «Органический трафик» отображает: целевые страницы, с наложением метрик GA4 (пользователи, сессии, события, конверсии)
- [ ] Данные доступны с разбивкой по измерениям: страна и тип устройства
- [ ] Данные Search Console доступны в GA4 с задержкой 48 часов

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-011 | Search Console хранит данные за последние 16 месяцев; соответственно, в GA4 данные Search Console также ограничены 16 месяцами |
| BR-INT-012 | Drill-down в отчёте поисковых запросов возможен только по измерениям Search Console, но не по измерениям Analytics |
| BR-INT-013 | Связь 1:1 — один ресурс Search Console может быть связан только с одним веб-потоком GA4 |

### FR-INT-005: BigQuery Export (ежедневный экспорт)
**Priority**: P0-Critical

**Description**: Система должна обеспечивать автоматический ежедневный экспорт данных о событиях GA4 в Google BigQuery для расширенного анализа и построения отчётов.

**Acceptance Criteria**:
- [ ] Администратор или редактор может настроить BigQuery Export из раздела Admin > Product Links > BigQuery Links
- [ ] Требуется проект Google Cloud с активированным BigQuery API
- [ ] Пользователь может выбрать регион размещения данных BigQuery (location)
- [ ] Пользователь может выбрать, какие потоки данных (data streams) экспортировать
- [ ] Пользователь может исключить определённые события из экспорта
- [ ] Ежедневный экспорт создаёт таблицу `events_YYYYMMDD` для каждого дня
- [ ] Таблица ежедневного экспорта обычно появляется через ~10 часов после окончания дня (между 8:00 и 11:00 UTC)
- [ ] Ежедневные таблицы обновляются до 3 дней после события для учёта поздних данных (late arrivals)
- [ ] Опционально можно включить экспорт пользовательских данных: таблицы `pseudonymous_users_` и `users_`

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-014 | Лимит ежедневного (batch) экспорта — 1 000 000 событий в день для стандартных ресурсов GA4 |
| BR-INT-015 | При превышении лимита 1 млн событий экспорт за этот день будет неполным (события сверх лимита не экспортируются) |
| BR-INT-016 | При систематическом превышении лимита ежедневный экспорт приостанавливается; администраторы и редакторы получают email-уведомление |
| BR-INT-017 | Приостановленный экспорт не восстанавливает данные за предыдущие дни |
| BR-INT-018 | Для ресурсов GA4 360 лимит значительно выше (миллиарды событий в день) |

---

### FR-INT-006: BigQuery Export (потоковый / streaming экспорт)
**Priority**: P1-High

**Description**: Система должна обеспечивать потоковый (streaming) экспорт данных в реальном времени из GA4 в BigQuery через intraday-таблицы.

**Acceptance Criteria**:
- [ ] При настройке BigQuery Export пользователь может включить Streaming Export дополнительно к ежедневному экспорту
- [ ] Streaming Export создаёт таблицу `events_intraday_YYYYMMDD`, которая обновляется непрерывно в течение дня
- [ ] В конце дня данные из intraday-таблицы объединяются с ежедневной таблицей `events_YYYYMMDD`
- [ ] После объединения intraday-таблица удаляется
- [ ] Streaming Export не имеет лимита на количество событий (в отличие от ежедневного экспорта)
- [ ] Streaming Export работает по принципу best-effort — могут быть пропуски данных из-за поздних событий или неудачных загрузок

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-019 | Streaming Export не содержит данные атрибуции пользователей для новых пользователей: поля traffic_source.name, traffic_source.source, traffic_source.medium будут пустыми |
| BR-INT-020 | Streaming Export — операция best-effort; гарантия полноты данных обеспечивается только ежедневным экспортом |
| BR-INT-021 | Для GA4 360 доступен «Fresh Daily Export» — ежедневная таблица, которая появляется раньше стандартной (~2:00 UTC) |

---

### FR-INT-007: Схема данных BigQuery Export
**Priority**: P1-High

**Description**: Система должна экспортировать события в BigQuery с определённой схемой, включающей все параметры событий, свойства пользователей и метаданные.

**Acceptance Criteria**:
- [ ] Каждая строка таблицы `events_YYYYMMDD` соответствует одному событию
- [ ] Основные поля: event_date, event_timestamp, event_name, event_params (REPEATED RECORD), user_id, user_pseudo_id, user_properties (REPEATED RECORD), device, geo, traffic_source, ecommerce, items (REPEATED RECORD)
- [ ] Параметры событий (event_params) хранятся как вложенные записи (RECORD) с полями key, value.string_value, value.int_value, value.float_value, value.double_value
- [ ] Свойства пользователей (user_properties) хранятся аналогично с полями key, value, set_timestamp_micros
- [ ] Таблицы пользовательских данных (`pseudonymous_users_`, `users_`) содержат только пользовательские данные GA4
- [ ] Схема поддерживает вложенные и повторяющиеся поля (NESTED / REPEATED)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-022 | Стоимость хранения и запросов BigQuery оплачивается отдельно в рамках проекта Google Cloud |
| BR-INT-023 | Оптимизация стоимости: рекомендуется использовать партиционирование таблиц по дате и кластеризацию по event_name |

### FR-INT-008: Интеграция с Google Tag Manager (GTM)
**Priority**: P0-Critical

**Description**: Система должна обеспечивать настройку и управление сбором данных GA4 через контейнеры Google Tag Manager (web и server-side).

**Acceptance Criteria**:
- [ ] GA4 поддерживает интеграцию с GTM через Google Tag (тег конфигурации), в котором указывается Measurement ID (G-XXXXXXXXXX)
- [ ] Конфигурационный тег GA4 в GTM устанавливается с триггером Initialization — All Pages
- [ ] Через GTM можно настроить отправку пользовательских событий GA4 с произвольными параметрами
- [ ] GTM поддерживает отправку пользовательских свойств (User Properties) в GA4
- [ ] Enhanced Measurement (расширенное измерение) работает параллельно с GTM-тегами: отслеживание прокрутки, исходящих кликов, поиска на сайте, видео-вовлечённости, скачивания файлов
- [ ] GTM Server-Side контейнер позволяет отправлять данные GA4 через серверную прослойку для повышения точности и контроля над данными
- [ ] Все изменения в GTM проходят через систему версий, превью и публикации

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-024 | Measurement ID уникален для каждого веб-потока данных (web data stream) |
| BR-INT-025 | При использовании GTM и прямой установки gtag.js одновременно возможен двойной учёт событий; необходимо использовать только один метод |
| BR-INT-026 | GTM Server-Side контейнер требует отдельной инфраструктуры (App Engine, Cloud Run) и несёт дополнительные расходы |

### FR-INT-009: Интеграция с Firebase (мобильные приложения)
**Priority**: P0-Critical

**Description**: Система должна обеспечивать связывание проекта Firebase с ресурсом GA4 для сбора и анализа данных мобильных приложений (Android, iOS).

**Acceptance Criteria**:
- [ ] Firebase-проект может быть связан с ресурсом GA4 из Firebase Console (Project Settings > Integrations) или из GA4 Admin
- [ ] При связке можно создать новый ресурс GA4 или выбрать существующий
- [ ] Потоки данных Android и iOS, созданные в Firebase, синхронизируются с GA4 после настройки интеграции
- [ ] Потоки данных, созданные в GA4, синхронизируются с Firebase автоматически
- [ ] Firebase SDK автоматически собирает базовые события: first_open, session_start, screen_view, app_update, os_update, app_remove и др.
- [ ] Пользовательские события, настроенные через Firebase SDK, отображаются в GA4
- [ ] Аудитории GA4 экспортируются в Firebase с backfill до 30 дней данных (при наличии)
- [ ] Предиктивные аудитории и аудитории с динамической оценкой из GA4 экспортируются в Firebase
- [ ] Данные могут передаваться между продуктами с задержкой до 24 часов после связки

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-027 | Связь Firebase — GA4 является обязательной для аналитики мобильных приложений в GA4 |
| BR-INT-028 | Firebase Analytics и GA4 используют единую событийную модель данных; Firebase Analytics является подмножеством GA4 |
| BR-INT-029 | Управление связью Firebase — GA4 доступно только владельцам (Owners) проекта Firebase |
| BR-INT-030 | Один Firebase-проект может быть связан только с одним ресурсом GA4 |

### FR-INT-010: Интеграция с Looker Studio (бывший Data Studio)
**Priority**: P1-High

**Description**: Система должна обеспечивать подключение данных GA4 к Looker Studio через нативный коннектор для построения интерактивных дашбордов и отчётов.

**Acceptance Criteria**:
- [ ] Looker Studio предоставляет встроенный (нативный) коннектор Google Analytics, поддерживающий ресурсы GA4
- [ ] Коннектор извлекает данные в реальном времени через GA4 Data API
- [ ] Доступны все стандартные поля GA4 Data API, включая пользовательские измерения и метрики
- [ ] Пользователь может переименовывать поля, добавлять вычисляемые метрики, менять типы данных и агрегации
- [ ] Данные GA4 могут быть объединены (blend) с данными из других источников: Google Ads, Search Console, BigQuery, внешние платформы
- [ ] Looker Studio использует предиктивные метрики GA4 (вероятность покупки, вероятность оттока)
- [ ] Отчёты Looker Studio могут быть расшарены, экспортированы в PDF, встроены на веб-страницы

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-031 | Looker Studio подчиняется квотам GA4 Data API; при большом объёме данных или сложных запросах возможны ошибки превышения лимитов |
| BR-INT-032 | Сегменты и сравнения GA4 недоступны напрямую в коннекторе Looker Studio |
| BR-INT-033 | Нативный коннектор бесплатен; партнёрские коннекторы (Coupler.io, Two Minute Reports и др.) предоставляют расширенные возможности за отдельную плату |

### FR-INT-011: Интеграция с Google Merchant Center
**Priority**: P1-High

**Description**: Система должна обеспечивать связывание ресурса GA4 с аккаунтом Google Merchant Center для анализа эффективности бесплатных товарных объявлений и товарного каталога.

**Acceptance Criteria**:
- [ ] Администратор или редактор может создать связь из раздела Admin > Product Links > Merchant Center Links
- [ ] Связь является many-to-many: один ресурс GA4 может быть связан с несколькими аккаунтами Merchant Center и наоборот
- [ ] Для связки необходимо включить Auto-tagging в аккаунте Merchant Center
- [ ] После связки в GA4 доступны данные о конверсиях из бесплатных товарных объявлений (free listings)
- [ ] Ключевые события purchase и in_app_purchase, возникшие из кликов органического поиска, экспортируются из GA4 в Merchant Center
- [ ] Данные из Merchant Center доступны для анализа поведения пользователей: просмотры товаров, клики, покупки
- [ ] В GA4 отображаются рекомендации Merchant Center по устранению проблем с одобрением товаров (product disapprovals)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-034 | Auto-tagging обязателен для связки Merchant Center с GA4 |
| BR-INT-035 | Экспортируются только события purchase и in_app_purchase из органического поискового трафика |
| BR-INT-036 | Рекомендации Merchant Center отображаются в нескольких разделах GA4, обеспечивая видимость статуса одобрения товаров |

### FR-INT-012: Интеграция с Display & Video 360 (DV360)
**Priority**: P1-High

**Description**: Система должна обеспечивать связывание ресурса GA4 с аккаунтом Display & Video 360 для обмена аудиториями, конверсиями и данными о кампаниях.

**Acceptance Criteria**:

### FR-INT-015: Measurement Protocol
**Priority**: P1-High

**Description**: Система должна предоставлять HTTP-протокол для серверной отправки событий напрямую на серверы GA4, минуя клиентский JavaScript.

**Acceptance Criteria**:
- [ ] Measurement Protocol отправляет события через HTTP POST-запросы на endpoint GA4
- [ ] Для аутентификации используется API Secret, создаваемый в Admin > Data Streams > выбранный поток > Measurement Protocol API Secrets
- [ ] Каждый запрос содержит: Measurement ID (или Firebase App ID), API Secret, client_id (или app_instance_id), массив событий
- [ ] Поддерживаются все стандартные и пользовательские события GA4
- [ ] Measurement Protocol предназначен для дополнения (augment) клиентского сбора данных, а не для его замены
- [ ] Для корректной атрибуции необходимо предварительное создание пользователя через клиентский тег (gtag, GTM, Firebase SDK)
- [ ] События, отправленные через Measurement Protocol, отображаются в стандартных отчётах GA4 (с ограничениями)
- [ ] Поддержка отправки событий с устройств без стандартного SDK: киоски, умные часы, IoT

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-INT-046 | Окно атрибуции для событий Measurement Protocol — 72 часа; события с меткой времени старше 72 часов от момента отправки не атрибутируются к корректной сессии и помечаются как «Unassigned» |
| BR-INT-047 | Measurement Protocol не создаёт новых пользователей и не изменяет существующие пользовательские данные |
| BR-INT-048 | Measurement Protocol не валидирует отправляемые данные; некорректные данные будут приняты без ошибки |
| BR-INT-049 | События, отправленные через Measurement Protocol, не могут быть изменены функцией «Modify Event» в GA4 |
| BR-INT-050 | При использовании только Measurement Protocol (без клиентского тега) доступна лишь частичная отчётность |
| BR-INT-051 | Каждое событие может содержать до 25 параметров |

## Состояния и статусы

### Статусы связи с продуктом (Product Link)

```
[Инициализация] → PENDING → ACTIVE → DELETED
                      ↓
                   FAILED (ошибка связки)
```

| Статус | Описание |
|--------|----------|
| PENDING | Запрос на связку отправлен, ожидается подтверждение со стороны внешнего продукта |
| ACTIVE | Связь активна, данные передаются |
| FAILED | Связка не удалась (недостаточно прав, аккаунт недоступен) |
| DELETED | Связь удалена; передача данных прекращена, исторические данные сохраняются |

### Статусы BigQuery Export

```
[Не настроен] → ACTIVE → PAUSED → ACTIVE
                   ↓                  ↑
              QUOTA_EXCEEDED ─────────┘ (после уменьшения объёма)
                   ↓
              SUSPENDED (при систематическом превышении)
```

| Статус | Описание |
|--------|----------|
| ACTIVE | Экспорт работает, данные передаются ежедневно и/или в реальном времени |
| PAUSED | Экспорт приостановлен пользователем |
| QUOTA_EXCEEDED | Лимит 1 млн событий в день превышен; данные за текущий день неполные |
| SUSPENDED | Экспорт приостановлен системой из-за систематического превышения квоты |

### Статусы Data Import

```
[Создание источника] → IDLE → UPLOADING → SUCCESS
                                  ↓            ↓
                               FAILED      PARTIAL (часть строк отклонена)
```

| Статус | Описание |
|--------|----------|
| IDLE | Источник данных создан, ожидает загрузки |
| UPLOADING | Файл загружается и обрабатывается |
| SUCCESS | Загрузка успешна, все строки импортированы |
| PARTIAL | Загрузка частично успешна, часть строк отклонена из-за ошибок формата |
| FAILED | Загрузка не удалась (неверный формат, превышение лимита, ошибка SFTP) |

### Статусы экспорта аудиторий

```
[Создание аудитории] → BUILDING → ACTIVE → EXPIRED
                                     ↓
                                  NOT_EXPORTED (нарушены условия экспорта)
```

| Статус | Описание |
|--------|----------|
| BUILDING | Аудитория создаётся, происходит backfill |
| ACTIVE | Аудитория активна и экспортируется в связанные продукты |
| NOT_EXPORTED | Аудитория не экспортируется: отключены Google Signals, Personalized Advertising или данные исключены из персонализации |
| EXPIRED | Аудитория архивирована (неактивна, превышен лимит количества аудиторий) |

## Ограничения и лимиты

### Общие ограничения интеграций

| Параметр | Значение |
|----------|----------|
| Максимум связей Google Ads на один ресурс GA4 | Без ограничений (рекомендуется до 400) |
| Максимум связей Search Console на один веб-поток | 1 |
| Максимум связей BigQuery на один ресурс | 1 |
| Максимум связей Firebase на один ресурс | 1 (один Firebase-проект) |
| Максимум связей Merchant Center на один ресурс | Множественные (many-to-many) |
| Максимум связей DV360 на один ресурс | Множественные |
| Максимум связей SA360 на один ресурс | Множественные |
| Максимум связей Ad Manager на один ресурс | 1 |

### Ограничения BigQuery Export

| Параметр | Значение (стандартный GA4) | Значение (GA4 360) |
|----------|---------------------------|---------------------|
| Лимит ежедневного экспорта | 1 000 000 событий/день | Миллиарды событий/день |
| Лимит потокового экспорта | Без лимита (best-effort) | Без лимита |
| Fresh Daily Export | Недоступен | Доступен (~2:00 UTC) |
| Время появления ежедневной таблицы | ~10 часов (8:00-11:00 UTC) | Раньше (Fresh Export) |
| Обновление ежедневной таблицы для поздних данных | До 3 дней | До 3 дней |

### Ограничения Data Import

| Параметр | Значение |
|----------|----------|
| Максимальный размер файла | 1 ГБ |
| Максимальный размер файла Cost Data на одну дату | 90 МБ |
| Максимум загрузок в день на ресурс | 120 |
| Максимум источников Custom Event Data | 5 |
| Задержка отображения в отчётах | До 24 часов |
| Поддерживаемые форматы | CSV, SFTP |
| Максимум параметров события | 25 |
| Максимум пользовательских свойств | 25 |

### Ограничения Measurement Protocol

| Параметр | Значение |
|----------|----------|
| Окно атрибуции | 72 часа от момента отправки |
| Максимум параметров на событие | 25 |
| Максимум событий на запрос | 25 |
| Валидация данных | Отсутствует (данные принимаются без валидации) |
| Создание новых пользователей | Невозможно |
| Изменение существующих данных | Невозможно |
| Modify Event в GA4 | Не применяется к событиям Measurement Protocol |

### Ограничения аудиторий

| Параметр | Значение (стандартный GA4) | Значение (GA4 360) |
|----------|---------------------------|---------------------|
| Максимум аудиторий | 100 | 400 |
| Максимальная длительность членства | 540 дней | 540 дней |
| Минимальный размер для ремаркетинга (Search) | 1 000 пользователей | 1 000 пользователей |
| Минимальный размер для ремаркетинга (Display) | 100 пользователей | 100 пользователей |
| Backfill при создании | До 30 дней (только в Google Ads) | До 30 дней |

### Ограничения Search Console

| Параметр | Значение |
|----------|----------|
| Глубина исторических данных | 16 месяцев |
| Задержка данных | 48 часов |
| Связь с потоком данных | 1:1 (один ресурс SC — один поток GA4) |

## Интеграции с другими модулями

### Связь с модулем «Отчёты и аналитика»

| Интеграция | Как используется в отчётах |
|------------|----------------------------|
| Google Ads | Данные о кампаниях, кликах, показах, расходах отображаются в отчётах «Привлечение» (Acquisition). Метрики Google Ads доступны как измерения и метрики |
| Search Console | Данные отображаются в отдельных отчётах «Поисковые запросы Google» и «Органический поисковый трафик» |
| Ad Manager | Данные о доходах от рекламы отображаются в разделе «Монетизация» (Monetization > Publisher Ads) |
| DV360 / SA360 | Данные о кампаниях доступны в отчётах привлечения с фильтрацией по соответствующим измерениям |
| Data Import (Cost) | Расходы внешних рекламных платформ отображаются в отчётах привлечения наряду с Google Ads |
| Data Import (Item) | Обогащённые данные о товарах доступны в отчётах электронной коммерции |

### Связь с модулем «Аудитории и сегменты»

| Интеграция | Как используется с аудиториями |
|------------|-------------------------------|
| Google Ads | Аудитории GA4 автоматически экспортируются в Google Ads для ремаркетинга и таргетинга |
| DV360 | Аудитории GA4 автоматически экспортируются для программатик-таргетинга |
| SA360 | Аудитории GA4 автоматически экспортируются для таргетинга поисковой рекламы |
| Ad Manager | Аудитории экспортируются при включении Google Signals и Personalized Advertising |
| Firebase | Аудитории с предиктивными метриками экспортируются в Firebase для таргетирования push-уведомлений, Remote Config, A/B-тестов |
| Data Import (User) | Импортированные свойства пользователей доступны как условия при создании аудиторий |

### Связь с модулем «Конверсии и ключевые события»

| Интеграция | Как используется с конверсиями |
|------------|-------------------------------|
| Google Ads | Ключевые события GA4 импортируются как конверсии для Smart Bidding |
| DV360 | Конверсии GA4 используются для оптимизации ставок и пользовательских стратегий |
| SA360 | Конверсии GA4 экспортируются для биддинговых стратегий |
| Merchant Center | События purchase и in_app_purchase из органического трафика передаются в MC |
| Measurement Protocol | Офлайн-конверсии отправляются через MP и учитываются как ключевые события |
| Data Import (Offline) | Офлайн-конверсии импортируются и доступны в отчётах конверсий |

### Связь с модулем «Сбор данных»

| Интеграция | Как используется для сбора данных |
|------------|----------------------------------|
| Google Tag Manager | Основной инструмент для настройки тегов GA4, событий и параметров |
| Firebase SDK | Основной метод сбора данных с мобильных приложений (Android, iOS) |
| Measurement Protocol | Серверный метод отправки событий (дополнение к клиентскому) |
| BigQuery Export | Экспортирует собранные данные для расширенного анализа |

### Связь с модулем «Визуализация и дашборды»

| Интеграция | Как используется для визуализации |
|------------|----------------------------------|
| Looker Studio | Нативный коннектор для построения дашбордов на данных GA4 |
| BigQuery | Данные BigQuery Export используются как источник для Looker Studio (через BigQuery-коннектор) с полным доступом к сырым данным |

### Связь с модулем «Администрирование»

| Интеграция | Как управляется через администрирование |
|------------|----------------------------------------|
| Все Product Links | Создание, редактирование и удаление связей доступно через Admin > Product Links |
| Data Import | Настройка источников и загрузка данных через Admin > Data Import |
| BigQuery Export | Настройка экспорта через Admin > Product Links > BigQuery Links |
| Measurement Protocol | Управление API Secrets через Admin > Data Streams > MP API Secrets |
| Google Signals | Глобальная настройка, влияющая на экспорт аудиторий во все рекламные продукты |
| Personalized Advertising | Глобальная настройка, влияющая на персонализацию рекламы во всех связанных продуктах |
