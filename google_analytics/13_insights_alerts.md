# Автоматические инсайты и оповещения — Google Analytics (GA4)

## 1. Общее описание модуля

Модуль "Автоматические инсайты и оповещения" является центральным интеллектуальным компонентом Google Analytics 4, объединяющим машинное обучение, статистический анализ аномалий и конверсационный AI для проактивного информирования пользователей о значимых изменениях в данных. Модуль включает систему Analytics Intelligence, которая непрерывно анализирует потоки данных ресурса (property), обнаруживает аномалии, выявляет тренды и генерирует текстовые описания ключевых изменений на естественном языке.

### Ключевые функции модуля:
- Автоматические инсайты (Automated Insights) — ML-обнаружение аномалий и трендов без участия пользователя
- Пользовательские инсайты (Custom Insights) — мониторинг условий, заданных пользователем, с email-оповещениями
- Сгенерированные инсайты (Generated Insights) — AI-сводка изменений на главной странице и в детальных отчётах
- Analytics Advisor — конверсационный AI-помощник на базе Gemini для анализа данных на естественном языке
- Поисковая строка Analytics Intelligence — мгновенные ответы на вопросы о данных
- Обнаружение аномалий (Anomaly Detection) — статистическая модель для выявления отклонений в временных рядах
- Email-оповещения — уведомления при срабатывании условий пользовательских инсайтов

## 3. Функциональные требования

### FR-INS-001: Автоматические инсайты (Automated Insights)

**Приоритет**: P0-Critical

**Описание**: Система непрерывно анализирует данные ресурса GA4 с использованием машинного обучения и автоматически генерирует инсайты при обнаружении значимых изменений, аномалий или новых трендов. Инсайты отображаются на панели инсайтов (Insights Dashboard) и на главной странице GA4.

**Критерии приёмки**:
- [ ] Система автоматически обнаруживает аномалии в метриках (пользователи, сеансы, события, конверсии, доход)
- [ ] Система выявляет изменения трендов (рост, снижение, сезонные колебания)
- [ ] Каждый инсайт содержит текстовое описание изменения на естественном языке
- [ ] Инсайты отображаются в виде карточек на панели инсайтов
- [ ] Карточки отображаются в порядке от самых новых к старым
- [ ] По клику на карточку открывается детальное представление инсайта
- [ ] Инсайты хранятся в течение 1 года с момента генерации
- [ ] Пользователь может загрузить больше инсайтов кнопкой "Load more"

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-INS-001 | Автоматические инсайты генерируются без участия пользователя на основе ML-моделей |
| BR-INS-002 | Для генерации инсайтов ресурс должен иметь историческими данными (рекомендуется 3+ месяца) |
| BR-INS-003 | Инсайты сохраняются и доступны в течение 1 года |
| BR-INS-004 | Панель инсайтов обновляется в реальном времени при обнаружении новых аномалий |
| BR-INS-005 | Автоматические инсайты доступны всем пользователям ресурса, включая читателей |

### FR-INS-002: Обнаружение аномалий (Anomaly Detection)

**Приоритет**: P0-Critical

**Описание**: Analytics Intelligence применяет байесовскую модель пространства состояний временных рядов (Bayesian state-space time series model) к историческим данным для прогнозирования ожидаемого значения метрики. Если фактическое значение выходит за пределы доверительного интервала (credible interval), точка данных помечается как аномалия.

**Критерии приёмки**:
- [ ] Модель строит прогноз на основе исторических данных с вычислением доверительного интервала
- [ ] Точка данных помечается как аномалия, если фактическое значение выходит за пределы доверительного интервала
- [ ] Аномалии обнаруживаются для всех основных метрик (пользователи, сеансы, просмотры страниц, события, конверсии, доход)
- [ ] Поддерживаются три гранулярности обнаружения: почасовая, дневная, недельная
- [ ] Для каждой гранулярности используется соответствующий период обучения модели

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-INS-006 | Период обучения для почасовых аномалий — 2 недели |
| BR-INS-007 | Период обучения для дневных аномалий — 90 дней |
| BR-INS-008 | Период обучения для недельных аномалий — 32 недели |
| BR-INS-009 | Почасовое обнаружение аномалий доступно только для веб-данных (не для приложений) |
| BR-INS-010 | Для обнаружения аномалий в приложениях существует задержка в сборе событий, поэтому почасовая гранулярность недоступна |
| BR-INS-011 | Модель автоматически учитывает сезонность (день недели, время суток, период года) |

### FR-INS-003: Пользовательские инсайты (Custom Insights)

**Приоритет**: P0-Critical

**Описание**: Пользователи с ролью Аналитик и выше создают собственные условия мониторинга данных. Когда заданные условия выполняются, система генерирует инсайт, отображает его на панели инсайтов и при необходимости отправляет email-оповещение.

**Критерии приёмки**:
- [ ] Пользователь может создать пользовательский инсайт с нуля (from scratch) или на основе предложенного шаблона
- [ ] Пользователь задаёт имя инсайта
- [ ] Пользователь выбирает частоту проверки условия (hourly, daily, weekly, monthly)
- [ ] Пользователь задаёт условие с выбором метрики, типа условия и порогового значения
- [ ] Пользователь может добавить сегмент/фильтр по измерению для сужения области мониторинга
- [ ] Пользователь может включить или выключить email-оповещения
- [ ] Пользователь может указать email-адреса получателей уведомлений
- [ ] Все пользователи ресурса видят сработавшие пользовательские инсайты на панели инсайтов, независимо от настроек email

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-INS-012 | Максимум 50 пользовательских инсайтов на один ресурс (property) |
| BR-INS-013 | Частота "Hourly" (ежечасно) доступна только для веб-данных |
| BR-INS-014 | Email-уведомления отправляются только пользователям, имеющим доступ к ресурсу GA4 |
| BR-INS-015 | Сработавшие пользовательские инсайты видны всем пользователям ресурса на панели, даже если email-оповещение настроено не для всех |
| BR-INS-016 | Пользовательский инсайт с условием "аномалия" требует достаточного периода обучения модели в зависимости от выбранной частоты |

### FR-INS-004: Настройка условий пользовательских инсайтов

**Приоритет**: P0-Critical

**Описание**: Условие пользовательского инсайта строится по формуле: `Метрика + Тип условия + Пороговое значение`. Дополнительно условие может быть ограничено сегментом (фильтром по измерению).

**Критерии приёмки**:
- [ ] Пользователь выбирает метрику из списка доступных метрик ресурса
- [ ] Пользователь выбирает тип условия из предопределённого перечня
- [ ] Для условий с процентным изменением пользователь задаёт пороговое значение (%) и период сравнения
- [ ] Для условий с абсолютным значением пользователь задаёт пороговое число
- [ ] Для условия "аномалия" пороговое значение не требуется (определяется моделью)
- [ ] Пользователь может добавить фильтр по измерению (dimension) для ограничения контекста

**Доступные метрики для условий**:

| Метрика | Описание |
|---------|----------|
| Sessions (Сеансы) | Количество сеансов |
| Total Users (Всего пользователей) | Количество уникальных пользователей |
| New Users (Новые пользователи) | Количество новых пользователей |
| Active Users (Активные пользователи) | Количество активных пользователей |
| Views (Просмотры) | Количество просмотров страниц/экранов |
| Event Count (Количество событий) | Общее количество событий |
| Conversions / Key Events (Конверсии / Ключевые события) | Количество конверсий |
| Total Revenue (Общий доход) | Суммарный доход |
| Purchase Revenue (Доход от покупок) | Доход от электронной коммерции |
| Ad Revenue (Доход от рекламы) | Доход от рекламных показов |

**Типы условий**:

| Тип условия | Описание | Требует порог | Требует период сравнения |
|-------------|----------|:---:|:---:|
| Is anomaly (Аномалия) | Статистическое отклонение от прогноза модели | Нет | Нет |
| % increase is more than (% рост более чем) | Метрика выросла на указанный процент | Да | Да |
| % decrease is more than (% падение более чем) | Метрика снизилась на указанный процент | Да | Да |
| % change is more than (% изменение более чем) | Метрика изменилась (рост или падение) на указанный процент | Да | Да |
| Is greater than or equal to (>= значение) | Абсолютное значение метрики >= порогу | Да | Нет |
| Is less than or equal to (<= значение) | Абсолютное значение метрики <= порогу | Да | Нет |

**Периоды сравнения (для процентных условий)**:

| Период сравнения | Описание | Рекомендация |
|------------------|----------|-------------|
| Yesterday (Вчера) | Сравнение с предыдущим днём | Подходит для метрик без сильных дневных колебаний |
| Same day last week (Тот же день неделю назад) | Сравнение с тем же днём прошлой недели | Рекомендуется для большинства сценариев — компенсирует колебания по дням недели |
| Same day last year (Тот же день год назад) | Сравнение с тем же днём прошлого года | Подходит для анализа с учётом сезонности |

**Частота проверки**:

| Частота | Описание | Ограничения |
|---------|----------|------------|
| Hourly (Ежечасно) | Проверка каждый час | Только веб-данные. Не поддерживается для приложений |
| Daily (Ежедневно) | Проверка раз в день | Доступна для всех типов данных |
| Weekly (Еженедельно) | Проверка раз в неделю | Доступна для всех типов данных |
| Monthly (Ежемесячно) | Проверка раз в месяц | Доступна для всех типов данных |

**Фильтры по измерениям (Dimension Filters)**:

Пользователь может сузить область мониторинга, добавив фильтр по одному или нескольким измерениям. Например:
- Страна = "United States" — мониторить метрику только для пользователей из США
- Источник/канал = "google / organic" — мониторить только органический трафик из Google
- Тип устройства = "mobile" — мониторить только мобильный трафик
- Название страницы = "/checkout" — мониторить конверсии на странице оформления заказа

### FR-INS-005: Предложенные шаблоны инсайтов (Suggested Insights)

**Приоритет**: P1-High

**Описание**: При создании пользовательского инсайта система предлагает до 5 предварительно настроенных шаблонов, покрывающих типичные сценарии мониторинга. Пользователь может создать инсайт из шаблона "как есть" или использовать шаблон как отправную точку для настройки.

**Критерии приёмки**:
- [ ] Система предлагает набор предварительно настроенных шаблонов при создании нового инсайта
- [ ] Каждый шаблон содержит предзаполненные метрику, тип условия и частоту
- [ ] Пользователь может создать инсайт из шаблона одним кликом (кнопка "Create")
- [ ] Пользователь может выбрать "Review and create" для предварительного редактирования шаблона
- [ ] Шаблоны покрывают ключевые метрики: события, пользователи, просмотры, конверсии, доход

**Типичные предложенные шаблоны**:

| Шаблон | Метрика | Условие | Частота |
|--------|---------|---------|---------|
| Anomaly in daily events | Event Count | Is anomaly | Daily |
| Anomaly in daily users | Total Users | Is anomaly | Daily |
| Anomaly in daily views | Views | Is anomaly | Daily |
| Anomaly in daily conversions | Conversions | Is anomaly | Daily |
| Anomaly in daily revenue | Total Revenue | Is anomaly | Daily |

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-INS-017 | Шаблоны предлагаются на основе типа данных ресурса (веб-сайт, приложение, оба) |
| BR-INS-018 | Шаблон с условием "аномалия" требует накопления обучающих данных (90 дней для daily) |
| BR-INS-019 | Инсайты, созданные из шаблонов, учитываются в общем лимите 50 на ресурс |

### FR-INS-006: Email-оповещения

**Приоритет**: P0-Critical

**Описание**: Для каждого пользовательского инсайта можно настроить отправку email-уведомлений при срабатывании условия. Email содержит описание инсайта, текущее значение метрики, ожидаемое значение (для аномалий) и ссылку на панель инсайтов в GA4.

**Критерии приёмки**:
- [ ] Пользователь может включить/выключить email-оповещения при создании или редактировании пользовательского инсайта
- [ ] Пользователь указывает email-адреса получателей (через запятую)
- [ ] Email-оповещения отправляются только пользователям, имеющим доступ к ресурсу GA4
- [ ] Email содержит название инсайта, описание сработавшего условия, значение метрики и ссылку в GA4
- [ ] Оповещения отправляются каждый раз, когда условие срабатывает (при каждой проверке)

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-INS-020 | Email-уведомления можно отправлять только пользователям с доступом к ресурсу GA4 |
| BR-INS-021 | Частота email-оповещений определяется частотой проверки инсайта (hourly, daily, weekly, monthly) |
| BR-INS-022 | Один и тот же инсайт может отправлять оповещения нескольким получателям |
| BR-INS-023 | Отключение email-оповещений не удаляет инсайт — он продолжает отображаться на панели |
| BR-INS-024 | Автоматические инсайты (Automated Insights) не поддерживают email-оповещения — только пользовательские |

### FR-INS-007: Панель инсайтов (Insights Dashboard)

**Приоритет**: P0-Critical

**Описание**: Центральная панель для просмотра и управления всеми инсайтами ресурса. Отображает автоматические и пользовательские инсайты в хронологическом порядке. Доступна через раздел "Insights & recommendations" на главной странице GA4 и через отдельную страницу "View all insights".

**Критерии приёмки**:
- [ ] На главной странице GA4 (Home) отображается секция "Insights and recommendations" с последними инсайтами
- [ ] По клику "View all insights" открывается полная панель инсайтов
- [ ] Инсайты отображаются в виде карточек в хронологическом порядке (новые сверху)
- [ ] Каждая карточка содержит: заголовок, краткое описание, дату, тип (автоматический/пользовательский)
- [ ] По клику на карточку открывается детальное представление с графиком и контекстом
- [ ] Кнопка "Load more" загружает более старые инсайты
- [ ] Кнопка "Manage" открывает список пользовательских инсайтов для редактирования
- [ ] Кнопка "Create" позволяет создать новый пользовательский инсайт
- [ ] Пользователь может удалить (dismiss) карточку инсайта из ленты

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-INS-025 | Инсайты хранятся и доступны для просмотра в течение 1 года |
| BR-INS-026 | Панель обновляется в реальном времени при генерации новых инсайтов |
| BR-INS-027 | Удаление (dismiss) карточки убирает её из ленты, но не удаляет пользовательский инсайт |
| BR-INS-028 | На главной странице отображается ограниченное количество последних инсайтов |

### FR-INS-008: Управление пользовательскими инсайтами

**Приоритет**: P1-High

**Описание**: Пользователи с соответствующими правами могут управлять списком пользовательских инсайтов: просматривать, редактировать, удалять и создавать новые.

**Критерии приёмки**:
- [ ] На панели инсайтов по кнопке "Manage" открывается список всех пользовательских инсайтов ресурса
- [ ] Для каждого инсайта отображается: название, частота, статус (активен/неактивен), email-оповещения (вкл/выкл)
- [ ] По кнопке "..." (три точки) доступны действия: "Edit" (редактировать) и "Delete" (удалить)
- [ ] Редактирование позволяет изменить все параметры инсайта: название, условие, частоту, фильтры, email
- [ ] Удаление требует подтверждения
- [ ] Создание нового инсайта возможно через кнопку "Create"
- [ ] Отображается текущее количество пользовательских инсайтов из лимита (например, "15 / 50")

**Бизнес-правила**:

| Правило | Описание |

### FR-INS-013: Предиктивные метрики (Predictive Metrics)

**Приоритет**: P2-Medium

**Описание**: ML-модели GA4 прогнозируют будущее поведение пользователей на основе исторических данных. Предиктивные метрики используются для создания предиктивных аудиторий и могут генерировать инсайты о прогнозируемых изменениях.

**Критерии приёмки**:
- [ ] Система рассчитывает вероятность покупки (Purchase Probability) — вероятность совершения покупки пользователем в ближайшие 28 дней
- [ ] Система рассчитывает вероятность оттока (Churn Probability) — вероятность того, что активный пользователь не вернётся в ближайшие 7 дней
- [ ] Система рассчитывает прогнозируемый доход (Predicted Revenue) — ожидаемый доход от пользователя за ближайшие 28 дней
- [ ] Предиктивные метрики доступны для создания предиктивных аудиторий

**Бизнес-правила**:

| Правило | Описание |
|---------|----------|
| BR-INS-050 | Для расчёта предиктивных метрик требуется минимальный объём данных о конверсиях/покупках |
| BR-INS-051 | Предиктивные метрики автоматически обновляются по мере поступления новых данных |

## 5. Состояния и статусы

### 5.1. Состояния пользовательского инсайта

```
[Создание] → [Активен] ⇄ [Неактивен] → [Удалён]
                 ↓
           [Сработал] → [Отправлено оповещение]
                 ↓
           [Ожидание] → [Следующая проверка]
```

| Состояние | Описание | Переходы |
|-----------|----------|----------|
| **Создание (Creating)** | Пользователь заполняет форму нового инсайта | -> Активен (при сохранении) |
| **Активен (Active)** | Инсайт активен и проверяется с заданной периодичностью | -> Неактивен (при деактивации), -> Удалён (при удалении) |
| **Неактивен (Inactive)** | Инсайт существует, но проверка и оповещения приостановлены | -> Активен (при реактивации), -> Удалён (при удалении) |
| **Сработал (Triggered)** | Условие инсайта выполнено — создан инсайт на панели | -> Ожидание (до следующей проверки) |
| **Ожидание (Waiting)** | Ожидание следующего цикла проверки | -> Сработал (если условие вновь выполнено) |
| **Удалён (Deleted)** | Инсайт удалён и не может быть восстановлен | Финальное состояние |

### 5.2. Состояния карточки инсайта на панели

| Состояние | Описание |
|-----------|----------|
| **Новый (New)** | Карточка только что появилась на панели, ещё не просмотрена |
| **Просмотрен (Viewed)** | Пользователь кликнул на карточку и увидел детали |
| **Скрыт (Dismissed)** | Пользователь скрыл карточку из ленты |
| **Истёк (Expired)** | Карточка удалена по истечении 1 года хранения |

### 5.3. Состояния модели обнаружения аномалий

| Состояние | Описание |
|-----------|----------|
| **Обучение (Training)** | Модель накапливает исторические данные. Аномалии ещё не определяются |
| **Готова (Ready)** | Модель обучена и может обнаруживать аномалии |
| **Обновляется (Updating)** | Модель переобучается на новых данных (постоянный процесс) |
| **Недостаточно данных (Insufficient Data)** | Ресурс не имеет достаточно данных для обучения модели |

### 5.4. Состояния email-оповещения

| Состояние | Описание |
|-----------|----------|
| **Включено (Enabled)** | Email-оповещения активны для данного инсайта |
| **Выключено (Disabled)** | Email-оповещения отключены |
| **Отправлено (Sent)** | Оповещение успешно отправлено получателям |
| **Ошибка доставки (Delivery Failed)** | Не удалось доставить оповещение (некорректный email, недоступный почтовый сервер) |

## 6. Ограничения и лимиты

### 6.1. Количественные ограничения

| Ограничение | Значение | Примечание |
|-------------|----------|------------|
| Максимум пользовательских инсайтов на ресурс | 50 | Включая инсайты из шаблонов |
| Срок хранения инсайтов на панели | 1 год | С даты генерации |
| Минимальный объём данных для Analytics Intelligence | 3+ месяца | Рекомендуется для корректных ответов |
| Период обучения для почасовых аномалий | 2 недели | Модель не работает до накопления данных |
| Период обучения для дневных аномалий | 90 дней | Модель не работает до накопления данных |
| Период обучения для недельных аномалий | 32 недели | Модель не работает до накопления данных |

### 6.2. Ограничения по типам данных

| Ограничение | Описание |
|-------------|----------|
| Почасовые инсайты — только веб | Частота "Hourly" недоступна для данных из мобильных приложений из-за задержки сбора событий |
| Analytics Advisor — только английский | На момент запуска конверсационный AI доступен только на английском языке |
| Предиктивные метрики — требования к объёму | Для расчёта требуется минимальный объём данных о покупках/конверсиях |

### 6.3. Ограничения email-оповещений

| Ограничение | Описание |
|-------------|----------|
| Получатели — только пользователи ресурса | Email-оповещения отправляются только пользователям с доступом к GA4 property |
| Нет email для автоматических инсайтов | Автоматические (ML-generated) инсайты не поддерживают email-уведомления |
| Частота = частота проверки | Email-оповещение может приходить не чаще, чем частота проверки (hourly / daily / weekly / monthly) |

## 8. Глоссарий

| Термин | Описание |
|--------|----------|
| **Analytics Intelligence** | Набор AI/ML-функций GA4 для автоматического анализа данных: обнаружение аномалий, тренды, ответы на вопросы |
| **Automated Insight** | Инсайт, автоматически сгенерированный ML-моделью при обнаружении аномалии или значимого изменения |
| **Custom Insight** | Пользовательский инсайт с условием, заданным пользователем, с опциональным email-оповещением |
| **Generated Insight** | AI-сгенерированная текстовая сводка на главной странице или в детальном отчёте |
| **Analytics Advisor** | Конверсационный AI-помощник на базе Gemini, доступный в интерфейсе GA4 |
| **Anomaly Detection** | Статистический метод обнаружения выбросов на основе байесовской модели временных рядов |
| **Credible Interval** | Доверительный интервал — диапазон ожидаемых значений метрики, вне которого точка считается аномалией |
| **Bayesian State-Space Model** | Статистическая модель, используемая GA4 для прогнозирования значений временных рядов |
| **Evaluation Frequency** | Частота проверки условия пользовательского инсайта: ежечасно, ежедневно, еженедельно, ежемесячно |
| **Comparison Period** | Период сравнения для процентных условий: вчера, тот же день неделю назад, тот же день год назад |
| **Predictive Metric** | ML-метрика, прогнозирующая будущее поведение: вероятность покупки, вероятность оттока, прогнозируемый доход |
| **Predictive Audience** | Аудитория, созданная на основе предиктивных метрик (например, "пользователи с высокой вероятностью покупки") |
| **Key Driver Analysis** | Анализ ключевых факторов — определение причин значимых изменений в метриках |
| **Stream Diagnostics** | Автоматическая диагностика потоков данных: обнаружение неактивных или некорректно настроенных потоков |
| **Training Period** | Период обучения ML-модели — объём исторических данных, необходимый для корректной работы аномалий |
| **Property** | Ресурс GA4 — сущность, объединяющая данные одного сайта/приложения |
| **Data Stream** | Поток данных — конфигурация сбора данных с конкретного источника (веб-сайт, iOS-приложение, Android-приложение) |
| **Suggested Insight** | Предложенный шаблон пользовательского инсайта с предзаполненными параметрами |
| **Gemini** | Семейство AI-моделей Google, используемое в Analytics Advisor |
