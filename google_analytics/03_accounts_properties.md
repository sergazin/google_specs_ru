# Структура аккаунтов и ресурсов

## Описание

Модуль управления иерархической структурой Google Analytics 4 (GA4). Обеспечивает создание, настройку, перенос и удаление организационных единиц платформы: организации, аккаунты, ресурсы (properties), потоки данных (data streams). Модуль определяет, как данные группируются, кому принадлежат, кто имеет к ним доступ, и как различные источники данных (веб-сайты, мобильные приложения) объединяются в единую аналитическую структуру.

Иерархия GA4:
```
Organization (Google Marketing Platform)
  └── Account (аккаунт)
        └── Property (ресурс)
              ├── Data Stream — Web
              ├── Data Stream — iOS App
              └── Data Stream — Android App
```

Для GA4 360 (платная версия) доступны дополнительные типы ресурсов:
```
Property (обычный ресурс)
  ├── Subproperty (подресурс — подмножество данных)
  └── Roll-up Property (сводный ресурс — объединение данных из нескольких ресурсов)
```

### Глоссарий

| Термин | Определение |
|--------|-------------|
| Organization | Верхний уровень иерархии, управляемый через Google Marketing Platform. Объединяет несколько аккаунтов Analytics |
| Account | Контейнер верхнего уровня в GA4. Принадлежит одному юридическому лицу. Регулируется региональными условиями обслуживания |
| Property | Ресурс — контейнер для отчётов на основе собранных данных. Представляет приложение и/или веб-сайт |
| Data Stream | Поток данных — канал сбора данных из конкретной точки взаимодействия (сайт, приложение) |
| Measurement ID | Уникальный идентификатор веб-потока данных в формате G-XXXXXXXXXX |
| Stream ID | Числовой идентификатор потока данных |
| Firebase App ID | Идентификатор мобильного приложения в Firebase, используемый для потоков iOS и Android |
| Subproperty | Подресурс (GA4 360) — получает подмножество данных из родительского ресурса |
| Roll-up Property | Сводный ресурс (GA4 360) — объединяет данные из нескольких ресурсов-источников |
| Enhanced Measurement | Автоматическое отслеживание взаимодействий (прокрутка, клики, поиск, видео, загрузки) без изменения кода |
| Trash Can | Корзина — временное хранилище удалённых аккаунтов и ресурсов (35 дней до безвозвратного удаления) |
| Data Retention | Период хранения данных на уровне событий (2 месяца или 14 месяцев) |

## Роли пользователей

### Стандартные роли

| Роль | Уровень доступа | Описание |
|------|-----------------|----------|
| **Администратор (Administrator)** | Полный | Полное управление аккаунтом/ресурсом. Управление пользователями, правами, настройками. Может назначать и отзывать любые роли |
| **Редактор (Editor)** | Высокий | Изменение настроек аккаунта/ресурса, конфигураций, потоков данных. НЕ может управлять пользователями и правами |
| **Маркетолог (Marketer)** | Средний | Управление аудиториями, конверсиями, моделями атрибуции. Не может изменять структурные настройки |
| **Аналитик (Analyst)** | Ограниченный | Создание и редактирование общих отчётов, дашбордов, сегментов. Просмотр данных |
| **Наблюдатель (Viewer)** | Минимальный | Только просмотр отчётов и данных. Не может создавать или изменять ничего |

### Ограничения данных (Data Restrictions)

| Ограничение | Описание |
|-------------|----------|
| **Без метрик стоимости (No Cost Metrics)** | Пользователь не видит метрики стоимости Google Ads (стоимость, CPC, CPM и т.д.) |
| **Без метрик дохода (No Revenue Metrics)** | Пользователь не видит метрики дохода (выручка, LTV, средний чек и т.д.) |

### Правила наследования прав

| Правило | Описание |
|---------|----------|
| Наследование сверху вниз | Роль на уровне аккаунта автоматически распространяется на ВСЕ ресурсы этого аккаунта |
| Повышение, но не понижение | Если пользователь имеет роль Editor на уровне аккаунта и Viewer на уровне ресурса — действует Editor (более высокая роль) |
| Локальное повышение | Пользователю можно назначить более высокую роль на уровне конкретного ресурса, чем его роль на уровне аккаунта |
| Наследование ограничений | Ограничение No Cost Metrics на уровне аккаунта действует для ВСЕХ ресурсов. Нельзя снять унаследованное ограничение на уровне ресурса |
| Добавление ограничений | На уровне ресурса можно ДОБАВИТЬ ограничение, но нельзя СНЯТЬ унаследованное с уровня аккаунта |

### Уровни применения ролей

| Уровень | Администратор | Редактор | Маркетолог | Аналитик | Наблюдатель |
|---------|---------------|----------|------------|----------|-------------|
| Аккаунт | Да | Да | Да | Да | Да |
| Ресурс (Property) | Да | Да | Да | Да | Да |

## Функциональные требования

### Организация (Organization)

#### FR-ACC-001: Создание организации
**Priority**: P2-Medium

**Description**: Пользователь может создать организацию в Google Marketing Platform для объединения нескольких аккаунтов Analytics и других продуктов Google Marketing Platform.

**Acceptance Criteria**:
- [ ] Организация создаётся через Google Marketing Platform Home (marketingplatform.google.com/home)
- [ ] Для создания организации пользователь должен иметь роль Org admin или User admin в Google Marketing Platform
- [ ] Организация получает уникальное имя
- [ ] Организация доступна как для Analytics 360, так и для Analytics Standard

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ORG-001 | Организация является необязательным верхним уровнем иерархии — аккаунт может существовать без организации |
| BR-ORG-002 | Один аккаунт Analytics может быть привязан только к одной организации |
| BR-ORG-003 | Управление пользователями организации осуществляется через Google Marketing Platform |

---

#### FR-ACC-002: Привязка аккаунта Analytics к организации
**Priority**: P2-Medium

**Description**: Администратор организации может привязать существующий аккаунт Google Analytics к организации для централизованного управления.

**Acceptance Criteria**:
- [ ] Привязка выполняется через раздел Administration > Organizations в Google Marketing Platform
- [ ] Для привязки необходимо указать ID аккаунта Analytics (можно несколько через запятую)
- [ ] После привязки пользователи аккаунта становятся пользователями организации
- [ ] Привязанные аккаунты доступны для управления из Google Marketing Platform

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ORG-004 | Для привязки аккаунта пользователь должен быть Org admin и Administrator аккаунта Analytics |
| BR-ORG-005 | Привязка не изменяет существующих пользователей и настройки аккаунта |

### Аккаунт (Account)

#### FR-ACC-003: Создание аккаунта
**Priority**: P0-Critical

**Description**: Пользователь может создать новый аккаунт Google Analytics. Аккаунт является корневым контейнером, представляющим одно юридическое лицо.

**Acceptance Criteria**:
- [ ] Пользователь указывает имя аккаунта
- [ ] Пользователь указывает страну (определяет региональные условия обслуживания)
- [ ] Система предлагает настроить параметры обмена данными (Data Sharing Settings)
- [ ] Пользователь принимает условия обслуживания (Terms of Service), специфичные для выбранной страны
- [ ] После создания аккаунта пользователю предлагается создать первый ресурс (Property)
- [ ] Создатель аккаунта автоматически получает роль Администратора

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ACC-001 | Один Google-аккаунт (gmail/workspace) может владеть не более чем 100 аккаунтами Analytics |
| BR-ACC-002 | Каждый аккаунт Analytics привязан к одному юридическому лицу |
| BR-ACC-003 | Страна аккаунта определяет применимые условия обслуживания и требования к обработке данных (GDPR, CCPA и др.) |
| BR-ACC-004 | Имя аккаунта может быть изменено в любое время Администратором или Редактором |

---

#### FR-ACC-004: Настройки обмена данными (Data Sharing Settings)
**Priority**: P1-High

**Description**: Администратор или Редактор может управлять параметрами обмена данными аккаунта с Google.

**Acceptance Criteria**:
- [ ] Настройка «Google products & services» — обмен данными с другими продуктами Google
- [ ] Настройка «Benchmarking» — участие в анонимном бенчмаркинге по индустрии
- [ ] Настройка «Technical support» — доступ техподдержки Google к данным аккаунта
- [ ] Настройка «Account specialists» — доступ специалистов Google к данным для рекомендаций
- [ ] Каждая настройка включается/выключается независимо
- [ ] Изменения применяются ко всем ресурсам аккаунта

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ACC-005 | Данные, переданные Google в рамках «Google products & services», обрабатываются Google как независимым контроллером (для GDPR) |
| BR-ACC-006 | Настройки обмена данными могут быть изменены в любой момент |
| BR-ACC-007 | Отключение обмена данными не удаляет ранее переданные данные |

---

#### FR-ACC-005: Принятие условий обработки данных (Data Processing Terms)
**Priority**: P1-High

**Description**: Администратор аккаунта может принять условия обработки данных Google Ads (Data Processing Amendment / DPA) в настройках аккаунта.

**Acceptance Criteria**:
- [ ] Условия доступны в разделе Account Settings
- [ ] Принять условия может только Администратор аккаунта
- [ ] Для бизнесов в ЕЭП, Великобритании и Швейцарии условия DPA обязательны
- [ ] Для бизнесов за пределами ЕЭП/UK/Швейцарии условия принимаются проактивно
- [ ] Статус принятия DPA отображается в настройках аккаунта

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ACC-008 | Принятие DPA является юридически обязывающим и не может быть отменено |
| BR-ACC-009 | DPA распространяется на все ресурсы в аккаунте |

---

#### FR-ACC-006: Редактирование аккаунта
**Priority**: P0-Critical

**Description**: Пользователь с ролью Администратор или Редактор может изменять настройки аккаунта.

**Acceptance Criteria**:
- [ ] Можно изменить имя аккаунта
- [ ] Можно изменить настройки обмена данными
- [ ] Нельзя изменить страну аккаунта после создания
- [ ] Все изменения записываются в историю изменений (Change History)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ACC-010 | Страна аккаунта неизменяема после создания |
| BR-ACC-011 | Любое изменение настроек фиксируется в Change History с указанием пользователя, даты и времени |

---

#### FR-ACC-007: Удаление аккаунта
**Priority**: P1-High

**Description**: Администратор может удалить аккаунт Google Analytics. Удаление перемещает аккаунт в Корзину (Trash Can).

**Acceptance Criteria**:
- [ ] Только пользователь с ролью Администратор на уровне аккаунта может выполнить удаление
- [ ] При инициации удаления аккаунт перемещается в Корзину
- [ ] Все ресурсы аккаунта также перемещаются в Корзину
- [ ] Данные НЕ обрабатываются, пока аккаунт находится в Корзине
- [ ] Аккаунт остаётся в Корзине 35 дней
- [ ] После 35 дней аккаунт и все его данные удаляются безвозвратно
- [ ] Удаление фиксируется системой (Analytics System user) в Change History

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ACC-012 | Аккаунт с активными ресурсами можно удалить — все ресурсы удаляются вместе с аккаунтом |
| BR-ACC-013 | Период восстановления — ровно 35 календарных дней с момента удаления |
| BR-ACC-014 | Безвозвратное удаление выполняется автоматически системой (Analytics System user) |

---

#### FR-ACC-008: Восстановление аккаунта из Корзины
**Priority**: P1-High

**Description**: Администратор может восстановить аккаунт из Корзины в течение 35 дней после удаления.

**Acceptance Criteria**:
- [ ] Восстановление доступно через Admin > Account > Trash
- [ ] Для восстановления требуется роль Администратора на уровне аккаунта
- [ ] При восстановлении сохраняются все настройки: фильтры, права пользователей, связи с другими продуктами Google
- [ ] Обработка данных для основных отчётов возобновляется в течение 1 часа после восстановления
- [ ] Обработка данных в реальном времени (Realtime) возобновляется в течение нескольких секунд
- [ ] Восстанавливаются все ресурсы, которые были в аккаунте на момент удаления

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ACC-015 | Данные, которые должны были поступить за время нахождения в Корзине, теряются безвозвратно |
| BR-ACC-016 | Восстановление из Корзины после 35 дней невозможно ни при каких обстоятельствах |

---

### Ресурс (Property)

#### FR-ACC-009: Создание ресурса
**Priority**: P0-Critical

**Description**: Пользователь с ролью Администратор или Редактор на уровне аккаунта может создать новый ресурс (Property) GA4.

**Acceptance Criteria**:
- [ ] Пользователь указывает имя ресурса
- [ ] Пользователь выбирает часовой пояс отчётности (Reporting Time Zone)
- [ ] Пользователь выбирает валюту отчётности (Currency)
- [ ] Пользователь выбирает категорию индустрии (Industry Category) — обязательное поле
- [ ] Ресурс получает уникальный Property ID (числовой)
- [ ] После создания ресурса пользователю предлагается создать первый поток данных
- [ ] Ресурс создаётся в рамках текущего аккаунта

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-PROP-001 | В одном аккаунте можно создать не более 2 000 ресурсов |
| BR-PROP-002 | Категория индустрии обязательна при создании ресурса (с конца 2024 года) |
| BR-PROP-003 | Один ресурс GA4 может объединять данные с веб-сайта и мобильных приложений (кросс-платформенная аналитика) |
| BR-PROP-004 | Каждый ресурс получает уникальный числовой Property ID, который не может быть изменён |

---

#### FR-ACC-010: Настройки ресурса
**Priority**: P0-Critical

**Description**: Администратор или Редактор может управлять ключевыми настройками ресурса, которые влияют на сбор и отображение данных.

**Acceptance Criteria**:
- [ ] Можно изменить имя ресурса
- [ ] Можно изменить часовой пояс отчётности
- [ ] Можно изменить валюту отчётности
- [ ] Можно изменить категорию индустрии
- [ ] Можно настроить период хранения данных (Data Retention): 2 месяца или 14 месяцев
- [ ] Можно включить/выключить сброс таймера хранения при новой активности пользователя (Reset user data on new activity)
- [ ] Настройка Google Signals (сбор данных о кросс-девайсном поведении авторизованных пользователей Google)
- [ ] Все изменения записываются в Change History

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-PROP-005 | Часовой пояс влияет на границы дня в отчётах. Если посетитель приходит во вторник по своему времени, но в понедельник по часовому поясу ресурса — визит фиксируется как понедельник |
| BR-PROP-006 | Если выбран часовой пояс с летним/зимним временем — система автоматически переключается |
| BR-PROP-007 | Часовой пояс GMT не переключается на летнее время |
| BR-PROP-008 | Валюта влияет на отображение всех денежных метрик. Все транзакции конвертируются в выбранную валюту по ежедневному курсу |
| BR-PROP-009 | По умолчанию период хранения данных = 2 месяца. Рекомендуется немедленно переключить на 14 месяцев |
| BR-PROP-010 | Период хранения данных влияет только на данные уровня событий (используемые в Exploration-отчётах), а не на агрегированные данные в стандартных отчётах |
| BR-PROP-011 | Категория индустрии используется для бенчмаркинга — сравнения с аналогичными бизнесами |
| BR-PROP-012 | Изменение часового пояса и валюты применяется только к будущим данным, исторические данные НЕ пересчитываются |

---

#### FR-ACC-011: Удаление ресурса
**Priority**: P1-High

**Description**: Пользователь с ролью Редактор или Администратор может удалить ресурс. Ресурс перемещается в Корзину.

**Acceptance Criteria**:
- [ ] Удаление выполняется через Property Settings > Property details > Move to Trash Can
- [ ] Пользователь подтверждает удаление
- [ ] Ресурс перемещается в Корзину аккаунта
- [ ] Данные ресурса перестают обрабатываться
- [ ] Ресурс остаётся в Корзине 35 дней
- [ ] После 35 дней ресурс удаляется безвозвратно

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-PROP-013 | Для удаления достаточно роли Редактор на уровне аккаунта или ресурса |
| BR-PROP-014 | Удаление ресурса не удаляет аккаунт |
| BR-PROP-015 | Удаление ресурса удаляет все его потоки данных |
| BR-PROP-016 | При удалении ресурса тег (Measurement ID) становится неактивным — данные перестают собираться |

#### FR-ACC-012: Восстановление ресурса из Корзины
**Priority**: P1-High

**Description**: Администратор может восстановить ресурс из Корзины в течение 35 дней.

**Acceptance Criteria**:
- [ ] Восстановление доступно через Admin > Account > Trash
- [ ] Требуется роль Администратора на уровне аккаунта
- [ ] Все настройки ресурса сохраняются (конфигурации, права, связи)
- [ ] Обработка основных отчётов возобновляется в течение 1 часа
- [ ] Realtime-отчёты возобновляются в течение секунд
- [ ] Потоки данных восстанавливаются вместе с ресурсом

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-PROP-017 | Данные за период нахождения в Корзине теряются |
| BR-PROP-018 | Восстановление после 35 дней невозможно |

#### FR-ACC-013: Перенос ресурса между аккаунтами
**Priority**: P1-High

**Description**: Администратор может перенести (переместить) ресурс из одного аккаунта в другой.

**Acceptance Criteria**:
- [ ] Пользователь выбирает целевой аккаунт (destination account) из списка доступных
- [ ] Система проверяет наличие необходимых ролей в обоих аккаунтах
- [ ] При переносе сохраняются: Measurement ID / Tag ID, настройки ресурса, потоки данных, все исторические данные отчётов, конверсии, аудитории, пользовательские определения (custom dimensions/metrics)
- [ ] Measurement ID / Tag ID не изменяется — перетегирование сайта НЕ требуется
- [ ] Перенос завершается мгновенно

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-PROP-019 | Для переноса требуются роли Администратор И Редактор одновременно в обоих аккаунтах (источнике и назначении) |

#### FR-ACC-019: Настройка Enhanced Measurement (расширенное отслеживание)

#### FR-ACC-025: История изменений (Change History)
**Priority**: P1-High

- [ ] Фиксируется объект изменения (аккаунт, ресурс, поток данных, пользователь, настройка)
- [ ] Можно фильтровать историю по дате, типу изменения, пользователю

| Rule | Description |

## Состояния и статусы

### Жизненный цикл аккаунта

```
[Создание] → ACTIVE → [Удаление] → TRASHED → (35 дней) → DELETED (безвозвратно)
                         ↑                         |
                         └── [Восстановление] ──────┘
```

| Статус | Описание | Действия |
|--------|----------|----------|
| ACTIVE | Аккаунт активен, данные обрабатываются | Редактирование, удаление, управление пользователями, создание ресурсов |
| TRASHED | Аккаунт в Корзине (35 дней) | Восстановление. Данные НЕ обрабатываются |
| DELETED | Аккаунт безвозвратно удалён | Никакие действия невозможны. Данные утрачены |

### Жизненный цикл ресурса (Property)

```
[Создание] → ACTIVE → [Удаление] → TRASHED → (35 дней) → DELETED (безвозвратно)
                |        ↑                         |
                |        └── [Восстановление] ──────┘
                |
                └── [Перенос в другой аккаунт] → ACTIVE (в целевом аккаунте)
```

| Статус | Описание | Действия |
|--------|----------|----------|
| ACTIVE | Ресурс активен, данные обрабатываются | Редактирование, удаление, перенос, управление потоками |
| TRASHED | Ресурс в Корзине (35 дней) | Восстановление. Данные НЕ обрабатываются |
| DELETED | Ресурс безвозвратно удалён | Никакие действия невозможны |

### Жизненный цикл потока данных (Data Stream)

```
[Создание] → ACTIVE → [Удаление] → DELETED (безвозвратно)
```

| Статус | Описание | Действия |
|--------|----------|----------|
| ACTIVE | Поток активен, данные собираются | Редактирование настроек, удаление |
| DELETED | Поток безвозвратно удалён | Никакие действия невозможны. Исторические данные сохранены в ресурсе |

## User Stories

### Создание структуры с нуля

**US-ACC-001**: Как владелец нового бизнеса, я хочу создать аккаунт GA4 и ресурс для своего веб-сайта, чтобы начать отслеживать посетителей.

**US-ACC-002**: Как разработчик мобильного приложения, я хочу добавить потоки данных для iOS и Android в существующий ресурс, чтобы видеть объединённую аналитику по всем платформам.

**US-ACC-003**: Как маркетинг-директор, я хочу создать отдельные ресурсы для каждого бренда компании, чтобы анализировать их независимо.

### Управление доступом

**US-ACC-004**: Как администратор, я хочу предоставить маркетинговому агентству доступ к ресурсу с ролью Аналитик и ограничением No Revenue Metrics, чтобы они видели данные о трафике, но не о доходах.

**US-ACC-005**: Как администратор корпоративного аккаунта, я хочу назначить регионального менеджера Редактором только для ресурса его региона, не давая ему доступ к другим регионам.

**US-ACC-006**: Как администратор, я хочу отозвать доступ уволенного сотрудника ко всем ресурсам аккаунта одним действием (удаление на уровне аккаунта).

### Реорганизация структуры

**US-ACC-007**: Как администратор, я хочу перенести ресурс из аккаунта подрядчика в собственный аккаунт компании, сохранив все исторические данные.

**US-ACC-008**: Как администратор, я хочу удалить устаревший ресурс тестового сайта, чтобы не загромождать аккаунт.

**US-ACC-009**: Как администратор, я хочу восстановить случайно удалённый ресурс из Корзины, чтобы вернуть доступ к данным.

### Корпоративные сценарии (GA4 360)

**US-ACC-010**: Как администратор международной компании (GA4 360), я хочу создать сводный ресурс (Roll-up) для объединения данных из ресурсов разных стран, чтобы видеть глобальную картину.

**US-ACC-011**: Как администратор (GA4 360), я хочу создать подресурс (Subproperty) с фильтрами по конкретным данным для внешнего партнёра, чтобы ограничить его доступ к чувствительным данным.

### Настройка сбора данных

**US-ACC-012**: Как владелец сайта, я хочу отключить отслеживание прокрутки (Scrolls) в Enhanced Measurement, так как для одностраничного сайта эта метрика нерелевантна.

**US-ACC-013**: Как аналитик, я хочу увеличить период хранения данных до 14 месяцев, чтобы проводить год-к-году сравнения в Exploration-отчётах.

**US-ACC-014**: Как администратор, я хочу настроить кросс-доменное отслеживание между основным сайтом и магазином на поддомене, чтобы видеть полный путь пользователя.
