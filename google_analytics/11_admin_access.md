# Администрирование и управление доступом

## Описание

Модуль администрирования и управления доступом Google Analytics 4 (GA4) охватывает полный цикл управления аналитической платформой: от создания и настройки аккаунтов и ресурсов (properties) до гранулярного управления правами пользователей, политик хранения и удаления данных, атрибуции, фильтрации трафика и аудита изменений.

Административный интерфейс GA4 разделён на два уровня — **Account** (аккаунт) и **Property** (ресурс). Аккаунт является верхнеуровневым контейнером, объединяющим один или несколько ресурсов. Ресурс представляет собой сайт и/или приложение и содержит потоки данных (Data Streams), настройки сбора, отображения и управления данными.

Иерархия: **Organization (опционально) > Account > Property > Data Stream**.

Для пользователей Google Analytics 360 доступны дополнительные сущности: **Subproperty** (подресурс — подмножество данных основного ресурса) и **Roll-up Property** (объединяющий ресурс — агрегирует данные из нескольких ресурсов).

## Роли пользователей

### Основные роли

GA4 предоставляет четыре основные роли, назначаемые на уровне аккаунта и/или ресурса:

| Роль | Описание | Ключевые возможности |
|------|----------|---------------------|
| **Administrator** (Администратор) | Полный доступ к управлению аккаунтом/ресурсом | Управление пользователями и ролями, все настройки аккаунта/ресурса, удаление аккаунтов/ресурсов, просмотр данных |
| **Editor** (Редактор) | Управление настройками ресурса без права управлять пользователями | Изменение настроек ресурса, создание/редактирование/удаление потоков данных, событий, конверсий, аудиторий, запросы на удаление данных, просмотр данных |
| **Analyst** (Аналитик) | Создание и редактирование общих аналитических ресурсов | Создание/редактирование общих отчётов и Explorations, просмотр данных и конфигурации |
| **Viewer** (Наблюдатель) | Только просмотр | Просмотр отчётов и данных, просмотр конфигурации (без возможности изменений) |

### Дополнительная роль

| Роль | Описание |
|------|----------|
| **Marketer** (Маркетолог) | Промежуточная роль, позволяющая управлять аудиториями, конверсиями и некоторыми маркетинговыми настройками без полного доступа Editor |

### Ограничения данных (Data Restrictions)

Помимо ролей, администраторы могут назначать ограничения на просмотр определённых категорий данных:

| Ограничение | Описание |
|-------------|----------|
| **No Revenue Metrics** | Пользователь не видит метрики дохода (revenue, purchase revenue, ad revenue, LTV и производные) |
| **No Cost Metrics** | Пользователь не видит метрики затрат (cost per click, cost per conversion и производные) |

Ограничения применяются как в интерфейсе Analytics, так и через Analytics API.

### Наследование ролей

- Роли, назначенные на уровне **аккаунта**, автоматически наследуются всеми ресурсами в этом аккаунте
- На уровне **ресурса** можно назначить более высокую роль (повышение), но нельзя понизить роль ниже уровня, установленного на уровне аккаунта
- Ограничения данных, установленные на уровне аккаунта, распространяются на все ресурсы и не могут быть сняты на уровне отдельного ресурса (но могут быть добавлены дополнительные ограничения)

## Функциональные требования

### Управление аккаунтом

#### FR-ADM-001: Создание аккаунта Google Analytics
**Priority**: P0-Critical

**Description**: Пользователь с Google-аккаунтом может создать новый аккаунт Google Analytics. При создании необходимо указать базовые параметры аккаунта и настроить Data Sharing.

**Acceptance Criteria**:
- [ ] Пользователь указывает имя аккаунта (Account Name)
- [ ] Пользователь выбирает страну бизнеса (Country of Business)
- [ ] Пользователь настраивает Data Sharing Settings (обмен данными с Google)
- [ ] При создании аккаунта автоматически создаётся первый ресурс (Property)
- [ ] Создатель аккаунта получает роль Administrator
- [ ] Аккаунту присваивается уникальный Account ID (числовой)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-001 | Один пользователь Google может создать до 100 аккаунтов Analytics |
| BR-ADM-002 | Имя аккаунта обязательно и может быть изменено позже |
| BR-ADM-003 | Страна бизнеса влияет на применяемые правила обработки данных (GDPR, CCPA и т.д.) |

---

#### FR-ADM-002: Настройки аккаунта (Account Details)
**Priority**: P0-Critical

**Description**: Администратор может просматривать и редактировать основные настройки аккаунта.

**Acceptance Criteria**:
- [ ] Отображается Account ID (только чтение)
- [ ] Редактируется Account Name
- [ ] Редактируется Country of Business
- [ ] Изменения сохраняются и фиксируются в Change History

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-004 | Для редактирования настроек аккаунта требуется роль Editor или выше на уровне аккаунта |
| BR-ADM-005 | Account ID не может быть изменён после создания |

---

#### FR-ADM-003: Настройки обмена данными (Data Sharing Settings)
**Priority**: P1-High

**Description**: Администратор управляет тем, как данные, собираемые Analytics, передаются в другие продукты и сервисы Google.

**Acceptance Criteria**:
- [ ] Переключатель "Google products & services" — разрешает Google использовать данные аккаунта для улучшения продуктов Google и предоставления инсайтов, предложений, рекомендаций
- [ ] Переключатель "Benchmarking" — агрегированные данные вносят вклад в индустриальные бенчмарки (данные анонимизированы, невозможно идентифицировать организацию)
- [ ] Переключатель "Technical support" — предоставляет доступ техническим специалистам Google к данным аккаунта для решения проблем
- [ ] Переключатель "Account specialists" — предоставляет доступ специалистам по продажам Google
- [ ] Настройки могут быть изменены в любое время

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-006 | Для изменения Data Sharing Settings требуется роль Editor или выше на уровне аккаунта |
| BR-ADM-007 | Настройки Data Sharing определяются при создании аккаунта и могут быть изменены позднее |
| BR-ADM-008 | Агрегированные данные для бенчмарков не содержат идентифицирующей информации |

---

#### FR-ADM-004: Удаление аккаунта
**Priority**: P1-High

**Description**: Администратор может пометить аккаунт для удаления. Аккаунт перемещается в корзину (Trash) и может быть восстановлен в течение 35 дней.

**Acceptance Criteria**:
- [ ] Аккаунт перемещается в Trash при удалении
- [ ] Все ресурсы (Properties) и потоки данных (Data Streams) аккаунта также перемещаются в Trash
- [ ] Аккаунт хранится в Trash 35 дней до окончательного удаления
- [ ] Сбор данных прекращается после перемещения в Trash
- [ ] Отображается предупреждение о последствиях удаления

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-009 | Для удаления аккаунта требуется роль Administrator на уровне аккаунта |
| BR-ADM-010 | После истечения 35 дней аккаунт и все данные удаляются безвозвратно |
| BR-ADM-011 | Историческая data не может быть восстановлена после окончательного удаления |

---

#### FR-ADM-005: Восстановление аккаунта из корзины
**Priority**: P1-High

**Description**: Администратор или редактор может восстановить аккаунт из корзины (Trash) в течение 35 дней после удаления.

**Acceptance Criteria**:
- [ ] В разделе Trash отображается список удалённых аккаунтов и ресурсов
- [ ] Доступен поиск по удалённым элементам
- [ ] При восстановлении аккаунта автоматически восстанавливаются все его ресурсы и потоки данных
- [ ] Сбор данных возобновляется после восстановления (при наличии активных тегов)
- [ ] Данные, собранные до удаления, сохраняются при восстановлении

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-012 | Для восстановления аккаунта/ресурса требуется роль Editor или выше на уровне аккаунта |
| BR-ADM-013 | Данные, которые должны были быть собраны в период нахождения в Trash, утрачены безвозвратно |

### Управление ресурсом (Property)

#### FR-ADM-006: Создание ресурса (Property)
**Priority**: P0-Critical

**Description**: В рамках аккаунта пользователь может создать новый ресурс GA4. При создании указываются основные параметры ресурса.

**Acceptance Criteria**:
- [ ] Пользователь указывает Property Name (имя ресурса)
- [ ] Пользователь выбирает Reporting Time Zone (часовой пояс для отчётов)
- [ ] Пользователь выбирает Currency (валюта для отображения в отчётах)
- [ ] Пользователь выбирает Industry Category (категория индустрии)
- [ ] Ресурсу присваивается уникальный Property ID (числовой)
- [ ] При создании ресурса запускается Setup Assistant с рекомендациями

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-014 | Один аккаунт может содержать до 2000 ресурсов |
| BR-ADM-015 | Для создания ресурса требуется роль Editor или выше на уровне аккаунта |
| BR-ADM-016 | Часовой пояс определяет границы дня для всех отчётов (изменение не применяется ретроактивно) |
| BR-ADM-017 | Валюта определяет отображение денежных метрик (изменение не применяется ретроактивно) |
| BR-ADM-018 | Категория индустрии используется для бенчмарков и рекомендаций |

---

#### FR-ADM-007: Настройки ресурса (Property Settings)
**Priority**: P0-Critical

**Description**: Редактор или администратор может просматривать и изменять основные настройки ресурса.

**Acceptance Criteria**:
- [ ] Отображается Property ID (только чтение)
- [ ] Редактируется Property Name
- [ ] Редактируется Industry Category
- [ ] Редактируется Reporting Time Zone
- [ ] Редактируется Currency
- [ ] Все изменения фиксируются в Change History

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-019 | Property ID не может быть изменён после создания |
| BR-ADM-020 | Изменение часового пояса влияет на отображение данных в отчётах, начиная с момента изменения (не ретроактивно) |
| BR-ADM-021 | Изменение валюты влияет на отображение денежных метрик с момента изменения |

---

#### FR-ADM-008: Удаление ресурса (Property)
**Priority**: P1-High

**Description**: Администратор может пометить ресурс для удаления. Ресурс перемещается в корзину (Trash).

**Acceptance Criteria**:
- [ ] Ресурс перемещается в Trash при удалении
- [ ] Все потоки данных (Data Streams) ресурса перемещаются в Trash вместе с ним
- [ ] Ресурс хранится в Trash 35 дней до окончательного удаления
- [ ] Сбор данных для ресурса прекращается
- [ ] При восстановлении ресурса восстанавливаются все его Data Streams

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-022 | Для удаления ресурса требуется роль Editor или выше |
| BR-ADM-023 | Удаление Data Stream (напрямую, не через ресурс) является необратимым — восстановление невозможно |
| BR-ADM-024 | Историческая data Data Stream сохраняется в ресурсе даже после удаления самого Data Stream |

---

#### FR-ADM-009: Subproperty (Подресурс, только 360)
**Priority**: P2-Medium

**Description**: Пользователь Google Analytics 360 может создать подресурс (Subproperty), содержащий подмножество данных исходного ресурса (Source Property). Subproperty заменяет концепцию Views из Universal Analytics.

**Acceptance Criteria**:
- [ ] Subproperty создаётся на основе Source Property
- [ ] Настраиваются фильтры для определения подмножества данных, попадающих в Subproperty
- [ ] Subproperty имеет собственный Property ID
- [ ] Subproperty поддерживает собственные настройки пользователей, аудиторий и отчётов
- [ ] Нельзя создать Subproperty из Roll-up Property

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-025 | Функция доступна только для Google Analytics 360 |
| BR-ADM-026 | Каждое событие, обработанное в Subproperty, тарифицируется дополнительно (0.5 от стоимости исходного события) |
| BR-ADM-027 | Subproperty наследует данные Source Property с применением фильтров |

---

#### FR-ADM-010: Roll-up Property (Объединяющий ресурс, только 360)
**Priority**: P2-Medium

**Description**: Пользователь Google Analytics 360 может создать Roll-up Property, агрегирующий данные из нескольких ресурсов для обеспечения кросс-продуктового или кросс-регионального анализа.

**Acceptance Criteria**:
- [ ] Roll-up Property объединяет данные из двух или более ресурсов
- [ ] В Roll-up Property могут входить обычные ресурсы и Subproperties
- [ ] Roll-up Property не может включать другие Roll-up Properties
- [ ] Roll-up Property имеет собственный Property ID и настройки

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-028 | Функция доступна только для Google Analytics 360 |
| BR-ADM-029 | Каждое событие, обработанное в Roll-up Property, тарифицируется дополнительно (0.5 от стоимости исходного события) |
| BR-ADM-030 | Все включённые ресурсы должны находиться в одном аккаунте |

### Управление пользователями и правами доступа

#### FR-ADM-011: Управление доступом на уровне аккаунта (Account Access Management)
**Priority**: P0-Critical

**Description**: Администратор аккаунта управляет списком пользователей, их ролями и ограничениями данных на уровне аккаунта.

**Acceptance Criteria**:
- [ ] Отображается список всех пользователей аккаунта с их email, ролями и ограничениями данных
- [ ] Администратор может добавить нового пользователя по email (Google-аккаунт)
- [ ] Администратор может назначить одну из четырёх ролей (Administrator, Editor, Analyst, Viewer)
- [ ] Администратор может назначить ограничения данных (No Revenue Metrics, No Cost Metrics или оба)
- [ ] Администратор может изменить роль существующего пользователя
- [ ] Администратор может удалить пользователя из аккаунта
- [ ] Роль, назначенная на уровне аккаунта, автоматически наследуется всеми ресурсами

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-031 | Для управления пользователями на уровне аккаунта требуется роль Administrator на уровне аккаунта |
| BR-ADM-032 | Аккаунт должен иметь минимум одного пользователя с ролью Administrator |
| BR-ADM-033 | Пользователь не может удалить собственную роль Administrator, если он является единственным администратором |
| BR-ADM-034 | Приглашённый пользователь должен иметь действующий Google-аккаунт |

---

#### FR-ADM-012: Управление доступом на уровне ресурса (Property Access Management)
**Priority**: P0-Critical

**Description**: Администратор ресурса управляет списком пользователей, их ролями и ограничениями данных на уровне конкретного ресурса.

**Acceptance Criteria**:
- [ ] Отображается список пользователей ресурса с их ролями (включая унаследованные с уровня аккаунта)
- [ ] Администратор ресурса может добавить нового пользователя (только к данному ресурсу)
- [ ] Администратор ресурса может назначить роль пользователю на уровне ресурса
- [ ] Роль на уровне ресурса может быть выше, чем на уровне аккаунта (повышение)
- [ ] Роль на уровне ресурса не может быть ниже, чем на уровне аккаунта
- [ ] Дополнительные ограничения данных могут быть добавлены на уровне ресурса
- [ ] Ограничения данных, установленные на уровне аккаунта, не могут быть сняты на уровне ресурса

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-035 | Для управления пользователями на уровне ресурса требуется роль Administrator на уровне ресурса |
| BR-ADM-036 | Пользователь, имеющий роль Administrator на уровне аккаунта, автоматически является Administrator для всех ресурсов |
| BR-ADM-037 | Наследование ролей однонаправленное: аккаунт -> ресурс (повышение возможно, понижение — нет) |

---

#### FR-ADM-013: Управление группами пользователей
**Priority**: P2-Medium

**Description**: Администратор может назначать роли и ограничения группам пользователей через Google Groups для упрощения массового управления доступом.

**Acceptance Criteria**:
- [ ] Можно добавить Google Group как пользователя аккаунта/ресурса
- [ ] Всем участникам группы назначается указанная роль и ограничения
- [ ] Изменение членства в Google Group автоматически влияет на доступ в Analytics

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-038 | Google Group получает роль как единый пользователь |
| BR-ADM-039 | Индивидуальная роль пользователя имеет приоритет над ролью группы, если она выше |

### Настройки сбора данных (Data Collection)

#### FR-ADM-014: Google Signals
**Priority**: P1-High

**Description**: Администратор или редактор ресурса может активировать Google Signals — функцию, обеспечивающую кросс-девайсную аналитику на основе данных пользователей, авторизованных в Google и включивших Ads Personalization.

**Acceptance Criteria**:
- [ ] Переключатель включения/отключения Google Signals на уровне ресурса
- [ ] При включении собираются данные сессий пользователей, авторизованных в Google
- [ ] Обеспечивается кросс-девайсное отслеживание (один пользователь на нескольких устройствах)
- [ ] Данные Google Signals используются для cross-device remarketing
- [ ] Настройка Ads Personalization по странам/регионам — возможность отключить персонализацию рекламы для определённых стран
- [ ] Если Ads Personalization отключена для региона, Google Signals собирает данные только для целей измерения

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-040 | Для активации Google Signals требуется роль Editor или выше на уровне ресурса |
| BR-ADM-041 | Данные Google Signals по умолчанию хранятся 26 месяцев, но подчиняются более короткому периоду Data Retention, если он установлен |
| BR-ADM-042 | При малом объёме данных отчёты могут быть подвержены thresholding (порог агрегации) для защиты идентификации пользователей |

---

#### FR-ADM-015: Настройки согласия (Consent Settings)
**Priority**: P1-High

**Description**: Администратор настраивает параметры Consent Mode v2 для соответствия GDPR и другим регуляторным требованиям.

**Acceptance Criteria**:
- [ ] Настройка значений по умолчанию для consent-сигналов: analytics_storage, ad_storage, ad_user_data, ad_personalization
- [ ] Каждый сигнал может быть Granted или Denied по умолчанию
- [ ] Управление списком Google-сервисов, которые могут получать данные пользователей с согласием (для EEA)
- [ ] При наличии достаточного объёма данных включается behavioral modeling (моделирование поведения пользователей, не давших согласие)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-043 | Consent Mode v2 требует два новых сигнала: ad_user_data и ad_personalization |
| BR-ADM-044 | Behavioral modeling активируется автоматически, если ресурс получает достаточно трафика с consent-сигналами |

### Удаление данных (Data Deletion)

#### FR-ADM-017: Запросы на удаление данных
**Priority**: P1-High

**Description**: Редактор может создавать запросы на удаление текстовых данных, собранных event-параметрами, за указанный период. Это используется для удаления случайно собранных персональных данных (PII) или некорректных данных.

**Acceptance Criteria**:
- [ ] Создание запроса на удаление данных (Schedule Data Deletion Request)
- [ ] Указание временного диапазона данных для удаления
- [ ] Выбор типов параметров для удаления (все event parameters, registered event parameters, user properties, или конкретные параметры)
- [ ] Отображение списка всех запросов на удаление с их статусами
- [ ] Preview period — предварительный период перед фактическим удалением
- [ ] Grace period (первые 7 дней Preview) — возможность отмены запроса
- [ ] Текстовые данные заменяются на "(data deleted)", но само событие сохраняется в метриках

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-051 | Для создания запроса на удаление данных требуется роль Editor |
| BR-ADM-052 | Grace period: первые 7 дней — запрос может быть отменён пользователями с ролью Editor |
| BR-ADM-053 | С 8-го дня Preview начинается фактическое удаление, отмена невозможна |
| BR-ADM-054 | Удаление затрагивает текстовые значения параметров событий; числовые метрики и подсчёт событий сохраняются |
| BR-ADM-055 | Удалённые данные невозможно восстановить |

#### Статусы запроса на удаление данных

| Статус | Описание |
|--------|----------|
| **Scheduled** | Запрос создан, ожидает начала Preview |
| **Preview active (Grace period)** | Дни 1-7: данные помечены, запрос можно отменить |
| **Preview active / Deletion in progress** | С 8-го дня: начался процесс удаления, отмена невозможна |
| **Completed** | Удаление завершено |
| **Cancelled** | Запрос отменён в течение Grace period |

**Description**: Администратор управляет корзиной, содержащей аккаунты и ресурсы, помеченные для удаления.

**Acceptance Criteria**:
- [ ] Отображение списка всех удалённых аккаунтов и ресурсов
- [ ] Отображение даты удаления и оставшегося времени до окончательного удаления
- [ ] Поиск по удалённым элементам
- [ ] Восстановление элементов из корзины
- [ ] Корзина доступна в разделе Admin на уровне аккаунта

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ADM-098 | Элементы хранятся в корзине 35 дней |
| BR-ADM-099 | После 35 дней — необратимое удаление |
| BR-ADM-100 | Сбор данных прекращается в момент перемещения в корзину |
| BR-ADM-101 | Восстановление ресурса автоматически восстанавливает все его Data Streams |

## Состояния и статусы

### Жизненный цикл аккаунта / ресурса

```
[Created] --> (Active) --> [Move to Trash] --> (Trashed)
                                                  |
                                      [35 дней]   |   [Restore]
                                                  v        |
                                            (Deleted)   (Active)
                                          [необратимо]
```

| Состояние | Описание |
|-----------|----------|
| **Active** | Аккаунт/ресурс активен, данные собираются, отчёты доступны |
| **Trashed** | Перемещён в корзину; сбор данных прекращён; восстановление возможно в течение 35 дней |
| **Deleted** | Окончательно удалён; все данные и конфигурация потеряны безвозвратно |

### Жизненный цикл запроса на удаление данных

```
[Create Request] --> (Scheduled) --> (Preview - Grace Period, дни 1-7)
                                          |
                    [Cancel] <---         |
                        |                 v
                   (Cancelled)    (Preview - Deletion in Progress, день 8+)
                                          |
                                          v
                                     (Completed)
```

### Состояния фильтра данных

```
[Create] --> (Inactive) <--> (Testing) <--> (Active)
                ^                               |
                |-------------------------------|
```

## Интеграции с другими модулями

### Связь с модулем "Сбор данных и Data Streams"
- Административные настройки ресурса определяют конфигурацию Data Streams (веб, iOS, Android)
- Data Filters применяются к данным, поступающим через все Data Streams ресурса
- Enhanced Measurement настраивается на уровне Data Stream, но администрируется через Admin
- Удаление ресурса влечёт удаление всех Data Streams

### Связь с модулем "Отчёты и Explorations"
- Attribution Settings определяют распределение кредита конверсий во всех отчётах
- Reporting Identity влияет на подсчёт пользователей и сессий в отчётах
- Channel Grouping определяет классификацию источников трафика в Acquisition-отчётах
- Data Retention ограничивает временной диапазон данных, доступных в Explorations
- Data Restrictions (No Revenue / No Cost) скрывают соответствующие метрики из отчётов для конкретных пользователей

### Связь с модулем "Аудитории и сегменты"
- Ограничение на 100 аудиторий (стандартный) / 400 (360) определяется на уровне ресурса
- Аудитории экспортируются в Google Ads через Product Linking
- Google Signals влияет на полноту данных для построения аудиторий

### Связь с модулем "Конверсии и события"
- Лимит конверсий (30 / 50) определяется на уровне ресурса
- Data Deletion Requests могут удалить текстовые данные event-параметров
- Data Filters могут исключить определённые события из отчётов

### Связь с модулем "Рекламная интеграция"
- Google Ads Linking обеспечивает двусторонний обмен данными
- Attribution Settings определяют, как конверсии из Google Ads атрибутируются в отчётах
- Lookback Windows влияют на период учёта рекламных касаний

### Связь с модулем "BigQuery Export"
- BigQuery Linking настраивается в Admin > Product Linking
- Тип экспорта (Daily / Streaming) определяет задержку данных
- Настройки Data Retention не влияют на данные, экспортированные в BigQuery (они хранятся в BigQuery по его правилам)

### Связь с модулем "Consent и Privacy"
- Consent Settings определяют, какие данные собираются в зависимости от согласия пользователя
- Google Signals подчиняется настройкам Ads Personalization по регионам
- Data Sharing Settings контролируют передачу данных в продукты Google

### Связь с модулем "Монетизация и E-commerce"
- Data Restrictions (No Revenue Metrics) скрывают данные о доходе для определённых пользователей
- Merchant Center Linking обеспечивает передачу данных о товарных конверсиях
- Currency Settings влияют на отображение всех денежных метрик
