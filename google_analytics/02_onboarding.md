## Глоссарий

| Термин | Определение |
|--------|-------------|
| Аккаунт (Account) | Верхний уровень иерархии GA4. Организационная единица для управления одним или несколькими ресурсами. Обычно соответствует компании или организации |
| Ресурс (Property) | Контейнер для сбора и отчётности данных. Объединяет данные с сайтов и приложений. Содержит потоки данных, отчёты и настройки |
| Поток данных (Data Stream) | Канал передачи данных из источника (сайт или приложение) в ресурс GA4. Каждому источнику соответствует отдельный поток |
| Measurement ID | Уникальный идентификатор веб-потока данных (формат: G-XXXXXXXXXX). Используется в теге отслеживания |
| Google Tag (gtag.js) | JavaScript-сниппет, устанавливаемый на сайт для сбора данных и отправки в GA4 |
| Google Tag Manager (GTM) | Система управления тегами, позволяющая устанавливать и управлять тегами без изменения кода сайта |
| Enhanced Measurement | Набор автоматических событий, которые GA4 отслеживает без дополнительной настройки (скроллы, клики по исходящим ссылкам, поиск по сайту и др.) |
| Ключевое событие (Key Event) | Событие, отмеченное как важное для бизнеса (ранее называлось "конверсия"). Используется для измерения достижения бизнес-целей |
| Конверсия (Conversion) | В текущей терминологии GA4 --- ключевое событие, используемое для оптимизации рекламных кампаний в Google Ads |
| Google Signals | Функция, расширяющая сбор данных за счёт информации о пользователях, авторизованных в Google-аккаунтах с включенной персонализацией рекламы |
| Consent Mode | Механизм адаптации сбора данных к согласию пользователя на обработку cookies и персональных данных |
| Data Filter | Правило фильтрации данных на уровне ресурса (например, исключение внутреннего трафика) |
| DebugView | Инструмент отладки в GA4, показывающий поступающие события в реальном времени для конкретного устройства |
| Realtime Report | Отчёт в реальном времени, отображающий активность пользователей за последние 30 минут |
| Setup Assistant | Встроенный помощник настройки в GA4, предоставляющий чеклист рекомендуемых действий для завершения конфигурации ресурса |
| Attribution Model | Модель распределения ценности конверсии между различными каналами и точками касания пользователя |
| Data-Driven Attribution | Модель атрибуции по умолчанию в GA4, использующая машинное обучение для распределения ценности между точками касания |
| Reporting Identity | Метод идентификации пользователей в отчётах: по User-ID, по Google Signals, по Device-ID или комбинация (Blended) |
| Roll-up Property | Свойство GA4 360, агрегирующее данные из нескольких ресурсов в один |
| Sub-property | Свойство GA4 360, содержащее подмножество данных из основного ресурса |
| Cross-domain Tracking | Отслеживание пользователя при переходе между разными доменами как единого сеанса |

## Роли и права

| Роль | Описание | Права в контексте онбординга |
|------|----------|------------------------------|
| Администратор (Administrator) | Полный контроль над аккаунтом или ресурсом | Создание аккаунтов и ресурсов, управление пользователями и их ролями, настройка всех параметров, создание и удаление потоков данных, настройка фильтров данных, управление интеграциями |
| Редактор (Editor) | Управление настройками без управления пользователями | Создание ресурсов и потоков данных, настройка Enhanced Measurement, создание ключевых событий, настройка фильтров и хранения данных, настройка интеграций. Не может управлять пользователями и их ролями |
| Маркетолог (Marketer) | Управление аудиториями, конверсиями и атрибуцией | Создание и управление аудиториями, управление ключевыми событиями, настройка моделей атрибуции. Не может создавать потоки данных или фильтры |
| Аналитик (Analyst) | Создание и редактирование общих отчётов | Создание и редактирование исследований (explorations), работа с общими отчётами и дашбордами. Не может изменять настройки ресурса |
| Наблюдатель (Viewer) | Только просмотр данных | Просмотр отчётов и дашбордов, просмотр настроек (без изменения). Не может редактировать, создавать или удалять ничего |
| Владелец Google-аккаунта | Пользователь с Google-аккаунтом, инициирующий создание GA4 | Создание первого аккаунта Analytics, автоматическое получение роли Администратора на созданном аккаунте |

### Ограничения доступа по данным

| Ограничение | Описание |
|-------------|----------|
| Без ограничений по стоимости (No cost metrics restriction) | Доступ ко всем метрикам, включая данные о доходах и стоимости |
| Без ограничений по доходу (No revenue metrics restriction) | Доступ к метрикам доходов |
| Ограниченный по стоимости | Скрыты метрики, связанные со стоимостью привлечения |
| Ограниченный по доходу | Скрыты метрики, связанные с доходами |

### Наследование ролей

| Правило | Описание |
|---------|----------|
| Иерархическое наследование | Роль, назначенная на уровне аккаунта, автоматически распространяется на все ресурсы этого аккаунта |
| Повышение на уровне ресурса | На уровне конкретного ресурса можно назначить более высокую роль, чем роль на уровне аккаунта |
| Запрет понижения | Нельзя назначить на уровне ресурса более низкую роль, чем роль на уровне аккаунта |

## Обзор модуля

Модуль "Онбординг и начальная настройка" охватывает полный путь пользователя от создания аккаунта Google Analytics до момента, когда данные начинают корректно собираться и отображаться в отчётах. Цель модуля --- обеспечить быстрый, последовательный и корректный запуск аналитики для сайтов и мобильных приложений.

### Ключевые метрики модуля

| Метрика | Описание |
|---------|----------|
| Time to First Data | Время от создания потока данных до получения первого события в Realtime-отчёте |
| Setup Completion Rate | Доля пользователей, завершивших все шаги Setup Assistant |
| Tag Installation Success Rate | Доля потоков данных, для которых успешно установлен и верифицирован тег |
| Data Collection Verification Rate | Доля ресурсов, прошедших проверку корректности сбора данных |
| Enhanced Measurement Adoption Rate | Доля потоков данных с активированным Enhanced Measurement |
| Key Event Setup Rate | Доля ресурсов, в которых настроен хотя бы один Key Event |
| Internal Traffic Filter Adoption | Доля ресурсов с настроенным фильтром внутреннего трафика |
| Google Ads Linking Rate | Доля ресурсов, связанных с аккаунтом Google Ads |

## 1. Создание аккаунта Google Analytics

### FR-ONB-001: Создание нового аккаунта Analytics
**Priority**: P0-Critical

**Описание**: Система предоставляет возможность создать новый аккаунт Google Analytics. Аккаунт --- верхний уровень иерархии, объединяющий ресурсы (properties). Для создания аккаунта пользователь должен быть авторизован в Google-аккаунте.

**User Story**: Как владелец бизнеса, я хочу создать аккаунт Google Analytics, чтобы начать отслеживать поведение пользователей на моих сайтах и в приложениях.

**Сценарий**:
1. Пользователь переходит на analytics.google.com
2. Если у пользователя нет аккаунтов GA --- отображается экран приветствия с кнопкой "Начать измерение" (Start measuring)
3. Если есть аккаунты GA --- пользователь переходит в Admin > "+ Создать" > "Аккаунт"
4. Пользователь вводит название аккаунта
5. Пользователь настраивает параметры обмена данными (Account Data Sharing Settings)
6. Пользователь нажимает "Далее" и переходит к созданию ресурса

**Acceptance Criteria**:
- [ ] Пользователь может ввести произвольное название аккаунта
- [ ] Отображаются настройки обмена данными с чекбоксами
- [ ] Аккаунт не создаётся до завершения создания первого ресурса (аккаунт и ресурс создаются атомарно)
- [ ] После создания пользователь автоматически получает роль Администратора на аккаунте
- [ ] Название аккаунта можно изменить после создания

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ONB-001 | Максимум 100 аккаунтов Analytics на один Google-аккаунт |
| BR-ONB-002 | Название аккаунта обязательно и не может быть пустым |
| BR-ONB-003 | Для создания аккаунта требуется действующий Google-аккаунт |
| BR-ONB-004 | Создатель аккаунта автоматически становится Администратором |

---

### FR-ONB-002: Настройки обмена данными аккаунта
**Priority**: P1-High

**Описание**: При создании аккаунта пользователь настраивает, какими данными аккаунт будет делиться с Google. Эти настройки влияют на доступность определённых функций (например, бенчмаркинг).

**User Story**: Как администратор, я хочу контролировать, какие данные мой аккаунт Analytics передаёт Google, чтобы соответствовать политике конфиденциальности компании.

**Параметры обмена данными**:

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| Google products & services | Обмен данными с другими продуктами Google для улучшения сервисов | Включено |
| Benchmarking | Анонимный обмен данными для сравнения с аналогичными компаниями в отрасли | Включено |
| Technical support | Доступ службы технической поддержки к данным аккаунта | Включено |
| Account specialists | Доступ специалистов Google к данным для рекомендаций по оптимизации | Включено |

**Acceptance Criteria**:
- [ ] Каждый параметр представлен чекбоксом с описанием
- [ ] По умолчанию все параметры включены
- [ ] Пользователь может отключить любой параметр
- [ ] Настройки можно изменить после создания аккаунта в разделе Admin > Account Settings

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ONB-005 | Отключение "Benchmarking" делает недоступными отчёты по сравнению с отраслью |
| BR-ONB-006 | Настройки обмена данными применяются ко всем ресурсам в аккаунте |
| BR-ONB-007 | Только Администратор аккаунта может изменять настройки обмена данными |

## 2. Создание ресурса (Property)

### FR-ONB-003: Создание ресурса GA4
**Priority**: P0-Critical

**Описание**: После создания аккаунта (или в рамках существующего аккаунта) пользователь создаёт ресурс --- основную единицу сбора и отчётности данных в GA4. На этом этапе указываются базовые характеристики ресурса.

**User Story**: Как маркетолог, я хочу создать ресурс GA4 для моего сайта, чтобы начать собирать и анализировать данные о поведении пользователей.

**Сценарий**:
1. После ввода данных аккаунта пользователь переходит к шагу "Property details"
2. Вводит название ресурса (Property name)
3. Выбирает часовой пояс отчётности (Reporting time zone)
4. Выбирает валюту (Currency)
5. Нажимает "Далее" для перехода к описанию бизнеса

**Acceptance Criteria**:
- [ ] Поле названия ресурса обязательно для заполнения
- [ ] Список часовых поясов содержит все часовые пояса мира
- [ ] Список валют содержит все основные валюты мира
- [ ] Часовой пояс по умолчанию определяется по геолокации пользователя
- [ ] Валюта по умолчанию определяется по геолокации пользователя
- [ ] Часовой пояс и валюту можно изменить после создания ресурса

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ONB-008 | Максимум 2 000 ресурсов на один аккаунт Analytics |
| BR-ONB-009 | Название ресурса обязательно |
| BR-ONB-010 | Часовой пояс определяет формат дат в отчётах и границы суток для агрегации данных |
| BR-ONB-011 | Валюта определяет денежную единицу в отчётах о доходах. Изменение не конвертирует исторические данные |
| BR-ONB-012 | Изменение часового пояса применяется только к будущим данным, исторические данные не пересчитываются |

## 3. Выбор бизнес-целей

### FR-ONB-005: Выбор бизнес-целей (Business Objectives)
**Priority**: P0-Critical

**Описание**: Пользователь выбирает одну или несколько бизнес-целей, определяющих, как он планирует использовать Google Analytics. На основании выбора система формирует персонализированный набор отчётов (Business Objectives Collection) и рекомендуемые конфигурации.

**User Story**: Как маркетинг-менеджер, я хочу указать бизнес-цели компании, чтобы Google Analytics предоставил мне наиболее релевантные отчёты и рекомендации.

**Сценарий**:
1. После указания информации о бизнесе пользователь переходит к шагу "Business objectives"
2. Отображается список бизнес-целей с чекбоксами
3. Пользователь выбирает одну или несколько целей
4. Нажимает "Создать" (Create)

**Доступные бизнес-цели**:

| Цель | Описание | Связанные отчёты и рекомендации |
|------|----------|--------------------------------|
| Generate leads | Генерация лидов и контактов | Отчёты по формам, звонкам; рекомендуемые аудитории "Likely to contact" |

## 9. Фильтрация внутреннего трафика

### FR-ONB-020: Определение внутреннего трафика
**Priority**: P1-High

**Описание**: Пользователь определяет IP-адреса, которые относятся к внутреннему трафику (сотрудники, офис, разработчики). События от этих IP-адресов помечаются параметром traffic_type.

**User Story**: Как администратор, я хочу исключить трафик сотрудников из отчётов, чтобы данные отражали только реальных пользователей.

**Сценарий**:
1. Пользователь переходит в Admin > Data Streams > выбирает веб-поток
2. Открывает "Configure tag settings" > "Define internal traffic"
3. Нажимает "Create"
4. Вводит название правила (Rule name)
5. Задаёт значение параметра traffic_type (по умолчанию "internal")
6. Указывает IP-адрес или диапазон IP-адресов
7. Выбирает тип совпадения (Match type)

**Типы совпадения IP-адресов**:

| Тип | Описание | Пример |
|-----|----------|--------|
| IP address equals | Точное совпадение с одним IP | 192.168.1.1 |
| IP address begins with | Совпадение по началу IP | 192.168.1. |
| IP address ends with | Совпадение по окончанию IP | .1.1 |
| IP address contains | Содержит подстроку в IP | 168.1 |
| IP address is in range (CIDR) | Диапазон в формате CIDR | 192.168.1.0/24 |
| IP address is in range | Диапазон IP-адресов | 192.168.1.1--192.168.1.255 |

**Acceptance Criteria**:
- [ ] Можно создать несколько правил внутреннего трафика
- [ ] Поддерживаются IPv4 и IPv6
- [ ] Поддерживается CIDR-нотация для диапазонов
- [ ] Правила можно редактировать и удалять после создания

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ONB-069 | Определение внутреннего трафика только помечает события, но не исключает их --- для исключения нужен Data Filter |
| BR-ONB-070 | Правила применяются ко всем веб-потокам ресурса |
| BR-ONB-071 | Изменения вступают в силу для новых событий немедленно |

### FR-ONB-021: Создание фильтра данных для исключения внутреннего трафика
**Priority**: P1-High

**Описание**: После определения внутреннего трафика пользователь создаёт фильтр данных, который исключает (или включает только) события с параметром traffic_type из отчётов.

**User Story**: Как аналитик, я хочу активировать фильтр внутреннего трафика, чтобы в отчётах отображались только данные реальных пользователей.

**Сценарий**:

3. Пользователь может оставить фильтр в режиме тестирования для проверки
4. После проверки переводит фильтр в состояние "Active"

**Состояния фильтра данных**:

| Состояние | Описание |
|-----------|----------|

- [ ] Фильтр можно перевести из Testing в Active
- [ ] В режиме Testing можно проверить, какие данные будут затронуты
- [ ] Активный фильтр необратимо удаляет данные из обработки

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ONB-072 | Максимум 10 фильтров данных на ресурс |
| BR-ONB-073 | Активный фильтр действует необратимо --- исключённые данные никогда не будут обработаны и не попадут в отчёты или BigQuery |
| BR-ONB-074 | Рекомендуется держать фильтр в режиме Testing минимум 7 дней перед активацией |
| BR-ONB-075 | Фильтр начинает полностью работать через 24--48 часов после активации |

### FR-ONB-024: Настройка Consent Mode
**Priority**: P1-High

**Описание**: Consent Mode адаптирует поведение Google-тегов в зависимости от согласия пользователя на обработку cookies. Необходим для соответствия GDPR, CCPA и другим нормативным требованиям.

**User Story**: Как администратор сайта в ЕС, я хочу настроить Consent Mode, чтобы GA4 корректно работал с баннером согласия и не нарушал требования GDPR.

**Параметры согласия (Consent Signals)**:

| Параметр | Описание | Значения |
|----------|----------|----------|

| ad_storage | Согласие на хранение рекламных cookies | granted / denied |
| ad_user_data | Согласие на отправку пользовательских данных в Google для рекламы | granted / denied |
| ad_personalization | Согласие на персонализацию рекламы | granted / denied |

**Acceptance Criteria**:

- [ ] При отсутствии сигналов согласия --- отображается предупреждение
- [ ] Поведенческое моделирование (behavioral modeling) доступно при достаточном объёме данных

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ONB-085 | При analytics_storage = denied GA4 отправляет ping-запросы без cookies для базового моделирования |
| BR-ONB-086 | Поведенческое моделирование (behavioral modeling) активируется автоматически при наличии достаточного объёма данных с обоими состояниями (granted и denied) |
| BR-ONB-087 | Consent Mode необходим для легального сбора данных в ЕЭЗ и других регионах с требованиями к согласию |
| BR-ONB-088 | Для Consent Mode v2 обязательна передача всех четырёх параметров согласия |

4. Добавляет домены, которые должны быть связаны
5. Для каждого домена выбирает тип совпадения (contains, starts with, ends with, equals, regex)

- [ ] Максимум 100 условий (conditions)

**Business Rules**:

### FR-ONB-027: Настройка Reporting Identity
**Priority**: P2-Medium

**Описание**: Reporting Identity определяет, как GA4 идентифицирует и объединяет данные пользователей в отчётах. Влияет на точность подсчёта уникальных пользователей и кросс-девайс отслеживание.

**User Story**: Как аналитик, я хочу настроить метод идентификации пользователей, чтобы получать наиболее точные данные о количестве уникальных пользователей.

## Состояния и статусы

### Состояния ресурса (Property)

```
[Создание] --> [Настройка] --> [Активный (данные поступают)] --> [Активный (полная настройка)]
                    |                                                       |
                    v                                                       v
            [Нет данных (тег не установлен)]                   [Удалён (в корзине, 35 дней)]
                    |                                                       |
                    v                                                       v
            [Предупреждение (нет данных > 24ч)]                  [Удалён окончательно]
```

| Состояние | Описание | Переход |
|-----------|----------|---------|
| Создание | Ресурс создаётся --- ввод базовой информации | Автоматический переход в "Настройка" |
| Настройка | Ресурс создан, но нет потоков данных или тег не установлен | Переход в "Активный" после получения первого события |
| Нет данных | Поток создан, но данные не поступают (тег не установлен или ошибка) | Переход в "Активный" после получения данных; Предупреждение после 24ч |
| Активный (данные поступают) | Данные поступают, базовая настройка минимальна | Переход в "Полная настройка" при выполнении всех шагов Setup Assistant |
| Активный (полная настройка) | Все рекомендуемые шаги Setup Assistant выполнены | Стабильное состояние |
| Удалён (в корзине) | Ресурс перемещён в корзину; данные перестают собираться | Восстановление в течение 35 дней или окончательное удаление |
| Удалён окончательно | Ресурс удалён безвозвратно | Терминальное состояние |

## Интеграции с другими модулями

### Внутренние модули GA4

| Модуль | Связь с онбордингом |
|--------|---------------------|
| Отчёты и аналитика (Reports) | Онбординг определяет набор доступных отчётов через бизнес-цели. Настройка ключевых событий влияет на содержимое отчётов по конверсиям. Хранение данных определяет глубину данных в Explorations |
| Аудитории и сегменты (Audiences) | Бизнес-цели определяют рекомендуемые аудитории. Google Signals расширяет данные для аудиторий. Ключевые события используются как условия для аудиторий |
| Реклама и монетизация (Advertising) | Привязка Google Ads --- ключевой шаг онбординга. Ключевые события импортируются как конверсии в Google Ads. Модель атрибуции влияет на оценку рекламных каналов |
| Исследования (Explorations) | Период хранения данных определяет доступную глубину данных в исследованиях. Enhanced Measurement формирует базовый набор доступных событий |
| Настройки конфиденциальности (Privacy) | Consent Mode определяет объём собираемых данных. Data Sharing Settings влияют на доступность бенчмаркинга |
| Администрирование (Admin) | Управление пользователями и ролями --- часть онбординга. Setup Assistant --- центральный инструмент онбординга |
