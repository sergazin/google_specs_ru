# Google Analytics (GA4): Модуль "Аудитории и сегменты"

## 1. Описание

Модуль "Аудитории и сегменты" в Google Analytics 4 предоставляет инструменты для группировки пользователей по поведению, характеристикам, событиям и предиктивным метрикам. Модуль решает две ключевые задачи:

1. **Аудитории (Audiences)** — постоянные группы пользователей, которые автоматически обновляются, используются для анализа в стандартных отчётах и автоматически экспортируются в связанные рекламные платформы (Google Ads, Display & Video 360, Search Ads 360) для ремаркетинга.

2. **Сегменты (Segments)** — временные подмножества данных, доступные исключительно в модуле "Исследования" (Explorations), позволяющие сравнивать группы пользователей, сессий или событий без влияния на рекламные платформы.

**Ключевое различие:** Аудитории — это глобальные объекты на уровне ресурса (property), которые накапливают пользователей в реальном времени и доступны во всех отчётах и интеграциях. Сегменты — локальные объекты внутри конкретного исследования (exploration), не сохраняются за его пределами и не экспортируются.

---

## 2. Роли пользователей

| Роль | Права в модуле |
|------|---------------|
| **Администратор (Administrator)** | Полный доступ: создание, редактирование, архивирование, удаление аудиторий; управление связями с рекламными платформами; настройка Google Signals; управление триггерами аудиторий |
| **Редактор (Editor)** | Создание, редактирование и архивирование аудиторий; создание триггеров аудиторий; настройка экспорта в рекламные платформы |
| **Аналитик (Analyst)** | Просмотр аудиторий; создание и использование сегментов в Explorations; просмотр отчётов по аудиториям |
| **Зритель (Viewer)** | Только просмотр: доступ к отчётам по аудиториям; невозможность создания/редактирования аудиторий или сегментов |
| **Без доступа (No Access)** | Нет доступа к данным модуля |

**Бизнес-правило:** Для создания аудиторий с экспортом в Google Ads пользователь должен иметь роль Редактор или выше в GA4, а также административный доступ к связанному аккаунту Google Ads.

## 3. Функциональные требования

### 3.1 Аудитории: Создание и конфигурация

---

### FR-AUD-001: Создание пользовательской аудитории (Custom Audience)

**Приоритет:** P0-Critical

**Описание:** Система позволяет создавать пользовательские аудитории на основе комбинации условий, включающих события (events), параметры событий (event parameters), свойства пользователей (user properties), размерности (dimensions) и метрики (metrics).

**Acceptance Criteria:**
- [ ] Пользователь с ролью Редактор или выше может создать новую аудиторию
- [ ] При создании система запрашивает: название аудитории (до 100 символов), описание (до 1000 символов)
- [ ] Условия группируются в блоки условий (condition groups), внутри которых поддерживаются операторы AND и OR
- [ ] Между блоками условий поддерживается операция AND
- [ ] Каждое условие может строиться на основе: события, параметра события, свойства пользователя, размерности или метрики
- [ ] Система показывает оценочный размер аудитории (estimated audience size) на основе данных за последние 30 дней
- [ ] После сохранения аудитория начинает наполняться пользователями, соответствующими условиям

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-001 | Максимум 100 аудиторий на ресурс (property) для стандартных аккаунтов |
| BR-AUD-002 | Максимум 400 аудиторий на ресурс для аккаунтов GA4 360 |
| BR-AUD-003 | Название аудитории должно быть уникальным в рамках ресурса |
| BR-AUD-004 | Аудитория начинает наполняться с момента создания; также заполняется ретроспективно за последние 30 дней данными пользователей, соответствующих условиям |

---

### FR-AUD-002: Область действия условий (Condition Scoping)

**Приоритет:** P0-Critical

**Описание:** Каждый блок условий аудитории имеет настраиваемую область действия (scope), определяющую, как условия оцениваются относительно данных пользователя.

**Acceptance Criteria:**
- [ ] Для каждого блока условий доступен выбор области действия из трёх вариантов
- [ ] Область "Across all sessions" (Во всех сессиях): условия оцениваются по совокупности всех данных пользователя за период membership duration. Условия A и B не обязаны выполняться в одной сессии или одном событии
- [ ] Область "Within the same session" (В рамках одной сессии): все условия блока должны быть выполнены в одной и той же сессии
- [ ] Область "Within the same event" (В рамках одного события): все условия блока должны быть выполнены в одном событии
- [ ] Изменение области действия влияет на оценочный размер аудитории

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-005 | Область "Across all sessions" — наиболее широкая; область "Within the same event" — наиболее узкая |
| BR-AUD-006 | Для разных блоков условий внутри одной аудитории могут быть установлены разные области действия |
| BR-AUD-007 | При области "Within the same session" — если пользователь удовлетворяет условиям хотя бы в одной сессии, он включается в аудиторию |

---

### FR-AUD-003: Условия на основе событий

**Приоритет:** P0-Critical

**Описание:** Аудитория может быть построена на основе наличия или отсутствия конкретных событий, а также значений параметров событий.

**Acceptance Criteria:**
- [ ] Выбор события из списка всех зарегистрированных событий ресурса
- [ ] Для каждого события доступна фильтрация по параметрам события с операторами: равно, не равно, содержит, не содержит, начинается с, заканчивается с, регулярное выражение, входит в список
- [ ] Для числовых параметров: больше, меньше, равно, в диапазоне
- [ ] Условие на количество событий (event count): "более N раз", "менее N раз", "ровно N раз"
- [ ] Возможность задания временного окна для подсчёта количества событий

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-008 | Параметры событий доступны для фильтрации только если они зарегистрированы как пользовательские параметры (custom dimensions/metrics) или являются встроенными |
| BR-AUD-009 | Максимальное количество параметров событий для фильтрации — 10 на один блок условий |

---

### FR-AUD-004: Статическая и динамическая оценка условий

**Приоритет:** P1-High

**Описание:** Система поддерживает два режима оценки условий на основе размерностей: статический ("в любой момент времени") и динамический (текущее значение).

**Acceptance Criteria:**
- [ ] Для условий на основе размерностей доступен переключатель "At any point in time" (В любой момент времени)
- [ ] При включении "At any point in time": пользователь включается в аудиторию, если условие было истинным хотя бы один раз за всю историю, и не удаляется при изменении значения (статическая оценка)
- [ ] При выключении "At any point in time": пользователь включается при выполнении условия и удаляется, когда условие перестаёт быть истинным (динамическая оценка)
- [ ] Для метрик используется только динамическая оценка (текущее значение метрики)

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-010 | Статическая оценка ("At any point in time") доступна только для размерностей, не для метрик |
| BR-AUD-011 | При динамической оценке: пользователь добавляется в аудиторию при выполнении условия и удаляется при его невыполнении |
| BR-AUD-012 | При статической оценке: пользователь добавляется навсегда (в рамках membership duration), даже если условие впоследствии перестаёт выполняться |

---

### FR-AUD-005: Условия-последовательности (Sequence Conditions)

**Приоритет:** P0-Critical

**Описание:** Система позволяет определять последовательности действий пользователя как условие включения в аудиторию. Последовательности задают порядок, в котором пользователь должен совершить определённые действия.

**Acceptance Criteria:**
- [ ] Кнопка "Add sequence" создаёт блок условий-последовательностей
- [ ] Каждый шаг (step) последовательности содержит одно или несколько условий (события, параметры, размерности)
- [ ] Между шагами доступен выбор типа перехода:
  - "is followed by" (за ним следует) — между шагами могут быть другие события (непрямая последовательность)
  - "is directly followed by" (непосредственно за ним следует) — следующий шаг должен быть следующим событием (прямая последовательность)
- [ ] Для всей последовательности доступна настройка временного ограничения (time constraint): "вся последовательность должна произойти в течение N минут/часов/дней"
- [ ] Для отдельных шагов доступно временное ограничение "within N minutes/hours/days" (в течение N минут/часов/дней после предыдущего шага)

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-013 | Последовательности доступны только с областью действия "Across all sessions" или "Within the same session" |
| BR-AUD-014 | Максимальное количество шагов в последовательности — 10 |
| BR-AUD-015 | Временное ограничение на последовательность может быть задано в минутах, часах или днях |
| BR-AUD-016 | Если временное ограничение не задано, последовательность оценивается за весь период membership duration |

---

### FR-AUD-006: Исключения (Exclusion Groups)

**Приоритет:** P0-Critical

**Описание:** Система позволяет определять группы исключений — условия, при выполнении которых пользователь удаляется из аудитории.

**Acceptance Criteria:**
- [ ] Кнопка "Add group to exclude" добавляет группу исключений, визуально выделенную красным цветом
- [ ] Доступно два типа исключений:
  - "Temporarily exclude users when" (Временно исключить) — пользователь исключается из аудитории только на время выполнения условия исключения; при прекращении выполнения условия пользователь возвращается
  - "Permanently exclude users when" (Постоянно исключить) — пользователь исключается из аудитории навсегда, даже если условие исключения перестаёт выполняться
- [ ] Группы исключений поддерживают те же типы условий (события, параметры, размерности, метрики), что и группы включений
- [ ] Правила исключений оцениваются после правил включения

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-017 | Исключение имеет приоритет над включением: если пользователь удовлетворяет и условиям включения, и условиям исключения, он НЕ включается в аудиторию |
| BR-AUD-018 | Временное исключение: пользователь исключён только пока условие истинно |
| BR-AUD-019 | Постоянное исключение: после срабатывания пользователь больше не может войти в эту аудиторию (в рамках текущего membership duration) |

---

### FR-AUD-007: Membership Duration (Срок членства)

**Приоритет:** P0-Critical

**Описание:** Для каждой аудитории задаётся срок, в течение которого пользователь остаётся её членом после последнего срабатывания условий.

**Acceptance Criteria:**
- [ ] Поле "Set membership duration" с указанием количества дней
- [ ] Значение по умолчанию: 30 дней
- [ ] Максимальное значение: 540 дней (18 месяцев)
- [ ] Опция "Set to maximum limit" устанавливает значение 540 дней
- [ ] Переключатель "Reset on new activity" (Сброс при новой активности): при повторном срабатывании условий таймер membership duration обнуляется и начинает отсчёт заново

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-020 | При истечении membership duration пользователь автоматически удаляется из аудитории |
| BR-AUD-021 | При включённом "Reset on new activity" максимальная длительность ограничена 14 месяцами |
| BR-AUD-022 | Уменьшение membership duration (например, с 60 до 30 дней) приводит к удалению пользователей, чья последняя активность была более 30 дней назад |
| BR-AUD-023 | Увеличение membership duration (например, с 30 до 60 дней) сохраняет всех текущих участников до нового срока |
| BR-AUD-024 | Изменение membership duration не является ретроактивным в отношении уже удалённых пользователей |

### 3.2 Предопределённые аудитории

---

### FR-AUD-008: Предопределённые аудитории (Predefined Audiences)

**Приоритет:** P0-Critical

**Описание:** Система автоматически создаёт две предопределённые аудитории при создании ресурса GA4. Эти аудитории нельзя редактировать или удалять.

**Acceptance Criteria:**
- [ ] Аудитория "All Users" (Все пользователи): включает всех пользователей, которые когда-либо посещали сайт или открывали приложение
- [ ] Аудитория "Purchasers" (Покупатели): включает всех пользователей, совершивших событие purchase или in_app_purchase
- [ ] Предопределённые аудитории отображаются в общем списке аудиторий
- [ ] Предопределённые аудитории нельзя архивировать, удалить или изменить условия

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-025 | "All Users" и "Purchasers" не учитываются в лимите 100 (400 для 360) пользовательских аудиторий |
| BR-AUD-026 | "All Users" не имеет ограничения membership duration — включает всех исторических пользователей |
| BR-AUD-027 | "Purchasers" обновляется автоматически при каждом событии purchase / in_app_purchase |

---

### FR-AUD-009: Предложенные (рекомендованные) аудитории (Suggested Audiences)

**Приоритет:** P1-High

**Описание:** Система предлагает шаблоны аудиторий, сгруппированные по категориям, которые можно создать одним кликом или настроить перед сохранением.

**Acceptance Criteria:**
- [ ] При создании новой аудитории доступна вкладка "Use a reference" (шаблоны)
- [ ] Шаблоны организованы по вкладкам: "Top suggestions", "General", "Drive online sales", "Generate leads", "Predictive"
- [ ] При выборе шаблона открывается конструктор аудитории с предзаполненными условиями
- [ ] Пользователь может модифицировать предзаполненные условия перед сохранением

**Категории и шаблоны:**

**General (Общие):**
- Recently active users (Недавно активные) — пользователи, активные за последние N дней
- Non-purchasers (Не покупатели) — пользователи без событий purchase
- Spenders (Тратящие) — пользователи, совершившие покупки

**Drive online sales (Стимулирование онлайн-продаж):**
- Cart abandoners (Бросившие корзину) — пользователи, добавившие товар в корзину (add_to_cart), но не совершившие purchase
- Checkout starters (Начавшие оформление) — пользователи с событием begin_checkout без purchase

**Generate leads (Генерация лидов):**
- Lead form completers (Заполнившие форму лида) — пользователи с событием generate_lead
- Tutorial completers (Прошедшие обучение) — пользователи с событием tutorial_complete

**Demographics (Демография):**
- Шаблоны по возрасту, полу, языку, стране, интересам

**Technology (Технологии):**
- Шаблоны по платформе, версии ОС, категории устройства, бренду устройства, модели мобильного устройства

**Acquisition (Привлечение):**
- Шаблоны по каналам привлечения (поиск, социальные сети, реферальный трафик)

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-028 | Предложенные аудитории при создании занимают слот из общего лимита 100/400 |
| BR-AUD-029 | Шаблон — это отправная точка; все условия могут быть изменены перед сохранением |
| BR-AUD-030 | Набор предложенных аудиторий зависит от типа ресурса (веб / мобильное приложение / оба) |

### 3.3 Предиктивные аудитории

---

### FR-AUD-010: Предиктивные метрики (Predictive Metrics)

**Приоритет:** P1-High

**Описание:** GA4 использует модели машинного обучения для прогнозирования будущего поведения пользователей. На основе предиктивных метрик строятся предиктивные аудитории.

**Acceptance Criteria:**
- [ ] Система поддерживает три предиктивных метрики:
  - **Purchase probability** (Вероятность покупки) — вероятность того, что пользователь, который был активен в последние 28 дней, совершит покупку в течение следующих 7 дней
  - **Churn probability** (Вероятность оттока) — вероятность того, что пользователь, активный в последние 7 дней, не будет активен в течение следующих 7 дней
  - **Predicted revenue** (Прогнозируемый доход) — ожидаемый доход от всех покупок пользователя в течение следующих 28 дней
- [ ] Предиктивные метрики доступны для использования в условиях аудиторий как числовые значения (перцентили)
- [ ] Предиктивные метрики обновляются ежедневно

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-031 | Предиктивные метрики доступны только при выполнении требований к минимальному объёму данных (см. FR-AUD-011) |
| BR-AUD-032 | Если качество модели падает ниже минимального порога, предиктивные метрики становятся недоступны, а предиктивные аудитории перестают обновляться |
| BR-AUD-033 | Предиктивные модели обучаются на событиях purchase, in_app_purchase (для вероятности покупки) и session_start (для вероятности оттока) |

---

### FR-AUD-011: Требования к данным для предиктивных метрик

**Приоритет:** P1-High

**Описание:** Для работы предиктивных метрик система требует минимального объёма и качества данных.

**Acceptance Criteria:**
- [ ] Для метрики "Purchase probability":
  - Минимум 1000 пользователей, совершивших покупку, в 7-дневном периоде за последние 28 дней
  - Минимум 1000 пользователей, НЕ совершивших покупку, в том же 7-дневном периоде
- [ ] Для метрики "Churn probability":
  - Минимум 1000 возвращавшихся пользователей в 7-дневном периоде за последние 28 дней
  - Минимум 1000 пользователей, НЕ вернувшихся, в том же 7-дневном периоде
- [ ] Для метрики "Predicted revenue": требования аналогичны "Purchase probability"
- [ ] Система отображает статус готовности предиктивных метрик: "Eligible" (доступна), "Not eligible" (недоступна), "Ineligible: not enough data" (недостаточно данных)
- [ ] Минимальное качество модели должно поддерживаться в течение указанного периода

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-034 | Требования к данным должны выполняться постоянно; при падении объёма данных ниже порога метрика становится недоступной |

| BR-AUD-036 | Положительные и отрицательные примеры (покупатели/не покупатели, вернувшиеся/не вернувшиеся) должны быть сбалансированы |

### FR-AUD-012: Шаблоны предиктивных аудиторий (Predictive Audience Templates)

**Приоритет:** P1-High

**Описание:** GA4 предоставляет готовые шаблоны предиктивных аудиторий, использующих предиктивные метрики.

**Acceptance Criteria:**
- [ ] Доступны следующие шаблоны предиктивных аудиторий:
  - **Likely 7-day purchasers** — пользователи с вероятностью покупки выше 90-го перцентиля в ближайшие 7 дней
  - **Likely first-time 7-day purchasers** — пользователи, которые с высокой вероятностью совершат первую покупку в ближайшие 7 дней
  - **Likely 7-day churning purchasers** — покупатели, которые с высокой вероятностью не вернутся в ближайшие 7 дней
  - **Likely 7-day churning users** — пользователи, которые с высокой вероятностью не вернутся в ближайшие 7 дней

- [ ] Каждый шаблон можно модифицировать (например, изменить порог перцентиля)
- [ ] Предиктивные аудитории обновляются ежедневно при обновлении предиктивных метрик

### FR-AUD-013: Триггеры аудиторий (Audience Triggers)

**Приоритет:** P1-High

**Описание:** Триггер аудитории позволяет генерировать пользовательское событие (event) при вхождении пользователя в аудиторию. Это событие может быть отмечено как ключевое (key event / conversion).

**Acceptance Criteria:**
- [ ] При создании или редактировании аудитории доступен переключатель "Create an audience trigger"
- [ ] Поле для ввода имени генерируемого события (event name): до 40 символов, только буквы, цифры и подчёркивания
- [ ] Опция "Log an additional event when audience membership refreshes" (логировать дополнительное событие при обновлении членства)
- [ ] При включении этой опции: событие генерируется повторно (до 1 раза в день), когда пользователь, уже находящийся в аудитории, снова удовлетворяет условиям
- [ ] При выключении: событие генерируется только один раз — при первом вхождении в аудиторию
- [ ] Созданное событие отображается в списке событий и может быть отмечено как key event (conversion)
- [ ] Триггер обрабатывается серверно, во время обработки данных (не в реальном времени)

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-041 | Имя события триггера должно быть уникальным среди всех событий ресурса |
| BR-AUD-042 | Рекомендованный префикс для событий триггера: "audience_" (для отличия от других событий) |
| BR-AUD-043 | Максимум 20 триггеров аудиторий на один ресурс (property) |
| BR-AUD-044 | При обновлении членства: не более 1 генерации события на пользователя в день |
| BR-AUD-045 | Событие триггера обрабатывается с задержкой (обычно 24-48 часов), так как зависит от серверной обработки данных |
| BR-AUD-046 | Событие триггера можно отметить как key event (conversion), что позволяет использовать его для оптимизации рекламных кампаний |

### 3.7 Сегменты в Explorations

### FR-AUD-018: Типы сегментов

**Приоритет:** P0-Critical

**Описание:** В модуле Explorations (Исследования) доступны три типа сегментов, каждый из которых определяет единицу анализа.

**Acceptance Criteria:**
- [ ] **User segment (Сегмент пользователей):** включает все данные (все сессии и события) пользователей, удовлетворяющих заданным условиям. Единица анализа — пользователь целиком
- [ ] **Session segment (Сегмент сессий):** включает только те сессии, которые удовлетворяют заданным условиям. Другие сессии того же пользователя не включаются
- [ ] **Event segment (Сегмент событий):** включает только конкретные события, удовлетворяющие условиям. Другие события того же пользователя или сессии не включаются
- [ ] При создании сегмента пользователь выбирает тип из трёх вариантов
- [ ] Тип сегмента нельзя изменить после создания — требуется создать новый сегмент

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-059 | User segment — самый широкий: включает все данные пользователя при совпадении хотя бы одного условия |
| BR-AUD-060 | Session segment — средний: включает только совпавшие сессии, но все события внутри них |
| BR-AUD-061 | Event segment — самый узкий: включает только конкретные совпавшие события |
| BR-AUD-062 | Последовательности (sequence conditions) доступны ТОЛЬКО для User segments |

### FR-AUD-019: Создание сегментов в Explorations

**Приоритет:** P0-Critical

**Описание:** В исследованиях пользователь создаёт сегменты через конструктор, аналогичный конструктору аудиторий, но с дополнительными возможностями.

**Acceptance Criteria:**
- [ ] Конструктор сегментов доступен в панели "Segments" каждого исследования (exploration)
- [ ] Кнопка "+" позволяет создать новый сегмент
- [ ] Конструктор поддерживает:
  - Блоки условий с логикой AND/OR
  - Область действия (scope): "User", "Session", "Event"
  - Условия-последовательности (для user segments)
  - Группы исключений (временное и постоянное исключение)
  - Настройки "At any point in time" для размерностей
- [ ] Доступны предложенные шаблоны сегментов
- [ ] Создание сегмента из шаблона аудитории
- [ ] Предварительный просмотр количества пользователей/сессий/событий, попадающих в сегмент

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-063 | Максимум 10 сегментов в одном исследовании |
| BR-AUD-064 | Одновременно к одной технике исследования можно применить до 4 сегментов |
| BR-AUD-065 | Сегменты не сохраняются за пределами исследования (exploration), в котором созданы |
| BR-AUD-066 | Сегменты НЕ экспортируются в рекламные платформы |
| BR-AUD-067 | Сегменты могут быть построены на данных любого диапазона дат, выбранного в исследовании |

### FR-AUD-020: Последовательности в сегментах

**Приоритет:** P1-High

**Описание:** В сегментах пользователей доступны последовательности с расширенными настройками временных ограничений.

**Acceptance Criteria:**
- [ ] Кнопка "Add sequence" добавляет блок последовательности
- [ ] Между шагами: "is indirectly followed by" (может быть разделён другими событиями) и "is directly followed by" (следующее событие)
- [ ] Переключатель "Time constraint" для всей последовательности: определяет максимальное время от первого до последнего шага
- [ ] Временные единицы: минуты, часы, дни
- [ ] Для индивидуального шага: "within N [минут/часов/дней]" — время от предыдущего шага
- [ ] Неограниченное количество шагов (в рамках разумного)
- [ ] Каждый шаг может содержать несколько условий (AND/OR)

**Business Rules:**

| Rule | Description |
|------|-------------|
| BR-AUD-068 | Последовательности в сегментах доступны ТОЛЬКО для User segments |
| BR-AUD-069 | "Directly followed by" — между двумя шагами не должно быть ни одного другого события |
| BR-AUD-070 | "Indirectly followed by" — между шагами могут быть другие события, порядок выполнения шагов сохраняется |
| BR-AUD-071 | Если задано временное ограничение, и последовательность не завершена в указанное время, пользователь не включается в сегмент |

| log_on_membership_refresh | Boolean | Генерировать событие при обновлении членства |
| is_key_event | Boolean | Отмечено ли событие как key event (conversion) |

### 4.9 Сегмент (Segment) — Explorations

| Поле | Тип | Описание |
|------|-----|----------|
| segment_id | String | Уникальный идентификатор сегмента в рамках exploration |
| name | String | Название сегмента |
| type | Enum | user / session / event |
| condition_groups | Array[ConditionGroup] | Массив блоков условий |
| exclusion_groups | Array[ExclusionGroup] | Массив блоков исключений |
| sequence_groups | Array[SequenceGroup] | Массив последовательностей (только для user segments) |
| exploration_id | String | Идентификатор родительского исследования |
| color | String | Цвет сегмента для визуализации |
| size | Integer | Количество пользователей/сессий/событий |

## 5. Состояния и статусы

### 5.1 Статусы аудитории

| Статус | Описание | Переходы |
|--------|----------|----------|
| **Creating** | Аудитория только что создана, идёт первичное вычисление состава | -> Active, -> Error |
| **Active** | Аудитория активна, наполняется пользователями и экспортируется | -> Archived |
| **Populating** | Аудитория экспортирована в Google Ads, но ещё набирает минимальный размер | -> Ready (в Google Ads) |
| **Ready** | Аудитория в Google Ads достигла минимального размера и готова к использованию в кампаниях | -> Populating (при падении размера) |
| **Archived** | Аудитория архивирована, не обновляется, не экспортируется | Терминальный статус |
| **Error** | Ошибка при вычислении (например, некорректные условия) | -> Active (после исправления) |

### 5.2 Статусы предиктивных метрик

| Статус | Описание |
|--------|----------|
| **Eligible** | Метрика доступна; данных достаточно, модель качественная |
| **Not eligible** | Метрика недоступна; данных недостаточно |
| **Ineligible: not enough positive samples** | Недостаточно положительных примеров (покупателей/вернувшихся) |
| **Ineligible: not enough negative samples** | Недостаточно отрицательных примеров |
| **Ineligible: model quality below threshold** | Качество модели ниже минимального порога |
| **Processing** | Модель обучается/переобучается |

### 5.3 Статусы членства пользователя в аудитории

| Статус | Описание |
|--------|----------|
| **Active member** | Пользователь является членом аудитории; таймер membership не истёк |
| **Excluded (temporary)** | Пользователь временно исключён из аудитории условием исключения |
| **Excluded (permanent)** | Пользователь навсегда исключён из аудитории |
| **Expired** | Membership duration истёк; пользователь удалён из аудитории |
| **Refreshed** | Пользователь заново удовлетворил условиям; таймер сброшен (при reset_on_new_activity=true) |

## 6. Ограничения и лимиты

### 6.1 Лимиты аудиторий

| Параметр | Стандартный аккаунт | GA4 360 |

| Максимум триггеров аудиторий | 20 | 20 |
| Membership duration (минимум) | 1 день | 1 день |
| Membership duration (максимум) | 540 дней | 540 дней |
| Membership duration при "Reset on new activity" | до 14 месяцев | до 14 месяцев |
| Длина названия аудитории | до 100 символов | до 100 символов |
| Длина описания аудитории | до 1000 символов | до 1000 символов |
| Длина имени события триггера | до 40 символов | до 40 символов |
| Шагов в последовательности | до 10 | до 10 |
| Обновление предиктивных метрик | 1 раз в день | 1 раз в день |
| Data freshness экспорта аудиторий | ~24 часа | ~24 часа |
| Время появления аудитории в Google Ads | 24-48 часов | 24-48 часов |

### 6.2 Лимиты сегментов (Explorations)

| Параметр | Значение |
|----------|----------|
| Максимум сегментов на одно исследование (exploration) | 10 |
| Максимум сегментов, одновременно применённых к одной технике | 4 |
| Максимум сегментов в Segment Overlap | 3 |
| Доступность последовательностей | Только User segments |
| Экспорт в рекламные платформы | Невозможен (только через создание аудитории) |

### 6.3 Минимальные размеры для рекламных платформ

| Рекламная платформа/формат | Минимальный размер аудитории |
|---------------------------|------------------------------|
| Google Ads — RLSA (поисковый ремаркетинг) | 1000 пользователей |
| Google Ads — YouTube | 100 активных пользователей за 30 дней |
| Google Ads — Display Network | Не указан жёсткий минимум |
| Google Ads — общий таргетинг | 100 пользователей (рекомендуется 1000+) |

### 6.4 Требования к данным для предиктивных метрик

| Метрика | Минимальные требования |
|---------|----------------------|
| Purchase probability | 1000+ покупателей И 1000+ не-покупателей в 7-дневном периоде за последние 28 дней |
| Churn probability | 1000+ вернувшихся пользователей И 1000+ не-вернувшихся в 7-дневном периоде за последние 28 дней |
| Predicted revenue | Аналогично Purchase probability |

### 6.5 Требования для экспорта в Google Ads

| Требование | Описание |
|-----------|----------|
| Связка аккаунтов | GA4 property должен быть связан с Google Ads аккаунтом |
| Персонализированная реклама | "Enable Personalized Advertising" должен быть включён в настройках связки |
| Google Signals | Сбор данных Google Signals должен быть активирован в ресурсе GA4 |
| Согласие пользователей | Consent Mode: сигналы consent должны быть настроены для соответствия GDPR/законодательству |

## 8. Глоссарий

| Термин | Описание |
|--------|----------|
| **Audience (Аудитория)** | Постоянная группа пользователей на уровне ресурса GA4, автоматически обновляемая и экспортируемая в рекламные платформы |
| **Segment (Сегмент)** | Временная группа пользователей/сессий/событий внутри исследования (Exploration) |
| **Condition Group (Блок условий)** | Набор условий с логическими операторами AND/OR и заданной областью действия (scope) |
| **Scope (Область действия)** | Определяет, на каком уровне оцениваются условия: "Across all sessions", "Within the same session", "Within the same event" |
| **Sequence (Последовательность)** | Упорядоченный набор шагов, определяющий порядок действий пользователя |
| **Membership Duration (Срок членства)** | Период, в течение которого пользователь остаётся в аудитории (1-540 дней) |
| **Exclusion Group (Группа исключений)** | Условия для удаления пользователей из аудитории (временное или постоянное) |
| **Audience Trigger (Триггер аудитории)** | Механизм генерации события при вхождении пользователя в аудиторию |
| **Predictive Metric (Предиктивная метрика)** | Метрика, вычисленная моделью ML: вероятность покупки, вероятность оттока, прогнозируемый доход |
| **Predictive Audience (Предиктивная аудитория)** | Аудитория с хотя бы одним условием на основе предиктивной метрики |
| **Key Event (Ключевое событие)** | Событие, отмеченное как конверсия (ранее называлось "Conversion") |
| **Google Signals** | Сбор кросс-девайсных данных пользователей, авторизованных в Google |
| **Exploration (Исследование)** | Модуль GA4 для углублённого анализа данных с поддержкой сегментов |
| **Segment Overlap** | Техника исследования для визуализации пересечений между сегментами |
| **At any point in time** | Режим статической оценки условия: пользователь включается, если условие было истинным хотя бы однажды |
| **Data Freshness** | Время задержки обновления данных (для экспорта аудиторий — ~24 часа) |
| **RLSA** | Remarketing Lists for Search Ads — списки ремаркетинга для поисковых объявлений |
