# Аутентификация и управление аккаунтом Google Analytics (GA4)

## 1. Описание модуля

Модуль аутентификации и управления аккаунтом Google Analytics 4 обеспечивает безопасный доступ к платформе веб-аналитики через интеграцию с Google Account. Система поддерживает многоуровневую иерархию доступа (Организация > Аккаунт > Ресурс), пять ролей с различными правами, механизм ограничения доступа к данным (Data Restrictions), группы пользователей, сервисные аккаунты для программного доступа и тесную интеграцию с экосистемой Google Marketing Platform.

### 1.1 Ключевые особенности

- Единая аутентификация через Google Account (OAuth 2.0)
- Двухфакторная аутентификация (2-Step Verification) на уровне Google Account
- Пятиуровневая ролевая модель: Administrator, Editor, Marketer, Analyst, Viewer
- Ограничения данных (Data Restrictions): No Cost Metrics, No Revenue Metrics
- Каскадное наследование прав по иерархии (Аккаунт > Ресурс)
- Группы пользователей (User Groups) через организацию Google Marketing Platform
- Сервисные аккаунты для программного доступа (Machine-to-Machine)
- Интеграция с Google Marketing Platform Organization
- Корзина (Trash) с 35-дневным периодом восстановления

## 2. Иерархия сущностей GA4

### 2.1 Структура иерархии

```
[Google Marketing Platform Organization] (опционально)
     └── [GA4 Account] (аккаунт аналитики)
              ├── [Property 1] (ресурс/свойство)
              │        ├── [Data Stream: Web]
              │        ├── [Data Stream: iOS App]
              │        └── [Data Stream: Android App]
              ├── [Property 2]
              │        └── [Data Stream: Web]
              └── ...
```

### 2.2 Описание уровней

| Уровень | Описание | Лимит |
|---------|----------|-------|
| **Organization** | Верхний уровень в Google Marketing Platform. Объединяет аккаунты GA, GTM, Optimize и др. | Опционален |
| **Account** | Аккаунт аналитики. Точка входа, контейнер для ресурсов. Принадлежит одному юридическому лицу (Terms of Service) | До 100 аккаунтов на Google Account |
| **Property** | Ресурс (свойство). Представляет одно приложение или набор связанных приложений. Собирает и хранит данные | До 2 000 ресурсов на аккаунт |
| **Data Stream** | Поток данных из конкретного источника (сайт, iOS-приложение, Android-приложение) | До 50 потоков на ресурс (макс. 30 app-потоков) |

### 2.3 Бизнес-правила иерархии

**BR-HIER-001**: Один GA4 Account обычно создаётся на одну организацию (юридическое лицо).

**BR-HIER-002**: Один Property объединяет данные из разных платформ (веб + приложения) для одного продукта, в отличие от Universal Analytics, где для каждой платформы требовался отдельный ресурс.

**BR-HIER-003**: Data Streams не имеют самостоятельных настроек доступа — права наследуются от Property.

**BR-HIER-004**: Удаление Account удаляет все Properties и Data Streams внутри него.

**BR-HIER-005**: GA4 не имеет понятия «Views» (представлений), которые существовали в Universal Analytics. Вместо них используются Data Streams и фильтры отчётов.

## 3. Роли пользователей

### 3.1 Предустановленные роли

| Роль | Описание | Ключевые возможности |
|------|----------|---------------------|
| **Administrator** | Полный контроль над аккаунтом или ресурсом | Управление пользователями, все настройки, все данные |
| **Editor** | Управление конфигурацией без доступа к пользователям | Настройка событий, конверсий, фильтров, потоков данных |
| **Marketer** | Работа с маркетинговыми инструментами | Аудитории, конверсии, пользовательские события, атрибуция |
| **Analyst** | Создание и редактирование общих ресурсов аналитики | Пользовательские отчёты, исследования (Explorations), общие дашборды |
| **Viewer** | Только просмотр | Просмотр отчётов, дашбордов, конфигураций |

### 3.2 Детализация прав по ролям

| Действие | Administrator | Editor | Marketer | Analyst | Viewer |
|----------|:---:|:---:|:---:|:---:|:---:|
| Управление пользователями и ролями | + | - | - | - | - |
| Управление Data Streams | + | + | - | - | - |
| Настройка событий и параметров | + | + | - | - | - |
| Управление фильтрами данных | + | + | - | - | - |
| Настройка интеграций (Google Ads, BigQuery и др.) | + | + | - | - | - |
| Удаление аккаунта / ресурса | + | + | - | - | - |
| Перемещение ресурса между аккаунтами | + | - | - | - | - |
| Управление аудиториями | + | + | + | - | - |
| Управление конверсиями | + | + | + | - | - |
| Создание пользовательских событий | + | + | + | - | - |
| Создание и редактирование общих отчётов | + | + | + | + | - |
| Создание Explorations (исследований) | + | + | + | + | - |
| Просмотр отчётов и данных | + | + | + | + | + |
| Просмотр конфигурации | + | + | + | + | + |

### 3.3 Ограничения данных (Data Restrictions)

Data Restrictions — это дополнительные ограничения поверх роли. Ограничивают видимость определённых метрик, не затрагивая остальные права.

| Ограничение | Что скрывается | Пример использования |
|-------------|---------------|---------------------|
| **No Cost Metrics** | Все метрики, связанные с затратами на рекламу (Google Ads cost, CPC, CPM и др.) | Скрыть рекламный бюджет от внешнего подрядчика |
| **No Revenue Metrics** | Все метрики, связанные с доходом (revenue, purchase value, LTV и др.) | Скрыть выручку от маркетингового агентства |

### 3.4 Бизнес-правила ролей и ограничений данных

**BR-ROLE-001**: Роли назначаются на уровне Account или Property. Невозможно ограничить доступ на уровне отдельного Data Stream.

**BR-ROLE-002**: Права наследуются сверху вниз: роль, назначенная на уровне Account, автоматически действует на все Properties внутри этого аккаунта.

**BR-ROLE-003**: Нельзя назначить роль на уровне Property ниже, чем роль пользователя на уровне Account. Пример: если пользователь — Editor на уровне Account, его нельзя сделать Viewer на уровне Property.

**BR-ROLE-004**: Можно повысить роль на уровне Property. Пример: Viewer на уровне Account может быть Editor на конкретном Property.

**BR-ROLE-005**: Data Restrictions наследуются сверху вниз. Если пользователю установлено No Cost Metrics на уровне Account, оно действует на все Properties.

**BR-ROLE-006**: Data Restrictions можно добавить на уровне Property, но нельзя убрать унаследованное с уровня Account ограничение.

**BR-ROLE-007**: Data Restrictions применяются как в интерфейсе GA4, так и в API-вызовах аналитики.

**BR-ROLE-008**: Минимальная роль для управления пользователями — Administrator.

**BR-ROLE-009**: Administrator может назначать роли только своего уровня или ниже.

**BR-ROLE-010**: Роль Marketer включает все права Analyst плюс работа с аудиториями и пользовательскими событиями.

## 4. Функциональные требования

### FR-AUTH-001: Вход в Google Analytics через Google Account

**Priority**: P0-Critical

**Description**: Пользователь входит в GA4 через свой Google Account. GA4 не имеет собственной системы аутентификации и полностью полагается на Google Account.

**User Story**:
```
КАК аналитик
Я ХОЧУ войти в Google Analytics через свой Google Account
ЧТОБЫ просматривать и анализировать данные о трафике и поведении пользователей
```

**Предусловия:**
- У пользователя есть активный Google Account
- Пользователю предоставлен доступ к хотя бы одному GA4 Account или Property

**Основной сценарий:**
1. Пользователь переходит на analytics.google.com
2. Система перенаправляет на страницу входа Google (если не авторизован)
3. Пользователь вводит email
4. Пользователь вводит пароль
5. [Опционально] Пользователь проходит 2FA (2-Step Verification)
6. Система проверяет наличие доступа к GA4 ресурсам
7. Пользователь попадает в интерфейс GA4

**Альтернативные сценарии:**
- 3a. Пользователь уже авторизован в Google → пропуск шагов 3-5
- 6a. У пользователя нет доступа ни к одному GA4 ресурсу → предложение создать аккаунт или запросить доступ
- 6b. Google Account заблокирован → отказ в доступе с уведомлением

**Acceptance Criteria**:
- [ ] Вход осуществляется исключительно через Google Account
- [ ] Поддержка всех методов 2FA Google Account
- [ ] При отсутствии доступа к GA4 ресурсам показывается понятное сообщение
- [ ] Сессия сохраняется согласно настройкам Google Account

---

### FR-AUTH-002: Двухфакторная аутентификация (2-Step Verification)

**Priority**: P0-Critical

**Description**: 2FA управляется на уровне Google Account, а не внутри GA4. Однако администраторы Google Workspace могут сделать 2FA обязательной для всех пользователей организации, что влияет и на доступ к GA4.

**User Story**:
```
КАК IT-администратор организации
Я ХОЧУ обязать всех сотрудников использовать 2FA
ЧТОБЫ защитить доступ к аналитическим данным компании
```

**Доступные методы 2FA:**

| Метод | Уровень безопасности | Описание |
|-------|---------------------|----------|
| **Passkeys** | Высший | Биометрия (отпечаток, лицо) или PIN устройства |
| **Аппаратный ключ безопасности** | Высокий | Физическое устройство (YubiKey, Titan Security Key) |
| **Google Authenticator / TOTP** | Высокий | Одноразовые коды в приложении |
| **Google Prompt** | Высокий | Push-уведомление на доверенное устройство |
| **SMS-код** | Средний | Код в текстовом сообщении |
| **Голосовой звонок** | Средний | Код через голосовой вызов |
| **Резервные коды** | Резервный | 10 одноразовых кодов для экстренного доступа |

**Business Rules**:

| Rule | Description |
|------|-------------|
| BR-2FA-001 | 2FA настраивается и управляется на уровне Google Account, а не в GA4 |
| BR-2FA-002 | Администратор Google Workspace может принудительно включить 2FA для всей организации |
| BR-2FA-003 | При обязательной 2FA пользователи без настроенной 2FA теряют доступ ко всем сервисам Google, включая GA4 |
| BR-2FA-004 | Доверенные устройства можно пометить для пропуска повторной 2FA-проверки на срок до 30 дней |

### FR-AUTH-003: Аутентификация через сервисный аккаунт (Service Account)

**Priority**: P1-High

**Description**: Сервисные аккаунты обеспечивают программный (Machine-to-Machine) доступ к данным GA4 без участия пользователя. Используются для автоматизированных систем отчётности, интеграций и ETL-процессов.

**User Story**:
```
КАК разработчик
Я ХОЧУ настроить сервисный аккаунт для доступа к GA4
ЧТОБЫ автоматически получать данные аналитики для внутренних дашбордов
```

**Основной сценарий:**
1. Разработчик создаёт сервисный аккаунт в Google Cloud Console
2. Генерирует и скачивает JSON-ключ для аутентификации
3. Активирует Google Analytics Data API в проекте Google Cloud
4. Копирует email-адрес сервисного аккаунта (формат: name@project.iam.gserviceaccount.com)
5. Administrator GA4 добавляет email сервисного аккаунта как пользователя с нужной ролью (обычно Viewer)
6. Приложение использует JSON-ключ для аутентификации и доступа к данным

**Business Rules**:

| Rule | Description |
|------|-------------|
| BR-SA-001 | Сервисный аккаунт аутентифицируется через JSON-ключ (private key), а не через пароль или OAuth flow |
| BR-SA-002 | Сервисному аккаунту назначаются те же роли, что и обычному пользователю (Viewer, Analyst, Editor и т.д.) |
| BR-SA-003 | Рекомендуется назначать сервисному аккаунту минимально необходимую роль (принцип наименьших привилегий) |
| BR-SA-004 | JSON-ключ не имеет срока действия, но может быть отозван вручную в Google Cloud Console |
| BR-SA-005 | Один сервисный аккаунт может иметь доступ к нескольким GA4 Property |
| BR-SA-006 | Сервисный аккаунт не может входить через веб-интерфейс GA4 — только программный доступ через API |

### FR-AUTH-004: Аутентификация через OAuth 2.0 (пользовательский контекст)

**Priority**: P1-High

**Description**: OAuth 2.0 позволяет сторонним приложениям получать доступ к данным GA4 от имени конкретного пользователя после его явного согласия. Используется для пользовательских приложений, которым нужен доступ к GA4 данным.

**User Story**:
```
КАК пользователь стороннего аналитического инструмента
Я ХОЧУ предоставить ему доступ к моим данным GA4
ЧТОБЫ видеть аналитику в удобном мне интерфейсе
```

**Основной сценарий:**
1. Стороннее приложение перенаправляет пользователя на экран согласия Google (consent screen)
2. Пользователь входит в Google Account
3. Пользователь видит запрашиваемые разрешения (scopes)
4. Пользователь подтверждает доступ
5. Google возвращает авторизационный код приложению
6. Приложение обменивает код на access token и refresh token
7. Приложение использует access token для запросов к GA4 API

**Business Rules**:

| Rule | Description |
|------|-------------|
| BR-OAUTH-001 | Доступ через OAuth ограничен правами пользователя, который авторизовал приложение |
| BR-OAUTH-002 | Access token имеет ограниченный срок действия (обычно 1 час) |
| BR-OAUTH-003 | Refresh token позволяет получать новые access token без повторной авторизации пользователя |
| BR-OAUTH-004 | Пользователь может отозвать доступ приложения в настройках Google Account (Security > Third-party apps) |
| BR-OAUTH-005 | Приложение должно запрашивать только минимально необходимые scopes |

### FR-AUTH-005: Создание GA4 аккаунта

**Priority**: P0-Critical

**Description**: Создание нового аккаунта Google Analytics 4. Аккаунт является корневым контейнером для ресурсов (Properties) и определяет юридические условия использования.

**User Story**:
```
КАК владелец бизнеса
Я ХОЧУ создать аккаунт Google Analytics
ЧТОБЫ начать отслеживать данные о посещаемости моего сайта и приложения
```

**Основной сценарий:**
1. Пользователь переходит на analytics.google.com
2. Нажимает «Создать аккаунт» (или попадает на onboarding при первом визите)
3. Вводит название аккаунта (название компании/проекта)
4. Настраивает параметры обмена данными (Data Sharing Settings):
   - Google Products & Services
   - Benchmarking
   - Technical Support
   - Account Specialists
5. Принимает условия использования (Terms of Service) для своей страны/региона
6. Создаёт первый Property (ресурс) в рамках аккаунта
7. Создаёт первый Data Stream (поток данных)
8. Аккаунт создан и активен

**Business Rules**:

| Rule | Description |
|------|-------------|
| BR-ACC-001 | Один Google Account может владеть до 100 GA4 аккаунтов |
| BR-ACC-002 | Создатель аккаунта автоматически получает роль Administrator |
| BR-ACC-003 | Условия использования привязаны к стране/региону и определяют правовые обязательства |
| BR-ACC-004 | Data Sharing Settings можно изменить после создания аккаунта |
| BR-ACC-005 | Название аккаунта должно быть непустым (максимум 200 символов) |

### FR-AUTH-006: Создание ресурса (Property)

**Priority**: P0-Critical

**Description**: Создание нового ресурса (Property) в существующем GA4 аккаунте. Property — центральная сущность, которая собирает и хранит аналитические данные для одного продукта.

**User Story**:
```
КАК администратор GA4 аккаунта
Я ХОЧУ создать новый ресурс для нового продукта компании
ЧТОБЫ отслеживать его метрики отдельно от существующих продуктов
```

**Основной сценарий:**
1. Administrator или Editor открывает Admin > Create Property
2. Вводит название ресурса
3. Указывает часовой пояс для отчётности
4. Указывает валюту для финансовых метрик
5. Заполняет информацию о бизнесе (отрасль, размер компании)
6. Выбирает бизнес-цели (генерация лидов, e-commerce, вовлечённость и др.)
7. Property создан

**Business Rules**:

| Rule | Description |
|------|-------------|
| BR-PROP-001 | Максимум 2 000 ресурсов на один GA4 аккаунт |
| BR-PROP-002 | Создавать ресурсы могут только пользователи с ролью Editor или выше на уровне Account |
| BR-PROP-003 | Часовой пояс и валюта влияют на расчёт метрик в отчётах, но не на сбор данных |
| BR-PROP-004 | Property типа GA4 не может быть конвертирован обратно в Universal Analytics |
| BR-PROP-005 | В рамках одного Property рекомендуется объединять данные одного продукта (сайт + приложения) |

### FR-AUTH-007: Приглашение пользователя

**Priority**: P0-Critical

**Description**: Добавление нового пользователя к GA4 аккаунту или ресурсу с назначением роли и опциональных ограничений данных.

**User Story**:
```
КАК администратор GA4
Я ХОЧУ пригласить маркетолога в ресурс
ЧТОБЫ он мог анализировать данные и управлять аудиториями
```

**Основной сценарий:**
1. Administrator открывает Admin > Account/Property Access Management
2. Нажимает «+» > Add users
3. Вводит email-адреса (один или несколько, через запятую)
4. Выбирает роль (Administrator, Editor, Marketer, Analyst, Viewer)
5. [Опционально] Устанавливает Data Restrictions (No Cost Metrics, No Revenue Metrics)
6. [Опционально] Отмечает «Notify new users by email»
7. Нажимает Add
8. Пользователь получает доступ немедленно (без подтверждения приглашения)

**Состояния доступа:**
```
[Добавлен на уровне Account] → Доступ ко всем Properties аккаунта
[Добавлен на уровне Property] → Доступ только к данному Property
```

**Business Rules**:

| Rule | Description |
|------|-------------|
| BR-INV-001 | Приглашение действует мгновенно — пользователю не нужно принимать приглашение для получения доступа |
| BR-INV-002 | Приглашаемый должен иметь Google Account, привязанный к указанному email |
| BR-INV-003 | Можно добавить несколько пользователей одновременно (batch-добавление) |
| BR-INV-004 | При добавлении на уровне Account пользователь автоматически получает такую же роль на всех Properties |
| BR-INV-005 | Email-уведомление о добавлении отправляется по умолчанию, но может быть отключено |
| BR-INV-006 | Нельзя добавить пользователя с ролью выше, чем роль добавляющего |

**Acceptance Criteria**:
- [ ] Пользователь получает доступ немедленно после добавления
- [ ] Data Restrictions корректно ограничивают видимость метрик
- [ ] Наследование прав работает корректно при добавлении на уровне Account

### FR-AUTH-008: Управление группами пользователей (User Groups)

**Priority**: P1-High

**Description**: Группы пользователей позволяют массово управлять правами для наборов пользователей. Группы создаются через организацию Google Marketing Platform.

**User Story**:
```
КАК администратор крупной компании
Я ХОЧУ создать группу «Маркетинг» и назначить ей роль Marketer
ЧТОБЫ не настраивать доступ каждому маркетологу индивидуально
```

### FR-AUTH-011: Перемещение ресурса (Property) между аккаунтами

КАК администратор

| BR-TRASH-008 | После окончательного удаления (35 дней) восстановление невозможно |

## 5. Сущности данных

### 5.1 GA4 Account

| Атрибут | Описание | Ограничения |
|---------|----------|-------------|
| Account ID | Уникальный идентификатор аккаунта | Числовой, генерируется системой |
| Account Name | Название аккаунта | Непустое, до 200 символов |
| Country | Страна для Terms of Service | Определяется при создании |
| Data Sharing Settings | Параметры обмена данными | Набор переключателей |
| Created At | Дата создания | Не изменяется |
| Updated At | Дата последнего изменения | Автоматически |

### 5.2 Property (Ресурс)

| Атрибут | Описание | Ограничения |
|---------|----------|-------------|
| Property ID | Уникальный идентификатор ресурса | Числовой, генерируется системой |
| Property Name | Название ресурса | Непустое |
| Timezone | Часовой пояс для отчётности | IANA timezone |
| Currency | Валюта для финансовых метрик | ISO 4217 код валюты |
| Industry Category | Отрасль бизнеса | Из предопределённого списка |
| Business Size | Размер компании | Small / Medium / Large / Very Large |
| Data Retention | Период хранения данных для Explorations | 2 месяца (бесплатно) / 14 месяцев (бесплатно) / до 50 месяцев (360) |
| Created At | Дата создания | Не изменяется |

### 5.3 Data Stream (Поток данных)

| Атрибут | Описание | Ограничения |
|---------|----------|-------------|
| Stream ID | Уникальный идентификатор потока | Числовой, генерируется системой |
| Stream Name | Название потока | Непустое |
| Stream Type | Тип потока | Web / iOS app / Android app |
| Measurement ID | Идентификатор для тега (для Web) | Формат G-XXXXXXX |
| Website URL | URL сайта (для Web-потоков) | Валидный URL |
| App ID | Bundle ID / Package Name (для App-потоков) | Стандартный формат |
| Enhanced Measurement | Расширенное отслеживание | Включено/выключено + настройки |

### 5.4 User Access (Доступ пользователя)

| Атрибут | Описание | Ограничения |
|---------|----------|-------------|
| Email | Email пользователя (Google Account) | Валидный email, привязанный к Google Account |
| Level | Уровень назначения | Account / Property |
| Role | Роль пользователя | Administrator / Editor / Marketer / Analyst / Viewer |
| Data Restrictions | Ограничения данных | None / No Cost Metrics / No Revenue Metrics / оба |
| Effective Permissions | Эффективные права (с учётом наследования) | Рассчитываются системой |
| Source | Источник назначения | Direct / Inherited / User Group |

### 5.5 User Group (Группа пользователей)

| Атрибут | Описание | Ограничения |
|---------|----------|-------------|
| Group Name | Название группы | Непустое |
| Level | Уровень назначения | Account / Property |
| Role | Роль группы | Administrator / Editor / Marketer / Analyst / Viewer |
| Data Restrictions | Ограничения данных группы | None / No Cost Metrics / No Revenue Metrics / оба |
| Members | Список участников | Email-адреса Google Account |
| Organization | Организация GMP | Привязана к организации |

## 6. Состояния и статусы

### 6.1 Состояния GA4 Account

```
[Создание] → [Активный] ←→ [Настройка]
                  ↓
           [В корзине (Trash)]
                  ↓ (35 дней)
           [Окончательно удалён]
```

| Состояние | Описание | Возможные действия |
|-----------|----------|-------------------|
| **Создание** | Процесс первичной настройки аккаунта | Заполнение данных, принятие ToS |
| **Активный** | Аккаунт полностью функционален | Все операции доступны |
| **В корзине** | Помечен для удаления, данные не обрабатываются | Восстановление (Administrator) |
| **Окончательно удалён** | Необратимое удаление | Нет действий — данные потеряны навсегда |

### 6.2 Состояния Property

```
[Создание] → [Активный] ←→ [Настройка интеграций]
                  ↓
           [В корзине (Trash)]
                  ↓ (35 дней)
           [Окончательно удалён]
```

| Состояние | Описание | Возможные действия |
|-----------|----------|-------------------|
| **Создание** | Настройка нового ресурса | Заполнение данных, создание Data Stream |
| **Активный** | Ресурс собирает и обрабатывает данные | Все операции |
| **В корзине** | Помечен для удаления, сбор данных приостановлен | Восстановление |
| **Окончательно удалён** | Необратимое удаление | Невозможно |

### 6.3 Состояния Data Stream

```
[Создан] → [Активный (данные поступают)] ←→ [Активный (нет данных)]
                      ↓
               [Удалён] (без корзины, мгновенно)
```

| Состояние | Описание |
|-----------|----------|
| **Создан** | Data Stream создан, но тег ещё не установлен |
| **Активный (данные поступают)** | Данные поступают корректно |
| **Активный (нет данных)** | Тег не установлен или не работает, данные не поступают |
| **Удалён** | Data Stream удалён (без периода восстановления) |

### 6.4 Состояния доступа пользователя

```
[Добавлен] → [Активный доступ] ←→ [Роль изменена]
                    ↓
              [Удалён (доступ отозван)]
```

| Состояние | Описание |
|-----------|----------|
| **Добавлен** | Пользователь добавлен, доступ мгновенно активен |
| **Активный доступ** | Пользователь имеет доступ и может использовать GA4 |
| **Роль изменена** | Роль или Data Restrictions изменены, действует немедленно |
| **Удалён** | Доступ полностью отозван |

## 8. Интеграции с другими модулями

### 8.1 Связь с модулем «Отчёты и аналитика»

- Роль пользователя определяет, какие отчёты доступны для просмотра и редактирования
- Data Restrictions (No Cost / No Revenue) фильтруют видимые метрики в отчётах
- Analyst и выше могут создавать и сохранять пользовательские отчёты (Explorations)
- Viewer может только просматривать существующие отчёты

### 8.2 Связь с модулем «Сбор данных и события»

- Editor и выше могут создавать и модифицировать пользовательские события
- Marketer и выше могут помечать события как конверсии (Key Events)
- Настройка Data Streams (где происходит сбор данных) требует роли Editor

### 8.3 Связь с модулем «Аудитории и сегменты»

- Marketer и выше могут создавать и управлять аудиториями
- Аудитории используются для ремаркетинга через связанные аккаунты Google Ads
- Создание аудиторий ограничено лимитом (100 бесплатно / 400 для 360)

### 8.4 Связь с модулем «Интеграции»

- Связывание с внешними продуктами (Product Linking) требует роли Editor+ в GA4
- Каждый внешний продукт требует дополнительной роли в самом продукте
- Разрыв связей при перемещении Property влияет на все зависимые модули

### 8.5 Связь с модулем «Монетизация и подписки»

- Переход на Google Analytics 360 увеличивает лимиты конфигурации и данных
- 360 предоставляет дополнительные функции: sub-properties, roll-up properties, расширенный SLA
- Управление подпиской 360 осуществляется через Google Marketing Platform

### 8.6 Связь с модулем «Администрирование и настройки»

- Change History фиксирует все административные действия пользователей
- Data Sharing Settings влияют на то, какие данные доступны Google и в бенчмарках
- Trash Can обеспечивает 35-дневный grace period для восстановления удалённых сущностей

## 9. Глоссарий

| Термин | Определение |
|--------|-------------|
| **GA4** | Google Analytics 4 — четвёртое поколение платформы веб-аналитики Google, основанное на событийной модели данных |
| **Account** | Аккаунт аналитики — верхний уровень иерархии GA4, контейнер для ресурсов |
| **Property** | Ресурс (свойство) — уровень, на котором собираются и хранятся аналитические данные одного продукта |
| **Data Stream** | Поток данных — источник данных (сайт или мобильное приложение), подключённый к Property |
| **Measurement ID** | Идентификатор измерения (формат G-XXXXXXX) — используется в теге для отправки данных |
| **Data Restrictions** | Ограничения данных — механизм скрытия определённых метрик (cost, revenue) от пользователей |
| **User Group** | Группа пользователей — набор пользователей с общими правами доступа |
| **GMP** | Google Marketing Platform — платформа для управления маркетинговыми продуктами Google |
| **Organization** | Организация GMP — верхний уровень иерархии, объединяющий аккаунты разных продуктов Google |
| **Product Linking** | Связывание продуктов — установка связи между GA4 Property и другим продуктом Google |
| **Change History** | История изменений — журнал аудита всех административных действий в GA4 |
| **Trash Can** | Корзина — временное хранилище удалённых аккаунтов и ресурсов (35 дней до окончательного удаления) |
| **Effective Permissions** | Эффективные права — итоговые права пользователя с учётом наследования, групп и прямых назначений |
| **Service Account** | Сервисный аккаунт — специальный аккаунт для программного (M2M) доступа к GA4 через API |
| **OAuth 2.0** | Протокол авторизации, используемый для предоставления доступа сторонним приложениям от имени пользователя |
| **Key Event** | Ключевое событие (ранее «конверсия») — событие, отмеченное как значимое для бизнес-целей |
| **Exploration** | Исследование — инструмент расширенного анализа данных в GA4 |
| **Google Analytics 360** | Платная версия GA4 для крупных компаний с расширенными лимитами и SLA |
