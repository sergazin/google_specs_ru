# События и конверсии (Events & Key Events / Conversions)

## Executive Summary

| Атрибут | Значение |
|---------|----------|
| Module ID | GA-05 |
| Название модуля | Events & Key Events (Conversions) |
| Приоритет | P0-Critical |
| Зависимости | `01_auth`, `02_property_setup`, `03_data_streams`, `04_data_collection` |
| Последнее обновление | 2026-02-14 |

## Описание

Google Analytics 4 (GA4) построен на полностью событийной модели данных (event-based data model). В отличие от Universal Analytics, где существовали отдельные типы обращений (pageview, event, transaction, social), в GA4 абсолютно всё является событием. Каждое взаимодействие пользователя с сайтом или приложением фиксируется как событие с набором параметров.

Модуль «События и конверсии» является ядром GA4 и охватывает:
- Сбор, классификацию и управление событиями четырёх типов (автоматические, улучшенные, рекомендуемые, пользовательские)
- Маркировку событий как ключевых (Key Events, ранее — «конверсии»)
- Управление параметрами событий и пользовательскими определениями (custom dimensions, custom metrics)
- Настройку атрибуции конверсий и окон конверсии
- Создание и модификацию событий через интерфейс администрирования

### Терминологическое уточнение (2024+)

В марте 2024 года Google переименовал «Conversion events» (события-конверсии) в «Key events» (ключевые события) внутри GA4. Термин «Conversion» (конверсия) теперь зарезервирован исключительно за данными, которые передаются из GA4 в Google Ads для оптимизации рекламных кампаний. Таким образом:
- **Key Event (Ключевое событие)** — важное действие пользователя, отмечаемое в GA4 для измерения успеха бизнеса. Отображается в отчётах GA4.
- **Conversion (Конверсия)** — ключевое событие, экспортированное в Google Ads для оптимизации ставок и таргетинга.

## Роли пользователей

| Роль | Права в модуле событий | Описание |
|------|------------------------|----------|
| Администратор (Administrator) | Полный доступ: создание, модификация, удаление событий; настройка ключевых событий; управление атрибуцией; настройка пользовательских определений | Владелец аккаунта или ресурса с максимальными правами |
| Редактор (Editor) | Создание и модификация событий; маркировка событий как ключевых; создание пользовательских определений; изменение настроек атрибуции | Аналитик или маркетолог с правами редактирования |
| Маркетолог (Marketer) | Создание аудиторий на основе событий; просмотр отчётов по событиям и ключевым событиям; создание пользовательских определений | Роль для маркетинговых специалистов |
| Аналитик (Analyst) | Просмотр всех отчётов по событиям; создание исследований (Explorations) на основе событий; экспорт данных | Доступ только на чтение с расширенным анализом |
| Наблюдатель (Viewer) | Просмотр стандартных и пользовательских отчётов по событиям | Минимальные права, только просмотр |

## Функциональные требования

### FR-EVT-001: Событийная модель данных GA4
**Priority**: P0-Critical

**Description**: Все взаимодействия пользователя с сайтом или приложением записываются как события. Каждое событие состоит из имени события (event_name) и набора параметров (event parameters), описывающих контекст взаимодействия. Система хита (hit) из Universal Analytics полностью заменена событийной моделью.

**Acceptance Criteria**:
- [ ] Каждый хит в GA4 записывается как событие с именем и параметрами
- [ ] Имя события является обязательным полем
- [ ] К каждому событию могут быть прикреплены параметры (ключ-значение)
- [ ] Система поддерживает до 25 параметров на одно событие (стандартный ресурс)
- [ ] Система поддерживает до 100 параметров на одно событие (GA4 360)
- [ ] Параметры делятся на автоматически собираемые и пользовательские
- [ ] К каждому событию автоматически прикрепляются системные параметры (timestamp, user_id, session_id, device info и др.)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-EVT-001 | Имя события может содержать только буквы латинского алфавита, цифры и символ подчёркивания |
| BR-EVT-002 | Имя события должно начинаться с буквы |
| BR-EVT-003 | Длина имени события — не более 40 символов |
| BR-EVT-004 | Имена событий чувствительны к регистру (case-sensitive) |
| BR-EVT-005 | Имена событий не могут использовать зарезервированные имена и префиксы |
| BR-EVT-006 | Длина имени параметра — не более 40 символов |
| BR-EVT-007 | Длина значения строкового параметра — не более 100 символов |

### FR-EVT-002: Автоматически собираемые события (Automatically Collected Events)
**Priority**: P0-Critical

**Description**: GA4 автоматически собирает ряд событий без необходимости дополнительной настройки. Эти события регистрируются при наличии установленного тега Google (gtag.js) или Firebase SDK.

**Acceptance Criteria**:
- [ ] Событие `first_visit` автоматически регистрируется при первом посещении пользователем сайта
- [ ] Событие `session_start` автоматически регистрируется при каждом начале новой сессии
- [ ] Событие `user_engagement` автоматически регистрируется при активном взаимодействии пользователя с сайтом/приложением
- [ ] Для мобильных приложений автоматически собираются дополнительные события: `first_open`, `app_update`, `app_remove`, `os_update`, `app_exception`, `app_clear_data`, `notification_receive`, `notification_foreground`, `notification_dismiss`, `notification_open`, `in_app_purchase`, `dynamic_link_first_open`, `dynamic_link_app_open`
- [ ] Пользователю не требуется добавлять дополнительный код для сбора автоматических событий
- [ ] Автоматические события нельзя отключить

**Автоматически собираемые события (веб)**:

| Событие | Описание | Условие срабатывания |
|---------|----------|----------------------|
| `first_visit` | Первое посещение сайта пользователем | Первое обращение нового пользователя |
| `session_start` | Начало сессии | Каждое новое начало сессии (после 30 мин неактивности или смены UTM-источника) |
| `user_engagement` | Активное вовлечение пользователя | Пользователь находился на странице с фокусом >= 10 секунд |

**Автоматически собираемые события (мобильные приложения)**:

| Событие | Описание | Условие срабатывания |
|---------|----------|----------------------|
| `first_open` | Первое открытие приложения | Первый запуск приложения после установки |
| `app_update` | Обновление приложения | Приложение обновлено до новой версии |
| `app_remove` | Удаление приложения | Приложение удалено с устройства (только Android) |
| `os_update` | Обновление ОС | Обновление операционной системы устройства |
| `app_exception` | Ошибка приложения | Возникновение сбоя или ошибки |
| `in_app_purchase` | Покупка в приложении | Завершение покупки внутри приложения через App Store / Google Play |

### FR-EVT-003: Улучшенные события (Enhanced Measurement Events)
**Priority**: P0-Critical

**Description**: GA4 предоставляет набор событий улучшенного отслеживания, которые автоматически регистрируются при включённой опции Enhanced Measurement в настройках веб-потока данных. Эта функция включена по умолчанию, но каждое событие может быть отключено индивидуально.

**Acceptance Criteria**:
- [ ] Enhanced Measurement включён по умолчанию при создании веб-потока данных
- [ ] Администратор или Редактор может включить/отключить каждое событие улучшенного отслеживания независимо
- [ ] Настройки доступны в разделе Admin > Data Streams > Web Stream > Enhanced Measurement
- [ ] Изменения применяются только к будущим данным, исторические данные не затрагиваются
- [ ] Не требуется дополнительная настройка кода для работы Enhanced Measurement

**Список событий Enhanced Measurement**:

| Событие | Описание | Параметры | Поведение по умолчанию |
|---------|----------|-----------|------------------------|
| `page_view` | Просмотр страницы | `page_location`, `page_referrer`, `page_title` | Включено, нельзя отключить через Enhanced Measurement |
| `scroll` | Прокрутка до 90% страницы | `percent_scrolled` (всегда = 90) | Включено |
| `click` (outbound) | Клик по внешней ссылке (переход на другой домен) | `link_url`, `link_domain`, `link_classes`, `link_id`, `outbound` | Включено |
| `view_search_results` | Использование поиска по сайту | `search_term` | Включено |
| `video_start` | Начало воспроизведения встроенного видео (YouTube) | `video_title`, `video_url`, `video_provider`, `video_current_time`, `video_duration`, `video_percent`, `visible` | Включено |
| `video_progress` | Прогресс просмотра видео (10%, 25%, 50%, 75%) | Те же + `video_percent` с соответствующим значением | Включено |
| `video_complete` | Завершение просмотра видео | Те же параметры | Включено |
| `file_download` | Клик по ссылке на загружаемый файл | `file_name`, `file_extension`, `link_url`, `link_text`, `link_domain` | Включено |
| `form_start` | Начало взаимодействия с формой | `form_id`, `form_name`, `form_destination` | Включено |
| `form_submit` | Отправка формы | `form_id`, `form_name`, `form_destination`, `form_submit_text` | Включено |

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ENH-001 | Событие `scroll` срабатывает только при прокрутке до 90% высоты страницы, промежуточные пороги не регистрируются |
| BR-ENH-002 | Видеосекции Enhanced Measurement работают только с встроенными YouTube-видео (через iframe с включённым JS API) |
| BR-ENH-003 | Событие `file_download` срабатывает при клике на ссылку с расширениями: pdf, xls, xlsx, doc, docx, txt, rtf, csv, exe, key, pps, ppt, pptx, 7z, pkg, rar, gz, zip, avi, mov, mp4, mpeg, wmv, midi, mp3, wav, wma |
| BR-ENH-004 | Событие `view_search_results` срабатывает при наличии в URL параметров: q, s, search, query, keyword |
| BR-ENH-005 | Функция `form_start` / `form_submit` может работать некорректно: она может зафиксировать отправку формы даже при ошибке валидации (если не заполнено обязательное поле). Рекомендуется проводить аудит и при необходимости настраивать события через GTM |

### FR-EVT-004: Рекомендуемые события (Recommended Events)
**Priority**: P0-Critical

**Description**: Рекомендуемые события — это события с предопределёнными именами и параметрами, которые Google рекомендует реализовать для раскрытия полного потенциала отчётности GA4. Они не собираются автоматически — их необходимо настроить вручную (через код или GTM). Однако при правильной реализации они автоматически обогащают стандартные отчёты и измерения.

**Acceptance Criteria**:
- [ ] Рекомендуемые события имеют предопределённые имена, которые нельзя изменять
- [ ] Для каждого рекомендуемого события определён набор обязательных и опциональных параметров
- [ ] При корректной отправке рекомендуемые события автоматически заполняют соответствующие стандартные отчёты (например, E-commerce Purchases)
- [ ] Система предоставляет категории рекомендуемых событий: для всех ресурсов, для интернет-магазинов, для игр, для образования

**Рекомендуемые события для всех ресурсов**:

| Событие | Описание | Обязательные параметры |
|---------|----------|-----------------------|

| `share` | Шеринг контента | `content_type`, `item_id`, `method` |

### FR-EVT-005: Пользовательские события (Custom Events)
**Priority**: P0-Critical

**Description**: Пользовательские события — это события, имена и параметры которых определяются пользователем GA4 самостоятельно. Они используются для отслеживания действий, не покрываемых автоматическими, улучшенными или рекомендуемыми событиями.

**Acceptance Criteria**:
- [ ] Пользователь может создать событие с произвольным именем, соблюдающим правила именования
- [ ] Пользователь может определить произвольные параметры для пользовательского события
- [ ] Пользовательские события отображаются в отчёте «События» наряду с другими типами
- [ ] Пользовательские события могут быть помечены как ключевые (Key Events)
- [ ] Пользовательские параметры должны быть зарегистрированы как пользовательские определения (custom definitions) для отображения в отчётах

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-CUS-001 | Нельзя использовать имена, совпадающие с автоматическими или рекомендуемыми событиями, для событий с другой семантикой |
| BR-CUS-002 | Нельзя использовать зарезервированные префиксы: `google_`, `ga_`, `firebase_` |
| BR-CUS-003 | Рекомендуется использовать формат snake_case для имён событий (например, `form_lead_submit`) |
| BR-CUS-004 | Максимальное количество уникальных имён событий: 500 (для мобильных приложений), неограниченно для веб-потоков |
| BR-CUS-005 | Рекомендуется не использовать заглавные буквы, так как имена чувствительны к регистру: `Page_View` и `page_view` — разные события |

### FR-EVT-006: Зарезервированные имена и правила именования
**Priority**: P1-High

**Description**: GA4 резервирует ряд имён событий и префиксов, которые нельзя использовать для пользовательских событий. Система должна валидировать имена на этапе создания.

**Acceptance Criteria**:
- [ ] Система блокирует создание событий с зарезервированными именами
- [ ] Система блокирует создание событий с зарезервированными префиксами
- [ ] При попытке отправки события с зарезервированным именем данные отбрасываются

**Зарезервированные префиксы**:
- `google_`
- `ga_`
- `firebase_`

**Зарезервированные имена событий (примеры)**:
- `ad_activeview`, `ad_click`, `ad_exposure`, `ad_impression`, `ad_query`, `ad_reward`
- `app_clear_data`, `app_exception`, `app_install`, `app_remove`, `app_store_refund`, `app_store_subscription_cancel`, `app_store_subscription_convert`, `app_store_subscription_renew`, `app_update`
- `error`, `first_open`, `first_visit`, `in_app_purchase`
- `notification_dismiss`, `notification_foreground`, `notification_open`, `notification_receive`
- `os_update`, `screen_view`, `session_start`, `user_engagement`

**Зарезервированные имена параметров**:
- `firebase_conversion`
- Имена, начинающиеся с `google_`, `ga_`, `firebase_`

### FR-EVT-007: Ключевые события (Key Events)
**Priority**: P0-Critical

**Description**: Ключевое событие (Key Event) — это любое событие GA4, помеченное как критически важное для измерения успеха бизнеса. Ранее эти события назывались «конверсиями». Маркировка события как ключевого влияет на его отображение в отчётах и позволяет использовать его в моделях атрибуции.

**Acceptance Criteria**:
- [ ] Администратор или Редактор может пометить любое существующее событие как ключевое
- [ ] Маркировка выполняется через переключатель (toggle) в разделе Admin > Events или Admin > Key Events
- [ ] Событие, помеченное как ключевое, начинает отображаться в отчётах по ключевым событиям
- [ ] Маркировка применяется только к будущим данным; исторические данные не пересчитываются
- [ ] Ключевые события отображаются со специальной иконкой (звезда) в списке событий
- [ ] Максимальное количество ключевых событий: 30 (стандартный ресурс) / 50 (GA4 360)
- [ ] Некоторые события помечены как ключевые по умолчанию: `purchase`, `first_open` (для приложений)
- [ ] GA4 может предлагать потенциальные ключевые события на основе паттернов поведения пользователей (через Insights)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-KEY-001 | Ключевое событие начинает учитываться в отчётах только с момента маркировки; ретроактивный пересчёт невозможен |
| BR-KEY-002 | При снятии маркировки ключевого события исторические данные сохраняются, но событие перестаёт считаться ключевым в будущих данных |
| BR-KEY-003 | Событие `purchase` по умолчанию помечено как ключевое и не может быть снято с маркировки без потери возможности отслеживания дохода |
| BR-KEY-004 | Лимит в 30 (или 50 для 360) ключевых событий является жёстким ограничением ресурса |
| BR-KEY-005 | Одно и то же событие не может быть помечено как ключевое дважды |

### FR-EVT-008: Метод подсчёта ключевых событий (Counting Method)
**Priority**: P0-Critical

**Description**: Для каждого ключевого события можно настроить метод подсчёта, определяющий, как считается число ключевых событий: каждое срабатывание или один раз за сессию.

**Acceptance Criteria**:
- [ ] Доступны два метода подсчёта: «Once per event» (на каждое событие) и «Once per session» (один раз за сессию)
- [ ] Метод подсчёта настраивается индивидуально для каждого ключевого события
- [ ] Администратор или Редактор может изменить метод подсчёта через Admin > Key Events > три точки > Change counting method
- [ ] Разные ключевые события в одном ресурсе могут иметь разные методы подсчёта
- [ ] Метод подсчёта по умолчанию для новых ключевых событий: «Once per event»

**Методы подсчёта**:

| Метод | Описание | Пример | Рекомендация |
|-------|----------|--------|-------------|
| Once per event | Считает каждое срабатывание события как отдельное ключевое событие | Если пользователь совершил 5 покупок за сессию — засчитывается 5 ключевых событий | Рекомендуется для событий покупок, подписок, транзакций |
| Once per session | Считает не более одного ключевого события за сессию, независимо от количества срабатываний | Если пользователь отправил 3 формы за сессию — засчитывается 1 ключевое событие | Рекомендуется для событий типа «отправка формы», «подписка на рассылку» |

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-CNT-001 | Метод «Once per event» является рекомендуемым по умолчанию от Google |
| BR-CNT-002 | Метод «Once per session» был автоматически установлен для ключевых событий, мигрированных из целей Universal Analytics через инструмент миграции (после апреля 2023) |
| BR-CNT-003 | Изменение метода подсчёта применяется только к будущим данным |
| BR-CNT-004 | Метод подсчёта влияет на данные в отчётах GA4, но не на данные, экспортированные в Google Ads |

### FR-EVT-009: Создание событий через интерфейс (Create Events)
**Priority**: P1-High

**Description**: GA4 позволяет создавать новые события на основе существующих непосредственно через интерфейс администрирования, без необходимости изменения кода или настройки GTM. Новое событие срабатывает, когда входящее событие соответствует заданным условиям.

**Acceptance Criteria**:
- [ ] Администратор или Редактор может создать новое событие через Admin > Events > Create event
- [ ] Пользователь задаёт имя нового события
- [ ] Пользователь задаёт одно или несколько условий совпадения (matching conditions) на основе параметров входящего события
- [ ] Условия поддерживают операторы: equals, contains, starts with, ends with, matches regex, is one of, does not equal, does not contain, does not start with, does not end with, does not match regex, is not one of, less than, greater than, greater than or equal to
- [ ] Пользователь может скопировать параметры из исходного события (checkbox «Copy parameters from the source event»)
- [ ] Пользователь может добавить, изменить или удалить параметры для нового события
- [ ] Максимум созданных событий через интерфейс: 50 на ресурс

**Пример**:
Создание события `generate_lead_contact_form` на основе события `form_submit`, когда параметр `page_location` содержит `/contact`:
- Matching condition 1: `event_name` equals `form_submit`
- Matching condition 2: `page_location` contains `/contact`
- Copy parameters from source event: да
- Custom event name: `generate_lead_contact_form`

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-CRE-001 | Созданные события не применяются к историческим данным; они срабатывают только для будущих данных |
| BR-CRE-002 | Созданные события обрабатываются после модифицированных событий |
| BR-CRE-003 | Условия совпадения объединяются логикой AND (все условия должны быть истинными) |
| BR-CRE-004 | Лимит в 50 созданных событий является жёстким ограничением ресурса |
| BR-CRE-005 | Если исходное событие изменено модификацией (FR-EVT-010), создание события будет работать с уже модифицированной версией |

### FR-EVT-010: Модификация событий через интерфейс (Modify Events)
**Priority**: P1-High

**Description**: GA4 позволяет модифицировать существующие события непосредственно через интерфейс: изменять значения параметров, добавлять новые параметры или переименовывать события. Модификация изменяет само входящее событие, в отличие от создания (FR-EVT-009), которое генерирует новое событие.

**Acceptance Criteria**:
- [ ] Администратор или Редактор может модифицировать событие через Admin > Events > Modify event
- [ ] Пользователь задаёт условия совпадения для определения, какие события модифицировать
- [ ] Пользователь определяет модификации: изменение значений параметров, добавление новых параметров, переименование события
- [ ] Модификации выполняются в порядке, указанном в списке Event modifications (порядок можно менять перетаскиванием)
- [ ] Максимум модификаций событий: 50 на ресурс

**Типы модификаций**:

| Тип модификации | Описание | Пример |
|-----------------|----------|--------|
| Переименование события | Изменение значения параметра `event_name` | `page_view` → `homepage_view` (при условии `page_location` = `/`) |
| Изменение значения параметра | Замена значения существующего параметра | Заменить значение `page_title` на `Homepage` при определённых условиях |
| Добавление параметра | Добавление нового параметра к событию | Добавить параметр `page_type` = `landing` к определённым page_view |
| Удаление параметра | Установка пустого значения параметра | Очистить значение `user_id` для определённых событий |

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-MOD-001 | Модификации не применяются к историческим данным |
| BR-MOD-002 | Модификации обрабатываются до создания событий (FR-EVT-009) |
| BR-MOD-003 | Порядок модификаций важен: они выполняются последовательно, и результат одной модификации может влиять на условия следующей |
| BR-MOD-004 | Лимит в 50 модификаций является жёстким ограничением ресурса |
| BR-MOD-005 | Модификация события не создаёт новый тип события — она изменяет обрабатываемое событие in-place |

### FR-EVT-011: Параметры событий (Event Parameters)
**Priority**: P0-Critical

**Description**: Каждое событие в GA4 может содержать параметры — пары ключ-значение, описывающие контекст взаимодействия. Параметры делятся на автоматически собираемые (системные) и пользовательские.

**Acceptance Criteria**:
- [ ] Каждое событие может содержать до 25 параметров (стандартный ресурс) / до 100 параметров (GA4 360)
- [ ] Системные параметры добавляются автоматически (language, page_location, page_referrer, page_title, screen_resolution и др.)
- [ ] Пользовательские параметры задаются через код или GTM
- [ ] Параметры имеют тип: String или Number
- [ ] Пользовательские параметры доступны в отчётах только после их регистрации как пользовательских определений (custom definitions)
- [ ] Без регистрации пользовательские параметры записываются, но не отображаются в стандартных отчётах (доступны только через BigQuery Export)

**Системные параметры (собираемые автоматически)**:

| Параметр | Описание | Тип |
|----------|----------|-----|
| `language` | Язык браузера/устройства | String |
| `page_location` | URL текущей страницы | String |
| `page_referrer` | URL страницы-источника | String |
| `page_title` | Заголовок страницы | String |
| `screen_resolution` | Разрешение экрана | String |
| `ga_session_id` | Идентификатор сессии | String |
| `ga_session_number` | Порядковый номер сессии пользователя | Number |
| `engagement_time_msec` | Время вовлечения в миллисекундах | Number |

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-PAR-001 | Если событие содержит более 25 (или 100 для 360) параметров, лишние параметры отбрасываются |
| BR-PAR-002 | Длина имени параметра не должна превышать 40 символов |
| BR-PAR-003 | Длина строкового значения параметра не должна превышать 100 символов; значения, превышающие лимит, обрезаются |
| BR-PAR-004 | Имена параметров чувствительны к регистру |
| BR-PAR-005 | Имена параметров не могут начинаться с зарезервированных префиксов (`google_`, `ga_`, `firebase_`) |

### FR-EVT-012: Пользовательские определения (Custom Definitions)
**Priority**: P0-Critical

**Description**: Пользовательские определения (Custom Definitions) — это механизм регистрации пользовательских параметров событий и свойств пользователей для их использования в стандартных отчётах, исследованиях (Explorations) и аудиториях. Без регистрации параметры записываются, но недоступны для анализа через интерфейс GA4.

**Acceptance Criteria**:
- [ ] Администратор, Редактор или Маркетолог может создавать пользовательские определения через Admin > Custom definitions
- [ ] Поддерживаются три типа пользовательских определений: Custom Dimensions (пользовательские измерения), Custom Metrics (пользовательские метрики), Calculated Metrics (вычисляемые метрики)
- [ ] Пользовательские измерения имеют три области видимости (scope): Event-scoped, User-scoped, Item-scoped
- [ ] Данные по зарегистрированному определению начинают отображаться в отчётах в течение 24 часов
- [ ] После удаления пользовательского определения необходимо подождать 48 часов перед созданием нового

**Типы пользовательских определений**:

| Тип | Область видимости | Описание | Пример |
|-----|-------------------|----------|--------|
| Event-scoped Custom Dimension | На уровне события | Значение рассчитывается и сохраняется для каждого события отдельно | `button_text`, `form_type`, `content_category` |
| User-scoped Custom Dimension | На уровне пользователя | Значение сохраняется для пользователя и автоматически применяется ко всем будущим событиям; новое значение перезаписывает старое | `membership_level`, `user_type`, `subscription_plan` |
| Item-scoped Custom Dimension | На уровне товара (ecommerce) | Значение привязано к элементу массива `items` в ecommerce-событиях | `item_color`, `item_size`, `item_brand_category` |
| Custom Metric | На уровне события | Числовое значение параметра, зарегистрированное как метрика для агрегации | `discount_amount`, `delivery_days`, `content_length` |

**Лимиты пользовательских определений**:

| Тип определения | Стандартный ресурс | GA4 360 |
|-----------------|--------------------|---------|
| Event-scoped custom dimensions | 50 | 125 |
| User-scoped custom dimensions | 25 | 100 |
| Item-scoped custom dimensions | 10 | 25 |
| Custom metrics | 50 | 125 |

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-DEF-001 | Регистрация параметра, который уже является предопределённым измерением GA4 (например, `page_title`, `transaction_id`), расходует квоту, но не даёт дополнительной ценности |
| BR-DEF-002 | Пользовательские определения не действуют ретроактивно: данные появляются в отчётах только с момента регистрации |
| BR-DEF-003 | User-scoped custom dimension сохраняет последнее установленное значение; предыдущие значения не доступны для сравнения |
| BR-DEF-004 | Item-scoped custom dimensions доступны только в контексте ecommerce-событий, содержащих массив `items` |
| BR-DEF-005 | После удаления custom dimension или metric необходимо подождать 48 часов, прежде чем можно будет создать новое определение на освободившемся слоте |
| BR-DEF-006 | При достижении лимита невозможно создать новое определение без удаления существующего |

### FR-EVT-013: Модели атрибуции (Attribution Models)
**Priority**: P0-Critical

**Description**: Модель атрибуции определяет, каким источникам трафика (каналам, кампаниям) присваивается заслуга за совершение ключевого события. GA4 поддерживает несколько моделей атрибуции, которые можно переключать в настройках ресурса.

**Acceptance Criteria**:
- [ ] Администратор или Редактор может выбрать модель атрибуции через Admin > Attribution settings
- [ ] Изменение модели атрибуции мгновенно пересчитывает данные во всех отчётах (включая исторические)
- [ ] Поддерживаются три модели атрибуции
- [ ] Модель по умолчанию — Data-driven attribution

**Доступные модели атрибуции**:

| Модель | Описание | Алгоритм | Рекомендация |
|--------|----------|----------|-------------|
| Data-driven attribution (DDA) | Распределяет заслугу за ключевое событие на основе данных аккаунта с помощью машинного обучения | Анализирует до 50 точек взаимодействия за 90 дней до конверсии; учитывает время между взаимодействием и конверсией, тип формата, устройство и другие сигналы | По умолчанию. Рекомендуется для ресурсов с достаточным объёмом данных |
| Paid and organic last click | 100% заслуги получает последний канал, по которому кликнул пользователь перед конверсией | Прямой трафик (Direct) игнорируется; если последний клик — Direct, заслуга передаётся предыдущему не-Direct каналу | Для простого однопоточного анализа |
| Google paid channels last click | 100% заслуги получает последний Google Ads канал, через который кликнул пользователь | Если Google Ads клика нет в пути, используется fallback к модели «Paid and organic last click» | Для приоритетной оценки рекламных каналов Google |

**Устаревшие модели (удалены с ноября 2023)**:
- First click (первый клик)
- Linear (линейная)
- Time decay (временной спад)
- Position-based (на основе позиции)

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-ATR-001 | Изменение модели атрибуции влияет на все отчёты, включая исторические данные |
| BR-ATR-002 | Data-driven attribution требует достаточного объёма данных; при малом объёме система может деградировать к last-click логике |
| BR-ATR-003 | Модель атрибуции влияет на отчёты в GA4, но не напрямую на данные, передаваемые в Google Ads (Google Ads использует свою модель атрибуции) |
| BR-ATR-004 | Модели first click, linear, time decay и position-based удалены и более недоступны |

### FR-EVT-014: Окна конверсии / Окна ретроспективного просмотра (Conversion Lookback Windows)
**Priority**: P0-Critical

**Description**: Окно конверсии (Key Event Lookback Window) определяет, за какой период времени до совершения ключевого события точки взаимодействия (touchpoints) могут получить атрибуционную заслугу. Точки взаимодействия за пределами окна конверсии не учитываются при атрибуции.

**Acceptance Criteria**:
- [ ] Настройки окна конверсии доступны через Admin > Attribution settings
- [ ] Поддерживаются отдельные окна для событий привлечения (acquisition) и прочих ключевых событий
- [ ] Изменения окон конверсии применяются только к будущим данным
- [ ] Администратор или Редактор может изменить окна конверсии

**Настройки окон конверсии**:

| Тип ключевого события | Опции окна | Значение по умолчанию | Описание |
|-----------------------|------------|----------------------|----------|
| Acquisition events (`first_visit`, `first_open`) | 7 дней, 30 дней | 30 дней | Период, за который точки взаимодействия учитываются при атрибуции первого визита пользователя |
| All other key events | 30 дней, 60 дней, 90 дней | 90 дней | Период, за который точки взаимодействия учитываются при атрибуции прочих ключевых событий |
| Engaged-view key events | 1 день, 3 дня, 5 дней, 7 дней | 3 дня | Период, за который просмотры видеорекламы учитываются при атрибуции |

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-WIN-001 | Изменение окна конверсии не пересчитывает исторические данные; оно влияет только на будущие данные |
| BR-WIN-002 | Более короткое окно конверсии приводит к тому, что меньше точек взаимодействия получают заслугу, что может снизить количество атрибуционных конверсий |
| BR-WIN-003 | Для бизнесов с длинным циклом принятия решения (B2B, недвижимость) рекомендуется использовать максимальное окно (90 дней) |
| BR-WIN-004 | Окно конверсии применяется ко всем ключевым событиям соответствующего типа; индивидуальная настройка для отдельных ключевых событий невозможна |

### FR-EVT-015: Ключевые события и конверсии Google Ads (Key Events vs Conversions)
**Priority**: P1-High

**Description**: В GA4 существует разграничение между «Key Events» (ключевые события для анализа в GA4) и «Conversions» (конверсии для оптимизации рекламных кампаний в Google Ads). Конверсия — это ключевое событие, которое было экспортировано в Google Ads и используется для оптимизации ставок.

**Acceptance Criteria**:
- [ ] Key Event — это событие, помеченное как важное в GA4 для отображения в отчётах
- [ ] Conversion — это Key Event, связанное с аккаунтом Google Ads и экспортированное для оптимизации рекламы
- [ ] Пользователь может пометить Key Event как Conversion для Google Ads через настройки связи аккаунтов
- [ ] Metrics «Key events» и «Conversions» отображаются раздельно в отчётах GA4
- [ ] Не все Key Events обязательно являются Conversions; пользователь выбирает, какие Key Events экспортировать в Google Ads

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-GAD-001 | Для создания конверсии в Google Ads необходимо предварительно пометить событие как Key Event в GA4 |
| BR-GAD-002 | Данные Key Events в GA4 и Conversions в Google Ads могут расходиться из-за разных моделей атрибуции |
| BR-GAD-003 | GA4 использует кроссплатформенную атрибуцию (web + app), тогда как Google Ads использует свою атрибуцию, ориентированную на рекламу |
| BR-GAD-004 | Для корректной работы конверсий в Google Ads необходима активная связь (link) между GA4 и Google Ads |

### FR-EVT-016: Отчёт о событиях в реальном времени (Realtime Events Report)
**Priority**: P1-High

**Description**: GA4 предоставляет возможность просматривать события в реальном времени (в течение последних 30 минут) через отчёт Realtime. Это позволяет верифицировать корректность настройки событий.

**Acceptance Criteria**:
- [ ] Все зарегистрированные события отображаются в отчёте Realtime в течение нескольких секунд после срабатывания
- [ ] Отчёт показывает количество событий за последние 30 минут
- [ ] Отчёт позволяет фильтровать по имени события
- [ ] Для каждого события отображаются его параметры
- [ ] Ключевые события выделены визуально в отчёте Realtime
- [ ] Отчёт также доступен через режим DebugView для детального просмотра событий конкретного устройства

**Business Rules**:
| Rule | Description |
|------|-------------|
| BR-RT-001 | Данные в Realtime отчёте не являются окончательными и могут незначительно отличаться от данных в стандартных отчётах |
| BR-RT-002 | DebugView показывает события только от устройств с включённым режимом отладки |
| BR-RT-003 | В Realtime отображаются данные за последние 30 минут; более ранние данные автоматически удаляются из отчёта |

---

### FR-EVT-017: Свойства пользователя (User Properties)
**Priority**: P1-High

**Description**: Свойства пользователя (User Properties) — это атрибуты, описывающие сегменты пользовательской базы. Они устанавливаются через код и автоматически применяются ко всем будущим событиям пользователя. Для использования в отчётах необходимо зарегистрировать их как User-scoped custom dimensions.

**Acceptance Criteria**:
- [ ] Пользовательские свойства задаются через `gtag('set', 'user_properties', {...})` или Firebase SDK
- [ ] Установленное значение свойства применяется ко всем последующим событиям пользователя
- [ ] Новое значение свойства перезаписывает предыдущее
- [ ] Для использования в отчётах свойство должно быть зарегистрировано как User-scoped custom dimension
- [ ] Максимум User-scoped custom dimensions: 25 (стандартный) / 100 (GA4 360)

**Автоматически собираемые свойства пользователя**:

| Свойство | Описание |
|----------|----------|
| `age` | Возрастная группа пользователя (при включённых демографических данных Google Signals) |
| `gender` | Пол пользователя (при включённых демографических данных Google Signals) |
| `interests` | Интересы пользователя (при включённых демографических данных Google Signals) |
| `first_open_time` | Время первого открытия приложения |
| `first_visit_time` | Время первого визита на сайт |

### FR-EVT-018: Отчёт DebugView
**Priority**: P1-High

**Description**: DebugView — это инструмент отладки событий в реальном времени, позволяющий просматривать поток событий от конкретного устройства с детализацией по параметрам.

**Acceptance Criteria**:
- [ ] DebugView доступен через Admin > DebugView
- [ ] Отображает хронологический поток событий от выбранного устройства
- [ ] Для каждого события показывает все параметры и их значения
- [ ] Ключевые события выделены визуально (цветом или иконкой)
- [ ] Поддерживает фильтрацию по устройствам с активным режимом отладки
- [ ] Для веб: режим отладки активируется через расширение Google Analytics Debugger или через параметр `debug_mode: true` в конфигурации тега
- [ ] Для приложений: режим отладки активируется через Firebase Debug Mode

## Состояния и статусы

### Жизненный цикл события

```
[Отправка клиентом] --> [Получение сервером GA4]
[Получение сервером] --> [Применение модификаций (Modify Events)]
[После модификаций] --> [Применение создания событий (Create Events)]
[Обработанное событие] --> [Проверка: является ли Key Event?]
    [Да] --> [Учёт в Key Events с применением counting method]
    [Нет] --> [Запись как обычное событие]
[Записанное событие] --> [Доступно в Realtime (мгновенно)]
[Записанное событие] --> [Доступно в стандартных отчётах (до 24-48 часов)]
[Записанное событие] --> [Экспорт в BigQuery (в соответствии с расписанием)]
```

### Статусы события в системе

| Статус | Описание |
|--------|----------|
| Received | Событие получено сервером GA4 |
| Processed | Событие прошло обработку (модификации, создание) |
| Recorded | Событие записано в хранилище данных |
| Key Event Counted | Событие учтено как ключевое (с применением counting method) |
| Exported to Ads | Ключевое событие экспортировано в Google Ads как конверсия |
| Dropped | Событие отброшено (невалидное имя, превышение лимитов, дубликат транзакции) |

### Статусы пользовательского определения (Custom Definition)

| Статус | Описание |
|--------|----------|
| Active | Определение активно, данные собираются и отображаются в отчётах |
| Pending | Определение создано, данные будут доступны в течение 24 часов |
| Archived | Определение удалено; слот освободится через 48 часов |

## Интеграции с другими модулями

### Внутренние интеграции GA4

| Модуль GA4 | Описание интеграции |
|------------|---------------------|
| Отчёты (Reports) | Все события и ключевые события отображаются в стандартных и пользовательских отчётах. Ключевые события выделяются в отдельных отчётах и метриках |
| Исследования (Explorations) | События и их параметры используются в качестве измерений и метрик для построения кастомных исследований (воронки, пути, когорты, свободная форма) |
| Аудитории (Audiences) | События и их параметры используются для определения условий сегментации. Ключевые события могут служить триггерами включения/исключения пользователей из аудитории |
| Потоки данных (Data Streams) | Enhanced Measurement настраивается на уровне веб-потока данных. Каждый поток данных отправляет события в общий ресурс GA4 |
| BigQuery Export | Все события (включая ключевые) экспортируются в BigQuery с полной структурой параметров. Позволяет SQL-анализ на уровне сырых данных |
| Пользовательские определения (Custom Definitions) | Параметры событий и свойства пользователей регистрируются как пользовательские определения для использования в отчётах |
| DebugView | Отображает поток событий в реальном времени для отладки. Показывает все параметры и статусы ключевых событий |

### Внешние интеграции

| Внешний сервис | Описание интеграции |
|----------------|---------------------|
| Google Ads | Ключевые события могут быть экспортированы как конверсии в Google Ads для оптимизации ставок, таргетинга и Smart Bidding. Данные конверсий используются для автоматической стратегии назначения ставок (Target CPA, Target ROAS, Maximize conversions) |
| Google Tag Manager (GTM) | GTM служит основным инструментом для настройки пользовательских и рекомендуемых событий. Триггеры GTM определяют условия срабатывания, а теги GA4 Event отправляют события в GA4 |
| Google Looker Studio | Данные о событиях и ключевых событиях доступны для визуализации в Looker Studio (бывший Data Studio) через нативный коннектор GA4 |
| Firebase | Для мобильных приложений Firebase SDK является основным инструментом сбора событий. Events и User Properties задаются через Firebase Analytics, данные автоматически попадают в GA4 |
| Google Search Console | Данные поискового трафика интегрируются с событиями GA4 для анализа пути от поискового запроса до конверсии |
| Google Merchant Center | Данные о товарах из Merchant Center обогащают ecommerce-события (purchase, add_to_cart и др.) дополнительными атрибутами |
| CRM-системы | Через Measurement Protocol возможна отправка офлайн-событий (телефонные звонки, CRM-конверсии) в GA4 для объединения онлайн и офлайн-данных |
| Consent Management Platforms (CMP) | Системы управления согласием (OneTrust, Cookiebot и др.) влияют на сбор событий: при отсутствии согласия пользователя события могут не собираться или собираться без идентификаторов |
