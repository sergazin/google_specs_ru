# Google Ads: Модуль "Аудитории и ремаркетинг"

## 1. Общее описание модуля

Модуль "Аудитории и ремаркетинг" позволяет рекламодателям таргетировать объявления на определённые группы пользователей на основе их поведения, интересов, демографических характеристик и взаимодействий с бизнесом. Модуль объединяет инструменты для создания, управления и комбинирования аудиторий для повышения эффективности рекламных кампаний.

**Важное терминологическое обновление:**
- "Типы аудиторий" теперь называются "Сегменты аудиторий" (Audience Segments)
- "Ремаркетинг" теперь называется "Ваши данные" (Your Data)

---

## 2. Типы сегментов аудиторий

### 2.1 Сегменты "Ваши данные" (Your Data Segments)

Объединяют ремаркетинг и Customer Match — аудитории на основе собственных данных рекламодателя.

#### 2.1.1 Посетители сайта (Website Visitors)

**Описание:** Пользователи, которые посещали веб-сайт рекламодателя.

**Типы ремаркетинга:**
- **Стандартный ремаркетинг** — показ объявлений прошлым посетителям при просмотре сайтов и приложений в контекстно-медийной сети
- **Динамический ремаркетинг** — показ объявлений с конкретными товарами/услугами, которые пользователь просматривал на сайте
- **Списки ремаркетинга для поисковой рекламы (RLSA)** — таргетинг на прошлых посетителей в поисковой сети

**Правила создания сегментов:**
- Базовое правило: "Посещение веб-страницы"
- Уточнение по URL: "URL содержит", "URL равен", "URL начинается с"
- Уточнение по реферальному URL
- Уточнение по параметрам из event snippets
- Уточнение по атрибутам из Google Merchant Center

**Логика построения правил:**
- Комбинирование условий через AND (И)
- Комбинирование условий через OR (ИЛИ)
- Исключение действий (НЕ)

**Пример правила:** "URL содержит 'stilettos'" — сегмент пользователей, посещавших страницы с туфлями на шпильках.

**Срок участия (Membership Duration):**
- По умолчанию: 30 дней
- Максимум: 540 дней
- Рекомендация: срок должен соответствовать среднему циклу покупки
- При повторном посещении — счётчик сбрасывается

**Минимальные требования:**
- Для RLSA: минимум 1000 пользователей
- Для YouTube: минимум 100 активных пользователей за 30 дней

**Опции предзаполнения:**
- Добавить посетителей за последние 30 дней
- Начать с пустого сегмента

#### 2.1.2 Пользователи приложения (App Users)

**Описание:** Пользователи, взаимодействовавшие с мобильным приложением.

**Критерии создания:**
- Все пользователи приложения
- Пользователи, совершившие определённые действия
- Пользователи, не совершившие определённые действия
- Комбинации включений и исключений

**Параметры:**
- Выбор приложения
- Выбор аналитической платформы
- Период активности (до 540 дней)
- Выбор конкретных действий для включения/исключения

#### 2.1.3 Пользователи YouTube (YouTube Users)

**Описание:** Пользователи, взаимодействовавшие с YouTube-каналом рекламодателя.

**Типы взаимодействий:**
- Просмотр любого видео с канала
- Просмотр определённых видео
- Подписка на канал
- Посещение страницы канала
- Лайк видео
- Добавление видео в плейлист
- Комментирование видео
- Шеринг видео

### 2.2 Customer Match (Списки клиентов)

**Описание:** Загрузка собственных данных о клиентах для показа рекламы им и похожим пользователям.

**Каналы показа:** Поиск, вкладка Покупки, Gmail, YouTube, Контекстно-медийная сеть.

#### Требования к данным:

**Формат файла:**
- CSV-файл
- Кодировка: ASCII или UTF-8 (UTF-16 не поддерживается)

**Заголовки столбцов (на английском):**
- Email
- Phone
- First Name
- Last Name
- Country
- Zip

**Форматирование данных:**
- **Email:** стандартная нормализация, удаление пробелов; для gmail.com/googlemail.com — удаление точек и суффиксов после +
- **Телефон:** формат E164
- **Страна:** двухбуквенный код страны

**Хеширование:**
- Приватные данные (Email, Phone, First Name, Last Name) хешируются алгоритмом SHA-256
- Country и Zip не хешируются

**Минимальные требования:**
- Минимум один идентификатор: email, телефон или адрес
- Для использования в поиске/шоппинге: минимум 1000 совпавших профилей
- Максимум 20 идентификаторов на одного пользователя

**Срок действия:**
- Максимальный срок участия: 540 дней
- Для активности списка: минимум 100 участников, обновлённых за последние 540 дней

**Комбинированное сопоставление:**
- Загрузка email + телефон + адрес для повышения точности сопоставления
- Обязательные 6 столбцов для комбинированного сопоставления

### 2.3 Сегменты по интересам (Affinity Segments)

**Описание:** Аудитории на основе долгосрочных интересов, увлечений и привычек пользователей.

**Как Google определяет интересы:**
- Посещаемые сайты
- Просматриваемые видео
- Используемые приложения
- Посещаемые физические места
- Поисковая история

**Количество категорий:** ~150 сегментов, организованных в ~12 основных категорий.

**Примеры категорий:**
- Автолюбители
- Фанаты спорта
- Любители роскошных путешествий
- Модники
- Технологические энтузиасты
- Любители фитнеса
- Любители домашнего декора
- Шопоголики
- Геймеры

**Применение:** Эффективны для кампаний по повышению узнаваемости бренда, охвата широкой аудитории.

**Конфиденциальность:** Google не использует чувствительную информацию (здоровье, раса, религия, сексуальная ориентация).

### 2.4 Сегменты по намерениям (In-Market Segments)

**Описание:** Аудитории пользователей, активно исследующих и готовящихся к покупке определённых товаров/услуг.

**Как Google определяет намерение покупки:**
- Клики на релевантные объявления и последующие конверсии
- Контент посещаемых сайтов и страниц
- Частота и давность посещений
- Сравнение товаров в одной категории
- Исследование предложений конкурирующих брендов

**Количество категорий:** 25 основных категорий с множеством подкатегорий.

**Пример:** Категория "Подарки и мероприятия" → Подкатегория "Цветы" — для бизнеса по продаже цветов.

**Совместимость с кампаниями:**
- Поиск
- Шоппинг
- Контекстно-медийная сеть
- Demand Gen
- Видео
- Performance Max (как сигнал)

**Преимущество:** Самая "низкофуннельная" и высокоинтентная опция среди готовых аудиторий Google.

### 2.5 Сегменты по жизненным событиям (Life Events)

**Описание:** Аудитории пользователей, переживающих важные жизненные события.

**Доступные события:**
- Переезд (скоро переезжает / недавно переехал)
- Свадьба
- Выпуск из университета
- Смена работы
- Выход на пенсию
- Покупка дома
- Создание бизнеса

**Временное окно:** Google идентифицирует пользователей в 6-месячном окне вокруг события.

**Совместимость с кампаниями:**
- Display
- Video
- Demand Gen
- Performance Max
- **НЕ доступно:** Search, Shopping

**Преимущество:** Крупные жизненные события часто связаны с большими покупками (дом, обручальное кольцо) или всплеском покупательской активности.

### 2.6 Пользовательские сегменты (Custom Segments)

**Описание:** Создание собственных аудиторий на основе ключевых слов, URL и приложений.

**Типы входных данных:**

1. **Ключевые слова/Интересы:**
   - Пользователи, искавшие указанные термины в Google
   - Работает как точное соответствие с близкими вариантами
   - Пример: "running shoes" — таргетинг на людей, искавших беговые кроссовки

2. **URL:**
   - Пользователи, посещающие сайты, **похожие** на указанные (не конкретные сайты!)
   - Важно: это не placement-таргетинг
   - Пример: URL конкурентов для таргетинга на их аудиторию

3. **Приложения:**
   - Пользователи, использующие приложения, **похожие** на указанные
   - Объявления НЕ показываются в самих приложениях
   - Пример: фитнес-приложения для продвижения сервиса доставки здорового питания

**Совместимость с кампаниями:**
- Display
- Demand Gen
- Video
- Gmail
- Performance Max
- **НЕ доступно:** Search, Shopping

**Рекомендация:** Создавать отдельные сегменты для разных типов входных данных, не объединять всё в один.

### 2.7 Детальная демография (Detailed Demographics)

**Описание:** Таргетинг на пользователей по долгосрочным демографическим характеристикам.

#### Базовая демография:

| Параметр | Search | Display | Video | Shopping |
|----------|--------|---------|-------|----------|
| Возраст | ✅ | ✅ | ✅ | ❌ |
| Пол | ✅ | ✅ | ✅ | ❌ |
| Родительский статус | ❌ | ✅ | ✅ | ❌ |
| Семейный доход | ⚠️* | ⚠️* | ✅ | ❌ |

*Доступно только в ~20 странах

**Диапазоны семейного дохода (США):**
- Топ 10%
- 11-20%
- 21-30%
- 31-40%
- 41-50%
- Нижние 50%

#### Расширенная демография:

**Доступно во всех кампаниях:**
- Родительский статус (с возрастом детей: младенцы, малыши, дошкольники, школьники, подростки)
- Семейное положение
- Образование
- Статус владения жильём

**Только для Search:**
- Занятость (размер компании, отрасль)

**Категория "Неизвестно":**
- Пользователи с неопределённой демографией
- Рекомендация: не исключать, чтобы не потерять значительную часть аудитории

### 2.8 Похожие сегменты / Lookalike (Lookalike Segments)

**Описание:** Аудитории пользователей, схожих по характеристикам с существующими клиентами.

**Важное изменение:** Google больше не генерирует автоматически Similar Audiences. Lookalike-сегменты создаются вручную.

**Доступность:** Только для кампаний Demand Gen.

**Требования к исходному списку (Seed List):**
- Минимум 1000 активных совпавших пользователей
- Через API: минимум 100 пользователей в сумме всех seed-списков
- Максимум 10 существующих списков для создания одного Lookalike

**Источники seed-списка:**
- Customer Match списки
- Посетители сайта
- Пользователи приложения
- Подписчики YouTube-канала

**Ограничения:**
- Customer Match на основе Mobile Device ID не поддерживается

**Уровни расширения:**
- **Узкий (Narrow):** 2.5% людей в локации, наиболее похожих на seed-список
- **Сбалансированный (Balanced):** 5%
- **Широкий (Broad):** 10%

**Обновление:** Автоматически каждые 1-2 дня.

**Рекомендация:** Создавать за 2-3 дня до запуска кампании.

**Статус:** Если seed-список перестаёт соответствовать минимальным требованиям, таргетинг прекращается через ~3 дня, сегмент получает статус "Неактивен".

## 3. Динамический ремаркетинг

### 3.1 Описание

Показ персонализированных объявлений с конкретными товарами/услугами, которые пользователь просматривал на сайте.

### 3.2 Применение

- **Display Network**
- **Performance Max**
- **App-кампании**

### 3.3 Для розничной торговли (Retail)

**Требования:**
- Аккаунт Google Merchant Center
- Товарный фид (Product Feed)
- Настроенный Google Tag на сайте
- Респонсивные объявления для Display

**Форматы фида:** .csv, .tsv, .xls, .xlsx

**Включение:**
1. В Merchant Center → Настройки → Дополнения
2. Нажать "Добавить" на карточке "Динамический ремаркетинг"

### 3.4 Для других бизнесов (Non-Retail)

- Управление через Assets в Google Ads
- Собственный фид данных

### 3.5 Бизнес-преимущества

- Снижение показателя брошенных корзин
- Напоминание о просмотренных товарах
- Автоматический подбор товаров из фида на основе:
  - Популярности
  - Истории просмотров пользователя
- Масштабирование на весь каталог товаров

## 4. Комбинированные сегменты (Combined Segments)

### 4.1 Описание

Создание сложных аудиторий путём объединения нескольких сегментов с логическими операторами.

### 4.2 Логические операторы

- **AND (И):** Пользователь должен быть во ВСЕХ указанных сегментах
- **OR (ИЛИ):** Пользователь должен быть ХОТЯ БЫ В ОДНОМ из сегментов
- **NOT (НЕ):** Исключение пользователей из определённых сегментов

### 4.3 Правила

- Минимум один сегмент должен быть включён перед добавлением исключений
- Исключения влияют только на комбинированный сегмент, не на другие сегменты в кампании
- Минимальный размер: 1000 пользователей (для защиты конфиденциальности)
- При размере менее 1000 — кампании/группы объявлений автоматически приостанавливаются

### 4.4 Примеры комбинаций

- In-Market + Affinity сегменты
- Ремаркетинг + Custom + Affinity сегменты
- Демография + In-Market сегменты

## 5. Настройки таргетинга: Targeting vs Observation

### 5.1 Режим "Таргетинг" (Targeting)

**Описание:** Ограничивает показ объявлений только выбранным аудиториям.

**Эффект:** Сужает охват до конкретных сегментов.

**Когда использовать:**
- Узкоспециализированные кампании
- Ремаркетинг-кампании
- Кампании с ограниченным бюджетом на конкретную аудиторию

### 5.2 Режим "Наблюдение" (Observation)

**Описание:** Не ограничивает охват, но позволяет отслеживать эффективность по выбранным аудиториям.

**Эффект:** Охват остаётся прежним, но доступна статистика по сегментам.

**Когда использовать:**
- Все Search-кампании (рекомендация Google)
- Display-кампании продвинутых рекламодателей
- Тестирование аудиторий перед применением таргетинга

**Важно для Smart Bidding:** Аудитории в режиме "Наблюдение" используются как сигналы для стратегий умного назначения ставок.

## 6. Исключение аудиторий (Audience Exclusions)

### 6.1 Описание

Предотвращение показа объявлений определённым группам пользователей.

### 6.2 Совместимость

- Search
- Display
- Demand Gen
- Standard Shopping
- Video

### 6.3 Ограничения

- Недоступно при создании кампании (только для существующих)
- Исключения по ключевым словам и аудиториям применимы только для first-party данных

### 6.4 Рекомендации

- Сначала наблюдать за эффективностью с аудиториями
- Затем добавлять исключения на основе данных

### 6.5 Типичные сценарии исключений

- Существующие клиенты (для acquisition-кампаний)
- Уже конвертированные пользователи
- Нецелевые демографические группы
- Пользователи с низкой вовлечённостью

---

## 7. Уровни применения аудиторий

### 7.1 Уровень кампании

- Применяется ко всем группам объявлений в кампании
- Удобно для единообразного таргетинга

### 7.2 Уровень группы объявлений

- Гранулярный контроль
- Разные аудитории для разных групп объявлений
- Возможность тестирования

## 8. Audience Manager (Менеджер аудиторий)

### 8.1 Функции

- Централизованное управление всеми сегментами
- Создание новых сегментов
- Редактирование существующих сегментов
- Просмотр размера и статуса сегментов
- Удаление неиспользуемых сегментов

### 8.2 Секции

- **Сегменты (Segments):** Все созданные аудитории
- **Источники данных (Data Sources):** Подключённые теги и источники
- **Ваши аналитические данные (Your Data Insights):** Статистика по аудиториям

## 10. Сроки и ретеншн

### 10.1 Membership Duration (Срок участия)

- **По умолчанию:** 30 дней
- **Максимум:** 540 дней
- **При повторном действии:** Счётчик сбрасывается

### 10.2 Влияние изменения срока

**Уменьшение срока (60 → 30 дней):**
- Пользователи, добавленные 31-60 дней назад, удаляются

**Увеличение срока (30 → 60 дней):**
- Все текущие участники остаются до 60 дней

### 10.3 Неактивность

- Для сегментов Google: пользователь удаляется при неактивности более 18 месяцев

## 11. User Stories

### US-001: Создание базового ремаркетинга
**Как** маркетолог,
**я хочу** создать аудиторию из посетителей моего сайта за последние 30 дней,
**чтобы** показывать им напоминающие объявления и возвращать на сайт.

### US-002: Сегментация по страницам
**Как** маркетолог e-commerce,
**я хочу** создать отдельные аудитории для посетителей разных категорий товаров,
**чтобы** показывать релевантные объявления по каждой категории.

### US-003: Динамический ремаркетинг
**Как** владелец интернет-магазина,
**я хочу** показывать пользователям объявления с товарами, которые они просматривали,
**чтобы** напомнить о брошенных корзинах и увеличить конверсии.

### US-004: Загрузка списка клиентов
**Как** маркетолог,
**я хочу** загрузить базу email-адресов моих клиентов,
**чтобы** показывать им рекламу новых продуктов и акций.

### US-005: Поиск похожей аудитории
**Как** маркетолог,
**я хочу** найти пользователей, похожих на моих лучших клиентов,
**чтобы** расширить охват на потенциально заинтересованную аудиторию.

### US-006: Исключение конвертированных
**Как** маркетолог,
**я хочу** исключить пользователей, которые уже совершили покупку,
**чтобы** не тратить бюджет на показы им acquisition-рекламы.

### US-007: Таргетинг по жизненным событиям
**Как** агент по недвижимости,
**я хочу** показывать рекламу людям, которые планируют переезд,
**чтобы** предложить им услуги в момент максимальной релевантности.

### US-008: Таргетинг по намерению покупки
**Как** автодилер,
**я хочу** таргетировать людей, активно исследующих покупку автомобиля,
**чтобы** показать им актуальные предложения.

### US-009: Комбинирование сегментов
**Как** маркетолог,
**я хочу** объединить in-market аудиторию с определённой демографией,
**чтобы** сузить таргетинг до наиболее релевантной аудитории.

### US-010: Сегментация по давности
**Как** маркетолог,
**я хочу** создать отдельные аудитории для посетителей за 7, 14 и 30 дней,
**чтобы** настроить разные сообщения и ставки в зависимости от давности визита.

### US-011: Пользовательский сегмент по конкурентам
**Как** маркетолог,
**я хочу** создать аудиторию на основе URL сайтов конкурентов,
**чтобы** показывать рекламу пользователям, интересующимся похожими продуктами.

### US-012: Таргетинг по интересам для awareness
**Как** бренд-менеджер,
**я хочу** таргетировать людей с интересом к спорту и фитнесу,
**чтобы** повысить узнаваемость бренда спортивного питания.

## 12. Бизнес-правила

### BR-001: Минимальный размер аудитории
Система не позволяет использовать аудитории меньше минимального порога (1000 для RLSA, 100 для YouTube) для защиты конфиденциальности пользователей.

### BR-002: Автоматическая приостановка
При уменьшении размера комбинированного сегмента ниже 1000 пользователей, соответствующие кампании/группы объявлений автоматически приостанавливаются.

### BR-003: Хеширование данных Customer Match
Все персональные данные (email, телефон, имя, фамилия) ОБЯЗАТЕЛЬНО хешируются SHA-256 перед отправкой на серверы Google.

### BR-004: Срок действия Customer Match
Списки Customer Match автоматически теряют участников, не обновлённых более 540 дней.

### BR-005: Обновление Lookalike
Lookalike-сегменты автоматически обновляются каждые 1-2 дня на основе seed-списка.

### BR-006: Сброс membership duration
При повторном совершении целевого действия счётчик срока участия пользователя сбрасывается.

### BR-007: Неактивность в сегментах Google
Пользователи удаляются из сегментов Google при отсутствии активности более 18 месяцев.

### BR-008: Ограничение идентификаторов
Максимум 20 идентификаторов (email, телефон и т.д.) на одного пользователя в Customer Match.

### BR-009: Статус Lookalike при несоответствии
При падении seed-списка ниже минимального порога Lookalike-сегмент получает статус "Неактивен" через ~3 дня.

### BR-010: Конфиденциальность
Google не использует чувствительные данные (здоровье, раса, религия, сексуальная ориентация) для таргетинга.

### BR-011: Custom Segments — не плейсменты
URL в Custom Segments определяют **похожую** аудиторию, а НЕ места размещения рекламы.

### BR-012: Life Events — временное окно
Пользователи определяются в окне ±6 месяцев от жизненного события.

## 14. Стратегии использования аудиторий

### 14.1 Стратегия по давности (Recency-based)

Создание нескольких аудиторий с разным сроком участия:
- **0-7 дней:** Высокая вовлечённость, агрессивные ставки
- **8-14 дней:** Средняя вовлечённость, умеренные ставки
- **15-30 дней:** Низкая вовлечённость, консервативные ставки

### 14.2 Стратегия по воронке

- **Top of Funnel:** Affinity сегменты для awareness
- **Middle of Funnel:** In-Market + Custom сегменты для consideration
- **Bottom of Funnel:** Ремаркетинг + Customer Match для conversion

### 14.3 Стратегия исключений

- Исключение конвертированных из acquisition-кампаний
- Исключение подписчиков из кампаний на подписку
- Исключение текущих клиентов из prospecting-кампаний

### 14.4 Многослойный таргетинг

Комбинирование нескольких типов сегментов для точного таргетинга:
- Демография + In-Market + Custom = высокоточная аудитория
