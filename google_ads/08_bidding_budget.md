# Модуль "Ставки и бюджеты" — Google Ads

## 1. Общее описание модуля

Модуль "Ставки и бюджеты" является ключевым компонентом рекламной платформы Google Ads, отвечающим за управление финансовыми аспектами рекламных кампаний. Модуль определяет, сколько рекламодатель готов платить за взаимодействие с рекламой (клик, показ, просмотр, конверсию) и как распределять рекламный бюджет между кампаниями.

### Ключевые функции модуля:
- Назначение ставок для участия в рекламных аукционах
- Управление дневными и общими бюджетами кампаний
- Автоматическая оптимизация ставок с помощью машинного обучения
- Корректировка ставок по различным критериям
- Прогнозирование расходов и результатов
- Контроль и мониторинг расходования средств

## 2. Стратегии назначения ставок

### 2.1. Ручные стратегии

#### 2.1.1. Manual CPC (Ручная цена за клик)

**Описание:**
Стратегия, при которой рекламодатель самостоятельно устанавливает максимальную цену за клик для каждого ключевого слова или группы объявлений.

**Бизнес-логика:**
- Рекламодатель устанавливает максимальную ставку (Max CPC), которую готов платить за один клик
- Фактическая цена за клик обычно ниже максимальной и зависит от аукциона
- Можно устанавливать ставки на уровне ключевого слова, группы объявлений или кампании
- Система предлагает рекомендованные ставки на основе конкурентных данных

**Правила работы:**
- Минимальная ставка зависит от валюты аккаунта (например, $0.01 для USD)
- Максимальная ставка ограничена системой (до $1000 в большинстве случаев)
- При установке ставки ниже порога входа в аукцион объявление не показывается
- Ставка по умолчанию группы объявлений применяется, если не задана ставка на уровне ключевого слова

**User Stories:**
- *Как рекламодатель, я хочу установить разные ставки для разных ключевых слов, чтобы больше платить за высококонверсионные запросы*
- *Как маркетолог, я хочу видеть рекомендованные ставки для попадания на первую страницу, чтобы понимать конкурентность ниши*
- *Как владелец бизнеса, я хочу контролировать каждую ставку вручную, чтобы полностью управлять расходами*

**Применимость:**
- Поисковые кампании
- Торговые кампании (Shopping)
- Кампании отелей (единственный доступный вариант)

### 2.2. Автоматические стратегии (без Smart Bidding)

#### 2.2.1. Maximize Clicks (Максимум кликов)

**Описание:**
Автоматическая стратегия, при которой система устанавливает ставки для получения максимального количества кликов в рамках заданного бюджета.

**Бизнес-логика:**
- Система анализирует вероятность клика для каждого аукциона
- Ставки устанавливаются автоматически для максимизации числа кликов
- Можно установить ограничение максимальной ставки (Max CPC Bid Limit)
- Не требует данных о конверсиях для работы

**Правила работы:**
- Система тратит весь доступный дневной бюджет
- При установке лимита Max CPC система не превышает указанную ставку
- Доступна корректировка ставок по расписанию показов
- Работает на уровне кампании

**User Stories:**
- *Как маркетолог, я хочу привлечь максимум трафика на сайт при фиксированном бюджете, чтобы увеличить узнаваемость бренда*
- *Как начинающий рекламодатель, я хочу использовать простую стратегию без необходимости отслеживать конверсии*
- *Как специалист, я хочу установить потолок ставки, чтобы не переплачивать за дорогие клики*

**Когда использовать:**
- Цель — увеличение трафика на сайт
- Нет настроенного отслеживания конверсий
- Новый аккаунт без исторических данных
- Бренд-кампании для защиты бренда

#### 2.2.2. Target Impression Share (Целевой процент показов)

**Описание:**
Стратегия, автоматически устанавливающая ставки для достижения заданного процента показов в определённой позиции на странице результатов поиска.

**Бизнес-логика:**
- Рекламодатель выбирает целевую позицию:
  - **Absolute Top** (Абсолютный верх) — первая позиция над результатами поиска
  - **Top** (Верх страницы) — позиции над органическими результатами
  - **Anywhere** (Любое место) — любая видимая позиция
- Устанавливается целевой процент показов (например, 80%)
- Можно установить ограничение максимальной ставки

**Правила работы:**
- Процент показов рассчитывается как: (фактические показы / возможные показы) × 100%
- Система агрессивно повышает ставки для достижения цели
- При низком лимите Max CPC цель может не достигаться
- Рекомендуемый целевой процент для Absolute Top — около 80%

**User Stories:**
- *Как владелец бренда, я хочу показываться на первой позиции по брендовым запросам в 100% случаев, чтобы защитить бренд от конкурентов*
- *Как маркетолог, я хочу гарантированно быть в топе по важным ключевым словам, чтобы максимизировать видимость*

**Ограничения:**
- Доступна только для поисковых кампаний
- Не оптимизирует конверсии — фокус на видимости
- Может значительно увеличить CPC

### 2.3. Smart Bidding (Умные стратегии)

Smart Bidding — набор стратегий автоматического назначения ставок, использующих машинное обучение Google для оптимизации конверсий или их ценности в каждом аукционе (auction-time bidding).

**Общие характеристики Smart Bidding:**
- Оптимизация в реальном времени для каждого аукциона
- Учёт множества сигналов: устройство, местоположение, время суток, браузер, язык, операционная система, списки ремаркетинга
- Автоматическая адаптация к сезонности и трендам
- Требуется настроенное отслеживание конверсий

#### 2.3.1. Maximize Conversions (Максимум конверсий)

**Описание:**
Стратегия, автоматически устанавливающая ставки для получения максимального количества конверсий в рамках заданного бюджета.

**Бизнес-логика:**
- Система анализирует вероятность конверсии для каждого аукциона
- Ставки устанавливаются автоматически на основе прогнозов машинного обучения
- Полностью расходует дневной бюджет для максимизации конверсий
- Не учитывает ценность конверсий — все конверсии равноценны

**Правила работы:**
- Требуется минимум 15-30 конверсий за последние 30 дней для эффективной работы
- Может начать работать с малым количеством данных
- Система самообучается и улучшает результаты со временем
- Период обучения обычно составляет 1-2 недели

**User Stories:**
- *Как интернет-магазин, я хочу получать максимум заказов при фиксированном бюджете, чтобы масштабировать бизнес*
- *Как SaaS-компания, я хочу максимизировать число регистраций, не думая о ручной настройке ставок*
- *Как лид-генератор, я хочу получать максимум заявок при ограниченном бюджете*

#### 2.3.2. Maximize Conversion Value (Максимум ценности конверсий)

**Описание:**
Стратегия, автоматически устанавливающая ставки для максимизации общей ценности (дохода) от конверсий в рамках бюджета.

**Бизнес-логика:**
- Система оптимизирует не количество, а суммарную ценность конверсий
- Учитывает разную ценность разных конверсий (например, разные суммы заказов)
- Предпочитает высокодоходные конверсии низкодоходным
- Требуется передача ценности конверсий в систему

**Правила работы:**
- Необходимо настроить передачу ценности конверсий (transaction value)
- Рекомендуется минимум 2 типа конверсий с разными ценностями
- Для оптимальной работы нужно 30-50 конверсий за 30 дней
- Полностью расходует дневной бюджет

**User Stories:**
- *Как e-commerce магазин, я хочу максимизировать выручку, а не количество заказов, чтобы увеличить прибыль*
- *Как рекламодатель, я хочу, чтобы система предпочитала клиентов с высоким чеком*

#### 2.3.3. Target CPA (Целевая цена за конверсию)

**Описание:**
Стратегия, автоматически устанавливающая ставки для получения максимума конверсий при заданной целевой цене за конверсию.

**Бизнес-логика:**
- Рекламодатель устанавливает целевую стоимость привлечения одной конверсии (Target CPA)
- Система стремится получить максимум конверсий, сохраняя среднюю CPA на целевом уровне
- Фактическая CPA может отклоняться от целевой в отдельных периодах
- По сути, это Maximize Conversions с ограничением по стоимости

**Правила работы:**
- Рекомендуется минимум 30 конверсий за последние 30 дней
- Нельзя устанавливать нереалистично низкую Target CPA — система не будет показывать объявления
- Рекомендуется начинать с CPA, близкой к текущей фактической
- При изменении Target CPA рекомендуется менять не более чем на 15-20%

**Формула расчёта:**
```
Средняя CPA = Общие расходы / Количество конверсий
```

**User Stories:**
- *Как маркетолог, я хочу получать лиды не дороже $50, чтобы соблюдать юнит-экономику*
- *Как владелец SaaS, я хочу контролировать стоимость привлечения клиента, чтобы сохранять прибыльность*
- *Как агентство, я хочу гарантировать клиенту определённую стоимость конверсии*

#### 2.3.4. Target ROAS (Целевая рентабельность)

**Описание:**
Стратегия, автоматически устанавливающая ставки для достижения заданной рентабельности рекламных расходов.

**Бизнес-логика:**
- ROAS (Return on Ad Spend) = Доход от рекламы / Расходы на рекламу × 100%
- Рекламодатель устанавливает целевой ROAS (например, 400% = $4 дохода на $1 расхода)
- Система балансирует между объёмом и рентабельностью
- По сути, это Maximize Conversion Value с ограничением по рентабельности

**Правила работы:**
- Рекомендуется минимум 50 конверсий с ценностью за последние 30 дней
- Необходимо передавать ценность каждой конверсии
- Желательно иметь минимум 2 различных ценности конверсий
- При слишком высоком Target ROAS объём показов может сильно снизиться

**Формула расчёта:**
```
ROAS = (Общий доход / Общие расходы) × 100%
Пример: ROAS 500% означает $5 дохода на каждый $1 расхода
```

**User Stories:**
- *Как e-commerce магазин, я хочу получать минимум 400% возврата на рекламу, чтобы оставаться прибыльным*
- *Как маркетолог, я хочу масштабировать кампании, сохраняя определённую рентабельность*
- *Как финансовый директор, я хочу контролировать эффективность маркетинговых инвестиций*

### 2.4. Стратегии для медийной и видеорекламы

#### 2.4.1. Target CPM (Целевая цена за тысячу показов)

**Описание:**
Стратегия для максимизации охвата при заданной средней цене за 1000 показов.

**Бизнес-логика:**
- Рекламодатель устанавливает желаемую среднюю цену за 1000 показов
- Система оптимизирует для получения уникального охвата
- Фактическая CPM может колебаться, но средняя стремится к целевой
- Оптимальна для кампаний на узнаваемость бренда

**Применимость:**
- Видеокампании (YouTube)
- Demand Gen кампании

**User Stories:**
- *Как бренд-менеджер, я хочу охватить максимум уникальных пользователей при бюджете CPM не выше $5*

#### 2.4.2. Viewable CPM (vCPM — Цена за видимые показы)

**Описание:**
Ручная стратегия, при которой оплата производится только за видимые показы.

**Бизнес-логика:**
- Показ считается видимым, если:
  - Для баннеров: 50% площади видно минимум 1 секунду
  - Для видео: 50% площади видно минимум 2 секунды
- Рекламодатель устанавливает максимальную ставку за 1000 видимых показов
- Оптимально для повышения узнаваемости бренда

**Применимость:**
- Медийные кампании (Display Network)
- Недоступна для поисковых кампаний

**User Stories:**
- *Как рекламодатель, я хочу платить только за показы, которые реально видели пользователи*

#### 2.4.3. CPV (Цена за просмотр видео)

**Описание:**
Стратегия для видеорекламы, при которой оплата производится за просмотр видео или взаимодействие с ним.

**Бизнес-логика:**
- Просмотр засчитывается, если пользователь:
  - Посмотрел минимум 30 секунд видео (или всё видео, если оно короче)
  - Взаимодействовал с объявлением (клик по CTA, карточке, сопутствующему баннеру)
- Рекламодатель устанавливает максимальную цену за просмотр

**Применимость:**
- Видеокампании TrueView на YouTube
- Кампании Video Action

**User Stories:**
- *Как маркетолог, я хочу платить только когда пользователи реально смотрят мои видео*

### 2.5. Портфельные стратегии ставок

**Описание:**
Портфельные стратегии позволяют применять одну стратегию назначения ставок к нескольким кампаниям одновременно.

**Бизнес-логика:**
- Создаётся общая стратегия, которая применяется к группе кампаний
- Система оптимизирует ставки с учётом данных всех кампаний в портфеле
- Позволяет устанавливать ограничения Max CPC даже для Smart Bidding стратегий
- Ускоряет обучение алгоритмов за счёт большего объёма данных

**Преимущества:**
- Единое управление ставками для группы кампаний
- Возможность установки Max CPC Bid Limit для Smart Bidding
- Ускоренное обучение алгоритма за счёт объединённых данных
- Централизованное изменение настроек для всех кампаний

**Доступные типы портфельных стратегий:**
- Target ROAS
- Target CPA
- Maximize Clicks
- Maximize Conversions
- Maximize Conversion Value
- Target Impression Share

**Правила работы:**
- Кампании в портфеле должны иметь схожие цели конверсии
- Рекомендуется объединять кампании с низким объёмом конверсий
- Можно связывать портфельные стратегии с общими бюджетами

**User Stories:**
- *Как маркетолог, я хочу применить единую стратегию Target CPA ко всем поисковым кампаниям, чтобы упростить управление*
- *Как специалист, я хочу объединить маленькие кампании для ускорения обучения алгоритма*
- *Как агентство, я хочу установить потолок ставки для Smart Bidding, чтобы контролировать максимальный CPC*

## 3. Типы бюджетов

### 3.1. Дневной бюджет кампании (Average Daily Budget)

**Описание:**
Средняя сумма, которую рекламодатель готов тратить на кампанию ежедневно.

**Бизнес-логика:**
- Устанавливается на уровне отдельной кампании
- Является средним значением — фактические расходы могут отклоняться день ото дня
- Система может перерасходовать в дни высокого трафика и недорасходовать в дни низкого

**Правила работы:**
- Дневной расход может превышать бюджет до 2 раз (overdelivery)
- Месячный расход никогда не превышает: Дневной бюджет × 30.4
- Минимальный дневной бюджет зависит от валюты и типа кампании
- Изменение бюджета вступает в силу немедленно

**Формула месячного лимита:**
```
Максимальный месячный расход = Дневной бюджет × 30.4
Пример: $100/день → максимум $3,040/месяц
```

**User Stories:**
- *Как малый бизнес, я хочу тратить не более $50 в день на рекламу, чтобы контролировать расходы*
- *Как маркетолог, я хочу понимать, сколько максимум я потрачу за месяц при заданном дневном бюджете*

### 3.2. Общий бюджет (Shared Budget)

**Описание:**
Единый дневной бюджет, который распределяется между несколькими кампаниями в аккаунте.

**Бизнес-логика:**
- Создаётся один бюджет, который делится между выбранными кампаниями
- Система автоматически перераспределяет средства между кампаниями
- Если одна кампания не расходует бюджет, излишки перетекают в другие
- Оптимизирует использование бюджета между связанными кампаниями

**Правила работы:**
- Устанавливается общий дневной бюджет для группы кампаний
- Кампании конкурируют за бюджет на основе потенциала производительности
- Нельзя использовать для: Performance Max, App кампаний, Smart Shopping, Hotel (с комиссионной ставкой)
- Рекомендуется комбинировать с портфельными стратегиями ставок

**User Stories:**
- *Как маркетолог, я хочу автоматически перераспределять бюджет между кампаниями, чтобы не упускать трафик в высокопотенциальных кампаниях*
- *Как владелец бизнеса, я хочу установить общий бюджет $500/день для всей рекламы, не думая о распределении*
- *Как специалист, я хочу максимизировать эффективность общего маркетингового бюджета*

### 3.3. Общий бюджет кампании (Campaign Total Budget)

**Описание:**
Фиксированный общий бюджет на весь период проведения кампании.

**Бизнес-логика:**
- Устанавливается сумма на весь период кампании (от старта до завершения)
- Система распределяет расходы по дням для оптимального использования
- Дневные лимиты не применяются — система тратит оптимально
- Общий расход никогда не превысит установленный бюджет

**Правила работы:**
- Требуется указать даты начала и окончания кампании
- Тип бюджета нельзя изменить после создания кампании
- Доступен для: Demand Gen, Search, Shopping, Performance Max
- Система учитывает прошедшие расходы и корректирует дневные траты

**User Stories:**
- *Как маркетолог, я хочу потратить ровно $10,000 на двухнедельную промо-акцию, чтобы уложиться в выделенный бюджет*
- *Как event-менеджер, я хочу распределить рекламный бюджет мероприятия на весь период продвижения*

---

## 4. Корректировки ставок (Bid Adjustments)

### 4.1. Общие принципы

**Описание:**
Корректировки ставок позволяют увеличивать или уменьшать ставки для определённых сегментов аудитории, устройств, времени или местоположений.

**Бизнес-логика:**
- Выражаются в процентах от базовой ставки (от -100% до +900%)
- Множественные корректировки перемножаются (не складываются)
- Корректировка -100% полностью исключает показы для сегмента
- Smart Bidding автоматически учитывает большинство факторов

**Формула расчёта с множественными корректировками:**
```
Итоговая ставка = Базовая ставка × (1 + Корректировка1) × (1 + Корректировка2) × ...

Пример:
Базовая ставка: $1.00
Корректировка по устройству (мобильные): +10%
Корректировка по местоположению (Москва): +20%
Итоговая ставка: $1.00 × 1.10 × 1.20 = $1.32
```

### 4.2. Корректировки по устройствам

**Описание:**
Позволяют изменять ставки для показов на разных типах устройств.

**Типы устройств:**
- Компьютеры (десктопы и ноутбуки)
- Мобильные устройства (смартфоны)
- Планшеты

**Бизнес-логика:**
- Диапазон: от -100% (полное исключение) до +900%
- Устанавливается на уровне кампании или группы объявлений
- Корректировка на уровне группы объявлений переопределяет кампанию
- Исключение: если кампания имеет -100%, группа объявлений не может это переопределить

**User Stories:**
- *Как e-commerce магазин, я хочу снизить ставки на мобильных на 20%, так как конверсия там ниже*
- *Как локальный бизнес, я хочу полностью исключить показы на десктопах, так как мои клиенты ищут на ходу*
- *Как B2B компания, я хочу повысить ставки для десктопов на 30%, так как бизнес-решения принимаются в офисе*

### 4.3. Корректировки по местоположению

**Описание:**
Позволяют изменять ставки для показов пользователям в определённых географических регионах.

**Уровни таргетинга:**
- Страны
- Регионы/области
- Города
- Радиус вокруг точки
- Почтовые индексы (в некоторых странах)

**Бизнес-логика:**
- Диапазон: от -90% до +900%
- Применяется наиболее специфичная корректировка (город важнее страны)
- Множественные корректировки для одной локации не суммируются

**Правило специфичности:**
```
Если установлено:
- Россия: +10%
- Москва: +30%
Для пользователя из Москвы применяется только +30% (более специфичная)
```

**User Stories:**
- *Как сеть ресторанов, я хочу повысить ставки на 50% для районов рядом с нашими точками*
- *Как федеральная компания, я хочу платить больше за клики из столицы, где выше покупательская способность*

### 4.4. Корректировки по расписанию (Ad Schedule)

**Описание:**
Позволяют изменять ставки в зависимости от дня недели и времени суток.

**Бизнес-логика:**
- Можно создавать несколько временных интервалов для разных дней
- Диапазон корректировок: от -90% до +900%
- Интервалы можно задавать с точностью до 15 минут
- Можно полностью отключить показы в определённые периоды (-100% недоступна, но можно исключить из расписания)

**User Stories:**
- *Как B2B компания, я хочу повысить ставки в рабочие часы на 20%, так как ЛПР принимают решения в офисе*
- *Как служба доставки еды, я хочу максимально увеличить ставки в обеденное время и вечером*
- *Как ночной клуб, я хочу концентрировать бюджет на пятницу и субботу вечером*

### 4.5. Корректировки по аудиториям

**Описание:**
Позволяют изменять ставки для определённых аудиторных сегментов.

**Типы аудиторий:**
- Списки ремаркетинга (посетители сайта)
- Похожие аудитории
- Аудитории по интересам (Affinity)
- Аудитории заинтересованных покупателей (In-market)
- Аудитории жизненных событий
- Собственные данные (Customer Match)

**Бизнес-логика:**
- Диапазон: от -90% до +900%
- Можно комбинировать с другими критериями таргетинга
- Позволяет делать ставки выше для "тёплой" аудитории

**User Stories:**
- *Как e-commerce, я хочу повысить ставки на 50% для пользователей, которые добавляли товар в корзину, но не купили*
- *Как SaaS, я хочу увеличить ставки для пользователей, посещавших страницу цен*
- *Как автодилер, я хочу платить больше за аудиторию "планирующие покупку автомобиля"*

### 4.6. Корректировки по демографии

**Описание:**
Позволяют изменять ставки на основе демографических характеристик пользователей.

**Доступные параметры:**
- Возраст: 18-24, 25-34, 35-44, 45-54, 55-64, 65+, Неизвестно
- Пол: Мужской, Женский, Неизвестно
- Семейный доход: Верхние 10%, 11-20%, 21-30%, и т.д. (не во всех странах)
- Родительский статус: Родители, Не родители, Неизвестно

**Бизнес-логика:**
- Диапазон: от -90% до +900%
- Категория "Неизвестно" может составлять значительную долю трафика
- Корректировки по демографии перемножаются с другими

**User Stories:**
- *Как бренд детских товаров, я хочу повысить ставки на 40% для категории "Родители"*
- *Как люксовый бренд, я хочу увеличить ставки для аудитории с высоким доходом*

### 4.7. Ограничения при Smart Bidding

**Важно:**
При использовании Smart Bidding (Target CPA, Target ROAS, Maximize Conversions, Maximize Conversion Value):
- Корректировки по устройствам **работают** только как -100% (полное исключение)
- Корректировки по времени, аудиториям, демографии **игнорируются** — система оптимизирует автоматически
- Корректировки по местоположению **игнорируются** — система учитывает геолокацию автоматически

Это связано с тем, что Smart Bidding самостоятельно учитывает все эти факторы при расчёте оптимальной ставки для каждого аукциона.

## 5. Сезонные корректировки (Seasonality Adjustments)

### 5.1. Описание

Инструмент для информирования Smart Bidding об ожидаемых краткосрочных изменениях в коэффициенте конверсии.

### 5.2. Бизнес-логика

- Используется для событий, которые Smart Bidding не может предсказать
- Рекламодатель указывает ожидаемое изменение конверсии (например, +50%)
- Система корректирует ставки с учётом ожидаемого изменения
- После окончания периода система автоматически возвращается к норме

### 5.3. Правила использования

- Оптимальны для коротких событий (1-7 дней)
- Не рекомендуется использовать дольше 14 дней
- Не нужны для предсказуемой сезонности (Новый год и т.п.) — Smart Bidding учитывает её автоматически
- Используйте только при ожидании значительных изменений конверсии

### 5.4. Доступность

- Search, Shopping, Display: Target CPA, Target ROAS
- Performance Max: все стратегии
- App кампании: все стратегии (бета)

### 5.5. Примеры использования

| Событие | Длительность | Ожидаемое изменение конверсии |
|---------|--------------|------------------------------|
| Флеш-распродажа | 3 дня | +50% |
| Black Friday | 4 дня | +80% |
| Запуск нового продукта | 7 дней | +30% |
| Технические работы на сайте | 1 день | -70% |

### 5.6. User Stories

- *Как маркетолог, я хочу сообщить системе о предстоящей распродаже с ожидаемым ростом конверсии на 50%, чтобы система агрессивнее делала ставки*
- *Как e-commerce менеджер, я хочу предупредить систему о техническом окне, когда конверсия упадёт на 90%, чтобы не тратить бюджет впустую*

## 6. Прогнозирование и планирование

### 6.1. Performance Planner (Планировщик эффективности)

**Описание:**
Инструмент для прогнозирования результатов кампаний и оптимального распределения бюджета.

**Возможности:**
- Прогнозирование кликов, конверсий, расходов на период до квартала
- Моделирование влияния изменения бюджета на результаты
- Рекомендации по оптимальному распределению бюджета между кампаниями
- Создание планов для нескольких кампаний одновременно

**Бизнес-логика:**
- Использует исторические данные аккаунта и рыночные тренды
- Учитывает сезонность и конкурентную среду
- Симулирует релевантные аукционы за последние 7-10 дней
- Прогнозы обновляются ежедневно

**Доступность:**
- Search, Shopping, Display, App, Video, Local, Performance Max кампании
- Поддерживает до 10,000 кампаний в одном плане
- Доступен на уровне управляющих аккаунтов (MCC)

**Метрики прогнозирования:**
- Клики
- Показы
- Конверсии
- Ценность конверсий
- CPC, CPA, ROAS

**User Stories:**
- *Как маркетолог, я хочу узнать, сколько конверсий я получу при увеличении бюджета на 20%, чтобы обосновать запрос дополнительного бюджета*
- *Как финансовый директор, я хочу спрогнозировать расходы на рекламу на следующий квартал*
- *Как агентство, я хочу показать клиенту, как изменится результат при разных уровнях бюджета*

### 6.2. Рекомендации по бюджету

**Описание:**
Система автоматически предоставляет рекомендации по оптимизации бюджета.

**Типы рекомендаций:**

1. **"Limited by Budget" (Ограничено бюджетом)**
   - Появляется, когда кампания могла бы получить больше трафика
   - Показывает упущенные показы и клики
   - Предлагает конкретную сумму увеличения бюджета

2. **Рекомендации по перераспределению**
   - Предложения перенести бюджет из менее эффективных кампаний
   - Прогноз дополнительных конверсий при перераспределении

3. **Прогноз пейсинга**
   - Показывает, будет ли бюджет израсходован к концу периода
   - Предупреждает о потенциальном недорасходе или перерасходе

**User Stories:**
- *Как маркетолог, я хочу видеть, какие кампании ограничены бюджетом, чтобы принять решение о перераспределении*
- *Как специалист, я хочу получать уведомления о неэффективном использовании бюджета*

## 7. Мониторинг и контроль расходов

### 7.1. Пейсинг бюджета (Budget Pacing)

**Описание:**
Инструменты для отслеживания темпа расходования бюджета.

**Функции:**
- Отображение текущего расхода vs. плана
- Прогноз расхода на конец месяца
- Предупреждения о отклонениях от плана
- Визуализация трендов расходов

**Статусы кампаний:**
- **Eligible** — кампания активна и показывается
- **Limited by budget** — бюджет ограничивает показы
- **Learning** — стратегия ставок в режиме обучения
- **Projected to be limited** — прогнозируется ограничение бюджетом

### 7.2. Лимиты и ограничения

**Правила overdelivery (перерасхода):**
- Дневной расход может превысить бюджет до 2 раз
- Для кампаний с оплатой за конверсии — до 30.4 раз
- Месячный расход не превышает дневной бюджет × 30.4
- При превышении месячного лимита система предоставляет кредит

**User Stories:**
- *Как финансист, я хочу быть уверен, что месячный расход не превысит запланированный, чтобы соблюдать бюджет*
- *Как маркетолог, я хочу понимать, почему вчера потратилось вдвое больше дневного бюджета*

### 7.3. Оповещения и уведомления

**Типы автоматических уведомлений:**
- Исчерпание бюджета
- Значительные изменения в расходах
- Статус "Limited by budget"
- Проблемы с биллингом
- Завершение периода обучения стратегии

**Настраиваемые правила:**
- Уведомление при превышении определённого расхода
- Автоматическая пауза кампании при достижении лимита
- Оповещение об аномальном CPC или CPA

## 8. Бизнес-правила модуля

### 8.1. Правила биллинга

1. Оплата производится после показа рекламы (постоплата для автоматических платежей)
2. Можно установить предоплатный баланс для контроля расходов
3. Порог оплаты увеличивается по мере истории успешных платежей
4. При неуспешном платеже показ рекламы приостанавливается

### 8.2. Правила работы стратегий

1. **Период обучения:**
   - Smart Bidding требует 1-2 недели для обучения
   - Во время обучения результаты могут быть нестабильными
   - Значительные изменения настроек перезапускают обучение

2. **Минимальные требования к данным:**
   - Maximize Conversions: рекомендуется 15+ конверсий за 30 дней
   - Target CPA: рекомендуется 30+ конверсий за 30 дней
   - Target ROAS: рекомендуется 50+ конверсий с ценностью за 30 дней

3. **Изменение целевых показателей:**
   - Рекомендуется менять Target CPA/ROAS не более чем на 15-20% за раз
   - Резкие изменения могут привести к резкому падению объёмов

### 8.3. Правила взаимодействия ставок и бюджета

1. Бюджет является ограничивающим фактором — система не превысит его
2. При недостаточном бюджете конкурентоспособность ставок снижается
3. Рекомендуется устанавливать бюджет минимум в 10× Target CPA
4. Для Target ROAS бюджет должен позволять минимум 5-10 конверсий в день

### 8.4. Правила комбинирования настроек

1. Портфельные стратегии + Общие бюджеты = рекомендованная комбинация
2. Manual CPC можно комбинировать с любыми корректировками ставок
3. Smart Bidding игнорирует большинство корректировок (кроме -100% по устройствам)
4. Корректировки перемножаются, не складываются

## 10. Глоссарий терминов
