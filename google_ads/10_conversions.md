# Модуль "Конверсии и отслеживание" — Google Ads

## 1. Общее описание модуля

Модуль "Конверсии и отслеживание" — центральный компонент Google Ads, позволяющий рекламодателям измерять эффективность рекламных кампаний путём отслеживания действий пользователей после взаимодействия с рекламой. Модуль обеспечивает сбор данных о конверсиях с веб-сайтов, мобильных приложений, телефонных звонков и офлайн-источников, а также предоставляет инструменты атрибуции для понимания вклада каждого рекламного взаимодействия в достижение бизнес-целей.

---

## 2. Типы конверсий

### 2.1 Конверсии с веб-сайта (Website Conversions)

#### Описание
Отслеживание действий пользователей на сайте после клика по рекламе. Используется Google Tag (gtag.js) для измерения событий.

#### Поддерживаемые действия
- **Покупка (Purchase)** — завершение транзакции электронной коммерции
- **Добавление в корзину (Add to Cart)** — добавление товара в корзину
- **Отправка формы (Submit Lead Form)** — заполнение контактной формы
- **Регистрация (Sign Up)** — создание аккаунта
- **Подписка (Subscribe)** — оформление подписки
- **Просмотр страницы (Page View)** — посещение определённой страницы
- **Пользовательские события (Custom)** — любые специфичные для бизнеса действия

#### Способы срабатывания
1. **По загрузке страницы (Page Load)** — конверсия засчитывается при посещении определённой страницы (например, страницы "Спасибо за заказ")
2. **По клику (Click)** — конверсия засчитывается при клике на элемент (кнопка, ссылка)

#### Требования
- Установленный Google Tag на всех страницах сайта
- Event Snippet на странице конверсии или вызов события через gtag()
- Включённый JavaScript в браузере пользователя

---

### 2.2 Конверсии из приложений (App Conversions)

#### Описание
Отслеживание установок приложений и действий внутри мобильных приложений через Firebase SDK или сторонние партнёры по атрибуции.

#### Поддерживаемые действия
- **Первый запуск (First Open)** — первый запуск приложения после установки
- **Покупка в приложении (In-App Purchase)** — совершение платежа внутри приложения
- **Подписка (Subscription)** — оформление подписки в приложении
- **Достижение уровня (Level Achieved)** — прогресс в игре
- **Регистрация (Sign Up)** — создание аккаунта в приложении
- **Пользовательские события** — любые события, логируемые через Firebase

#### Интеграция с Firebase
- Связывание проекта Firebase с аккаунтом Google Ads
- Отметка событий как конверсий в консоли Firebase
- Автоматический импорт отмеченных событий в Google Ads
- Не требуется дополнительный код после интеграции Firebase SDK

#### Измерение на устройстве для iOS (On-Device Conversion Measurement)
- Измерение установок и действий с сохранением приватности пользователей
- Использование first-party данных из процесса аутентификации приложения
- Хэширование идентификаторов на устройстве — никакие персональные данные не покидают устройство

#### Web to App Connect
- Связывание кликов по рекламе на веб-сайте с конверсиями в приложении
- Настройка deep linking для перенаправления из рекламы в приложение
- Среднее увеличение конверсий: 2x при использовании deep linking

### 2.3 Конверсии телефонных звонков (Phone Call Conversions)

#### Типы отслеживания звонков

**1. Звонки из рекламы (Calls from Ads)**
- Пользователь нажимает на телефонный номер в объявлении или расширении
- Работает только на мобильных устройствах
- Использует переадресационный номер Google для отслеживания
- Конверсия засчитывается при достижении минимальной длительности звонка

**2. Звонки на номер с сайта (Calls to Website Number)**
- Google динамически заменяет номер на сайте на переадресационный
- Отслеживается связь между кликом по рекламе и последующим звонком
- Конверсия засчитывается при достижении минимальной длительности

**3. Клики по номеру на мобильном сайте (Clicks on Mobile Website)**
- Отслеживается только факт клика (тапа) по номеру телефона
- Сам звонок не отслеживается
- Подходит для стран без поддержки переадресационных номеров Google

**4. Импортированные конверсии звонков (Imported Call Conversions)**
- Импорт данных из CRM или системы отслеживания звонков
- Позволяет отслеживать качество звонков (квалифицированный лид, продажа)
- Наиболее точный метод — основан на реальных результатах продаж

#### Настройки звонковых конверсий
- **Минимальная длительность звонка** — порог в секундах для засчитывания конверсии (по умолчанию 60 секунд)
- **Категория конверсии** — квалифицированный лид, продажа, бронирование и т.д.
- **Стоимость конверсии** — денежное значение звонка

#### Требования к странам
- Переадресационные номера Google доступны в ограниченном списке стран
- В остальных странах доступно только отслеживание кликов

### 2.4 Офлайн-конверсии и импорт (Offline Conversions Import)

#### Описание
Импорт данных о конверсиях, произошедших вне онлайн-среды — в магазинах, по телефону, при личных встречах.

#### Способы идентификации

**1. GCLID (Google Click ID)**
- Уникальный идентификатор клика по рекламе
- Добавляется к URL при переходе по рекламе
- Необходимо сохранять в CRM вместе с данными лида
- Максимальный срок импорта: 90 дней с момента клика

**2. Enhanced Conversions for Leads (Улучшенные конверсии для лидов)**
- Использование first-party данных пользователей (email, телефон)
- Хэширование данных перед отправкой (SHA-256)
- Не требует передачи GCLID
- Максимальный срок импорта: 63 дня

#### Типы импортируемых конверсий

**Квалифицированный лид (Qualified Lead)**
- Лид, прошедший первичную квалификацию в CRM
- Показывает Google Ads какие клики приводят к качественным лидам

**Закрытая сделка (Converted Lead)**
- Лид, завершивший процесс покупки/заключения договора
- Позволяет оптимизировать на реальную выручку

#### Методы импорта

**1. Data Manager (рекомендуемый)**
- Визуальный интерфейс без кода
- Прямая интеграция с CRM (Salesforce, HubSpot)
- Автоматическая синхронизация
- Поддержка GCLID и user-provided data

**2. Загрузка файла**
- Ручной или автоматический (по расписанию) upload CSV/Excel
- Формат: GCLID, время конверсии, ценность, валюта

**3. Google Ads API**
- Программный импорт из собственных систем
- Рекомендуется для больших объёмов данных

#### Бизнес-правила импорта
- Импорт должен происходить не реже 1 раза в сутки для оптимальной работы Smart Bidding
- Конверсии атрибутируются к дате клика, а не дате импорта
- Дубликаты по transaction_id игнорируются

## 3. Модели атрибуции

### 3.1 Доступные модели (2025)

С сентября 2023 года Google оставил только две модели атрибуции:

#### Data-Driven Attribution (Атрибуция на основе данных) — по умолчанию
- **Принцип работы**: Анализирует все взаимодействия пользователя с рекламой на пути к конверсии
- **Сравнение путей**: Сопоставляет пути конвертировавшихся и не конвертировавшихся пользователей
- **Определение паттернов**: Выявляет, какие взаимодействия с рекламой чаще приводят к конверсии
- **Распределение ценности**: Кредит распределяется между всеми взаимодействиями пропорционально их вкладу
- **Минимальные требования**: Больше не требуется минимальный порог данных — работает для всех аккаунтов
- **Поддерживаемые каналы**: Search, Shopping, YouTube, Display, Demand Gen

#### Last Click (Последний клик)
- **Принцип работы**: 100% кредита присваивается последнему клику перед конверсией
- **Применение**: Подходит для коротких циклов покупки, импульсных покупок
- **Ограничение**: Игнорирует влияние предшествующих точек касания
- **Статус**: Доступна как альтернатива, но не рекомендуется

### 3.2 Устаревшие модели (недоступны с 2023)

Следующие модели были удалены:
- **First Click (Первый клик)** — 100% кредита первому взаимодействию
- **Linear (Линейная)** — равное распределение между всеми взаимодействиями
- **Time Decay (Затухание по времени)** — больший вес недавним взаимодействиям
- **Position-Based (Позиционная)** — 40% первому, 40% последнему, 20% остальным

Конверсии, использовавшие эти модели, автоматически переведены на Data-Driven Attribution.

## 4. Окна конверсии (Conversion Windows)

### 4.1 Типы окон

#### Click-through Conversion Window (Окно конверсий по кликам)
- **Описание**: Период после клика по рекламе, в течение которого конверсия будет атрибутирована
- **Доступные значения**: 1-90 дней
- **По умолчанию**: 30 дней
- **Рекомендация**: Минимум 7 дней для достаточного объёма данных

#### Engaged-view Conversion Window (Окно конверсий по просмотрам видео)
- **Применение**: Видеореклама (YouTube)
- **Условие**: Пользователь смотрел минимум 10 секунд skippable-рекламы или 5 секунд in-feed/Shorts
- **Доступные значения**: 1-30 дней
- **По умолчанию**: 3 дня

#### View-through Conversion Window (Окно конверсий по показам)
- **Применение**: Display и Video кампании
- **Условие**: Пользователь видел рекламу (50% площади минимум 1 секунду), но не кликал
- **Доступные значения**: 1-30 дней
- **По умолчанию**: 1 день

### 4.2 Бизнес-рекомендации по выбору окна

| Тип бизнеса | Рекомендуемое окно | Обоснование |
|-------------|-------------------|-------------|
| E-commerce (низкая цена) | 7-14 дней | Быстрое принятие решения |
| E-commerce (высокая цена) | 30-60 дней | Длительный цикл выбора |
| B2B услуги | 60-90 дней | Длительный процесс продаж |
| SaaS | 30-60 дней | Период оценки и триала |
| Местные услуги | 7-14 дней | Срочные потребности |

### 4.3 Lookback Window (Окно ретроспективного анализа)
- **Отличие от Conversion Window**: Используется в отчётах по атрибуции, не влияет на подсчёт конверсий
- **Назначение**: Определяет, какие взаимодействия учитываются при анализе путей конверсии
- **Доступные значения**: 30, 60, 90 дней

## 5. Enhanced Conversions (Улучшенные конверсии)

### 5.1 Общее описание

Enhanced Conversions — функция повышения точности отслеживания конверсий путём использования first-party данных пользователей. Данные хэшируются на стороне клиента и безопасно передаются в Google для сопоставления с аккаунтами Google.

### 5.2 Enhanced Conversions for Web

#### Принцип работы
1. Пользователь кликает по рекламе и попадает на сайт
2. Пользователь совершает конверсию (покупка, регистрация)
3. Сайт собирает данные пользователя (email, телефон, адрес)
4. Данные хэшируются с помощью SHA-256 на стороне клиента
5. Хэшированные данные отправляются вместе с событием конверсии
6. Google сопоставляет хэш с залогиненными пользователями Google
7. Конверсия атрибутируется даже при отсутствии cookies

#### Поддерживаемые данные
- **Email** — основной идентификатор
- **Телефон** — в формате E.164 (+7XXXXXXXXXX)
- **Имя и фамилия** — обязательны для использования адреса
- **Адрес** — страна, почтовый индекс, город (опционально)

#### Требования к нормализации
- Удаление пробелов в начале и конце
- Приведение к нижнему регистру
- Формат телефона E.164

### 5.3 Enhanced Conversions for Leads

#### Отличие от Enhanced Conversions for Web
- Предназначена для офлайн-конверсий
- Данные собираются на этапе отправки формы
- Конверсия импортируется позже при закрытии сделки в CRM

#### Преимущества
- Не требуется хранение GCLID
- Проще в интеграции
- Поддержка Engaged-view conversions
- Cross-device конверсии

### 5.4 Настройка через Google Ads Data Manager

Data Manager (2024-2025) — централизованный инструмент для управления first-party данными:
- Point-and-click интерфейс
- Интеграции с Salesforce, HubSpot, Zapier
- Автоматическое хэширование
- Мониторинг качества данных

## 6. Подсчёт и типы конверсий

### 6.1 Counting (Подсчёт конверсий)

#### "Every" (Каждая)
- Подсчитывается каждая конверсия после взаимодействия с рекламой
- **Применение**: E-commerce (каждая покупка имеет ценность)
- **Важно**: Использовать transaction_id для дедупликации

#### "One" (Одна)
- Подсчитывается только одна конверсия на взаимодействие
- **Применение**: Лидогенерация (повторная регистрация не имеет ценности)

### 6.2 Cross-Device Conversions (Кросс-девайс конверсии)

#### Описание
Отслеживание конверсий, начатых на одном устройстве и завершённых на другом.

#### Пример
- Пользователь кликает по рекламе на смартфоне
- Позже совершает покупку на десктопе
- Конверсия атрибутируется к мобильному клику

#### Методология
- Используются данные залогиненных пользователей Google
- Моделирование для пользователей без входа
- Privacy-safe подход

#### Ограничение
Кросс-девайс конверсии доступны только при использовании нативного отслеживания Google Ads. При импорте из GA4 эта функциональность недоступна.

### 6.3 View-through vs Engaged-view vs Click-through

| Тип | Условие | Учёт в Conversions | Применение |
|-----|---------|-------------------|------------|
| Click-through | Клик по рекламе | Да | Все форматы |
| Engaged-view | Просмотр 10+ сек видео | Да | YouTube |
| View-through | Показ без клика | Только All Conversions | Display, Video |

## 7. Категории и цели конверсий

### 7.1 Стандартные категории

#### Продажи (Sales)
- Purchase (Покупка)
- Add to Cart (Добавление в корзину)
- Begin Checkout (Начало оформления)
- Subscriptions (Подписки)

#### Лиды (Leads)
- Submit Lead Form (Отправка формы)
- Phone Call Lead (Звонок)
- Book Appointment (Запись на приём)
- Request Quote (Запрос цены)
- Get Directions (Проложить маршрут)

#### Вовлечённость (Engagement)
- Page View (Просмотр страницы)
- Sign Up (Регистрация)
- Contact (Контакт)
- Download (Скачивание)

### 7.2 Цели конверсии (Conversion Goals)

#### Стандартные цели
- Конверсии автоматически группируются по категориям
- Например, все действия Purchase объединяются в цель "Purchases"
- Стандартные цели используются для оптимизации кампаний

#### Кастомные цели
- Возможность объединить разные типы действий
- Пример: цель "High-Value Actions" = Purchase + Submit Lead Form
- Рекомендуется для продвинутых сценариев

### 7.3 Primary vs Secondary Actions

#### Primary Actions (Основные)
- Используются для оптимизации ставок (Smart Bidding)
- Отображаются в столбце "Conversions"
- Должны отражать ключевые бизнес-цели

#### Secondary Actions (Вторичные)
- Только для наблюдения и отчётности
- Отображаются в столбце "All Conversions"
- Не влияют на оптимизацию ставок

#### Бизнес-правило
Рекомендуется иметь только ОДНО primary действие типа Purchase для избежания двойного подсчёта.

## 8. Интеграция с Google Analytics 4

### 8.1 Связывание аккаунтов

#### Преимущества
- Обогащение отчётов по пути конверсии
- Импорт ключевых событий GA4 в Google Ads
- Единый источник правды для данных
- Статистически значимое улучшение: +23% конверсий, -10% CPA

#### Требования
- Роль Marketer в Google Analytics
- Роль Admin в Google Ads
- Включённая автоматическая пометка (auto-tagging)

### 8.2 Импорт конверсий из GA4

#### Процесс
1. Создать ключевое событие (Key Event) в GA4
2. В Google Ads: Goals → Conversions → Import
3. Выбрать Google Analytics 4 properties
4. Выбрать нужные события для импорта

#### Ограничения импортированных конверсий
- Недоступны Enhanced Conversions
- Недоступны View-through conversions
- Недоступны Cross-device conversions
- Задержка данных: до 24 часов

#### Attribution Settings
- Можно выбрать каналы для атрибуции: только Google Paid или Paid + Organic
- Настройка в GA4: Advertising → Conversion Attribution Settings

### 8.3 Дедупликация

При наличии конверсий и из Google Ads, и из GA4:
- GA4-конверсии автоматически помечаются как Secondary
- Предотвращает двойной подсчёт
- Рекомендуется использовать один источник для оптимизации

## 9. Ценность конверсии (Conversion Value)

### 9.1 Статическая ценность

- Фиксированное значение для каждого типа конверсии
- Пример: каждая отправка формы = 100 USD
- Подходит для лидогенерации с известной средней ценностью лида

### 9.2 Динамическая ценность

- Передаётся с каждой конверсией индивидуально
- Пример: сумма заказа = ценность конверсии
- Требует передачи параметра value в событии конверсии

### 9.3 Conversion Value Rules

#### Описание
Правила корректировки ценности конверсий в реальном времени на основе условий.

#### Условия корректировки
- **Географическое положение** — разная ценность для разных регионов
- **Устройство** — мобильные vs десктопные конверсии
- **Аудитория** — сегменты пользователей

#### Применение
- Оптимизация Target ROAS и Maximize Conversion Value
- Работает в Search, Shopping, Display, Performance Max

## 10. User Stories

### 10.1 E-commerce менеджер

**US-001**: Как e-commerce менеджер, я хочу отслеживать все покупки на сайте, чтобы понимать ROI рекламных кампаний.

**US-002**: Как e-commerce менеджер, я хочу видеть ценность каждого заказа в отчётах, чтобы оптимизировать кампании на ROAS.

**US-003**: Как e-commerce менеджер, я хочу использовать Enhanced Conversions, чтобы не терять данные о конверсиях из-за блокировки cookies.

### 10.2 B2B маркетолог

**US-004**: Как B2B маркетолог, я хочу импортировать офлайн-конверсии из CRM, чтобы Google Ads оптимизировался на реальные сделки.

**US-005**: Как B2B маркетолог, я хочу установить окно конверсии 90 дней, потому что цикл продаж в моём бизнесе длинный.

## 11. Бизнес-правила

### 11.1 Общие правила

| ID | Правило |
|----|---------|
| BR-001 | Конверсия атрибутируется к дате клика/взаимодействия, а не к дате совершения конверсии |
| BR-002 | Одна конверсия может быть атрибутирована только одному взаимодействию с рекламой |
| BR-003 | При наличии кросс-девайс пути конверсия атрибутируется к устройству первого взаимодействия |
| BR-004 | View-through конверсии не учитываются, если был клик по любой другой рекламе |
| BR-005 | Transaction_id используется для дедупликации — повторные события с тем же ID игнорируются |

### 11.2 Правила атрибуции

| ID | Правило |
|----|---------|
| BR-006 | Data-Driven Attribution — модель по умолчанию для всех новых конверсий |
| BR-007 | При недостатке данных DDA автоматически откатывается к упрощённой модели |
| BR-008 | Только Primary конверсии используются для оптимизации ставок |
| BR-009 | Конверсии вне окна конверсии не атрибутируются к рекламе |

### 11.3 Правила Enhanced Conversions

| ID | Правило |
|----|---------|
| BR-010 | Данные пользователей должны быть хэшированы (SHA-256) перед отправкой |
| BR-011 | Минимум один идентификатор (email ИЛИ телефон) обязателен |
| BR-012 | Для использования адреса обязательны: имя, фамилия, страна, почтовый индекс |
| BR-013 | Телефон должен быть в формате E.164 |
| BR-014 | Email должен быть приведён к нижнему регистру без пробелов |

### 11.4 Правила импорта офлайн-конверсий

| ID | Правило |
|----|---------|
| BR-015 | Максимальный срок импорта с GCLID: 90 дней |
| BR-016 | Максимальный срок импорта с user-provided data: 63 дня |
| BR-017 | Для оптимальной работы Smart Bidding импорт должен происходить ежедневно |
| BR-018 | Рекомендуется включать GCLID даже при использовании Enhanced Conversions for Leads |

### 11.5 Правила для приложений

| ID | Правило |
|----|---------|
| BR-019 | Событие должно быть отмечено как конверсия в Firebase для импорта в Google Ads |
| BR-020 | First Open атрибутируется к последнему взаимодействию с рекламой перед установкой |
| BR-021 | In-app события атрибутируются через GCLID или device ID |

## 12. Глоссарий

| Термин | Определение |
|--------|-------------|
| **Conversion** | Действие пользователя, имеющее ценность для бизнеса |
| **GCLID** | Google Click Identifier — уникальный ID клика по рекламе |
| **Attribution** | Процесс определения вклада рекламных взаимодействий в конверсию |
| **Conversion Window** | Период времени, в течение которого конверсия атрибутируется к взаимодействию |
| **Enhanced Conversions** | Технология улучшения точности отслеживания через first-party данные |
| **Primary Conversion** | Конверсия, используемая для оптимизации ставок |
| **Secondary Conversion** | Конверсия только для наблюдения и отчётности |
| **Data-Driven Attribution** | Модель атрибуции на основе машинного обучения |
| **View-through Conversion** | Конверсия после просмотра рекламы без клика |
| **Engaged-view Conversion** | Конверсия после просмотра видео минимум 10 секунд |
| **Cross-device Conversion** | Конверсия, начатая на одном устройстве и завершённая на другом |
| **Conversion Value** | Денежная ценность конверсии |
| **Smart Bidding** | Автоматическая стратегия ставок на основе машинного обучения |
| **Google Tag** | JavaScript-код для отслеживания событий на сайте |
| **Firebase SDK** | Инструментарий для отслеживания событий в мобильных приложениях |

## 13. Связанные модули

- **Кампании** — конверсии используются как цели оптимизации
- **Ставки (Smart Bidding)** — автоматическая оптимизация на основе данных о конверсиях
- **Аудитории** — сегментация на основе конверсионных действий
- **Отчёты** — анализ эффективности на основе конверсий
- **Google Analytics 4** — источник импорта конверсий
- **Firebase** — источник данных о конверсиях в приложениях
- **CRM системы** — источник офлайн-конверсий
