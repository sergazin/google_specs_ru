# Уведомления и алерты Google Ads

## 1. Обзор модуля

Модуль уведомлений и алертов Google Ads обеспечивает своевременное информирование пользователей о критических событиях, изменениях статуса и возможностях оптимизации рекламных кампаний. Система поддерживает многоканальную доставку уведомлений и позволяет настраивать автоматические правила для проактивного управления аккаунтом.

### 1.1 Ключевые особенности

- Многоканальная доставка (email, in-app, push в мобильном приложении)
- Настраиваемые предпочтения уведомлений по категориям
- Автоматические правила (Automated Rules) для проактивных действий
- Кастомные уведомления о производительности
- Иерархическая система алертов для Manager Account (MCC)
- Приоритизация критичности уведомлений (красный/жёлтый/синий)

## 2. Категории уведомлений

### 2.1 Обязательные критические уведомления

| Категория | Описание | Критичность |
|-----------|----------|-------------|
| **Отклонённые объявления** | Объявления нарушают политики Google | Критическая |
| **Проблемы с оплатой** | Платёж отклонён, карта истекает | Критическая |
| **Остановка показа рекламы** | Все объявления остановлены | Критическая |
| **Нарушения политик** | Предупреждения о нарушении рекламных политик | Критическая |
| **Блокировка аккаунта** | Аккаунт заблокирован или ограничен | Критическая |

### 2.2 Уведомления по обслуживанию кампаний

| Категория | Описание | Настройки |
|-----------|----------|-----------|
| **Campaign Maintenance** | Проблемы с доставкой объявлений | Все / Только критические / Нет |
| **Кампания завершается** | Приближается дата окончания кампании | Автоматически |
| **Ограничение бюджетом** | Кампания ограничена бюджетом | Автоматически |
| **Низкая эффективность ключевых слов** | Ключевые слова не генерируют показы | Настраивается |

### 2.3 Биллинговые уведомления

| Категория | Описание | Триггер |
|-----------|----------|---------|
| **Платёж отклонён** | Банк/карта отклонили платёж | Немедленно |
| **Карта истекает** | Срок действия карты скоро истечёт | За 30 дней |
| **Бюджет аккаунта заканчивается** | Остаток бюджета ниже порога | Настраиваемый |
| **Бюджет аккаунта исчерпан** | Бюджет полностью израсходован | Немедленно |
| **Нет платёжной информации** | Не добавлен способ оплаты | При создании |
| **Предоплата не получена** | Банковский перевод не поступил | Ежедневно |

### 2.4 Рекомендации и оптимизация

| Категория | Описание | Настройки |
|-----------|----------|-----------|
| **Optimization Score** | Рекомендации по улучшению показателя оптимизации | Все / Нет |
| **Персонализированные советы** | Индивидуальные рекомендации по улучшению | Все / Нет |
| **Новые функции** | Информация о новых возможностях платформы | Все / Нет |
| **Newsletters** | Информационные рассылки Google Ads | Все / Нет |
| **Специальные предложения** | Промокоды и акции | Все / Нет |

### 2.5 Визуальная индикация приоритета

| Цвет | Приоритет | Примеры |
|------|-----------|---------|
| **Красный** | Критический | Объявления не показываются, платёж отклонён |
| **Жёлтый/Оранжевый** | Важный | Ограничение бюджетом, проблемы доставки |
| **Синий** | Информационный | Рекомендации, советы по оптимизации |

## 4. Автоматические правила (Automated Rules)

### 4.1 Обзор автоматических правил

Автоматические правила позволяют настроить автоматическое выполнение действий или отправку уведомлений при выполнении заданных условий. Это мощный инструмент для проактивного управления кампаниями.

### 4.2 Типы действий в правилах

#### Действия с кампаниями

| Действие | Описание |
|----------|----------|
| **Приостановить кампанию** | Остановка показа всех объявлений кампании |
| **Запустить кампанию** | Возобновление показа приостановленной кампании |
| **Увеличить бюджет** | Увеличение дневного бюджета на % или сумму |
| **Уменьшить бюджет** | Уменьшение дневного бюджета на % или сумму |

#### Действия с группами объявлений

| Действие | Описание |
|----------|----------|
| **Приостановить группу** | Остановка показа объявлений группы |
| **Запустить группу** | Возобновление показа группы |
| **Увеличить ставку** | Повышение ставки для группы |
| **Уменьшить ставку** | Понижение ставки для группы |

#### Действия с ключевыми словами

| Действие | Описание |
|----------|----------|
| **Приостановить ключевое слово** | Остановка показа по ключевому слову |
| **Запустить ключевое слово** | Возобновление показа по ключевому слову |
| **Увеличить ставку** | Повышение max CPC для ключевого слова |
| **Уменьшить ставку** | Понижение max CPC для ключевого слова |

#### Действия с объявлениями

| Действие | Описание |
|----------|----------|
| **Приостановить объявление** | Остановка показа конкретного объявления |
| **Запустить объявление** | Возобновление показа объявления |

#### Только уведомление

| Действие | Описание |
|----------|----------|
| **Отправить email** | Уведомление без выполнения действия в аккаунте |

| **Email only when there are errors** | Уведомление только при ошибках |
| **Don't send email** | Без email-уведомлений |

## 5. User Stories

### 5.1 Настройка уведомлений

#### US-NOTIF-001: Настройка email-предпочтений
```
КАК владелец рекламного аккаунта
Я ХОЧУ настроить категории email-уведомлений
ЧТОБЫ получать только релевантную информацию и не пропускать критические алерты
```

**Предусловия:**
- Пользователь авторизован в Google Ads
- Пользователь имеет права Admin или Standard

**Основной сценарий:**
1. Пользователь переходит в Admin > Notifications
2. Система отображает список категорий уведомлений
3. Пользователь выбирает предпочтения для каждой категории
4. Пользователь сохраняет настройки
5. Система применяет новые предпочтения

**Бизнес-правила:**
- Минимум один пользователь аккаунта должен получать критические уведомления
- Если пользователь единственный — он не может отключить критические уведомления

---

#### US-NOTIF-002: Настройка кастомных push-уведомлений
```
КАК мобильный рекламодатель
Я ХОЧУ настроить уведомления об изменении производительности
ЧТОБЫ оперативно реагировать на значительные изменения метрик
```

**Предусловия:**
- Установлено мобильное приложение Google Ads
- Push-уведомления разрешены в настройках устройства

**Основной сценарий:**
1. Пользователь открывает приложение Google Ads
2. Переходит в More > Settings > Custom notifications
3. Нажимает Create / "+"
4. Выбирает уровень (Account / Campaign / Ad group)
5. Выбирает тип уведомления (Performance Change / Status)
6. Для Performance Change:
   - Выбирает метрику
   - Устанавливает порог изменения (%)
   - Выбирает период (Daily / Weekly / Monthly)
7. Сохраняет настройку

**Примеры настроек:**
- "Уведомить, если CTR упадёт более чем на 20% за неделю"
- "Уведомить, если CPA вырастет более чем на 30% за день"
- "Уведомить, если статус кампании изменится на 'Limited by budget'"

### 5.2 Работа с биллинговыми уведомлениями

#### US-NOTIF-003: Реакция на отклонённый платёж
```
КАК рекламодатель
Я ХОЧУ получить уведомление об отклонённом платеже
ЧТОБЫ оперативно решить проблему и возобновить показ рекламы
```

**Триггер:**
- Платёжная система отклонила транзакцию

**Сценарий:**
1. Система обнаруживает отклонённый платёж
2. Отправляет критическое уведомление (email + in-app красная полоса)
3. Пользователь видит уведомление с причиной отклонения
4. Пользователь нажимает "Fix it"
5. Система направляет в раздел Billing > Payment methods
6. Пользователь исправляет платёжную информацию
7. Пользователь нажимает "Retry"
8. При успехе — реклама возобновляется в течение 24 часов

**Типичные причины отклонения:**
- Недостаточно средств на счёте
- Превышен кредитный лимит
- Карта истекла
- Неверные данные карты (номер/CVV)
- Банк блокирует интернет/международные транзакции

---

#### US-NOTIF-004: Предупреждение об истечении карты
```
КАК рекламодатель с автоплатежами
Я ХОЧУ заранее узнать об истечении срока карты
ЧТОБЫ обновить данные до прерывания рекламы
```

**Сценарий:**
1. Система проверяет срок действия карты
2. За 30 дней до истечения отправляет предупреждение
3. Пользователь получает email и in-app уведомление
4. Пользователь обновляет платёжные данные
5. Система подтверждает новую карту

---

### 5.3 Работа с уведомлениями о политиках

#### US-NOTIF-005: Уведомление об отклонённом объявлении
```
КАК рекламодатель
Я ХОЧУ узнать причину отклонения объявления
ЧТОБЫ исправить нарушение и запустить рекламу
```

**Сценарий:**
1. Модерация отклоняет объявление
2. Система отправляет уведомление с указанием политики
3. Пользователь просматривает детали нарушения
4. Варианты действий:
   - Исправить объявление и отправить на повторную проверку
   - Подать апелляцию, если считает решение ошибочным
5. При успешной проверке — объявление активируется

**Важные ограничения:**
- Максимум 2 апелляции на одно решение
- Превышение лимита апелляций может привести к блокировке аккаунта

---

#### US-NOTIF-006: Предупреждение о нарушении trademark
```
КАК рекламодатель
Я ХОЧУ знать о жалобах на использование торговых марок
ЧТОБЫ избежать блокировки аккаунта
```

**Сценарий:**
1. Владелец товарного знака подаёт жалобу в Google
2. Google рассматривает жалобу
3. При подтверждении — рекламодатель получает предупреждение
4. Даётся 7 дней на исправление до приостановки аккаунта
5. Рекламодатель может:
   - Удалить товарный знак из объявлений
   - Подать встречную апелляцию (если имеет права на использование)

### 5.4 Автоматические правила

#### US-NOTIF-007: Создание правила контроля бюджета
```
КАК рекламодатель с фиксированным месячным бюджетом
Я ХОЧУ автоматически получать уведомление при расходовании 80% бюджета
ЧТОБЫ принять решение о корректировке до исчерпания бюджета
```

**Настройка правила:**
1. Пользователь переходит в Tools & Settings > Bulk Actions > Rules
2. Создаёт новое правило для кампании
3. Действие: "Send email only"
4. Условие: Cost > $800 (при бюджете $1000)
5. Период данных: Same month
6. Частота: Daily
7. Email: уведомлять при срабатывании

---

#### US-NOTIF-008: Автоматическая остановка при высоком CPA
```
КАК performance-маркетолог
Я ХОЧУ автоматически останавливать ключевые слова с высокой ценой конверсии
ЧТОБЫ не тратить бюджет на неэффективные ключевые слова
```

**Настройка правила:**
1. Создание правила для ключевых слов
2. Действие: "Pause keywords"
3. Условия:
   - Conversions >= 5 (достаточно данных)
   - Cost per conversion > $50 (порог CPA)
4. Период данных: Previous 14 days
5. Частота: Weekly
6. Email: уведомлять при изменениях

---

#### US-NOTIF-009: Увеличение ставок для эффективных ключевых слов
```
КАК рекламодатель
Я ХОЧУ автоматически повышать ставки для ключевых слов с хорошей конверсией
ЧТОБЫ получать больше конверсий по эффективным запросам
```

**Настройка правила:**
1. Создание правила для ключевых слов
2. Действие: "Raise bid by 15%"
3. Ограничение: Max CPC не выше $10
4. Условия:
   - Conversions > 50
   - Cost per conversion < $10
   - Avg. position > 3
5. Период данных: Previous 7 days
6. Частота: Weekly

---

#### US-NOTIF-010: Повышение бюджета по дням недели
```
КАК рекламодатель с сезонным трафиком
```

**Настройка правил (2 связанных правила):**

**Правило 1: Увеличение бюджета**

**Правило 2: Возврат бюджета**

### 5.5 Уведомления для Manager Account (MCC)

#### US-NOTIF-012: Управление уведомлениями для клиентских аккаунтов
```
КАК менеджер агентства
Я ХОЧУ получать критические уведомления по всем клиентским аккаунтам
ЧТОБЫ оперативно реагировать на проблемы клиентов
```

**Сценарий:**
1. Администратор MCC настраивает предпочтения уведомлений
2. Для каждого типа уведомлений выбирает:
   - Получать все
   - Только критические
   - Не получать (только если клиент получает сам)
3. Система автоматически перенаправляет критические уведомления в MCC, если у клиента никто не получает

**Типы уведомлений MCC:**
- Payment alerts (отклонённые платежи, истекающие карты)
- Keyword and Creative alerts (отклонённые объявления, неэффективные ключевые слова)
- Campaign alerts (завершающиеся кампании)
- Budget alerts (заканчивающиеся бюджеты)
- Account alerts (проблемы с аккаунтами)

## 6. Бизнес-правила

### 6.1 Общие правила уведомлений

**BR-NOTIF-001**: Критические уведомления (биллинг, блокировка, все объявления отклонены) не могут быть полностью отключены — минимум один пользователь аккаунта должен их получать.

**BR-NOTIF-002**: Если единственный пользователь аккаунта пытается отключить критические уведомления — система не позволяет это сделать.

**BR-NOTIF-003**: Если клиентский аккаунт связан с MCC и у клиента никто не получает критические уведомления — MCC автоматически получает их от имени клиента.

**BR-NOTIF-004**: Время обновления ежедневных алертов — 2:00 по местному времени рекламодателя. Это касается: алертов о завершении кампаний, бюджетных алертов, платёжных алертов.

**BR-NOTIF-005**: Email-адрес для уведомлений должен иметь доступ к аккаунту Google Ads.

### 6.2 Правила автоматических правил

**BR-RULE-001**: Время выполнения автоматического правила — в пределах 2 часов после запланированного времени. Например, правило на 9:00 может выполниться с 9:00 до 11:00.

**BR-RULE-002**: Частота выполнения и период данных должны быть согласованы. Правило с hourly частотой и данными за "previous day" выполнится 0 или 24 раза за день, но не 1 раз.

**BR-RULE-003**: Рекомендуется устанавливать лимиты (min/max) для правил, изменяющих ставки и бюджеты, чтобы избежать экстремальных значений.

**BR-RULE-004**: Для правил на основе конверсий рекомендуется использовать периоды данных от 14 дней и более, так как конверсии могут атрибутироваться с задержкой до 30 дней.

**BR-RULE-005**: Изменения ставок рекомендуется делать небольшими шагами (10-15%), а не резкими скачками (30%+).

**BR-RULE-006**: Несколько правил могут применяться к одному объекту. Если правила конфликтуют — применяется последнее выполненное.

### 6.3 Правила политик и апелляций

**BR-POLICY-001**: Максимальное количество апелляций по одному решению — 2. Превышение может привести к блокировке аккаунта.

**BR-POLICY-002**: Перед апелляцией рекомендуется исправить нарушение — апелляция без изменений с высокой вероятностью будет отклонена.

**BR-POLICY-003**: Предупреждение о нарушении trademark даётся за 7 дней до приостановки аккаунта.

**BR-POLICY-004**: Нарушения политик не ведут к немедленной блокировке — сначала выдаётся предупреждение (кроме серьёзных нарушений: мошенничество, опасный контент).

### 6.4 Правила биллинговых уведомлений

**BR-BILLING-001**: При отклонении платежа некоторые аккаунты могут продолжать показ рекламы короткое время для устранения проблемы.

**BR-BILLING-002**: После исправления платёжных данных реклама возобновляется в течение 24 часов.

**BR-BILLING-003**: Уведомление об истечении карты отправляется за 30 дней до даты истечения.

**BR-BILLING-004**: Биллинговые уведомления настраиваются через раздел Billing > Settings > Payment contacts.

## 7. Рекомендации (Optimization Score)

### 7.1 Механизм рекомендаций

| Характеристика | Описание |
|----------------|----------|
| **Optimization Score** | Оценка от 0% до 100% потенциала аккаунта |
| **Влияние рекомендаций** | Каждая рекомендация показывает % улучшения score |
| **Персонализация** | Рекомендации основаны на истории аккаунта и трендах |
| **Уровни** | Доступны на уровне кампании, аккаунта и MCC |

### 7.2 Действия с рекомендациями

| Действие | Результат | Влияние на score |
|----------|-----------|------------------|
| **Apply (Применить)** | Рекомендация внедряется | Score увеличивается |
| **Dismiss (Отклонить)** | Рекомендация скрывается | Score увеличивается (такой же эффект) |
| **Auto-apply (Автоприменение)** | Рекомендации применяются автоматически | Score поддерживается |

### 7.3 Важные особенности

**BR-RECOM-001**: Optimization Score — это НЕ показатель эффективности аккаунта, а показатель того, рассмотрены ли рекомендации.

**BR-RECOM-002**: Отклонение рекомендации даёт такой же прирост score, как и её применение.

**BR-RECOM-003**: Отклонённые рекомендации не появляются повторно в течение определённого периода (зависит от типа рекомендации).

**BR-RECOM-004**: Optimization Score доступен только для активных кампаний: Search, Display, Video Action, App, Performance Max, Demand Gen, Shopping.

## 9. Лучшие практики

### 9.1 Настройка уведомлений

1. **Не отключайте критические уведомления** — даже если они кажутся избыточными, они предупреждают о реальных проблемах
2. **Настройте резервный email** — добавьте второго администратора для получения критических алертов
3. **Используйте in-app уведомления** — они показывают приоритет проблемы цветом
4. **Настройте push в приложении** — для оперативного реагирования на изменения

### 9.2 Автоматические правила

1. **Начинайте с уведомлений** — используйте "Send email only" перед автоматическими действиями
2. **Тестируйте на малых объёмах** — применяйте правила сначала к отдельным кампаниям
3. **Устанавливайте лимиты** — всегда задавайте min/max для ставок и бюджетов
4. **Согласовывайте частоту и данные** — hourly правило с данными за вчера выполнится 24 раза
5. **Используйте длинные периоды для конверсий** — минимум 14 дней из-за задержки атрибуции
6. **Мониторьте историю правил** — проверяйте журнал выполнения в Rules > View history

### 9.3 Работа с отклонениями

1. **Читайте политику перед апелляцией** — понимание нарушения повышает шансы на успех
2. **Исправляйте перед апелляцией** — апелляция без изменений обычно отклоняется
3. **Не превышайте лимит апелляций** — максимум 2 апелляции на решение
4. **Сохраняйте доказательства** — при trademark-спорах подготовьте документы о праве использования
