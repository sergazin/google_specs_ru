# Совместная работа (Collaboration)

## Описание

Модуль совместной работы в Google Sheets обеспечивает полноценное взаимодействие множества пользователей с одной таблицей в режиме реального времени. Система позволяет видеть курсоры и изменения других пользователей мгновенно, управлять уровнями доступа, обмениваться комментариями и назначать задачи прямо в документе.

Система состоит из девяти ключевых компонентов:
1. **Редактирование в реальном времени** - одновременная работа до 100 редакторов с мгновенной синхронизацией
2. **Отображение курсоров** - визуализация позиций и действий других пользователей
3. **Управление доступом** - гибкая система разрешений (Viewer, Commenter, Editor)
4. **Общий доступ по ссылке** - быстрое предоставление доступа через URL
5. **Комментарии к ячейкам** - обсуждение конкретных данных в таблице
6. **Упоминания и назначение задач** - уведомление коллег и делегирование ответственности
7. **Встроенный чат** - оперативное общение в реальном времени
8. **Уведомления об изменениях** - отслеживание активности в документе
9. **Защита листов и диапазонов** - ограничение редактирования критичных данных

## Роли пользователей

### Базовые роли доступа:
- **Владелец (Owner)** - создатель документа с полным контролем, может передать владение, удалить файл, управлять всеми настройками доступа
- **Редактор (Editor)** - может редактировать содержимое, добавлять/удалять листы, управлять доступом (если разрешено владельцем), защищать диапазоны
- **Комментатор (Commenter)** - может просматривать документ, оставлять комментарии и участвовать в обсуждениях, но не редактировать данные
- **Читатель (Viewer)** - может только просматривать документ без возможности редактирования или комментирования

### Специальные права:
- **Пользователь с правами на защищенный диапазон** - редактор, которому явно разрешено изменять защищенный диапазон или лист
- **Администратор Google Workspace** - управление организационными политиками доступа и аудит активности

## Функциональные требования

### FR-COL-001: Совместное редактирование в реальном времени (Real-time Collaborative Editing)
**Описание:** Несколько пользователей могут одновременно редактировать одну таблицу, видя изменения друг друга в режиме реального времени без необходимости обновления страницы или синхронизации файлов.

**Роли:** Владелец, Редактор

**Предусловия:**
- Пользователи авторизованы в Google Sheets
- Пользователи имеют права редактора на документ
- Документ открыт в браузере или мобильном приложении

**Основной сценарий:**
1. Первый пользователь открывает таблицу Google Sheets
2. Второй пользователь открывает ту же таблицу по ссылке или из Google Drive
3. Иконка второго пользователя появляется в правом верхнем углу рядом с кнопкой "Share"
4. Оба пользователя видят цветные индикаторы ячеек, в которых находятся курсоры других
5. Когда один пользователь вводит данные в ячейку, другой видит изменения мгновенно
6. При изменении форматирования (шрифт, цвет, границы) изменения применяются для всех
7. Все изменения автоматически сохраняются в облако

**Альтернативные сценарии:**
- Сценарий A (Конфликт редактирования): два пользователя одновременно редактируют одну ячейку - система сохраняет последнее введенное значение
- Сценарий B (Потеря соединения): при потере интернета пользователь может продолжить работу офлайн, изменения синхронизируются при восстановлении связи
- Сценарий C (Массовое редактирование): несколько пользователей работают в разных частях таблицы - каждый видит все изменения без задержки
- Сценарий D (Отмена изменений): пользователь нажимает Ctrl+Z - отменяются только его собственные изменения

**Бизнес-правила:**
- BR-COL-001: Google Sheets поддерживает одновременную работу до 100 редакторов в одном документе
- BR-COL-002: Изменения передаются всем участникам в течение миллисекунд через WebSocket-соединение
- BR-COL-003: Каждый пользователь имеет собственную историю отмены (Undo), не влияющую на других
- BR-COL-004: Документ сохраняется автоматически после каждого изменения
- BR-COL-005: При одновременном редактировании одной ячейки приоритет имеет последний ввод
- BR-COL-006: История версий сохраняет все изменения с указанием автора и времени

**Результат:** Все участники работают с актуальной версией документа, видя изменения друг друга в реальном времени

### FR-COL-002: Отображение курсоров других пользователей (Display Other Users' Cursors)
**Описание:** Система отображает позиции курсоров всех активных пользователей в таблице, позволяя видеть, кто в какой ячейке работает в данный момент.

**Роли:** Владелец, Редактор, Комментатор, Читатель

**Предусловия:**
- В документе одновременно находятся несколько пользователей
- Все пользователи имеют права на просмотр документа
- Документ открыт в веб-версии Google Sheets

**Основной сценарий:**
1. Пользователь открывает таблицу, в которой уже работают другие участники
2. В правом верхнем углу отображаются аватары всех активных пользователей
3. При наведении на аватар отображается имя пользователя и его email
4. Ячейка, в которой находится курсор другого пользователя, подсвечивается цветной рамкой
5. Цвет рамки соответствует уникальному цвету, назначенному каждому пользователю
6. Рядом с рамкой ячейки отображается имя пользователя в цветной метке
7. При перемещении курсора другого пользователя подсветка плавно переходит к новой ячейке

**Альтернативные сценарии:**
- Сценарий A (Выделение диапазона): другой пользователь выделяет несколько ячеек - весь выделенный диапазон подсвечивается его цветом
- Сценарий B (Редактирование ячейки): когда другой пользователь вводит текст в ячейку, виден процесс набора в реальном времени
- Сценарий C (Переход на другой лист): при переходе пользователя на другой лист его курсор исчезает с текущего листа
- Сценарий D (Много пользователей): при большом количестве участников аватары группируются с индикатором "+N"

**Бизнес-правила:**
- BR-COL-007: Каждому пользователю автоматически назначается уникальный цвет из палитры
- BR-COL-008: Цвет пользователя сохраняется в течение всей сессии редактирования
- BR-COL-009: Подсветка курсоров отображается для всех типов пользователей, включая читателей
- BR-COL-010: Позиция курсора обновляется в реальном времени с минимальной задержкой
- BR-COL-011: При клике на аватар пользователя экран прокручивается к его текущей позиции
- BR-COL-012: Неактивные пользователи (более 5 минут без действий) отображаются затемненным аватаром

**Результат:** Пользователь видит позиции и действия всех активных участников в документе

### FR-COL-003: Управление уровнями доступа (Manage Access Levels)
**Описание:** Владелец или редактор с соответствующими правами может назначать и изменять уровни доступа для пользователей: Viewer (только просмотр), Commenter (комментирование), Editor (редактирование).

**Роли:** Владелец, Редактор (если разрешено владельцем)

**Предусловия:**
- Пользователь авторизован и имеет права на управление доступом
- Документ создан и доступен для настройки

**Основной сценарий:**
1. Пользователь нажимает кнопку "Share" (Поделиться) в правом верхнем углу
2. Открывается диалоговое окно управления доступом
3. В разделе "People with access" отображается список пользователей с текущими правами
4. Пользователь нажимает на выпадающий список рядом с именем участника
5. Выбирает новый уровень доступа: Viewer, Commenter или Editor
6. Изменения применяются мгновенно
7. Участник получает уведомление об изменении своих прав (опционально)

**Альтернативные сценарии:**
- Сценарий A (Удаление доступа): выбирает "Remove" в выпадающем меню - пользователь теряет доступ к документу
- Сценарий B (Передача владения): владелец выбирает "Make owner" для назначения нового владельца
- Сценарий C (Запрет редакторам управлять доступом): в настройках снимает галочку "Editors can change permissions and share"
- Сценарий D (Блокировка скачивания): включает опцию "Prevent viewers and commenters from downloading, printing, and copying"

**Бизнес-правила:**
- BR-COL-013: Viewer может только просматривать документ без возможности изменений
- BR-COL-014: Commenter может просматривать и оставлять комментарии, но не редактировать данные
- BR-COL-015: Editor может редактировать содержимое, добавлять листы и управлять доступом (если разрешено)
- BR-COL-016: Только владелец может передать права владения другому пользователю
- BR-COL-017: При передаче владения предыдущий владелец становится редактором
- BR-COL-018: Изменение прав доступа применяется мгновенно и влияет на текущую сессию пользователя

**Результат:** Уровень доступа пользователя изменен согласно выбранному значению

### FR-COL-004: Предоставление доступа по ссылке (Share via Link)
**Описание:** Владелец или редактор может создать ссылку для общего доступа с определенным уровнем разрешений, позволяя получить доступ к документу без персонального приглашения.

**Роли:** Владелец, Редактор (если разрешено)

**Предусловия:**
- Пользователь имеет права на управление доступом
- Организационные политики разрешают создание общих ссылок

**Основной сценарий:**
1. Пользователь нажимает кнопку "Share" в правом верхнем углу
2. В разделе "General access" видит текущий статус (по умолчанию "Restricted")
3. Нажимает на выпадающий список и выбирает "Anyone with the link"
4. Выбирает уровень доступа для всех, кто получит ссылку: Viewer, Commenter или Editor
5. Нажимает кнопку "Copy link" для копирования ссылки в буфер обмена
6. Отправляет ссылку нужным людям через email, мессенджер или другие каналы
7. Получатели ссылки могут открыть документ без входа в Google-аккаунт (для Viewer)

**Альтернативные сценарии:**
- Сценарий A (Ограничение по организации): выбирает "Anyone in [Organization]" - доступ только для сотрудников компании
- Сценарий B (Возврат к ограниченному доступу): меняет "Anyone with the link" на "Restricted" - ссылка перестает работать для новых пользователей
- Сценарий C (Доступ без Google-аккаунта): при выборе Viewer доступ возможен без авторизации, для Commenter и Editor требуется Google-аккаунт
- Сценарий D (Установка срока действия): для Google Workspace можно установить дату истечения срока действия ссылки

**Бизнес-правила:**
- BR-COL-019: Опция "Anyone with the link" делает документ доступным всем, кто знает URL
- BR-COL-020: Для организаций Google Workspace доступна опция ограничения по домену
- BR-COL-021: Ссылка остается активной до изменения настроек владельцем
- BR-COL-022: Администраторы организации могут запретить создание публичных ссылок
- BR-COL-023: При выборе Editor любой с ссылкой может изменять данные - использовать с осторожностью
- BR-COL-024: Формат ссылки: https://docs.google.com/spreadsheets/d/{fileId}/edit

**Результат:** Создана ссылка для общего доступа с выбранным уровнем разрешений

### FR-COL-005: Приглашение пользователей по email (Invite Users by Email)
**Описание:** Владелец или редактор может пригласить конкретных пользователей по email-адресу, назначив персональный уровень доступа и отправив уведомление.

**Роли:** Владелец, Редактор (если разрешено)

**Предусловия:**
- Пользователь имеет права на управление доступом
- Известны email-адреса приглашаемых пользователей

**Основной сценарий:**
1. Пользователь нажимает кнопку "Share" в правом верхнем углу
2. В поле "Add people, groups, and calendar events" начинает вводить email-адрес
3. Система предлагает автодополнение из контактов Google
4. Выбирает пользователя из списка или вводит email полностью
5. В выпадающем списке справа выбирает уровень доступа: Viewer, Commenter или Editor
6. Опционально вводит сообщение в поле "Message"
7. Нажимает кнопку "Send" для отправки приглашения
8. Приглашенный получает email с ссылкой на документ

**Альтернативные сценарии:**
- Сценарий A (Множественное приглашение): вводит несколько email через запятую - все получают одинаковый уровень доступа
- Сценарий B (Приглашение группы Google): вводит email группы Google Groups - все участники группы получают доступ
- Сценарий C (Без уведомления): снимает галочку "Notify people" - пользователь получает доступ без email-уведомления
- Сценарий D (Внешний пользователь без Google-аккаунта): получатель получает приглашение создать аккаунт Google

**Бизнес-правила:**
- BR-COL-025: Email-уведомление содержит ссылку на документ, имя отправителя и сообщение
- BR-COL-026: Приглашенные видят документ в разделе "Shared with me" в Google Drive
- BR-COL-027: Можно пригласить до 200 пользователей за одну операцию
- BR-COL-028: Для организаций Google Workspace внешние приглашения могут быть ограничены политикой
- BR-COL-029: Каждому пользователю можно назначить индивидуальный уровень доступа
- BR-COL-030: При приглашении группы все текущие и будущие участники получают доступ

**Результат:** Пользователи получили персональные приглашения с доступом к документу

### FR-COL-006: Добавление комментария к ячейке (Add Comment to Cell)
**Описание:** Пользователь может добавить комментарий к конкретной ячейке для обсуждения данных, постановки вопросов или предоставления обратной связи без изменения содержимого ячейки.

**Роли:** Владелец, Редактор, Комментатор

**Предусловия:**
- Пользователь имеет права Commenter или выше
- Ячейка выбрана

**Основной сценарий:**
1. Пользователь выделяет ячейку, к которой хочет добавить комментарий
2. Нажимает правую кнопку мыши и выбирает "Comment" или использует Ctrl+Alt+M
3. Открывается поле ввода комментария справа от ячейки
4. Вводит текст комментария
5. Нажимает кнопку "Comment" для публикации
6. На ячейке появляется желтый треугольник в правом верхнем углу
7. Все пользователи с доступом видят индикатор комментария

**Альтернативные сценарии:**
- Сценарий A (Комментарий к диапазону): выделяет несколько ячеек и добавляет общий комментарий к диапазону
- Сценарий B (Просмотр комментария): наведение курсора на ячейку с индикатором показывает текст комментария
- Сценарий C (Ответ на комментарий): другой пользователь нажимает "Reply" и добавляет ответ в ветку обсуждения
- Сценарий D (Добавление с панели): открывает панель комментариев через меню View > Comments

**Бизнес-правила:**
- BR-COL-031: Комментарии привязаны к конкретной ячейке или диапазону и перемещаются вместе с ними
- BR-COL-032: Комментарии сохраняются в документе и доступны всем пользователям с правами на просмотр
- BR-COL-033: Каждый комментарий содержит имя автора, дату и время создания
- BR-COL-034: Ветка комментариев может содержать неограниченное количество ответов
- BR-COL-035: При удалении ячейки связанный комментарий также удаляется
- BR-COL-036: Комментарии отличаются от заметок (Notes) - заметки не поддерживают ответы и уведомления

**Результат:** Комментарий добавлен к ячейке и виден всем участникам

### FR-COL-007: Упоминание пользователя в комментарии (@Mention)
**Описание:** При создании комментария пользователь может упомянуть конкретного человека через @, чтобы привлечь его внимание и отправить персональное уведомление.

**Роли:** Владелец, Редактор, Комментатор

**Предусловия:**
- Пользователь имеет права на комментирование
- Упоминаемый пользователь имеет доступ к документу или добавляется автоматически

**Основной сценарий:**
1. Пользователь начинает создавать комментарий к ячейке
2. В тексте комментария вводит символ "@"
3. Появляется выпадающий список контактов и участников документа
4. Начинает вводить имя или email нужного человека
5. Выбирает пользователя из списка автодополнения
6. Завершает текст комментария и нажимает "Comment"
7. Упомянутый пользователь получает email-уведомление с ссылкой на комментарий

**Альтернативные сценарии:**
- Сценарий A (Множественные упоминания): упоминает нескольких пользователей в одном комментарии - каждый получает уведомление
- Сценарий B (Упоминание пользователя без доступа): при упоминании нового email предлагается предоставить доступ
- Сценарий C (Упоминание в ответе): упоминание в ответе на комментарий также отправляет уведомление
- Сценарий D (Упоминание в ячейке): можно упомянуть пользователя прямо в содержимом ячейки через @

**Бизнес-правила:**
- BR-COL-037: Символ "@" активирует функцию упоминания в любом месте комментария
- BR-COL-038: Email-уведомление содержит текст комментария, имя автора и прямую ссылку на ячейку
- BR-COL-039: Упомянутый пользователь выделяется синим цветом в тексте комментария
- BR-COL-040: При упоминании пользователя без доступа появляется предложение предоставить доступ
- BR-COL-041: Пользователь может отключить уведомления об упоминаниях в настройках
- BR-COL-042: Упоминание работает как с Google-аккаунтами, так и с внешними email

**Результат:** Упомянутый пользователь получил уведомление о комментарии

### FR-COL-008: Назначение задачи через комментарий (Assign Task via Comment)
**Описание:** Пользователь может назначить задачу конкретному человеку через комментарий, превращая обсуждение в отслеживаемое действие с ответственным исполнителем.

**Роли:** Владелец, Редактор, Комментатор

**Предусловия:**
- Пользователь имеет права на комментирование
- Создается комментарий с упоминанием пользователя

**Основной сценарий:**
1. Пользователь создает комментарий к ячейке
2. В тексте комментария упоминает пользователя через "@"
3. После выбора пользователя появляется чекбокс "Assign to [имя пользователя]"
4. Отмечает чекбокс для назначения задачи
5. Завершает текст комментария и нажимает "Assign"
6. Назначенный пользователь получает email с задачей
7. Комментарий отображается как назначенная задача с иконкой и именем исполнителя

**Альтернативные сценарии:**
- Сценарий A (Переназначение задачи): в ответе на комментарий упоминает другого пользователя и нажимает "Reassign"
- Сценарий B (Выполнение задачи): исполнитель нажимает "Mark as done" (галочка) - задача закрывается как выполненная
- Сценарий C (Отклонение задачи): исполнитель может ответить и отклонить задачу с объяснением
- Сценарий D (Просмотр всех задач): через меню Tools > Notification rules можно настроить отслеживание

**Бизнес-правила:**
- BR-COL-043: Назначенная задача отличается от обычного комментария визуально и функционально
- BR-COL-044: Только один пользователь может быть назначен исполнителем одной задачи
- BR-COL-045: Задачу может переназначить любой пользователь с правами комментирования
- BR-COL-046: При отметке "Done" задача переходит в статус выполненной и сворачивается
- BR-COL-047: Email о назначенной задаче содержит кнопки быстрых действий: Open, Mark as done
- BR-COL-048: Выполненные задачи сохраняются в истории комментариев

**Результат:** Задача назначена пользователю с уведомлением и возможностью отслеживания

### FR-COL-009: Разрешение комментария (Resolve Comment)
**Описание:** Автор комментария или другие участники могут пометить обсуждение как разрешенное, скрывая его из основного вида, но сохраняя в истории.

**Роли:** Владелец, Редактор, Комментатор, автор комментария

**Предусловия:**
- Существует открытый комментарий к ячейке
- Пользователь имеет права на комментирование

**Основной сценарий:**
1. Пользователь открывает ветку комментариев к ячейке
2. Просматривает обсуждение и убеждается, что вопрос решен
3. Нажимает кнопку "Resolve" (галочка) в правом верхнем углу комментария
4. Комментарий скрывается из основного вида
5. Желтый индикатор на ячейке исчезает
6. Автор комментария получает уведомление о разрешении (если включено)
7. Разрешенный комментарий доступен в истории через панель комментариев

**Альтернативные сценарии:**
- Сценарий A (Повторное открытие): в истории комментариев нажимает "Re-open" для возобновления обсуждения
- Сценарий B (Просмотр истории): через View > Comments > Open comment history просматривает все разрешенные комментарии
- Сценарий C (Удаление комментария): автор или владелец может полностью удалить комментарий через меню "..."
- Сценарий D (Массовое разрешение): можно разрешить несколько комментариев последовательно через панель

**Бизнес-правила:**
- BR-COL-049: Разрешение комментария не удаляет его, а перемещает в архив
- BR-COL-050: Любой пользователь с правами комментирования может разрешить любой комментарий
- BR-COL-051: Разрешенные комментарии сохраняются в истории документа бессрочно
- BR-COL-052: При повторном открытии комментарий возвращается на ячейку с желтым индикатором
- BR-COL-053: Разрешение назначенной задачи также помечает её как выполненную
- BR-COL-054: История комментариев показывает, кто и когда разрешил комментарий

**Результат:** Комментарий отмечен как разрешенный и перемещен в архив

### FR-COL-010: Встроенный чат (Built-in Chat)
**Описание:** Пользователи, одновременно работающие в документе, могут общаться через встроенный чат в реальном времени без необходимости использования внешних мессенджеров.

**Роли:** Владелец, Редактор (требуется наличие других активных пользователей)

**Предусловия:**
- В документе одновременно находятся минимум два пользователя
- Пользователи имеют права редактора
- Документ открыт в веб-версии Google Sheets

**Основной сценарий:**
1. Пользователь замечает, что в документе присутствуют другие участники (аватары в правом верхнем углу)
2. Нажимает на иконку чата (облачко) рядом с аватарами или в верхней панели
3. Открывается панель чата в правой части экрана
4. Вводит сообщение в текстовое поле внизу панели
5. Нажимает Enter или кнопку отправки
6. Сообщение мгновенно появляется у всех участников, находящихся в документе
7. Другие пользователи могут ответить в той же панели

**Альтернативные сценарии:**
- Сценарий A (Недоступность чата): если в документе только один пользователь, иконка чата неактивна или скрыта
- Сценарий B (Закрытие чата): пользователь закрывает панель - при получении нового сообщения появляется индикатор
- Сценарий C (Выход пользователя): когда участник покидает документ, он больше не видит сообщения чата
- Сценарий D (Форматирование): чат поддерживает только простой текст без форматирования

**Бизнес-правила:**
- BR-COL-055: Чат доступен только когда в документе находятся несколько активных пользователей
- BR-COL-056: История чата НЕ сохраняется после закрытия документа всеми участниками
- BR-COL-057: Уведомления о новых сообщениях в чате не отправляются по email
- BR-COL-058: Чат не привязан к конкретным ячейкам, в отличие от комментариев
- BR-COL-059: Сообщения в чате видят только пользователи, находящиеся в документе в данный момент
- BR-COL-060: Для важных обсуждений рекомендуется использовать комментарии вместо чата

**Результат:** Участники могут общаться в реальном времени внутри документа

### FR-COL-011: Настройка уведомлений об изменениях (Configure Edit Notifications)

**Роли:** Владелец, Редактор, Комментатор, Читатель (для документов, к которым имеется доступ)

**Предусловия:**
- Пользователь имеет доступ к документу
- Email-адрес пользователя подтвержден в Google

**Основной сценарий:**
1. Пользователь открывает документ Google Sheets
2. Переходит в меню Tools > Notification settings (Инструменты > Настройки уведомлений)
3. В разделе "Edit notifications" (Уведомления о редактировании) выбирает опцию
4. Доступные варианты: "Any changes are made" (Любые изменения) или "Off" (Выключено)
5. Выбирает частоту: "Email - daily digest" (Ежедневная сводка) или "Email - right away" (Сразу)
6. Нажимает "Save" (Сохранить)
7. Система отправляет уведомления согласно настройкам

**Альтернативные сценарии:**
- Сценарий A (Уведомления о комментариях): в разделе "Comment notifications" выбирает: All comments, Comments for you, или None
- Сценарий B (Уведомление при отправке формы): если к таблице привязана форма, можно включить уведомление о новых ответах
- Сценарий C (Отписка от уведомлений): получив уведомление по email, нажимает "Unsubscribe" в письме
- Сценарий D (Индивидуальные настройки): каждый пользователь настраивает уведомления независимо

**Бизнес-правила:**
- BR-COL-061: Настройки уведомлений индивидуальны для каждого пользователя и каждого документа
- BR-COL-062: Ежедневная сводка отправляется один раз в день со всеми изменениями
- BR-COL-063: Уведомление "right away" отправляется в течение нескольких минут после изменения
- BR-COL-064: Уведомления о комментариях "@mentions" включены по умолчанию
- BR-COL-065: Пользователь может управлять уведомлениями через Tools > Notification settings
- BR-COL-066: Для более детальных уведомлений (конкретные ячейки) требуется Google Apps Script

**Результат:** Пользователь получает уведомления об изменениях согласно настройкам

**Роли:** Владелец, Редактор

**Предусловия:**
- Пользователь имеет права редактора
- Таблица содержит минимум один лист

**Основной сценарий:**
1. Пользователь переходит в меню Data > Protect sheets and ranges (Данные > Защита листов и диапазонов)

3. Нажимает "Add a sheet or range" (Добавить лист или диапазон)
4. Выбирает вкладку "Sheet" (Лист)
5. В выпадающем списке выбирает лист для защиты
6. Опционально отмечает "Except certain cells" и указывает ячейки-исключения
7. Нажимает "Set permissions" (Установить разрешения)
8. Выбирает "Only you" или "Custom" для указания пользователей с правами редактирования

- Сценарий A (Предупреждение вместо блокировки): выбирает "Show a warning when editing this range" - пользователи видят предупреждение, но могут редактировать
- Сценарий B (Исключение ячеек): защищает лист, но оставляет определенные ячейки открытыми для редактирования
- Сценарий C (Изменение защиты): открывает существующую защиту и меняет список разрешенных пользователей
- Сценарий D (Удаление защиты): нажимает иконку корзины для удаления защиты

**Бизнес-правила:**
- BR-COL-067: Только пользователи с правами Editor могут устанавливать защиту
- BR-COL-068: Владелец документа всегда может редактировать защищенные области
- BR-COL-069: Viewers и Commenters не видят опцию защиты в меню
- BR-COL-070: Защита листа отображается значком замка на вкладке листа
- BR-COL-071: Защита не является абсолютной безопасностью - редакторы могут скопировать данные
- BR-COL-072: Можно защитить несколько листов с разными наборами разрешенных пользователей

**Результат:** Лист защищен и может редактироваться только указанными пользователями

**Альтернативные сценарии:**
- Сценарий A (Удаление срока): нажимает на дату и выбирает "Remove expiration" - доступ становится бессрочным
- Сценарий B (Продление срока): изменяет дату истечения на более позднюю
- Сценарий C (Автоматическое истечение): по достижении даты доступ отзывается автоматически в 00:00 UTC
- Sценарий D (Уведомления): за 7 дней и за 1 день до истечения отправляются напоминания

**Бизнес-правила:**
- BR-COL-091: Срок действия можно установить только для ролей Viewer и Commenter
- BR-COL-092: Для роли Editor установка срока недоступна
- BR-COL-093: Максимальный срок - 1 год от текущей даты
- BR-COL-094: При истечении срока пользователь видит документ в "Shared with me", но не может открыть
- BR-COL-095: Владелец может в любой момент продлить или отменить срок
- BR-COL-096: Функция доступна только для Google Workspace (не для личных аккаунтов)

**Результат:** Установлен срок действия доступа для пользователя

### FR-COL-017: Запрос доступа к документу (Request Access)
**Описание:** Пользователь без доступа может запросить разрешение на просмотр или редактирование документа, отправив запрос владельцу.

**Роли:** Любой пользователь Google (без текущего доступа)

**Предусловия:**
- Пользователь имеет ссылку на документ
- Документ имеет ограниченный доступ (Restricted)
- Владелец не отключил возможность запроса доступа

**Основной сценарий:**
1. Пользователь переходит по ссылке на документ Google Sheets
2. Видит страницу "You need access" (Вам нужен доступ)
3. Отображается название документа и информация о владельце
4. Нажимает кнопку "Request access" (Запросить доступ)
5. Опционально вводит сообщение с объяснением, зачем нужен доступ
6. Нажимает "Send" (Отправить)
7. Владелец получает email с запросом и кнопками быстрого одобрения/отклонения

**Альтернативные сценарии:**
- Сценарий A (Одобрение): владелец нажимает "Share" в email - пользователь получает доступ Viewer
- Сценарий B (Одобрение с повышением прав): владелец открывает настройки и назначает Editor или Commenter
- Сценарий C (Отклонение): владелец игнорирует запрос или нажимает "Decline"
- Сценарий D (Повторный запрос): система ограничивает частоту повторных запросов

**Бизнес-правила:**
- BR-COL-097: Запрос отправляется владельцу и всем редакторам с правами управления доступом
- BR-COL-098: Email содержит прямые ссылки для быстрого одобрения или отклонения
- BR-COL-099: Один пользователь может отправить только один запрос, повторные блокируются
- BR-COL-100: При одобрении пользователь получает email с ссылкой на документ
- BR-COL-101: Владелец может отключить возможность запроса доступа в настройках
- BR-COL-102: Запросы сохраняются в истории и видны в диалоге Share

**Результат:** Запрос на доступ отправлен владельцу документа

### FR-COL-018: Управление правами редакторов (Manage Editor Permissions)
**Описание:** Владелец может ограничить возможности редакторов по управлению доступом и предотвратить несанкционированное распространение документа.

**Роли:** Владелец

**Предусловия:**
- Пользователь является владельцем документа
- К документу предоставлен доступ редакторам

**Основной сценарий:**
1. Владелец нажимает кнопку "Share"
2. В диалоге нажимает на иконку шестеренки (Settings) в правом верхнем углу
3. Видит список опций безопасности
4. Снимает галочку "Editors can change permissions and share" - редакторы теряют возможность управления доступом
5. Ставит галочку "Viewers and commenters can see the option to download, print, and copy" для разрешения или снимает для запрета
6. Нажимает "Done" (Готово)
7. Изменения применяются мгновенно

**Альтернативные сценарии:**
- Сценарий A (Запрет скачивания): снимает галочку скачивания - Viewers и Commenters не могут экспортировать данные
- Сценарий B (Полный контроль): оставляет все галочки - редакторы имеют максимальные права
- Сценарий C (Минимальные права): снимает все галочки - редакторы могут только редактировать содержимое
- Сценарий D (Организационные политики): для Google Workspace администратор может установить политики по умолчанию

**Бизнес-правила:**
- BR-COL-103: Только владелец может изменять настройки прав редакторов
- BR-COL-104: Запрет на изменение доступа применяется ко всем редакторам документа
- BR-COL-105: Блокировка скачивания не влияет на возможность редакторов экспортировать данные
- BR-COL-106: Эти настройки не защищают от скриншотов и копирования вручную
- BR-COL-107: Настройки применяются ко всему документу, нельзя установить для отдельных листов
- BR-COL-108: При передаче владения новый владелец наследует и может изменить настройки

**Результат:** Права редакторов ограничены согласно настройкам владельца

## Нефункциональные требования

### Производительность
- **NFR-COL-001**: Изменения должны передаваться другим пользователям в течение 500 мс
- **NFR-COL-002**: Система должна поддерживать до 100 одновременных редакторов без деградации производительности
- **NFR-COL-003**: Открытие диалога Share должно происходить менее чем за 1 секунду
- **NFR-COL-004**: Email-уведомления о комментариях должны отправляться в течение 5 минут

### Надежность
- **NFR-COL-005**: Автосохранение должно происходить после каждого изменения без потери данных
- **NFR-COL-006**: При потере соединения система должна корректно синхронизировать изменения после восстановления
- **NFR-COL-007**: Конфликты редактирования одной ячейки должны разрешаться предсказуемо (последний ввод побеждает)
- **NFR-COL-008**: История версий должна сохраняться бессрочно для аккаунтов Workspace

### Безопасность
- **NFR-COL-009**: Все операции по управлению доступом должны логироваться для аудита
- **NFR-COL-010**: Защита диапазонов не должна обходиться через API или импорт данных
- **NFR-COL-011**: Ссылки для общего доступа должны быть криптографически стойкими
- **NFR-COL-012**: Данные должны передаваться по защищенному соединению (TLS 1.3+)

### Совместимость
- **NFR-COL-013**: Функции совместной работы должны работать во всех современных браузерах
- **NFR-COL-014**: Мобильные приложения должны поддерживать все основные функции совместной работы
- **NFR-COL-015**: Курсоры других пользователей должны отображаться в веб-версии и мобильных приложениях
