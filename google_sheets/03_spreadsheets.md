# Управление таблицами (Spreadsheets Management)

## Описание

Модуль управления таблицами является центральным компонентом Google Sheets, обеспечивающим полный жизненный цикл работы с электронными таблицами: от создания и организации до экспорта и удаления. Модуль тесно интегрирован с Google Drive для файлового хранения, организации в папках и управления доступом.

Google Sheets использует иерархическую структуру: одна таблица (Spreadsheet) может содержать множество листов (Sheets/Tabs), каждый из которых представляет отдельную сетку данных. Пользователь может создавать таблицы из шаблонов, импортировать файлы различных форматов и экспортировать данные для использования в других приложениях.

---

## Роли пользователей

### Роли уровня файла (определяются через Google Drive)

| Роль | Описание |
|------|----------|
| **Владелец (Owner)** | Создатель таблицы или пользователь, которому передано владение. Полный контроль над файлом: редактирование, шаринг, удаление, передача владения |
| **Редактор (Editor)** | Пользователь с правом редактирования. Может изменять данные, структуру листов, форматирование. Не может удалить файл или передать владение |
| **Комментатор (Commenter)** | Пользователь с правом комментирования. Может просматривать данные и оставлять комментарии. Не может редактировать содержимое |
| **Читатель (Viewer)** | Пользователь с правом просмотра. Может только просматривать данные. Не может редактировать или комментировать |
| **Анонимный пользователь** | Пользователь без аккаунта Google. Может просматривать публичные таблицы через ссылку "Доступно всем в интернете" |

### Организационные роли (Google Workspace)

| Роль | Описание |
|------|----------|
| **Администратор домена** | Может управлять настройками Google Sheets на уровне организации, политиками шаринга, аудитом |
| **Участник домена** | Пользователь организации с корпоративным аккаунтом. Может иметь расширенные квоты и возможности |

## Функциональные требования

### FR-SPR-001: Создание новой таблицы

**Описание:** Создание пустой электронной таблицы Google Sheets

**Роли:** Владелец аккаунта Google

**Предусловия:**
- Пользователь авторизован в Google-аккаунте
- Пользователь имеет доступ к Google Sheets

**Основной сценарий:**
1. Пользователь переходит на sheets.google.com
2. Пользователь нажимает кнопку "+" (Пустой файл) или "Создать" в интерфейсе
3. Система создает новую таблицу с одним листом "Sheet1"
4. Таблица получает название "Новая таблица" (Untitled spreadsheet)
5. Таблица автоматически сохраняется в корневой папке "Мой диск" (My Drive)
6. Пользователь перенаправляется в редактор таблицы
7. Пользователь становится владельцем созданной таблицы

**Альтернативные сценарии:**

*A1. Создание через Google Drive:*
1. Пользователь находится в Google Drive
2. Пользователь нажимает "+ Создать" → "Google Таблицы" → "Пустой файл"
3. Система создает таблицу в текущей папке Drive
4. Открывается редактор таблицы

*A2. Создание через прямой URL:*
1. Пользователь вводит в браузере sheets.new
2. Система мгновенно создает новую пустую таблицу
3. Таблица сохраняется в "Мой диск"

*A3. Создание в конкретной папке:*
1. Пользователь открывает нужную папку в Google Drive
2. Пользователь создает таблицу
3. Таблица сохраняется в текущей папке, а не в корне

**Бизнес-правила:**
- BR-001: Каждая новая таблица содержит минимум один лист (Sheet1)
- BR-002: Название по умолчанию — "Новая таблица" (Untitled spreadsheet)
- BR-003: Таблица получает уникальный идентификатор в URL
- BR-004: Автосохранение включается автоматически
- BR-005: Создатель автоматически становится владельцем файла

**Результат:** Создана новая пустая таблица Google Sheets

### FR-SPR-002: Создание таблицы из шаблона

**Описание:** Создание таблицы на основе предустановленного или пользовательского шаблона

**Роли:** Владелец аккаунта Google

**Предусловия:**
- Пользователь авторизован в Google-аккаунте
- Доступны шаблоны в галерее

**Основной сценарий:**
1. Пользователь переходит на sheets.google.com
2. Пользователь нажимает "Галерея шаблонов" (Template Gallery) в правом верхнем углу
3. Система отображает категории шаблонов:
   - Личное (Personal): списки дел, бюджеты, планировщики
   - Работа (Work): табели, расписания, отчеты о расходах
   - Проект (Project): графики Ганта, таймлайны
   - Образование (Education): журналы оценок, расписание занятий
4. Пользователь выбирает нужный шаблон
5. Система создает копию шаблона
6. Новая таблица открывается в редакторе
7. Таблица получает название шаблона

**Альтернативные сценарии:**

*A1. Доступ из меню File:*
1. Пользователь открывает любую таблицу
2. Пользователь выбирает "Файл" → "Создать" → "Из галереи шаблонов"
3. Открывается галерея шаблонов
4. Пользователь выбирает шаблон

*A2. Шаблоны организации (Google Workspace):*
1. Пользователь с корпоративным аккаунтом открывает галерею
2. Помимо общих шаблонов, отображаются корпоративные шаблоны домена
3. Корпоративные шаблоны отмечены логотипом организации
4. Пользователь может выбрать корпоративный шаблон

*A3. Сохранение собственного шаблона (Google Workspace):*
1. Пользователь создает таблицу-шаблон
2. Пользователь открывает галерею шаблонов
3. Пользователь нажимает "Отправить шаблон" (Submit template)
4. Таблица добавляется в корпоративную галерею (требуется одобрение администратора)

**Бизнес-правила:**
- BR-006: Шаблон копируется полностью: данные, форматирование, формулы
- BR-007: Созданная таблица независима от исходного шаблона
- BR-008: Пользователь становится владельцем копии
- BR-009: Корпоративные шаблоны доступны только участникам домена
- BR-010: Для отправки корпоративных шаблонов может требоваться одобрение администратора

**Результат:** Создана таблица на основе выбранного шаблона

### FR-SPR-003: Переименование таблицы

**Описание:** Изменение названия существующей таблицы

**Роли:** Владелец, Редактор

**Предусловия:**
- Таблица существует
- Пользователь имеет права редактирования

**Основной сценарий:**
1. Пользователь открывает таблицу в редакторе
2. Пользователь кликает на название таблицы в левом верхнем углу
3. Название становится редактируемым (выделяется текстовое поле)
4. Пользователь вводит новое название
5. Пользователь нажимает Enter или кликает вне поля
6. Система сохраняет новое название
7. Изменение синхронизируется с Google Drive

**Альтернативные сценарии:**

*A1. Переименование через Google Drive:*
1. Пользователь находит таблицу в Google Drive
2. Пользователь кликает правой кнопкой мыши на файл
3. Пользователь выбирает "Переименовать" (Rename)
4. Вводит новое название и подтверждает

*A2. Переименование через меню File:*
1. Пользователь в редакторе выбирает "Файл" → "Переименовать"
2. Название становится редактируемым
3. Пользователь вводит новое название

*A3. Название содержит недопустимые символы:*
1. Пользователь пытается использовать символы: / \ * ? " < > |
2. Система не применяет недопустимые символы или заменяет их
3. Отображается предупреждение

**Бизнес-правила:**
- BR-011: Название может содержать до 255 символов
- BR-012: Некоторые специальные символы недопустимы
- BR-013: Название не обязательно уникально (файлы различаются по ID)
- BR-014: Изменение названия отражается во всех представлениях (Drive, недавние файлы)
- BR-015: История изменений названий сохраняется в истории версий

**Результат:** Название таблицы изменено

### FR-SPR-004: Копирование таблицы (создание копии)

**Описание:** Создание полной копии существующей таблицы

**Роли:** Владелец, Редактор, Комментатор, Читатель (если разрешено копирование)

**Предусловия:**
- Таблица существует
- У пользователя есть доступ к таблице
- Копирование не запрещено владельцем

**Основной сценарий:**
1. Пользователь открывает таблицу
2. Пользователь выбирает "Файл" → "Создать копию" (Make a copy)
3. Система отображает диалог с параметрами:
   - Название копии (по умолчанию: "Копия [оригинальное название]")
   - Папка назначения (по умолчанию: "Мой диск")
   - Опция "Предоставить доступ тем же пользователям" (Share it with the same people)
   - Опция "Скопировать комментарии" (Copy comments)
4. Пользователь настраивает параметры
5. Пользователь нажимает "Создать копию" (Make a copy)
6. Система создает копию таблицы
7. Копия открывается в новой вкладке

**Альтернативные сценарии:**

*A1. Копирование через Google Drive:*
1. Пользователь в Drive кликает правой кнопкой на файл
2. Выбирает "Создать копию" (Make a copy)
3. Копия создается в той же папке с приставкой "Копия"

*A2. Копирование отдельных листов:*
1. Пользователь кликает правой кнопкой на вкладку листа
2. Выбирает "Копировать в..." (Copy to)
3. Выбирает:
   - "Новый файл" (New spreadsheet) — создается новая таблица с этим листом
   - "Существующий файл" (Existing spreadsheet) — лист добавляется в другую таблицу
4. Лист копируется в указанное место

*A3. Копирование запрещено владельцем:*
1. Владелец в настройках доступа отключил "Читатели и комментаторы могут скачивать, печатать и копировать"
2. Пункт "Создать копию" недоступен для читателей/комментаторов
3. Только редакторы и владелец могут копировать

*A4. Копирование в папку без доступа:*
1. Пользователь выбирает папку, к которой нет доступа на запись
2. Система уведомляет об ошибке
3. Пользователь выбирает другую папку

**Бизнес-правила:**
- BR-016: Копия независима от оригинала — изменения не синхронизируются
- BR-017: Пользователь становится владельцем копии
- BR-018: По умолчанию комментарии не копируются
- BR-019: Копирование включает все листы, данные, форматирование, формулы
- BR-020: Связи с внешними данными (IMPORTRANGE) требуют повторной авторизации
- BR-021: Владелец может запретить копирование для читателей и комментаторов

**Результат:** Создана независимая копия таблицы

### FR-SPR-005: Перемещение таблицы в папку

**Описание:** Изменение расположения таблицы в структуре папок Google Drive

**Роли:** Владелец, Редактор (с ограничениями)

**Предусловия:**
- Таблица существует
- Пользователь имеет права на перемещение
- Пользователь имеет доступ к целевой папке

**Основной сценарий:**
1. Пользователь открывает таблицу в редакторе
2. Пользователь кликает на иконку папки рядом с названием таблицы
3. Система отображает текущее расположение файла
4. Пользователь нажимает иконку перемещения
5. Система отображает структуру папок Google Drive
6. Пользователь выбирает целевую папку
7. Пользователь нажимает "Переместить" (Move)
8. Таблица перемещается в выбранную папку

**Альтернативные сценарии:**

*A1. Перемещение через Google Drive:*
1. Пользователь в Drive выделяет таблицу
2. Пользователь кликает правой кнопкой → "Упорядочить" → "Переместить" (Organize → Move)
3. Выбирает целевую папку
4. Подтверждает перемещение

*A2. Перемещение перетаскиванием (Drag & Drop):*
1. Пользователь в Google Drive захватывает файл мышью
2. Перетаскивает на целевую папку
3. Файл перемещается

*A3. Перемещение нескольких файлов:*
1. Пользователь в Drive выделяет несколько таблиц (Ctrl+клик или Shift+клик)
2. Выбирает "Переместить"
3. Все выбранные файлы перемещаются в одну папку

*A4. Перемещение общего файла (не владелец):*
1. Редактор пытается переместить файл, которым не владеет
2. Система не позволяет физически переместить файл
3. Вместо этого создается ярлык (shortcut) в указанной папке
4. Оригинал остается на месте

*A5. Перемещение на общий диск (Shared Drive):*
1. Пользователь перемещает таблицу на общий диск организации
2. Владение файлом передается общему диску
3. Индивидуальное владение утрачивается
4. Система предупреждает об этом перед перемещением

**Бизнес-правила:**
- BR-022: Только владелец может физически перемещать файл
- BR-023: Редакторы могут создавать ярлыки, но не перемещать
- BR-024: Перемещение на общий диск меняет владельца на диск
- BR-025: Файл может находиться только в одной папке (но иметь несколько ярлыков)
- BR-026: При перемещении на общий диск применяются политики этого диска

**Результат:** Таблица перемещена в указанную папку

### FR-SPR-006: Создание ярлыка (Shortcut) для таблицы

**Описание:** Создание ссылки на таблицу в другой папке без физического перемещения

**Роли:** Владелец, Редактор, Комментатор, Читатель

**Предусловия:**
- Таблица существует
- Пользователь имеет любой уровень доступа к таблице
- Пользователь имеет доступ на запись в целевую папку

**Основной сценарий:**
1. Пользователь находит таблицу в Google Drive
2. Пользователь кликает правой кнопкой мыши
3. Выбирает "Упорядочить" → "Добавить ярлык" (Organize → Add shortcut)
4. Система отображает выбор папки
5. Пользователь выбирает целевую папку
6. Пользователь нажимает "Добавить ярлык" (Add shortcut)
7. Ярлык создается в выбранной папке

**Особенности ярлыков:**
- Ярлык указывает на оригинальный файл
- Изменения в файле отражаются при открытии через любой ярлык
- Удаление ярлыка не влияет на оригинальный файл
- Удаление оригинала делает все ярлыки недействительными
- Ярлык отображается с иконкой стрелки

**Бизнес-правила:**
- BR-027: Один файл может иметь множество ярлыков
- BR-028: Ярлык — это ссылка, а не копия
- BR-029: Права доступа определяются оригинальным файлом, не папкой с ярлыком
- BR-030: Ярлык полезен для организации общих файлов без смены их владельца

**Результат:** Создан ярлык на таблицу в указанной папке

### FR-SPR-007: Удаление таблицы (перемещение в корзину)

**Описание:** Удаление таблицы с перемещением в корзину Google Drive

**Роли:** Владелец, Редактор (для собственных файлов или если разрешено)

**Предусловия:**
- Таблица существует
- Пользователь имеет право удаления

**Основной сценарий:**
1. Пользователь находит таблицу в Google Drive
2. Пользователь кликает правой кнопкой мыши
3. Выбирает "Удалить" (Remove) или "Переместить в корзину" (Move to trash)
4. Система перемещает файл в корзину
5. Файл остается в корзине в течение 30 дней
6. После 30 дней файл удаляется автоматически

**Альтернативные сценарии:**

*A1. Удаление через редактор таблицы:*
1. Пользователь открывает таблицу
2. Пользователь выбирает "Файл" → "Переместить в корзину"
3. Система запрашивает подтверждение
4. Таблица перемещается в корзину
5. Пользователь перенаправляется на sheets.google.com

*A2. Удаление клавишей Delete:*
1. Пользователь выделяет файл в Google Drive
2. Пользователь нажимает Delete или Backspace
3. Файл перемещается в корзину

*A3. Удаление общего файла (не владельцем):*
1. Редактор удаляет файл, которым не владеет
2. Файл удаляется только из его представления Drive
3. Оригинал остается у владельца и других пользователей
4. Для полного удаления необходимо быть владельцем

*A4. Удаление файла с общего диска:*
1. Пользователь удаляет файл с общего диска (Shared Drive)
2. Файл перемещается в корзину общего диска
3. Администраторы диска могут восстановить файл
4. Любой участник диска с правами может восстановить

**Бизнес-правила:**
- BR-031: Удаленные файлы хранятся в корзине 30 дней
- BR-032: После 30 дней происходит автоматическое окончательное удаление
- BR-033: Только владелец может удалить файл для всех пользователей
- BR-034: Не-владельцы удаляют файл только из своего представления
- BR-035: На общих дисках действуют политики диска

**Результат:** Таблица перемещена в корзину

### FR-SPR-008: Восстановление таблицы из корзины

**Описание:** Восстановление ранее удаленной таблицы из корзины Google Drive

**Роли:** Владелец (или участник общего диска)

**Предусловия:**
- Таблица находится в корзине
- Не прошло более 30 дней с момента удаления

**Основной сценарий:**
1. Пользователь переходит в Google Drive
2. Пользователь открывает раздел "Корзина" (Trash) в левом меню
3. Пользователь находит нужную таблицу
4. Пользователь кликает правой кнопкой мыши

**Описание:** Добавление таблицы в избранное для быстрого доступа

**Роли:** Любой пользователь с доступом к таблице

**Предусловия:**
- Пользователь имеет доступ к таблице

**Основной сценарий:**
1. Пользователь открывает таблицу
2. Пользователь нажимает на иконку звездочки рядом с названием таблицы
3. Звездочка становится желтой (заполненной)
4. Таблица добавляется в раздел "Помеченные" (Starred) в Google Drive

**Альтернативный сценарий (через Drive):**
1. Пользователь находит таблицу в Google Drive
2. Кликает правой кнопкой → "Добавить в помеченные" (Add to starred)
3. Или кликает на иконку звездочки при наведении на файл

**Просмотр избранных:**
1. Пользователь переходит в Google Drive
2. В левом меню выбирает "Помеченные" (Starred)
3. Отображаются все избранные файлы

**Бизнес-правила:**
- BR-120: Избранное персональное — не влияет на других пользователей
- BR-121: Звездочка сохраняется независимо от изменений в файле
- BR-122: Можно пометить файлы, которыми пользователь не владеет

**Результат:** Таблица добавлена в избранное

### FR-SPR-030: Настройка регионального формата таблицы

**Описание:** Установка локали для форматирования чисел, дат, валют

**Роли:** Владелец, Редактор

**Предусловия:**
- Таблица открыта
- Пользователь имеет права редактирования

**Основной сценарий:**
1. Пользователь выбирает "Файл" → "Настройки" (File → Settings)
2. Открывается диалог настроек таблицы
3. Пользователь выбирает региональные настройки (Locale):
   - Россия — числа 1 000,00; даты ДД.ММ.ГГГГ; валюта ₽
   - США — числа 1,000.00; даты MM/DD/YYYY; валюта $
   - И другие регионы
4. Пользователь выбирает часовой пояс
5. Пользователь нажимает "Сохранить настройки"
6. Форматирование в таблице обновляется

**Бизнес-правила:**
- BR-123: Локаль влияет на формат чисел, дат, валют по умолчанию
- BR-124: Существующие ячейки с явным форматированием не изменяются
- BR-125: Настройки применяются ко всей таблице (всем листам)
- BR-126: Часовой пояс влияет на функции NOW(), TODAY()

**Результат:** Региональный формат таблицы настроен

## Состояния и статусы

### Статусы файла

| Статус | Описание |
|--------|----------|
| **Активный** | Файл доступен для работы в Google Drive |
| **В корзине** | Файл удален, но может быть восстановлен в течение 30 дней |
| **Удален навсегда** | Файл безвозвратно удален |

### Статусы листа

| Статус | Описание |
|--------|----------|
| **Видимый** | Лист отображается в панели вкладок |
| **Скрытый** | Лист скрыт, но доступен редакторам через меню |
| **Защищенный** | Лист или диапазон защищен от редактирования |

### Статусы синхронизации

| Статус | Описание |
|--------|----------|
| **Все изменения сохранены** | Данные синхронизированы с облаком |
| **Сохранение...** | Идет процесс сохранения |
| **Офлайн** | Нет подключения, изменения сохраняются локально |
