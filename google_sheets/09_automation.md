# Модуль автоматизации (Automation)

## Описание

Модуль автоматизации Google Sheets позволяет пользователям создавать автоматические действия без программирования (макросы) или с использованием скриптов (Google Apps Script). Включает запись и воспроизведение макросов, создание пользовательских функций, настройку триггеров по времени и событиям, автоматические уведомления, интеграцию с Google Forms и внешними системами через webhooks.

## Роли пользователей

### В контексте автоматизации
- **Владелец (Owner)** - полный доступ к макросам и скриптам, управление триггерами, разрешение доступа для других
- **Редактор (Editor)** - может записывать и запускать макросы, создавать триггеры для своих скриптов
- **Комментатор (Commenter)** - НЕ имеет доступа к автоматизации
- **Читатель (Viewer)** - НЕ имеет доступа к автоматизации

### В контексте Apps Script
- **Автор скрипта** - создатель скрипта, полный контроль над кодом и триггерами
- **Пользователь скрипта** - запускает скрипт, авторизует доступ к своим данным

## Функциональные требования

### FR-AUT-001: Запись макроса

**Описание:** Запись последовательности действий пользователя для автоматического воспроизведения

**Роли:** Владелец, Редактор

**Предусловия:**
- Пользователь имеет права редактирования таблицы
- Таблица открыта в браузере

**Основной сценарий:**
1. Пользователь открывает меню "Расширения" (Extensions)
2. Выбирает "Макросы" (Macros) -> "Записать макрос" (Record macro)
3. Система показывает панель записи с выбором типа ссылок:
   - Абсолютные ссылки (Absolute references) - действия привязаны к конкретным ячейкам
   - Относительные ссылки (Relative references) - действия относительно текущей позиции
4. Пользователь выполняет действия в таблице:
   - Форматирование ячеек
   - Ввод данных
   - Применение формул
   - Сортировка и фильтрация
   - Изменение размеров строк/столбцов
5. Пользователь нажимает "Сохранить" (Save) на панели записи
6. Система предлагает ввести:
   - Название макроса
   - Сочетание клавиш (Ctrl+Alt+Shift+[0-9] или Cmd+Option+Shift+[0-9] на Mac)
7. Пользователь сохраняет макрос
8. Система создает функцию Apps Script в файле macros.gs

**Альтернативный сценарий 1: Отмена записи**
- 5.1. Пользователь нажимает "Отмена" (Cancel)
- 5.2. Система прекращает запись без сохранения

**Бизнес-правила:**
- BR-001: Макросы сохраняются в привязанном проекте Apps Script
- BR-002: Максимум 10 макросов с сочетаниями клавиш на таблицу
- BR-003: Название макроса должно быть уникальным в пределах таблицы
- BR-004: При записи не сохраняются: навигация между листами, выделение ячеек без действий

**Результат:** Макрос записан и доступен для воспроизведения

---

### FR-AUT-002: Воспроизведение макроса

**Описание:** Запуск ранее записанного макроса

**Роли:** Владелец, Редактор

**Предусловия:**
- Существует хотя бы один записанный макрос
- Пользователь авторизовал выполнение скриптов

**Основной сценарий:**
1. Пользователь запускает макрос одним из способов:
   - Меню "Расширения" -> "Макросы" -> [Название макроса]
   - Сочетание клавиш (если назначено)
2. При первом запуске система запрашивает авторизацию:
   - Отображается список разрешений, которые требует макрос
   - Пользователь подтверждает или отклоняет
3. Система выполняет записанную последовательность действий
4. Результат отображается в таблице

**Альтернативный сценарий 1: Отказ в авторизации**
- 2.1. Пользователь отклоняет авторизацию
- 2.2. Макрос не выполняется
- 2.3. Показывается сообщение о необходимости авторизации

**Альтернативный сценарий 2: Ошибка выполнения**
- 3.1. Во время выполнения возникает ошибка
- 3.2. Система показывает сообщение об ошибке
- 3.3. Частично выполненные действия остаются в таблице

**Бизнес-правила:**
- BR-010: Авторизация запрашивается один раз, сохраняется для пользователя
- BR-011: При изменении кода макроса может потребоваться повторная авторизация
- BR-012: Макросы выполняются синхронно, блокируя интерфейс
- BR-013: Время выполнения макроса ограничено 6 минутами (как для Apps Script)

**Результат:** Макрос выполнен, изменения применены к таблице

### FR-AUT-003: Управление макросами

**Описание:** Просмотр, редактирование и удаление макросов

**Роли:** Владелец, Редактор

**Предусловия:**
- Существуют записанные макросы

**Основной сценарий:**
1. Пользователь открывает "Расширения" -> "Макросы" -> "Управление макросами" (Manage macros)
2. Система отображает список макросов:
   - Название макроса
   - Назначенное сочетание клавиш (если есть)
3. Для каждого макроса доступны действия:
   - Изменить сочетание клавиш
   - Удалить макрос
   - Редактировать скрипт (открывает Apps Script Editor)

**Бизнес-правила:**
- BR-020: При удалении макроса код остается в Apps Script (нужно удалять вручную)
- BR-021: Изменение сочетания клавиш вступает в силу немедленно
- BR-022: Только владелец может редактировать код макросов

**Результат:** Макросы управляются централизованно

### FR-AUT-004: Импорт функции как макроса

**Описание:** Использование существующей функции Apps Script в качестве макроса

**Роли:** Владелец, Редактор

**Предусловия:**
- В проекте Apps Script существуют функции без параметров

**Основной сценарий:**
1. Пользователь открывает "Расширения" -> "Макросы" -> "Импорт" (Import)
2. Система отображает список доступных функций из Apps Script
3. Пользователь выбирает функцию
4. Система добавляет функцию в список макросов
5. Пользователь может назначить сочетание клавиш

**Бизнес-правила:**
- BR-030: Только функции без параметров могут быть импортированы как макросы
- BR-031: Функция должна быть в том же проекте Apps Script, что и таблица

**Результат:** Функция Apps Script доступна как макрос

### FR-AUT-005: Создание проекта Apps Script

**Описание:** Открытие редактора Apps Script для создания скриптов

**Роли:** Владелец, Редактор

**Предусловия:**
- Пользователь имеет права редактирования таблицы

**Основной сценарий:**
1. Пользователь открывает "Расширения" -> "Apps Script"
2. Система открывает редактор Apps Script в новой вкладке:
   - Создается контейнер-связанный (container-bound) проект
   - Проект автоматически связан с таблицей
   - Доступны все API для работы с таблицей
3. Пользователь видит интерфейс редактора:
   - Файловый навигатор слева
   - Редактор кода в центре
   - Логи выполнения
   - Панель инструментов
4. По умолчанию создается файл Code.gs с пустой функцией myFunction()

**Структура проекта Apps Script:**

| Компонент | Описание |
|-----------|----------|
| .gs файлы | JavaScript код |
| .html файлы | HTML для веб-приложений и диалогов |
| appsscript.json | Манифест проекта (разрешения, триггеры) |
| macros.gs | Файл с записанными макросами |

**Бизнес-правила:**
- BR-040: Каждая таблица может иметь один привязанный проект Apps Script
- BR-041: Привязанный проект имеет доступ к SpreadsheetApp без авторизации
- BR-042: Проект наследует права доступа от таблицы
- BR-043: Изменения в коде автоматически сохраняются

**Результат:** Редактор Apps Script открыт, проект создан

### FR-AUT-006: Простые триггеры (Simple Triggers)

**Описание:** Автоматический запуск функций при определенных событиях в таблице

**Роли:** Автор скрипта

**Предусловия:**
- Существует проект Apps Script, связанный с таблицей

**Типы простых триггеров:**

| Функция | Событие | Описание |
|---------|---------|----------|
| onOpen(e) | Открытие таблицы | Запускается при открытии таблицы пользователем с правами редактирования |
| onEdit(e) | Редактирование ячейки | Запускается при изменении значения ячейки пользователем |
| onSelectionChange(e) | Изменение выделения | Запускается при выборе другой ячейки или диапазона |
| onInstall(e) | Установка дополнения | Запускается при установке дополнения из Marketplace |

**Основной сценарий:**
1. Пользователь создает функцию с зарезервированным именем:
```javascript
function onOpen(e) {
  // Добавление пользовательского меню
  SpreadsheetApp.getUi()
    .createMenu('Мое меню')
    .addItem('Запустить скрипт', 'myFunction')
    .addToUi();
}
```
2. Функция автоматически срабатывает при соответствующем событии
3. Авторизация не требуется для базовых операций

**Объект события (Event Object):**

| Свойство | Тип | Описание |
|----------|-----|----------|
| e.source | Spreadsheet | Объект таблицы |
| e.range | Range | Измененный диапазон (для onEdit) |
| e.value | String | Новое значение (для onEdit) |
| e.oldValue | String | Предыдущее значение (для onEdit) |
| e.user | User | Объект пользователя (ограничен для простых триггеров) |

**Бизнес-правила:**
- BR-050: Простые триггеры не требуют авторизации для базовых операций
- BR-051: Простые триггеры не могут вызывать сервисы, требующие авторизации (MailApp, UrlFetchApp)
- BR-052: Время выполнения простого триггера ограничено 30 секундами
- BR-053: onEdit срабатывает только при ручном редактировании, не при изменении формулами
- BR-054: onSelectionChange доступен с очередью до 2 событий

**Результат:** Функция автоматически выполняется при наступлении события

### FR-AUT-007: Устанавливаемые триггеры (Installable Triggers)

**Описание:** Расширенные триггеры с поддержкой авторизованных сервисов и дополнительных событий

**Роли:** Автор скрипта

**Предусловия:**
- Существует проект Apps Script
- Пользователь авторизовал скрипт

**Типы устанавливаемых триггеров:**

| Тип | Событие | Описание |
|-----|---------|----------|
| onOpen | Открытие таблицы | Как простой триггер, но с авторизацией |
| onEdit | Редактирование | Как простой триггер, но с авторизацией |
| onChange | Изменение структуры | Добавление/удаление листов, столбцов, строк |
| onFormSubmit | Отправка формы | При получении ответа из связанной Google Form |
| Time-driven | По расписанию | Периодическое выполнение |

**Основной сценарий создания через UI:**
1. Пользователь открывает Apps Script Editor
2. Нажимает на значок часов (Triggers) в левом меню
3. Нажимает "Добавить триггер" (Add Trigger)
4. Настраивает параметры:
   - Функция для запуска
   - Тип триггера (From spreadsheet / Time-driven)
   - Событие (On open / On edit / On change / On form submit)
   - Или расписание для time-driven триггера
5. Сохраняет триггер
6. При первом сохранении запрашивается авторизация

**Создание триггера программно:**
```javascript
function createTrigger() {
  ScriptApp.newTrigger('myFunction')
    .forSpreadsheet(SpreadsheetApp.getActive())
    .onEdit()
    .create();
}
```

**Преимущества перед простыми триггерами:**
- Доступ к авторизованным сервисам (MailApp, UrlFetchApp и др.)
- Выполнение от имени создателя триггера
- Дополнительные типы событий (onChange, onFormSubmit)
- Более длительное время выполнения

**Бизнес-правила:**
- BR-060: Устанавливаемые триггеры выполняются от имени создателя
- BR-061: НЕ использовать имена onOpen, onEdit для устанавливаемых триггеров (избежание двойного запуска)
- BR-062: Максимум 20 триггеров на пользователя на скрипт
- BR-063: Триггер сохраняется даже если создатель потеряет доступ к таблице
- BR-064: Время выполнения ограничено 6 минутами

**Результат:** Устанавливаемый триггер создан и активен

### FR-AUT-008: Триггеры по времени (Time-driven Triggers)

**Описание:** Автоматический запуск скриптов по расписанию

**Роли:** Автор скрипта

**Предусловия:**
- Существует проект Apps Script
- Пользователь авторизовал скрипт

**Типы временных триггеров:**

| Метод | Описание | Параметры |
|-------|----------|-----------|
| everyMinutes(n) | Каждые n минут | n = 1, 5, 10, 15, 30 |
| everyHours(n) | Каждые n часов | n = 1-24 |
| everyDays(n) | Каждые n дней | n = 1-365 |
| everyWeeks(n) | Каждые n недель | n = 1-52 |
| onMonthDay(day) | В определенный день месяца | day = 1-31 |
| onWeekDay(day) | В определенный день недели | ScriptApp.WeekDay.* |
| atHour(hour) | В определенный час | hour = 0-23 |
| nearMinute(minute) | Около определенной минуты | minute = 0-59 |
| inTimezone(tz) | В указанном часовом поясе | Строка часового пояса |

**Основной сценарий:**
1. Пользователь создает функцию для периодического выполнения:
```javascript
function dailyReport() {
  // Генерация отчета
  var sheet = SpreadsheetApp.getActiveSpreadsheet();
  // ... логика отчета
  MailApp.sendEmail('team@company.com', 'Daily Report', 'Report content');
}
```

2. Создает триггер через UI или код:
```javascript
function createDailyTrigger() {
  ScriptApp.newTrigger('dailyReport')
    .timeBased()
    .everyDays(1)
    .atHour(9)
    .inTimezone('Europe/Moscow')
    .create();
}
```

3. Система выполняет функцию по расписанию

**Важные особенности:**
- Время может отклоняться на несколько минут (например, триггер на 9:00 может сработать в 9:00-10:00)
- После установки времени оно фиксируется и сохраняется постоянным
- Часовой пояс по умолчанию - часовой пояс скрипта

**Бизнес-правила:**
- BR-070: Минимальный интервал - 1 минута
- BR-071: Время выполнения может отклоняться в пределах окна (например, 9:00-10:00 для atHour(9))
- BR-072: Пропущенные запуски не выполняются ретроспективно
- BR-073: Триггер продолжает работать даже если таблица закрыта
- BR-074: Ошибка триггера отправляется на email создателя

**Результат:** Скрипт выполняется автоматически по расписанию

### FR-AUT-009: Пользовательские функции (Custom Functions)

**Описание:** Создание собственных формул для использования в ячейках таблицы

**Роли:** Владелец, Редактор

**Предусловия:**
- Существует проект Apps Script, связанный с таблицей

**Основной сценарий:**
1. Пользователь создает функцию в Apps Script:
```javascript
/**
 * Конвертирует дюймы в миллиметры
 * @param {number} inches Значение в дюймах
 * @return {number} Значение в миллиметрах
 * @customfunction
 */
function IN2MM(inches) {
  return inches * 25.4;
}
```

2. Сохраняет скрипт
3. В таблице вводит формулу: `=IN2MM(A1)`
4. Функция появляется в автодополнении с описанием из JSDoc

**Поддерживаемые типы параметров и возвращаемых значений:**

| Тип | В ячейке | В скрипте |
|-----|----------|-----------|
| Number | 123, 1.5 | Number |
| String | "текст" | String |
| Boolean | TRUE/FALSE | Boolean |
| Date | дата | Date |
| Диапазон | A1:B10 | Number[][] или String[][] |
| Пусто | пустая ячейка | "" (пустая строка) |

**Возврат диапазона значений:**
```javascript
/**
 * Умножает все элементы матрицы на множитель
 * @param {number[][]} matrix Входная матрица
 * @param {number} multiplier Множитель
 * @return {number[][]} Результирующая матрица
 * @customfunction
 */
function MULTIPLY_MATRIX(matrix, multiplier) {
  return matrix.map(row => row.map(cell => cell * multiplier));
}
```

**Ограничения пользовательских функций:**
- Не могут изменять другие ячейки (только возвращать значение)
- Не могут вызывать сервисы, требующие авторизации
- Не могут отображать диалоги или боковые панели
- Время выполнения ограничено 30 секундами

**Бизнес-правила:**
- BR-080: Тег @customfunction обязателен для отображения в автодополнении
- BR-081: JSDoc комментарий отображается как подсказка
- BR-082: Функция должна быть детерминированной для корректного кэширования
- BR-083: Результат кэшируется до изменения входных параметров
- BR-084: Режим авторизации CUSTOM_FUNCTION имеет дополнительные ограничения

**Результат:** Пользовательская функция доступна как формула в таблице

### FR-AUT-010: Отправка email из скрипта

**Описание:** Автоматическая отправка электронных писем на основе данных таблицы

**Роли:** Автор скрипта

**Предусловия:**
- Существует проект Apps Script
- Скрипт авторизован для отправки email
- Не превышен дневной лимит email

**Сервисы для отправки email:**

| Сервис | Описание | Преимущества |
|--------|----------|--------------|
| MailApp | Простая отправка email | Легко использовать, не требует доступа к Gmail |
| GmailApp | Полный доступ к Gmail | Создание черновиков, доступ к inbox, вложения |

**Основной сценарий с MailApp:**
```javascript
function sendSimpleEmail() {
  MailApp.sendEmail({
    to: 'recipient@example.com',
    subject: 'Отчет',
    body: 'Текст письма',
    htmlBody: '<h1>HTML версия</h1>',
    attachments: [spreadsheetAsPdf],
    name: 'Автоматический отчет'
  });
}
```

**Сценарий массовой рассылки (Mail Merge):**
```javascript
function mailMerge() {
  var sheet = SpreadsheetApp.getActiveSheet();
  var data = sheet.getDataRange().getValues();
  var template = 'Уважаемый(ая) {{name}}, ваш заказ {{order}} обработан.';

  for (var i = 1; i < data.length; i++) {
    var email = data[i][0];
    var name = data[i][1];
    var order = data[i][2];

    var message = template
      .replace('{{name}}', name)
      .replace('{{order}}', order);

    MailApp.sendEmail(email, 'Статус заказа', message);
  }
}
```

**Параметры MailApp.sendEmail():**

### FR-AUT-018: Защита и блокировка от параллельного выполнения

**Описание:** Предотвращение конфликтов при одновременном выполнении скриптов

**Роли:** Автор скрипта

**Предусловия:**
- Скрипт может выполняться параллельно несколькими пользователями

**Основной сценарий:**
```javascript
function processData() {
  var lock = LockService.getScriptLock();

  try {
    // Попытка получить блокировку (ждать до 30 секунд)
    lock.waitLock(30000);

    // Критическая секция - только один экземпляр
    var sheet = SpreadsheetApp.getActiveSheet();
    var lastRow = sheet.getLastRow();

    // Безопасная обработка данных
    processRowsSafely(sheet, lastRow);

  } catch (e) {
    Logger.log('Не удалось получить блокировку: ' + e.message);
    throw e;
  } finally {
    // Обязательно освободить блокировку
    lock.releaseLock();
  }
}
```

**Типы блокировок:**

| Тип | Метод | Область |
|-----|-------|---------|
| Document Lock | LockService.getDocumentLock() | На уровне документа |
| Script Lock | LockService.getScriptLock() | На уровне скрипта |
| User Lock | LockService.getUserLock() | На уровне пользователя |

**Методы LockService:**

| Метод | Описание |
|-------|----------|
| tryLock(timeoutMs) | Попытаться получить блокировку, вернуть true/false |
| waitLock(timeoutMs) | Ждать блокировку, выбросить исключение при таймауте |
| hasLock() | Проверить, есть ли блокировка |
| releaseLock() | Освободить блокировку |

**Бизнес-правила:**
- BR-170: Блокировка автоматически освобождается через 6 минут
- BR-171: Рекомендуется использовать try-finally для гарантированного освобождения
- BR-172: Document Lock блокирует выполнение для всех пользователей документа
- BR-173: Script Lock блокирует все запуски скрипта
- BR-174: User Lock блокирует только запуски конкретного пользователя

**Результат:** Параллельное выполнение контролируется через блокировки

### FR-AUT-019: Хранение настроек и конфигурации

**Описание:** Сохранение пользовательских настроек и конфигурации скрипта

**Роли:** Автор скрипта

**Предусловия:**
- Существует проект Apps Script

**Сервисы хранения:**

| Сервис | Область | Лимит |
|--------|---------|-------|
| PropertiesService.getUserProperties() | Текущий пользователь и скрипт | 500 KB |
| PropertiesService.getScriptProperties() | Скрипт (для всех пользователей) | 500 KB |
| PropertiesService.getDocumentProperties() | Документ (для всех пользователей) | 500 KB |

**Основной сценарий:**
```javascript
// Сохранение настроек пользователя
function saveUserSettings(settings) {
  var userProps = PropertiesService.getUserProperties();
  userProps.setProperty('apiKey', settings.apiKey);
  userProps.setProperty('emailEnabled', settings.emailEnabled);
}

// Получение настроек
function getUserSettings() {
  var userProps = PropertiesService.getUserProperties();
  return {
    apiKey: userProps.getProperty('apiKey') || '',
    emailEnabled: userProps.getProperty('emailEnabled') === 'true'
  };
}

// Сохранение глобальной конфигурации
function saveGlobalConfig(config) {
  var scriptProps = PropertiesService.getScriptProperties();
  scriptProps.setProperties(config);
}

// Удаление всех настроек
function clearAllSettings() {
  PropertiesService.getUserProperties().deleteAllProperties();
}
```

**Методы Properties:**

| Метод | Описание |
|-------|----------|
| getProperty(key) | Получить значение по ключу |
| setProperty(key, value) | Установить значение |
| deleteProperty(key) | Удалить свойство |
| getProperties() | Получить все свойства как объект |
| setProperties(properties) | Установить несколько свойств |
| deleteAllProperties() | Удалить все свойства |
| getKeys() | Получить все ключи |

**Кэширование:**
```javascript
function getCachedData() {
  var cache = CacheService.getScriptCache();
  var cached = cache.get('expensiveData');

  if (cached) {
    return JSON.parse(cached);
  }

  // Долгая операция
  var data = fetchExpensiveData();

  // Кэшировать на 6 часов (21600 секунд)
  cache.put('expensiveData', JSON.stringify(data), 21600);

  return data;
}
```

**Бизнес-правила:**
- BR-180: Все значения хранятся как строки
- BR-181: Максимальный размер одного значения - 9 KB
- BR-182: Общий лимит хранилища - 500 KB на тип
- BR-183: Cache хранит данные до 6 часов
- BR-184: UserProperties доступны только владельцу настроек

**Результат:** Настройки сохранены и доступны между запусками

### FR-AUT-020: Обработка ошибок и логирование

**Описание:** Механизмы отладки, логирования и обработки ошибок в скриптах

**Роли:** Автор скрипта

**Предусловия:**
- Существует проект Apps Script

**Методы логирования:**

| Метод | Описание | Где смотреть |
|-------|----------|--------------|
| Logger.log(message) | Простое логирование | View -> Logs в редакторе |
| console.log(message) | Cloud Logging | View -> Executions |
| console.error(message) | Логирование ошибок | View -> Executions |
| console.warn(message) | Предупреждения | View -> Executions |
| console.info(message) | Информационные сообщения | View -> Executions |

**Обработка ошибок:**
```javascript
function safeOperation() {
  try {
    // Потенциально опасная операция
    var response = UrlFetchApp.fetch('https://api.example.com/data');
    var data = JSON.parse(response.getContentText());
    return processData(data);

  } catch (error) {
    // Логирование ошибки
    console.error('Ошибка в safeOperation: ' + error.message);
    console.error('Stack trace: ' + error.stack);

    // Уведомление администратора
    MailApp.sendEmail(
      'admin@company.com',
      'Ошибка скрипта',
      'Произошла ошибка: ' + error.message
    );

    // Возврат значения по умолчанию или проброс ошибки
    throw new Error('Не удалось выполнить операцию: ' + error.message);
  }
}
```

**Уведомления об ошибках триггеров:**
- При ошибке в триггере Google отправляет email создателю триггера
- Email содержит описание ошибки и ссылку на настройки триггера
- Можно отключить уведомления или настроить их частоту

**Отладка:**
```javascript
// Использование debugger (работает в редакторе)
function debugExample() {
  var data = fetchData();
  debugger; // Точка останова
  processData(data);
}

// Условное логирование
var DEBUG = true;

function debugLog(message) {
  if (DEBUG) {
    console.log('[DEBUG] ' + message);
  }
}
```

**Бизнес-правила:**
- BR-190: Logger.log() имеет ограничение на размер лога
- BR-191: Cloud Logging сохраняет логи на 30 дней
- BR-192: Необработанные исключения в триггерах отправляют уведомление
- BR-193: Можно настроить частоту уведомлений об ошибках (немедленно, ежедневно, еженедельно)
- BR-194: Логи доступны только автору скрипта

**Результат:** Ошибки обрабатываются корректно, логи доступны для анализа

## Сущности данных

### Макрос (Macro)
- **Macro ID** - уникальный идентификатор в проекте
- **Name** - название макроса
- **Shortcut** - сочетание клавиш (Ctrl+Alt+Shift+[0-9])
- **Function Name** - имя функции в Apps Script
- **Spreadsheet ID** - ID таблицы, к которой привязан
- **Created by** - создатель макроса
- **Created at** - дата создания
- **Last run at** - последний запуск

### Проект Apps Script (Script Project)
- **Project ID** - уникальный идентификатор проекта
- **Name** - название проекта
- **Type** - container-bound или standalone
- **Parent ID** - ID родительского документа (для container-bound)
- **Files** - список файлов (.gs, .html)
- **Manifest** - appsscript.json
- **Triggers** - список триггеров
- **Deployments** - развертывания (Web App, API, Add-on)
- **Owner** - владелец проекта
- **Editors** - редакторы проекта
- **Created at** - дата создания
- **Updated at** - дата изменения

### Триггер (Trigger)
- **Trigger ID** - уникальный идентификатор
- **Project ID** - ID проекта Apps Script
- **Function Name** - вызываемая функция
- **Type** - simple, installable, time-driven
- **Event Type** - onOpen, onEdit, onChange, onFormSubmit, clock
- **Schedule** - расписание (для time-driven)
- **Source** - источник события (spreadsheet, form, calendar)
- **Created by** - создатель триггера
- **Created at** - дата создания
- **Last run at** - последний запуск
- **Last error** - последняя ошибка

### Выполнение скрипта (Execution)
- **Execution ID** - уникальный идентификатор
- **Project ID** - ID проекта
- **Function Name** - выполненная функция
- **Trigger ID** - ID триггера (если есть)
- **Status** - running, completed, failed, cancelled, timeout
- **Start time** - время начала
- **End time** - время окончания
- **Duration** - продолжительность
- **User** - пользователь, запустивший
- **Error message** - сообщение об ошибке
- **Logs** - логи выполнения

### Развертывание (Deployment)
- **Deployment ID** - уникальный идентификатор
- **Project ID** - ID проекта
- **Type** - Web App, API Executable, Add-on
- **Version** - версия развертывания
- **URL** - URL для доступа (для Web App)
- **Execute as** - от чьего имени выполнять
- **Access** - кто имеет доступ
- **Created at** - дата создания
- **Updated at** - дата обновления

### Свойства (Properties)
- **Type** - user, script, document
- **Key** - ключ свойства
- **Value** - значение (строка)
- **Project/Document ID** - связанный проект или документ

## Состояния и статусы

### Статусы макроса
- **Active** - макрос активен, может быть запущен
- **Running** - макрос выполняется
- **Error** - последнее выполнение завершилось ошибкой

### Статусы триггера
- **Active** - триггер активен
- **Disabled** - триггер отключен
- **Error** - триггер в состоянии ошибки

### Статусы выполнения
- **Running** - выполняется
- **Completed** - успешно завершено
- **Failed** - завершено с ошибкой
- **Cancelled** - отменено пользователем
- **Timeout** - превышено время выполнения

### Жизненный цикл скрипта
```
[Created] -> [Development] -> [Deployed] -> [Running]
     |            |              |            |
     |            v              v            v
     |       [Testing]     [Versioned]    [Error]
     |            |              |            |
     v            v              v            v
[Deleted]   [Published]    [Deprecated]  [Disabled]
```

## Бизнес-правила (сводка)

### Общие правила
- BR-001: Макросы сохраняются в привязанном проекте Apps Script
- BR-002: Максимум 10 макросов с сочетаниями клавиш на таблицу
- BR-010: Авторизация запрашивается один раз, сохраняется для пользователя
- BR-040: Каждая таблица может иметь один привязанный проект Apps Script

### Правила триггеров
- BR-050: Простые триггеры не требуют авторизации для базовых операций
- BR-051: Простые триггеры не могут вызывать авторизованные сервисы
- BR-060: Устанавливаемые триггеры выполняются от имени создателя
- BR-061: НЕ использовать имена onOpen, onEdit для устанавливаемых триггеров
- BR-062: Максимум 20 триггеров на пользователя на скрипт

### Правила пользовательских функций
- BR-080: Тег @customfunction обязателен для автодополнения
- BR-082: Функция должна быть детерминированной для кэширования

- BR-090: Дневной лимит email зависит от типа аккаунта
- BR-091: Email отправляется от имени авторизовавшего скрипт
- BR-092: MailApp не сохраняет письма в "Отправленные"

### Правила интеграций

- BR-111: UrlFetchApp имеет лимит 20000 вызовов в день
