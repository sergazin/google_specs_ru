# Диаграммы и визуализация

## Описание

Модуль "Диаграммы и визуализация" является мощным инструментом Google Sheets для графического представления данных. Модуль позволяет превращать табличные данные в наглядные визуальные элементы: диаграммы различных типов, спарклайны (мини-диаграммы в ячейках), индикаторы прогресса и тепловые карты.

Google Sheets предоставляет более 17 типов диаграмм, включая базовые (линейные, столбчатые, круговые), специализированные (каскадные, воронки, географические карты), финансовые (японские свечи), а также организационные и древовидные диаграммы. Каждая диаграмма полностью настраиваемая: заголовки, оси, легенда, цвета, линии тренда и подписи данных.

Особенностью Google Sheets является функция SPARKLINE, позволяющая создавать компактные визуализации прямо в ячейках таблицы — линейные графики, столбчатые диаграммы, индикаторы прогресса и диаграммы выигрыш/проигрыш.

Диаграммы могут быть опубликованы в интернете и встроены на внешние сайты с автоматическим обновлением при изменении исходных данных.

## Роли пользователей

| Роль | Описание | Права доступа к диаграммам |
|------|----------|----------------------------|
| **Владелец (Owner)** | Создатель документа или пользователь с полными правами | Создание, редактирование, удаление диаграмм; публикация; встраивание; полная настройка |
| **Редактор (Editor)** | Участник с правами редактирования | Создание, редактирование, удаление диаграмм; изменение настроек; добавление спарклайнов |
| **Комментатор (Commenter)** | Участник с правами комментирования | Просмотр диаграмм; взаимодействие с интерактивными элементами; добавление комментариев |
| **Читатель (Viewer)** | Участник только с правами просмотра | Просмотр диаграмм; взаимодействие с интерактивными элементами; экспорт в изображение |

## Функциональные требования

### FR-CHR-001: Создание диаграммы

**Описание:** Система должна позволять пользователям создавать диаграммы на основе выбранных данных таблицы.

**Роли:** Владелец, Редактор

**Предусловия:**
- Пользователь авторизован в системе
- Документ открыт для редактирования
- В таблице присутствуют данные для визуализации

**Основной сценарий:**
1. Пользователь выделяет диапазон ячеек с данными для визуализации
2. Пользователь открывает меню "Вставка" (Insert) и выбирает "Диаграмма" (Chart)
3. Система анализирует выбранные данные и автоматически предлагает подходящий тип диаграммы
4. Система создаёт диаграмму и размещает её поверх таблицы
5. Справа открывается панель "Редактор диаграмм" (Chart Editor)
6. Пользователь может изменить тип диаграммы во вкладке "Настройка" (Setup)
7. Пользователь нажимает вне диаграммы для завершения создания

**Альтернативные сценарии:**

*A1: Создание через панель инструментов*
1. Пользователь выделяет данные
2. Пользователь нажимает значок диаграммы на панели инструментов
3. Система создаёт диаграмму с автоматически подобранным типом

*A2: Создание без предварительного выбора данных*
1. Пользователь выбирает "Вставка" → "Диаграмма" без выделения данных
2. Система создаёт пустую диаграмму
3. Пользователь указывает диапазон данных в редакторе диаграмм

*A3: Создание из рекомендуемых диаграмм*
1. Система анализирует данные и предлагает несколько подходящих типов
2. Пользователь просматривает рекомендации
3. Пользователь выбирает наиболее подходящий вариант

**Бизнес-правила:**
- BR-001: Система автоматически определяет оптимальный тип диаграммы на основе структуры данных
- BR-002: Первая строка или столбец могут использоваться как заголовки (настраивается)
- BR-003: Диаграмма создаётся как плавающий объект поверх ячеек
- BR-004: При создании диаграммы автоматически применяются настройки по умолчанию

**Результат:** Создана диаграмма, визуализирующая выбранные данные

### FR-CHR-002: Типы диаграмм — линейные графики

**Описание:** Система должна поддерживать создание линейных диаграмм для отображения трендов и изменений данных во времени.

**Роли:** Владелец, Редактор

**Предусловия:**
- Данные содержат как минимум один ряд числовых значений
- Данные имеют хронологическую или последовательную структуру

**Основной сценарий:**
1. Пользователь создаёт диаграмму и выбирает тип "Линейный график" (Line chart)
2. Система отображает данные в виде точек, соединённых прямыми линиями
3. Горизонтальная ось отображает категории или временные метки
4. Вертикальная ось отображает числовые значения
5. Каждый ряд данных представлен отдельной линией

**Подтипы линейных диаграмм:**

| Подтип | Описание | Применение |
|--------|----------|------------|
| **Line chart** | Стандартный линейный график с прямыми линиями | Тренды, временные ряды |
| **Smooth line chart** | Линейный график с плавными кривыми линиями | Визуально привлекательное представление трендов |
| **Line chart with markers** | Линейный график с маркерами точек данных | Акцент на отдельных значениях |

**Альтернативные сценарии:**

*A1: Множественные ряды данных*
1. Данные содержат несколько столбцов с числовыми значениями
2. Система отображает каждый столбец как отдельную линию
3. Каждая линия имеет уникальный цвет
4. Легенда идентифицирует каждый ряд данных

*A2: Настройка маркеров*
1. Пользователь открывает раздел "Серия" (Series) в настройках
2. Пользователь включает отображение точек (Point shape)
3. Пользователь выбирает форму маркера: круг, квадрат, треугольник, ромб, звезда

**Бизнес-правила:**
- BR-005: Линии соединяют точки данных в порядке их следования
- BR-006: Пустые значения могут разрывать линию или интерполироваться
- BR-007: Толщина линии настраивается (по умолчанию 2px)
- BR-008: Цвет каждой линии можно настроить индивидуально

**Результат:** Создан линейный график, отображающий тренды данных

### FR-CHR-003: Типы диаграмм — столбчатые и линейчатые

**Описание:** Система должна поддерживать создание столбчатых (вертикальных) и линейчатых (горизонтальных) диаграмм для сравнения категорий.

**Роли:** Владелец, Редактор

**Предусловия:**
- Данные содержат категории и соответствующие числовые значения
- Пользователь имеет права редактирования

**Основной сценарий:**
1. Пользователь создаёт диаграмму и выбирает тип:
   - "Столбчатая диаграмма" (Column chart) — вертикальные столбцы
   - "Линейчатая диаграмма" (Bar chart) — горизонтальные столбцы
2. Система отображает категории по одной оси, значения — по другой
3. Каждая категория представлена столбцом пропорциональной высоты/длины

**Подтипы столбчатых/линейчатых диаграмм:**

| Подтип | Описание | Применение |
|--------|----------|------------|
| **Standard** | Отдельные столбцы для каждой категории | Сравнение категорий |
| **Stacked** | Столбцы с накоплением (части целого) | Структура данных по категориям |
| **100% Stacked** | Столбцы нормализованы до 100% | Процентное соотношение частей |

**Альтернативные сценарии:**

*A1: Группированные столбцы*
1. Данные содержат несколько рядов для каждой категории
2. Система размещает столбцы каждого ряда рядом друг с другом
3. Разные ряды отображаются разными цветами

*A2: Столбцы с накоплением (Stacked)*
1. Пользователь выбирает подтип "Stacked column chart"
2. Система размещает значения рядов друг на друге
3. Общая высота столбца показывает сумму всех рядов

*A3: 100% столбцы с накоплением*
1. Пользователь выбирает подтип "100% stacked column chart"
2. Все столбцы нормализуются до одинаковой высоты (100%)
3. Отображается процентное соотношение рядов

**Бизнес-правила:**
- BR-009: Ширина столбцов автоматически подстраивается под количество категорий
- BR-010: Интервал между столбцами настраивается
- BR-011: Отрицательные значения отображаются столбцами ниже/левее нулевой линии
- BR-012: Подписи данных могут отображаться внутри или снаружи столбцов

**Результат:** Создана столбчатая или линейчатая диаграмма для сравнения данных

### FR-CHR-004: Типы диаграмм — круговые и кольцевые

**Описание:** Система должна поддерживать создание круговых и кольцевых диаграмм для отображения долей от целого.

**Роли:** Владелец, Редактор

**Предусловия:**
- Данные представляют части одного целого
- Сумма всех значений имеет смысл как 100%

**Основной сценарий:**
1. Пользователь создаёт диаграмму и выбирает тип "Круговая диаграмма" (Pie chart)
2. Система отображает данные в виде секторов круга
3. Размер каждого сектора пропорционален значению
4. Секторы окрашены в разные цвета для различения категорий

**Подтипы круговых диаграмм:**

| Подтип | Описание | Применение |
|--------|----------|------------|
| **Pie chart** | Стандартная круговая диаграмма | Доли от целого (5-7 категорий) |
| **Doughnut chart** | Кольцевая диаграмма с пустым центром | Эстетичное отображение долей |
| **3D Pie chart** | Трёхмерная круговая диаграмма | Визуальный эффект объёма |

**Альтернативные сценарии:**

*A1: Выделение сектора*
1. Пользователь выбирает сектор для выделения
2. Сектор выдвигается из круга на заданное расстояние
3. Акцентирует внимание на конкретной категории

*A2: Отображение подписей*
1. Пользователь настраивает подписи секторов:
   - None — без подписей
   - Value — абсолютные значения
   - Percentage — процентные значения
   - Label — названия категорий
   - Value and percentage — оба значения

*A3: Настройка начального угла*
1. Пользователь задаёт угол начала первого сектора
2. Диаграмма поворачивается для оптимального отображения

**Бизнес-правила:**
- BR-013: Рекомендуется использовать не более 5-7 секторов для читаемости
- BR-014: Мелкие секторы (менее 5%) могут быть объединены в категорию "Другое"
- BR-015: Сумма всех секторов всегда составляет 100%
- BR-016: Радиус отверстия кольцевой диаграммы настраивается (0-100%)

**Результат:** Создана круговая или кольцевая диаграмма для отображения пропорций

### FR-CHR-005: Типы диаграмм — точечные (Scatter)

**Описание:** Система должна поддерживать создание точечных диаграмм для отображения корреляций между двумя переменными.

**Роли:** Владелец, Редактор

**Предусловия:**
- Данные содержат две числовые переменные для каждой точки
- Пользователь хочет исследовать взаимосвязь между переменными

**Основной сценарий:**
1. Пользователь создаёт диаграмму и выбирает тип "Точечная диаграмма" (Scatter chart)
2. Система отображает каждую запись как точку на координатной плоскости
3. Горизонтальная ось (X) представляет первую переменную
4. Вертикальная ось (Y) представляет вторую переменную
5. Положение точки определяется значениями обеих переменных

**Подтипы точечных диаграмм:**

| Подтип | Описание | Применение |
|--------|----------|------------|
| **Scatter chart** | Только точки | Распределение данных |
| **Scatter with lines** | Точки соединены линиями | Последовательность точек |
| **Bubble chart** | Точки с переменным размером | Три переменные (X, Y, размер) |

**Альтернативные сценарии:**

*A1: Добавление линии тренда*
1. Пользователь включает линию тренда (Trendline) в настройках серии
2. Система рассчитывает и отображает линию регрессии
3. Типы: линейная, полиномиальная, экспоненциальная, логарифмическая

*A2: Пузырьковая диаграмма (Bubble chart)*
1. Пользователь выбирает тип "Bubble chart"
2. Третий столбец данных определяет размер пузырька
3. Система масштабирует размер пузырьков пропорционально значениям

*A3: Цветовое кодирование по категориям*
1. Данные содержат столбец с категориями
2. Система окрашивает точки в соответствии с категорией
3. Легенда отображает соответствие цветов и категорий

**Бизнес-правила:**
- BR-017: Точечные диаграммы требуют минимум двух числовых столбцов
- BR-018: Линия тренда рассчитывается методом наименьших квадратов
- BR-019: Уравнение линии тренда может отображаться на диаграмме
- BR-020: Коэффициент R² показывает качество аппроксимации

**Результат:** Создана точечная диаграмма для анализа корреляций

### FR-CHR-006: Типы диаграмм — с областями (Area)

**Описание:** Система должна поддерживать создание диаграмм с областями для отображения кумулятивных данных и трендов.

**Роли:** Владелец, Редактор

**Предусловия:**
- Данные содержат временные ряды или последовательные категории
- Пользователь хочет подчеркнуть объём или накопление данных

**Основной сценарий:**
1. Пользователь создаёт диаграмму и выбирает тип "Диаграмма с областями" (Area chart)
2. Система отображает данные как линии с закрашенной областью под ними
3. Область между линией и осью X заполняется цветом
4. Несколько рядов данных могут накладываться друг на друга

**Подтипы диаграмм с областями:**

| Подтип | Описание | Применение |
|--------|----------|------------|
| **Area chart** | Стандартная диаграмма с областями | Тренды с акцентом на объём |
| **Stacked area chart** | Области накладываются друг на друга | Кумулятивные данные |
| **100% stacked area** | Области нормализованы до 100% | Процентное соотношение во времени |
| **Stepped area chart** | Ступенчатая диаграмма с областями | Дискретные изменения |

**Альтернативные сценарии:**

*A1: Прозрачность областей*
1. При перекрытии нескольких рядов области частично прозрачны
2. Пользователь может настроить уровень прозрачности
3. Позволяет видеть все ряды данных одновременно

*A2: Ступенчатая диаграмма (Stepped)*
1. Пользователь выбирает "Stepped area chart"
2. Линии соединяют точки горизонтальными и вертикальными сегментами
3. Подходит для данных, изменяющихся дискретно

**Бизнес-правила:**
- BR-021: Области отображаются в порядке следования рядов данных
- BR-022: Stacked area показывает сумму всех рядов в каждой точке
- BR-023: Области могут иметь прозрачность для наложения
- BR-024: Цвет области соответствует цвету линии границы

**Результат:** Создана диаграмма с областями для визуализации кумулятивных данных

### FR-CHR-007: Типы диаграмм — гистограмма

**Описание:** Система должна поддерживать создание гистограмм для отображения распределения данных по интервалам (bins).

**Роли:** Владелец, Редактор

**Предусловия:**
- Данные содержат набор числовых значений
- Пользователь хочет исследовать распределение данных

**Основной сценарий:**
1. Пользователь создаёт диаграмму и выбирает тип "Гистограмма" (Histogram)
2. Система автоматически группирует значения в интервалы (bins)
3. Высота каждого столбца показывает количество значений в интервале
4. Горизонтальная ось отображает диапазоны значений
5. Вертикальная ось отображает частоту (количество)

**Альтернативные сценарии:**

*A1: Настройка количества интервалов*
1. Пользователь открывает настройки гистограммы
2. Пользователь указывает размер корзины (Bucket size)
3. Система пересчитывает распределение

*A2: Настройка диапазона*
1. Пользователь указывает минимальное и максимальное значения
2. Система исключает данные за пределами диапазона
3. Интервалы распределяются в указанном диапазоне

*A3: Отображение выбросов*
1. Пользователь включает отображение выбросов (Outliers)
2. Система показывает крайние значения отдельно
3. Позволяет анализировать аномалии в данных

**Бизнес-правила:**
- BR-025: Гистограмма отличается от столбчатой диаграммы: столбцы примыкают друг к другу
- BR-026: Количество интервалов автоматически рассчитывается или задаётся вручную
- BR-027: Ширина всех интервалов одинакова
- BR-028: Гистограмма показывает распределение (нормальное, скошенное и т.д.)

**Результат:** Создана гистограмма для анализа распределения данных

### FR-CHR-008: Типы диаграмм — географические карты (Geo Chart)

**Описание:** Система должна поддерживать создание географических диаграмм для отображения данных на карте.

**Роли:** Владелец, Редактор

**Предусловия:**
- Данные содержат географические идентификаторы (названия стран, регионов, ISO-коды)
- Данные содержат числовые значения для каждого региона

**Основной сценарий:**

1. Пользователь вводит формулу:

3. Каждое значение представлено сегментом пропорциональной длины
4. Общая длина составляет 100% ширины ячейки

**Параметры столбчатого спарклайна:**

| Параметр | Описание | Пример |
|----------|----------|--------|
| `charttype` | Тип диаграммы | "bar" |
| `max` | Максимальное значение шкалы | 100 |
| `color1` | Цвет первого сегмента | "green" |
| `color2` | Цвет второго сегмента | "red" |

**Альтернативные сценарии:**

*A1: Индикатор прогресса*
```
=SPARKLINE(B1, {"charttype","bar"; "max",1; "color1","green"})
```
1. B1 содержит значение от 0 до 1 (процент выполнения)
2. max=1 устанавливает шкалу до 100%
3. Полоса заполняется пропорционально значению

```
=SPARKLINE({B1, 1-B1}, {"charttype","bar"; "color1","green"; "color2","lightgrey"})
```
1. Первый сегмент (зелёный) — выполнено
2. Второй сегмент (серый) — осталось

*A3: Условное цветовое кодирование*
```
=SPARKLINE(B1, {"charttype","bar"; "max",1; "color1",IF(B1>0.7,"green",IF(B1>0.5,"yellow","red"))})
```
1. Цвет зависит от значения прогресса
2. Зелёный если >70%, жёлтый если >50%, иначе красный

**Бизнес-правила:**
- BR-141: Bar спарклайн показывает пропорции частей целого
- BR-142: Параметр max определяет 100% шкалы
- BR-143: Несколько значений отображаются как сегменты
- BR-144: Без указания max система использует сумму значений

*A1: Отслеживание побед/поражений*

```
=SPARKLINE({1,-1,1,1,-1}, {"charttype","winloss"; "color","green"; "negcolor","red"})
```
1. 1 представляет победу (зелёный вверх)
2. -1 представляет поражение (красный вниз)

*A2: На основе формулы*

```
=SPARKLINE(ArrayFormula(IF(B1:F1>C$1,1,-1)), {"charttype","winloss"})
```

2. Выше цели = выигрыш, ниже = проигрыш

- Пользователь имеет права редактирования

   ```
   =SPARKLINE(B2, {"charttype","bar"; "max",1; "color1","#4CAF50"})
   ```
3. Система отображает горизонтальную полосу
4. Заполнение пропорционально значению прогресса

**Альтернативные сценарии:**

*A1: Двухцветный прогресс-бар*

1. Пользователь форматирует ячейку справа от спарклайна

3. Визуальный и числовой индикатор вместе

- BR-153: max=1 устанавливает шкалу для процентных значений (0-1)
- BR-154: Для значений 0-100 используйте max=100

**Параметры цветовой шкалы:**

| Параметр | Описание | Примеры значений |
|----------|----------|------------------|

| Max color | Цвет для максимальных значений | Зелёный, Синий |

1. Пользователь выбирает белый для Minpoint
2. Пользователь выбирает насыщенный цвет для Maxpoint
3. Создаётся градиент от белого к цвету

*A2: Дивергентная тепловая карта*
1. Пользователь добавляет Midpoint
2. Настраивает среднее значение (например, 0 или целевое)
3. Minpoint — один цвет (например, красный)
4. Midpoint — нейтральный (например, белый)
5. Maxpoint — другой цвет (например, зелёный)
6. Отклонения в обе стороны визуально различимы

*A3: Тепловая карта с фиксированными порогами*
1. Пользователь устанавливает Minpoint как Number (например, 0)
2. Пользователь устанавливает Maxpoint как Number (например, 100)
3. Значения за пределами используют крайние цвета
4. Шкала не зависит от фактических данных

**Бизнес-правила:**
- BR-157: Тепловая карта применяется ко всему выделенному диапазону
- BR-158: Цвета интерполируются между точками

- BR-160: Тепловая карта обновляется при изменении данных

### FR-CHR-041: Пользовательская тепловая карта с формулами

**Описание:** Система должна позволять создавать настраиваемые тепловые карты с помощью условного форматирования на основе формул.

**Роли:** Владелец, Редактор

**Предусловия:**
- Требуется сложная логика окрашивания
- Стандартная цветовая шкала недостаточна

**Основной сценарий:**
1. Пользователь выделяет диапазон данных
2. Открывает "Формат" → "Условное форматирование"
3. Выбирает "Пользовательская формула" (Custom formula is)
4. Создаёт несколько правил с разными условиями и цветами
5. Каждое правило применяет свой цвет при выполнении условия

**Альтернативные сценарии:**

*A1: Трёхцветная схема*
1. Правило 1: `=$B1<50` — красный фон
2. Правило 2: `=AND($B1>=50,$B1<80)` — жёлтый фон

1. Правило: `=$B1>AVERAGE($B$1:$B$100)` — зелёный

*A3: Выделение строк по условию*
1. Формула применяется ко всей строке
2. Пример: `=$C1="Critical"` — красный фон для всей строки
3. Создаёт визуальный акцент на важных записях

**Бизнес-правила:**
- BR-161: Правила применяются в порядке приоритета
- BR-162: Первое сработавшее правило определяет цвет
- BR-163: Формулы должны использовать относительные ссылки для строк
- BR-164: Условное форматирование не влияет на фактические данные
