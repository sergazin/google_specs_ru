# Версионность и история изменений

## Описание

Модуль версионности и истории изменений в Google Drive обеспечивает автоматическое сохранение версий файлов, позволяя пользователям отслеживать изменения, просматривать историю, восстанавливать предыдущие версии и управлять жизненным циклом версий. Система автоматически создает версии при каждом изменении файла, сохраняет информацию о том, кто и когда внес изменения, позволяет именовать важные версии, сравнивать версии между собой и управлять сроком хранения версий в зависимости от типа аккаунта. Версионность является критически важной функцией для совместной работы, восстановления после ошибок и соблюдения требований аудита.

## Роли пользователей

- **Владелец файла (Owner)** - создатель файла, имеет полный доступ к истории версий, может восстанавливать, именовать, удалять версии, управлять настройками версионности
- **Редактор (Editor)** - может редактировать файл и создавать новые версии, просматривать историю, восстанавливать версии
- **Комментатор (Commenter)** - может просматривать историю версий, но не может создавать или восстанавливать версии
- **Читатель (Viewer)** - может просматривать историю версий в режиме только для чтения
- **Администратор Google Workspace** - может управлять политиками хранения версий на уровне организации, устанавливать сроки хранения, просматривать версии всех файлов домена
- **Система Google Drive** - автоматически создает версии, применяет политики хранения, очищает устаревшие версии

## Функциональные требования

### FR-VERSION-001: Автоматическое создание версии при изменении файла

**Описание:** Система автоматически создает новую версию файла при каждом сохранении изменений для обеспечения истории изменений.

**Роли:** Владелец файла, Редактор, Система Google Drive

**Предусловия:**
- Файл существует в Google Drive
- Пользователь имеет права на редактирование файла
- Файл поддерживает версионность (документы, таблицы, презентации, загруженные файлы)

**Основной сценарий:**
1. Пользователь открывает файл для редактирования в Google Drive
2. Пользователь вносит изменения в содержимое файла
3. Пользователь сохраняет изменения (явно или автоматически)
4. Система определяет, что контент изменился по сравнению с предыдущей версией
5. Система создает новую версию файла:
   - Сохраняет текущее содержимое как новую версию
   - Присваивает версии уникальный идентификатор
   - Фиксирует временную метку изменения
   - Сохраняет информацию об авторе изменения (user_id, имя, email)
   - Связывает версию с файлом через file_id
6. Система сохраняет предыдущую версию в истории версий
7. Новая версия становится текущей активной версией файла
8. Система обновляет метаданные файла (modified_time, modifying_user)
9. Счетчик версий увеличивается на единицу

**Альтернативные сценарии:**
- Сценарий А (Изменения отсутствуют): Если контент не изменился, новая версия не создается
- Сценарий Б (Google Docs/Sheets/Slides): Версии создаются автоматически при автосохранении (каждые несколько секунд активного редактирования)
- Сценарий В (Загруженный файл): При загрузке новой версии через "Manage versions" или перезаписи файла создается новая версия
- Сценарий Г (Множественные быстрые изменения): Система может объединять версии, созданные в течение короткого периода (несколько минут) в одну версию
- Сценарий Д (Офлайн редактирование): При восстановлении соединения версия создается с меткой времени момента синхронизации
- Сценарий Е (Конфликт версий): При одновременном редактировании создаются конфликтующие версии, которые требуют разрешения

**Бизнес-правила:**
- BR-001: Новая версия создается при каждом значимом изменении содержимого файла
- BR-002: Для Google Docs/Sheets/Slides версии создаются автоматически в процессе работы (автосохранение)
- BR-003: Для загруженных файлов (PDF, Office, изображения) версии создаются при явной загрузке новой версии
- BR-004: Минимальный интервал между автоматическими версиями - несколько секунд активного редактирования
- BR-005: Версии содержат полный снимок содержимого файла на момент сохранения
- BR-006: Каждая версия неизменяема (immutable) после создания
- BR-007: Система сохраняет до 100 версий для загруженных файлов (non-Google форматы)
- BR-008: Для Google Docs/Sheets/Slides сохраняются все версии без ограничения количества
- BR-009: Версии создаются только при наличии фактических изменений контента
- BR-010: Переименование файла не создает новую версию (только изменение содержимого)

**Результат:** Новая версия файла создана и сохранена в истории версий, предыдущая версия доступна для восстановления

### FR-VERSION-002: Просмотр истории версий файла

**Описание:** Пользователь может просмотреть полную историю всех версий файла с информацией о времени изменения и авторах.

**Роли:** Владелец файла, Редактор, Комментатор, Читатель

**Предусловия:**
- Файл существует в Google Drive
- Пользователь имеет доступ к файлу (минимум права на просмотр)
- Файл имеет хотя бы одну версию в истории

**Основной сценарий:**
1. Пользователь открывает файл в Google Drive
2. Для Google Docs/Sheets/Slides:
   - Пользователь нажимает "Файл" > "История версий" > "Смотреть историю версий"
   - Или использует горячую клавишу Ctrl+Alt+Shift+H (Cmd+Option+Shift+H на Mac)
3. Для других типов файлов:
   - Пользователь кликает правой кнопкой мыши на файле
   - Выбирает "Управление версиями" (Manage versions)
4. Система открывает панель истории версий справа от документа или отдельное окно
5. Система отображает список всех версий в обратном хронологическом порядке:
   - Дата и точное время создания версии
   - Имя и аватар пользователя, создавшего версию
   - Название версии (если присвоено)
   - Размер изменений (для некоторых типов файлов)
   - Индикатор текущей версии
6. Пользователь может прокручивать список версий
7. Система может группировать версии по времени:
   - "Сегодня" с точным временем
   - "Вчера" с точным временем
   - Дата с временем для более старых версий
   - "Именованные версии" в отдельной секции
8. Для Google Docs система может показывать цветовое кодирование изменений разных пользователей
9. Пользователь может фильтровать версии:
   - Только именованные версии
   - Версии конкретного пользователя
   - Версии за определенный период

**Альтернативные сценарии:**
- Сценарий А (Пустая история): Если версий нет, система показывает "История версий пуста"
- Сценарий Б (Большое количество версий): Система использует ленивую загрузку (lazy loading) для отображения старых версий
- Сценарий В (Ограниченные права доступа): Читатели и комментаторы видят историю в режиме только для чтения
- Сценарий Г (Удаленная версия): Удаленные версии не отображаются в истории
- Сценарий Д (Мобильное приложение): На мобильных устройствах интерфейс истории версий адаптирован для сенсорного управления
- Сценарий Е (Офлайн режим): В офлайн режиме доступны только кешированные версии

**Бизнес-правила:**
- BR-011: История версий доступна для всех пользователей с доступом к файлу
- BR-012: Версии отображаются в обратном хронологическом порядке (новые сверху)
- BR-013: Для Google Docs/Sheets/Slides отображаются все версии без ограничений
- BR-014: Для загруженных файлов отображаются до 100 последних версий или версии за последние 30 дней (что больше)
- BR-015: Именованные версии всегда отображаются независимо от срока хранения
- BR-016: Каждая версия показывает автора и временную метку
- BR-017: Текущая активная версия помечается специальным индикатором
- BR-018: Система группирует версии по временным периодам для удобства навигации
- BR-019: Читатели и комментаторы могут только просматривать историю, но не изменять версии

**Результат:** Пользователь просмотрел полную историю версий файла с информацией об изменениях

### FR-VERSION-003: Просмотр содержимого конкретной версии

**Описание:** Пользователь может открыть и просмотреть содержимое любой предыдущей версии файла без восстановления.

**Роли:** Владелец файла, Редактор, Комментатор, Читатель

**Предусловия:**
- Файл имеет историю версий
- Пользователь открыл панель истории версий
- Версия существует и доступна для просмотра

**Основной сценарий:**
1. Пользователь находится в панели истории версий
2. Пользователь выбирает интересующую версию из списка (кликает на нее)
3. Система загружает содержимое выбранной версии
4. Для Google Docs/Sheets/Slides:
   - Система отображает предпросмотр версии в режиме чтения
   - Показывает документ в том виде, как он выглядел на момент создания версии
   - Выделяет изменения по сравнению с предыдущей версией (опционально)
   - Разными цветами отмечает правки разных пользователей
5. Для загруженных файлов:
   - Система показывает превью версии (если возможно)
   - Или предлагает скачать версию для просмотра
6. В верхней части интерфейса отображается информация:
   - "Версия от [дата время]"
   - "Автор: [имя пользователя]"
   - "Это не текущая версия" (если просматривается старая версия)
7. Пользователь может навигировать между версиями:
   - Стрелки "Предыдущая версия" / "Следующая версия"
   - Слайдер для быстрой навигации по времени
8. Пользователь может сравнивать версии визуально
9. Пользователь может вернуться к текущей версии в любой момент

**Альтернативные сценарии:**
- Сценарий А (Версия повреждена): Если версия недоступна, система показывает "Невозможно загрузить эту версию"
- Сценарий Б (Большой файл): Для больших файлов загрузка может занять время, показывается индикатор загрузки
- Сценарий В (Формат не поддерживает превью): Система предлагает скачать версию для просмотра в стороннем приложении
- Сценарий Г (Режим сравнения): Пользователь может включить режим подсветки изменений между версиями
- Сценарий Д (Офлайн режим): Неактивные версии недоступны для просмотра в офлайн режиме

**Бизнес-правила:**
- BR-020: Просмотр версий доступен всем пользователям с доступом к файлу
- BR-021: Просмотр версии не изменяет текущую активную версию
- BR-022: Для Google Docs/Sheets/Slides версии открываются в режиме чтения с подсветкой изменений
- BR-023: Для загруженных файлов доступен превью или скачивание версии
- BR-024: Система показывает метаданные версии (автор, время, размер)
- BR-025: Можно навигировать между версиями без возврата к списку
- BR-026: Просмотр не создает новую версию
- BR-027: Контент версии неизменяем и соответствует состоянию на момент создания

**Результат:** Пользователь просмотрел содержимое выбранной версии файла

### FR-VERSION-004: Восстановление предыдущей версии файла

**Описание:** Пользователь может восстановить файл к состоянию одной из предыдущих версий, сделав ее текущей активной версией.

**Роли:** Владелец файла, Редактор

**Предусловия:**
- Файл имеет историю версий
- Пользователь имеет права на редактирование файла
- Пользователь находится в режиме просмотра истории версий
- Выбрана версия для восстановления

**Основной сценарий:**
1. Пользователь открывает историю версий файла (FR-VERSION-002)
2. Пользователь просматривает и выбирает версию для восстановления (FR-VERSION-003)
3. Пользователь нажимает кнопку "Восстановить эту версию" (Restore this version)
4. Система показывает диалог подтверждения:
   - "Восстановить эту версию?"
   - "Текущая версия будет сохранена в истории"
   - "Вы можете отменить это действие позже"
   - Кнопки: "Восстановить" и "Отмена"
5. Пользователь подтверждает восстановление
6. Система выполняет операцию восстановления:
   - Создает копию выбранной версии
   - Сохраняет текущую версию в историю (как точку перед восстановлением)
   - Делает восстановленную версию текущей активной версией
   - Обновляет метаданные файла (modified_time, modifying_user)
7. Система создает новую запись в истории версий с пометкой:
   - "Восстановлено из версии от [дата]"
   - "Восстановил: [имя пользователя]"
   - "Время восстановления: [дата время]"
8. Система закрывает панель истории версий
9. Пользователь видит файл в восстановленном состоянии
10. Система отправляет уведомление всем участникам о восстановлении версии (если настроено)

**Альтернативные сценарии:**
- Сценарий А (Отмена восстановления): Пользователь нажимает "Отмена", восстановление не происходит
- Сценарий Б (Конфликт версий): Если файл редактируется другим пользователем, система блокирует восстановление до завершения редактирования
- Сценарий В (Недостаточно прав): Если пользователь не имеет прав редактора, кнопка "Восстановить" недоступна
- Сценарий Г (Немедленное повторное восстановление): Пользователь может восстановить предыдущую версию, чтобы отменить восстановление
- Сценарий Д (Google Docs): При восстановлении сохраняются комментарии и предложения текущей версии
- Сценарий Е (Загруженный файл): Для загруженных файлов восстановление заменяет текущий файл содержимым из выбранной версии

**Бизнес-правила:**
- BR-028: Восстановление версии доступно только пользователям с правами редактирования
- BR-029: При восстановлении текущая версия автоматически сохраняется в истории
- BR-030: Восстановленная версия создает новую запись в истории с пометкой о восстановлении
- BR-031: Восстановление можно отменить повторным восстановлением предыдущей версии
- BR-032: Все участники с доступом к файлу получают уведомление о восстановлении (опционально)
- BR-033: Для Google Docs/Sheets/Slides восстановление происходит мгновенно
- BR-034: Для загруженных файлов восстановление может занять время в зависимости от размера
- BR-035: Восстановление версии не удаляет историю версий
- BR-036: Метаданные восстановленной версии обновляются (время изменения, автор последнего изменения)
- BR-037: Счетчик версий увеличивается на единицу при восстановлении

**Результат:** Файл восстановлен к состоянию выбранной версии, текущая версия сохранена в истории

### FR-VERSION-005: Создание именованной версии (Named Version)

**Описание:** Пользователь может присвоить имя конкретной версии для обозначения важных вех, релизов или контрольных точек.

**Роли:** Владелец файла, Редактор

**Предусловия:**
- Файл существует и имеет версии
- Пользователь имеет права на редактирование файла
- Пользователь находится в панели истории версий

**Основной сценарий:**
1. Пользователь открывает историю версий файла
2. Пользователь находит версию, которую хочет именовать
3. Для Google Docs/Sheets/Slides:
   - Пользователь нажимает на иконку "три точки" (⋮) рядом с версией
   - Выбирает "Назвать эту версию" (Name this version)
4. Для загруженных файлов:
   - Функция именования может быть недоступна или ограничена
5. Система открывает диалог для ввода имени версии:
   - Поле "Название версии" (до 200 символов)
   - Поле "Описание" (опционально, до 500 символов)
   - Кнопки "Сохранить" и "Отмена"
6. Пользователь вводит осмысленное название версии, например:
   - "Финальная версия для публикации"
   - "Версия после согласования с клиентом"
   - "v1.0 - первый релиз"
   - "Версия перед редизайном"
7. Пользователь опционально добавляет описание
8. Пользователь нажимает "Сохранить"
9. Система сохраняет имя и описание версии
10. Именованная версия отображается в истории с выделением:
    - Отображается название версии вместо обычной даты/времени
    - Имеет специальный значок или метку (например, звездочку ⭐)
    - Показывается в верхней части списка или в отдельной секции "Именованные версии"
11. Система помечает версию как "Сохранить навсегда" (Keep forever)
12. Именованная версия защищена от автоматического удаления при очистке старых версий

**Альтернативные сценарии:**
- Сценарий А (Редактирование имени): Пользователь может изменить название и описание версии позже
- Сценарий Б (Удаление имени): Пользователь может удалить имя, версия становится обычной (но остается помеченной "Сохранить навсегда")
- Сценарий В (Дублирующиеся имена): Система позволяет создавать версии с одинаковыми именами (нет проверки уникальности)

3. Система применяет правила хранения версий:
   - **Для загруженных файлов (non-Google форматы):**

   - Превышают лимит 100 версий (для загруженных файлов)
5. Система удаляет устаревшие версии:

   - Освобождает занимаемое пространство в квоте
6. Система сохраняет минимальную историю:
   - Текущая версия
   - Именованные версии
   - Версии с меткой "Сохранить навсегда"
   - Последние версии за 30 дней
7. Система обновляет счетчики использования хранилища
8. Пользователи не получают уведомлений об автоматической очистке версий

- Сценарий В (Превышение квоты): При превышении квоты хранилища пользователь получает уведомление об очистке старых версий
- Сценарий Г (Ручная очистка): Пользователь может вручную удалить версии до истечения 30 дней
- Сценарий Д (Восстановление удаленных версий): Удаленные версии не подлежат восстановлению
- Сценарий Е (Google Workspace политики): Администраторы могут установить срок хранения отличный от 30 дней

**Бизнес-правила:**
- BR-068: Для загруженных файлов хранятся до 100 версий ИЛИ версии за последние 30 дней
- BR-069: Для Google Docs/Sheets/Slides хранятся все версии (если не установлены организационные политики)
- BR-070: Версии с меткой "Сохранить навсегда" никогда не удаляются автоматически
- BR-071: Именованные версии никогда не удаляются автоматически
- BR-072: Текущая активная версия всегда сохраняется
- BR-073: Очистка происходит автоматически без уведомления пользователей
- BR-074: Удаленные версии не подлежат восстановлению
- BR-075: Google Workspace администраторы могут устанавливать кастомные политики через Google Vault
- BR-076: Срок хранения по умолчанию: 30 дней для неименованных версий
- BR-077: При превышении лимита 100 версий удаляются самые старые неименованные версии
- BR-078: Версии, созданные в течение последних 30 дней, защищены от удаления независимо от количества
- BR-079: Хранение версий учитывается в общей квоте Google Drive

### FR-VERSION-010: Загрузка новой версии файла (Upload New Version)

**Описание:** Пользователь может загрузить новую версию файла, заменив текущую версию при сохранении истории предыдущих версий.

**Роли:** Владелец файла, Редактор

- Файл существует в Google Drive
- Пользователь имеет права на редактирование файла
- Файл не является Google Docs/Sheets/Slides (для них используется онлайн-редактирование)
- У пользователя есть новая версия файла на локальном устройстве

1. Пользователь находит файл в Google Drive
2. Пользователь кликает правой кнопкой мыши на файле
3. Пользователь выбирает "Управление версиями" (Manage versions)
4. Система открывает диалог управления версиями:
   - Список существующих версий с датами и авторами
   - Размер каждой версии
   - Кнопка "Загрузить новую версию" (Upload new version)

    - Создает новую запись в истории версий

    - modified_time: текущее время
    - modifying_user: текущий пользователь
    - size: размер нового файла
    - version: номер версии увеличивается

- Пользователь имеет доступ к файлу

- Сценарий Ж (Запрет на скачивание): Если владелец запретил скачивание, функция недоступна

**Бизнес-правила:**

- BR-101: Для Google Docs/Sheets/Slides пользователь выбирает формат экспорта при скачивании

- BR-103: Скачивание версии не изменяет текущую активную версию

### FR-VERSION-012: Отслеживание изменений с указанием авторов

**Описание:** Система отслеживает и отображает информацию о том, кто и когда внес изменения в каждой версии файла.

**Роли:** Владелец файла, Редактор, Комментатор, Читатель, Система Google Drive

**Предусловия:**
- Файл существует и имеет историю версий
- Пользователь имеет доступ к файлу
- Файл редактировался разными пользователями

**Основной сценарий:**
1. Система автоматически отслеживает изменения при каждом редактировании
2. При создании новой версии система записывает:
   - **user_id** - уникальный идентификатор автора
   - **user_name** - полное имя пользователя
   - **user_email** - email автора
   - **user_photo** - аватар пользователя
   - **modified_time** - точная временная метка изменения
   - **modification_type** - тип изменения (edit, upload, restore)
3. Пользователь открывает историю версий
4. Система отображает для каждой версии:
   - Аватар и имя автора изменения
   - Дату и точное время (например, "15 декабря 2025, 14:32")
   - Тип действия ("отредактировал", "загрузил новую версию", "восстановил версию")
5. Для Google Docs/Sheets/Slides дополнительно:
   - При просмотре версии система выделяет изменения разными цветами для разных авторов
   - Каждый автор имеет уникальный цвет подсветки
   - При наведении на выделенный текст показывается имя автора и время изменения
6. Пользователь может фильтровать версии по автору:
   - Система показывает список всех участников редактирования
   - Пользователь выбирает автора
   - Отображаются только версии, созданные этим пользователем
7. Пользователь может просмотреть детальную информацию об авторе:
   - Кликает на аватар или имя
   - Система показывает профиль пользователя (если доступно)
8. Для совместного редактирования система показывает:
   - Кто в данный момент редактирует файл
   - Где находится курсор каждого редактора
   - Имя редактора рядом с его курсором

**Альтернативные сценарии:**
- Сценарий А (Анонимный пользователь): Если файл редактировался анонимным пользователем (через ссылку), показывается "Анонимный пользователь"
- Сценарий Б (Удаленный пользователь): Если аккаунт автора удален, показывается "Удаленный пользователь"
- Сценарий В (Множественные редакторы в одной версии): Для Google Docs несколько пользователей могут внести изменения в одной версии, все авторы отображаются
- Сценарий Г (Автоматические изменения): Изменения, внесенные ботами или скриптами, помечаются соответствующим образом
- Сценарий Д (Часовой пояс): Время отображается в часовом поясе пользователя, просматривающего историю
- Сценарий Е (Групповое редактирование): При одновременном редактировании несколькими пользователями система показывает всех участников

**Бизнес-правила:**
- BR-109: Каждая версия содержит информацию об авторе изменения
- BR-110: Система автоматически фиксирует временную метку каждого изменения
- BR-111: Для Google Docs/Sheets/Slides изменения разных авторов выделяются разными цветами
- BR-112: Информация об авторе неизменяема и хранится с версией
- BR-113: Пользователи могут фильтровать версии по автору
- BR-114: При совместном редактировании отображаются все активные редакторы в реальном времени
- BR-115: Анонимные пользователи (редактирование через ссылку) помечаются как "Анонимный"
- BR-116: Время отображается в часовом поясе просматривающего пользователя
- BR-117: Для загруженных файлов автором версии считается пользователь, загрузивший файл
- BR-118: История авторства доступна всем пользователям с доступом к файлу
- BR-119: При восстановлении версии автором новой версии считается пользователь, выполнивший восстановление

**Результат:** Пользователь просмотрел детальную информацию о том, кто и когда вносил изменения в файл

- BR-120: Функция "Только именованные версии" доступна только для Google Workspace Business Standard и выше
- BR-121: Фильтр работает только для Google Docs/Sheets/Slides

- BR-123: Версии с меткой "Сохранить навсегда" также могут отображаться в фильтре

- BR-127: Фильтр помогает быстро находить важные контрольные точки в длинной истории версий

### FR-VERSION-014: Политики хранения версий для Google Workspace (Google Vault)

**Описание:** Администраторы Google Workspace могут устанавливать организационные политики хранения версий для соблюдения требований аудита и комплаенса.

**Роли:** Администратор Google Workspace, Система Google Drive

**Предусловия:**
- Организация использует Google Workspace
- Администратор имеет доступ к Google Vault
- Настроена лицензия Google Vault для организации

**Основной сценарий:**
1. Администратор входит в консоль администратора Google Workspace
2. Администратор переходит в раздел Google Vault
3. Администратор выбирает "Правила хранения" (Retention Rules)
4. Администратор нажимает "Создать правило хранения"
5. Система открывает мастер создания правила:
   - Выбор сервиса: Google Drive
   - Выбор организационного подразделения или всей организации
   - Выбор типа данных: "Файлы и версии"
6. Администратор настраивает срок хранения версий:
   - **Сохранять версии в течение**: [количество] дней/месяцев/лет
   - **Минимальный срок хранения**: версии не могут быть удалены до истечения срока
   - **Максимальный срок хранения**: версии автоматически удаляются после истечения срока
7. Администратор настраивает исключения:
   - Файлы с определенными метками
   - Файлы в определенных папках
   - Файлы определенных пользователей
8. Администратор настраивает действия после истечения срока:
   - Автоматическое удаление версий
   - Перемещение в архив
   - Уведомление администратора
9. Администратор сохраняет правило хранения
10. Система применяет правило ко всем файлам в области действия:
    - Версии старше указанного срока удаляются (или архивируются)
    - Версии младше указанного срока защищены от удаления
    - Новые версии автоматически подпадают под правило
11. Система применяет правила в соответствии с расписанием:
    - Ежедневно проверяет файлы на соответствие правилам
    - Удаляет или архивирует версии согласно политике
    - Ведет логи применения правил для аудита
12. Администратор может просматривать отчеты о применении правил:
    - Количество удаленных версий
    - Объем освобожденного пространства
    - Файлы, подпадающие под правило

**Альтернативные сценарии:**
- Сценарий А (Конфликт правил): Если применяются несколько правил, приоритет имеет правило с большим сроком хранения
- Сценарий Б (Судебный запрет): При установке судебного запроса (Litigation Hold) все версии сохраняются независимо от правил
- Сценарий В (Экспорт версий для аудита): Администратор может экспортировать версии для расследования или аудита
- Сценарий Г (Изменение правила): При изменении правила новые сроки применяются к существующим версиям
- Сценарий Д (Отключение правила): При отключении правила версии возвращаются к стандартной политике хранения
- Сценарий Е (Версии важных файлов): Администратор может исключить критически важные файлы из автоматического удаления

**Бизнес-правила:**
- BR-128: Google Vault доступен для Google Workspace Business Plus, Enterprise, Education Fundamentals и выше
- BR-129: Правила хранения применяются на уровне организации или организационного подразделения
- BR-130: Минимальный срок хранения защищает версии от преждевременного удаления
- BR-131: Максимальный срок хранения автоматически удаляет старые версии для соблюдения политик
- BR-132: Судебный запрос (Litigation Hold) имеет приоритет над правилами хранения
- BR-133: При конфликте правил применяется самый длительный срок хранения
- BR-134: Правила применяются ежедневно в автоматическом режиме
- BR-135: Администраторы могут экспортировать версии для аудита и расследований
- BR-136: Удаленные по правилам версии не подлежат восстановлению
- BR-137: Именованные версии и версии с меткой "Сохранить навсегда" могут быть исключены из правил
- BR-138: Правила хранения учитывают требования регуляторов (GDPR, HIPAA, SOX и т.д.)

**Результат:** Организационная политика хранения версий установлена и автоматически применяется ко всем файлам

2. Система определяет список пользователей для уведомления:
   - Владелец файла
   - Пользователи с доступом к файлу (редакторы, комментаторы)
   - Пользователи, подписанные на уведомления для папки
3. Система генерирует уведомление с информацией:
   - Имя пользователя, выполнившего действие
   - Название файла со ссылкой
   - Тип действия (восстановлено, именовано, удалено)
   - Дата и время действия
   - Детали (например, из какой версии восстановлено)
4. Система отправляет уведомления через выбранные каналы:
   - Email уведомление на адрес пользователя
   - Push-уведомление в мобильном приложении Google Drive
   - Уведомление в веб-интерфейсе (колокольчик)
5. Пользователь получает уведомление:
   - Для email: "Имя Пользователя восстановил файл 'Название' к версии от [дата]"
   - Для push: "Файл 'Название' изменен: восстановлена версия от [дата]"
6. Пользователь может кликнуть на уведомление:
   - Система открывает файл в Google Drive
   - Опционально открывает историю версий
7. Для именованных версий уведомление содержит:
   - "Имя Пользователя создал именованную версию 'Название версии' для файла 'Название файла'"
   - Ссылка на файл и версию
8. Пользователь может настроить предпочтения уведомлений:
   - Отключить уведомления для конкретного файла
   - Настроить типы событий, о которых получать уведомления
   - Выбрать каналы уведомлений (email, push, веб)

**Альтернативные сценарии:**
- Сценарий А (Уведомления отключены): Если пользователь отключил уведомления, они не отправляются
- Сценарий Б (Массовые изменения): При множественных изменениях за короткий период система объединяет уведомления
- Сценарий В (Критическое восстановление): При восстановлении очень старой версии уведомление помечается как важное
- Сценарий Г (Анонимное редактирование): Если изменение внесено анонимным пользователем, уведомление содержит "Анонимный пользователь"
- Сценарий Д (Автоматические действия): Действия, выполненные скриптами или ботами, помечаются соответствующим образом
- Сценарий Е (Настройка частоты): Пользователь может выбрать получение дайджеста уведомлений (раз в день) вместо мгновенных

**Бизнес-правила:**
- BR-139: Уведомления отправляются всем пользователям с доступом к файлу
- BR-140: Уведомления можно отключить на уровне файла, папки или аккаунта
- BR-141: Восстановление версии всегда генерирует уведомление
- BR-142: Создание именованной версии генерирует уведомление (опционально)
- BR-143: Обычное редактирование не генерирует уведомление о версиях (только о редактировании)
- BR-144: Пользователь может настроить каналы уведомлений (email, push, веб)
- BR-145: При массовых изменениях система объединяет уведомления для снижения спама
- BR-146: Уведомления содержат прямую ссылку на файл и историю версий
- BR-147: Анонимные пользователи отображаются как "Анонимный" в уведомлениях
- BR-148: Администраторы могут отключить уведомления о версиях на уровне организации

**Результат:** Пользователи получили уведомления о важных событиях связанных с версиями файла

### FR-VERSION-016: Восстановление удаленного файла с версиями

**Описание:** При восстановлении удаленного файла из корзины восстанавливается вся история версий файла.

**Роли:** Владелец файла, Редактор (с правами на удаление)

**Предусловия:**
- Файл был удален и находится в корзине
- Файл имел историю версий до удаления
- Не прошло более 30 дней с момента удаления (для бесплатных аккаунтов)
- Пользователь имеет права на восстановление файла

**Основной сценарий:**
1. Пользователь переходит в корзину Google Drive
2. Пользователь находит удаленный файл в списке
3. Пользователь кликает правой кнопкой мыши на файле
4. Пользователь выбирает "Восстановить" (Restore)
5. Система выполняет восстановление файла:
   - Восстанавливает файл в исходное расположение
   - Восстанавливает текущую активную версию
   - Восстанавливает всю историю версий файла
   - Восстанавливает именованные версии
   - Восстанавливает метки "Сохранить навсегда"
6. Система восстанавливает метаданные файла:
   - Права доступа
   - Участники совместного доступа
   - Комментарии
   - История версий полностью
7. Файл появляется в исходной папке
8. Пользователь получает уведомление "Файл восстановлен"
9. Пользователь может открыть историю версий:
   - Все версии доступны так же, как до удаления
   - Временные метки версий не изменились
   - Информация об авторах сохранена
10. Счетчики использования хранилища обновляются

**Альтернативные сценарии:**
- Сценарий А (Файл окончательно удален): Если файл удален из корзины, восстановление невозможно, версии потеряны навсегда
- Сценарий Б (Исходная папка удалена): Файл восстанавливается в корневую папку "Мой диск"
- Сценарий В (Конфликт имен): Если в исходной папке уже есть файл с таким именем, восстановленный файл получает "(1)" в названии
- Сценарий Г (Частичная история): Если некоторые версии были удалены до помещения файла в корзину, они не восстанавливаются
- Сценарий Д (Google Workspace Vault): Администраторы могут восстановить файлы и версии даже после удаления из корзины (в пределах срока хранения)
- Сценарий Е (Превышение квоты): Если восстановление приведет к превышению квоты, система показывает предупреждение

**Бизнес-правила:**
- BR-149: При восстановлении файла восстанавливается вся история версий
- BR-150: Файлы хранятся в корзине 30 дней для бесплатных аккаунтов
- BR-151: Google Workspace администраторы могут увеличить срок хранения в корзине
- BR-152: Все версии, существовавшие до удаления, восстанавливаются
- BR-153: Метки "Сохранить навсегда" и именованные версии сохраняются при восстановлении
- BR-154: Восстановление не создает новую версию
- BR-155: Права доступа и участники восстанавливаются вместе с файлом
- BR-156: После окончательного удаления из корзины версии не подлежат восстановлению
- BR-157: Восстановленные версии учитываются в квоте хранилища
- BR-158: Google Vault может хранить удаленные файлы и версии дольше для соблюдения политик

**Результат:** Файл восстановлен из корзины вместе с полной историей версий

### FR-VERSION-017: Ограничения и лимиты версионности

**Описание:** Система применяет различные ограничения и лимиты на хранение и управление версиями в зависимости от типа файла и аккаунта.

**Роли:** Система Google Drive, Администратор Google Workspace

**Предусловия:**
- Файлы существуют в Google Drive
- Система применяет политики хранения

**Основной сценарий:**
1. Система применяет лимиты на основе типа файла и аккаунта:

   **Для загруженных файлов (PDF, Office, изображения и т.д.):**
   - Максимум 100 версий на файл ИЛИ
   - Версии за последние 30 дней (что больше)
   - Старые неименованные версии удаляются автоматически

   **Для Google Docs/Sheets/Slides:**
   - Все версии сохраняются без ограничения количества (по умолчанию)
   - Версии старше 30 дней подлежат очистке только при превышении квоты
   - Именованные версии хранятся бессрочно

   **Для бесплатных аккаунтов Google:**
   - Общая квота хранилища: 15 GB (общая для Drive, Gmail, Photos)
   - Версии учитываются в квоте хранилища
   - Срок хранения неименованных версий: 30 дней
   - Лимит 100 версий для загруженных файлов

   **Для Google Workspace:**
   - Квота зависит от плана (30 GB - 5 TB на пользователя)
   - Администраторы могут устанавливать кастомные политики через Vault
   - Возможность увеличения срока хранения версий
   - Функция "Только именованные версии" доступна для Business Standard+

2. Система автоматически очищает версии, превышающие лимиты:
   - Проверка выполняется ежедневно
   - Удаляются самые старые неименованные версии
   - Именованные версии и версии с меткой "Сохранить навсегда" защищены
   - Версии за последние 30 дней защищены (для загруженных файлов)

3. При достижении лимитов система:
   - Продолжает создавать новые версии
   - Автоматически удаляет самые старые версии по правилам
   - Не блокирует создание новых версий
   - Уведомляет пользователя при превышении квоты хранилища (не версий)

4. Пользователь может управлять версиями для освобождения места:
   - Ручное удаление неименованных версий (владелец файла)
   - Снятие метки "Сохранить навсегда" с версий
   - Удаление именованных версий
   - Очистка истории версий

**Альтернативные сценарии:**
- Сценарий А (Превышение квоты): При превышении общей квоты хранилища система блокирует загрузку новых файлов, но продолжает создавать версии
- Сценарий Б (Google Workspace Unlimited): Для планов с неограниченным хранилищем лимиты на версии практически отсутствуют
- Сценарий В (Кастомные политики): Администраторы могут устанавливать отличные от стандартных лимиты через Vault
- Сценарий Г (Критически важные файлы): Пользователи могут пометить все версии важных файлов как "Сохранить навсегда"

**Бизнес-правила:**
- BR-159: Для загруженных файлов: максимум 100 версий ИЛИ версии за 30 дней (что больше)
- BR-160: Для Google Docs/Sheets/Slides: все версии сохраняются без ограничения количества
- BR-161: Неименованные версии старше 30 дней подлежат автоматическому удалению
- BR-162: Именованные версии и версии с меткой "Сохранить навсегда" хранятся бессрочно
- BR-163: Версии учитываются в общей квоте хранилища Google Drive
- BR-164: Бесплатные аккаунты: 15 GB общей квоты для Drive, Gmail, Photos
- BR-165: Google Workspace: квота от 30 GB до 5 TB на пользователя (зависит от плана)
- BR-166: При достижении лимита 100 версий удаляются самые старые неименованные версии
- BR-167: Администраторы могут устанавливать кастомные политики хранения через Google Vault
- BR-168: Система не блокирует создание новых версий при достижении лимитов (удаляет старые)
- BR-169: Функция "Только именованные версии" доступна для Business Standard, Plus, Enterprise, Education Plus
- BR-170: Максимальный размер файла для версионирования: 5 TB (зависит от плана)

**Результат:** Система применила лимиты и политики хранения версий согласно типу аккаунта и файла

## Сущности данных

### Версия файла (File Version)
- **version_id** - уникальный идентификатор версии
- **file_id** - связь с файлом Google Drive
- **version_number** - порядковый номер версии (incrementing)
- **content_hash** - хеш содержимого для определения изменений
- **size** - размер версии в байтах
- **created_at** - дата и время создания версии (timestamp)
- **modified_by_user_id** - ID пользователя, создавшего версию
- **modified_by_user_name** - полное имя пользователя
- **modified_by_user_email** - email пользователя
- **modification_type** - тип изменения (edit, upload, restore, create)
- **is_current** - флаг текущей активной версии (boolean)
- **is_named** - флаг именованной версии (boolean)
- **version_name** - название версии (nullable, до 200 символов)
- **version_description** - описание версии (nullable, до 500 символов)
- **keep_forever** - флаг "Сохранить навсегда" (boolean)
- **marked_by_user_id** - ID пользователя, поставившего метку "Сохранить навсегда"
- **marked_at** - дата установки метки "Сохранить навсегда"
- **download_url** - временная ссылка для скачивания версии
- **mime_type** - MIME тип файла
- **storage_location** - расположение содержимого версии в хранилище

### Метаданные истории версий (Version History Metadata)
- **file_id** - связь с файлом
- **total_versions_count** - общее количество версий
- **named_versions_count** - количество именованных версий
- **keep_forever_versions_count** - количество версий с меткой "Сохранить навсегда"
- **oldest_version_date** - дата создания самой старой версии
- **newest_version_date** - дата создания самой новой версии
- **total_versions_size** - общий размер всех версий в байтах
- **last_cleanup_date** - дата последней автоматической очистки версий
- **next_cleanup_date** - дата следующей плановой очистки

### Изменения в версии (Version Changes)
- **change_id** - уникальный идентификатор изменения
- **version_id** - связь с версией
- **change_type** - тип изменения (addition, deletion, modification, formatting)
- **user_id** - ID автора изменения
- **user_color** - цвет подсветки для автора (для визуализации)
- **change_location** - позиция изменения в документе (для Google Docs)
- **old_content** - старое содержимое (для сравнения)
- **new_content** - новое содержимое
- **timestamp** - временная метка изменения

### Политика хранения версий (Version Retention Policy)
- **policy_id** - уникальный идентификатор политики
- **organization_id** - ID организации Google Workspace (nullable для личных аккаунтов)
- **applies_to** - область применения (organization, organizational_unit, user, folder)
- **target_id** - ID цели (org_unit_id, user_id, folder_id)
- **retention_period_days** - срок хранения версий в днях
- **max_versions_count** - максимальное количество версий (nullable)
- **auto_delete_after_period** - автоматически удалять после истечения срока (boolean)
- **exclude_named_versions** - исключить именованные версии из правила (boolean)
- **exclude_keep_forever** - исключить версии с меткой "Сохранить навсегда" (boolean)
- **created_by_admin_id** - ID администратора, создавшего политику
- **created_at** - дата создания политики
- **is_active** - флаг активности политики (boolean)
- **priority** - приоритет при конфликте политик (integer)

### Действия с версиями (Version Actions Log)
- **action_id** - уникальный идентификатор действия
- **version_id** - связь с версией
- **file_id** - связь с файлом
- **action_type** - тип действия (create, restore, delete, name, download, view)
- **performed_by_user_id** - ID пользователя, выполнившего действие
- **performed_at** - дата и время действия
- **ip_address** - IP адрес, с которого выполнено действие
- **user_agent** - информация о браузере/приложении
- **action_details** - JSON с деталями действия (например, из какой версии восстановлено)
- **result** - результат действия (success, failure, partial)
- **error_message** - сообщение об ошибке (nullable)

### Настройки уведомлений о версиях (Version Notification Settings)
- **user_id** - ID пользователя
- **file_id** - ID файла (nullable, для настроек уровня файла)
- **folder_id** - ID папки (nullable, для настроек уровня папки)
- **notify_on_restore** - уведомлять о восстановлении версий (boolean)
- **notify_on_named_version** - уведомлять о создании именованных версий (boolean)
- **notify_on_version_delete** - уведомлять об удалении версий (boolean)
- **notification_channels** - каналы уведомлений: email, push, web (JSON array)
- **digest_mode** - режим дайджеста (immediate, daily, weekly)

## Состояния и статусы

### Типы версий
- **current_version** - текущая активная версия файла
- **historical_version** - предыдущая версия в истории
- **named_version** - именованная версия (с названием)
- **restored_version** - версия, созданная в результате восстановления
- **uploaded_version** - версия, созданная при загрузке файла
- **auto_saved_version** - автоматически сохраненная версия (Google Docs)

### Статусы хранения версий
- **active** - версия активна и доступна для просмотра/восстановления
- **keep_forever** - версия помечена для постоянного хранения
- **pending_deletion** - версия ожидает удаления (при превышении лимитов)
- **deleted** - версия удалена (содержимое недоступно)
- **archived** - версия архивирована (по политике Vault)

### Типы изменений в версиях
- **create** - создание файла (первая версия)
- **edit** - редактирование содержимого (обычное изменение)
- **upload** - загрузка новой версии файла
- **restore** - восстановление из предыдущей версии
- **rename** - переименование файла (может не создавать версию)
- **format_change** - изменение форматирования (Google Docs)
- **content_addition** - добавление нового контента
- **content_deletion** - удаление контента
- **content_modification** - изменение существующего контента

### Политики хранения (Retention Policies)
- **default_personal** - стандартная политика для личных аккаунтов (30 дней/100 версий)
- **default_workspace** - стандартная политика для Google Workspace (все версии для Google форматов)
- **custom_retention** - кастомная политика, установленная администратором
- **litigation_hold** - судебный запрет (все версии хранятся бессрочно)
- **compliance_policy** - политика соответствия нормативным требованиям

### Уровни доступа к версиям
- **owner_full_access** - владелец (полный доступ: просмотр, восстановление, удаление, именование)
- **editor_access** - редактор (просмотр, восстановление, именование)
- **commenter_access** - комментатор (только просмотр истории)
- **viewer_access** - читатель (только просмотр истории, если не запрещено скачивание)
- **no_access** - нет доступа к истории версий

## Ограничения и лимиты

### Лимиты количества версий
- **Загруженные файлы (non-Google форматы)**: максимум 100 версий ИЛИ версии за 30 дней (что больше)
- **Google Docs/Sheets/Slides**: все версии без ограничения количества (по умолчанию)
- **Именованные версии**: нет лимита (ограничено только квотой хранилища)
- **Версии с меткой "Сохранить навсегда"**: нет лимита (ограничено квотой)

### Сроки хранения версий
- **Неименованные версии**: 30 дней для загруженных файлов (затем автоматическое удаление)
- **Неименованные версии Google Docs**: хранятся бессрочно (до превышения квоты)
- **Именованные версии**: бессрочно (защищены от автоматического удаления)
- **Версии "Сохранить навсегда"**: бессрочно
- **Удаленные файлы в корзине**: 30 дней (затем окончательное удаление с версиями)

### Размеры и квоты
- **Максимальный размер файла**: 5 TB (зависит от плана Google Workspace)
- **Квота бесплатного аккаунта**: 15 GB (общая для Drive, Gmail, Photos)
- **Квота Google Workspace**: 30 GB - 5 TB на пользователя (зависит от плана)
- **Размер версии**: учитывается в общей квоте хранилища
- **Совокупный размер версий файла**: не может превышать квоту аккаунта

### Лимиты именования и описания
- **Максимальная длина названия версии**: 200 символов
- **Максимальная длина описания версии**: 500 символов
- **Количество именованных версий**: без ограничений (ограничено квотой)

### Временные ограничения
- **Минимальный интервал между автоматическими версиями**: несколько секунд (для Google Docs)
- **Частота очистки старых версий**: ежедневно (автоматическая задача)
- **Срок действия ссылки на скачивание версии**: временная (обычно несколько часов)
- **Задержка применения политик хранения**: до 24 часов

### Функциональные ограничения по типу аккаунта
- **Бесплатный Google аккаунт**:
  - Функция "Только именованные версии" недоступна
  - Стандартные лимиты хранения (15 GB)
  - Нет доступа к Google Vault

- **Google Workspace Business Standard и выше**:
  - Функция "Только именованные версии" доступна
  - Увеличенная квота хранилища
  - Возможность кастомных политик через Vault (для некоторых планов)

- **Google Workspace Enterprise**:
  - Полный доступ к Google Vault
  - Кастомные политики хранения версий
  - Судебные запреты (Litigation Hold)
  - Расширенные возможности аудита версий

### Ограничения по типу файла
- **Google Docs/Sheets/Slides**: полная поддержка версионности с визуализацией изменений
- **Загруженные Office файлы**: поддержка версий, но без визуализации изменений
- **PDF, изображения, видео**: поддержка версий как полных копий файла
- **Папки**: версионность не применяется (только к файлам)
- **Ярлыки (shortcuts)**: версионность не применяется

## Интеграции с другими модулями

### Модуль "Управление файлами и папками"
- Версионность применяется ко всем файлам в Drive
- При перемещении файла история версий перемещается вместе с ним
- При копировании файла копируется только текущая версия (история не копируется)
- При удалении файла в корзину вся история версий сохраняется

### Модуль "Совместный доступ и разрешения"
- Права доступа определяют возможность просмотра и восстановления версий
- Владелец имеет полный доступ к управлению версиями
- Редакторы могут создавать, просматривать и восстанавливать версии
- Комментаторы и читатели могут только просматривать историю
- Изменение прав доступа не влияет на существующие версии

### Модуль "Поиск и организация"
- Поиск может находить файлы по содержимому в предыдущих версиях
- Поиск не индексирует неактивные версии напрямую
- Метаданные версий (автор, дата) доступны для поиска

### Модуль "Синхронизация (Google Drive Desktop)"
- Приложение синхронизирует только текущую активную версию
- Доступ к истории версий возможен только через веб-интерфейс или мобильное приложение
- При восстановлении версии через веб, синхронизация обновляет локальную копию

### Модуль "Комментарии и обсуждения"
- Комментарии привязаны к файлу, а не к версиям
- При восстановлении версии комментарии сохраняются
- Комментарии могут ссылаться на контент, который был изменен в последующих версиях

### Модуль "Google Workspace (Docs, Sheets, Slides)"
- Встроенная интеграция версионности в редакторы Google Docs
- Визуализация изменений с цветовой подсветкой по авторам
- Функция "Compare Documents" для сравнения версий
- Режим "Suggesting" связан с версионностью (предложения сохраняются в версиях)

### Модуль "Уведомления"
- Уведомления о восстановлении версий
- Уведомления о создании именованных версий
- Настройки уведомлений на уровне файла, папки или аккаунта

### Модуль "Хранилище и квота"
- Версии учитываются в общей квоте хранилища
- Старые версии автоматически удаляются при превышении лимитов для освобождения места
- Именованные версии и версии "Сохранить навсегда" потребляют квоту постоянно
- Управление хранилищем влияет на политики хранения версий

### Модуль "Google Vault (Архивация и комплаенс)"
- Администраторы могут устанавливать политики хранения версий
- Судебные запреты (Litigation Hold) сохраняют все версии бессрочно
- Экспорт версий для аудита и расследований
- Кастомные сроки хранения для соответствия нормативным требованиям

### Модуль "Аудит и логирование"
- Все действия с версиями логируются для аудита
- Логи содержат: кто, когда, какое действие выполнил (создание, восстановление, удаление)
- Администраторы могут просматривать полную историю действий с версиями
- Логи используются для расследований инцидентов безопасности

### Модуль "API Google Drive"
- API предоставляет доступ к истории версий программно
- Разработчики могут создавать, просматривать, скачивать, удалять версии через API
- API поддерживает все операции, доступные в веб-интерфейсе
- Версионность доступна через revisions endpoint в Drive API v3
