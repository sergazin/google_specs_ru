# Поиск и фильтрация

## Описание

Модуль поиска и фильтрации Google Drive - это комплексная система обнаружения и организации файлов, которая включает текстовый поиск по именам файлов и содержимому документов, OCR-распознавание текста в изображениях и отсканированных PDF, расширенные операторы поиска для точного поиска, AI-поиск с использованием Gemini для семантического анализа, предиктивный поиск Quick Access на базе машинного обучения, фильтрацию по множеству параметров (тип, дата, владелец), поиск по меткам и звездочкам, а также управление историей поиска. Система использует глубокие нейронные сети для предсказания нужных файлов и обеспечивает доступ к документам в два раза быстрее по сравнению с ручной навигацией.

## Роли пользователей

- **Владелец личного Drive** - может искать в своих файлах и файлах, которыми с ним поделились
- **Участник общего диска (Shared Drive)** - может искать в файлах общего диска в соответствии с правами доступа
- **Менеджер общего диска** - имеет расширенные возможности поиска, включая удаленные файлы в корзине
- **Пользователь Workspace с Gemini** - имеет доступ к AI-поиску и семантическому анализу контента
- **Администратор домена** - может искать через Google Vault с дополнительными фильтрами и eDiscovery
- **Гостевой пользователь** - может искать только в файлах, к которым ему предоставлен доступ

## Функциональные требования

### FR-SEARCH-001: Базовый текстовый поиск по именам файлов

**Описание:** Поиск файлов и папок по ключевым словам в именах с автоматическим подбором результатов в реальном времени.

**Роли:** Все пользователи

**Предусловия:**
- Пользователь авторизован в Google Drive
- Есть доступ к файлам для поиска

**Основной сценарий:**
1. Пользователь открывает Google Drive в браузере или приложении
2. Нажимает на строку поиска в верхней части интерфейса или использует сочетание клавиш "/"
3. Начинает вводить поисковый запрос (минимум 1 символ)
4. Система активирует live search с задержкой не более 300мс
5. Поиск выполняется по следующим полям:
   - Имя файла (частичное совпадение)
   - Имя папки (частичное совпадение)
   - Описание файла (если установлено пользователем)
6. Под строкой поиска появляется выпадающий список с первыми результатами (до 5-7 элементов)
7. Каждый результат в выпадающем списке показывает:
   - Иконку типа файла
   - Название с выделенным совпадением
   - Путь расположения файла
   - Дату последнего изменения
8. При продолжении ввода результаты автоматически обновляются
9. Пользователь может:
   - Нажать Enter для отображения полной страницы результатов
   - Кликнуть на конкретный файл в выпадающем списке для открытия
   - Использовать стрелки вверх/вниз для навигации по результатам

**Альтернативные сценарии:**
- Сценарий А (Нет результатов): Система показывает "Файлы не найдены", предлагает проверить правописание и попробовать другие ключевые слова
- Сценарий Б (Медленное соединение): Показывается индикатор загрузки, результаты появляются с задержкой
- Сценарий В (Только файлы с доступом): Если найдены файлы без доступа, они не показываются
- Сценарий Г (Архивные файлы): Файлы в корзине не включаются в результаты по умолчанию

**Бизнес-правила:**
- BR-001: Поиск не зависит от регистра (case-insensitive)
- BR-002: Поиск учитывает частичные совпадения (префиксный поиск)
- BR-003: Минимальная длина запроса - 1 символ
- BR-004: Максимальная задержка live search - 300мс
- BR-005: Результаты показываются только для файлов с доступом на чтение или выше
- BR-006: По умолчанию поиск в "Моем диске" и файлах, доступных пользователю
- BR-007: Файлы в корзине исключены из базового поиска
- BR-008: Максимум 5-7 результатов в выпадающем списке

**Результат:** Пользователь находит нужные файлы по имени

### FR-SEARCH-002: Поиск по содержимому файлов

**Описание:** Поиск текста внутри документов, включая Google Docs, Sheets, Slides, PDF и другие текстовые форматы.

**Роли:** Все пользователи

**Предусловия:**
- Файл проиндексирован системой Google Drive
- Пользователь имеет доступ к файлу
- Файл содержит текстовый контент

**Основной сценарий:**
1. Пользователь вводит поисковый запрос в строку поиска
2. Система автоматически включает поиск по содержимому файлов
3. Поиск выполняется в следующих типах файлов:
   - Google Документы (Docs, Sheets, Slides, Forms)
   - PDF документы (проиндексированные)
   - Текстовые файлы (.txt, .md, .csv)
   - Microsoft Office файлы (Word, Excel, PowerPoint)
   - HTML и код файлы
4. Система анализирует содержимое файлов и находит совпадения
5. Результаты поиска отображают:
   - Название файла
   - Превью совпадения с контекстом (фрагмент текста до 150 символов)
   - Выделенное ключевое слово в превью
   - Тип файла и местоположение
6. При клике на результат файл открывается с переходом к найденному фрагменту (если возможно)
7. В Google Docs автоматически активируется функция "Find in document" с поисковым запросом

**Альтернативные сценарии:**
- Сценарий А (Неиндексированный файл): Новые файлы могут не сразу попасть в индекс, поиск не найдет содержимое до индексации
- Сценарий Б (Изображения без OCR): Текст на изображениях требует OCR (см. FR-SEARCH-003)
- Сценарий В (Зашифрованные файлы): Файлы с шифрованием не индексируются
- Сценарий Г (Большой файл): Для файлов >50MB индексация может быть ограничена

**Бизнес-правила:**
- BR-009: Индексация нового файла занимает от нескольких минут до нескольких часов
- BR-010: Поддерживаются Google Workspace форматы, PDF, Office, текстовые файлы
- BR-011: Максимальный размер индексируемого файла - 50MB для большинства типов
- BR-012: Поиск по содержимому работает только для файлов с текстовым контентом
- BR-013: Файлы в корзине не индексируются
- BR-014: Превью показывает до 150 символов контекста вокруг совпадения
- BR-015: При открытии Google Docs поиск переходит к первому совпадению

**Результат:** Пользователь находит файлы по тексту внутри них

### FR-SEARCH-003: OCR-поиск в изображениях и PDF

**Описание:** Автоматическое распознавание текста (OCR) в изображениях и отсканированных PDF для поиска по их содержимому.

**Роли:** Все пользователи

**Предусловия:**
- Файл является изображением (JPEG, PNG, GIF, BMP, TIFF) или PDF
- Изображение содержит читаемый текст
- Файл загружен и проиндексирован

**Основной сценарий:**
1. Пользователь загружает изображение или PDF с текстом в Google Drive
2. Система автоматически запускает OCR-обработку:
   - Обнаруживает наличие текста на изображении
   - Распознает текст с использованием Google Cloud Vision API
   - Извлекает текст и добавляет в индекс поиска
   - Сохраняет распознанный текст в метаданных файла
3. Процесс индексации занимает от нескольких минут до нескольких часов
4. Пользователь выполняет текстовый поиск
5. Система ищет совпадения в распознанном тексте из изображений
6. Результаты показывают:
   - Изображение/PDF с миниатюрой
   - Фрагмент распознанного текста с совпадением
   - Метка "Текст распознан из изображения"
7. При открытии файла пользователь видит оригинальное изображение

**Альтернативные сценарии:**
- Сценарий А (Низкое качество изображения): OCR может работать неточно, текст распознается частично или с ошибками
- Сценарий Б (Нестандартный шрифт): Рукописный или художественный текст может не распознаться
- Сценарий В (Многоязычный текст): Система распознает основные языки автоматически
- Сценарий Г (Объекты на изображении): Google Drive также распознает объекты (см. FR-SEARCH-004)

**Бизнес-правила:**
- BR-016: OCR работает автоматически для всех загруженных изображений и PDF
- BR-017: Поддерживаются форматы: JPEG, PNG, GIF, BMP, TIFF, PDF
- BR-018: Максимальный размер файла для OCR - 2MB для изображений, 50MB для PDF
- BR-019: OCR распознает печатный текст с точностью ~95% при хорошем качестве
- BR-020: Поддерживается более 50 языков для распознавания
- BR-021: Индексация OCR может занять до 24 часов для больших файлов
- BR-022: Распознанный текст не изменяет оригинальный файл

**Результат:** Пользователь может искать текст внутри изображений и сканов

### FR-SEARCH-004: Распознавание объектов на изображениях

**Описание:** Автоматическое определение объектов, мест и концепций на изображениях для поиска по визуальному содержимому.

**Роли:** Все пользователи

**Предусловия:**
- Файл является изображением (JPEG, PNG, GIF, BMP)
- Изображение проиндексировано системой
- Изображение содержит распознаваемые объекты

**Основной сценарий:**
1. Пользователь загружает изображение в Google Drive
2. Система автоматически анализирует содержимое с помощью Google Cloud Vision API:
   - Распознает объекты (машина, собака, здание и т.д.)
   - Определяет места (Эйфелева башня, Нью-Йорк)
   - Идентифицирует концепции (пейзаж, закат, портрет)
   - Извлекает метки (tags) для индексации
3. Распознанные объекты добавляются в метаданные изображения
4. Пользователь вводит запрос типа "фото собаки" или "снимки с пляжа"
5. Система ищет совпадения в распознанных объектах и метках
6. Результаты показывают изображения с соответствующими объектами
7. Каждый результат отображает:
   - Миниатюру изображения
   - Название файла
   - Список распознанных объектов
   - Местоположение и дата

**Альтернативные сценарии:**
- Сценарий А (Абстрактное изображение): Система может не распознать объекты на абстрактных изображениях
- Сценарий Б (Частичное распознавание): Некоторые объекты могут не распознаться или распознаться неточно
- Сценарий В (Поиск на английском): Некоторые метки могут быть только на английском языке
- Сценарий Г (Множественные объекты): На изображении может быть распознано до 50+ объектов

**Бизнес-правила:**
- BR-023: Распознавание объектов работает автоматически при загрузке изображений
- BR-024: Поддерживаются основные форматы изображений
- BR-025: Система распознает тысячи категорий объектов
- BR-026: Точность распознавания зависит от качества и четкости изображения
- BR-027: Метаданные объектов не изменяют оригинальный файл
- BR-028: Индексация может занять от нескольких минут до нескольких часов

**Результат:** Пользователь может искать изображения по содержащимся объектам

### FR-SEARCH-005: Расширенные операторы поиска

**Описание:** Использование специальных операторов для точного и сложного поиска файлов по множеству параметров.

**Роли:** Все пользователи

**Предусловия:**
- Пользователь знаком с синтаксисом операторов
- Пользователь находится в интерфейсе поиска

**Основной сценарий:**
1. Пользователь открывает строку поиска в Google Drive
2. Вводит поисковый запрос с использованием операторов:

   **Операторы владельца и доступа:**
   - `owner:email@example.com` - файлы владельца
   - `from:email@example.com` - файлы, которыми поделился пользователь
   - `to:email@example.com` - файлы, которыми я поделился с пользователем
   - `is:starred` - помеченные звездочкой
   - `is:trashed` - файлы в корзине

   **Операторы типа файла:**
   - `type:document` - Google Документы
   - `type:spreadsheet` - Google Таблицы
   - `type:presentation` - Google Презентации
   - `type:pdf` - PDF файлы
   - `type:image` - изображения
   - `type:video` - видео
   - `type:folder` - только папки

   **Операторы даты:**
   - `before:2024-12-01` - до определенной даты
   - `after:2024-01-01` - после определенной даты
   - `modifieddate:2024-12-10` - конкретная дата изменения

   **Другие операторы:**
   - `title:"название"` - точное совпадение в названии
   - `sharedwith:me` - файлы, которыми поделились со мной
   - `has:writer` - файлы где я имею права редактора
   - `has:reader` - файлы где я имею права на чтение

3. Можно комбинировать операторы через пробел (логика AND)
4. Пример: `owner:me type:pdf after:2024-01-01`
5. Система обрабатывает запрос и применяет все фильтры
6. Результаты показывают только файлы, соответствующие всем критериям
7. В интерфейсе отображаются активные фильтры в виде чипов

**Альтернативные сценарии:**
- Сценарий А (Неправильный синтаксис): Система игнорирует неправильный оператор и ищет как обычный текст
- Сценарий Б (Нет результатов): Слишком строгая комбинация фильтров может не дать результатов
- Сценарий В (Использование GUI): Можно использовать визуальный интерфейс фильтров вместо операторов
- Сценарий Г (Сохранение запроса): Сложные запросы можно сохранить для повторного использования

**Бизнес-правила:**
- BR-029: Операторы не зависят от регистра
- BR-030: Множественные операторы комбинируются через логику AND
- BR-031: Дата должна быть в формате YYYY-MM-DD
- BR-032: Операторы `owner:`, `from:`, `to:` требуют email или "me"
- BR-033: Неправильный синтаксис обрабатывается как обычный текстовый поиск
- BR-034: Максимум 50 операторов в одном запросе

**Результат:** Пользователь получает точные результаты по сложным критериям

### FR-SEARCH-006: Quick Access - предиктивный поиск

**Описание:** Интеллектуальная система на базе машинного обучения, которая предсказывает и показывает нужные файлы на главной странице до начала поиска.

**Роли:** Все пользователи

**Предусловия:**
- Пользователь авторизован в Google Drive
- Есть история использования файлов
- Функция Quick Access включена (по умолчанию)

**Основной сценарий:**
1. Пользователь открывает главную страницу Google Drive
2. Система Quick Access автоматически анализирует множество сигналов:
   - Последние 20 событий редактирования для каждого документа
   - События в Google Calendar (предстоящие встречи)
   - Паттерны рабочего дня (регулярные встречи, обзоры)
   - Взаимодействие с коллегами (совместная работа)
   - Время суток и день недели
   - Местоположение файлов
   - Частота доступа к файлам
3. Система использует глубокую нейронную сеть для расчета релевантности каждого файла
4. Для каждого документа вычисляется relevance score
5. Топ-10 файлов с наивысшим score показываются в разделе "Quick Access"
6. Каждый файл отображается с:
   - Миниатюрой/иконкой
   - Названием
   - Последним временем изменения
   - Владельцем (если не вы)
7. Пример предсказания: если через несколько минут встреча с коллегой, показывается презентация, над которой вы работали вместе
8. Раздел обновляется динамически в течение дня

**Альтернативные сценарии:**
- Сценарий А (Новый аккаунт): Для новых пользователей показываются последние файлы
- Сценарий Б (Отключение Quick Access): Можно скрыть раздел в настройках
- Сценарий В (Нерелевантные предсказания): Пользователь может скрыть файл из Quick Access
- Сценарий Г (Множественные устройства): Предсказания синхронизируются между устройствами

**Бизнес-правила:**
- BR-035: Quick Access использует глубокие нейронные сети Google
- BR-036: Система анализирует тысячи признаков для каждого файла
- BR-037: Предсказания обновляются в реальном времени
- BR-038: Максимум 10-15 файлов в разделе Quick Access
- BR-039: Учитываются события Calendar за следующие 2 часа
- BR-040: Quick Access ускоряет доступ к файлам в 2 раза по сравнению с ручным поиском
- BR-041: Можно отключить в настройках: Settings > General > Suggestions
- BR-042: Система учитывает паттерны всех пользователей (агрегированно)

**Результат:** Нужные файлы доступны без поиска, экономия времени

### FR-SEARCH-007: Фильтрация результатов поиска

**Описание:** Применение визуальных фильтров для уточнения результатов поиска по типу файла, владельцу, дате изменения и другим параметрам.

**Роли:** Все пользователи

**Предусловия:**
- Выполнен поиск с результатами
- Пользователь находится на странице результатов поиска

**Основной сценарий:**
1. Пользователь выполняет поиск и видит результаты
2. Под строкой поиска отображаются чипы фильтров (Filter chips):
   - **Type** (Тип файла)
   - **People** (Люди - владелец/участник)
   - **Modified** (Дата изменения)
   - **Location** (Расположение)
   - **Has** (Дополнительные атрибуты)
3. Пользователь нажимает на чип "Type"
4. Открывается выпадающее меню с опциями:
   - Documents (Документы)
   - Spreadsheets (Таблицы)
   - Presentations (Презентации)
   - Forms (Формы)
   - PDFs
   - Images (Изображения)
   - Videos (Видео)
   - Folders (Папки)
   - Audio (Аудио)

### FR-SEARCH-015: Сохраненные поиски и автоматизация

**Описание:** Сохранение сложных поисковых запросов и автоматическое обновление результатов.

**Роли:** Все пользователи

**Предусловия:**
- Пользователь создал сложный поисковый запрос
- Пользователь хочет повторно использовать запрос
- Пользователь находится на странице результатов

**Основной сценарий:**
1. Пользователь создает сложный поисковый запрос с операторами:
   - Например: `type:document owner:me after:2024-01-01 is:starred`
2. После выполнения поиска видит результаты
3. В адресной строке браузера формируется URL с параметрами поиска
4. Пользователь может:
   - Добавить URL в закладки браузера
   - Поделиться ссылкой с коллегами
   - Сохранить в документе для повторного использования
5. При открытии сохраненной ссылки:
   - Автоматически выполняется поиск
   - Показываются актуальные результаты
   - Все фильтры применены
6. Для регулярных поисков можно создать скрипт через Google Apps Script:
   - Автоматический поиск по расписанию
   - Отправка результатов на email
   - Создание отчетов
7. Через Drive API можно автоматизировать поиск:
   - Использовать query параметры
   - Получать результаты программно
   - Интегрировать с внешними системами

**Альтернативные сценарии:**
- Сценарий А (Изменение параметров): URL можно редактировать вручную для изменения фильтров
- Сценарий Б (Коллективное использование): Ссылкой можно поделиться с командой
- Сценарий В (API интеграция): Через Drive API можно создавать сложные автоматизации
- Сценарий Г (Apps Script): Можно создать custom меню в Drive для быстрых поисков

**Бизнес-правила:**
- BR-092: URL поиска содержит все параметры запроса
- BR-093: Сохраненные поиски обновляются автоматически (live results)
- BR-094: Можно делиться ссылками, но доступ к файлам зависит от permissions
- BR-095: Apps Script может выполнять до 100 поисков в день
- BR-096: Drive API имеет квоту 1000 запросов в 100 секунд на пользователя

**Результат:** Автоматизация повторяющихся поисков

## Сущности данных

### Поисковый запрос (Search Query)
- **query_id** - уникальный идентификатор запроса
- **user_id** - ID пользователя, выполнившего поиск
- **query_text** - текст поискового запроса
- **query_operators** - массив использованных операторов
- **timestamp** - дата и время выполнения
- **search_scope** - область поиска (my_drive, shared_drives, all)
- **filters_applied** - примененные фильтры (JSON)
- **results_count** - количество найденных результатов
- **execution_time_ms** - время выполнения в миллисекундах

### Результат поиска (Search Result)
- **result_id** - уникальный ID результата
- **file_id** - ID файла в Google Drive
- **file_name** - название файла
- **file_type** - тип файла (document, spreadsheet, pdf и т.д.)
- **owner_email** - email владельца
- **modified_date** - дата последнего изменения
- **relevance_score** - оценка релевантности (0-100)
- **match_type** - тип совпадения (title, content, ocr, object)
- **preview_snippet** - фрагмент содержимого с совпадением
- **file_path** - путь к файлу в Drive
- **permissions** - уровень доступа пользователя (owner, editor, viewer)

### Quick Access Item
- **file_id** - ID файла
- **relevance_score** - оценка релевантности (0-1.0)
- **prediction_factors** - факторы предсказания (JSON)
  - calendar_events - связанные события календаря
  - recent_edits - количество недавних правок
  - collaboration_score - оценка совместной работы
  - time_of_day_pattern - паттерн времени использования
  - access_frequency - частота доступа
- **last_updated** - время последнего обновления score
- **position** - позиция в списке Quick Access (1-15)

### История поиска (Search History)
- **user_id** - ID пользователя
- **queries** - массив последних запросов (до 10)
- **query_text** - текст запроса
- **query_timestamp** - время выполнения
- **results_clicked** - файлы, на которые кликнули из результатов
- **last_updated** - последнее обновление истории

### OCR Metadata
- **file_id** - ID файла
- **ocr_text** - распознанный текст
- **ocr_language** - определенный язык
- **ocr_confidence** - уверенность распознавания (0-100%)
- **processing_date** - дата обработки OCR
- **detected_objects** - массив распознанных объектов на изображении
- **object_labels** - метки объектов для индексации

### Фильтр поиска (Search Filter)
- **filter_type** - тип фильтра (type, people, date, location, has)
- **filter_value** - значение фильтра
- **filter_operator** - оператор (equals, contains, before, after)
- **is_active** - активен ли фильтр
- **display_name** - отображаемое название

### Label (Workspace)
- **label_id** - ID метки
- **label_name** - название метки
- **label_color** - цвет метки (hex)
- **workspace_id** - ID организации Workspace
- **created_by** - создатель метки
- **created_date** - дата создания
- **is_shared** - доступна ли всем в организации

### Gemini Search Session
- **session_id** - ID сессии AI-поиска
- **user_id** - ID пользователя
- **gemini_model** - используемая модель (gemini-2.5-pro)
- **query_text** - запрос на естественном языке
- **intent_analysis** - анализ намерения (JSON)
- **semantic_results** - семантические результаты
- **ai_summary** - резюме от AI
- **files_analyzed** - количество проанализированных файлов
- **execution_time_ms** - время выполнения

## Состояния и статусы

### Статусы индексации файла
- **pending** - ожидает индексации
- **indexing** - в процессе индексации
- **indexed** - проиндексирован, доступен для поиска
- **ocr_processing** - выполняется OCR
- **ocr_completed** - OCR завершен
- **error** - ошибка индексации
- **excluded** - исключен из индекса (корзина, без доступа)

### Типы поискового совпадения
- **title_match** - совпадение в названии файла
- **content_match** - совпадение в содержимом
- **ocr_match** - совпадение в OCR-тексте
- **object_match** - совпадение с распознанным объектом на изображении
- **metadata_match** - совпадение в метаданных (описание)
- **semantic_match** - семантическое совпадение (через Gemini)

### Области поиска (Search Scope)
- **my_drive** - только личный диск
- **shared_with_me** - файлы с общим доступом
- **shared_drives** - общие диски организации
- **starred** - помеченные файлы
- **trash** - корзина
- **all** - все доступные области

### Уровни доступа для поиска
- **owner** - владелец файла
- **writer** - редактор
- **commenter** - комментатор
- **reader** - читатель
- **no_access** - нет доступа (файл не показывается)

## Ограничения и лимиты

### Лимиты поиска
- **Минимальная длина запроса**: 1 символ
- **Максимальная длина запроса**: 2048 символов
- **Максимум операторов в запросе**: 50
- **Задержка live search**: 300мс
- **Результатов в выпадающем списке**: 5-7
- **Результатов на странице**: 100 (с пагинацией)
- **История поиска**: последние 10 запросов

### Лимиты индексации
- **Максимальный размер файла для индексации содержимого**: 50MB
- **Максимальный размер для OCR (изображения)**: 2MB
- **Максимальный размер для OCR (PDF)**: 50MB
- **Время индексации**: от нескольких минут до 24 часов
- **Поддерживаемых языков OCR**: 50+

### Лимиты Quick Access
- **Файлов в Quick Access**: 10-15
- **Обновление предсказаний**: в реальном времени
- **Учитываемых признаков**: тысячи для каждого файла
- **Calendar events в анализе**: следующие 2 часа

### Лимиты Gemini Search
- **Файлов для анализа за запрос**: до 50
- **Поддерживаемые форматы**: PDF, DOCX, TXT, JSON, code files, Google Workspace
- **Требуется**: подписка Google Workspace с Gemini
- **Модель**: Gemini 2.5 Pro

### API лимиты (Drive API)
- **Запросов в 100 секунд на пользователя**: 1000
- **Запросов в день**: без жесткого лимита (зависит от квоты)
- **Apps Script поисков в день**: 100
- **Максимум результатов за API запрос**: 1000 (с pageToken для пагинации)

### Лимиты фильтрации
- **Активных фильтров одновременно**: 10
- **Custom date range**: до 10 лет в прошлое
- **Labels на файл (Workspace)**: 100

### Лимиты Google Vault
- **Максимум экспорта за раз**: 500GB
- **Retention период**: бессрочно (настраивается)
- **Файлов под hold**: без ограничений

## Интеграции с другими модулями

### Модуль "Хранилище и управление файлами"
- Поиск работает только с файлами, к которым есть доступ
- Результаты учитывают структуру папок
- Файлы в корзине исключены из обычного поиска
- Интеграция с Starred и Quick Access разделами

### Модуль "Совместный доступ и права"
- Поиск учитывает permissions пользователя
- Оператор `sharedwith:me` для файлов с общим доступом
- Оператор `from:` и `to:` для отслеживания sharing
- Файлы без доступа не показываются в результатах

### Модуль "Google Workspace Integration"
- Индексация содержимого Google Docs, Sheets, Slides, Forms
- Открытие файла с переходом к найденному фрагменту
- Labels доступны только в Workspace
- Gemini Search требует Workspace с Gemini

### Модуль "Версионирование"
- Поиск по последней версии файла
- История версий не индексируется отдельно
- Изменения содержимого переиндексируются автоматически

### Модуль "Мобильные приложения"
- Поиск доступен на iOS и Android
- Quick Access на главной странице мобильного приложения
- Голосовой поиск через Google Assistant
- Синхронизация истории поиска между устройствами

### Модуль "Офлайн режим"
- Поиск по содержимому не работает офлайн
- Поиск по названиям файлов доступен для кэшированных файлов
- OCR и объекты недоступны офлайн
- Quick Access показывает последние кэшированные предсказания

### Google Calendar
- Quick Access анализирует события календаря
- Предсказание файлов для предстоящих встреч
- Учет рабочих паттернов и регулярных событий

### Gmail
- Gemini Deep Research может искать одновременно в Drive и Gmail
- Интеграция для поиска вложений сохраненных в Drive
- Unified search в будущих версиях

### Google Vault (для администраторов)
- eDiscovery поиск по всей организации
- Retention policies для сохранения удаленных файлов
- Legal holds для блокировки удаления
- Audit logs для всех поисковых операций

### Google Cloud Vision API
- OCR-распознавание текста в изображениях
- Определение объектов и меток на фото
- Автоматическая индексация визуального контента

### Gemini AI
- File Search Tool в Gemini API
- Семантический поиск и анализ
- RAG система для работы с документами
- Natural language queries

## Метрики и производительность

### Ключевые метрики
- **Скорость Quick Access**: файлы доступны в 2 раза быстрее чем ручной поиск
- **Точность OCR**: ~95% для печатного текста хорошего качества
- **Задержка live search**: <300мс от ввода до результатов
- **Время индексации**: нового файла: минуты - часы (зависит от размера)
- **Синхронизация истории**: мгновенная между устройствами

### Бенчмарки производительности
- **Поиск в 10,000 файлов**: <1 секунда
- **Поиск в 100,000 файлов**: 1-3 секунды
- **OCR обработка изображения 2MB**: 1-5 минут
- **Quick Access предсказания**: обновление в реальном времени
- **Gemini анализ 50 файлов**: 5-30 секунд
