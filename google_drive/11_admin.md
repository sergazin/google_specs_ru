# Административная панель Google Workspace

## Описание
Модуль административной панели Google Workspace для управления Google Drive на уровне организации. Предоставляет суперадминистраторам и администраторам возможность централизованного управления пользователями, настройки общих дисков (Shared Drives), внедрения политик безопасности и DLP (Data Loss Prevention), управления квотами хранилища, настройки аудита и мониторинга, конфигурации Google Vault для архивирования и eDiscovery, а также управления интеграциями с внешними приложениями. Обеспечивает соблюдение корпоративных стандартов безопасности и регуляторных требований.

## Роли пользователей
- **Суперадминистратор** - полный доступ ко всем настройкам Google Workspace, управление ролями администраторов, конфигурация критичных параметров безопасности
- **Администратор Drive** - управление настройками Google Drive, общими дисками, квотами хранилища и DLP-правилами
- **Администратор безопасности** - настройка политик безопасности, управление DLP, мониторинг логов и инцидентов безопасности
- **Администратор eDiscovery (Vault)** - доступ к Google Vault для создания политик хранения, поиска и экспорта данных для юридических целей
- **Аудитор** - доступ только для чтения к логам активности и отчетам без возможности изменения настроек

## Функциональные требования

### FR-ADMIN-001: Управление пользователями организации
**Описание:** Создание, редактирование и удаление учетных записей пользователей Google Workspace с назначением лицензий Drive и настройкой параметров доступа
**Роли:** Суперадминистратор, Администратор Drive
**Предусловия:**
- Наличие активной подписки Google Workspace
- Доступ к консоли администрирования admin.google.com
- Доменная верификация организации завершена
**Основной сценарий:**
1. Администратор открывает раздел "Каталог → Пользователи" в Admin Console
2. Администратор нажимает кнопку "Добавить нового пользователя"
3. Система отображает форму создания пользователя
4. Администратор вводит имя, фамилию и желаемый email адрес (@company.com)
5. Система проверяет уникальность email в домене
6. Администратор выбирает организационное подразделение (OU) для пользователя
7. Администратор назначает лицензии Google Workspace (включая Drive storage квоту)
8. Система создает учетную запись и отправляет временный пароль на альтернативный email
9. Администратор настраивает дополнительные параметры (обязательная 2FA, лимиты хранилища)
10. Новый пользователь получает доступ к Google Drive согласно политикам OU
**Альтернативные сценарии:**
- Сценарий А (email занят): Система отображает ошибку "Этот адрес уже используется" и предлагает альтернативные варианты
- Сценарий Б (массовое создание): Администратор загружает CSV файл с данными нескольких пользователей для массового импорта
- Сценарий В (приостановка пользователя): Вместо удаления администратор временно приостанавливает аккаунт, сохраняя все данные Drive
- Сценарий Г (передача владения файлами): При удалении пользователя система предлагает передать все файлы Drive другому пользователю
**Бизнес-правила:**
- BR-ADMIN-001: При удалении пользователя его файлы из "Мой диск" сохраняются в течение 20 дней в корзине администратора
- BR-ADMIN-002: Приостановленный пользователь не может войти в систему, но его файлы остаются доступными для сотрудников с правами доступа
- BR-ADMIN-003: Изменения лицензии применяются немедленно, но изменение квоты хранилища может занять до 24 часов
- BR-ADMIN-004: Администратор может принудительно выйти из всех сессий пользователя для немедленного применения изменений безопасности
- BR-ADMIN-005: При создании пользователя автоматически применяются политики безопасности родительского OU
- BR-ADMIN-006: Один администратор не может удалить другого администратора с равными или выше привилегиями
**Результат:** Создан новый пользователь с доступом к Google Drive согласно корпоративным политикам и назначенной квоте хранилища

### FR-ADMIN-002: Создание и настройка общих дисков (Shared Drives)
**Описание:** Создание общих дисков для команд и проектов с централизованным управлением участниками, правами доступа и политиками безопасности
**Роли:** Суперадминистратор, Администратор Drive
**Предусловия:**
- Лицензия Google Workspace Business Standard или выше
- Разрешение на создание общих дисков включено для организации
- Наличие пользователей для назначения участниками
**Основной сценарий:**
1. Администратор переходит в "Apps → Google Workspace → Drive и Документы → Управление общими дисками"
2. Администратор нажимает "Создать общий диск"
3. Система отображает форму создания с полями настройки
4. Администратор вводит название общего диска (например, "Marketing Team 2025")
5. Администратор выбирает организационное подразделение, к которому относится диск
6. Администратор добавляет участников с назначением ролей (Manager, Content Manager, Contributor, Commenter, Viewer)
7. Администратор настраивает параметры доступа (разрешение внешнего доступа, возможность добавления файлов)
8. Система создает общий диск с применением политик OU
9. Система отправляет уведомления всем добавленным участникам
10. Общий диск появляется в разделе "Общие диски" у всех участников
**Альтернативные сценарии:**
- Сценарий А (назначение диска другому OU): Администратор перемещает существующий общий диск в другое подразделение с автоматическим применением новых политик
- Сценарий Б (блокировка внешнего доступа): Администратор устанавливает жесткую политику "запретить внешний доступ" с блокировкой изменения для менеджеров диска
- Сценарий В (установка квоты диска): Администратор устанавливает лимит хранилища для конкретного общего диска (например, 100 GB)
- Сценарий Г (массовое управление): Администратор экспортирует список всех общих дисков организации в CSV и применяет изменения массово
**Бизнес-правила:**
- BR-ADMIN-007: По умолчанию общие диски наследуют политики безопасности родительского OU
- BR-ADMIN-008: Администратор может изменить участников и права любого общего диска вне зависимости от роли Manager
- BR-ADMIN-009: Настройка "Запретить внешний доступ" блокируется для менеджеров, если администратор установил этот флаг
- BR-ADMIN-010: Удаленный общий диск сохраняется в корзине администратора 30 дней с возможностью восстановления
- BR-ADMIN-011: Изменения политик безопасности применяются к существующим общим дискам в течение 24 часов
- BR-ADMIN-012: Один общий диск может содержать до 500,000 файлов и папок
**Результат:** Создан общий диск с настроенными участниками и политиками безопасности для совместной работы команды

### FR-ADMIN-003: Настройка политик Data Loss Prevention (DLP)
**Описание:** Создание и применение правил DLP для автоматического обнаружения и блокировки распространения конфиденциальных данных через Google Drive
**Роли:** Суперадминистратор, Администратор безопасности
**Предусловия:**
- Лицензия Google Workspace Enterprise Plus или Education Plus
- Доступ к разделу "Безопасность → Защита данных" в Admin Console
- Определены типы конфиденциальных данных для защиты
**Основной сценарий:**
1. Администратор переходит в "Безопасность → Доступ и контроль данных → Защита данных"
2. Администратор нажимает "Управление правилами" и выбирает "Добавить правило"
3. Система отображает мастер создания DLP-правила
4. Администратор задает имя правила (например, "Блокировка номеров банковских карт")
5. Администратор выбирает область применения (все OU, конкретные группы или пользователи)
6. Администратор выбирает детекторы контента (предустановленные: PII, номера карт, паспорта или кастомные регулярные выражения)
7. Администратор настраивает условия срабатывания (минимум 3 совпадения в документе)
8. Администратор выбирает действия: блокировка внешнего доступа, предупреждение пользователя, уведомление администратора, применение метки Drive
9. Система активирует правило и начинает сканирование новых и измененных файлов
10. При обнаружении совпадений система применяет настроенные действия и создает инциденты в Security Center
**Альтернативные сценарии:**
- Сценарий А (только предупреждение): Администратор настраивает режим аудита без блокировки для мониторинга без вмешательства
- Сценарий Б (применение IRM): При срабатывании правила система автоматически запрещает скачивание, печать и копирование файла для всех с доступом Viewer
- Сценарий В (исключения из правила): Администратор добавляет группу "Finance Team" в исключения для работы с финансовыми данными
- Сценарий Г (кастомный детектор): Администратор создает детектор по регулярному выражению для поиска внутренних кодов проектов
**Бизнес-правила:**
- BR-ADMIN-013: DLP правила применяются к новым и измененным файлам в реальном времени, полное сканирование может занять до 24 часов
- BR-ADMIN-014: При срабатывании правила блокировки пользователь получает уведомление с причиной и контактом администратора
- BR-ADMIN-015: Один файл может вызвать срабатывание нескольких DLP правил одновременно с применением всех действий
- BR-ADMIN-016: DLP IRM (Information Rights Management) запрещает скачивание, печать и копирование для пользователей с правами Viewer и Commenter
- BR-ADMIN-017: Инциденты DLP сохраняются в Security Center в течение 180 дней с возможностью экспорта
- BR-ADMIN-018: DLP правила применяются к файлам размером до 30 MB, файлы большего размера пропускаются
**Результат:** Активировано DLP правило, автоматически защищающее конфиденциальные данные от несанкционированного распространения

### FR-ADMIN-004: Настройка Google Vault для архивирования и eDiscovery
**Описание:** Конфигурация политик хранения данных Drive, создание материалов для судебных разбирательств и экспорт данных для eDiscovery
**Роли:** Суперадминистратор, Администратор eDiscovery
**Предусловия:**
- Лицензия Google Workspace Business Plus, Enterprise или Education Plus
- Доступ к Google Vault (vault.google.com)
- Лицензия Vault назначена администратору eDiscovery
**Основной сценарий:**
1. Администратор eDiscovery открывает vault.google.com
2. Администратор переходит в раздел "Хранение → Правила хранения"
3. Администратор нажимает "Создать правило хранения"
4. Администратор выбирает сервис "Drive" и указывает название правила
5. Администратор выбирает область применения (вся организация, конкретные OU или пользователи)
6. Администратор устанавливает срок хранения (например, "хранить бессрочно" или "хранить 7 лет")
7. Администратор настраивает действие после истечения срока (удалить навсегда или оставить)
8. Система активирует правило и начинает архивирование всех файлов Drive согласно политике
9. Администратор создает "Дело" для судебного разбирательства
10. Администратор применяет "Hold" (блокировка удаления) к аккаунтам вовлеченных пользователей, предотвращая удаление любых данных
**Альтернативные сценарии:**
- Сценарий А (поиск и экспорт): Администратор выполняет поиск по ключевым словам, диапазону дат и общим дискам, затем экспортирует результаты в MBOX или PST
- Сценарий Б (поиск по Document ID): Администратор вводит до 1000 ID документов Drive для точечного экспорта конкретных файлов
- Сценарий В (Hold на общий диск): Администратор накладывает Hold на весь общий диск, блокируя удаление любых файлов всеми участниками
- Сценарий Г (аудит Vault действий): Администратор просматривает логи действий других администраторов Vault для контроля соблюдения политик
**Бизнес-правила:**
- BR-ADMIN-019: Google Vault не является резервной копией - при отсутствии правил хранения удаленные пользователями файлы уничтожаются навсегда
- BR-ADMIN-020: Hold имеет приоритет над правилами хранения и предотвращает удаление данных даже после истечения срока хранения
- BR-ADMIN-021: Экспорт из Vault может включать до 2 TB данных в одной операции
- BR-ADMIN-022: Поиск и экспорт доступны только для данных пользователей с активными или приостановленными аккаунтами
- BR-ADMIN-023: Правила хранения применяются к новым файлам немедленно, к существующим - в течение 24 часов
- BR-ADMIN-024: При удалении пользователя с активным Hold его данные сохраняются бессрочно до снятия Hold
**Результат:** Настроена политика архивирования данных Drive с возможностью поиска и экспорта для юридических целей

### FR-ADMIN-005: Управление квотами и лимитами хранилища
**Описание:** Установка персональных и групповых квот хранилища Drive для пользователей и мониторинг использования дискового пространства организации
**Роли:** Суперадминистратор, Администратор Drive
**Предусловия:**
- Наличие активной подписки Google Workspace с пулом хранилища
- Доступ к разделу "Apps → Drive и Документы" в Admin Console
- Понимание текущего использования хранилища организацией
**Основной сценарий:**
1. Администратор переходит в "Apps → Google Workspace → Drive и Документы → Настройки хранилища"
2. Администратор просматривает общую статистику использования хранилища организации
3. Администратор выбирает организационное подразделение или группу пользователей
4. Администратор активирует опцию "Установить лимит хранилища для пользователей"
5. Администратор вводит лимит (например, 50 GB на пользователя)
6. Система отображает предупреждение о последствиях для пользователей, превысивших лимит
7. Администратор подтверждает применение лимита
8. Система применяет квоту к пользователям (для Drive - немедленно при следующем изменении файла)
9. Пользователи, превысившие лимит, получают уведомление о необходимости освободить место
10. Администратор настраивает уведомления при достижении 80% и 100% квоты
**Альтернативные сценарии:**
- Сценарий А (индивидуальная квота): Администратор устанавливает уникальную квоту для конкретного пользователя, отличную от OU
- Сценарий Б (квота для общих дисков): Администратор устанавливает лимит 100 GB для каждого нового общего диска
- Сценарий В (мониторинг превышения): Администратор просматривает отчет пользователей, превысивших квоту, и принудительно удаляет файлы из корзины
- Сценарий Г (увеличение пула): При исчерпании организационного пула администратор приобретает дополнительное хранилище через консоль биллинга
**Бизнес-правила:**
- BR-ADMIN-025: Google Workspace использует пулированное хранилище - каждая лицензия добавляет квоту в общий пул организации
- BR-ADMIN-026: Пользователь, превысивший квоту, не может создавать новые файлы в Docs/Sheets/Slides и загружать файлы в Drive
- BR-ADMIN-027: Лимит загрузки составляет 750 GB в день на пользователя, независимо от квоты хранилища
- BR-ADMIN-028: Максимальный размер одного файла - 5 TB
- BR-ADMIN-029: Пользователь может иметь до 500 млн файлов и папок в своем аккаунте
- BR-ADMIN-030: Квота применяется к Gmail, Drive и Google Photos суммарно
**Результат:** Установлены квоты хранилища для контроля использования дискового пространства организацией

### FR-ADMIN-006: Настройка шифрования на стороне клиента (CSE)
**Описание:** Включение и конфигурация client-side encryption для обеспечения полного контроля над ключами шифрования данных Drive
**Роли:** Суперадминистратор
**Предусловия:**
- Лицензия Google Workspace Enterprise Plus или Education Plus
- Надстройка Assured Controls или Assured Controls Plus
- Настроен внешний поставщик ключей (Key Management Service)
- Настроен внешний провайдер идентификации (IdP)
**Основной сценарий:**
1. Администратор переходит в "Безопасность → Доступ и контроль данных → Шифрование на стороне клиента"
2. Администратор нажимает "Настроить сервис ключей"
3. Система отображает список поддерживаемых KMS (Flowcrypt, Fortanix, Futurex, Stormshield и другие)
4. Администратор выбирает поставщика ключей и вводит URL endpoint сервиса
5. Администратор настраивает подключение к внешнему IdP (для контроля доступа к ключам)
6. Система проверяет соединение с KMS и IdP
7. Администратор выбирает организационные подразделения для включения CSE
8. Администратор активирует опцию "Включить шифрование на стороне клиента по умолчанию"
9. Система применяет настройки к выбранным OU
10. Пользователи из этих OU получают возможность создавать зашифрованные документы Drive с полным контролем ключей вне Google
**Альтернативные сценарии:**
- Сценарий А (опциональное CSE): Администратор не включает CSE по умолчанию, позволяя пользователям выбирать при создании каждого документа
- Сценарий Б (внешний доступ к CSE): Администратор настраивает возможность предоставления доступа к зашифрованным файлам внешним пользователям через временные токены
- Сценарий В (отключение CSE): Администратор отключает CSE для OU, все зашифрованные файлы становятся недоступными для редактирования
- Сценарий Г (мониторинг использования): Администратор просматривает отчеты об использовании CSE в организации через Security Center
**Бизнес-правила:**
- BR-ADMIN-031: CSE шифрует данные до отправки в Google, Google не имеет доступа к ключам дешифрования
- BR-ADMIN-032: CSE поддерживается только для Google Docs, Sheets, Slides и загруженных файлов (PDF, Office)
- BR-ADMIN-033: Зашифрованные файлы не индексируются поиском Drive и не доступны для DLP сканирования

**Результат:** Настроены политики безопасности для мобильных устройств, обеспечивающие защиту корпоративных данных Drive

## Глоссарий

**Admin Console** - веб-интерфейс для управления Google Workspace, доступный по адресу admin.google.com

**Organizational Unit (OU)** - организационное подразделение, логическая группировка пользователей для применения политик

**DLP (Data Loss Prevention)** - технология предотвращения утечки конфиденциальных данных через автоматическое обнаружение и блокировку

**IRM (Information Rights Management)** - управление правами на информацию, функция DLP для запрета скачивания, печати и копирования файлов

**eDiscovery** - процесс обнаружения и сбора электронных данных для судебных разбирательств

**Hold** - юридическая блокировка удаления данных в Google Vault для сохранения доказательной базы

**CSE (Client-Side Encryption)** - шифрование на стороне клиента, когда данные шифруются до отправки в Google с использованием внешних ключей

**KMS (Key Management Service)** - внешний сервис управления ключами шифрования для CSE

**Shared Drive** - общий диск, коллективное хранилище файлов принадлежащее команде, а не отдельному пользователю

**Pooled Storage** - пулированное хранилище, общий пул дискового пространства организации

**Google Workspace Marketplace** - магазин сторонних приложений для интеграции с Google Workspace

**OAuth2 Scopes** - набор разрешений, запрашиваемых сторонними приложениями для доступа к данным через API

**GCDS (Google Cloud Directory Sync)** - инструмент для синхронизации пользователей из Active Directory в Google Workspace

**BYOD (Bring Your Own Device)** - политика использования личных устройств для рабочих задач
