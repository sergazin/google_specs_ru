# Корзина и восстановление данных (Trash & Recovery)

## Описание

Модуль управления корзиной и восстановлением данных в Google Drive, предназначенный для защиты пользователей от случайного или преднамеренного удаления файлов и папок. Обеспечивает возможность временного хранения удаленных элементов, их восстановления или окончательного удаления с освобождением пространства хранилища.

Система состоит из пяти ключевых компонентов:
1. **Перемещение в корзину** - мягкое удаление файлов и папок
2. **Автоматическая очистка корзины** - удаление элементов старше 30 дней
3. **Восстановление из корзины** - возврат файлов в исходное местоположение
4. **Окончательное удаление** - безвозвратное удаление данных
5. **Административное восстановление** - восстановление через Google Workspace Admin

## Роли пользователей

- **Владелец файла** - создатель файла/папки, имеет полные права на удаление и восстановление
- **Редактор** - может перемещать файлы в корзину только в "Моем диске", не может удалить файлы владельца
- **Просматривающий/Комментатор** - не может удалять файлы
- **Участник Shared Drive (Contributor)** - не может удалять файлы, только добавлять
- **Контент-менеджер Shared Drive (Content Manager)** - может перемещать файлы в корзину Shared Drive и восстанавливать их
- **Менеджер Shared Drive (Manager)** - может окончательно удалять файлы из корзины Shared Drive
- **Администратор Google Workspace** - может восстанавливать удаленные файлы пользователей в течение 25 дней после полного удаления

### FR-TRASH-001: Перемещение файла в корзину (Move to Trash)
**Описание:** Пользователь может переместить файл или папку в корзину, где элемент будет храниться до 30 дней или до ручного удаления.

**Роли:** Владелец файла, Редактор (с ограничениями), Контент-менеджер Shared Drive

**Предусловия:**
- Пользователь имеет право на удаление файла (является владельцем или редактором)
- Файл находится в "Моем диске" или Shared Drive, к которому у пользователя есть доступ
- Файл не заблокирован политиками администратора

**Основной сценарий:**
1. Пользователь выбирает один или несколько файлов/папок в Google Drive
2. Нажимает правой кнопкой мыши и выбирает "Удалить" или нажимает клавишу Delete
3. Альтернативно: кликает на иконку корзины в верхней панели
4. Система перемещает файл в корзину
5. Файл исчезает из исходного местоположения
6. Файл появляется в разделе "Корзина" в левой панели навигации
7. Пространство хранилища НЕ освобождается (файл продолжает занимать место)

**Альтернативные сценарии:**
- Сценарий A (Удаление из контекстного меню файла): пользователь открывает контекстное меню файла → Remove
- Сценарий B (Удаление папки с содержимым): при удалении папки все вложенные файлы и подпапки также перемещаются в корзину
- Сценарий C (Удаление файла, расшаренного с другими): файл исчезает из "Shared with me" у других пользователей, они теряют доступ

**Бизнес-правила:**
- BR-TRASH-001: Файлы в корзине продолжают занимать место в квоте хранилища пользователя
- BR-TRASH-002: При удалении папки удаляются все вложенные элементы рекурсивно
- BR-TRASH-003: Удаленный файл сохраняет свои метаданные (имя, дата создания, размер, владелец)
- BR-TRASH-004: Если владелец удаляет расшаренный файл, все пользователи теряют доступ к нему
- BR-TRASH-005: Редактор может удалить только те файлы, которые сам создал; не может удалить файлы владельца
- BR-TRASH-006: Время удаления фиксируется для отсчета 30-дневного периода
- BR-TRASH-007: Ярлыки (shortcuts) удаляются отдельно от целевых файлов

**Результат:** Файл перемещен в корзину, но не удален окончательно

### FR-TRASH-002: Просмотр содержимого корзины
**Описание:** Пользователь может просмотреть список всех удаленных файлов и папок в корзине с их метаданными.

**Роли:** Владелец файла, Любой пользователь (для своих удаленных файлов)

**Предусловия:**
- Пользователь авторизован в Google Drive

**Основной сценарий:**
1. Пользователь кликает на "Корзина" (Trash) в левой панели навигации
2. Открывается список удаленных элементов
3. Для каждого элемента отображается:
   - Название файла/папки
   - Тип (иконка: документ, таблица, папка и т.д.)
   - Владелец
   - Дата удаления (например, "Deleted Dec 15, 2025")
   - Исходное местоположение (Location)
   - Размер файла
4. Пользователь может сортировать по:
   - Дате удаления (по умолчанию, от новых к старым)
   - Названию
   - Исходному местоположению
   - Владельцу
5. Может использовать поиск для фильтрации элементов

**Альтернативные сценарии:**
- Сценарий A (Пустая корзина): если в корзине нет элементов, отображается сообщение "Корзина пуста"
- Сценарий B (Просмотр деталей файла): клик на файл открывает панель с подробной информацией

**Бизнес-правила:**
- BR-TRASH-008: В корзине отображаются только файлы, удаленные владельцем или пользователем
- BR-TRASH-009: Файлы, удаленные более 30 дней назад, автоматически скрыты (уже окончательно удалены)
- BR-TRASH-010: Корзина "Моего диска" и корзины Shared Drive разделены
- BR-TRASH-011: Счетчик в разделе "Корзина" показывает количество элементов (опционально)

**Результат:** Пользователь видит список удаленных элементов

### FR-TRASH-003: Восстановление файла из корзины (Restore from Trash)
**Описание:** Пользователь может восстановить удаленный файл или папку в исходное местоположение или в корень "Моего диска".

**Роли:** Владелец файла, Контент-менеджер/Менеджер Shared Drive

**Предусловия:**
- Файл находится в корзине
- С момента удаления прошло менее 30 дней
- Пользователь имеет право на восстановление (владелец или соответствующая роль в Shared Drive)

**Основной сценарий:**
1. Пользователь открывает раздел "Корзина"
2. Находит нужный файл или папку
3. Кликает правой кнопкой мыши на элемент
4. Выбирает "Восстановить" (Restore)
5. Альтернативно: выбирает файл и кликает на иконку "Восстановить" в верхней панели
6. Система проверяет, существует ли исходная папка
7. Файл перемещается обратно в исходное местоположение
8. Файл исчезает из корзины
9. Файл появляется в исходной папке

**Альтернативные сценарии:**
- Сценарий A (Исходная папка удалена): если родительская папка тоже в корзине, файл восстанавливается в корень "Моего диска"
- Сценарий B (Массовое восстановление): пользователь выбирает несколько файлов и восстанавливает их одновременно
- Сценарий C (Восстановление папки с содержимым): все вложенные файлы и подпапки восстанавливаются вместе с родительской папкой
- Сценарий D (Конфликт имен): если в целевой папке уже есть файл с таким же именем, создается копия с суффиксом " (1)", " (2)" и т.д.

**Бизнес-правила:**
- BR-TRASH-012: При восстановлении файл возвращается в исходное местоположение с сохранением всех метаданных
- BR-TRASH-013: Права доступа (sharing permissions) восстанавливаются полностью
- BR-TRASH-014: История версий файла сохраняется
- BR-TRASH-015: Время последней модификации не меняется при восстановлении
- BR-TRASH-016: Пользователи, у которых был доступ к файлу, снова получают его после восстановления
- BR-TRASH-017: Если файл был в нескольких папках (multiple locations), он восстанавливается во все эти местоположения
- BR-TRASH-018: Комментарии и предложения к файлу восстанавливаются

**Результат:** Файл восстановлен в исходное местоположение или корень диска

### FR-TRASH-004: Окончательное удаление файла (Delete Forever)
**Описание:** Пользователь может безвозвратно удалить файл из корзины, освобождая пространство хранилища.

**Роли:** Владелец файла, Менеджер Shared Drive

**Предусловия:**
- Файл находится в корзине
- Пользователь имеет право на окончательное удаление

**Основной сценарий:**
1. Пользователь открывает раздел "Корзина"
2. Выбирает один или несколько файлов
3. Кликает правой кнопкой мыши
4. Выбирает "Удалить навсегда" (Delete forever)
5. Система показывает диалог подтверждения: "Вы уверены? Файл будет удален навсегда и его невозможно будет восстановить"
6. Пользователь подтверждает действие
7. Файл окончательно удаляется из системы
8. Пространство хранилища освобождается

**Альтернативные сценарии:**
- Сценарий A (Отмена удаления): пользователь нажимает "Отмена" в диалоге подтверждения, файл остается в корзине
- Сценарий B (Массовое удаление): выбор нескольких файлов и удаление всех одновременно

**Бизнес-правила:**
- BR-TRASH-019: После окончательного удаления файл НЕВОЗМОЖНО восстановить штатными средствами
- BR-TRASH-020: Освобождение пространства может занять до 48 часов (видимость в квоте)
- BR-TRASH-021: Все метаданные файла удаляются
- BR-TRASH-022: История версий удаляется полностью
- BR-TRASH-023: Комментарии и предложения удаляются
- BR-TRASH-024: Sharing ссылки становятся недействительными
- BR-TRASH-025: Google Workspace администратор может восстановить файл в течение 25 дней после окончательного удаления (только для корпоративных аккаунтов)

**Результат:** Файл удален безвозвратно, пространство освобождено

### FR-TRASH-005: Очистка всей корзины (Empty Trash)
**Описание:** Пользователь может очистить всю корзину одним действием, удалив все файлы навсегда.

**Роли:** Владелец файла, Менеджер Shared Drive

**Предусловия:**
- В корзине есть хотя бы один файл

**Основной сценарий:**
1. Пользователь открывает раздел "Корзина"
2. Кликает на опцию "Очистить корзину" (Empty Trash) в верхней части экрана или в меню с тремя точками
3. Система показывает диалог подтверждения: "Навсегда удалить все элементы из корзины? Это действие нельзя отменить"
4. Показывает количество элементов и общий размер данных для удаления
5. Пользователь подтверждает действие
6. Система удаляет все файлы из корзины
7. Отображается сообщение "Корзина очищена"
8. Пространство хранилища освобождается

**Альтернативные сценарии:**
- Сценарий A (Отмена очистки): пользователь нажимает "Отмена", все файлы остаются в корзине

**Бизнес-правила:**
- BR-TRASH-026: Очистка корзины необратима
- BR-TRASH-027: Все файлы удаляются одновременно, независимо от их количества
- BR-TRASH-028: Процесс может занять время для больших объемов данных (отображается индикатор прогресса)
- BR-TRASH-029: Освобождение пространства в квоте может занять до 48 часов
- BR-TRASH-030: Операция логируется для Google Workspace аккаунтов (в Admin Console)

**Результат:** Все файлы в корзине удалены навсегда

### FR-TRASH-006: Автоматическая очистка корзины (30-дневное правило)
**Описание:** Система автоматически удаляет файлы из корзины, которые находятся там более 30 дней.

**Роли:** Система (автоматическое)

**Предусловия:**
- Файл находится в корзине 30 или более дней

**Основной сценарий:**
1. Система ежедневно проверяет дату удаления каждого файла в корзине
2. Если с момента удаления прошло 30 дней, файл помечается для автоматического удаления
3. Система выполняет окончательное удаление файла без уведомления пользователя
4. Файл исчезает из корзины
5. Пространство хранилища освобождается

**Альтернативные сценарии:**
- Сценарий A (Уведомление перед удалением): система может отправить email-уведомление за несколько дней до автоматического удаления (опционально, зависит от настроек)

**Бизнес-правила:**
- BR-TRASH-031: Период хранения в корзине - ровно 30 дней с момента перемещения в корзину
- BR-TRASH-032: Отсчет начинается с момента первого удаления (если файл удалялся, восстанавливался и снова удалялся, отсчет начинается заново)
- BR-TRASH-033: Автоматическое удаление необратимо
- BR-TRASH-034: Пользователь НЕ получает уведомление о том, что файл был автоматически удален (по умолчанию)
- BR-TRASH-035: Для Google Workspace администратор может настроить политику хранения (retention policy) для увеличения или уменьшения периода
- BR-TRASH-036: Автоматическое удаление происходит в фоновом режиме, не влияя на производительность

**Результат:** Файлы старше 30 дней автоматически удалены навсегда

### FR-TRASH-007: Корзина Shared Drive (Shared Drive Trash)
**Описание:** Shared Drive имеет собственную независимую корзину, отдельную от "Моего диска", с особыми правами доступа.

**Роли:** Контент-менеджер Shared Drive, Менеджер Shared Drive

**Предусловия:**
- Пользователь является участником Shared Drive
- Файл принадлежит Shared Drive

**Основной сценарий:**
1. Контент-менеджер или Менеджер удаляет файл из Shared Drive
2. Файл перемещается в корзину этого конкретного Shared Drive (НЕ в личную корзину пользователя)
3. Для доступа к корзине Shared Drive:
   - Пользователь открывает Shared Drive в навигации
   - Кликает на меню с тремя точками рядом с названием Shared Drive
   - Выбирает "View trash" или "Trash"
4. Открывается корзина с файлами, удаленными из этого Shared Drive
5. Контент-менеджер может восстановить файлы
6. Только Менеджер может окончательно удалить файлы

**Альтернативные сценарии:**
- Сценарий A (Ограниченный доступ): Contributors и Viewers не видят корзину Shared Drive
- Сценарий B (Восстановление файла Shared Drive): процесс аналогичен FR-TRASH-003, но файл восстанавливается в Shared Drive

**Бизнес-правила:**
- BR-TRASH-037: Каждый Shared Drive имеет собственную независимую корзину
- BR-TRASH-038: Файлы из Shared Drive НЕ попадают в личную корзину пользователя
- BR-TRASH-039: Contributors не могут удалять файлы из Shared Drive
- BR-TRASH-040: Контент-менеджеры могут удалять и восстанавливать файлы, но НЕ могут окончательно удалять
- BR-TRASH-041: Только Менеджеры могут окончательно удалять файлы из корзины Shared Drive
- BR-TRASH-042: 30-дневное правило применяется к корзине Shared Drive так же, как к личной корзине
- BR-TRASH-043: Права доступа к корзине Shared Drive определяются ролью пользователя в Shared Drive

**Результат:** Файлы Shared Drive управляются в отдельной корзине с особыми правами

### FR-TRASH-008: Удаление файла, расшаренного с другими пользователями
**Описание:** Владелец может удалить файл, к которому есть доступ у других пользователей; все теряют доступ.

**Роли:** Владелец файла

**Предусловия:**
- Пользователь является владельцем файла
- Файл расшарен с другими пользователями (editors, viewers, commenters)

**Основной сценарий:**
1. Владелец удаляет расшаренный файл (перемещает в корзину)
2. Система проверяет список пользователей с доступом
3. Файл исчезает из раздела "Shared with me" у всех пользователей
4. Пользователи теряют возможность открыть файл по ссылке
5. Sharing ссылки становятся недействительными (показывают ошибку доступа)
6. Если файл был в избранном (Starred) у других пользователей, он исчезает оттуда
7. Владелец может восстановить файл из корзины
8. При восстановлении все права доступа восстанавливаются автоматически

**Альтернативные сценарии:**
- Сценарий A (Передача владения перед удалением): владелец может передать права владения другому пользователю, после чего тот решает судьбу файла
- Сценарий B (Удаление редактором): редактор НЕ может удалить файл владельца, только убрать его из своего "Shared with me"

**Бизнес-правила:**
- BR-TRASH-044: Только владелец может удалить расшаренный файл для всех
- BR-TRASH-045: Редакторы/просматривающие могут только убрать файл из своего вида (Remove), но файл остается у владельца
- BR-TRASH-046: При удалении владельцем ВСЕ пользователи теряют доступ немедленно
- BR-TRASH-047: Sharing ссылки остаются в корзине и восстанавливаются при восстановлении файла
- BR-TRASH-048: Если файл был в нескольких папках разных пользователей, он исчезает из всех
- BR-TRASH-049: Пользователи НЕ получают уведомление о том, что файл был удален владельцем (по умолчанию)

**Результат:** Файл удален владельцем, доступ потерян у всех пользователей

### FR-TRASH-009: Поведение при удалении файла из "Shared with me"
**Описание:** Пользователь, у которого есть доступ к файлу, может убрать его из своего "Shared with me", но это не удаляет файл для владельца.

**Роли:** Редактор, Просматривающий, Комментатор

**Предусловия:**
- Файл находится в разделе "Shared with me"
- Пользователь НЕ является владельцем файла

**Основной сценарий:**
1. Пользователь открывает раздел "Shared with me"
2. Кликает правой кнопкой мыши на файл
3. Выбирает "Remove" (Удалить)
4. Система показывает диалог: "Удалить из 'Shared with me'? Файл будет удален только для вас, владелец и другие пользователи сохранят доступ"
5. Пользователь подтверждает

**1. Система хранилища и квот:**
- Файлы в корзине учитываются в общей квоте пользователя
- При приближении к лимиту система рекомендует очистить корзину
- Освобождение пространства после окончательного удаления

**2. Система поиска:**
- Поиск в корзине работает по названию и метаданным
- Глобальный поиск Drive не включает файлы из корзины
- Фильтры по дате удаления, типу файла и местоположению

**3. Sharing и права доступа:**
- При удалении владельцем все пользователи теряют доступ
- Sharing ссылки становятся неактивными
- При восстановлении права доступа восстанавливаются полностью

**4. Версионирование:**
- История версий файла сохраняется в корзине
- При восстановлении все версии восстанавливаются
- При окончательном удалении все версии удаляются

**5. Уведомления:**
- Уведомления о заполнении хранилища
- Email-уведомления администраторам о критичных операциях
- Возможность настройки уведомлений о приближении 30-дневного срока (опционально)

**6. Google Workspace Admin:**
- Административное восстановление через Admin Console
- Логирование операций удаления в Audit Log
- Передача владения файлами при удалении аккаунта
- Настройка политик хранения

**7. Google Vault:**
- Расширенное хранение данных согласно политикам
- eDiscovery поиск и экспорт
- Legal Hold для предотвращения удаления
- Архивирование для соответствия регуляторным требованиям

## Лимиты и ограничения

| Параметр | Лимит | Примечание |
|----------|-------|-----------|
| Период хранения в корзине | 30 дней | Стандартный для всех аккаунтов |
| Административное восстановление (Workspace) | 25 дней | После полного удаления из корзины |
| Восстановление после удаления аккаунта | 20 дней | Только для Google Workspace |
| Максимальное количество файлов в корзине | Неограниченно | Ограничено только квотой хранилища |
| Время освобождения квоты после удаления | До 48 часов | Может быть задержка в отображении |
| Период хранения в Google Vault | Настраивается | От 1 дня до бессрочно |
| Максимальная глубина вложенности папок | Сохраняется | При восстановлении структура полностью восстанавливается |
| Количество одновременно восстанавливаемых файлов | До 500 | За одну операцию |
| Размер файла для удаления | Неограниченно | Любой размер в рамках квоты |

## Состояния файла и переходы

```
[Активный файл в Drive]
    ↓ (Пользователь удаляет)
[В корзине - до 30 дней]
    ↓ (Восстановление)          ↓ (Окончательное удаление или 30 дней истекли)
[Восстановлен в исходное    [Окончательно удален]
 местоположение]                ↓ (Только для Workspace - в течение 25 дней)
    ↑                         [Административное восстановление]
    └──────────────────────────┘

[Файл с Vault retention policy]
    ↓ (Удаление пользователем)
[В корзине + копия в Vault]
    ↓ (Окончательное удаление)
[Удален из Drive, но остается в Vault согласно политике]
```

## Сценарии использования

### Сценарий 1: Личный пользователь со случайным удалением
```
Ситуация: Пользователь случайно удалил важную фотографию

Шаги:
1. Пользователь обнаруживает, что фотография исчезла
2. Открывает раздел "Корзина"
3. Находит фотографию по названию или дате удаления
4. Кликает "Restore"
5. Фотография возвращается в исходную папку

Результат: Файл восстановлен без потери данных
```

### Сценарий 2: Освобождение места в хранилище
```
Ситуация: Пользователь получил уведомление о заполненном хранилище

Шаги:
1. Пользователь проверяет использование хранилища
2. Обнаруживает, что 8 GB из 15 GB занято корзиной
3. Открывает корзину
4. Просматривает файлы, убеждается что они не нужны
5. Нажимает "Empty Trash"
6. Подтверждает действие
7. Через несколько часов квота обновляется, свободно 8 GB

Результат: Хранилище освобождено
```

### Сценарий 3: Командная работа в Shared Drive
```
Ситуация: Контент-менеджер случайно удалил важный документ проекта из Shared Drive

Шаги:
1. Другой участник команды замечает пропажу документа
2. Связывается с контент-менеджером
3. Контент-менеджер открывает Shared Drive
4. Кликает на меню Shared Drive → View Trash
5. Находит удаленный документ
6. Восстанавливает его
7. Документ возвращается в исходную папку Shared Drive
8. Все участники снова имеют доступ

Результат: Документ восстановлен, работа команды продолжается
```

### Сценарий 4: Корпоративное администрирование
```
Ситуация: Сотрудник покинул компанию, его аккаунт нужно удалить, но файлы сохранить

Шаги:
1. HR уведомляет IT о увольнении сотрудника
2. Администратор открывает Google Workspace Admin Console
3. Находит аккаунт сотрудника
4. Выбирает опцию "Transfer ownership of Drive files"
5. Указывает email менеджера как нового владельца
6. Подтверждает передачу
7. Все файлы сотрудника переходят к менеджеру
8. Аккаунт сотрудника удаляется
9. Менеджер получает уведомление о полученных файлах

Результат: Данные сохранены, аккаунт удален безопасно
```

### Сценарий 5: Восстановление через Google Vault
```
Ситуация: Юридический отдел требует восстановить файл, удаленный 40 дней назад

Шаги:
1. Compliance офицер получает запрос от юристов
2. Проверяет, что к файлу применена retention policy в Vault
3. Открывает Google Vault
4. Вводит критерии поиска (имя файла, владелец, дата)
5. Находит файл в архиве Vault
6. Выбирает опцию "Restore" или "Export"
7. Файл восстанавливается в Drive пользователя или экспортируется
8. Юридический отдел получает доступ к данным

Результат: Файл восстановлен благодаря политике хранения
```

### Сценарий 6: Удаление расшаренного файла владельцем
```
Ситуация: Владелец проекта завершил работу и удаляет все файлы проекта, расшаренные с командой

Шаги:
1. Владелец выбирает папку проекта с 50 файлами
2. Нажимает Delete
3. Папка и все файлы перемещаются в корзину владельца
4. Все участники команды теряют доступ к файлам
5. Файлы исчезают из "Shared with me" у всех
6. Через 30 дней файлы автоматически удаляются навсегда
7. Пространство в квоте владельца освобождается

Результат: Проект закрыт, данные удалены, хранилище освобождено
```

```
┌─────────────────────────────────────────────────────────────────┐
│                      ЖИЗНЕННЫЙ ЦИКЛ ФАЙЛА                        │
└─────────────────────────────────────────────────────────────────┘

[Создан/Загружен]
       │
       ▼
[Активен в Drive] ◄──────┐
       │                 │
       │ Delete          │ Restore
       ▼                 │
[В корзине] ─────────────┘
       │
       ├─────► [Restore] → [Активен в Drive]
       │
       ├─────► [Delete Forever] → [Окончательно удален]
       │
       └─────► [30 дней истекло] → [Автоматически удален]
                                          │
                                          ▼
                            [Workspace Admin Recovery]
                                   (25 дней)
                                          │
                                          ▼
                                  [Восстановлен] или
                                  [Безвозвратно удален]

С Google Vault:
[Активен в Drive] + [Копия в Vault]
       │
       ▼ Delete
[В корзине] + [Копия в Vault]
       │
       ▼ Delete Forever
[Окончательно удален] + [Остается в Vault согласно policy]
```
