# Совместная работа и управление доступом (Sharing & Collaboration)

## Описание

Модуль совместной работы и управления доступом в Google Drive, предназначенный для организации командного взаимодействия с файлами и папками. Обеспечивает гибкую систему разграничения прав доступа, позволяет делиться содержимым через ссылки или прямые приглашения, управлять разрешениями для отдельных пользователей, групп и организаций, а также работать с общими дисками для команд.

Система состоит из восьми ключевых компонентов:
1. **Общий доступ по ссылке** - создание и управление публичными и ограниченными ссылками
2. **Приглашение пользователей** - добавление конкретных людей с разными уровнями доступа
3. **Уровни разрешений** - управление правами просмотра, комментирования и редактирования
4. **Управление доступом групп** - предоставление доступа группам пользователей
5. **Временные ограничения** - установка срока действия разрешений
6. **Общие диски (Shared Drives)** - коллективное владение файлами
7. **Запросы на доступ** - обработка запросов от пользователей без доступа
8. **Организационные политики** - корпоративное управление доступом

## Роли пользователей

### Для обычных файлов и папок (My Drive):
- **Владелец (Owner)** - создатель файла, имеет полный контроль, может передать владение, удалить файл
- **Редактор (Editor)** - может редактировать содержимое, загружать файлы в папку, управлять доступом (если разрешено владельцем)
- **Комментатор (Commenter)** - может оставлять комментарии и предложения, но не редактировать
- **Читатель (Viewer)** - может только просматривать и скачивать файлы

### Для общих дисков (Shared Drives):
- **Менеджер (Manager)** - полный контроль: управление файлами, участниками, настройками диска
- **Контент-менеджер (Content Manager)** - управление файлами: создание, редактирование, удаление, перемещение
- **Участник (Contributor)** - создание и редактирование файлов, но без права удаления
- **Комментатор (Commenter)** - добавление комментариев без редактирования
- **Читатель (Viewer)** - только просмотр содержимого

### Администраторы:
- **Администратор Google Workspace** - управление политиками доступа, ограничениями внешнего доступа, настройками общих дисков для организации

### FR-SHR-001: Создание ссылки для общего доступа (Create Shareable Link)
**Описание:** Пользователь может создать ссылку на файл или папку, по которой другие пользователи смогут получить доступ к содержимому без необходимости отдельного приглашения.

**Роли:** Владелец, Редактор (если владелец разрешил управление доступом)

**Предусловия:**
- Пользователь авторизован в Google Drive
- Пользователь имеет права на управление доступом к файлу/папке
- Организационные политики разрешают создание общих ссылок

**Основной сценарий:**
1. Пользователь открывает файл или папку в Google Drive
2. Нажимает кнопку "Share" (Поделиться) в правом верхнем углу
3. Открывается диалог управления доступом
4. В разделе "General access" нажимает на текущий статус (по умолчанию "Restricted")
5. Раскрывается меню с опциями доступа: "Restricted", "Anyone with the link", "Anyone in [Organization]"
6. Выбирает "Anyone with the link" для создания публичной ссылки
7. Выбирает уровень доступа из выпадающего списка: Viewer, Commenter или Editor

**Альтернативные сценарии:**
- Сценарий A (Ограниченная ссылка для организации): вместо "Anyone with the link" выбирает "Anyone in [Organization]" - доступ только для сотрудников компании
- Сценарий B (Копирование ссылки): после создания нажимает "Copy link" - ссылка копируется в буфер обмена
- Сценарий C (Отправка через email): нажимает кнопку с иконкой конверта для отправки ссылки по электронной почте

**Бизнес-правила:**
- BR-SHR-001: Ссылка остается активной до тех пор, пока владелец не изменит настройки доступа
- BR-SHR-002: При выборе "Anyone with the link" файл становится доступен всем, кто знает URL
- BR-SHR-003: Формат ссылки: https://drive.google.com/file/d/{fileId}/view или /open или /edit
- BR-SHR-004: Для папок используется формат: https://drive.google.com/drive/folders/{folderId}
- BR-SHR-005: Администраторы организации могут запретить создание публичных ссылок
- BR-SHR-006: Изменение уровня доступа по ссылке применяется ко всем, кто получит эту ссылку

**Результат:** Создана ссылка для общего доступа с выбранным уровнем разрешений

### FR-SHR-002: Приглашение конкретных пользователей (Invite Specific Users)
**Описание:** Владелец или редактор с соответствующими правами может пригласить конкретных пользователей Google, указав их email-адреса, и назначить индивидуальные уровни доступа.

**Роли:** Владелец, Редактор (если разрешено)

**Предусловия:**
- Пользователь авторизован в Google Drive
- Пользователь имеет права на управление доступом к ресурсу
- Email-адреса приглашаемых пользователей известны

**Основной сценарий:**
1. Пользователь открывает диалог "Share" для файла или папки
2. В поле "Add people, groups, or calendar events" начинает вводить email-адрес
3. Система предлагает автодополнение из контактов Google и организации
4. Выбирает пользователя из списка или вводит email полностью
5. Выбирает уровень доступа: Viewer, Commenter или Editor
6. Опционально добавляет сообщение в текстовое поле "Message"
7. Нажимает кнопку "Send" (Отправить)

**Альтернативные сценарии:**
- Сценарий A (Множественное приглашение): вводит несколько email-адресов через запятую или пробел - все получат одинаковый уровень доступа
- Сценарий B (Отключение уведомления): снимает галочку "Notify people" - приглашенные не получат email-уведомление
- Сценарий C (Приглашение без Google-аккаунта): если email не связан с Google-аккаунтом, пользователь получит приглашение создать аккаунт
- Сценарий D (Изменение сообщения): редактирует текст сообщения перед отправкой

**Бизнес-правила:**
- BR-SHR-007: Email-уведомление включает ссылку на файл, имя отправителя и опциональное сообщение
- BR-SHR-008: Приглашенные пользователи видят файл в разделе "Shared with me"
- BR-SHR-009: Можно пригласить до 200 пользователей за одну операцию
- BR-SHR-010: Внешние пользователи (не из организации) могут быть заблокированы политикой
- BR-SHR-011: Владелец всегда может отозвать доступ у любого приглашенного пользователя
- BR-SHR-012: Каждому пользователю можно назначить индивидуальный уровень доступа

**Результат:** Пользователи получили персональные приглашения с доступом к ресурсу

### FR-SHR-003: Управление уровнями разрешений (Manage Permission Levels)
**Описание:** Владелец или уполномоченный редактор может изменять уровни доступа для уже приглашенных пользователей, повышая или понижая их права.

**Роли:** Владелец, Редактор (с правами управления доступом)

**Предусловия:**
- Пользователь имеет права на управление доступом
- К файлу/папке уже предоставлен доступ другим пользователям
- Пользователь открыл диалог управления доступом

**Основной сценарий:**
1. Пользователь открывает диалог "Share" для файла или папки
2. Видит список "People with access" - всех пользователей с доступом
3. Находит нужного пользователя в списке
4. Нажимает на выпадающий список с текущим уровнем доступа (Viewer/Commenter/Editor)
5. Выбирает новый уровень доступа из списка
6. Изменение применяется мгновенно
7. Система отображает уведомление об изменении разрешений

**Альтернативные сценарии:**
- Сценарий A (Полное удаление доступа): выбирает "Remove access" в выпадающем меню - пользователь теряет доступ к файлу
- Сценарий B (Передача владения): владелец выбирает "Make owner" - другой пользователь становится владельцем
- Сценарий C (Уведомление об изменении): опционально отправляет уведомление пользователю об изменении его прав

**Бизнес-правила:**
- BR-SHR-013: Изменение разрешений применяется мгновенно без задержки
- BR-SHR-014: Понижение прав с Editor до Viewer немедленно блокирует возможность редактирования
- BR-SHR-015: Только владелец может передать владение другому пользователю
- BR-SHR-016: При передаче владения предыдущий владелец становится редактором
- BR-SHR-017: Нельзя понизить свои собственные права, если вы единственный владелец
- BR-SHR-018: Для файлов Google Workspace (Docs, Sheets) редактор может работать в реальном времени

**Результат:** Уровень доступа пользователя изменен согласно выбору

### FR-SHR-004: Предоставление доступа группе (Share with Group)
**Описание:** Владелец может предоставить доступ целой группе пользователей Google Groups, вместо индивидуального добавления каждого участника.

**Роли:** Владелец, Редактор (с правами управления доступом)

**Предусловия:**
- Существует группа Google Groups
- Пользователь знает email-адрес группы
- Пользователь имеет права на управление доступом к ресурсу

**Основной сценарий:**
1. Пользователь открывает диалог "Share" для файла или папки
2. В поле "Add people, groups..." вводит email-адрес группы (например, team@company.com)
3. Система распознает, что это группа, и показывает иконку группы
4. Выбирает группу из автодополнения
5. Назначает уровень доступа для всей группы: Viewer, Commenter или Editor
6. Опционально добавляет сообщение для участников группы
7. Нажимает "Send"

**Альтернативные сценарии:**
- Сценарий A (Автоматическое добавление новых участников): когда в группу добавляются новые пользователи, они автоматически получают доступ
- Sценарий B (Удаление доступа группы): удаляет группу из списка доступа - все участники теряют доступ
- Сценарий C (Индивидуальное переопределение): добавляет отдельного участника группы с другим уровнем доступа - персональные права имеют приоритет

**Бизнес-правила:**
- BR-SHR-019: Все участники группы получают одинаковый уровень доступа
- BR-SHR-020: Новые участники, добавленные в группу позже, автоматически получают доступ
- BR-SHR-021: Удаленные из группы пользователи автоматически теряют доступ
- BR-SHR-022: Индивидуальные разрешения имеют приоритет над групповыми
- BR-SHR-023: Владелец группы не влияет на права доступа к файлу
- BR-SHR-024: Группы могут быть вложенными - вложенные участники также получают доступ

**Результат:** Все участники группы получили доступ к ресурсу с назначенным уровнем разрешений

### FR-SHR-005: Установка срока действия доступа (Set Access Expiration)
**Описание:** Владелец может установить дату истечения срока действия доступа для конкретных пользователей или групп, после которой доступ автоматически отзывается.

**Роли:** Владелец, Редактор (с правами управления доступом)

**Предусловия:**
- Пользователь имеет права на управление доступом
- Доступ уже предоставлен пользователю или группе
- Функция доступна для аккаунтов Google Workspace (не для личных аккаунтов Gmail)

**Основной сценарий:**
1. Пользователь открывает диалог "Share" для файла или папки
2. Находит пользователя в списке "People with access"
3. Нажимает на иконку настроек (три точки) рядом с уровнем доступа
4. Выбирает "Give temporary access" (Предоставить временный доступ)
5. Открывается календарь выбора даты истечения срока
6. Выбирает дату истечения (не более 1 года в будущем)
7. Нажимает "Save" (Сохранить)

**Альтернативные сценарии:**
- Сценарий A (Стандартный срок 30 дней): нажимает "Send" без выбора даты - автоматически устанавливается срок 30 дней
- Сценарий B (Изменение срока): редактирует дату истечения для уже установленного временного доступа
- Сценарий C (Отмена ограничения по времени): удаляет дату истечения - доступ становится постоянным
- Сценарий D (Уведомление о истечении): за 7 дней до истечения владелец и пользователь получают уведомления

**Бизнес-правила:**
- BR-SHR-025: Срок действия может быть установлен только для роли Viewer на папки
- BR-SHR-026: Для файлов срок действия можно установить только для ролей Viewer и Commenter
- BR-SHR-027: Максимальный срок действия - 1 год от текущей даты
- BR-SHR-028: При истечении срока доступ отзывается автоматически в 00:00 UTC указанной даты
- BR-SHR-029: Если изменить роль пользователя на Editor, срок действия автоматически удаляется
- BR-SHR-030: Уведомления об истечении отправляются за 7 дней и в день истечения

**Результат:** Установлен срок действия доступа, после которого права будут автоматически отозваны

### FR-SHR-006: Создание и управление общим диском (Create and Manage Shared Drive)
**Описание:** Пользователи Google Workspace могут создавать общие диски для командной работы, где файлы принадлежат всей команде, а не отдельным пользователям.

**Роли:** Менеджер общего диска, Администратор Google Workspace

**Предусловия:**
- Пользователь имеет аккаунт Google Workspace (не личный Gmail)
- Администратор организации разрешил создание общих дисков
- Пользователь имеет права на создание общих дисков

**Основной сценарий:**
1. Пользователь открывает Google Drive и переходит в раздел "Shared drives" в левой панели
2. Нажимает кнопку "+ New" (Создать) в верхней части списка общих дисков
3. Вводит название общего диска (например, "Marketing Team 2025")
4. Нажимает "Create" (Создать)
5. Открывается диалог добавления участников
6. Добавляет участников, указывая их email-адреса
7. Назначает каждому участнику роль: Manager, Content Manager, Contributor, Commenter или Viewer

**Альтернативные сценарии:**
- Сценарий A (Добавление участников позже): создает диск без участников, добавляет их позже через настройки
- Сценарий B (Настройка ограничений доступа): в настройках диска включает "Prevent people outside the organization from being added" - блокирует внешних пользователей
- Сценарий C (Ограничение копирования): включает опцию "Prevent commenters and viewers from downloading, printing, and copying files"
- Sценарий D (Удаление общего диска): менеджер может удалить пустой диск или диск с файлами (файлы перемещаются в корзину)

**Бизнес-правила:**
- BR-SHR-031: Файлы в общем диске принадлежат всей команде, а не создателю файла
- BR-SHR-032: Если участник покидает организацию, его файлы остаются в общем диске
- BR-SHR-033: Только менеджеры могут добавлять и удалять участников
- BR-SHR-034: Контент-менеджеры могут управлять файлами, но не участниками
- BR-SHR-035: Общий диск должен иметь минимум одного менеджера
- BR-SHR-036: Максимальное количество участников в общем диске - 600

**Результат:** Создан общий диск с назначенными участниками и настройками доступа

### FR-SHR-007: Обработка запроса на доступ (Handle Access Request)
**Описание:** Когда пользователь открывает ссылку на файл с ограниченным доступом, он может запросить разрешение, а владелец может одобрить или отклонить запрос.

**Роли:** Запрашивающий (любой пользователь), Владелец, Редактор (с правами управления доступом)

**Предусловия:**
- Файл/папка имеет ограниченный доступ (не публичная ссылка)
- Пользователь знает ссылку, но не имеет доступа
- Владелец не отключил возможность запроса доступа

**Основной сценарий:**
1. Пользователь переходит по ссылке на файл без доступа
2. Видит страницу "You need access" (Вам нужен доступ)
3. Отображается информация: название файла, владелец, опциональное описание
4. Нажимает кнопку "Request access" (Запросить доступ)
5. Опционально добавляет сообщение для владельца
6. Нажимает "Send request" (Отправить запрос)
7. Владелец получает email-уведомление о запросе

**Альтернативные сценарии:**
- Сценарий A (Одобрение запроса): владелец открывает уведомление, нажимает "Grant access", выбирает уровень доступа (Viewer/Commenter/Editor), пользователь получает доступ
- Сценарий B (Отклонение запроса): владелец нажимает "Deny" - пользователь получает уведомление об отказе
- Сценарий C (Игнорирование запроса): владелец не отвечает - запрос остается в списке ожидающих
- Сценарий D (Автоматическое одобрение): для пользователей организации владелец может настроить автоматическое предоставление доступа Viewer

**Бизнес-правила:**
- BR-SHR-037: Запрос доступа отправляется всем пользователям с правами управления доступом
- BR-SHR-038: Владелец может отключить возможность запроса доступа в настройках
- BR-SHR-039: Email-уведомление содержит ссылку для быстрого одобрения/отклонения
- BR-SHR-040: После одобрения пользователь получает email с ссылкой на файл
- BR-SHR-041: Запросы хранятся в истории и могут быть просмотрены позже
- BR-SHR-042: Один пользователь может запросить доступ только один раз, повторный запрос блокируется

**Результат:** Запрос на доступ отправлен владельцу или обработан согласно его решению

### FR-SHR-008: Настройка организационных политик доступа (Configure Organizational Sharing Policies)
**Описание:** Администратор Google Workspace может установить политики доступа на уровне организации, ограничивающие возможности пользователей по предоставлению доступа к файлам.

**Роли:** Администратор Google Workspace

**Предусловия:**
- Пользователь имеет права администратора в Google Workspace Admin Console
- Организация использует платный аккаунт Google Workspace

**Основной сценарий:**
1. Администратор открывает Google Workspace Admin Console (admin.google.com)
2. Переходит в раздел Apps → Google Workspace → Drive and Docs
3. Выбирает подраздел "Sharing settings" (Настройки общего доступа)
4. Выбирает организационное подразделение (OU) для применения политики
5. Настраивает параметры внешнего доступа: "External sharing" - включить/отключить
6. Устанавливает ограничения на типы ссылок: разрешить/запретить публичные ссылки
7. Нажимает "Save" (Сохранить)

**Альтернативные сценарии:**
- Сценарий A (Блокировка внешнего доступа): отключает "Allow users to share files outside the organization" - сотрудники не могут делиться с внешними пользователями
- Сценарий B (Ограничение на скачивание): включает "Prevent viewers and commenters from downloading, printing, and copying files" - запрет на экспорт данных
- Сценарий C (Предупреждение о внешнем доступе): включает "Display a warning when sharing outside the organization" - показывает предупреждение при попытке внешнего доступа
- Сценарий D (Автоматическое истечение ссылок): настраивает автоматическое истечение публичных ссылок через заданный период

**Бизнес-правила:**
- BR-SHR-043: Организационные политики имеют приоритет над индивидуальными настройками пользователей
- BR-SHR-044: Политики могут быть настроены для разных подразделений (OU) отдельно
- BR-SHR-045: Изменения политик применяются в течение 24 часов
- BR-SHR-046: Администратор может просматривать все файлы с внешним доступом в организации
- BR-SHR-047: Политики применяются как к My Drive, так и к Shared Drives
- BR-SHR-048: Можно настроить белый список доменов для внешнего доступа

**Результат:** Установлены организационные политики доступа, ограничивающие возможности предоставления доступа для пользователей

### FR-SHR-009: Настройка дополнительных ограничений безопасности (Configure Advanced Security Restrictions)
**Описание:** Владелец файла или администратор могут установить дополнительные ограничения безопасности для предотвращения нежелательных действий с общим содержимым.

**Роли:** Владелец, Администратор Google Workspace

**Предусловия:**
- Пользователь имеет права владельца на файл/папку
- Доступ к файлу предоставлен другим пользователям
- Для некоторых ограничений требуется Google Workspace (не личный аккаунт)

**Основной сценарий:**
1. Пользователь открывает диалог "Share" для файла
2. Нажимает на иконку шестеренки (Settings) в правом верхнем углу диалога
3. Открывается раздел "General access settings"
4. Видит опции ограничений: "Viewers and commenters can see the option to download, print, and copy"
5. Снимает галочку для блокировки скачивания и печати
6. Включает опцию "Disable options to download, print, and copy for commenters and viewers"
7. Нажимает "Done" (Готово)

**Альтернативные сценарии:**
- Сценарий A (Запрет редакторам изменять доступ): снимает галочку "Editors can change permissions and share" - только владелец может управлять доступом
- Сценарий B (Блокировка добавления новых пользователей): для общего диска менеджер отключает возможность контент-менеджерам добавлять участников
- Sценарий C (Предотвращение копирования структуры): включает защиту от копирования папки с сохранением разрешений
- Сценарий D (Водяной знак): для Google Workspace Enterprise включает опцию водяных знаков с email просматривающего

**Бизнес-правила:**
- BR-SHR-049: Блокировка скачивания применяется только к ролям Viewer и Commenter
- BR-SHR-050: Редакторы всегда могут скачивать файлы независимо от ограничений
- BR-SHR-051: Блокировка скачивания не защищает от скриншотов и фотографирования экрана
- BR-SHR-052: Для файлов Google Workspace (Docs, Sheets, Slides) ограничения более эффективны
- BR-SHR-053: Водяные знаки доступны только в Google Workspace Enterprise и Education Plus
- BR-SHR-054: Водяной знак содержит email просматривающего и дату/время доступа

**Результат:** Установлены дополнительные ограничения безопасности для защиты содержимого от нежелательного распространения

### FR-SHR-010: Управление доступом к папке с ограниченным доступом (Limited Access Folder Management)
**Описание:** Владелец папки или менеджер общего диска может создать вложенную папку с ограниченным доступом, доступную только определенным пользователям, даже если родительская папка доступна многим.

**Роли:** Владелец папки, Менеджер общего диска

**Предусловия:**
- Пользователь имеет права на создание папок
- Функция "Limited access" доступна (внедрена с февраля 2025)
- Аккаунт Google Workspace (функция недоступна для личных аккаунтов)

**Основной сценарий:**
1. Пользователь создает новую папку внутри общей папки или общего диска
2. Нажимает правой кнопкой на созданную папку
3. Выбирает "Share" → "Restrict access to this folder"
4. Система показывает предупреждение о том, что папка станет доступна только добавленным пользователям
5. Нажимает "Continue" (Продолжить)
6. Добавляет конкретных пользователей или группы, которые должны иметь доступ
7. Назначает уровни доступа для каждого пользователя

**Альтернативные сценарии:**
- Сценарий A (Добавление доступа позже): создает ограниченную папку без пользователей, добавляет их позже
- Сценарий B (Снятие ограничения): владелец может удалить ограничение и вернуть наследование прав от родительской папки
- Сценарий C (Запрос доступа к ограниченной папке): пользователи с доступом к родительской папке могут запросить доступ к ограниченной
- Сценарий D (Перемещение в ограниченную папку): при перемещении файла в ограниченную папку он становится доступен только её участникам

**Бизнес-правила:**
- BR-SHR-055: Ограниченная папка не наследует разрешения от родительской папки
- BR-SHR-056: Пользователи родительской папки не видят содержимое ограниченной папки
- BR-SHR-057: Файлы в ограниченной папке доступны только явно добавленным пользователям
- BR-SHR-058: Начиная с сентября 2025 нельзя устанавливать разные права на отдельные файлы внутри общей папки
- BR-SHR-059: Ограниченная папка отображается с иконкой замка для пользователей без доступа
- BR-SHR-060: Менеджеры общего диска всегда имеют доступ ко всем ограниченным папкам

**Результат:** Создана папка с ограниченным доступом, изолированная от разрешений родительской структуры

### FR-SHR-011: Передача владения файлом (Transfer File Ownership)
**Описание:** Владелец файла может передать полное владение другому пользователю, сохранив за собой права редактора или полностью потеряв доступ.

**Роли:** Владелец

**Предусловия:**
- Пользователь является владельцем файла или папки
- Новый владелец имеет аккаунт Google
- Для некоторых организаций передача владения может быть ограничена администратором

**Основной сценарий:**
1. Пользователь открывает диалог "Share" для файла
2. Находит пользователя, которому хочет передать владение, в списке доступа
3. Нажимает на выпадающий список с текущим уровнем доступа
4. Выбирает "Make owner" (Сделать владельцем)
5. Система показывает подтверждение: "Transfer ownership to [User]?"
6. Подтверждает передачу, нажимая "Yes" (Да)
7. Новый владелец получает email-уведомление о передаче владения

**Альтернативные сценарии:**
- Сценарий A (Отказ от доступа): при передаче владения текущий владелец может выбрать "Remove my access after transfer" - полностью теряет доступ
- Сценарий B (Сохранение прав редактора): по умолчанию прежний владелец становится редактором
- Сценарий C (Передача папки): при передаче владения папкой все вложенные файлы, созданные владельцем, также передаются
- Sценарий D (Отмена передачи): новый владелец может передать владение обратно

**Бизнес-правила:**
- BR-SHR-061: Новый владелец получает полный контроль над файлом, включая право удаления
- BR-SHR-062: Прежний владелец автоматически становится редактором, если не выбрано иное
- BR-SHR-063: Нельзя передать владение пользователю, не имеющему текущего доступа к файлу
- BR-SHR-064: Передача владения необратима без согласия нового владельца
- BR-SHR-065: При передаче папки права на вложенные файлы других владельцев не изменяются
- BR-SHR-066: В организациях администратор может ограничить передачу владения только внутри организации

**Результат:** Владение файлом передано новому владельцу, права прежнего владельца изменены

### FR-SHR-012: Просмотр и аудит разрешений (View and Audit Permissions)
**Описание:** Владелец, администратор или пользователи с соответствующими правами могут просматривать полный список всех пользователей и групп, имеющих доступ к файлу, а также историю изменений доступа.

**Роли:** Владелец, Администратор Google Workspace, Редактор (с правами управления доступом)

**Предусловия:**
- Пользователь имеет права на просмотр настроек доступа
- К файлу предоставлен доступ одному или нескольким пользователям

**Основной сценарий:**
1. Пользователь открывает файл в Google Drive
2. Нажимает кнопку "Share" в правом верхнем углу
3. Видит раздел "People with access" со списком всех пользователей
4. Для каждого пользователя отображается: имя, email, аватар, уровень доступа, дата добавления
5. Нажимает на иконку "Details" (информация) для просмотра дополнительных сведений
6. Видит: кто предоставил доступ, когда, наличие срока истечения
7. Может прокручивать список для просмотра всех участников

**Альтернативные сценарии:**
- Сценарий A (Просмотр истории изменений): администратор открывает Activity dashboard в Admin Console для просмотра всех изменений доступа
- Сценарий B (Фильтрация по типу доступа): использует фильтр для отображения только редакторов или только читателей
- Сценарий C (Экспорт списка доступа): администратор экспортирует отчет о всех разрешениях в CSV
- Sценарий D (Поиск конкретного пользователя): использует поле поиска для быстрого нахождения пользователя в длинном списке

**Бизнес-правила:**
- BR-SHR-067: Список доступа показывает как прямые, так и унаследованные права (через группы или папки)
- BR-SHR-068: Для пользователей с доступом через группу отображается название группы
- BR-SHR-069: Владелец всегда отображается в верхней части списка
- BR-SHR-070: Администраторы могут просматривать разрешения для всех файлов в организации
- BR-SHR-071: История изменений доступа хранится неограниченно долго для аудита
- BR-SHR-072: В списке отображаются также pending requests (ожидающие запросы на доступ)

**Результат:** Пользователь получил полную информацию о всех имеющих доступ к ресурсу и истории изменений

## Нефункциональные требования

### Производительность
- **NFR-SHR-001**: Изменение разрешений должно применяться мгновенно (менее 1 секунды)
- **NFR-SHR-002**: Открытие диалога управления доступом должно происходить менее чем за 2 секунды
- **NFR-SHR-003**: Email-уведомления о предоставлении доступа должны отправляться в течение 5 минут
- **NFR-SHR-004**: Система должна поддерживать одновременное предоставление доступа 200 пользователям без деградации производительности

### Безопасность
- **NFR-SHR-005**: Все операции по управлению доступом должны логироваться для аудита
- **NFR-SHR-006**: Ссылки для общего доступа должны быть криптографически стойкими (минимум 128 бит энтропии)
- **NFR-SHR-007**: Система должна поддерживать двухфакторную аутентификацию для доступа к конфиденциальным файлам
- **NFR-SHR-008**: При внешнем доступе должно отображаться предупреждение (если включено администратором)

### Совместимость
- **NFR-SHR-009**: Управление доступом должно работать во всех современных браузерах (Chrome, Firefox, Safari, Edge)
- **NFR-SHR-010**: Мобильные приложения (iOS, Android) должны поддерживать все функции управления доступом
- **NFR-SHR-011**: API для управления разрешениями должен быть доступен для интеграции с внешними системами

### Масштабируемость
- **NFR-SHR-012**: Общий диск должен поддерживать до 600 участников без потери производительности
- **NFR-SHR-013**: Файл может иметь до 600 прямых разрешений (не считая унаследованных)
- **NFR-SHR-014**: Система должна обрабатывать до 100,000 запросов на доступ в день для крупных организаций

### Удобство использования
- **NFR-SHR-015**: Интерфейс управления доступом должен быть интуитивно понятен без обучения
- **NFR-SHR-016**: Критические действия (передача владения, удаление доступа) должны требовать подтверждения
- **NFR-SHR-017**: Все уведомления должны содержать прямые ссылки для выполнения действий (одобрение, отказ)

## Интеграции

### Внутренние интеграции Google:
- **Google Groups** - синхронизация участников групп для автоматического управления доступом
- **Google Workspace Admin Console** - централизованное управление политиками
- **Google Calendar** - интеграция для предоставления доступа к файлам участникам событий
- **Gmail** - отправка уведомлений и приглашений по email
- **Google Docs/Sheets/Slides** - совместное редактирование в реальном времени

### Внешние интеграции:
- **SAML/SSO** - интеграция с корпоративными системами единого входа
- **Active Directory** - синхронизация пользователей и групп
- **DLP (Data Loss Prevention)** - контроль за распространением конфиденциальной информации
- **Third-party security tools** - интеграция с системами защиты от утечек данных

## Технические ограничения

- **TL-SHR-001**: Максимум 600 прямых разрешений на файл (не включая унаследованные)
- **TL-SHR-002**: Максимум 600 участников в одном общем диске
- **TL-SHR-003**: Максимум 200 пользователей можно пригласить одновременно за одну операцию
- **TL-SHR-004**: Максимальный срок действия временного доступа - 1 год
- **TL-SHR-005**: Длина сообщения при приглашении - до 5000 символов
- **TL-SHR-006**: Публичные ссылки имеют ID длиной 28-44 символа
- **TL-SHR-007**: Изменения организационных политик применяются в течение 24 часов

## Метрики успеха

- **Количество файлов с общим доступом** - индикатор активности совместной работы
- **Время отклика на запросы доступа** - средняя скорость обработки запросов владельцами
- **Процент файлов с временными ограничениями** - показатель использования функций безопасности
- **Количество активных общих дисков** - индикатор командной работы
- **Процент внешнего доступа** - мониторинг распространения данных за пределы организации
- **Количество отозванных доступов** - индикатор управления жизненным циклом разрешений

## Требования к безопасности и приватности

### Защита данных:
- Все операции по управлению доступом логируются в audit log
- Ссылки для общего доступа должны быть непредсказуемыми (использование UUID)
- Поддержка шифрования в состоянии покоя и при передаче (TLS 1.3+)
- Возможность полного удаления доступа при увольнении сотрудника

### Соответствие регуляторным требованиям:
- **GDPR** - пользователи могут запросить список всех, с кем они поделились файлами
- **HIPAA** - для медицинских организаций доступны расширенные ограничения доступа
- **SOC 2** - полное логирование всех операций по управлению доступом
- **ISO 27001** - соответствие стандартам управления информационной безопасностью

### Контроль распространения:
- Администраторы могут блокировать внешний доступ
- Возможность установки водяных знаков на документы (Enterprise)
- Предотвращение скачивания, печати и копирования для читателей
- Автоматические уведомления при предоставлении доступа внешним пользователям
