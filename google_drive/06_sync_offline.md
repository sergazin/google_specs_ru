# Синхронизация и офлайн-режим

## Описание

Модуль синхронизации и офлайн-доступа Google Drive обеспечивает непрерывную работу с файлами независимо от наличия интернет-соединения. Система автоматически синхронизирует изменения между облаком и локальными устройствами, предоставляет доступ к файлам в офлайн-режиме, управляет конфликтами при одновременном редактировании и оптимизирует использование дискового пространства через потоковую передачу. Модуль включает выборочную синхронизацию, резервное копирование папок компьютера, управление кешем и интеллектуальное предсказание файлов для офлайн-доступа. Все операции выполняются прозрачно для пользователя с минимальным влиянием на производительность системы.

## Роли пользователей

- **Обычный пользователь (Free User)** - имеет доступ к базовой синхронизации, ограниченный офлайн-доступ (только Google Docs, Sheets, Slides), 15 ГБ облачного хранилища.
- **Google One подписчик** - расширенное хранилище (100 ГБ - 2 ТБ), приоритет в синхронизации, расширенные возможности резервного копирования.
- **Google Workspace пользователь (Business)** - неограниченное хранилище (для команд 5+ человек), расширенные политики синхронизации, централизованное управление, аудит синхронизации.
- **Администратор Google Workspace** - может управлять политиками синхронизации для организации, контролировать доступ к офлайн-режиму, устанавливать ограничения на объем синхронизации.
- **Система синхронизации** - автоматически управляет синхронизацией, разрешает конфликты, оптимизирует использование сетевых ресурсов.

## Функциональные требования

### FR-SYNC-001: Установка и настройка Google Drive для рабочего стола

**Описание:** Пользователь устанавливает приложение Google Drive для рабочего стола (Google Drive for Desktop) для синхронизации файлов между компьютером и облаком.

**Роли:** Обычный пользователь, Google One подписчик, Google Workspace пользователь

**Предусловия:**
- Пользователь имеет учетную запись Google
- Операционная система: Windows 10+, macOS 10.15+ или Chrome OS
- Наличие интернет-соединения для первоначальной установки
- Минимум 2 ГБ свободного места на системном диске

**Основной сценарий:**
1. Пользователь загружает установщик Google Drive for Desktop с официального сайта
2. Пользователь запускает установщик
3. Система запрашивает разрешения администратора (Windows) или пароль (macOS)
4. Установщик копирует файлы приложения в системную папку:
   - Windows: C:\Program Files\Google\Drive File Stream
   - macOS: /Applications/Google Drive.app
5. Система устанавливает драйвер виртуального диска
6. Установщик создает ярлыки и добавляет приложение в автозагрузку
7. После установки автоматически запускается приложение
8. Система показывает окно авторизации Google
9. Пользователь вводит email и пароль Google аккаунта
10. Система запрашивает разрешение на доступ к Google Drive
11. Пользователь подтверждает доступ
12. Система проверяет учетные данные и авторизует пользователя
13. Появляется мастер первоначальной настройки с выбором режима синхронизации:
    - Stream (Потоковая передача) - файлы хранятся только в облаке
    - Mirror (Зеркалирование) - файлы дублируются локально
14. Пользователь выбирает режим синхронизации
15. Система предлагает выбрать папки для синхронизации (по умолчанию - "My Drive")
16. Пользователь подтверждает выбор или настраивает выборочную синхронизацию
17. Система создает виртуальный диск "Google Drive" (буква G:\ в Windows или в Finder на macOS)
18. Начинается индексация файлов в облаке
19. Система отображает иконку в системном трее с индикатором прогресса
20. После завершения индексации файлы становятся доступны через виртуальный диск

**Альтернативные сценарии:**
- Сценарий А (Обновление с предыдущей версии): Система автоматически мигрирует настройки из Backup and Sync
- Сценарий Б (Несколько аккаунтов): Пользователь может добавить несколько Google аккаунтов (личный и рабочий)
- Сценарий В (Ошибка авторизации): Система показывает ошибку и предлагает повторить вход
- Сценарий Г (Недостаточно места): Система предупреждает о нехватке места и предлагает режим Stream
- Сценарий Д (Отмена установки): Пользователь может отменить установку на любом этапе
- Сценарий Е (Корпоративные политики): Для Google Workspace применяются политики администратора

**Бизнес-правила:**
- BR-SYNC-001: Приложение доступно только для Windows, macOS и Chrome OS
- BR-SYNC-002: Требуется стабильное интернет-соединение для первоначальной установки
- BR-SYNC-003: Виртуальный диск создается автоматически и не может быть изменен вручную
- BR-SYNC-004: По умолчанию выбран режим Stream для экономии дискового пространства
- BR-SYNC-005: Один компьютер может иметь несколько Google аккаунтов одновременно (до 4)
- BR-SYNC-006: Для Google Workspace администратор может запретить установку на личных устройствах
- BR-SYNC-007: Приложение автоматически добавляется в автозагрузку
- BR-SYNC-008: Требуется минимум 2 ГБ для системных файлов и кеша

**Результат:** Google Drive for Desktop установлен, пользователь авторизован, выбран режим синхронизации, виртуальный диск создан и доступен

### FR-SYNC-002: Режим потоковой передачи (Stream)

**Описание:** Файлы хранятся только в облаке и загружаются по требованию при открытии. Диск показывает все файлы, но они занимают минимум локального пространства.

**Роли:** Обычный пользователь, Google One подписчик, Google Workspace пользователь

**Предусловия:**
- Google Drive for Desktop установлен и авторизован
- Выбран режим Stream при настройке или в настройках
- Имеется интернет-соединение для доступа к файлам

**Основной сценарий:**
1. Пользователь открывает виртуальный диск "Google Drive" в проводнике
2. Система отображает структуру папок и файлов из облака
3. Рядом с каждым файлом показан статус синхронизации:
   - Иконка облака (☁) - файл только в облаке, не загружен
   - Иконка с галочкой (✓) - файл доступен офлайн
   - Иконка синхронизации (🔄) - файл синхронизируется
4. Пользователь видит все файлы, но они не занимают место на диске
5. Пользователь дважды кликает на файл для открытия
6. Система проверяет наличие файла в локальном кеше
7. Если файл не в кеше:
   - Система начинает загрузку файла из облака
   - Показывается индикатор прогресса
   - Файл временно сохраняется в кеш-директории
8. Система открывает файл в соответствующем приложении
9. Пользователь редактирует файл
10. При сохранении изменений:
    - Изменения сначала записываются в локальный кеш
    - Система автоматически начинает загрузку изменений в облако
    - Иконка меняется на статус синхронизации
11. После завершения загрузки иконка меняется на "синхронизировано"
12. Если файл не используется несколько дней, система удаляет его из кеша
13. Файл остается видимым, но статус меняется на "только в облаке"

**Альтернативные сценарии:**
- Сценарий А (Отсутствие интернета): Система показывает ошибку "Файл недоступен офлайн" и предлагает сделать его доступным
- Сценарий Б (Медленное соединение): Система показывает прогресс загрузки с оценкой времени
- Сценарий В (Большой файл): Для файлов >100 МБ система запрашивает подтверждение перед загрузкой
- Сценарий Г (Прерванная загрузка): Система автоматически возобновляет загрузку при восстановлении соединения
- Сценарий Д (Переполнение кеша): Система автоматически удаляет старые неиспользуемые файлы из кеша
- Сценарий Е (Часто используемые файлы): Система автоматически делает их доступными офлайн

**Бизнес-правила:**
- BR-SYNC-009: Режим Stream - режим по умолчанию для всех новых установок
- BR-SYNC-010: Кеш занимает максимум 20% свободного места на диске (настраивается)
- BR-SYNC-011: Файлы автоматически удаляются из кеша через 30 дней неиспользования
- BR-SYNC-012: Часто используемые файлы (открытые >3 раз за неделю) автоматически кешируются
- BR-SYNC-013: Google Docs, Sheets, Slides не занимают место (открываются в браузере)
- BR-SYNC-014: Размер файлов в проводнике показывается корректно, даже если они не загружены
- BR-SYNC-015: При открытии файла офлайн предлагается сделать его доступным
- BR-SYNC-016: Система приоритезирует загрузку активно используемых файлов
- BR-SYNC-017: Предварительная загрузка происходит только при WiFi соединении (настраивается)

**Результат:** Файлы доступны через виртуальный диск, загружаются по требованию, кеш управляется автоматически

### FR-SYNC-003: Режим зеркалирования (Mirror)

**Описание:** Файлы полностью дублируются на локальном диске и в облаке. Все изменения синхронизируются автоматически в обе стороны.

**Роли:** Обычный пользователь, Google One подписчик, Google Workspace пользователь

**Предусловия:**
- Google Drive for Desktop установлен и авторизован
- Выбран режим Mirror при настройке или в настройках
- Достаточно свободного места на локальном диске

**Основной сценарий:**
1. Пользователь выбирает режим Mirror в настройках
2. Система показывает предупреждение о необходимом дисковом пространстве
3. Система отображает общий размер файлов в Google Drive
4. Пользователь подтверждает выбор режима
5. Система начинает загрузку всех файлов из облака
6. Отображается прогресс синхронизации:
   - Общее количество файлов
   - Количество синхронизированных файлов
   - Оставшееся время
   - Скорость загрузки
7. Файлы последовательно загружаются и сохраняются в локальную папку:
   - Windows: C:\Users\[Username]\Google Drive\My Drive
   - macOS: ~/Google Drive/My Drive
8. Для каждого файла создается точная локальная копия
9. После завершения загрузки все файлы доступны офлайн
10. При изменении файла локально:
    - Система детектирует изменение через File System Watcher
    - Изменения автоматически загружаются в облако
    - Статус файла меняется на "синхронизация"
11. При изменении файла в облаке (с другого устройства):
    - Система получает уведомление о изменении
    - Автоматически загружается новая версия
    - Локальный файл обновляется
12. Все файлы постоянно синхронизированы между облаком и диском
13. Иконка в трее показывает статус: "Все файлы синхронизированы"

**Альтернативные сценарии:**
- Сценарий А (Недостаточно места): Система показывает ошибку и предлагает режим Stream или выборочную синхронизацию
- Сценарий Б (Конфликт версий): При одновременном редактировании создается копия с суффиксом "(конфликт)"
- Сценарий В (Паузa синхронизации): Пользователь может приостановить синхронизацию вручную
- Сценарий Г (Удаление файла): Удаление локально синхронизируется в облако и наоборот
- Сценарий Д (Большое количество файлов): Система синхронизирует файлы в приоритетном порядке (недавние первыми)
- Сценарий Е (Переход на Stream): Пользователь может переключиться на Stream, локальные файлы удаляются

**Бизнес-правила:**
- BR-SYNC-018: Режим Mirror требует место на диске равное размеру всех файлов в Drive
- BR-SYNC-019: Синхронизация двусторонняя - изменения применяются в обе стороны
- BR-SYNC-020: Удаление файла локально отправляет его в корзину в облаке
- BR-SYNC-021: При конфликте версий создается копия с именем "файл (конфликт YYYY-MM-DD)"
- BR-SYNC-022: Google Docs, Sheets, Slides не синхронизируются как файлы (только ярлыки .gdoc, .gsheet, .gslides)
- BR-SYNC-023: Все файлы доступны офлайн по умолчанию
- BR-SYNC-024: Система уведомляет о нехватке места заблаговременно (при остатке <10%)
- BR-SYNC-025: Приоритет загрузки: недавно измененные файлы > новые файлы > старые файлы
- BR-SYNC-026: Максимальный размер одного файла для синхронизации: 5 ТБ

**Результат:** Все файлы полностью синхронизированы и доступны офлайн, изменения автоматически синхронизируются в обе стороны

### FR-SYNC-004: Выборочная синхронизация (Selective Sync)

**Описание:** Пользователь может выбрать конкретные папки для синхронизации в режиме Mirror, остальные остаются только в облаке.

**Роли:** Обычный пользователь, Google One подписчик, Google Workspace пользователь

**Предусловия:**
- Google Drive for Desktop установлен
- Пользователь находится в настройках приложения

**Основной сценарий:**
1. Пользователь открывает настройки Google Drive (клик на иконку в трее > Settings)
2. Пользователь переходит в раздел "Google Drive preferences"
3. Пользователь видит вкладку "My Drive"
4. Система отображает дерево папок с чекбоксами:
   - Корневая папка "My Drive"
   - Все подпапки первого уровня
   - Для каждой папки показан размер
5. Пользователь снимает галочку с папок, которые не нужно синхронизировать
6. Система показывает:
   - "Будет синхронизировано: [размер]"
   - "Останется только в облаке: [размер]"
7. Пользователь может развернуть папки и выбрать подпапки
8. Пользователь нажимает "Apply"
9. Система показывает диалог подтверждения:
   - "Несинхронизированные папки будут удалены с этого компьютера"
   - Опция "Удалить также из облака" (по умолчанию выключена)
10. Пользователь подтверждает изменения
11. Система начинает применение изменений:
    - Удаляет локальные копии несинхронизированных папок
    - Сохраняет их в облаке
    - Синхронизирует только выбранные папки
12. В проводнике видны только синхронизированные папки
13. Несинхронизированные папки доступны через веб-интерфейс или в режиме Stream
14. Система отображает статус "Выборочная синхронизация активна"

**Альтернативные сценарии:**
- Сценарий А (Добавление папки): Пользователь ставит галочку на несинхронизированной папке, она начинает загружаться
- Сценарий Б (Общая папка): Shared with me можно также выборочно синхронизировать
- Сценарий В (Переключение режима): При переходе на Stream все ограничения снимаются
- Сценарий Г (Недостаточно места): Система предупреждает, если выбранные папки не помещаются на диск
- Сценарий Д (Изменение структуры): При создании новой папки в облаке система спрашивает о синхронизации
- Сценарий Е (Командные диски): Для Google Workspace можно выбирать синхронизацию Shared Drives

**Бизнес-правила:**
- BR-SYNC-027: Выборочная синхронизация доступна только в режиме Mirror
- BR-SYNC-028: Минимальная единица синхронизации - папка, нельзя выбрать отдельный файл
- BR-SYNC-029: Shared with me и My Drive настраиваются независимо
- BR-SYNC-030: Nested папки наследуют статус родительской папки
- BR-SYNC-031: При создании новой папки в облаке она синхронизируется только если родитель синхронизирован
- BR-SYNC-032: Настройки выборочной синхронизации сохраняются для каждого устройства отдельно
- BR-SYNC-033: Для Google Workspace администратор может принудительно синхронизировать определенные папки
- BR-SYNC-034: Размер папок обновляется в реальном времени при изменениях

**Результат:** Только выбранные папки синхронизируются локально, остальные доступны только в облаке

### FR-SYNC-005: Офлайн-доступ к файлам Google Workspace (Docs, Sheets, Slides)

**Описание:** Пользователь может сделать документы Google Docs, Sheets, Slides доступными для редактирования без интернета.

**Роли:** Обычный пользователь, Google One подписчик, Google Workspace пользователь

**Предусловия:**
- Используется браузер Google Chrome
- Установлено расширение Google Docs Offline (устанавливается автоматически)
- Пользователь авторизован в Google аккаунте

**Основной сценарий:**
1. Пользователь открывает Google Drive в браузере (drive.google.com)
2. Пользователь кликает на иконку "Настройки" (⚙) в правом верхнем углу
3. Выбирает "Settings"
4. Система открывает панель настроек
5. Пользователь видит секцию "Offline"
6. Пользователь включает переключатель "Create, open and edit your recent Google Docs, Sheets, and Slides files on this device while offline"
7. Система показывает сообщение "Setting up offline access..."
8. Система начинает синхронизацию:
   - Скачивает последние 30 недавно открытых документов
   - Кеширует их в браузере (IndexedDB)
   - Размер одного документа в кеше: 1-5 МБ
9. Индикатор показывает прогресс: "Синхронизировано X из Y документов"
10. После завершения система показывает: "Офлайн-доступ настроен"
11. Пользователь может вручную добавить конкретный документ:
    - Открывает документ
    - Кликает "File" > "Make available offline"
    - Система добавляет документ в офлайн-кеш
12. При потере интернета:
    - Пользователь открывает Google Drive
    - Видны только офлайн-доступные документы (с иконкой ✓)
    - Пользователь может открывать и редактировать эти документы
13. Все изменения сохраняются локально
14. При восстановлении интернета:
    - Система автоматически синхронизирует изменения в облако
    - Показывается уведомление "Синхронизация завершена"

**Альтернативные сценарии:**

### FR-SYNC-006: Разрешение конфликтов синхронизации

**Описание:** Система автоматически обнаруживает и разрешает конфликты при одновременном редактировании файла на разных устройствах.

**Роли:** Обычный пользователь, Google One подписчик, Google Workspace пользователь, Система синхронизации

**Предусловия:**
- Файл изменен на двух устройствах одновременно
- Оба устройства пытаются синхронизировать изменения
- Режим Mirror или файл доступен офлайн в режиме Stream

**Основной сценарий:**
1. Пользователь редактирует файл "document.docx" на ноутбуке офлайн
2. Одновременно другой пользователь (или тот же на другом устройстве) редактирует тот же файл онлайн
3. Ноутбук подключается к интернету
4. Система синхронизации начинает загрузку локальных изменений
5. Система обнаруживает, что версия в облаке изменена после последней синхронизации
6. Система детектирует конфликт версий:
   - Локальная версия: изменена в 14:30
   - Облачная версия: изменена в 14:35
   - Последняя синхронизация: 14:00
7. Система применяет стратегию разрешения конфликта:
   - Для Google Docs/Sheets/Slides: автоматическое слияние изменений (operational transformation)
   - Для обычных файлов: создание копии с конфликтом
8. Для обычных файлов система:
   - Сохраняет облачную версию как "document.docx"
   - Сохраняет локальную версию как "document (конфликт YYYY-MM-DD HH-MM).docx"
   - Помещает обе версии в одну папку
9. Система отправляет уведомление пользователю:
   - "Обнаружен конфликт синхронизации для document.docx"
   - Кнопка "Просмотреть конфликты"
10. Пользователь открывает обе версии и сравнивает изменения
11. Пользователь вручную объединяет изменения в одну версию
12. Пользователь удаляет ненужную версию
13. Система синхронизирует окончательную версию в облако

**Альтернативные сценарии:**
- Сценарий А (Google Docs): Изменения автоматически сливаются, конфликты не создаются
- Сценарий Б (Одинаковые изменения): Если изменения идентичны, конфликт не создается
- Сценарий В (Множественные конфликты): При редактировании на >2 устройствах создаются несколько копий с конфликтами
- Сценарий Г (Большой файл): Для файлов >100 МБ система предупреждает о длительной синхронизации
- Сценарий Д (Автоматическое разрешение): Администратор может настроить правило "последние изменения выигрывают"
- Сценарий Е (Конфликт удаления): Если файл удален на одном устройстве и изменен на другом, сохраняется измененная версия

**Бизнес-правила:**
- BR-SYNC-045: Конфликт возникает только при изменении файла на разных устройствах без синхронизации
- BR-SYNC-046: Google Docs, Sheets, Slides автоматически сливают изменения (Operational Transformation)
- BR-SYNC-047: Для обычных файлов (Word, Excel, PDF) создается копия с суффиксом "(конфликт YYYY-MM-DD HH-MM)"
- BR-SYNC-048: Облачная версия всегда сохраняется с оригинальным именем
- BR-SYNC-049: Локальная версия переименовывается с добавлением метки конфликта
- BR-SYNC-050: Конфликтные файлы помещаются в ту же папку, что и оригинал
- BR-SYNC-051: Уведомление о конфликте отправляется владельцу файла
- BR-SYNC-052: Для Google Workspace администратор может видеть логи конфликтов
- BR-SYNC-053: Стратегия "last write wins" применяется только при явном указании
- BR-SYNC-054: Конфликты хранятся в корзине после разрешения (90 дней)

**Результат:** Конфликт обнаружен и разрешен, пользователь получил уведомление, созданы копии файлов для ручного объединения

- BR-SYNC-066: Минимальный размер кеша: 2 ГБ

**Предусловия:**

2. Происходит внезапное отключение интернета или сбой приложения
3. Система детектирует потерю соединения
4. Система автоматически:
   - Сохраняет состояние синхронизации в локальную БД
   - Останавливает активные операции
   - Помечает незавершенные загрузки для повторной попытки
5. Пользователь видит статус "Офлайн" в иконке трея

   - Система автоматически детектирует подключение

8. Система возобновляет синхронизацию:
   - Загружает список изменений с момента отключения
   - Сравнивает локальные и облачные версии файлов
   - Детектирует конфликты (если файл изменен офлайн и онлайн)

   - Система проверяет частично загруженные файлы

   - Не перезагружает файл с начала
10. Для незавершенных выгрузок:
    - Система проверяет локальные изменения
    - Повторно загружает измененные файлы в облако
11. Система показывает уведомление: "Синхронизация восстановлена"
12. Все изменения, сделанные офлайн, загружаются в облако
13. Статус меняется на "Все файлы синхронизированы"

**Альтернативные сценарии:**

- Сценарий Б (Множественные отключения): Система терпеливо повторяет попытки с экспоненциальной задержкой
- Сценарий В (Конфликт версий): При обнаружении конфликта создается копия с меткой конфликта
- Сценарий Г (Критический сбой): При серьезном сбое пользователь может переустановить приложение без потери данных
- Сценарий Д (Восстановление из резервной копии): Система может восстановить состояние из локального snapshot

**Бизнес-правила:**
- BR-SYNC-123: Система автоматически возобновляет синхронизацию при восстановлении соединения
- BR-SYNC-124: Незавершенные загрузки возобновляются с последней позиции (не перезагружаются)
- BR-SYNC-125: Максимум 10 попыток восстановления с экспоненциальной задержкой (1с, 2с, 4с, ..., 512с)
- BR-SYNC-126: Локальные изменения имеют приоритет при восстановлении
- BR-SYNC-127: Состояние синхронизации сохраняется в локальной БД каждые 10 секунд
- BR-SYNC-128: При критическом сбое пользователь получает уведомление с инструкциями
- BR-SYNC-129: Частично загруженные файлы хранятся в временной папке и удаляются после успешной загрузки
- BR-SYNC-130: Система логирует все сбои для анализа
- BR-SYNC-131: После 10 неудачных попыток система запрашивает ручное вмешательство

**Результат:** Синхронизация автоматически восстановлена, все изменения загружены в облако без потери данных

### FR-SYNC-015: Синхронизация на мобильных устройствах

**Описание:** Мобильные пользователи (Android, iOS) могут синхронизировать файлы для офлайн-доступа с управлением использованием мобильных данных.

**Роли:** Обычный пользователь (мобильное приложение)

**Предусловия:**
- Установлено приложение Google Drive для Android или iOS
- Пользователь авторизован в приложении
- Достаточно свободного места на устройстве

**Основной сценарий:**
1. Пользователь открывает приложение Google Drive на телефоне
2. Переходит в "Settings" (Настройки)
3. Выбирает раздел "Storage" или "Offline"
4. Система показывает опции:
   - "Offline access" - включить офлайн-доступ
   - "Download files over WiFi only" - загружать только по WiFi
   - "Download files over mobile data" - загружать также через мобильные данные (предупреждение об использовании трафика)
5. Пользователь включает "Offline access"
6. Система показывает список рекомендуемых файлов для офлайн-доступа:
   - Недавно открытые документы
   - Часто используемые файлы
   - Помеченные звездочкой
7. Пользователь может вручную отметить файлы для офлайн-доступа:
   - Переходит к нужному файлу
   - Нажимает три точки > "Make available offline"
   - Система начинает загрузку файла
8. Индикатор показывает прогресс загрузки
9. После завершения файл отмечен иконкой ✓
10. При отсутствии интернета:
    - Пользователь может фильтровать список файлов: "Available offline"
    - Видны только офлайн-доступные файлы
    - Пользователь может открывать и редактировать эти файлы
11. Изменения сохраняются локально
12. При восстановлении соединения:
    - Система автоматически синхронизирует изменения
    - Показывается уведомление "Синхронизация завершена"
13. Для экономии места система автоматически удаляет старые офлайн-файлы:
    - Неиспользуемые более 30 дней
    - Файлы без ручной отметки "Keep offline"
14. Пользователь может управлять офлайн-файлами:
    - "Settings" > "Storage" > "Clear offline files"
    - Удаляет все офлайн-файлы кроме отмеченных вручную

**Альтернативные сценарии:**
- Сценарий А (Недостаточно места): Система показывает предупреждение и предлагает освободить место
- Сценарий Б (Автоматическая синхронизация): Система автоматически делает доступными часто используемые файлы
- Сценарий В (Папки офлайн): Пользователь может отметить папку целиком для офлайн-доступа
- Сценарий Г (Лимит мобильных данных): Система предупреждает о превышении лимита и приостанавливает загрузку
- Сценарий Д (Фоновая синхронизация): Система синхронизирует файлы в фоне при подключении к WiFi

**Бизнес-правила:**
- BR-SYNC-132: По умолчанию синхронизация только по WiFi (экономия мобильных данных)
- BR-SYNC-133: Максимальный размер офлайн-кеша на мобильном: 10% свободного места или 5 ГБ
- BR-SYNC-134: Система автоматически удаляет неиспользуемые офлайн-файлы через 30 дней
- BR-SYNC-135: Файлы, отмеченные вручную, не удаляются автоматически
- BR-SYNC-136: Синхронизация приостанавливается при заряде батареи <15%
- BR-SYNC-137: Синхронизация приостанавливается при включении режима энергосбережения
- BR-SYNC-138: Google Photos автоматически синхронизирует фото и видео (если включено)
- BR-SYNC-139: Для Google Workspace мобильная синхронизация контролируется политиками администратора
- BR-SYNC-140: Максимальный размер одного файла для офлайн-доступа на мобильном: 100 МБ

**Результат:** Файлы доступны офлайн на мобильном устройстве, синхронизация управляется с учетом мобильных данных и заряда батареи

## Сущности данных

### Настройки синхронизации (Sync Settings)
- **user_id** - идентификатор пользователя Google
- **sync_mode** - режим синхронизации (stream, mirror)
- **selective_sync_enabled** - включена ли выборочная синхронизация
- **selected_folders** - список ID папок для синхронизации
- **cache_size_limit** - максимальный размер кеша (в байтах)
- **auto_manage_cache** - автоматическое управление кешем
- **bandwidth_upload_limit** - лимит скорости загрузки (KB/s, 0 = без лимита)
- **bandwidth_download_limit** - лимит скорости выгрузки (KB/s)
- **sync_only_wifi** - синхронизировать только по WiFi
- **pause_on_battery** - приостановить при работе от батареи
- **backup_folders** - список локальных папок для резервного копирования
- **backup_to_photos** - резервное копирование фото/видео в Google Photos
- **created_at** - дата создания настроек
- **updated_at** - дата последнего обновления

### Статус синхронизации файла (File Sync Status)
- **file_id** - уникальный идентификатор файла в Google Drive
- **local_path** - путь к файлу на локальном диске
- **cloud_path** - путь к файлу в облаке
- **status** - статус (synced, syncing, error, offline_only, cloud_only, conflict)
- **last_synced** - время последней синхронизации
- **local_modified** - время последнего изменения локально
- **cloud_modified** - время последнего изменения в облаке
- **local_size** - размер локального файла (байты)
- **cloud_size** - размер облачного файла (байты)
- **checksum** - контрольная сумма файла (MD5)
- **version** - версия файла
- **is_offline** - отмечен ли файл для офлайн-доступа
- **sync_priority** - приоритет синхронизации (0-100)
- **error_message** - сообщение об ошибке (если есть)
- **retry_count** - количество попыток синхронизации

### Очередь синхронизации (Sync Queue)
- **queue_id** - уникальный идентификатор операции
- **file_id** - ID файла для синхронизации
- **operation** - тип операции (upload, download, delete, update_metadata)
- **priority** - приоритет операции (0-100)
- **status** - статус (pending, in_progress, completed, failed, cancelled)
- **progress** - прогресс операции (0-100%)
- **bytes_transferred** - количество переданных байт
- **total_bytes** - общий размер
- **speed** - скорость передачи (bytes/sec)
- **started_at** - время начала операции
- **completed_at** - время завершения
- **error_code** - код ошибки (если есть)
- **retry_after** - время следующей попытки

### Кеш файлов (File Cache)
- **file_id** - ID файла
- **cache_path** - путь к файлу в кеше
- **cached_at** - время добавления в кеш
- **last_accessed** - время последнего доступа
- **access_count** - количество обращений к файлу
- **size** - размер в кеше (байты)
- **is_pinned** - закреплен ли файл (не удалять автоматически)
- **expiry_date** - дата истечения кеша

### Метаданные файла (File Metadata)
- **file_id** - ID файла
- **name** - имя файла
- **mime_type** - MIME-тип
- **size** - размер (байты)
- **created_at** - дата создания
- **modified_at** - дата последнего изменения
- **owner_id** - ID владельца
- **shared** - флаг общего доступа
- **permissions** - права доступа (JSON)
- **tags** - теги и метки (массив)
- **description** - описание файла
- **parent_folder_id** - ID родительской папки
- **is_starred** - отмечен ли звездочкой
- **version_count** - количество версий

### Конфликты синхронизации (Sync Conflicts)
- **conflict_id** - уникальный ID конфликта
- **file_id** - ID файла с конфликтом
- **local_version** - локальная версия файла
- **cloud_version** - облачная версия файла
- **local_modified** - время изменения локально
- **cloud_modified** - время изменения в облаке
- **status** - статус конфликта (pending, resolved, ignored)
- **resolution_strategy** - стратегия разрешения (create_copy, keep_local, keep_cloud, manual)
- **conflict_file_id** - ID созданной копии с конфликтом
- **created_at** - время обнаружения конфликта
- **resolved_at** - время разрешения конфликта

### Shared Drives синхронизация (Shared Drive Sync)
- **drive_id** - ID командного диска
- **user_id** - ID пользователя
- **sync_enabled** - включена ли синхронизация
- **sync_mode** - режим (stream, mirror, selective)
- **selected_folders** - список папок для выборочной синхронизации
- **role** - роль пользователя (manager, content_manager, contributor, viewer)
- **last_synced** - время последней синхронизации
- **total_files** - общее количество файлов
- **total_size** - общий размер (байты)

### Логи синхронизации (Sync Logs)
- **log_id** - уникальный ID записи
- **user_id** - ID пользователя
- **timestamp** - время события
- **event_type** - тип события (sync_started, sync_completed, error, conflict_detected)
- **file_id** - ID файла (если применимо)
- **operation** - операция (upload, download, delete, update)
- **status** - статус (success, failed, warning)
- **details** - детали события (JSON)
- **error_message** - сообщение об ошибке
- **device_id** - ID устройства

## Состояния и статусы

### Статусы синхронизации
- **synced** - файл полностью синхронизирован (иконка ✓)
- **syncing** - файл синхронизируется (иконка 🔄)
- **error** - ошибка синхронизации (иконка ✗)
- **offline_only** - файл только локально, не синхронизирован в облако
- **cloud_only** - файл только в облаке, не загружен локально (иконка ☁)
- **conflict** - конфликт версий (требует разрешения)
- **available_offline** - файл доступен офлайн (иконка ✓ с зеленым фоном)
- **paused** - синхронизация приостановлена
- **pending** - файл в очереди на синхронизацию
- **deleted** - файл удален (ожидает синхронизации удаления)

### Режимы синхронизации
- **stream** - потоковая передача (файлы по требованию)
- **mirror** - зеркалирование (полная синхронизация)
- **selective** - выборочная синхронизация

### Приоритеты синхронизации
- **high** (100) - офлайн-файлы, недавно измененные
- **medium** (50) - часто используемые файлы
- **low** (0) - редко используемые, большие файлы

### Стратегии разрешения конфликтов
- **create_copy** - создать копию с меткой конфликта
- **keep_local** - оставить локальную версию
- **keep_cloud** - оставить облачную версию
- **merge** - автоматическое слияние (для Google Docs)
- **manual** - требует ручного разрешения

### Типы операций синхронизации
- **upload** - загрузка в облако
- **download** - загрузка из облака
- **update** - обновление файла
- **delete** - удаление файла
- **update_metadata** - обновление метаданных
- **move** - перемещение файла
- **rename** - переименование файла
